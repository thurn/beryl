Description

Read first: docs/beryl-3d.md 'Hosts' ('Losing the surface', 'Low memory', Request), 'Bug reports'; ios/Beryl3D as the iOS touch bead (by-q44s.7.6) left it (perform(_:), the pausing of the link); the low-memory bead's (by-q44s.7.5) handoff (what Lifecycle::LowMemory does in the client and renderer, and that a lost surface keeps the GPU device); rust/crates/beryl_mobile/ios/Sources/BerylMobile.swift (share: how the Tauri app presents UIActivityViewController for a file, including popoverPresentationController.sourceView); tools/src/beryl_tools/beryl3d/phone.py (run_ios_smoke).

Why. The milestone's exit checks need suspend and resume with the surface lost and recreated, and the low-memory path, to work on iOS, and the client's platform requests to be carried out.

Build, in the Swift host:

  • Suspend and resume. On UIApplication.didEnterBackgroundNotification: beryl3d_lifecycle(BERYL_SUSPENDED), then beryl3d_surface_lost, then pause the link. iOS forbids GPU work in the background, so no beryl3d_frame call happens until willEnterForegroundNotification, which sends BERYL_RESUMED, passes the layer again with beryl3d_surface and unpauses. Also handle willResignActive (a call or the app switcher) by pausing the link only, and didBecomeActive by unpausing.
  • Low memory. didReceiveMemoryWarningNotification sends BERYL_LOW_MEMORY and unpauses the link so the change is drawn. Debug builds (#if DEBUG) also observe the Darwin notification ca.thurn.beryl3d.test.memory-warning (CFNotificationCenterGetDarwinNotifyCenter) and call the same handler, because xcrun simctl cannot raise a memory warning.
  • Requests, the cases of perform(_:):
    • BERYL_REQUEST_SHARE: present UIActivityViewController(activityItems: [URL(fileURLWithPath: text)]) from the root view controller, with popoverPresentationController.sourceView set to the view, as BerylMobile.swift does. A missing file prints an error and does nothing.
    • BERYL_REQUEST_HAPTIC: UIImpactFeedbackGenerator(style: .light) or .medium by haptic, impactOccurred().
    • BERYL_REQUEST_OPEN_URL: UIApplication.shared.open(url) when URL(string:) parses it. Debug builds append one line per request carried out to Documents/host.log, through a small debug-only helper, so the smoke test can read what the host did from the same folder as the frame log. Debug builds also observe the Darwin notifications ca.thurn.beryl3d.test.share, .test.haptic and .test.open-url, which call perform(_:) with a request built in Swift (the share of the newest frame log, a medium haptic, https://example.com), so the smoke tests each case's code without a screen that asks for it (milestone 3's bug report is the first real sender of Share).

Smoke test: just b3d ios-smoke --lifecycle. After the first frame is shown it sends the app to the background (xcrun simctl launch <udid> com.apple.Preferences), waits 3 seconds, brings it back (xcrun simctl launch <udid> ca.thurn.beryl3d, which foregrounds the running process), posts ca.thurn.beryl3d.test.memory-warning, .test.haptic and .test.share with xcrun simctl spawn <udid> notifyutil -p <name>, waits for the recording's end, takes the screenshot (the share sheet in it is expected), and only then posts .test.open-url, because opening a URL sends the app to the background. It fails unless: the frame log has Lifecycle lines Suspended, Resumed and LowMemory in that order; no frame line falls between Suspended and Resumed; frames follow Resumed; the fixture ended; beryl3d.log holds no error; and host.log names the haptic, the URL and the share. Add its log-reading checks to tools/tests/test_beryl3d_phone.py.

Not in this bead: text entry; the phone layout; anything about a lost GPU device.

Run: just b3d ios-smoke; just b3d ios-smoke --lifecycle; just test-py tools/tests/test_beryl3d_phone.py.

Acceptance criteria

just b3d ios-smoke --lifecycle passes: Lifecycle lines Suspended, Resumed, LowMemory in order, no frame between Suspended and Resumed, frames after Resumed, the fixture ends, no error in beryl3d.log, and host.log records the haptic, the share and the URL; just test-py tools/tests/test_beryl3d_phone.py passes.
