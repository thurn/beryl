Close reason

FaceIx, Castings, ManaColor options and ManaPool replace raw u8s; outputs byte-identical

Description

Part of Milestone 1 (epic by-b0q), filed by the M1b Mason audit (by-b0q.4.1) at staging 2532e87. Follows by-b0q.2.4 (Slot/Seat/CardIx newtypes), which left three raw u8s in the engine's decision and stack types. M1b's agents, CLI and protocol then copied their decoding into four more crates.

Current design

  • Opt::Cast { slot, face: u8, costs: u8 } and StackEntry { face: u8, costs: u8, .. } (rust/crates/beryl_engine/src/decision.rs, state.rs:442-449): costs is a bitmask over Face::casting, decoded by hand as costs & (1 << i) != 0 in 8 places across 6 crates: beryl_engine cast.rs:154, resolve.rs:255, effect.rs:150; beryl_search rollout.rs:347, expert/mod.rs:1212; beryl_cli transcript.rs:369; beryl_session protocol.rs:851 and 909. The expert also reads costs != 0 as "this card's one option was paid" (expert/mod.rs:774, 1166-1173).
  • face: u8 (22 fields and parameters) is turned into an index by hand as def.faces[usize::from(face)] 44 times (13 in the expert, 8 in cast.rs, 3 in protocol.rs, ...).
  • Opt::Mana { slot, color: u8 }, Opt::Pool(u8) and Player::mana: [u8; 6] index colors by number although card::ManaColor exists; consumers convert with COLORS[usize::from(color)] and mana[color as usize] (engine.rs:407, mana.rs:833, effect.rs:493, scenario run.rs:653, protocol.rs:807).

Proposed design

#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, Hash)]
pub struct FaceIx(u8);            // FRONT, BACK; CardDef::face(FaceIx) -> &Face
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, Hash)]
pub struct Castings(u8);          // set over Face::casting
impl Castings {
    pub const NONE: Castings;
    pub fn contains(self, i: usize) -> bool;
    pub fn paid<'a>(self, face: &'a Face) -> impl Iterator<Item = &'a CastingOption>;
    pub fn is_empty(self) -> bool;
}
Opt::Cast { slot: Slot, face: FaceIx, costs: Castings }
Opt::Mana { slot: Slot, color: ManaColor }
Opt::Pool(ManaColor)
pub struct ManaPool([u8; 6]);     // Index<ManaColor>

The protocol and transcript keep their current wire format (a list of option indexes, colors by name).

What it eliminates

The 8 bitmask decodes (one Castings::paid), the 44 usize::from(face) indexings (one CardDef::face), the color-index conversions, and the possibility of passing a face, a cost set, a color and an X value to one another's u8 parameter.

Behavior that must not change

Every decision sequence and state hash (replay tests, scenarios, both oracles, perf_counts_stay_in_their_bands), the agents' choices for the same seeds, the PlayerView JSON (ui fixtures replay unchanged), and the State size assert.

Smallest black-box test

The existing suites unchanged, plus grep -rn '1 << i' rust/crates --include=*.rs finds no casting-bitmask decode outside Castings, and no faces[usize::from( outside CardDef::face.

Acceptance criteria

  • Opt::Cast, StackEntry (and the other face fields) use a face-index newtype and a casting-options set type; Opt::Mana / Opt::Pool and the player's mana pool use ManaColor.
  • No hand-written costs & (1 << i) decode or faces[usize::from(face)] index remains outside those types' methods.
  • PlayerView JSON, transcripts, replay files and every decision sequence are unchanged: replay, scenario, oracle, agent and perf-count tests, just ui-test and just ui-shots pass without re-recorded fixtures.
  • State stays under its compile-time size assert.
