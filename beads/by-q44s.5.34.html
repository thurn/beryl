Audio thread plays effects and music with rodio; settings saved; tests and lane pass

Description

Read first: the epic by-q44s ('Rules for every bead'); rust/beryl3d/AGENTS.md; docs/beryl-3d.md 'Sound', 'Threads'. Code: beryl_scene src/frame.rs (Frame::sounds, SoundId: milestone 2 fills it, by-q44s.3.31; SoundId(n) is the n-th key of sounds in ui/src/audio/manifest.json), src/screens/mod.rs (Music, Request::Music, Request::Audio, Settings, from the contract); beryl_3d src/app.rs (where the host drains requests after a frame), src/main.rs. Web: ui/src/audio/manifest.json (sources, music: menu, game, win and loss with their variants; sounds: 30 cues with gain and variants), ui/src/audio/sound.ts (play, setMusic, audioSettings: music, sfx and muted; how a cue picks a variant and caps its copies), ui/src/audio/loops.json (exact loop lengths for menu and game), ui/src/audio/SoundControls.tsx. The files: ui/public/audio/sfx holds WAV files and ui/public/audio/music holds M4A (AAC) files.

Build, in beryl_3d, a new file src/audio.rs:

  • rodio 0.23.0 with default features off and the features that decode WAV, Symphonia's MP4 container and its AAC decoder, and playback (Cargo.toml comment: replaces the web's Web Audio). Run cargo add rodio@0.23.0 --no-default-features and add those features by the names rodio 0.23.0's Cargo.toml gives them; correct docs/beryl-3d.md 'Sound', which names only playback and mp4 and says the files are all M4A.
  • At startup a worker decodes every sound of manifest.json into memory; the audio thread owns the output stream. After each frame the host sends each Frame::sounds entry to the audio thread as a message (a variant chosen as sound.ts chooses, the cue's gain, the copy cap); playing is never a file read.
  • Music: Request::Music starts that track's variant on the audio thread and loops it at the exact length in loops.json (win and loss do not loop); Request::Audio sets the music and effects volumes and mute.
  • Settings persistence: Request::SaveSettings writes settings.json in the app's data folder and the host sends it back as Input::Settings at startup.
  • An app with no audio device runs silent and logs it once.

Do not build: Android's playback through the Kotlin host (milestone 4).

Tests, in beryl_3d: every sound and track in manifest.json decodes (a test over the files); the loop length of game matches loops.json; settings written and read back are equal; with no device the audio thread starts and drops messages.

Run: just b3d cargo-test -p beryl_3d; just b3d app --for 10s (windowless; it must start and end); just b3d lane.

Acceptance criteria

The tests pass; just b3d app --for 10s starts and ends with no audio error in its log (output in a comment); docs/beryl-3d.md 'Sound' names the features used and the two file formats.
