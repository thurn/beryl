Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'Automated checks' and 'Manual QA', and the appendix's own 'Manual QA' section. The epic's decision: every Manual QA step that can be scripted becomes an automated check; nobody opens a window.

  1. Appendix coverage. Write ui/scripts/appendix.test.mjs (run by npm test) that parses the tables of docs/manual-multiplayer-cockatrice.md and, for every row whose last column does not say "Not carried over", finds a command in data/table-commands.json by a mapping file data/table-appendix-map.json (row text to command id, or to gesture:<name> for rows that are gestures, each gesture naming the kept-table-*.mjs check that covers it). A row with no mapping fails the test. Rows marked "Not carried over" must map to nothing, and the test asserts no command's label matches them. Describe the map file in data/AGENTS.md.
  2. Manual QA list. Go through the doc's Manual QA bullets one by one. For each, find the kept-table-*.mjs check that covers it or write one (in kept-table-qa.mjs, using pair()). Keep a table in a comment on this bead: bullet, check title, or the reason it cannot be automated. The only acceptable reasons are: it needs two machines on different networks; it needs a real window (Cmd+W closing the window after leaving the table, key delivery through the native menu); it compares with Cockatrice itself.
  3. Hidden information in the browser. One check with pair() that plays 30 scripted actions including draws, a face-down play, a reveal, a look and a shuffle, and after each asserts the guest page's whole DOM text and every recorded game-update payload contain no name of a card the guest does not know.
  4. Whole-run acceptance. Run every item under "Whole-run acceptance" in the epic and record the result of each in the same comment. Fix failures that are small; file a bead under M3 for any that is not.

Run just ui-unit (which warms a fresh worktree), then run the new checks by title with just ui-test and record titles and outcomes in the acceptance comment. Add each new kept module to ui/scripts/kept.mjs. Recorded manual table checks must open #/table; the default engine route silently ignores manual updates. Use pair() for two-seat acceptance, as M2's solo projections exercise only one live session. Then run just check and just ci. The fast gate may defer browser checks when it reaches its wall limit, so retain the explicit results.

Acceptance criteria

appendix.test.mjs maps every carried-over appendix row to a command or a covered gesture and fails on an unmapped row; every scriptable Manual QA bullet has a named check and the rest have one of the three allowed reasons, listed in a comment; the browser redaction check passes; each whole-run acceptance item's result is recorded.
