Added Layout::for_size phone/desktop selector with tests

Description

Read docs/beryl-3d.md “Sizes” and “The test driver”. The inspector names a phone layout in beryl_scene src/agent/fault.rs (Layout), but the live client receives a logical Size and Insets via Input::Surface (src/input.rs). Give the existing Layout enum a single Layout::for_size(Size) selector: Phone when min(width, height) < 500 logical points, Desktop at 500 or above. Reuse that enum at the table, screen and inspection boundaries. In beryl_scene src/table/mod.rs keep Window as the input geometry type. Do not switch any callers to the new layout here. The later table and screen beads call the selector from their normal paths; the checks bead uses it to infer layout from reproduced test names.

Tests in beryl_scene tests/all/agent.rs: all three portrait sizes, a rotated narrow window, and the inclusive desktop boundary at 500 logical points, regardless of pixel density. Run: just b3d cargo-test -p beryl_scene --test all agent::

Acceptance criteria

The public selector classifies the portrait, rotation and boundary cases in the agent test, and the existing desktop recordings keep their output.
