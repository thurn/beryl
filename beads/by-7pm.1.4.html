Description

Build the phone layout of the game screen as DESIGN.md specifies, rendering real beryl_session state through ui/src/ipc.ts, in the browser first (?phone), with the prototype's three boards as fixtures and screenshot checks. This bead is the board and its static rendering; gestures and sheets come in the next bead of the lane. Read the run epic, then /Users/dthurn/beryl-mobile-prototype/DESIGN.md (Layout, Height budget, Rows, Creature zone, Hand, Middle, Components, Fonts and tokens, Prototype shortcuts), look at screenshots/, and serve the prototype (prototype/, ?s=main|attack|respond) to compare.

What to do

  • Phone mode: ui/src/mobile/ holds the phone screens. App picks phone mode on a Tauri mobile platform (detect via @tauri-apps/plugin-os if worth the dependency, or the user agent / navigator.maxTouchPoints plus portrait narrow viewport; prefer an explicit platform signal from Rust through app_info in beryl_session::ipc::AppInfo, which regenerates ui/src/generated/protocol.ts via ts-rs; its header says how). ?phone forces it in headless runs. App.tsx routes /game to the phone game screen in phone mode; the start screen can stay the desktop's for now (a later bead designs it).
  • ui/src/mobile/layout.ts: pure functions from a PlayerView (types in ui/src/generated/protocol.ts) and the viewport to placements, implementing DESIGN.md exactly: strips 48/60, middle 44/110, height budget formula (oneRow, zMin, R, L, O), 5:7 cards 0.716, 5px gaps, identical permanents stacked with 3px peeks (reuse twins/referenced from ui/src/game/decisions.ts the way desktop layout.ts does), tapped 90° with widened slot, even overlap on overflow, creature zone 1–3 rows picking the tallest card (cap 128), opponent's fullest row nearest the middle, hand fan (width min(100, W×0.25), step formula, d×2.2°, d²×1.4px, 66% showing above the bottom edge plus safe-area inset). Keep it a pure module like desktop ui/src/game/layout.ts, and keep per-object identity by public slot so later animation can glide cards between zones (see that file's header).
  • ui/src/mobile/PhoneBoard.tsx (or similar): renders the placements with the desktop's Card.tsx (full scans; normal images, card back for face-down/opponent hand; border-radius: 4.8% / 3.4%), overlays from DESIGN.md's Overlays table using the desktop classes (.card-loyalty, .card-pt, .card-counters, .card-playable, .card-target, .card-source), the life orbs from Player.tsx (LifeOrb) at --orb: 0.37px, piles (26×36 with offset edge), opponent hand backs (24×34 overlapping by 10), ≡ icon button, the middle phase icon on the gold line (sun/crossed swords/moon, gold glow on your turn) and the stack (68px cards, 44px apart, top in source glow), and the dock (Button primary at 40px/18px type, min width 84, plus .pass-on-button) wired to the same decisions the desktop dock sends (Board.tsx's Dock/DockButtons/TurnButton usage and decisions.ts). Import ui/src/design/*.css; put phone styles in a ui/src/mobile/phone.css. No card names, mana icons, turn number, step track, pile counts or captions on screen (DESIGN.md Principle 2).
  • Scripted boards for the prototype's three states in rust/crates/beryl_cli/src/boards.rs: the late-game WU mirror at turn 14 with ~30 permanents (main: your main phase, land drop and sorceries castable; attack: declare attackers; respond: opponent's Fractured Identity targets your The Wandering Emperor). Read the prototype's index.html state object for the exact cards; use cards in the V1 cube that are implemented (beryl_cards); substitute the nearest implemented card if one isn't, and say which. Add fixtures to ui/fixtures.json the way existing board fixtures are made (find how, e.g. just ui-shots --help, tools/src/beryl_tools/shots.py, and existing board names in boards.rs).
  • Shots in ui/shots.json: phone-main, phone-attack, phone-respond at 393×759 and 375×647 (and one at 430×~850). Compare them with /Users/dthurn/beryl-mobile-prototype/screenshots/iphone15-0{1,2,3}-*.png and iphone-se-0{1,2,3}-*.png by eye (Read the PNGs); match the layout, not pixel-perfect.
  • Checks: extend the shot checks (tools/src/beryl_tools/shots.py and its in-page checks) for phone shots: fail on any visible UI text with computed font-size < 12px (the P/T slash exempt) and any interactive element smaller than ~40×40 CSS px; no horizontal scroll; nothing outside the viewport except the hand's cut-off. touch-action: none on the body in phone mode.

Acceptance

cd ui && npm run typecheck, just ui-shots phone-main phone-attack phone-respond pass with the new checks; desktop shots unchanged (just ui-shots); just test-rust passes (boards.rs). Report the shot paths and your comparison against the prototype screenshots in the close reason.
