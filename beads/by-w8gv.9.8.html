Close reason

Trigger is event x subject x Players, matched through a per-kind listener index; unmatched triggers refused by the table; rollouts 389,507,068 -> 388,818,178, no bump; staging 4c4c8470

Description

Milestone 5 of Project 50k (plan K5 and K3; epic by-w8gv.9): the rules library and the card port. Line numbers and counts below were read at staging f5034c58; the code as it stands wins over this text, and a deviation is a comment on this bead.

First bead of the vocabulary lane. Milestone 2 designed Effect, Objects, Players, Amount and Condition and moved the rest of the vocabulary without redesigning it. The M2 Mason audit (comment on by-w8gv.9.1) put that redesign at the front of this milestone, before any card is ported, so each card file is written once. Its item 1:

"Trigger (beryl_card/src/trigger.rs) is a flat list with one entry for each pair of event and subject: YouCast, YouDraw, YouDiscard, YouAttack, YouCreateTokens(Types), Step(TurnStep, Whose). 17 of the paper test's 60 cards needed a new entry, nearly all an event that exists with another subject or player. As it stands the enum grows with the card pool. Make it event x subject Filter x Players. Matching is on the hot path: index by event kind behind a capability bit (docs/rules-coverage.md, Principles) and prove it on the count gate."

What exists

  • beryl_card/src/trigger.rs (71 lines): Trigger { None, Enters, Dies, Attacks, YouAttack, CombatDamageToPlayer, Step(TurnStep, Whose), YouCreateTokens(Types), YouCast, YouDiscard, YouDraw, Delayed(Delayed) } and Delayed { YourNextMainPhase, NextEndStep }.
  • beryl_rules/src/trigger.rs (450 lines): match_event (line 46), times, face_abilities, fires (line 140), match_leaving (line 222, leaves-the-battlefield abilities look back in time, CR 603.10a), lki, enqueue, fire_delayed, next_to_stack, put_on_stack, delay, entered_with.
  • The events themselves: beryl_kernel/src/event.rs. The per-game facts a table keeps about its cards: beryl_kernel/src/table.rs (FaceFacts, capability bits).
  • 20 card files name Trigger:: (grep beryl_cards/src), and beryl_cards/src/generate.rs reads it.
  • beryl_card/tests/paper_test.rs compiles the paper test's definitions that fit. The paper test's list is the comment of 2026-11-11 04:46 on by-w8gv.3: cards 1, 3, 6, 12, 13, 25, 29, 39, 43, 47, 48, 49, 52, 54, 55, 57 and 60 asked for a trigger entry ("a Frog you control attacks", "an opponent casts", "each player's upkeep").

Scope

  1. Trigger becomes a product: the event (a closed list of kinds the engine raises), the subject (a filter on the object the event is about, with "this" as one value), and whose (a Players value read from the ability's controller) where the event has a player. No variant names its subject or player. Step takes Players. Keep Copy, const-buildable, and small: Ability holds one and its size is a power of two (beryl_card/src/ability.rs, the const assertion).
  2. Delayed triggers (CR 603.7) are made by effects, not printed: decide whether Trigger::Delayed stays a variant or becomes the same product with a "next time" marker, and record it. The port writes Mana Drain and Teferi, Hero of Dominaria against it.
  3. The engine matches by event kind: an event looks only at abilities indexed under its kind, and when no card in the game has a trigger of that kind the check is one AND. Measure against today's match_event.
  4. Rewrite the trigger of each of the 20 card files to the new form (that field only; bodies are the port's), and generate.rs's read.
  5. Write in beryl_card/tests/paper_test.rs the triggers of the 17 paper-test cards whose event the engine already raises.

No new rules features (run epic by-w8gv, K14): the vocabulary may now say things no implemented card says. Where the engine has no code path for an expressible value, the card table must refuse the definition when it is built (TableError, beryl_kernel/src/table.rs) or the definition check must reject it, with a test; it must never run as a silent no-op. List each such gap in a comment on this bead: they are docs/rules-coverage.md's project, not this one's.

Gotchas

  • times makes one trigger for several simultaneous events of a kind (tokens created together); match_leaving reads last-known information. Both keep their answers.
  • The order triggers are put on the stack and the questions TriggerOrder asks are replayed by saves and rollouts.
  • The next bead of this lane replaces Whose in Filter; use Players here and leave Filter's own Whose to it.

Tests: beryl_rules/src/tests/events.rs (2,084 lines, most of the trigger coverage), cargo test -p beryl_cards; the fast check's oracle lane runs each changed card's scenarios in XMage and Forge.

Design as built (local commit 49206f02, not yet pushed: see the disk-full note below).

SHAPE. beryl_card/src/trigger.rs: Trigger { event: TriggerEvent, subject: Subject, whose: Players, delayed: bool }.

  • TriggerEvent, the closed list of kinds the engine raises: Enters, Dies, Attacks (CR 508.3a, once per creature), PlayerAttacks (CR 508.3d, once per declaration), DealsCombatDamageToPlayer, Step(TurnStep), MainPhase (either of a turn's two, CR 505.1), CreatesTokens, Casts, Discards, Draws. No entry names a subject or a player.
  • Subject: This or A(Filter). A(Filter::Any) is what a trigger says of an event about no object (a step, a draw).
  • whose: Players, read for the ability's controller: the trigger fires when the event's player is one of them. Players::EachPlayer is "a player" and what an event with no player says. Step takes Players.
  • Builders are const: Trigger::ENTERS, DIES, ATTACKS, DEALS_COMBAT_DAMAGE_TO_A_PLAYER, Trigger::step(step, whose), main_phase, attack, creates_tokens(whose, filter), casts(whose, filter), discards, draws, Trigger::of(event, subject), .whose(players), .next().

DEVIATION: Ability holds the trigger by reference (trigger: Option<&'static Trigger>), not by value. Measured: Filter is 24 bytes and Players 40; Ability is 128 bytes with 13 to spare, so a Trigger by value makes it 256 (the power-of-two assertion). The body and the condition are held by reference already. Ability::triggered(&Trigger::ENTERS, body); in a static a builder call is promoted (&Trigger::casts(Players::You, Filter::Any)), in a const fn body it needs a named const (ability.rs, YOUR_END_STEP). Trigger no longer derives PartialEq/Eq/Hash (Filter and Players do not): readers ask trigger.event == ... or trigger.is_this(TriggerEvent::Enters).

DELAYED TRIGGERS (scope 2): the same product with a "next time" marker, not a variant. CR 603.7 says a delayed trigger's event the way a printed one's is said, with the word "next": Mana Drain is Trigger::main_phase(Players::You).next(), Teferi, Hero of Dominaria is Trigger::step(TurnStep::End, Players::EachPlayer).next(). Delayed the enum is gone. A delayed trigger is in no index: it waits in the state's delayed list and fire_delayed reads its event and players with the functions the printed ones use (begins, listener::is_for). The table accepts a delayed trigger only on a step or main phase, the one moment fire_delayed is called for. For by-w8gv.9.16: an Effect::Delayed { when: Trigger, .. } can hold the product directly; the delayed field exists because today a delayed trigger is an ability in its card's list and the table must not index it as printed.

ENGINE (scope 3). New beryl_kernel/src/listener.rs: Listener { kind, face, ability, trigger }, listens_to(&Trigger) -> Result<u16, Unmatched> (the one place that says which products the engine matches), is_for(players, player, you). GameTable keeps every card's listeners flat with a start per game index; GameTable::listeners(card, face, kind) gives a face's triggered abilities of one kind in face order. beryl_rules/src/trigger.rs match_event, match_leaving read only those; fires reads the subject and the players the same way for every kind (about, how_many, is_for). The one-AND check when no card of the game has the kind was already there (GameTable::listens_any) and is unchanged; the order triggers are found in is unchanged (battlefield order, then the face's ability order, then emblems by seat).

REFUSAL. TableError::Trigger { card, unmatched } from GameTable::new, for a deck's card or a token one makes. Tests: beryl_kernel listener.rs (each refused product, by reason) and table.rs (a_table_refuses_a_trigger_the_engine_cannot_match). beryl_session/src/replay.rs maps it to SessionError::Deck.

GAPS: products the vocabulary says and the engine has no code path for. Each is refused when the table is built (listener::Unmatched), never a silent no-op. They are docs/rules-coverage.md's project.

  • Enters with a subject other than this ("whenever another creature enters"): permanents entering together must see each other (CR 603.6a) and events are matched one at a time. Unmatched::Subject.
  • Dies with a subject other than this ("whenever a creature you control dies"): match_leaving looks back (CR 603.10a) only for the leaving permanent's own abilities. Subject.
  • Attacks with a subject other than this ("whenever a Frog you control attacks"): one trigger for each attacker the filter accepts; fires gives one. Subject.
  • DealsCombatDamageToPlayer with a subject other than this. Subject.
  • Casts or Discards of this object itself ("when you cast this spell", "when you discard this card"): abilities that function on the stack or from a hand or graveyard are not matched. Subject.
  • A subject on an event about no object (Step, MainPhase, Draws), or This for a set (PlayerAttacks, CreatesTokens). Subject.
  • Players other than You, EachOpponent and EachPlayer (a target, "its controller", "its owner", "that player"), and any but EachPlayer on Enters, Dies and Attacks, which no player does. Unmatched::Whose.
  • A delayed trigger on anything but a step or main phase ("the next time you draw"). Unmatched::Delayed.

NEW PRODUCTS THE ENGINE NOW MATCHES, through the code that matches the pool's, each with a test in beryl_rules/src/tests/triggers.rs: Casts for EachOpponent; Casts with a filter on the spell; Step for EachPlayer; a printed MainPhase; Draws for EachPlayer; PlayerAttacks with a filter on the attackers (the count is the amount). No card of the pool says any of them, so no game changed.
