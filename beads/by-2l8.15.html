Typed decision indices, Entrant enum, Resume sentinel, Choose folded into Agent; formats kept; old-binary upgrade verified; staging 5051db3

Description

Mason finding (by-2l8.11), long-think runner, rust/crates/beryl_cli/src/longthink/.

Current design

  • Two index spaces are both called "decision": the game's (usize: Line position, Crash.decision, DecisionRecord.decision, Stop::Differs, Game::until, BERYL_LONGTHINK_PANIC, the panel's Now.decision) and the agent's own (u32: Searched.decision/chain, Line.resume, Game::from, Mcts::resumed, DecisionRecord.agent_decision). upgrade.rs mixes them in one call (from[seat] = chain; until: Some(i + 1)), and from = [u32::MAX; 2] is a sentinel for "replay every search from the log". decisions.jsonl is the epic's training data (D7), so its consumers inherit the ambiguity.
  • game::Entrant { name: String, budget: Option<Budget> }: Spec::new and game::build both match the strings "mcts-hidden"/"mcts-omniscient", build has a runtime error for a search without a budget, and play and the tests use budget.is_some() as "is a search".
  • game::Choose duplicates beryl_search::Agent to add one method, searched() -> Option<(Option<&Search>, u32)> (a nested option), with impls for Mcts and Box<dyn Agent + Send>; upgrade.rs's test doubles implement it.

Proposed design

struct GameDecision(usize);   // index in the game, from 0
struct AgentDecision(u32);    // index among one agent's own decisions
enum Entrant { Search { sight: Sight, budget: Budget }, Fixed(String) }
enum From { Log, At(AgentDecision) }   // replaces the u32::MAX sentinel
// beryl_search::Agent gains defaulted methods; Choose and its impls go:
fn last_search(&self) -> Option<&Search> { None }
fn resume_point(&self) -> Option<AgentDecision> { None }

Serde keeps the JSON shapes (transparent newtypes; Entrant serializes to the same name/iterations it is shown and keyed by), so no file format changes.

Eliminates

The string dispatch and its error branch, the Choose trait and both impls, the sentinel, and any chance of passing a game index where an agent index belongs.

Must not change

Every file a run writes (games, decisions, logs, crashes) keeps its format; game keys, seeds and moves are unchanged; an existing run resumes and --upgrade adopts the new binary into a run started by the old one.

Smallest acceptance test

The existing longthink tests pass unchanged in what they assert, plus one: a tiny run played by the binary built before this change (or a committed tiny run fixture) is adopted by --upgrade with this change and resumes to the same files as an uninterrupted run.

Acceptance criteria

Game and agent decision indices are distinct types end to end; Entrant is an enum with no runtime name dispatch; game::Choose is gone (Agent carries last_search/resume_point); run files keep their formats and --upgrade adopts the new binary into a run started by the old one, shown by a test.

Derek Thurn2026-11-06

Done as proposed, with these choices and deviations:

  • AgentDecision lives in beryl_search (Search.decision/chain, Mcts::resumed, Agent::resume_point, and Mcts's own counter are typed). beryl_search gains a serde dependency for its #[serde(transparent)] derive: the orphan rule bars beryl_cli from implementing Serialize for it, and remote-derive shims for Option fields cost more than the dependency. GameDecision lives in longthink/game.rs.
  • The sentinel enum is game::Resume { Log, At(AgentDecision) }; 'From' would shadow the prelude trait in game.rs. A Resume::Log search that reaches the end of its log now fails the replay explicitly instead of asking an agent built at u32::MAX.
  • Mcts's inherent last_search/resume_point moved into its Agent impl; the Box<T> impl forwards both (without it a boxed search would silently log nothing).
  • Acceptance test: a committed tiny-run fixture checked by --upgrade would break on every later card or engine change that alters play (verify replays games), so it would be a change-detector. Instead, committed run::tests::run_files_keep_their_format: lines of every run file (log lines with and without search/resume, a game and a crashed game record, a decisions line with null means, a crash, a clock line) written by the pre-change binary round-trip byte for byte. Then a one-time cross-binary check: staging ebb0eec's beryl_cli played a tiny 2-game ladder (4,8 rungs, 1 tree, expert); a copy cut after game 1 with game 2's log cut mid reuse chain (seat 1 resume 7 at its decision 8) was adopted by this binary with --upgrade ('1 games replayed and the one in progress, 94 searches repeated'), then resumed by the adopted binary to 2 games: games.jsonl, decisions.jsonl and both transcripts byte-identical to the old binary's uninterrupted run and to the new binary's, and logs identical but ms.
  • just check passes; cargo test -p beryl_cli -p beryl_search passed in full (longthink integration tests included).
