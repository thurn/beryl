Close reason

b3d-render is beryl_pictures with no engine (28 MB, 0.37 CPU-s); edit-case median 6.4-12.4 s depending on machine state, remaining causes recorded in docs/beryl-3d.md

Description

Symptom: after a one-line edit in beryl_scene, just b3d png verbs-zones --at 1500ms took a median of 32 s over five runs at load 22 to 37 (docs/beryl-3d.md, 'Edit-to-output time'), against the epic's exit check of 6 s. just b3d tree was brought to 2.5 s by by-q44s.1.50, which stopped b3d linking the engine; b3d-render was left as it was.

Why, as measured: about 13 s is the build after the edit (beryl_scene, then beryl_inspect, beryl_render, beryl_host and beryl_3d, which all depend on it), and the rest is macOS checking the newly linked 134 MB executable before its first run, 28 s at load 20 to 50. b3d-render lives in beryl_3d, which links beryl_session and so the engine, the cards and the search, though drawing a recording needs none of them.

Fix direction: give the pictures a binary that links only beryl_scene, beryl_inspect, beryl_render, beryl_host's headless host and beryl_assets (no beryl_session), as b3d does; tools/src/beryl_tools/beryl3d/cli.py runs it from the linker's own file already. Then measure the edit case again by the doc's method (five runs, a different edit each time, the load beside each) and update the table in 'Edit-to-output time' and the row in 'Measurements'.

Measured in by-q44s.1.10 and by-q44s.1.16.

Acceptance criteria

After a one-line edit in beryl_scene, just b3d png verbs-zones --at 1500ms answers in a median of 6 s or less over five runs, with the load beside each, recorded in docs/beryl-3d.md 'Edit-to-output time' and 'Measurements'; or the doc names what remains and why.

Handoff: b3d-render moved from beryl_3d into a new program-only crate rust/beryl3d/crates/beryl_pictures (src/main.rs, film.rs, font.rs; tests/pictures.rs runs the binary). beryl_assets' decklist_faces and MatchFaces::list are behind a new 'decklists' feature (the only path to beryl_session); its unused beryl_card_store dep was removed. rust/beryl3d/Cargo.toml: [profile.dev.package.""] opt-level 1, and ctt/ctt-/fast_image_resize/fearless_simd/half at 3, because placeholders (faces with no scan) are compressed on every run. tools/.../beryl3d/cli.py builds -p beryl_pictures. Result: 134 MB -> 28 MB, program 2.6 -> 0.37 CPU-s; edit-case medians 6.4 s (load 52-68) and 12.4 s an hour later (load 22-25): the 6 s target is met only some of the time. docs/beryl-3d.md 'Edit-to-output time' has every run and what remains: the five-crate serial rebuild (scene -> assets/inspect -> render -> host -> pictures) and macOS's check of the new executable; next levers named there (shorter chain, dependencies as a dynamic library). Gotcha: the first lane run after this change rebuilds every dependency at opt 1 (lane took 165 s once); the shared b3d target cache needs refreshing.
