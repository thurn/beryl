Flaky checks file a P1 delete bead (flaky.py); quarantine removed; 9 quarantined checks got beads (0f5b9fbd, c33d7b64)

Description

What we see

checks.py reruns a failed step once, and a pass on the rerun prints a flaky: line and passes the lane. verdicts.py quarantines a check that flakes twice in seven days: it keeps running and being logged but cannot fail CI. AGENTS.md now says flaky tests are deleted.

What to change

  • A check that fails and then passes on its rerun gets a verdict of flaky as now, does not fail the lane, and files a P1 bead to delete the check (or replace it with a deterministic test of the same behaviour, if that is cheap and the check has caught real bugs). One open bead per check.
  • Remove quarantine from verdicts.py: there is no state in which a check runs but cannot fail. Checks quarantined today get the same delete bead.
  • Keep the narrowed rerun only as the way to detect a flake.

Rewrite before deleting

Every bead this files asks, for each check it names, before deleting or moving it: could a fast, deterministic test (a Rust unit test, a Node test with no browser, a check against a recorded fixture) keep most of what this end-to-end check protects? If so, the agent writes that test and then deletes the slow check. If not, it deletes the check (no catches) or moves it to the nightly (some catches). The bead records which it chose and why.

Files and tests

tools/src/beryl_tools/checks.py (the rerun in run_all), tools/src/beryl_tools/verdicts.py (quarantine, Beads), tools/src/beryl_tools/reruns.py, tools/tests/test_checks.py, the tests for verdicts in tools/tests/, docs/checks.md.
