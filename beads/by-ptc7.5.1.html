Description

Audit the architecture as it stands after milestones 1 and 4, before the three keystone families build on it. Read the plan, the two contracts, the four Wardens' close reasons of the module passes, and just citations coverage.

Answer, with evidence, in a comment on this bead:

  1. The bug log (docs/bugs.md), entry by entry: which guard now stops each one's class (a lint, a type, a check, a differential test)? Try to write five of the logged bugs again, one from each of the five largest classes in the plan's table. Report which compile, and which tests catch those that do. A class with no guard gets one, or a sentence on why none can exist, in the plan's table.
  2. Would this layout hold a full Comprehensive Rules? Take the unowned rules of just citations coverage section by section and say where each section's code would go. A section with no obvious home means the module map is wrong: fix the map and file the move.
  3. The three designs the families are about to build (Format and the turn as a plan; casting inside a resolution and combat::assigner; Shape on a card definition): read Designs F to I of the plan against the code as it now is. Amend each section where the module passes changed what it should say, and put the corrected file names into each family's foundation bead.
  4. Compile and check time: just efficiency compile now against the series' first week. Did the passes and the L: Layout decision move it, and which way?
  5. The numbers: the count from the epic's first bead to now, State<Small>'s size, the non-test lines of the kernel, rules and card crates before milestone 1 and now, and the number of source files between 745 and 800 lines.

File each important finding as a child of this gate, so the families wait for it. A follow-up that is not a defect is filed outside the epic at P3.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.
