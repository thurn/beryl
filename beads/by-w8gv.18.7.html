CardTable::get indexed by name via OnceLock<HashMap>; tests added, pushed 2908be45

Description

CardTable::get scans every card by name; index it (plan: docs/project-50k.md, Milestones, 7a, "the indexed card table"). Fully specified; one file.

The file is rust/crates/beryl_kernel/src/table.rs (the table moved there from beryl_engine/src/table.rs in 137cfc29; beryl_engine re-exports it). It is the only engine-track file M7a edits, and this bead edits only the CardTable struct, new and get in it: the engine chain owns the rest of the file and of the crate, and another session may be working there, so keep the diff to those lines.

Today

pub struct CardTable { cards: &'static [&'static CardDef] }
pub const fn new(cards: &'static [&'static CardDef]) -> Self
pub fn get(&self, name: &str) -> Option<&'static CardDef> {
    self.cards.iter().copied().find(|c| c.name == name)
}

Tables are statics built by the const fn (beryl_cards::CARDS, and small ones in tests: grep CardTable::new), so new must stay const and its signature unchanged.

Do

  • Add a field by_name: std::sync::OnceLock<std::collections::HashMap<&'static str, &'static CardDef>>, initialized with OnceLock::new() in new.
  • get builds the map on first use (one pass over cards, entry(c.name).or_insert(c), so the first card of a name still wins as the scan's did) and looks the name up in it.
  • Nothing may iterate the map: cards() keeps returning the slice, so every order the engine sees is unchanged.
  • No new dependency (the kernel takes none). Keep #[derive(Debug)].
  • A unit test in table.rs: each card of a small table is found by name, an unknown name is None, and of two definitions with one name the first is returned.
  • Leave GameTable alone: its scans are over one game's cards (at most 255).

Verify

cargo test -p beryl_kernel -p beryl_engine -p beryl_cards; just check. Parity (plan K11) at the push: the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds; slow CI's counts lane (just count-gate, bar 405,276,238 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. If the count rises, GameTable::new is calling get inside the measured region: say so in a comment on this bead rather than raising the bar.

Acceptance criteria
