Close reason

Description

Read first: docs/beryl-3d.md 'Hosts' (the headless host) and 'The agent interface' ('Commands', which says just b3d is two programs, and 'What is printed', which bounds a film). The text commands exist in beryl_inspect, with the option parser in its library.

  • beryl_host: Headless, which owns a Client, an offscreen Renderer and the face textures, and has seek, frame and png. It takes a Recording.
  • beryl_3d: a second binary, b3d-render ([[bin]] in beryl_3d's Cargo.toml, src/bin/b3d_render.rs), which depends on beryl_inspect, beryl_host and beryl_render and reads its options with beryl_inspect's parser.
    • png <recording> [--tree] [--crop <locator>] draws the frame at --at. It prints the command that reproduces it, the file's path, and with --tree the tree of the same frame.
    • film <recording> --from <moment> --to <moment> [--frames <n> | --every <duration>] [--crop <locator>] draws at most 24 frames into one PNG, as a grid no wider than 2,000 pixels, each frame labelled with its time in its top left corner. --crop follows one element. With the path it prints one line for each frame: its time and what was moving. Asking for more than 24 frames is an error that says how many the span would make.
    • The labels are digits from a small bitmap font built into this program. Text in the table is another bead's.
    • Every file is written under $BERYL_CACHE/b3d/out/ with a name made from the recording, seat, size, moment and process id, so two runs never share one.
  • The tools package: png and film build and run b3d-render; one line each in just b3d's listing; --help with two examples. Add both to the b3d skill and to rust/beryl3d/AGENTS.md.

Edit-to-output time, as the text commands' bead measured it: after a one-line edit to a function body in beryl_scene, time just b3d png verbs-zones --at 1500ms, five times, with the load. The target is 6 seconds. Report it in a comment and beside the other number in the doc.

Run: just b3d png verbs-zones --at 1500ms --tree; just b3d film verbs-zones --from 0ms --to 3s --frames 12; just b3d lane.

Acceptance criteria

Both commands work in a fresh worktree; the tree at 1500 ms and the PNG at 1500 ms show the same card in flight (a test samples a pixel inside that card's box and finds it is not the table's colour); a film of 12 frames is one PNG at most 2,000 pixels wide with a line of text per frame; two runs started together write two files; beryl_inspect still has no GPU dependency (scene-purity passes); the edit-to-output time is reported.
