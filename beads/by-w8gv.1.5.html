Close reason

Fuzz failures shrink via proptest and print as a replayable scenario (66dd3d56)

Description

Fuzzing today is random-agent games with invariants after each decision (just fuzz, beryl_cli/src/game.rs; beryl_search/tests/games.rs). A failure arrives as a whole game. Add shrinking (plan K12: proptest as a dev-dependency only, never in a hot-path crate's runtime dependencies).

  • Model a game as (seed, decks, a vector of choice indices taken modulo the candidate count). A proptest in beryl_search/tests generates the choices; the property is that every prefix plays without an invariant or reference violation and without a panic.
  • On failure proptest shrinks the choice vector; print the minimal game as a scenario-shaped transcript (beryl_cli/src/transcript.rs has the vocabulary) so it can be pasted into a card's scenarios.
  • Keep the default case count small enough for the fast check's rust lane; just fuzz runs it long.
  • Cargo.toml comment on the dependency says what it replaces, as the existing ones do.

Acceptance criteria

A test with a deliberately broken invariant (behind a test-only hook) shrinks a failing game to a handful of choices and prints it; the normal property passes in just check.

Handoff: rust/crates/beryl_search/tests/shrink.rs adds the property fuzz_games_keep_the_invariants: a game is (seed, Vec<u16> choices taken modulo the candidate count) played under the exact profile with Stops::Forced (the scenario runner's), so a shrunk game prints as a pasteable Scenario. Its setup is at the first priority (hands and libraries as dealt), its actions follow, and the play-or-draw and mulligans go in comments above it. proptest 1.11 is a dev-dependency only (std + handle-panics, failure persistence off, deterministic ChaCha RNG, 12 cases by default, BERYL_FUZZ_GAMES for more; just fuzz now runs --test games --test shrink). Panics are caught in Game::play, so a panicking game still prints. a_broken_invariant_shrinks_to_a_scenario: a check that panics when a card reaches a graveyard shrinks to 8 choices (Strip Mine destroying its own Swamp) and the printed scenario replays decision by decision through Live (names, candidates, hands). New beryl_scenario::script (the inverse of answer) and source (an Action as card-file Rust). Runner::picks and pick_for now call script, so run.rs went from 1139 to 1083 lines (allowlist lowered). Gotchas: State::library is bottom first (the test reverses it, and the replay check catches it if not). The scenario's seed redraws randomness after the setup, so a failure after a shuffle or coin flip may not replay. The land-play invariant shrank only to a local minimum of 17 choices, because proptest removes elements and lowers values but cannot swap passes for a land, so the test uses the graveyard check. Fast check ran 118 s adjusted against its 60 s budget on a machine at load 25 on 18 cores; the slow parts were clippy at 46 s (the new dependency rebuilt it) and tests at 70 s. The two new tests take about 5 s each in debug and run in parallel.
