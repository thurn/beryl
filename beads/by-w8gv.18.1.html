Scope (plan: Card pool pipeline, K2; Authoring tools):

  • just cards (tools/src/beryl_tools/cards.py) reads two decklists today, searches printings at 0.6 s per card and writes a 65 KB data/cards.json the UI bundles (ui/src/cards.ts:3). Move to Scryfall bulk data for the whole in-scope pool (no un-sets, dexterity or Alchemy cards) and build an indexed card store served over IPC on demand; the UI bundle no longer contains card data, and app startup does not read the whole store. beryl_app's art.rs image cache is unchanged.
  • No stub files (K2): an unimplemented card is a record in the store. Nothing here creates a Rust file per card.
  • Specs generate per requested card (beryl_cli/src/specs/mod.rs:46 spawns a thread per card for all cards); tests that iterate every spec are bounded. Split specs/mod.rs under 800 lines while there.
  • CardTable::get is a linear scan (beryl_engine/src/table.rs:24): index it. This is the only file under beryl_engine/src this epic edits; the engine chain owns the rest.
  • just card brief <name>: Oracle text and rulings, the nearest implemented cards (tools/src/beryl_tools/specs.py already ranks by rules text) and the XMage class from $BERYL_CACHE/oracles. Never the Forge script (K16). Its matching-vocabulary-entries part reads beryl_card, so give that bead a dependency on by-w8gv.3.
  • Subtype and counter-kind generation from Scryfall's catalogs changes engine types and belongs to M7b (by-w8gv.13), not here.

Models (2026-11-10, overrides the tier rules above)

Follow the run epic's Models section (by-w8gv), raised at the user's request: tier:fable for every bead that designs or writes rules-engine or game-UI logic, and for this milestone's Warden when its work is engine or UI logic; tier:opus for tooling and infrastructure; tier:sonnet only for mechanical, fully specified work. When unsure between fable and opus for engine or UI work, choose fable.
