Description

Read first: docs/beryl-3d.md 'Rendering' ('The Baseline tier') and 'The frame' (materials, sorting). Check wgpu 30's documentation before writing against it: its API breaks every release (v30 moved present to the queue and made vertex buffer entries optional).

In rust/beryl3d/crates/beryl_render:

  • Renderer::new(device, queue, target_format). The Baseline tier's two pipelines are created here, an opaque one that writes depth and a blended one that tests it, each a single shader choosing its branch from the record's material (table, card, contact shadow, glow for now). Colors are premultiplied, so ordinary and additive shapes share one blend setting. No shader in the opaque pipeline discards a pixel. No pipeline is created after startup.
  • Three meshes: a card as a rounded rectangle of about 40 vertices, the one-pixel strip around it that fades its edge (drawn blended), and a unit quad. The strip's vertices each carry the outline's outward direction, and the vertex shader moves the strip's outer ring one physical pixel outward on screen, using the target's size in pixels from a uniform (doc 'The Baseline tier').
  • The instance layout is the doc's 80-byte Draw: three rows of the transform as Float32x4, uv as Uint16x4, layer with material and flags as Uint16x2 (unpack the two bytes in the shader), tint as Unorm8x4, params as Float32x4.
  • Each material's shading is its own WGSL function named shade_ and the material (shade_table, shade_card, shade_contact_shadow, shade_glow), called from the one fragment entry point. The GPU-count bead counts each function's cost by that name.
  • Clips: a run of records that share a clip index (bits 4 to 7 of flags) is drawn with the scissor set to that entry of Frame::clips; index 0 is the whole target.
  • render(&Frame, &mut target): upload the draw list as one instance buffer unchanged, then one instanced draw per run of records with the same mesh, texture array and clip, in the list's order: the opaque records with a depth buffer, then the blended ones, depth-tested on the table and untested in the flat layer.
  • The card branch samples a layer of a 2D array texture (card backs are a layer of the same array) and multiplies by the tint. No lighting.
  • An offscreen target with readback to RGBA bytes, and write_png.
  • Renderer::headless(limits): creates an adapter and device with no surface. With Limits::downlevel_webgl2_defaults() it is the floor's feature set.
  • Until the face pipeline bead lands, fill the face array with generated placeholder faces (a flat color per card and a name-hashed stripe), so cards are tellable apart.

Tests in beryl_render/tests, all offscreen: a scene of three solid quads is drawn and five sampled pixels are within 2/255 of the expected colors; the nearer card covers the farther where two overlap, whichever was drawn first; a mark on a covered card is hidden with it; a 600-card frame draws in at most 6 draw calls; every test also runs on a device created with the downlevel limits and gets no validation error.

The tests need a GPU adapter. On this Mac Metal works with no window. Other machines are for the cross-target bead and the spike bead to report on.

Run: just b3d cargo-test -p beryl_render.

What the prototype found (rust/prototypes/beryl3d, 2026-11-14; read its code for a working example, then build it properly):

  • The prototype's src/render.rs and src/shader.wgsl are a working Baseline renderer against wgpu 30.0.2 and took a few hours: easier than this bead assumes. API points that differ from older wgpu: queue.present(frame); surface.get_current_texture() returns the CurrentSurfaceTexture enum; device.push_error_scope(filter) returns a guard whose pop() is the future; RequestAdapterOptions gained apply_limit_buckets (use ..Default::default()); get_mapped_range() returns a Result; PollType::wait_indefinitely(); InstanceDescriptor::new_without_display_handle() for no window; PipelineLayoutDescriptor { bind_group_layouts: &[Some(&layout)], immediate_size: 0 }.
  • WGSL allows textureSample only in uniform control flow, and the material varies per instance: sample before branching (the doc's 'Rendering' now says so).
  • A card's back is the layer in the record's uv[0], chosen with front_facing, u mirrored.
  • Depth32Float and everything else here drew on a device with Limits::downlevel_webgl2_defaults() with no validation error.
  • The '600-card frame in at most 6 draw calls' test will see 2 if the table and shadows use the card mesh.

Acceptance criteria

A hand-built frame of twenty cards, three of them lifted, is drawn offscreen to a PNG with the cards in perspective and contact shadows under the lifted ones; the pixel-sample and downlevel-limit tests pass; no wgpu type is named outside beryl_render.

Each run binds the instance buffer at its offset and draws from instance 0 (GLES has no first instance). Contract changes in beryl_scene: Frame.layer (start of flat layer, set by FrameBuilder from the first band >= Layer, or len) and Frame.view_projection (FrameBuilder::camera; Table::write sets it); Draw::edge(); Draw derives bytemuck Pod. Colors are sRGB values blended as stored (target Rgba8Unorm, faces Rgba8Unorm). One-layer arrays are padded to two (GL). Doc 'The frame' and 'The Baseline tier' updated.
