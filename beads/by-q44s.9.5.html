Description

Read first: docs/beryl-3d.md 'Timing a script' and 'Timeline parity'; tools/src/beryl_tools/beryl3d/timeline.py (compare, agree, run_parity); beryl_scene's src/beat.rs (the port of laid in ui/src/stage/beat.ts) and src/play (the table a script plays over); and the web interface's side, ui/scripts/timeline.mjs and ui/src/stage/beat.ts.

data/beryl3d/timeline-parity.json lists the recordings whose Beryl 3D timeline (just b3d timeline <recording> --seat <seat>) does not yet agree with the web interface's, with the number of differing steps. This milestone's exit check needs it empty.

For each recording below: run just b3d timeline-parity <recording> to see the steps that differ, find the cause in beryl_scene (most likely beat laying a beat out in time, or a step the client makes itself while a prompt is open, marked "own": true), fix it in beryl_scene, and run just b3d timeline-parity --update to lower or remove the entry. Never change rust/crates/beryl_protocol/src/script/timing.rs or the web interface for this (rule 5); if the web side is wrong, file a bead under by-q44s.9 saying why and leave that entry.

Where a difference comes only from the layout rule the doc names in 'Timeline parity' (a beat lasts until the cards that close up are at their new places, and the web holds a strike back while it would cross an earlier one), do not copy the web's layout. Instead, in timeline.py, make compare accept that one class of difference, recognised from the two timelines alone (state in a comment exactly what is accepted and why), add a test for it to tools/tests/test_beryl3d.py's timeline tests, and change the doc's paragraph to say such recordings are accepted rather than listed. Only the first bead of the lane that meets this case makes that change; later beads reuse it.

Add each fixed recording's broken state as a test only if no interface test already plays it (rule 7). Run: just b3d timeline-parity <recording> for each, just b3d timeline-parity --fixtures, just test-py tests/test_beryl3d.py.

Before enact push: run just b3d cargo-test and just b3d test yourself, because the fast check can cut them at its time limit. Tests in beryl_inspect locate elements by role and name, never by numeric id. Do not re-pin limits in data/beryl3d/gates.json by hand.

This bead's recordings (seat and steps differing, as listed on 2026-11-16): combat-attackers/opponent 24, combat-attackers/you 6, combat-declare/opponent 2, combat-declare/you 2.
