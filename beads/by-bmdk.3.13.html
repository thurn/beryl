Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'Drag' and 'Placement', and the appendix tables under 'Moving a card'.

How interface beads in this milestone fit together: ui/src/table/client.ts (bead "Table screen") is the manual table's pointer client. It owns the selection, sends actions with tableAct from ui/src/ipc.ts, and lets each interaction register handlers from its own file. Put your code in the file this bead names and register it; change client.ts only to add a registration point it lacks. Check your work on a live manual table in a headless browser: ui/scripts/table.mjs (same bead) starts one through the HTTP server and gives a Playwright page. Add one scripted check per behavior to ui/scripts/kept-table-<topic>.mjs and run it with just ui-test <title>.

File: ui/src/table/drag.ts and DropTargets.tsx.

  • holdable: any card the viewer may act on (their own hand, any public card, a revealed or lent hidden zone's cards). A drag picks up the card under the pointer, or the whole selection if that card is in it (the others follow as a stack; draw them with the same held pose offset by a few pixels each).
  • Drop targets: each battlefield side and row, a hand the dragger may act on, the stack, and each library, graveyard and exile pile. Light the target under the held card using the pointer's held-over event.
  • A library under a dragged card shows two halves, top and bottom; dropping on one sends move with that position.
  • Dropping more than one card on a library opens the ordering tray engine games use (ui/src/stage/Tray.tsx, tray.ts), filled locally with the dropped cards; confirming sends one move with the chosen order. No host prompt is involved.
  • Shift held on release drops the card face down. Dragging from a pile takes its top card; Option held takes the bottom card.
  • On the battlefield (doc, Placement): between two cards of its row is reorder; another row on its controller's side is pin; the other player's side is give; onto a permanent, for an Aura, Equipment or Fortification, is attach; dragging an attached card off its host is unattach. A drop on a viewer moves the card to that zone.
  • A drop that is taken returns true from the pointer's drop so the card stays where it was let go until the update arrives and the stage settles it; a drop on nothing glides back. A refused drop shakes.

Checks (kept-table-drag.mjs): hand to library top and bottom; two cards to library opens the tray; reorder; pin a land to the creature row; attach and unattach; give control (use a two-seat table if table.mjs can start one yet, otherwise check the action sent); a drag out of a zone the viewer may not touch is not picked up. A fixture or kept moment with a card held over a library (two halves visible) for the generic audits. data/ui-conventions.json: no-equivalent, "Library drop halves".

Acceptance criteria

Every drop in the doc's Drag and Placement sections sends the right action and has a headless check; multi-card library drops use the ordering tray; the two-halves state is under the generic audits.

Handoff: TableDrag and DropTargets handle drag sources, target overlays and the local library order tray. dropActions.ts builds the typed actions from the held view, and dropZones.ts maps desktop rows, phone bands and zone viewers. TableView.seat exposes the absolute guest seat for destination actions while older and solo views default to zero. The CLI only starts solo sessions, so the two-seat headless check supplies a guest projection and verifies the give request and the inaccessible library. Mixed-source selections require one move per contiguous source-zone group in an atomic batch; a single-source library selection sends one move. The Arena recording directory was unavailable on this host; the library order tray uses the existing Beryl tray layout and the wording documented in UI Conventions.
