Decision: no test deleted, because the flaky test cannot be identified; the step now names its tests (2ff11003). The flake happened on Cygnus (by ci at 4c90f19f72, tree 596a9b4d). The step reported no checks of its own, so the run log held one 'python:pytest' record, and the step's output is kept nowhere reachable from JARVIS. Cygnus has no SSH entry, and no bead carries its output tail. JARVIS's CI log shows only two pytest failures, test_scale clone-renames and test_warm tauri-target; each failed again on its rerun, so both were real. Reproduction: 12 runs of the full suite with -n 4 at load 13–20, all passed. Change: tests/conftest.py now reports each test to $BERYL_CHECK_RESULTS as '<lane>:<node id>' (python_tests.LANE_ENV carries the lane; the scale lane passes --lane scale). reruns.failed_pytests narrows the one rerun to the failed node ids, and runs the whole suite on a collection error. The next flake of a Python test will name its test, flaky.py will file a bead for that exact check, and the rerun costs seconds instead of the whole suite. Verified: a temporary test that fails once produced 'flaky: python tests/...::test_once' after a narrowed rerun. The full suite reported 523 passes. Tests: test_a_pytest_rerun_runs_only_the_tests_that_failed in tools/tests/test_runlog.py. Handoff: runs.jsonl gains about 520 records per python-lane run (the rust lane already logs far more). If a pytest flake recurs on Cygnus, its bead will now name the test.
