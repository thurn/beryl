Close reason

One 0.7em rules text size for every card, centered from the left, fit by useRulesFit; hand/graveyard art and text overrides removed (b4770fc)

Description

The docs/ui_mockups images are generated references, not a pixel spec: they are not consistent with one another, and earlier pixel-matching work fitted code to each one separately. This bead removes one such fit. Prefer one rule that holds in every state over matching any single mockup. just ui-compare verdicts for the affected regions may get worse; that is expected, so do not tune values back toward the mockups.

ui/src/components/Card.tsx's SHORT_TEXT = 30 is a cutoff: rules text of 30 characters or fewer is centered at 0.86em (.card-rules-short), and at 31 or more it is set top-left at 0.86 × 0.7em (.card-rules:not(.card-rules-short) in components.css), about 30% smaller, on top of useRulesFit, which already shrinks text that does not fit. Counterspell set one side of the cutoff and Doom Blade the other. Use one text size and alignment for every card and let useRulesFit do the shrinking (centering short text is fine if it does not change the size).

Related per-place overrides in screens.css to fold into the same rule: .pile-card .card-rules (bold 0.6em text on a graveyard's top card, after battlefield.png's Doom Blade) and the .hand-card .card-art flex-basis values that size art differently for lands and nonlands in hand. A card in the hand, a graveyard or the stack should read like the same card anywhere: scale the whole frame, not individual parts.

Acceptance criteria

No character-count cutoff decides rules text size; graveyard and hand cards scale as whole frames with no per-place text or art overrides. just check and just ci pass, with no new constants tuned to a single mockup.
