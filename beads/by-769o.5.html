Close reason

Run log records cpu_seconds per check via wait4 (511cb08d, 82ecf8c7)

Description

Why

The Mac is never quiet (load average around 20-40 is normal), so a check's wall time, and the load-adjusted seconds from clock.py, mostly measure the other work on the machine. The CI budget detector (a later bead in this epic) needs a cost per check that load barely changes: CPU time.

What to change

  • For every step checks.py runs, record the CPU time (user plus system) of the step's whole process tree, and write it to each of the step's rows in $BERYL_CACHE/ci/runs.jsonl as a new field, for example cpu_seconds. resource.getrusage(RUSAGE_CHILDREN) before and after the step counts children that have been waited for; check that it also counts grandchildren such as cargo's rustc processes and headless browser pages, and fall back to the per-process sampling in cpu.py where it does not.
  • Where one step runs many checks (for example ui-test or nextest), split the step's CPU time across its checks in proportion to their wall time, and say so in a comment.
  • Keep seconds as it is.

Files and tests

tools/src/beryl_tools/checks.py (Steps.run), tools/src/beryl_tools/runlog.py, tools/src/beryl_tools/cpu.py, tools/tests/test_checks.py, and a test in tools/tests/ for the runlog field. Windows (Cygnus) has no resource module: record nothing there, or use a portable source.
