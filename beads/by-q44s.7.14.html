Description

Review the phone hosts of milestone 4: rust/beryl3d/crates/beryl_3d/src/ffi (mod.rs, android.rs), include/beryl3d.h, beryl_host/src/phone.rs, the low-memory changes in beryl_scene (faces.rs, client.rs) and beryl_render (renderer.rs, faces.rs), the Swift host in rust/beryl3d/crates/beryl_3d/ios, the Kotlin host in rust/beryl3d/crates/beryl_3d/android, and tools/src/beryl_tools/beryl3d/phone.py and sweep.py, against docs/beryl-3d.md 'Hosts', 'Threads', 'Card faces' and the epic's rules. Fix what you find, with tests.

Look hardest at:

  • No game or layout logic in a host. Every decision is in Rust. A Swift or Kotlin line that chooses what a touch means, positions anything but the native text field at the rectangle it was given, decides what Back does, filters or reorders inputs, or keeps game state is a defect: move it into Rust.
  • Every unsafe block in src/ffi: its comment says which pointer it trusts and why, and the header's comments promise the same lifetime (the request's text pointer until the next call; the surface until beryl3d_surface_lost; the wake context for the app's life).
  • A C value that can become an invalid Rust enum, an id over 255, a NULL string where the header allows one, or a negative size.
  • The wake callback: it is called from other threads; the host hops to its main thread before touching the link or the Choreographer; it cannot be called after the app is freed; on Android the JNI thread attachment does not leak a thread per call.
  • Ticks while idle: a host that keeps calling beryl3d_frame on every display tick when the library said never, or that misses a wake and leaves the table frozen after a session update.
  • The frame rate the library asks for: applied once per change, not every frame; Android below API 30 relies on the library's skipped ticks.
  • Suspend: no beryl3d_frame between surface_lost and the next surface (iOS forbids GPU work in the background; Android's surface is gone after surfaceDestroyed returns); the GL path's EGL surface recreated on the same context.
  • Low memory: full-size faces dropped and board-size kept; the tier never rises again after it; nothing allocated on the frame thread to do it.
  • Touch ids: freed on end and cancel, the lowest free id reused, two fingers never sharing one.
  • Text entry: the field removed on EndTextEntry, and on suspend; the keyboard's height reaching the library as an inset, not by moving anything in the host.

Run: cd rust/beryl3d && cargo test -p beryl_3d -p beryl_host -p beryl_scene -p beryl_render; just test-py tools/tests/test_beryl3d_phone.py. Review the Swift and Kotlin hosts by reading them; nothing runs in a simulator, emulator or phone.

Acceptance criteria

Problems found are fixed with tests; a comment on this bead says, for each host, that it holds no game or layout logic and how that was checked, and lists every unsafe block in src/ffi with the pointer it trusts.

Warden review of the phone hosts and C functions.

No game or layout logic, per host (checked by reading every line of each host file):

  • iOS (ios/Beryl3D/App.swift, Table.swift, Touches.swift, TableRequests.swift): it passes the layer, size, nativeScale and safeAreaInsets as given; each touch with an id and phase; lifecycle notifications; and CACurrentMediaTime. It applies the wake's hz to preferredFrameRateRange only when it changes, and pauses the link for NEVER or with a timer for a distant AT. perform() only carries out share, haptic and URL. Nothing chooses what a touch means, positions anything, filters or reorders inputs, or keeps game state. TouchIds gives the lowest free id from 1 to 255, frees it on end and cancel, and never gives two touches the same id. Coalesced touches are not sent, which is delivery, not filtering.
  • Android (MainActivity.kt, Touches.kt, Native.kt, PlatformRequests.kt): the same plumbing. Back is passed as BERYL_KEY_BACK down and up; Rust decides what it does. Insets are converted from pixels to points and passed. Touches.kt frees ids on UP, POINTER_UP and CANCEL and reuses the lowest free one. setFrameRate is applied once per change (lastRate, reset on surfaceDestroyed); below API 30 it relies on Phone's skipped ticks. No frame runs between surfaceDestroyed and the next surface: stopFrames, plus requestFrame and doFrame require currentSurface and resumed. The EGL surface is recreated on the same device (Renderer::attach).
  • Wake: iOS hops with DispatchQueue.main.async; Android's Waker posts one Handler runnable per batch. Neither misses a wake: a wake that lands during a tick runs after it and unpauses. The app is never freed, so the wake cannot outlive it.

Every unsafe block in src/ffi and the pointer it trusts: mod.rs

  • unsafe impl Send/Sync for HostWake, HostWake::call: the host's wake callback and context, callable from any thread for the process's life (the header now says so).
  • Beryl3d::surface: the native surface, valid until beryl3d_surface_lost.
  • beryl3d_new: config and its strings, valid for the call. optional: a C string, NULL or NUL-terminated for the call.
  • beryl3d_surface, surface_lost, lifecycle, frame, pointer, key: app from beryl3d_new, used on one thread. beryl3d_text: app plus the UTF-8 string for the call. beryl3d_next_request: app plus out, writable. Request text stays valid until the next next_request or frame call, as the header says (in fact until the next next_request).
  • beryl3d_offscreen, beryl3d_close (tools feature only): app; close gives it up. types.rs: the test's CStr::from_ptr(out.text), which points into a live CString. android.rs
  • Window::drop: the ANativeWindow reference from ANativeWindow_fromSurface, released once.
  • string, optional, utf16: the JNI env of the calling thread and a live jstring.
  • unsafe impl Send/Sync for Waker, Waker::new, wake, env, Detach::drop (new): the JavaVM, a global reference (never deleted, since the app lives for the process) and a method id, valid on every thread. env() uses GetEnv first and attaches only an unknown thread, once per thread.
  • Native_create: env, strings and the waker object. Native_surface: app and a live Surface, whose window reference Window holds until surface loss. surfaceLost, lifecycle, frame, pointer, key: app. text: app and a non-null jstring (Kotlin's parameter is String). nextRequest: app and a float array of at least 4. requestText: app.

C values: every enum goes through a match and unnamed values are dropped. The id is held to u8. Width and height are u32 (Android uses max(1)), and the renderer clamps 0 to 1. NULL fixture and stand_in are allowed; a NULL data_dir becomes "". display_hz is sanitized in Phone::new.

Fixed (one commit):

  1. Android Waker attached threads and never detached them. ART aborts the app when an attached native thread exits (the session thread, or the live connection threads that live.rs starts for each connection). A thread-local Detach guard now detaches on exit.
  2. Android recreated the activity on config changes that configChanges does not cover (locale, font scale), and that called Native.create again: a second game, with the first leaked and still running. The app now lives in a process-wide Library object in MainActivity.kt.
  3. A scale that was zero, negative or NaN, or a NaN or negative inset, reached the client. surface_from_c now replaces them, and pointer_from_c drops non-finite positions. Both are unit-tested in types.rs.

Left alone:

  • Text entry: neither host has a native field. BEGIN_TEXT_ENTRY and END_TEXT_ENTRY are logged and ignored, because by-q44s.7.10 was dropped (no phone testing). So "field removed on End and on suspend" and "keyboard height as an inset" do not apply yet.
  • Low memory: Renderer::low_memory makes a 4x4 token texture on the main thread, which is the frame thread on phones. It is a tiny GPU object, not a reallocation of faces. The tier stays Baseline after LowMemory (Client::low_memory).
  • iOS low memory in the background calls Renderer::low_memory, which creates resources but submits no GPU commands, and iOS allows that.

Verified: cargo test -p beryl_3d -p beryl_host -p beryl_scene -p beryl_render passes; test_beryl3d_phone.py passes (10); clippy -D warnings passes on the host and on aarch64-linux-android for beryl_3d (with missing_const_for_thread_local allowed, a false positive in beryl_assets on that target); the Android library and APK build with gradle. Nothing was run in a simulator, emulator or phone, as the bead says.
