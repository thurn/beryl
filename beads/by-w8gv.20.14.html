Close reason

bisection records selection misses (cut/not chosen/unknown); ci-report prints misses per 100 landed commits (bc0db0ff, e35c9c58)

Description

Add the selection-miss verdict (plan K18; docs/project-50k.md, Target architecture, Checks, "Verdicts": "Selection miss: slow CI failed a check the fast check did not choose"). Step two of the CI track (by-w8gv.20). Builds on the selection bead (per-check chosen in runs.jsonl) and the bisection bead (the culprit commit).

What

  • When bisection names a culprit commit for a check, look up that commit's fast-check run in runs.jsonl (script check, its tree or commit). If the check was not run there (absent, or chosen: cut), or no fast-check run of the commit is in this host's log, record verdict miss on the check's ci-check bead (verdicts.STORE.record, steward set as for other slow-CI verdicts). Add miss to verdicts.VERDICTS and to just verdict. A miss is recorded beside the later stale or catch verdict, not instead of it.
  • Print miss: <check> (fast check at <sha> did not choose it: <reason>) in the bisection block.
  • just ci-report counts misses per check and prints misses per 100 landed commits over the window, the number the epic's acceptance uses ("if selection misses are under 1 per 100 commits").
  • A culprit commit whose fast check ran on another host (no record here) counts as unknown, not miss. Print it.

Files

tools/src/beryl_tools/verdicts.py (VERDICTS, STORE, settle), runlog.py (Tally, report), checks.py or bisect.py (the bisection block), cli.py.

Tests

pytest: a culprit whose fast run chose the check (no miss), one that cut it (miss), one with no record (unknown); ci-report's per-100-commits figure.

Acceptance criteria

A bisected culprit whose fast check did not run the check records verdict miss on its ci-check bead and prints a miss line; just ci-report shows misses per 100 commits; pytest covers chosen, cut and unknown.

Deviations: (1) the description both says a culprit with no fast-check record here is a miss and that it is unknown; followed the acceptance (chosen, cut, unknown): no record = unknown, nothing recorded. (2) The miss entry carries no 'steward': the Steward bead is filed only after by ci exits, so it cannot be known at bisection time; the entry carries 'bead' (the culprit's delivering bead), 'fast' (the fast check's commit) and 'chosen' (why: cut, not chosen, skipped, its <lane> lane did not run) instead. (3) enact push runs the fast check at the pushed tip, not at each commit, so the lookup takes the first fast-check run at the culprit or a later commit that the culprit's bead delivered (by commit or tree); a later push's run is never used.
