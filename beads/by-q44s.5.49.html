Close reason

Description

The web interface now prepares every manual table in a lobby (ui/src/screens/Lobby.tsx, ui/src/table/lobby/TableEntries.tsx, commit fb79cc146): 'Solo table' calls tableLobby({kind: 'solo'}) and the lobby loads a deck, sets assists and starts the table. Beryl 3D's start screen instead starts a solo table directly with TableConnections::solo and the sample WU Control deck (beryl_scene src/manual/mod.rs solo_request, src/client/manual.rs start_table), because it has no lobby screen.

Build the lobby screen in beryl_scene (a new Screen or a table sub-screen; see src/screens/table.rs and the start screen src/screens/start.rs): SessionCommand variants for TableConnections::lobby (TableLobbyRequest with LobbyChange: View, Solo, LoadDeck, Sideboard, Ready, SetAssist, Settings, Start), answered on beryl_3d's session thread (src/session.rs Live, which already holds a TableConnections), the lobby's LobbyUpdate events reaching the client (Live::new passes |_| {} for table events today), and the 'Solo table' press going through the lobby as the web's does. Host and join need the link and are out of scope unless the web's lobby screen offers them without one.

Read first: docs/manual-multiplayer.md (lobby), rust/crates/beryl_table_session/src/connections.rs (lobby), rust/crates/beryl_protocol/src/ipc/table.rs (LobbyChange, LobbyUpdate), the lobby commands of data/table-commands.json (scope lobby; beryl_scene src/manual/commands.rs COMMANDS has them).

Acceptance criteria

Decisions: (1) The lobby is a new Screen::Lobby (screens/lobby.rs, client/lobby.rs, manual/lobby.rs). 'Solo table' sends SessionCommand::TableLobby(LobbyChange::Solo); the session thread forwards TableEvent::Lobby as Input::Lobby. A LobbyUpdate with no view switches Lobby -> Table; one with a view switches Table -> Lobby (after Next game). take_session no longer switches away from the lobby, because a solo table sends its table view while still in its lobby. (2) Beryl 3D has no deck picker or deck import, so 'Change' (Cmd+O) loads the sample WU Control deck (manual::solo_request). Paste decklist, file and saved-deck pickers, and the sideboard swap are not built. (3) Host and join need the link and are out of scope; the web's lobby offers them only from the start screen's TableEntries with a link, so nothing here builds them. The Match section (seats, invite code, score) is built and shows once a lobby has two seats. (4) Game settings: two number fields whose placeholder is the current value, and 'Save settings'; 'First' is shown, not chosen (a solo table has one seat). (5) No bundled font has U+2713, so the start screen's Fair deal tick never drew; the shared checkbox now draws a filled gold square. The bug report's AI box and checked menu rows have the same missing glyph (follow-up filed). (6) LobbyChange gained Clone, PartialEq, Eq so SessionCommand can carry it.
