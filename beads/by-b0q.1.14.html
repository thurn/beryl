Warden review of b8fddaf (by-b0q.1.5), on staging 235cd13.

Verified by running: just test-rust green (strict-runner failure tests, every card's scenarios, dump test); cargo run -p beryl_cards --bin beryl_scenario -- dump PATH writes JSON that python parses, 3 entries (Plains, Island, Tundra); fuzz/determinism/info-independence/perf-count tests 0.7 s in debug; allocations binary reports 0 allocations; just fuzz 1000 passes in ~10 s. No wall-clock thresholds: perf bands are deterministic counts, stall rate is a count.

Fixed in 71f99eb:

  • The scenario runner never checked State::check_invariants; setups bypass the rules (place/set_tapped/order_library), so a bad setup or rules path could pass silently. It now checks invariants at every new position and fails the scenario on a violation.
  • Assertion::Tapped compared the base Object.controller; since by-b0q.1.7 control is the layer-2 result (State::controller). It now reads s.controller(slot), and refuses after game over, where derived may be stale.
  • AdvanceTo stopped at any priority in the target step, including the non-active player's after the active player passed; it now stops only at the active player's priority (as documented), and passes via the explicit Opt::Pass rather than assuming Choice(0).
  • State::begin_at now refuses Untap and Cleanup (CR 502.4, 514.3: no priority there) and an out-of-range active player.

Left alone: tests are black-box and catch real regressions (the executor's mutation checks confirm); RandomAgent and determinize are sound. Note for the bead that adds face-down exile: invariants treat Exile as public (known to both), which face-down exile (known to owner only, section 13) will contradict.
