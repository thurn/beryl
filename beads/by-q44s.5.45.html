Close reason

The live socket test waits for the first rendered frame and verifies the initial board without polling.

Description

Symptom: the fast check failed on beryl_3d::all live::a_running_app_answers_tree_do_and_png (27 s, load average 27 on 18 cores) during the push of by-q44s.5.9, then passed alone in 2.8 s. Why: rust/beryl3d/crates/beryl_3d/tests/all/live.rs polls the app's tree 400 times with a 50 ms sleep (a 20 s bound) for the 'Auto Pay' button while the app's clock runs in real time to --pause-at prompt:2; under load the app takes longer than that to reach the pause. That makes the test depend on machine speed, which the epic's rules forbid. Fix: wait on something the app reports (for example a 'paused' line on its stdout, or a socket request that blocks until the pause is reached) instead of a count of sleeps, keeping only a generous hang bound; or delete the test if no such signal can be added cheaply. Files: crates/beryl_3d/tests/all/live.rs, the live socket code in crates/beryl_3d (grep LIVE_SOCKET).
