Close reason

beryl3d --agent plays a whole game unattended; Measurements gives search throughput and late frames (budget not met: by-q44s.1.60)

Description

docs/beryl-3d.md 'Threads' sets the budget for the search threads' scheduling class (decision C9): with the table still, search throughput stays within 2% of what the current app achieves, and the app's frame log shows no late frame while the AI thinks. Nothing has measured it in Beryl 3D. by-q44s.1.16 could not: beryl3d --window none resumes the newest unfinished game (Live::begin in rust/beryl3d/crates/beryl_3d/src/session.rs), which waits for the player, and nothing answers for the player in a run with no window, so the AI never searches.

Do: give the app's tools build a way to play a whole game with an agent answering for the viewer (for example --agent <name>, starting a fresh game whose viewer seat an agent of beryl_session::agents() plays, as the prototype's 'live' board did with mcts-hidden against expert). Then measure, five runs each with the load beside them: (1) search throughput (iterations or rollouts a second, from the search's own counters) with the table still, in Beryl 3D and in the web app's session with the same agent and seed; (2) the frame log's late frames and the frame thread's worst client and encode times while the AI searches, with --load off and on. Write the numbers into 'Measurements' and say whether the budget is met.

Acceptance criteria

The app's tools build can play a whole game with no person; docs/beryl-3d.md 'Measurements' gives search throughput in Beryl 3D against the web app's and the late frames while the AI searches, five runs each with loads, and marks the 'Threads' budget met or names the bead that fixes it.

Handoff: beryl3d --agent <name> (tools feature; also --opponent, default mcts-hidden, --seed, default 20261114, --search-class) starts a fresh game the agent plays for the viewer, keeps no replay, and ends the run at game over through the new Feed::ended (beryl_host frames.rs; FrameLoop::driven_to_end renamed at_end). The session thread's class is a parameter of session::spawn; Session::end runs when Commands drops (Drop now joins the thread) and Live prints search_report (rollouts and engine steps a second over Sessions::agent_moves, the latest 200). The frame log's Summary.searching counts frames, late frames and worst client/encode while the view said Thinking; Run.game records the game. Measured from a release build with tools, 5 rounds x 4 configurations (driver kept only in the session scratchpad): utility searched at a median 0.88 of default's rate, so the budget is not met (by-q44s.1.60); late frames show up in every run whatever the class, at loads 41-77. Live play first crashed the client: unnumbered abilities in the table built by Played::of(before); numbered by place now (numbered in beryl_scene compile.rs), with the real fix filed as by-q44s.1.59.
