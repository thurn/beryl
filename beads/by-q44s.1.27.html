Warden review (staging afcc42ceb): no problems found, no code changed.

Before/after comparison. I recorded fixtures with the current beryl_cli, then played each one through a ScriptStage on a held clock twice. The first run used ui/src from f85506675 (the commit before the lane's first, a58a6a678), with the old timingOf and effectsOf. The second used ui/src at the staging tip, which plays the sent timing. Both runs used the same layout (stage-table row) and called settle() after each view. I compared every start and end edge from stage.follow, plus each step's effects (name, layer, edge, target, duration, delay, and the easing sampled at 0.25/0.5/0.75).

  • The five fixtures (with view and edge counts): verbs-combat (36 views, 136 edges), verbs-zones-theirs (51, 250), stack-counter (15, 78), late-game (209, 1004) and choice-trigger-order (338, 1056).
  • Three extra fixtures: arrow-spell, arrow-player and verbs-burn-theirs. arrow-player covers an arrow at a player, whose name the new playedOf filters out of after.
  • Result: the step times and effects were identical, 2,550 edges plus 64 in the extra pair. As a mutation test, scaling the sent duration by 1.01 changed 2,531 of the 2,550 edges, so the comparison does catch differences.

Own steps. All 15 own_timings entries match what the old timingOf and effectsOf gave a prompt's act of the same shape. The fields compared were duration, delay, stagger, easing, with, hold, leads and effects. afterEnds is true exactly where the old after was not empty. The only differences were a flag left unset versus false, and key order.

Other leads checked:

  • No TypeScript or Python chooses a case. Case names appear under ui/src and tools/ only as protocol enums, mark kinds or the vanish closes constant (CLOSED in tracks.ts, which reads the data). motion.py only reads step.case.
  • Every Script the code builds is timed last: Screen::script (after PLANTED, then verify), Screen::reset, Follow::restart, beryl_table_session's normal path and its reset. The one exception is fixture prop::after, which has no steps and so no timings. Nothing in the builder changes the script after .timed.
  • Follow::play checks the timing length in every build, and spec serving and describe go through it. Debug builds check it in verify and reset.
  • timing.rs and conventions.rs contain no numbers except 0 and 1 defaults: every value is read from data/ui-conventions.json.
  • OwnStep covers every act prompt.ts makes. prompt.ts never points an arrow at the stack, as 1.25's handoff says.
  • main.tsx waits for stageTimings before the first render, and the fixture, spec and live transports all answer the command.

The tests are black-box and test behavior. I pruned none.

Checks run: just test-rust -p beryl_session (340 passed), just ui-typecheck, just ui-unit (313 passed).
