Description

Beryl missed mana value 0 for a nontoken permanent copying a transformed back face (by-ptc7.1.14). XMage’s CleverImpersonatorTest.testCopyPlaneswalker has the right setup with transformed Liliana, but asserts loyalty and presence. TokenCopyTest.testCopyTransformedDFC asserts the right mana-value distinction for token copies. Beryl’s oracles currently replay Beryl-authored scenarios, so they only compare what those scenarios assert.

Investigate a coverage-driven way to discover upstream tests worth adapting. Start with the XMage test suite at Beryl’s pinned revision. Compare a small, source-linked manifest with extracting card references, actions and assertions from supported upstream test shapes. Match requirements against Beryl’s card registry and scenario/export capabilities. A card landing, an oracle pin moving or a new scenario assertion becoming supported should surface newly eligible tests. Distinguish tests ready to replay from candidates missing card support or faithful action/assertion translation, and report the reason. Preserve the rules fact an imported test checks, including outcomes that depend on the precise value. Inspect Forge’s test suite for comparable fixtures and use Forge only as a test oracle. Start from tools/src/beryl_tools/{oracles.py,xmage_export.py}, rust/crates/beryl_scenario_types/src/lib.rs and the two named XMage tests. Coordinate with by-ptc7.1.14 for the existing fix, and with the Part II card workflow for the cheapest discovery hook.

Acceptance criteria

Document the tradeoffs and demonstrate a small reproducible pilot. Show that a candidate with missing card coverage is surfaced when its last required card becomes available, and that unsupported actions or assertions remain visible with a reason. For the copied-back-face case, show which upstream tests are reusable and demonstrate that an adapted regression with the original and nontoken copy mana values distinguishes the buggy behavior from the correct behavior. Name the upstream tests and pinned revisions, report the pilot’s runtime and limits, and identify the smallest integration point for future card additions.
