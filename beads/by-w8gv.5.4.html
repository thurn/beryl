Close reason

Zones, battlefield order, knowledge and the derived cache are crate-private behind ZoneKey accessors and mutators; the engine no longer writes derived_dirty; counts 404,476,069 -> 404,167,248

Description

Milestone 3 (plan K6, K7): the zone structures, the battlefield order, what each player knows and the layer cache become private to the kernel, and zones are keyed so a command zone and shared zones are possible.

Read first

docs/project-50k.md: Decisions K6, K7, K11 and K12, and "Crates", "State" and "Kernel rules" under Target architecture. rust/crates/beryl_kernel/src/lib.rs: its rustdoc is the kernel's API contract (who writes, mutator and getter naming, events, the board door, the legacy accessor, sets and orders); follow it, and change it in the same push when the code proves it wrong. enact brief shows the handoffs of the beads this one depends on.

Scope

  • Zones<L> (members per owner and zone, the stack bitboard, the library and graveyard queues, next_timestamp), State::battlefield, State::derived, State::listening, State::knowledge.
  • Raw uses in rust/crates/beryl_engine/src when this was decomposed (grep \.zones\b, \.battlefield\b, \.derived\b, \.knowledge\b): zones in effect.rs 2, face_down.rs 2, sba.rs 1, start.rs 4; battlefield in combat.rs 21, turn.rs 7, layers.rs 6, mana.rs 5, cast.rs 3, sba.rs 3, event.rs 2, trigger.rs 2; derived in cast.rs 8, combat.rs 7, mana.rs 7, layers.rs 4, event.rs 2, sba.rs 2, trigger.rs 2; knowledge in resolve.rs 6, effect.rs 2, face_down.rs 2, layers.rs 1; listening in layers.rs and trigger.rs. Most reads have an accessor already (battlefield(), derived(slot), zone(owner, zone), library(player), graveyard(player), knows(player, slot)).
  • The moves themselves are already kernel code (zone.rs: move_to_place, leave, draw, reorder_library, shuffle_library, rebind, cease_to_exist). Make them the public mutators the contract names. Mason note 6 on by-w8gv.5.1 is not this bead's (the stack queue is the by-w8gv.5.8 (stack and pending) bead's).
  • The derived cache: layers.rs computes Derived and the listening mask, the kernel stores them. Give layers.rs one way to store a recomputation and clear the dirty flag, and make every kernel mutator that invalidates the cache set the flag itself, so beryl_engine no longer writes flags.derived_dirty (today event.rs, layers.rs, mana.rs, sba.rs, trigger.rs, turn.rs, effect.rs and face_down.rs touch flags).
  • Knowledge: looking at, revealing and forgetting cards (CR 400.2, 701.20) as mutators. resolve.rs's Resolving::knowledge snapshot and restore go through them.
  • Zone keys (K7): today zone(owner, zone) and members: [[Bitboard; Zone::OWNED]; 2] give every zone an owner, and emblems live in Player::emblems. Key the accessors so that a zone with no owner (the stack, the battlefield and exile as the rules see them, CR 400.1) and a command zone (CR 408) can be named without another signature change. The contract or the key's rustdoc says how each would be added. Add neither.

Constraints

  • These accessors return Bitboard. Leave its API alone: the by-w8gv.5.6 (order-free sets) bead changes it.
  • combat.rs, mana.rs and cast.rs read the battlefield and the cache in the rollout's hottest loops. Run just bench-count before and after and record both.
  • Player count and capacities stay as they are ([_; 2], DECK_SLOTS): the by-w8gv.5.14 (capacities) bead parameterizes them once this bead has made them the kernel's private business.

Parity and checks

Parity (plan K11) at the push: just check passes; the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds (cargo test -p beryl_bench rollouts_never_change); slow CI's counts lane (just count-gate, bar 405,276,238 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. No behavior changes: no rules fix, no new card, no new mechanic. Work the card-names and file-length allowlists down as files are touched (data/card-names-allowlist.json, data/file-length-allowlist.json; an entry moves with its file and its count only falls; a new file is under 800 lines). Rules code cites the Comprehensive Rules (AGENTS.md); keep the citations of code you move.

Acceptance criteria

State's zones, battlefield, derived, listening and knowledge fields and every field of Zones are private; beryl_engine reaches them only through kernel mutators and accessors; a zone is named by a key that can express a shared zone and a command zone, and the key's rustdoc says how each would be added; no command zone or shared-zone logic is added; flags.derived_dirty is set by the mutators that invalidate the cache and by nothing in beryl_engine; just bench-count before and after is recorded on the bead; parity holds.

Decisions and deviations (executor):

  • just bench-count, rollouts corpus: before 404,476,069 instructions (staging 04c19eb1), after 404,167,248 (bar 405,276,238). The first cut read 409,277,330: with the recompute taking the lent cache by value it was inlined into layers::refresh, so every clean refresh paid a call. refresh now tests State::is_derived_stale and recompute asks for the cache itself.
  • Zone key: state::ZoneKey { Of(Seat, Zone), Stack }, taken by State::zone and Observation::zone. Its rustdoc says how a shared battlefield or exile and a command zone would be added. No shared-zone logic: the battlefield and exile are still named a player's part at a time, and only the stack, which was already kept once, has a key of its own (sba.rs read zones.stack).
  • The zone chokepoints are methods of State: move_object (was move_to_place; move_to and put_on_bottom are gone, callers pass Place), draw, draw_n, reorder_library, shuffle_library, rebind, cease_to_exist, and the reads signature and hand_size. They return no Event: event.rs builds a zone change's event with its reason, and start.rs deals and mulligans with none (the contract's Events section says so). Token creation stays make_token from by-w8gv.5.3.
  • The cache: State::rederive lends derive::Rederive (reads as the State; results() is the slice to fill; finish(listening) stores the mask, shows face-down permanents to their controllers and clears the mark). drop_stale_effects runs inside rederive and is crate-private now.
  • Flags::derived_dirty is pub(crate); the engine reads State::is_derived_stale and State::listening() (None while stale). add_counters and remove_counters take layered: bool, the answer of layers::counters_matter, because only the rules can read the card. The effects queue's two writers that mark the cache moved to legacy_mut: start_effect (takes the next timestamp) and end_effects(duration). legacy set_object_flags marks the cache when IMPENDING changes.
  • Knowledge: reveal(sink, slot), look(sink, player, cards), forget(player, slot), knowledge() and restore_knowledge(snapshot) for a paused resolution, keep_seen(run, random) (the loop of resolve.rs's keep_what_was_seen).
  • New reads: State::permanents() (each permanent with its Derived, in battlefield order), which replaced the zips of battlefield and derived in sba.rs, cast.rs, mana.rs and reference.rs.
  • Board: forget_derived (reference.rs's fresh recompute and the invariant tests) and Corruption::Unlisted.
  • The lock test beryl_cli longthink::files::tests::a_second_lock_names_the_first_holder failed in two of four full workspace runs here and passes alone; other sessions run the same test at once. Not touched.

Handoff: staging dedf1bd4, 5bcca414 and d510b3e3. State's battlefield, derived, listening, zones and knowledge, every field of Zones, and Flags::derived_dirty are pub(crate): beryl_engine reaches them only through the kernel.

Files: beryl_kernel/src/state.rs (ZoneKey; zone(key), knowledge(), is_derived_stale(), permanents(), listening()), zone.rs (the chokepoints as State methods), knowledge.rs (new), derive.rs (new: rederive and Rederive), legacy.rs (start_effect, end_effects; set_object_flags marks the cache for IMPENDING), mutate.rs (counter mutators take layered), board.rs (forget_derived, Corruption::Unlisted), lib.rs (contract: Mutators table and the paragraph before it, Events). In beryl_engine: layers.rs (refresh and recompute), event.rs, effect.rs, turn.rs, sba.rs, cast.rs, mana.rs, trigger.rs, resolve.rs, reference.rs, face_down.rs, start.rs, combat.rs. Every other crate changed only for ZoneKey (beryl_engine re-exports it at its root).

What replaced what:

  • s.zone(owner, zone) -> s.zone(ZoneKey::Of(owner, zone)); s.zones.stack -> s.zone(ZoneKey::Stack). Observation::zone takes the key too.
  • zone::move_to_place / move_to / put_on_bottom -> s.move_object(sink, slot, to, place). zone::draw, draw_n, reorder_library, shuffle_library, rebind, cease_to_exist, signature, hand_size -> methods of the same name.
  • s.battlefield.len() and .as_slice()[i] -> s.battlefield(); battlefield zipped with derived -> s.permanents().
  • s.flags.derived_dirty reads -> s.is_derived_stale(); s.listening -> s.listening() (None while stale). Writes: gone from the engine. The mutators that mark the cache: move_object and cease_to_exist (a permanent enters or leaves), turn_face_up, add_counters / remove_counters with layered = true, legacy start_effect, end_effects (when one ended) and set_object_flags (IMPENDING), Board::set_controller, attach, set_face, set_impending, forget_derived. Only Rederive::finish clears it.
  • s.knowledge writes -> reveal, look, forget, restore_knowledge, keep_seen; the layers' face-down knowledge is in Rederive::finish. Reads -> knows(player, slot), knowledge().
  • zones.next_timestamp: taken by the zone move, turn_face_up and legacy start_effect.

Gotchas: (1) Keep layers::refresh a flag test and a call. Passing the lent cache into recompute by value made the compiler inline recompute into refresh and cost 1.2% (409.3M); the per-symbol diff of callgrind_annotate in the VM against $HOME/gungraun/count-gate found it in one run. (2) Rederive derefs to State for reads; results() reborrows, so compute a value before writing it. (3) ZoneKey::Of(_, Zone::Stack) indexes past the owned zones and panics, as zone(owner, Stack) always did. (4) file-length: run.rs, rollout.rs and protocol.rs sit at their allowance, so a new use line has to join an existing group. (5) Counts: 404,476,069 before, 404,167,248 after (measured before the rebase onto newer staging).

A reviewer should check: ZoneKey's rustdoc against K7; that no mutator which changes a layer input misses the mark (reference.rs's check_layers would catch one in any test that plays the engine); knowledge.rs's keep_seen and restore_knowledge against the old resolve.rs; reference.rs's comparison through permanents().

Verified: cargo test for the workspace (corpus replay, rollouts_never_change, corpus_never_changes), clippy, the fast check at push including the oracle lane for the touched card files. Not run by me: slow CI, running on staging now.
