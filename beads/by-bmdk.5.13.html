Library flows landed on staging in 0e09f9f3 with private host-held sorts and one undoable result

Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Library flows'.

Interface code goes in ui/src/table/, registered with TableClient (ui/src/table/client.ts). Headless checks start a table with ui/scripts/table.mjs and go in ui/scripts/kept-table-<topic>.mjs; run one with just ui-test <title>.

Host: rust/crates/beryl_table_session/src/flows.rs. Interface: ui/src/table/flows.ts. The text matching and result batches are in beryl_table::assist::text (flows, flow_result, flow_line); the tray prompt is TablePrompt::Sort.

  • With the Library flows assist on, the library's context menu has "Scry…" and "Surveil…" rows under an "Assists" heading; each asks for N with the number prompt. "Look at top cards…" ends by asking for the order to put the cards back in.
  • A card whose rules text names one of these has the row in its own menu with the number filled in ("Scry 2" on a spell on the stack whose text says "scry 2"). The host puts the available flows for each known card in the view (add flows to the object's manual data in TableView, or to a per-object map there) so the interface does not read rules text.
  • Choosing a flow sends a new action flow { kind, n, source? } that only opens a prompt: the host looks at the top N cards for that seat (they become known to it) and opens Sort with piles "top" and "bottom" (scry), "top" and "graveyard" (surveil) or one ordered pile (look). When the player finishes, the result is one batch, logged as what it was: "Scried 2: 1 on top, 1 on the bottom".
  • The other player sees the cards lifted and where each went. They see what a card is only if it went somewhere public, as a surveilled card put into the graveyard does.
  • With the assist off none of these rows exist.

Tests: tests/flows.rs for each flow's batch, log line and what the other seat learns. Check (kept-table-flows.mjs, with pair()): scry 2 from the library menu: the tray appears, and the other page shows two cards lifted, then where each went, and never a name.

Acceptance criteria

Scry, surveil and look-and-reorder run from the library menu and from cards whose text names them, as host-held Sort prompts that end in one logged batch; the other seat learns only what went somewhere public; rows are absent with the assist off.
