Close reason

Treasures are consumed classes in the mana solver: castability and payment count them, sacrifice_options is gone; preview, scenario trace and XMage exporter handle sacrificed Treasures

Description

Found by the architecture audit of the Arena retarget (by-0w2.14). Read docs/engine-architecture.md §10 first; rules code cites the CR with yawgatog links (AGENTS.md).

Current design

mana.rs keeps mana abilities whose cost is {T} plus sacrificing the source (is_sacrificed: the Treasure tokens Beza, the Bounding Spring and Currency Converter make, both in the mirror) outside the payment solver. Sources::of reads only is_simple abilities, so payable/castable never count a Treasure's mana: a spell payable only with it is not offered at priority. Instead cast::priority_options always appends mana::sacrifice_options, under every payment profile: one Opt::Mana per colour it makes (W, U, B, R and G) for each group of interchangeable Treasures. Using one takes two decisions (float, then cast), and the mana empties at the end of the step if the player doesn't follow through.

Consequences:

  • Every priority decision while a Treasure is out gains 5 options that are almost always wrong. That inflates MCTS branching and lets random and greedy rollouts burn Treasures.
  • A priority decision with a Treasure out is never a one-option (forced) decision (engine::advance).
  • It contradicts §10: "A decision is offered when plans differ in consumed resources: permanents sacrificed, ..." and "Standalone mana-ability activations are offered only when timing-restricted ... or when the ability has effects beyond mana".
  • No scenario pays for anything with a Treasure (no test in beryl_cards or beryl_engine does).

Proposed design

Consumed sources join the solver as classes of their own:

struct Class { members: Bitboard, produces: ManaSet, rank: u8, consumed: bool }
// taps[i] of a consumed class = how many of its members are sacrificed
  • payable counts them, so a spell castable only with a Treasure is offered and paid in one cast.
  • The set of consumed sources is part of a plan's outcome (§10). To keep decisions few, a plan that sacrifices more is offered only when no plan sacrificing fewer exists, or when it scores strictly higher on still_payable (it keeps a later cost payable that the others don't). Payment::Greedy never sacrifices when it can avoid it.
  • pay taps, then sacrifices (Reason::Sacrifice), as mana::activate does now (CR 602.2b, 601.2h).
  • sacrifice_options leaves priority under auto and greedy payment. Manual payment keeps offering each Treasure as a source (manual_options already lists them), and standalone_options there may offer it too.

This removes sacrifice_options, the float-then-cast sequence, and the 5 extra options at every priority. Lotus Petal-style sources (§10) fit the same class later.

Must not change

  • The Treasure's ability ({T}, sacrifice: one mana of any colour, CR 111.10a).
  • Manual payment.
  • Plans and offers when no consumed source is on the battlefield. The rollout corpus may re-pin only where a Treasure exists.

Acceptance criteria

  • Scenario: P0 controls an Island and a Treasure with Counterspell in hand; P1 casts a spell. Counterspell is offered at P0's priority, and casting it sacrifices the Treasure within that cast, with no standalone mana activation.
  • Scenario: with a Treasure out and nothing castable, P0's priority options under auto payment are the same as in the same state without the Treasure.
  • Scenario: a spell payable from lands alone is paid without sacrificing the Treasure (auto and greedy).
  • just test-rust and just fuzz pass; just check passes.

Derek Thurn2026-11-06

Executor notes (496dc5b): Treasures are a consumed solver class (rank above every other source, never merged with non-consumed ones). Plans are keyed by (floating remainder, sacrificed count); a plan sacrificing more is dropped when any plan sacrificing fewer scores >= on still_payable, so it is offered only when strictly better than all of them; offered plans sort fewest-sacrificed first. Greedy keeps the first plan in greedy order with the fewest sacrifices (stops at the first sacrifice-free plan, so Treasure-free positions are untouched). sacrifice_options/sacrificed_sources are gone; manual payment now sees Treasures through the class loop in manual_options and standalone_options, and its rest-payability checks count Treasures (castability now counts them under every profile). Tests: a 'Test Treasure' engine card (2 in EVERYTHING) with payment tests for each acceptance case plus the strictly-better and manual branches, the brute-force solver test extended to Treasures; Beza's old 'Treasure sacrificed for mana' scenario (which relied on the standalone activation) is now 'Beza's Treasure pays for Counterspell' (acceptance 1, and P0's priority with nothing castable is forced). Verified: over 120 seeded mirror games, all 69 with no Treasure have identical counts before/after; the perf pins moved only for the two pinned games with a Treasure (random seed 2, greedy seed 1), re-pinned.
