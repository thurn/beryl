Close reason

Builder reads causes, payments and stack names from the engine's tags; infer's cause/payment/stack guesses deleted; cause invariant added (found a table bug); 1,455 of 12,055 scripts changed, by reason on the bead

Description

Step two of the presentation track (epic by-w8gv.21; docs/project-50k.md, Target architecture, Presentation, "Causes" and "Invariants"; K23, K24). The engine now tags every recorded event with its cause and names the stack entry it is about (read the handoff of the first lane:event-tags bead: the tag's type and how an entry is named). This bead has the script builder read the cause and deletes the session's guesses of it.

The code

rust/crates/beryl_session/src/script/: mod.rs (read its whole doc: Names, Spans, Mana, Building, Cause), infer.rs (every guess, in one place), build.rs (Screen, Builder; walk takes infer::tell's Told per event; cause(origin) turns an Origin into a Subject; lift, announce, cast, finish), mana.rs (Builder::mana, pay_owed, drain, paid_into: reads Told.pays and drains), settle.rs (what the view's table has that no event told), check.rs (the rule invariants, carried), replay.rs, table.rs (Table::of, Entry). The engine's events become protocol events in src/protocol/event.rs (game_events) and reach the builder as view.events; the session buffers engine events in game.rs (events, paused) and game/views.rs.

Tests: rust/crates/beryl_session/tests/script_build.rs, script_spans.rs, script_order.rs, script_piles.rs, script.rs, with the harness in tests/common/mod.rs (views, scripts, script, text). cargo test -p beryl_session; cargo run -p beryl_cli -- script-check (every spec moment from both seats and every fixture, in a debug build); just specs --script <card> prints a moment's scripts as text.

What to do

  1. Before any change, dump every script as text from staging: every card's spec moments from both seats and every UI fixture's recording, one file each. script-check already builds them all; give it a flag that writes each script's text (script/text.rs) under a directory, outside the tree. Keep the dump: the count of scripts that change is this step's report.
  2. Carry the tags to the builder. Decide where they travel and record why: beside the events inside the session (nothing serialized changes), or on GameEvent (then ui/src/generated/protocol.ts is regenerated, UI fixtures re-recorded, and the save corpus must still replay). The UI reads view.events only for the log (ui/src/game/log.ts) and diagnostics and must not read a tag: the stage infers nothing. Prefer not serializing them.
  3. Step::cause comes from the tag. Delete infer.rs's causes, loose and assign, Origin::Top and Origin::Ability as guesses, and the tokenOrigins rule (a token's cause is the entry whose effect made it, which the stage's emerge already draws from).
  4. Mana: what a Mana event pays for is its tag's entry. Delete payments, paid_for, payer, ends_costs and Pays as guessed; drains stays only if it reads no event order. Show::Late (a loyalty cost shown once its ability is on the stack) is now the cost's own tag, not a guess.
  5. Stack identity: the builder follows the stack by the engine's names. Delete same, pair and lifts_from where the tag answers; settle.rs's use of same goes with them or is shown to be a comparison of two views' items that no tag covers (say which on the bead).
  6. The new invariant (K24, this step's): every step names a cause that existed when it ran. In check.rs beside carried: a step's cause, when it is a spell, ability or permanent, is on the table as the step's beat begins or leaves it in that beat (a spell's last effect as it resolves; a sacrificed permanent's ability), and a player cause is a player of the game. One test that a hand-built script naming a cause that is gone, and one naming a cause not yet there, each trip it; it runs wherever replay runs (build.rs verify).
  7. Hand-written snapshots change only where the script changed, each rewritten by hand with its reason in the commit body. Dump again and diff against step 1's dump: on this bead, the number of scripts that changed out of how many, grouped by reason (for example "a token made by a second permanent entering now names its trigger").
  8. script/mod.rs's doc ("Building", "Cause") says the cause is the engine's.

What may stay in infer.rs for the next bead: together, order, tell's simultaneity, show, quiet, looked, making.

Decisions and deviations (executor, 2026-11-12):

  1. Where the tags travel: beside the events inside the session, never serialized. Game keeps script::Names (the engine's stack followed through StackArrival/StackDeparture, one for both seats) and said, in step with events; protocol::heard turns them, per viewer, into script::Heard (each view event's cause, the abilities that arrived and left with their place among the events, the names of the view's stack), and Screen::script(view, &Heard) builds from it. GameEvent, protocol.ts, fixtures and saves are untouched, so the UI cannot read a tag. Why: nothing a consumer has changes, and the stage infers nothing.
  2. An ability's number is the game's, not the seat's: Names numbers each ability as the engine says it arrived (from 1, never reused), so both seats' scripts call it the same and a reset says the numbers it has rather than new ones. A spell's name is its card's slot.
  3. Names::agree brings the names into line with the engine's own stack at every view (shown stack with the resolving entry in its place). Following makes it a no-op; it is what covers events that were never told: a cast cancelled (the board restored), an undo, a game loaded or replayed. No call site reseeds by hand.
  4. An ability goes on the stack where the engine says it arrived, which is before its costs (CR 602.2a, then 602.2b). So mana::Owed, pay_owed, Show::Late, pay_late, early, announced, making() and lift's own numbering are deleted with no replacement: nothing looks ahead for the ability a cost pays for. An ability first shown by a script goes on as that script's Ability event announces it (as a spell's card already flew with its Cast event's item).
  5. Kept, with the reason each is no guess about the engine:
    • drains (build.rs): mana spent from a pool has no engine event, so what a pool lost streaks into the first thing its player pays for in the script. It reads the tag for what is paid (Cast/Ability/ResolutionPayment's entry) but still reads "first", which is event order. Left for .74 to sort as presentation.
    • lift_ahead (stack.rs): a trigger lifts out of a permanent before that leaves, though the engine puts it on the stack afterwards (CR 603.3b). Staging (Arena I3Te0m1bBFw 26:56.75). It reads the stack item's own source and compares names; infer::lifts_from is gone.
    • Held (stack.rs): the opponent's ability whose cost is being paid is held back from the view (hold_back_activation_being_paid), so its arrival is remembered and it goes on the stack with the first later event that names it.
    • An ability removed as it was being put on the stack (CR 603.3d: its departure is its controller's doing, not an effect's) is never shown, as before.
    • settle.rs no longer uses same: it compares the two tables' names. No comparison of two views' items is left anywhere.
    • infer.rs keeps together, order, tell, still (was show), quiet, looked, making: all read event order or the seat's own prompt, for .74.
  6. The new invariant (check.rs rule): a step's cause that is a spell, ability or permanent is on the table as the step runs, or left it earlier in the same beat. A cause that left in an earlier beat or has yet to come fails. A player cause is a Side, so the type holds it. It runs in carried, so wherever replay runs (build.rs verify, Follow::play). Tests: script_spans.rs a_cause_yet_to_come_breaks_a_rule and a_cause_that_is_gone_breaks_a_rule.
  7. What the invariant found on its first run (5 of 806 checks): Table::of left the resolving entry off the table whenever the view's stack had another entry that read the same, which is exactly two triggers of one ability (Currency Converter's two discards). The ability vanished from the stage a view early and its effect had no cause. Measured: across every spec moment, fixture and session test that guard fired only in that case, never for an entry genuinely listed twice. Removed in script/table.rs and, since the stage builds the same table, in ui/src/stage/table.ts tabled. No other UI file changed.
  8. Not changed from .71's "not done" list: costs other than mana paid as an effect resolves stay the effect's; an until-exile's return keeps the cause of the move that freed it.
  9. beryl_scenario gains watch_tagged (events with their tags) for the session's script tests, whose harness now follows the stack as a session does (tests/common/mod.rs views_heard).

By reason, a script counted under each that applies:

  • 959: the last step of a resolution names the resolving spell or ability (the spell's card leaving the stack, a permanent spell entering, an ability's vanish), where it named nothing (CR 608.2n, 608.3).
  • 635: a mana streak's cause is its source, whose mana ability made it, where it was the player (CR 605.3b).
  • 336: an ability's emerge names the player who put it on the stack; a triggered one named nothing (CR 603.3b).
  • 103: another step's cause is the engine's: an effect in the middle of a resolution names the resolving spell or ability rather than its source or nothing (a coin, a draw, an untap), a creature's death to lethal damage names nothing (state-based, CR 704.3) where it named the resolving ability, and a land tapped to pay as a spell resolves is its payer's doing.
  • 101: an activated ability goes on the stack before its costs are paid, as the engine says it arrived (CR 602.2a), so its emerge now comes before the taps and mana streak straight into it in the taps' beat; an ability of a permanent sacrificed for it now lifts out of it, with its source line, before it goes (3 of these).
  • 73: a loyalty cost counts where it is paid, the ability being on the stack already, ahead of the step that sets the ability's targets and draws their arrow; Show::Late used to hold it until after.
  • 50: only an ability's number changed: numbers are the game's, so a seat that never saw an ability skips its number, and a reset says the numbers the abilities have.
  • 10: the bug the new invariant found: the second of two identical triggers no longer vanishes from the table a view before it resolves (Currency Converter's moments and three converter-* fixtures).

No script changed for a reason outside this list (the classifier's 13 unclassified were the 10 above and 3 of the sacrificed-source ones, read by hand).
