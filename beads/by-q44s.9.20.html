Description

Read docs/beryl-3d.md 'The switch' and decision C11. The owner calls the switch (Beryl 3D becomes the app) and, separately, the deletion of the web interface. This bead makes neither change: it writes each as a list of exact edits a session could carry out the day the owner asks, read from the code as it is.

Post one comment on by-q44s.9 headed "The switch and the deletion", with:

  1. The switch: each justfile recipe that builds or runs the app today (dev, the release bundle recipe, ios-device, the phone builds; read the justfile and tools/src/beryl_tools/mobile.py, android.py, app.py) and what it would run instead; the bundle's identifier, icon and data folder (rust/crates/beryl_app's tauri.conf.json against beryl_3d's); the phone projects that would be built (rust/beryl3d/crates/ beryl_3d/ios and android); the checks and lanes that would move from the web's lanes to required (checks.py, slow_ci.py, Beryl 3D's lane and sweep); and what C1 says stops (no more web fixes).
  2. The deletion: every path removed (ui/, rust/crates/beryl_app and the Tauri phone projects, the browser checks and their scheduling in checks.py, slow_ci.py, sweep.py and nightly.py, the TypeScript protocol generation in beryl_session), every check, lane and allowlist under data/ that only the web uses, every skill that only drives the web, and every AGENTS.md section that must change. List the main workspace's crates that would lose a user (grep for each before listing it).
  3. What is still open for the owner: the conventions entries marked open in data/beryl3d/conventions/*.json, any entry left in data/beryl3d/timeline-parity.json, the parity list's incomplete lines (just b3d parity --full), and the manual QA steps only a person can do (from that comment on by-q44s.9).

Each list item names a file and the exact change. Run nothing that changes the tree; run nothing on a phone.

Acceptance criteria

A comment on by-q44s.9 holds the three lists, each item naming a file and its change; git status in the main checkout is clean afterwards.
