Ability's fields are private behind const builders; card() checks a definition as it compiles (Malformed, seven classes) and one test covers the body cards; 16 exemplars in the final form; when is if_then; rollouts 388,662,261 -> 388,617,465, no bump; staging 82ff5208

Description

Milestone 5 of Project 50k (plan K5 and K3; epic by-w8gv.9): the rules library and the card port. Line numbers and counts below were read at staging f5034c58; the code as it stands wins over this text, and a deviation is a comment on this bead.

Last bead of the vocabulary lane, and the last before the card port: it settles the form every card file takes. Plan, A card file (illustrative; the names are yours):

pub static CARD: Card = card(names::TEFERI_TIME_RAVELER) .static_ability(each_opponent(CastOnlyAtSorcerySpeed)) .loyalty(1, until_your_next_turn(you_may(CastAsThoughFlash(SORCERY)))) .loyalty( -3, target(up_to(1, ARTIFACT.or(CREATURE).or(ENCHANTMENT))), seq(&[return_to_hand(TARGET), draw(1)]), );

"Everything is built with const fn, so a definition is a static with no startup cost and no macro. Costs that are not printed (a kicker cost, 'unless they pay') use Scryfall's notation, parsed at compile time: mana("{1}{U}"). What the engine, AI, UI and tools need to know about an ability (whether it can pause, whether it is removal, what it needs to do anything) is read from the data, not declared beside it. A card the vocabulary cannot express keeps a Rust body in the same file."

Printed characteristics (cost, types, colors, loyalty) are still typed in the card file in this milestone: milestone 7b generates them from the card store (K2). Do not design the generated header.

From the M2 Mason audit (comment on by-w8gv.9.1)

Item 3: "Ability (beryl_card/src/ability.rs) is one struct of 14 fields with a kind tag. trigger, condition, replacement, layer, rule, produces, only_if_you_control and needs each apply to one kind and hold a None variant for the others, so a Static ability with a trigger, or a Mana ability whose produces disagrees with its AddMana effect, is representable. Card files write struct literals with ..Ability::NONE: 45 abilities with bodies and 20 as data today. Either make it an enum by kind, or make the fields private behind const builders that can only build valid combinations. Keep size_of a power of two: ability.rs records 0.11% on the gate."

Item 4: "An ill-formed definition makes the interpreter do nothing, silently, or fail only when played:

  • Objects::Target(n) or Players::Target(n) with no spec n, or a spec of the other kind (an object where a player is meant);
  • Players::ThatPlayer outside ForEachPlayer (a debug assertion at run time, interpret/scene.rs);
  • Condition::Paid(kind) on a face with no such casting option; Modification::Grant(i) past Face::grants;
  • CopyException::PowerToughness other than 1/1 (a panic at run time, interpret/run.rs no_primitive);
  • Effect::AddMana outside a mana ability. All of it is const data. One const fn check over a CardDef, asserted in a const _ beside each card (a compile error in the card's own file, which is what a cheap model writing cards needs and what M8's just card check wants) or, failing that, one test over CARDS, turns each of these into a build failure. Effect::asks and Effect::removes show the const walk works."

Item 5: "Needs is still declared, and may_pause and .removal() remain on the 45 bodies. Derive or delete each as the bodies go."

Item 7: "when(condition, then) in beryl_card/src/effect/build.rs builds Effect::If. On a card 'when' begins a triggered ability (CR 603.1), so the name will mislead whoever writes 'When this enters'. It has four uses, all in the engine's tests/effects.rs: rename it (if_then, beside if_else)."

Scope

  1. Ability cannot hold an invalid combination: an enum by kind, or private fields behind const builders. Its size stays a power of two. The beads before this one changed what a trigger, a static ability, a rule, a replacement and a cost are: build over those types as they now stand.
  2. A card and a face are built by const fn builders in the plan's form, including the compile-time parse of Scryfall's mana notation for costs that are not printed.
  3. The definition check: one const fn over a CardDef covering the five classes above and whatever the earlier beads of this milestone recorded as "the definition check must reject it", asserted in a const _ beside each card, or one test over CARDS where a const assertion cannot say it.
  4. when becomes if_then.
  5. For an ability whose behavior is data, whether it can pause, what it removes and what it needs are read from the data (Effect::asks and Effect::takes exist). They stay declared only on an ability with a Rust body, through the builder for one, until the milestone's closing bead.
  6. Convert the data-only card files and the shared tokens as the exemplars the port follows: azorius/floodfarm_verge.rs, azorius/seachrome_coast.rs, azorius/tundra.rs, black/swamp.rs, blue/counterspell.rs, blue/island.rs, multicolor/sparas_headquarters.rs, white/damn.rs, white/oust.rs, white/plains.rs, white/portable_hole.rs, white/reprieve.rs, white/staff_of_the_storyteller.rs, white/swift_reconfiguration.rs, white/the_wandering_emperor.rs, and beryl_cards/src/tokens.rs. Their definitions import the vocabulary from beryl_card, not through beryl_engine::card, so a data-only definition needs beryl_card alone (plan, Crates). The 32 card files with Rust bodies keep compiling through a construction path kept for them alone; name it so that it reads as temporary, and say on the bead what the closing bead must delete.
  7. How a custom body is registered was decided by the design bead (its comment in enact brief): give the builder for it.

Constraints

  • The engine scans a face's abilities for every decision it builds: field order, size and the accessors' inlining are on the counted path. just bench-count before and after.
  • beryl_cli's specs (beryl_cli/src/specs/auto.rs), beryl_session's card_records and beryl_search's knowledge tests (beryl_cards/src/tests/knowledge.rs) read abilities' fields: give them accessors, not public fields.
  • No procedural macro, and no macro_rules! where a const fn does the job (AGENTS.md).

Tests: cargo test -p beryl_card (paper_test.rs), cargo test -p beryl_cards, cargo test -p beryl_session, just check's script lane (every card's spec moments).

Parity and checks

Parity (plan K11) at the push: just check passes; the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds (cargo test -p beryl_bench rollouts_never_change); slow CI's counts lane (just count-gate, bar 389,343,295 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. Run just bench-count before and after and record both on the bead: the benchmark is the WU Control mirror, so what this milestone moves is on the counted path. No behavior changes: no rules fix, no new card, no new mechanic (K14). A rules bug you do find and fix gets a docs/bugs.md entry (AGENTS.md). A save or a rollout replays the decisions a game asked, in order: never change which questions a resolution asks, their order or their options.

Held by checks (AGENTS.md, Code structure): no card name in generic code; no source file over 800 lines (data/file-length-allowlist.json only shrinks, and a new file starts under the limit); rules code and card bodies ask the state for a player's opponents and never name the other of two; they change the state through a mutator, never the board door; a push whose bound is argued takes Queue::push_bounded and any other propagates Full; a count or position that grows with the layout is never narrowed with as. No procedural macro, and a macro_rules! only where a const fn cannot remove the repetition. beryl_card, beryl_kernel and beryl_rules take no runtime dependency. Rules code cites the Comprehensive Rules with a yawgatog link and a quotation; keep the citations of code you move, and check new ones against the pinned release with just citations. Forge is a test oracle only (K16): no entry, name or design comes from its scripts. beryl_search/src/expert and beryl_search/src/frozen are exempt from the project: edit them only where a call stops compiling, giving the answer the old read gave. Other tracks edit nearby files (presentation by-w8gv.21 in beryl_session and ui/, mobile, the AI ladder): enact push rebases and you fix the conflict.

Acceptance criteria

Ability cannot hold a combination its kind does not have (an enum by kind, or private fields behind const builders), with its size a power of two. The fifteen data-only card files and beryl_cards/src/tokens.rs write no Ability, Face or CardDef struct literal and no ..Ability::NONE, and their definitions import from beryl_card. One ill-formed definition from each of the audit's five classes is rejected at compile time or by the one test over CARDS, each shown by a test, and every card passes the check. when is if_then. For a data ability, pausing, removal and needs are read from the data. The construction path kept for the 32 body cards is named as temporary and listed on the bead for the closing bead to delete. Every card scenario passes unedited, just bench-count before and after is on the bead, and parity holds with no bump to the count gate.

Decisions and deviations.

  • Ability keeps its layout (128 bytes, align 32, same field order) with every field private; builders by kind (spell, activated, loyalty, mana, tap_for_mana, triggered, static_ability, rule_change, replacing, and the keyword ones) plus targeting, effect, custom, pauses, needing, only_if, starting, if_you_control, as_a_sorcery, each asserting its kind as the definition compiles. Readers use accessors of the fields' old names (kind(), cost() -> &Cost, targets(), body(), ...). Ability is now Copy (the twin test in beryl_cards/src/tests/effect_data.rs rebuilds one at run time).
  • Deviation: no separate construction path was kept for the 32 body cards' abilities. A script rewrote every Ability literal in the workspace (cards and tests) as a builder chain, so Ability::NONE is gone and there is nothing of that kind to delete. What is temporary, for the closing bead (by-w8gv.9.18) to delete: (1) Ability::pauses and Ability::needing with the may_pause and needs fields and Needs, once no Rust body declares them; (2) TargetSpec::removal / ::counter and TargetSpec::takes, likewise (Malformed::Declared already refuses them on effect data); (3) the CardDef { .. } and Face { ..Face::EMPTY } literals the 32 body card files still write, which skip the compile-time check and are covered only by beryl_cards' test every_card_and_token_is_well_formed: port each to card(name, &[Face::EMPTY....]) and that test can go, and CardDef/Face literals could then be closed off; (4) bodies! and conditions! as the design bead already lists.
  • The plan's card(name).ability(..) chain cannot be a const fn over &'static slices (a const fn cannot borrow what it builds), so the form is card(name, &[Face::EMPTY.cost(mana("{U}{U}")).types(..).abilities(&[Ability::spell().targeting(..).effect(..)])]).creating(&[&TOKEN]). card() runs CardDef::check and panics, so an ill-formed definition is a build error in the card's file (compile_fail doctest on card).
  • The check (beryl_card/src/check.rs, Malformed): Target, ThatPlayer, Paid, Grant, Copy, AddMana, and Declared (a removal/counter declaration on effect data). Objects::Paid with no such cost part is left unchecked, as by-w8gv.9.12 said.
  • Found by the builders' assertions: a spell declaring Timing::Sorcery in the paper test (unread: only activated abilities read timing; dropped), and replacement abilities carrying an effect (WouldDraw's instead), so effect/custom accept a replacement.
  • For data: asks() from Effect::asks, takes_target() from Effect::takes only, needs() is Needs::Nothing (no instruction is empty in a way Needs names). The debug assertion in interpret/mod.rs (may_pause without asks) is unrepresentable now and removed, as is the kernel table test of a static with Condition::Did (the builder refuses it; Unapplied::Resolving stays, since static_ability::applied takes any LayerSpec).
  • The planner missed: tools read card files as text. card_names.DEFINITION_NAME and scale.NAME_FIELD now match card(\n names::X, as well as name: names::X,.
  • just bench-count, rollouts: before 388,662,261, after 388,617,465 (-0.012%), bar 389,343,295, no bump. cargo test --workspace --all-features passes (corpus, rollouts_never_change, every card scenario unedited); just check passes.
