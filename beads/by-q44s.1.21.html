Close reason

Prompt bar through the flat layer with taffy, parley, a retained tree, text-fits and the glyph table, on staging at 0e5eafeea

Description

Read first: docs/beryl-3d.md 'The flat layer' (Elements, Sizes, Text), 'Components' (what handle does and what frame does), 'Determinism' (third-party code; no system fonts) and 'The frame' (the panel and glyph materials). For what the prompt bar shows and where it sits, read ui/src/stage/PromptBar.tsx and the prompt bar's rectangle in ui/src/stage/desktop.ts. Read the documentation of taffy 0.15.1 and parley 0.13.0 on docs.rs before writing against them: both change their API between releases.

Why this bead exists. Milestone 1 is there to prove the doc's numbers. The frame that costs most is likely one in which handle builds a screen and lays out text, and nothing has yet measured taffy or parley under the instruction-count gate. This bead builds the thinnest slice of the flat layer that makes that measurable: one prompt bar with a title and buttons. Milestone 3 builds the rest of the flat layer on it. Build nothing that is not listed here.

In rust/beryl3d/crates/beryl_scene (src/element, src/layout, src/text and src/tokens):

  • Fonts. Commit the TrueType files of Cinzel, Crimson Pro and Open Sans (the variable fonts from the google/fonts repository on GitHub, under its ofl/ directory) and the mana symbol font's mana.ttf (from the mana-font npm package the web interface already uses, ui/node_modules/mana-font/fonts), each with its licence file, in rust/beryl3d/crates/beryl_scene/fonts. Embed them with include_bytes!. Register only these with parley and switch system font fallback off. The spike bead's comment on the epic says whether parley can select a weight from a variable font: commit the variable files if it can, and the static Regular and Bold instances if it cannot. Expose the embedded files as fonts::ALL, for the glyph rasterizer.
  • element module: Element (role, name, style, text, a Press, children), the builder functions row(), column(), text(&str) and button(&str), and the style methods name, gap, padding, grow, align_items, justify_content, width, height, style, enabled, on_press, child and children. The doc's prompt_bar sample must compile as written. Press is the closed enum the doc describes, with one variant for now: Button(ButtonId).
  • tokens module: space::S, M, L and type_style::TITLE, BODY, BUTTON as plain constants, with values read off ui/src/design's CSS variables. Milestone 3 generates this module from a data file; write it so that only its values will change.
  • The retained tree. The client keeps the element tree. In handle, on an Update or a Reply, it calls the prompt bar's screen function and reconciles the result with the kept tree: a node whose role, name, style, text and Press are equal keeps its layout and its cached text. A frame with no input rebuilds and lays out nothing.
  • Layout with taffy, in handle only: the root is the window in logical points, padded by the safe area, and the prompt bar is anchored where desktop.ts puts it. A first placement is enough; milestone 3 fits the screens.
  • Text with parley, in handle only: shape and break each text node at the width taffy gives it, through taffy's measure function, and cache the result by text, style and width. Text never changes layout after handle returns.
  • Glyphs. The client keeps a table from (font, glyph id, size in physical pixels) to an atlas page and rectangle, filled by Input::Assets. frame writes one Draw::glyph per glyph whose entry is present, and adds each missing glyph once to a list the host drains with Client::wanted_glyphs(). A missing glyph draws nothing and moves nothing.
  • frame writes a Resolved for the region "prompt", for its text and for each button (Place::Layer, buttons interactive), a Draw::panel for the bar and each button, and the glyph records, in the flat layer's band.
  • A press on a button queues SessionCommand::Click with the open decision's id and revision and Click::Button. A Reply::Click replaces the prompt's state.
  • The 'text fits' check (doc 'Interface checks'), a function from a frame to faults, like the other frame checks.
  • Work counters: layout nodes computed and text runs shaped, per frame.

Tests in beryl_scene/tests, with the glyph table filled by a helper that gives every glyph a made-up rectangle: the prompt bar of a hand-built deciding view has its title and buttons among the frame's resolved elements at the expected places; a second handle with an equal view computes zero layout nodes and shapes zero runs; a title too long for its box fails 'text fits'; pressing "Cancel" queues the command; two clients given the same inputs return equal frames. Playing the recorded pay-default is a later bead's.

Do not write gate limits here: the gates' beads do.

Run: just b3d cargo-test -p beryl_scene.

Acceptance criteria

A hand-built deciding view yields a prompt region with its text and buttons, laid out by taffy with text shaped by parley; Client::frame still allocates nothing and lays out nothing; the fonts are committed with their licences and no system font is used; the two new work counters exist.

Decisions: (1) The spike bead (by-q44s.1.31) had not answered the variable-font question yet, so I checked it here: parley 0.13 applies a variable font's wght axis from its synthesis when shaping, and tests/flat_layer.rs a_variable_font_is_drawn_at_any_weight shows Open Sans 700 measures wider than 400 from the one file. So the variable files are committed. (2) GlyphKey gained weight: u16 (the rasterizer must know the wght axis value), and AssetReady::Glyphs now carries Vec<GlyphCell { key, rect, bearing }>: placing a glyph quad needs the bitmap's offset from the pen position, which the old (key, rect) pair lacked. Doc 'Hosts' corrected. (3) 'Text fits' needs each line's box, which no resolved element carries, so Frame gained lines: Vec<TextLine> (doc 'The frame' corrected). (4) The web dock is a column at right 39 / bottom 87 (ui/src/screens/styles/controls.css), not anything in desktop.ts; the bar is the doc's row sample anchored at that corner. (5) layout_nodes counts the taffy nodes that were dirty before compute (what taffy recomputes); text_runs counts parley builds. Both are accumulated in handle and reported by the next frame. (6) Panels: every button and the top element of a screen. No 'primary' styling yet, since Press carries only the ButtonId. Determinism note for the gate beads: fontique and parley use hashbrown with foldhash's default hasher internally; output frames are equal across clients (tested), but instruction-count equality is the spike's question.
