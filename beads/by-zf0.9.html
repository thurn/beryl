Paused bodies rerun from their first knowledge; repro plays through (cb392028)

Description

Found in by-zf0.7 (commit 2ecf20af). A live game panicked in freeze-saves: just freeze-saves --games 184 --seed 522000000 (game i=183, seed 522000183; use cargo run --release -p beryl_cli -- freeze-saves <empty dir> --games 184 --seed 522000000). Panic: beryl_engine effect.rs ask_object 'an answer among the objects', from Thirst for Discovery (beryl_cards blue/thirst_for_discovery.rs draw_three_discard) resolving for the agent (P1), turn 26.

What happens: a paused resolution keeps its answers as candidate indices (Resolving.record, resolve.rs run/resolve/replay_to_question, effect.rs EffectCtx::ask). The agent was handed the second discard with 8 candidates (session game.rs next_view, At::Agent from engine next -> r.question) and answered 7; the re-run that applies record [1, 5, 7] asks that discard with 7 candidates. The hand strings match between runs, so index 5 of the first discard named a different Plains in different runs (the hand holds 2 Plains both players know and 1 only its owner knows; engine::collapse keeps those apart since by-zf0.8). Likely cause: runs of one paused body bind cards to slots differently (the resolve run lends chance via the sink, view/replay runs do not; keep_what_was_seen in resolve.rs copies identities only when settled && !random), so a recorded index means a different card. Reverting by-zf0.7's batch order (event.rs in_order) hides it for this seed because the draw order changes, but staging's design has the same fragility.

Fix direction: make a paused body's runs agree on slot identities, or record paused answers by what they do (as save::Chosen does) rather than by index.

Acceptance criteria

The repro above plays without panic; a test pauses a body over a hand with copies known to different players and resumes it with the same answer meaning the same card; docs/bugs.md entry.

Handoff: commit cb392028. Cause: keep_what_was_seen added to the committed state the knowledge a paused run gained, and the next run started from it, so knowledge gained AFTER question k (Thirst's first discard shown to the opponent) existed BEFORE question k in the next run; knowledge-aware collapse then merged that Plains with the opponent-seen ones, the first discard's index named another Plains, the second's was out of range. Fix (engine only, no save format change): Resolving gains knowledge (what players knew as the resolution began; relayout maps it); resolve.rs rewind() starts every rerun (resolve inline + spare paths, replay_to_question) from it, only when continuing a paused resolution. Committed state still keeps the seen knowledge for observers/determinization. Gotcha: rules knowledge and chance's 'first time anyone learns it' now differ inside a rerun, so Sink gains revealed (cards earlier runs revealed beyond the original knowledge); chance::settle_but skips each once (consumed) and partner() never swaps with one. Without it every frozen save failed with extra reveals. Tests: casting a_paused_body_answers_each_question_with_the_card_first_chosen (new Test Rummage card, Game::of(deck)); fails without the fix. Verified: freeze-saves --games 184 --seed 522000000 plays through; corpus + all perturbations, ignored another-seed sweep, full workspace pass. docs/bugs.md entry. Reviewer: a kept slot regained by a path that doesn't call settle stays in sink.revealed for the rest of that run (harmless unless later hidden and re-revealed in the same run).
