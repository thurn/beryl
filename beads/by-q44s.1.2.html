Description

Read first: docs/beryl-3d.md 'Components', 'The frame', 'Determinism' and 'Hosts'.

This bead writes the types every other bead builds on, and nothing else. Seven beads start the moment it lands and write against these names at once, so keep it small and land it first. Prefer the doc's shapes. Where one proves wrong, correct the doc in the same change.

In rust/beryl3d/crates/beryl_scene, as modules frame, input, command and pose:

  • Client with new(config), handle(&mut self, input: Input), frame(&mut self, now: u64) -> &Frame, wake() -> Wake, next_request(), next_command() and wanted_glyphs(), each with its queue. handle stores what it is given and frame returns an empty frame. No placement, ordering or animation here.
  • Frame, Resolved, Role, StateBits, ElementId, NameRef, Load, Work, Wake, Draw and Material exactly as the doc's 'The frame' gives them. Draw is #[repr(C)] and exactly 80 bytes, with a compile-time size assertion. Material is a closed #[repr(u8)] enum with the doc's nine values in the doc's order. Each material has a constructor (Draw::card(...), Draw::panel(...), and so on) that fills only the fields the doc's table gives that material, so no other code writes uv or params.
  • Place, a closed enum: Layer for the flat layer, and for a card its zone, whose side of the table, and its battlefield row where it has one. Copy the row names from beryl_session/src/protocol/table.rs (RowName).
  • Input, Pointer, Key, SessionCommand, Reply, Request, AssetReady, FaceId, FaceSize and GlyphKey exactly as the doc's 'Hosts' gives them. KeyCode starts with the letters, the digits, Enter, Escape, Space, Tab, Backspace, Delete, the four arrows and Back. Tier is Baseline or Enhanced. Lifecycle is Suspended, Resumed or LowMemory. TextChange is the edited field's whole new text. Haptic is Light or Medium. Rect, Size and Insets are plain structs in logical points.
  • Pose (position, rotation, scale, opacity and how far the face has turned) and Segment, as the doc's 'Determinism' gives it. Types only: pose_at is the motion bead's.
  • FrameBuilder, what Client::frame writes into: resolved(...) -> u32 (the element's index), draw(band, Draw), clip(rect) -> u8 and finish() -> &Frame. Band is a closed enum: the opaque pass and the doc's seven blended bands. Here finish leaves the records in the order they were pushed. The frame assembly bead makes it order them.
  • Time is u64 nanoseconds. Geometry uses glam.

Tests in beryl_scene/tests: size_of::<Draw>() == 80; each constructor leaves at zero the fields the table does not give its material; a client given the same inputs and times twice returns equal frames.

Run: just b3d cargo-test -p beryl_scene.

What the prototype found (rust/prototypes/beryl3d, 2026-11-14; read its code for a working example, then build it properly):

  • A card turns over, so its record needs two layers. A card's face always fills its layer, so a card's uv rectangle is unused: the back's layer goes in uv[0] (the doc's 'The frame' says so). The shader picks the layer with @builtin(front_facing) and mirrors u on the back.

Acceptance criteria

The types exist with doc comments and match the doc's 'The frame' and 'Hosts' field for field; Client holds no logic beyond its queues; the tests pass; size_of::<Draw>() == 80 is asserted at compile time; no code outside draw.rs writes uv or params; the doc is corrected wherever a shape changed.
