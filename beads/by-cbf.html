Description

Goal: no human game ever ends in Outcome::Stalled, and search keeps today's speed.

Today a player game uses the same fixed-size State as search (beryl_engine/src/state.rs): 255 object slots (Slot is NonZeroU8), 256-bit Bitboards, Fixed<T, N> queues (128 permanents, 64 stack entries, 64 pending triggers, 32 delayed, 64 floating effects, 8 cast permissions, 8 entered-X). A full queue returns Err(Full), engine.rs calls stall(), and the game ends on a "Stalled" screen with a half-applied state. Player games also keep Limits::DEFAULT (500 decisions per turn, 200 turns) via with_stops in beryl_session/src/game.rs. Underworld Breach loops can overflow the stack and the decision budget; a card pool beyond the cube (Commander, multiplayer, 100-card decks) breaks the slot, player and deck limits outright.

Design: make the engine generic over a storage layout, State<L: Layout>.

  • Small is today's layout, unchanged: Copy, at most 20 KiB, u8 slots, [u64; 4] bitboards, Fixed queues with a u8 length, Option<Slot> keeping its niche. Search and rollouts run on it.
  • Large is unbounded: u16 (or wider) slots, a growable bitset, Vec queues whose push never fails. Clone, not Copy. It is where more players and bigger decks fit later.
  • Layout supplies the slot, bitset and queue types as associated types and consts, resolved at compile time: no dyn Layout, no runtime layout checks on hot paths.
  • Promotion lives in the session, not in apply: before applying a player-game action the session keeps the pre-action Small copy (a memcpy). On Stalled(Capacity) it widens that copy into Large with the same slot numbers (lossless) and applies the same Choice again; decisions are identical on both layouts, so the index still names the same option. The game stays Large from then on. Decision, Observation and ObjectRef take the layout parameter too; the session hides it behind enum Game { Small(..), Large(..) }.
  • Search on a Large game uses the same generic MCTS on heap clones: slower, still correct. Demoting back to Small (slot renumbering) is out of scope until needed. A Small rollout that overflows inside search may still stall and score 0.5.

Rejected: one bigger fixed layout. It gives up D4 (the state fits L1, a copy costs about 170 ns) and still has a limit.

Cost is mostly a mechanical refactor (about 70 files mention State; beryl_engine is about 14k lines; only 3 files in beryl_cards touch State). The engine compiles twice, so watch just check's 60 s budget as well as the count gate.
