M8 scope: "Add just card new <name> (a card file with its generated header) and just card check <name>: build one set crate, generated scenarios on Beryl, XMage and Forge, the render diff." The render diff is added to card check by the render lane's diff bead, which depends on this one: leave a clear place for it.

Today

tools/src/beryl_tools/card.py (254 lines; just card <command>) has brief, header (rewrites a file's generated header, card_header.py) and path (prints rust/cards/<crate>/<set>/<card>.rs, or says the card is store-only and where its file would go). Card files are found by card_files.py; set crates and their build scripts are generated (beryl_card_build, M7b), so adding a card means adding a file. Each face starts from a generated printed:: constant (AGENTS.md "Layout"). Generated scenarios for a card built only from library effects come from rust/crates/beryl_cards/src/derive/ (K3; beryl_scenario dumps them), and just oracle <card names> runs a card's scenarios in XMage and Forge (oracles.py, xmage.py, forge.py).

What to build

  1. just card new <name>: writes the card's file at card path's location with its generated header and the smallest definition that compiles, built from its printed:: constants (copy the shape of the nearest implemented card of the same type that nearest.py finds, minus its abilities), and prints the path and the next step (just card brief, then just card check). Refuses a card that already has a file, and a name the store lacks (same message as brief). Never writes a file for a card nobody is about to write (K2: an unimplemented card is a store record): the command is only for starting work.
  2. just card check <name>: in order, stopping at the first failure with a one-line reason: cargo check (then the card's own tests) of the one set crate holding the card, not the workspace; the card's generated scenarios on Beryl's strict runner (beryl_scenario for that card only, derived per K3), plus its hand-written scenarios if the file has any; the same scenarios in XMage and Forge (just oracle <name>, respecting data/oracle-divergences.json and data/oracle-exporter-gaps.json and the oracle lock); then a render step stub that the diff bead fills. Prints a short summary per step (pass, fail, unsupported with the reason) and exits non-zero on any failure. --no-oracles skips the two oracles for a fast loop. Each step reuses the existing command; add no second implementation.
  3. Tests in tools/tests for argument handling and the step order (mock the subprocess calls), within pyre strict.
