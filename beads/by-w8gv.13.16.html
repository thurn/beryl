Close reason

beryl_card_names removed; card edits rerun only their crate's build script; 37 vs 74 re-measured (74: 1.5-1.7 s vs 2.4 s)

Description

At 50,000 cards the one-edit rebuild (just scale, tools/src/beryl_tools/scale.py, budget 2 s) runs beryl_card_names' build script (0.3 s) and rechecks its 50,000 constants (0.7 s) after any change to a card file's code, though the names only change when a card file is added, removed or renamed, or a decklist or beryl_cards' sources change. Cause: beryl_card_build::card_names (rust/crates/beryl_card_build/src/generate.rs) prints cargo:rerun-if-changed=../../cards, and Cargo reruns a build script when any file under a watched directory gets a newer mtime; Cargo then always rebuilds the crate whose build script ran. Measured in by-w8gv.13.15 (comments there): with set crates of half the size (just scale --crates 74), the names crate is the rebuild's longest path (to about 1.4 s of 1.8-1.9 s on the clock), and pinning it in the scratch workspace leaves the set crate's path (units start 0.4 + set build script 0.25 + set check 0.45 + registry 0.13). Find a way for the names to be rebuilt only when the set of card files changes, for example: watch a file listing per set crate that only changes when its files do; or let the registry re-export each set crate's own generated names module (each set crate's build script already writes one) and keep only decklist and store-only names in beryl_card_names, measuring the registry's recheck since it runs after the set crate. Then re-measure 37 against 74 crates interleaved (scratch workspaces in separate BERYL_CACHE roots, timings script approach in by-w8gv.13.15) and, if smaller crates now give the rebuild real margin under normal load, halve MINIMUM/MAXIMUM in tools/src/beryl_tools/set_groups.py (RULE text, data/set-groups.json via just card crates) and record it under K8 in docs/project-50k.md.

Acceptance criteria

Editing one card file's code no longer reruns beryl_card_names' build script (cargo check -v shows it fresh); adding or removing a card file still updates the names. just scale's one-edit rebuild is re-measured with the fix at 37 and 74 crates, interleaved under normal load, and the numbers are recorded on the bead. Changing the grouping rule is no longer part of this bead (by-w8gv.13.18 does it).
