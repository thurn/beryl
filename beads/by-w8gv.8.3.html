Close reason

Layers list one entry per effect with a layout-wide target and stall on a full list; no discarded push left (check added); counts saturate; count gate holds with no bump

Description

From the M4 Mason audit (by-w8gv.8.1), read at staging 86ee9715. Two rules bugs in the layers, each confirmed with a throwaway test, and the two permissive habits that admit them. Both show only once a game outgrows a width, which is when nobody is watching.

The bugs

  1. An effect on a set is dropped. layers::recompute (beryl_engine/src/layers.rs:105) gathers what to apply in Applying, a list of 192 (layers.rs:35), one Apply for each permanent an effect changes, and discards a failed push (let _ = list...push, lines 152, 215, 228). Its comment, "a list longer than its capacity would need more effects than the cards can create at once", was true while an effect changed one object. Milestone 4 built locked-in sets (by-w8gv.7.5, State::start_effect_on_set), and resolved_effects pushes one entry for each member. Confirmed in Small: 120 Test Bears, three start_effect_on_set(.., LayerChange::ModifyPt(1, 1), Indefinite) over all of them; every Bear should be 5/5 and each is 3/3 or 4/4. No error, no stall into Large. No card of the pool makes a set of two or more today (both users of Effect::Modify target one object), so nothing plays wrong yet; the first card that says "creatures you control get" will.
  2. An effect lands on the wrong permanent. Apply::target is a u8 and both sites write target as u8 (layers.rs:156, 205). Large holds more than 256 permanents. Confirmed: a Large state with 301 permanents and ModifyPt(3, 3) started on the one at battlefield position 300 leaves it 2/2 and makes the one at position 44 a 5/5.

What admits them

  • A failed push to a fixed list may be thrown away: 35 let _ = ....push( in beryl_engine and beryl_kernel outside tests (grep -rn 'let _ = ' rust/crates/beryl_engine/src rust/crates/beryl_kernel/src), each with a comment arguing a bound, or none. Nothing checks the argument, in a debug build or under just fuzz.
  • The workspace allows clippy::cast_possible_truncation (rust/Cargo.toml:14), so as u8 narrows a position or a count that grows with the layout without a word. Besides the layers: trigger.rs:159 (attackers.count() as u8) and :184 (matching as u8), mana.rs:63, :1190 and :1266, start.rs:72.

Proposed design

  • Layers. One Apply for each effect, not for each permanent it changes: its target is one battlefield position or a locked-in set, and the apply loop walks the set's members as it reaches the entry. The list is then bounded by the store's 64 entries plus the static abilities, a set of 120 costs one entry, and the sort key no longer needs the target to order a set's members (they share a timestamp and commute, CR 613.7). A position is as wide as the layout (L::Index, or a kernel type for a battlefield position: plan "Kernel rules", index types). Where the list can still fill in Small (static abilities of 128 permanents), the recompute reports it the way every mutator does, so the game stalls into Large (docs/rules-coverage.md, principle 3), or the bound is asserted where it is argued. Sketch:

enum Target<L: Layout> { Position(L::Index), Set(LockedIn<L>) } struct Apply<L: Layout> { layer: u8, timestamp: u16, order: u8, target: Target<L>, source: L::Card, change: LayerChange }

  • Pushes. Queue gains a push for a list whose bound is argued, which asserts in debug builds (so just fuzz and the scenarios trip on a wrong argument) and is what every site with such a comment calls; a site with no argument propagates Full. No let _ = ....push( is left in rules code, and a check keeps it out, in the names lane beside board-door (tools/src/beryl_tools/checks.py).
  • Casts. Each as u8 of a count or position that grows with the layout (the sites above) saturates or is widened, with a test in Large for the two a trigger reads. Leave the rest: a cast of an enum's discriminant or of a number a constant bounds is not this.

What it eliminates

Both bugs; the class in which a game that outgrows Small plays on wrong instead of stalling; 35 unchecked arguments.

Must not change

Layer order and results for every scenario (CR 613.1 to 613.8): cargo test -p beryl_cards, just exhaust. rollouts_never_change and the frozen save corpus (cargo test -p beryl_session --test corpus). The count gate holds with no bump (bar 389,343,295, 1%, rust/crates/beryl_bench/count-gate.toml): the layers' recompute is on the counted path, most recomputes apply nothing and make no list, and that must stay so. Run just bench-count before and after and record both on the bead with size_of::<State<Small>>() if it moved (it should not).

Context

Read: beryl_engine/src/layers.rs (whole, 330 lines); beryl_kernel/src/effects.rs (layer_effects, Affects) and effects/sets.rs (locked_in); beryl_kernel/src/fixed.rs and layout.rs (Queue); beryl_kernel/src/lib.rs "Stores" ("Shapes, capacities and bytes", "Indexing and what an absent kind costs"). Templates for the tests: beryl_engine/src/tests/events.rs (game(), put, s.board().place_token, State::try_relayout::<Large>, layers::refresh, s.derived(slot).power). by-w8gv.8.2 (same gate) touches engine.rs, cast.rs:1741-1765 and combat.rs:66-74 only; enact push rebases. Need not read: beryl_session, ui/, card files. cast.rs, effect.rs and mana.rs are on data/file-length-allowlist.json: do not grow them. Rules code cites the Comprehensive Rules (AGENTS.md); add the docs/bugs.md entries. No new card, no new mechanic (K14).

Acceptance criteria

Engine tests, each failing before the change: (1) in Small, three +1/+1 effects each locked in on 120 permanents leave every one of them 3 bigger, or the game stalls with Full and plays on right in Large: never a silent shortfall; (2) in Large with over 256 permanents, a layer effect on the permanent at battlefield position 300 changes that permanent and no other; (3) in Large, a trigger that counts over 255 attackers or tokens reads a count that did not wrap. grep -rn 'let _ = .*\.push(' rust/crates/beryl_engine/src rust/crates/beryl_kernel/src finds nothing outside tests, and a check in the names lane fails on a new one. docs/bugs.md has both entries with their prevention. just check passes, the corpus replays, rollouts_never_change holds, and the count gate holds with no bump, with just bench-count before and after on the bead.

Decisions (executor):

  • Layers: Apply<L> is one entry per effect; its target is Target::Position(L::Index) or Target::Set(LockedIn<L>), and a set's members are walked in battlefield order as the entry applies. The sort key keeps the position as the last tiebreak for static abilities of permanents that share a timestamp (as before); a set's key has no position.
  • The list (192 in Small) can still fill with static abilities (64 effects + more than 128 static layer abilities), so layers::refresh now returns Result<(), Full>. On Full the results are still stored (lacking the effect) so nothing reads a stale cache in a body that runs on to its end, and every caller propagates: ? in sba/event/turn/interpret/EffectCtx::finish, EffectCtx::check in continuous.rs, and the engine loop through layers::over_or_refreshed, which ends the game Stalled(Capacity).
  • engine.rs was at its file-length entry (830), so perform_or_stall became stall_if_full(done, s), used at five sites; the file is 825 and its entry is lowered. mana.rs is 1584 (entry lowered).
  • Pushes: Queue::push_bounded (debug-asserts the argued bound) and Queue::push_if_room (a heuristic's sample: mana.rs's later costs and lands, which were deliberate truncations and keep their behavior). Sites with no argument propagate Full: combat::attack_targets, mana::assign, effect.rs's plan options and scry order (EffectCtx::check). combat::division's list is now typed BATTLEFIELD long.
  • 30 sites, not 35: the audit's grep counted every 'let _ =' (some bind other things: coverage.rs, engine.rs:55, interpret/mod.rs:98).
  • Casts: trigger amounts saturate at 255 (TriggerInfo::amount stays a byte, so State<Small> does not grow); mana.rs:63/1190 and start.rs:72 use try_from; mana.rs:1266 is bounded by c.amount and says so.
  • The check is 'discarded-push' (tools/src/beryl_tools/discarded_push.py), in the names lane; it scans beryl_kernel, beryl_engine and beryl_cards outside tests, catches the statement over several lines, '_ = x.push(..)' and '.push(..).ok();'.
  • All four new engine tests (beryl_engine/src/tests/widths.rs) were run against the base b0626f4c and failed there: bears 4/4 not 5/5; no stall; +3/+3 landing at position 44; trigger amounts [44, 44].
  • just count-gate before: 389,230,361 instructions (-0.03% against the bar).
