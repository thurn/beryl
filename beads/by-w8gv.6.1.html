Architecture audit of milestone 3 (M3: kernel) of epic by-w8gv.

Audit against docs/project-50k.md, not against taste:

  • Each decision this milestone implements (K ids in the milestone's description) is implemented as decided, or the deviation and its evidence are recorded on the milestone epic.
  • The conventions hold in new code: no card name in generic code, no file over 800 lines added to the allowlist, no procedural macros, words spelled out, no runtime dependency in the kernel, rules or card crates.
  • Nothing shaped by Forge has entered the engine or the vocabulary: string-typed parameters, script-variable indirection, per-card AI hints, or an entry whose only justification is that Forge has it (K16).
  • The hot path did not gain a general hook that runs in case some card cares (docs/rules-coverage.md, Principles).
  • The next milestone's plan section still fits the code as it now stands; if not, file the correction as a child here so the decompose bead sees it. File important findings as children of this gate epic. Do not rerun tournaments.

Acceptance criteria

Findings filed as children of by-w8gv.6, or none needed, recorded in the close reason.

Mason summary (audited staging 7003bf65; no code changed).

Verdict: milestone 3 implements K6 and K7 as decided and the kernel's design is sound. One finding filed; the rest is notes for milestone 4.

Against the bead's five checks:

  1. Decisions as decided: yes. Deviations were each decided on a child bead and are now listed in one comment on the milestone epic (by-w8gv.5).
  2. Conventions in new code: hold. The file-length allowlist only shrank over the milestone (21 entries removed, 4 lowered, none added; largest kernel file relayout.rs at 730). The card-names mechanics list lost nine entries and gained none. No procedural macro; three macro_rules in beryl_card, none in the kernel. beryl_card depends on nothing and beryl_kernel on beryl_card alone. No misspelt identifier.
  3. Forge shapes: none. Milestone 3 added index newtypes and Whose to the vocabulary; no string-typed parameter, script variable or AI hint.
  4. Hot path: no general hook added. The mutators are inline setters; counters_matter and the listening mask predate the milestone. Count 404,858,188 against the bar 405,276,238, no bump.
  5. Milestone 4's plan section fits. Its decompose bead's file references are stale and its list misses four pieces of one-mechanic state; the corrected map, the byte budget and the M2 Mason's carried note are a comment on by-w8gv.7.1 rather than a bead, since a comment reaches the decomposer in its brief and costs no session.

Ranked findings:

  1. FILED by-w8gv.6.2 (gate child, role:executor, tier:opus): two rules that only a person's memory enforces become checks. State::board() compiles in rules code and nothing searches for it (one use today, reference.rs:72); just citations runs only when someone remembers, and the 2026-11-06 rules release left about 96 dead citations that the Warden found by choosing to look.
  2. NOT FILED, on by-w8gv.7.1: State<Small> is 19,992 of 20,480 bytes, so 488 are free and the three stores have about 2,150 once the queues they replace are gone. This shapes the stores' design (a locked-in set per effect entry does not fit) and belongs in the design bead's acceptance.
  3. NOT FILED, on by-w8gv.7.1: Object::linked with State::link, StackEntry::exile and flashback, Casting::extra and ObjectFlags::ONE_ONE are one-mechanic state outside milestone 4's list.

Looked at and left alone (lower value, not filed):

  • The stack is two structures (the zone bitboard and the entry queue) kept in step by a two-call protocol: take_off_stack then the move. The invariants check it on every debug apply; deriving one from the other would cost the hot path.
  • Records with public fields admit states the rules never build: a StackEntry with neither object nor ability, a Casting whose step-specific fields (graveyard_from, left, bent, remaining) mean nothing in other steps. A tagged union would be cleaner; Casting is milestone 6's to reshape and StackEntry is size-tuned.
  • Battlefield timestamps are a u16 that wraps (zone.rs, legacy.rs, mutate.rs). A wrap would misorder layers silently instead of stalling; it needs 65,536 entries and effects in one game, which no budget allows today. Worth a debug_assert when the Effects store takes over next_timestamp.
  • Two kernel types are both named Place (ids::Place, a slot's place in a numbering; zone::Place, where in a library), beside TargetPlace.
  • The listening mask is a bare u16 in four signatures (GameTable::listens, State::listening, Rederive::finish, Copiable::may_listen).
  • Mutators take a Slot in some places and an ObjectRef in others, each checked by debug_assert; a Permanent type would be a large change for little.
  • table.rs holds facts computed for the mana solver (ManaFace, is_simple, is_sacrificed) beside the table itself. Milestone 4's capability bits will join them; if the list keeps growing it wants its own module.

Tests and budgets: the three Steward beads closed during the milestone were the CI track's (a Windows budget, a ui-test hang, one already green), none from kernel work. The retired long-think arena's tests were half of the rust lane's test time and its critical path (longest 37 to 59 s against 16 to 26 s for any other test on a quiet machine, from the run log); by-w8gv.20.17 moved them out of the fast check today, so nothing to file. just fuzz runs nightly and a bounded exhaust runs in the fast check.
