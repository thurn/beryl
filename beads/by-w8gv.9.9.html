LayerSpec names Objects and a Condition; Filter and Rule name Players; Whose, Affected, StaticCondition gone; table refuses unread statics and filters; rollouts 388,633,629 -> 386,956,937, no bump; staging 0c65d4c2

Description

Milestone 5 of Project 50k (plan K5 and K3; epic by-w8gv.9): the rules library and the card port. Line numbers and counts below were read at staging f5034c58; the code as it stands wins over this text, and a deviation is a comment on this bead.

Second bead of the vocabulary lane, from the M2 Mason audit (comment on by-w8gv.9.1), item 2, less its cost half (by-w8gv.9's cost bead):

"Affected {Itself, Enchanted} cannot say a filtered set (6 cards). StaticCondition {Always, HasCounter, Impending} is a second, smaller Condition (4 cards); its Impending is the Condition::All(Paid, Compare) that Ability::impending_countdown already writes. ... Whose, in Filter and in Trigger::Step, is Players' job (3 cards); M3 touches Whose for K7."

What exists

  • beryl_card/src/continuous.rs: LayerSpec { affected: Affected, condition: StaticCondition, modification: Modification }, Affected { Itself, Enchanted }, StaticCondition { Always, HasCounter(CounterKind), Impending }.
  • beryl_card/src/filter.rs (54 lines): Filter and Whose; Whose:: appears 39 times across the crates. beryl_kernel/src/filter.rs (122 lines) evaluates a filter (Evaluate, select).
  • beryl_card/src/effect/reference.rs (Objects, Players), effect/condition.rs (Condition, Comparison), beryl_rules/src/interpret/scene.rs (Scene evaluates them for a resolving ability).
  • beryl_rules/src/layers.rs (418 lines) applies static abilities and resolved effects in layer order (CR 613); beryl_kernel/src/derive.rs holds what the layers derive.
  • Four uses of Affected:: or StaticCondition:: in card files (grep -rn 'Affected::\|StaticCondition::' rust/crates/beryl_cards/src), plus Ability::impending_countdown in beryl_card/src/ability.rs.
  • The paper test (comment of 2026-11-11 04:46 on by-w8gv.3): a static ability affecting a filtered set, cards 12, 13, 27, 35, 42, 44; a static "as long as" that is a general condition, cards 5, 26, 32, 60; "[player] controls" taking a Players value, cards 20, 28, 39.

Scope

  1. A static ability's affected side is said with the expression type effects use for objects (this permanent, the enchanted permanent, the permanents a filter accepts), read from the ability's source and its controller (CR 604.1, CR 611.3: a static ability's effect "isn't 'locked in'; it applies at any given moment to whatever its text indicates").
  2. Its "as long as" is a Condition. StaticCondition goes; Impending is the Condition::All(Paid, Compare) already written by Ability::impending_countdown. Scene evaluates a condition for a resolving ability; a static ability has no resolution, so say what a condition is read against for a permanent on the battlefield, and reject at build time a condition that only makes sense while resolving (Did, ThatMany).
  3. Whose goes: Filter's "controlled by" and "owned by" take Players, as Trigger::Step does after the lane's first bead. The M3 Mason audit touched Whose for K7 (card data says "each opponent", never the other of two): keep that meaning.
  4. Write the paper test's cards for these three asks in beryl_card/tests/paper_test.rs.

No new rules features (run epic by-w8gv, K14): the vocabulary may now say things no implemented card says. Where the engine has no code path for an expressible value, the card table must refuse the definition when it is built (TableError, beryl_kernel/src/table.rs) or the definition check must reject it, with a test; it must never run as a silent no-op. List each such gap in a comment on this bead: they are docs/rules-coverage.md's project, not this one's. A static ability over a filtered set is the likely case: no implemented card has one, so the layers need not apply one, but the table must say so.

Constraints

  • The layers run on every change and are on the counted path. For the 47 cards the work they do must not grow: a filtered set costs nothing when no card in the game has one (a capability bit), and "itself" and "enchanted" stay as cheap as today.
  • Ability's size stays a power of two (ability.rs).
  • Filters are evaluated in the mana solver and target enumeration as well: Filter's size and select's cost are on the counted path.

Tests: beryl_rules/src/tests (rules.rs, events.rs, cast.rs), cargo test -p beryl_kernel filter, cargo test -p beryl_cards.

Design as built (worktree commits dde74c10, 858caddf; base staging 53b549f7).

STATIC ABILITIES. beryl_card/src/continuous.rs: LayerSpec { affected: Objects, condition: Option<Condition>, modification }. Affected and StaticCondition are gone.

  • The affected side is the Objects expression effects use: This, the new Objects::AttachedTo ("enchanted creature", CR 303.4b; the old Affected::Enchanted) and All { zone, filter } for a filtered set. Objects::AttachedTo is an entry of the shared expression type, so the interpreter reads it too (Scene::objects: what the source is attached to, nothing once the source has left); test attached_to_is_the_permanent_the_source_is_attached_to.
  • The "as long as" is a Condition or None. StaticCondition::Impending is the Condition::All(Paid, Compare) the countdown trigger already wrote: one const (ability.rs, IMPENDING) said by both. HasCounter(k) is Compare(Counters(This, k), AtLeast, Fixed(1)).
  • DEVIATION (size): Ability holds the spec by reference, layer: Option<&'static LayerSpec>, as it holds the trigger. Objects is 32 bytes and Condition 88, so a spec by value makes Ability 256. With the spec out, the fields fill 105 bytes and the alignment that rounds the struct to a power of two goes from 16 to 32, keeping it 128. Card files write Ability::static_ability(&LayerSpec { .. }).

WHAT A STATIC CONDITION IS READ AGAINST (scope 2). Scene reads a condition against a resolution. A static ability has none (CR 604.1): its expressions are read for the permanent it is on, "this" being that permanent and "you" its controller, against the game each time the layers run (CR 611.3a). Said in beryl_kernel/src/static_ability.rs (new), which is to static abilities what listener.rs is to triggers: applied(&LayerSpec) accepts or refuses one, holds(s, slot, &Condition) is the reader the layers call, reads_counters says which counter changes dirty the layers (layers::counters_matter).

  • The reader takes what the layers start from and never their results: Paid(kind) of this permanent, and Compare of Fixed and Counters(This, kind), under Not, All and Any. So it is the same before and after a recompute.
  • "Only makes sense while resolving" is a property of the vocabulary: const fn needs_a_resolution on Objects, Players, Amount, Condition, Filter and LayerSpec (Target, Those, X, ThatMany, Did, ThatPlayer, ManaValueAtMostX, at any depth). Ability::static_ability asserts it, so a card's static fails to compile; the table refuses the same thing in an ability written as a struct literal (TableError::Static, Unapplied::Resolving) until by-w8gv.9.13 leaves the builder the only way.

PLAYERS FOR WHOSE (scope 3). Whose is gone. Filter::Whose(&'static Players): by reference because Players names Objects, which names Filter; Filter stays 24 bytes. Whose::AnOpponent is Players::EachOpponent, K7's meaning kept ("you don't control" is still Not(Whose(You))). Rule::whose gives Option<Players>. Trigger::Step took Players already (by-w8gv.9.8).

  • One reader outside a resolution, beryl_kernel/src/filter.rs: reads(&Players) says which values it takes (You, EachOpponent, EachPlayer) and is_for(&Players, player, you) reads them, for a filter, a player target, a trigger's player and a rule's players. listener::is_for and filter::is_whose are gone; listener::listens_to asks the same reads().
  • beryl_card/src/walk.rs (new): CardDef::filters / Ability::filters call a visitor with every filter a definition holds, at any depth (targets, trigger subjects, conditions, static specs, effect data). The table uses it to refuse a filter naming other players (TableError::Players).

REFUSALS (GameTable::new, for a deck's card or a token it makes; beryl_session/src/replay.rs maps both to SessionError::Deck). Tests: beryl_kernel static_ability.rs (each reason, by product), table/tests.rs (a_table_refuses_what_the_engine_has_no_code_to_read), beryl_card ability.rs (the builder's assertion).

FILES. table.rs passed 800 lines with its new tests, so they moved to beryl_kernel/src/table/tests.rs (the shape trackers/tests.rs has). beryl_search/src/frozen/rollout.rs: the two reads of whose() now match Some(Players::You), the answer the old read gave.

COUNTS (just bench-count --bench rollout_counts, rollout_counts::cube_rollout, corpus), before at 53b549f7 and after:

  • rollouts: 388,633,629 -> 386,956,937 (-0.431%), under the gate's bar of 389,343,295, no bump
  • next_apply: 361,154,279 -> 359,488,028 (-0.461%)
  • policy: 1,746,603 -> 1,745,436 (-0.067%)
  • copy: 13,481 -> 13,481 The layers do no more work for the 47 cards: an ability with no static effect is one null test, as before; "this" and "attached to" are one match on the spec; only an ability with an "as long as" (impending) calls the reader. No capability bit was needed: a filtered set is never applied, so it costs nothing.

GAPS: what the vocabulary now says and the engine has no code path for. Each is refused when the table is built, never a silent no-op. They are docs/rules-coverage.md's project.

  • A static ability over a filtered set, Objects::All ("other Squirrels you control have menace", "all creatures have double strike", "legendary creature spells you cast have convoke"). The layers apply an ability to its own permanent or the one it is attached to. A filtered set must be found by the layers themselves, layer by layer, with dependencies (CR 613.8), and for a set on the stack or in another zone not by the layers at all. Unapplied::Affected.
  • A static "as long as" that reads the layers' own results or anything else they do not start from: Condition::Is, a Count of objects, Power, Toughness, ManaValue, Counters of an object other than this one, Times, a Custom condition ("as long as you control a red creature", "as long as it's a creature"). It would have to be read as the layers run. Unapplied::Condition.
  • A static ability that needs a resolution (a target, Those, X, ThatMany, Did, ThatPlayer). No code could ever read it; refused as the definition compiles by Ability::static_ability, and by the table for a struct literal. Unapplied::Resolving.
  • A filter naming players other than You, EachOpponent and EachPlayer: Target, ControllerOf, OwnerOf, ThatPlayer ("a land that player controls", "a creature its owner controls"). A filter is evaluated for one player, "you" (beryl_kernel filter::Evaluate), in target enumeration, the mana solver, trigger subjects and the interpreter alike; reading the rest needs the resolution's Scene passed into the evaluator. TableError::Players.
  • Not refused, and as before this bead: a static ability with a LayerSpec among a face's grants (an ability a continuous effect grants) is checked by the table but the layers apply only a face's own abilities; no card grants one.

PAPER TEST (scope 4), in beryl_card/tests/paper_test.rs (STATICS, AFFECTED, AS_LONG_AS, CONTROLS; test the_misfits_static_abilities_need_no_resolution).

A static "as long as" that is a general Condition (5, 26, 32, 60):
