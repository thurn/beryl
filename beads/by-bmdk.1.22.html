Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Views and animation' (the list "The two types need a few additions").

PlayerView and Script in rust/crates/beryl_session gain what a manual table needs. Every change is additive: an engine game's views and recordings must not change.

Add (files in the epic's Code map):

  • Status::Free in protocol/view.rs: the game is live and no decision is pending.
  • ZoneName::Sideboard in protocol/names.rs.
  • On ObjectView: note: Option<String>, pinned: Option<RowName> (a new enum Creatures | Others | Lands), face: FaceName (Front | Back | Down, default Front), named_counters: Vec<NamedCounter> with NamedCounter { name: String, count: u16 } beside the existing CounterView list (whose kind is a closed generated enum and whose count is a u8; leave it alone), doesnt_untap: bool, attached_to: Option<...> only if no such field exists already (check first and reuse it).
  • On the player's view (find the struct in view.rs that carries life): named_counters.
  • PlayerView.table: Option<TableView>, None for every engine game. TableView holds everything manual-only so nothing else grows: log: Vec<LogLine> (n, by, text, struck, undoable, blocked_by: Vec<u32>), proposals: Vec<ProposalView> (id, title, lines: Vec<{text, whose, on}>), labels: Vec<LabelView> (state nudges), assists (the viewer's five switches), phase (one of the eleven manual phases), seats: u8, acting: Vec<ZoneRef> (hidden zones lent or revealed to the viewer), prompt: Option<TablePrompt> (a host-held prompt; define it as an opaque tagged enum with one variant None-like placeholder; a later bead fills it).
  • Use #[serde(default, skip_serializing_if = ...)] on every new field so existing fixtures and saves still load and existing recordings serialize byte for byte as before.

Then:

  • List every new type in src/typescript.rs, and regenerate (epic, Rules, 6).
  • protocol/shown.rs names every PlayerView field; add the new one.
  • Fix every match and struct literal the compiler reports, in Rust and in ui/src (npm run typecheck). In the interface, handle Status free as "nothing pending" and ignore the other new fields: drawing them is milestone 2.
  • Constructors, so the manual adapter never writes a struct literal that breaks when the engine adds a field: in a new protocol/neutral.rs, PlayerView::neutral(you, opponent) (no priority, no legal plays, no decision, Status::Free, empty lists), ObjectView::card(slot, name, zone, controller, owner) and ObjectView::hidden(slot, zone, ...) with every other field at its default, and the same for the player and stack entry structs. protocol/build.rs keeps its literals.
  • Make public what the adapter needs: script::Table (of, apply), script::replay:: failure, Script, Step, Act and their payload types, and re-export them from beryl_session::script.

Tests: just test-rust -p beryl_session passes with no fixture or corpus file changed (git status shows none under ui/public/fixtures or the session's corpus); a new test builds a PlayerView::neutral, serializes it and reads it back; cd ui && npm run typecheck && npm test.

Acceptance criteria

All listed fields and types exist behind serde defaults; no existing fixture, corpus or save file changes; the generated TypeScript is current; neutral constructors and the script types the adapter needs are public; the engine game's tests and typecheck pass.
