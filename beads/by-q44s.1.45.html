Beryl 3D workspace, six crates, lane steps and checks on staging at 37adb2589

Description

Read first: the epic's 'Rules for every bead' and 'Code map'; docs/beryl-3d.md 'Components', 'Determinism' and 'Checks and isolation'. Then rust/Cargo.toml, rust/prototypes/beryl3d/Cargo.toml (a workspace outside the main one that builds against the main crates), tools/src/beryl_tools/warm.py (ensure_target, clone_into), board_door.py (a source lint to copy) and the package the bead before this one made, tools/src/beryl_tools/beryl3d.

  1. The workspace. rust/beryl3d/Cargo.toml is a workspace root: resolver = "3", members = ["crates/*"], its own Cargo.lock. Copy from rust/Cargo.toml the [workspace.package] table, the whole [workspace.lints] table, [profile.test], [profile.release], and the opt-level = 3 overrides for beryl_card_build, beryl_card_store and serde_json (the card crates' build scripts read the whole card store). Add rust/beryl3d/target to .gitignore. The main workspace's manifest and lock file do not change.
  2. Six library crates under rust/beryl3d/crates, each with [lints] workspace = true and a one-line description. Give each exactly these dependencies, pinned at exactly these releases (the ones the prototype built against), each with a Cargo.toml comment saying what it replaces. Do not choose other crates or versions.
    • beryl_scene: beryl_session (path ../../../crates/beryl_session), glam 0.34.3, taffy 0.15.1, parley 0.13.0. A Cargo feature driver, off by default, that guards no code yet. A build script with serde_json 1.0.154 as a build-dependency: it reads data/beryl3d/space.json and the audit object of data/beryl3d/gates.json and writes them to OUT_DIR/data.rs as constants, which src/data.rs includes. Create both files with empty objects ({"verbs": {}, "pointer": {}} and {"audit": {}, "frames": {}, "tiers": {}, "materials": {}, "tests": {}}).
    • beryl_render: beryl_scene, wgpu 30.0.2, bytemuck 1.25.2 with derive, pollster 1.0.1, image 0.25.10 with default features off and png.
    • beryl_assets: beryl_scene, image 0.25.10 with default features off and jpeg, png.
    • beryl_host: beryl_scene, beryl_render, beryl_assets, winit 0.30.13.
    • beryl_inspect: beryl_scene with driver, beryl_session. No GPU crate.
    • beryl_3d: the five crates above.
  3. In the tools package:
    • a warm build directory: before its first cargo command in a worktree, just b3d clones $BERYL_CACHE/b3d/target into rust/beryl3d/target with warm.py's clone_into, when the cache holds one (the sweep bead fills it);
    • subcommands: cargo <arguments> (cargo in the workspace), cargo-test [-p <crate>]... [filter] (its tests, run as just test-rust runs the main workspace's), clippy, fmt [--check];
    • purity.py, modelled on board_door.py. scene-purity: in beryl_scene/src it fails on std::time, std::thread, std::fs, std::net, std::sync::Mutex, std::sync::RwLock, std::collections::HashMap, std::collections::HashSet, wgpu and winit; in every crate but beryl_render it fails on wgpu::; and it fails if beryl_inspect/Cargo.toml names beryl_render, beryl_host, beryl_3d, wgpu or winit. lints-match: fails when the two workspaces' [workspace.lints] tables differ. data-names: fails when a key under verbs in data/beryl3d/space.json names no verb or case of data/ui-conventions.json. Python tests beside the other lints' tests;
    • the lane's steps, in this order: fmt --check, clippy (--workspace --all-targets -- -D warnings), cargo-test, scene-purity, lints-match, data-names.
  4. rust/beryl3d/AGENTS.md, with a one-line CLAUDE.md beside it that imports it: what the workspace is and why it is separate (C17); the six crates, one line each; that just b3d lists every command; the paths rule (Beryl 3D's files live only under rust/beryl3d, data/beryl3d and tools/src/beryl_tools/beryl3d); the data files, one line each; and that a break caused by a change to the main workspace is fixed in the Beryl 3D change that meets it. One line in rust/AGENTS.md and one in data/AGENTS.md point to it.

Measure, five times each with the load beside it, and put the numbers in a comment: a cold cargo check of the workspace; a cold debug build; and, after a one-line edit to beryl_scene/src/lib.rs, the rebuild of the workspace's tests.

Run: just b3d lane; just b3d cargo-test -p beryl_scene.

What the prototype found (rust/prototypes/beryl3d, 2026-11-14; read its code for a working example, then build it properly):

  • glam 0.34 deprecates Mat4::perspective_rh and Mat4::look_at_rh in favour of glam::camera::rh::proj::* and glam::camera::rh::view::*.
  • rust/prototypes/beryl3d has its own empty [workspace] and is built into $BERYL_CACHE/proto3d/target by just proto3d. Milestone 1's last bead deletes it.
