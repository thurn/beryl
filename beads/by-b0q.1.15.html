Warden review of by-b0q.1.2 and by-b0q.1.4. I ran each acceptance criterion to check it:

  • by cards: the replay regenerates data/cards.json byte for byte (test); 29 cards plus the 5 named tokens (7 tokens in all: Copy and the offspring too). The Python tests pass with outbound network denied (sandbox-exec).
  • beryl_app art: 5 tests (hit, miss with a download, failed download, spacing, path validation) pass offline. The spacing test only checks a lower bound, so it holds under load. Image::parse rejects traversal, uppercase and mismatched shards. just smoke passes with outbound network denied. No images are committed.
  • Oracles: from scratch in a fresh BERYL_CACHE, just oracle-setup took 234 s (XMage 141 s, Forge 86 s). The rerun is a no-op in 1.4 s. just oracle-smoke passes: EliteSpellbinderTest, 1 test run; the Forge sim game reaches a result. The coverage comment is on by-b0q. Fixed (staging 220b422): forge_jar picked the jar by text sort, which picks the old jar after a pin bump from 2.0.99 to 2.0.100. It now takes the newest jar by mtime. Also, by cards --replay X --record X would overwrite the fixture with []; the two flags are now mutually exclusive. Left alone: the scheme answers each request with a spawn_blocking thread that waits on the queue (fine at M1 scale). --cube writes to data/cards.json by default, which would break the byte-for-byte test if committed; that is documented as not committed. The cache is keyed by path without Scryfall's ?timestamp, so a rescan of the same printing is never refetched. That is acceptable.
