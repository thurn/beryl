Description

The module

Paths are relative to rust/crates/beryl_kernel/src/. Keep the existing paths unless a move is listed below.

asking.rs, cause.rs, chance.rs, decision.rs, event.rs, knowledge.rs, observation.rs, payable.rs, pending.rs, profile.rs, rng.rs, decision/collapse.rs, event/kinds.rs.

Use the module map in Design C for rule boundaries and other path moves.

A new Pending variant must go last, because the state hash reads the discriminant: say so beside the enum. Opt::{PlayLand, Attack, Block, Lethal, Defender} hold bare slots; the contract says whether they become references.

The kernel is organised by what it stores, not by rule, so most of its files declare //! Implements: none with a sentence, and a file declares a rule only where the kernel implements it itself (CR 400.7 in the zone move, CR 613.7 in timestamps).

What to do

One pass over this module, as three commits pushed separately (plan: Designs C, "One pass per module"). Read first: the module map in the plan, "Entities and records" and the typed-reference section of the kernel contract (rust/crates/beryl_kernel/src/lib.rs), the L: Layout section of the rules contract (rust/crates/beryl_rules/src/lib.rs), and the baseline Mason's comment on this bead listing one-card logic in these files.

  1. Move. Put each file where the module map says, with its //! Implements: header, and take the files off data/rule-ownership-allowlist.json. No behavior changes. A file that exists only because another reached 800 lines rejoins it or gets a name that says what it holds. A file still over 800 lines is split along rule boundaries. rule-ownership and file-length pass. Push this commit by itself, quickly: other passes rebase over it.
  2. Typed references. The module's functions take Permanent, Spell, CardIn and the set types where they mean one. Remove the is_current test a function made for itself where the type now carries it. Fix callers in other modules with the one-line adaptation the contract gives; do not convert their internals.
  3. Simplify. One query for each rules question the module answers (delete the parallel readers), no parameter nobody reads, no wrapper that only forwards, no comment that restates the code, and the L: Layout decision applied. Remove or generalise the one-card logic the Mason listed. Keep every Comprehensive Rules citation and quotation.

Behavior is held by just test-rust (scenarios, the mutation check, the frozen saves, rollouts_never_change), just fuzz 2000 and just count-gate. A test that pinned an internal you removed is rewritten against the query that replaced it.

The close reason gives the module's non-test lines before the pass and after each commit, the count before and after, and anything you found that is a rules bug (fixed with its docs/bugs.md entry, or filed as a child of this milestone). If simplifying finds little, say so: no number is a target.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.
