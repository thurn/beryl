Close reason

Mutation check over every card file (0 survivors, 3 equivalents, ~3 s) with regeneration and stolen-permanent witnesses; reach test retired

Description

What was seen

Five card definitions did less than their Oracle text said, and every check passed (the first entry of docs/bugs.md): Damn without "can't be regenerated", Thieving Skydiver without its attach, Currency Converter with "that card" for "that card from your graveyard". The Oracle text diff (just card render) found them. The scenarios did not, and still would not: a definition can say a clause while no scenario shows that the clause does anything.

Why

Two parts of the scenario machinery measure the wrong thing.

  • The generator (rust/crates/beryl_cards/src/derive/) starts every card from one fixed table of positions (derive/position.rs: lands, props and the card). Those positions exist to make a card playable. Nothing puts a regeneration shield in front of a destroy effect, a stolen permanent in front of "its owner's hand", or an empty set of legal targets in front of "up to one".
  • The test every_instruction_of_a_card_is_carried_out_by_its_own_scenarios (rust/crates/beryl_cards/src/tests/effects.rs) passes once a scenario reaches an instruction. Reaching destroy_without_regeneration with no shield in play shows nothing about the clause.

The oracles (XMage and Forge) only compare what a scenario reaches, so a position nobody builds is a clause nobody checks.

Change

Terms. A witness is a fragment of a starting position (permanents, cards in a zone, a step) under which two values of one field of a vocabulary entry give different outcomes. A mutant is a card definition with one node replaced by a neighbouring value.

  1. Witnesses. For each field of a vocabulary entry whose value changes what happens, declare its witnesses. Default location: a module in rust/crates/beryl_cards/src/derive/, keyed by the entry and field, because beryl_card may not name cards and witnesses are built from Prop:: cards (beryl_card_shared::props) and real cards. A witness that needs a card nobody has implemented means implementing a real card for it, as the card-writing skill's "Cards for scenarios" says. Never leave a witness out because the pool lacks the card.
  2. The generator uses every witness of every entry a card uses, whichever values the card's definition chose. Walk the definition with beryl_card::walk. A Damn written as a plain destroy then still meets a creature with a regeneration shield, and XMage and Forge, which read the Oracle text for themselves, disagree with Beryl in the oracle lane. Keep MOST_RUNS as the bound on what one opening adds.
  3. A mutation check in rust/crates/beryl_cards/src/tests/. For each card and each node of its effect data, build each neighbour, put the mutant in a card table in place of the card, and run the card's hand-written, library and generated scenarios in Beryl only. A mutant is killed when some scenario fails or ends in a different final snapshot. A surviving mutant fails the test with the card, the node and the neighbour. Neighbours to start with: each other variant of an enum field (Regeneration, a Players value, a destination zone, owner or controller), an amount one higher and one lower, an optional target made required and the reverse, a may removed, an If condition negated, one element dropped from a Sequence, a filter widened to Filter::Any.
  4. Survivors. A survivor means a witness is missing (add it, with a real card if needed) or the two definitions are truly equivalent (list it in a table in the test with the reason, as UNREACHABLE is today). There is no third outcome: "the engine does not implement the difference yet" is fixed, not listed.
  5. Retire the reach test once the mutation check holds on every card: a dropped Sequence element that survives is an instruction no scenario shows. Default: delete every_instruction_of_a_card_is_carried_out_by_its_own_scenarios and UNREACHABLE in the same change. Record it here if they must stay.

Regeneration is the first witness and needs the bead this one is blocked by.

Report on this bead

Before adding any witness, run the mutation check over the 48 card files and record: mutants per card, how many survive, and the survivors by cause. That number is how much today's scenarios miss. Record it again when the work is done, with the seconds the check takes and the generated scenarios added to the oracle lane.

Must not change

Every generated scenario still replays as written in the strict runner. The rust lane and the oracle lane stay inside their budgets (docs/checks.md). If the mutation check is too slow for the fast check over every card, run it for changed cards there and for all cards in slow CI; never raise a budget.

Design questions, with defaults

  • Scenarios stay the const builder data they are (Scenario::new(..).actions(&[..])), exported as JSON to the oracles. No separate scenario syntax.
  • Hand-written scenarios belong to a vocabulary entry (its witness) and to cards with a Rust body. Per-card scenarios come from the generator, and the oracles supply their expected outcome.

Acceptance criteria

Witnesses are declared per vocabulary field and the generator uses every witness of each entry a card uses; a mutation check runs over every card file and fails on a surviving mutant that is not listed as equivalent with a reason; changing Damn's Regeneration::Forbidden to Allowed is a killed mutant; the before and after survivor counts and the check's seconds are recorded on the bead; the rust and oracle lanes stay inside their budgets.
