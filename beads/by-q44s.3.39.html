Close reason

Beryl 3D places and marks merged cards, phased-out permanents, copies, hidden picks and For-opponent prompts (a4fbd1568)

Description

Symptom. While milestone 1 ran (2026-11-14 to 15), the web interface gained five object states and one zone that Beryl 3D receives but does not show. Beryl 3D only fills them in its test builders (rust/beryl3d/crates/beryl_scene/src/testing.rs). No milestone 2 or 3 bead names any of them (a search of by-q44s.3.* and by-q44s.5.* descriptions for each name finds none), so they would only turn up in the parity list in milestone 5.

The additions, all in rust/crates/beryl_protocol/src/protocol/view.rs ObjectView unless stated:

  • controlled_by: Option<Side>: a permanent controlled by the other player (8a1bf1cec, "view and draw phasing, merges, copies, control").
  • phased_out: bool: a phased-out permanent (same commit).
  • part_of: Option<ObjectId> and ZoneName::Merged: a card merged under another permanent (cfadf58d3 mutate, 8a1bf1cec, e76ba8678).
  • really: Option<String>: the card's real name when it is a copy of something else (8a1bf1cec, 751845137).
  • hidden_pick: bool: a hidden pick shown face down and set apart (50a00ba7b).

How the web shows each: read ui/src/stage (search for each field name) and the spec moments of the cards that cause them (Gemrazer for mutate, Phantasmal Image for copies, Thieving Skydiver for control; find a phasing card and a hidden-pick card with just card brief). Look up Arena's presentation with the arena-video skill where Arena has the mechanic.

Proposed change. Beryl 3D's table places and draws each state the way the web interface does: a controlled permanent on its controller's side, a phased-out permanent as the web draws it, merged cards stacked under their permanent, a copy's real name in the tree printout and inspector text, and a hidden pick face down and set apart. Each gets a stress board or fixture case so the interface checks cover it (rule 7 of the epic). If by-q44s.2.5 has landed, build test views with ObjectView::neutral.

Expected gain. Milestone 2 finishes with the table showing everything the session sends today, instead of milestone 5 finding these five gaps late.

Acceptance criteria

just b3d tree prints each of the five states for a fixture or spec moment that causes it, from both seats; each state has a stress board or fixture case that the interface checks run on; just b3d lane passes; the doc names each state where it describes the table.
