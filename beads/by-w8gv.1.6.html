AGENTS.md Code structure section, plan link and K31 bullet added

Description

Add a short "Code structure" section to AGENTS.md from docs/project-50k.md's Conventions, and link the plan from the Layout section. Keep it to rules an agent applies while writing code:

  • Spell words out; never misspell to dodge a keyword (static_ability, not statik).
  • No procedural macros written in this repo; a macro_rules! only where a const fn cannot remove the repetition.
  • No source file over 800 lines (the check and its allowlist).
  • No card name in generic code (the check and its allowlist); a one-card mechanic is a sign the abstraction is missing.
  • State a card creates lives in a store, not in a new field on Player, Object or State (plan K4).
  • Helpers shared by two cards live in the shared library, not in a card file.
  • The kernel, rules and card crates take no runtime dependencies; a new dependency's Cargo.toml comment says what it replaces.
  • Forge is a test oracle only: no card data, vocabulary or design comes from its scripts or code (plan K16). Also add one bullet to AGENTS.md's Enact section for plan K31, which the user asked on 2026-11-10 to hold for the whole project: no plan, bead or skill has a step that waits for the user's approval; where his judgement is wanted, proceed on a default and file a non-blocking bead labelled human (bd human list). Name the one exception, K1's count gate in docs/project-50k.md. The UI section already says this for UI judgements; do not repeat it there.

Run just fmt. Do not restate the plan.
