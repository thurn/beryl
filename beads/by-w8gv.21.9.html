Description

The session builds each seat's script for every update from today's flat events, and proves it by replay (plan K23, K24). This is the logic of ui/src/game/beats.ts moved to Rust. The inference is throwaway: step two (by-w8gv.21.5) replaces it with causes from the interpreter.

Read first: the epic by-w8gv.21 (the user's decisions, what was agreed with the CI track, the code map); docs/project-50k.md, Target architecture, Presentation (K22 to K31); docs/ui-conventions.md (generated from data/ui-conventions.json: edit the data). Then by-w8gv.21.8's handoff and its table of verbs.

Where

  • rust/crates/beryl_session/src/game.rs, draw_for(viewer) (about line 2024): builds each PlayerView through protocol.rs player_view(...) from self.events. sessions.rs (about line 258) wraps it as GameUpdate { session, view } (lib.rs:106).
  • Keep, per seat, the last view sent. Build the script from the previous view, the events and the next view in script/build.rs and send it beside the view. Decide whether the field sits on GameUpdate or PlayerView and say why on this bead; it must be optional on the wire, since recorded fixtures and older recordings have none. Regenerate ui/src/generated/protocol.ts.

What it ports (read as a list of cases, not as a design)

  • ui/src/game/beats.ts: the Walk class (from about line 263) cuts a view's events into beats: a spell or ability shown on the stack before it resolves, its effects before it leaves, a spell struck before it is carried off, cards shown face up before they land, draws, deals, shuffles; waterbendCuts, linkedReturnFlights, counterDeparture. The script expresses order and grouping only. HOLD (the table of fixed waits) is not ported: timing is the verbs' values.
  • Board.tsx tokenOrigins (about 2578) and triggerOrigin, abilityOrigin, abilityPlacement (2445 to 2527): which object a token or an ability came out of.

Scope

Steps for objects changing zone, face, tapped state, counters, attachment and controller; stack items appearing and finishing; players' life, hand and library counts, and mana pools as numbers. Arrows, lines, marks and the mana flow are by-w8gv.21.10. Put every guess at cause and simultaneity in one module (script/infer.rs) that step two can delete; the rest of the builder takes them as given.

The replay check

script/replay.rs applies a script to the previous view's table and must give the next view's table exactly (by-w8gv.21.8 says which part of a view that is). Run it as a debug assertion wherever the session builds a script, the way the engine checks its invariants on every debug apply (rust/crates/beryl_engine/src/invariants.rs, by-w8gv.1.4). A failure names the first field that differs and prints the script's text. A script is built only in the session; rollouts (beryl_search) never build views, so the count gate is untouched: confirm it and say how on this bead.

Decisions (script builder and replay check)

Code: rust/crates/beryl_session/src/script/ — table.rs (Table, what each act does to it), replay.rs (replay, failure), build.rs (Screen, the event walk), moves.rs (zone changes, the record a card arrives with), settle.rs (what no event told), infer.rs (every guess). Tests: tests/script_build.rs, one in tests/cancel.rs.

  • The field is on PlayerView (script?: Script), not GameUpdate. Every path a view takes is a PlayerView: Game's methods return one, review mode emits [PlayerView; 2], the fixture recorder and specs wrap them. On PlayerView the script travels all of them with no plumbing, and every test that plays a Game runs the check. It sits beside events, which it replaces at the cut-over. Optional on the wire; a view built by player_view alone has none.
  • A view's script is not part of its equality (protocol/shown.rs). A script depends on what the screen showed before, not on the game alone: a replayed game's last view is reached with no view before it, so its script is a reset where the live game's is steps. 18 existing assertions compare a replay's view with the live one. shown names every field, so a new field cannot be left out silently.
  • The table's stack is the view's, normalized (Table::of): the item whose resolution asks the viewer stays on top (a view drops it from its list for the viewer and keeps it for the opponent), and a spell is on the stack only while its card is (Time Spiral exiles itself and goes on resolving: the first case the check caught). The stage must do the same at a reset. This refines by-w8gv.21.8's "the table is the view's stack".
  • Events drive the steps; a settle pass closes the script. Each event becomes steps played on a working table with the same Table::apply the replay uses. Then every difference left against the view's table becomes a step: records (tap, flip, fly for side or host, count, and set for the rest, folded into the object's latest step where it has one), pile order, life, pool, turn, and the stack entry by entry. So a script always replays, and what settle writes is exactly what today's events do not tell: summoning sickness, power and toughness, blockers, mana pools, targetless triggers, a cast taken back, turning face up.
  • Guesses are in infer.rs only: cause by segment (costs before a Cast or Ability are the player's; events before AbilityFinished or a spell's resolve departure are its effects; the rest is loose), which events share a beat, dwell, cards already looked at, a loyalty cost shown after its ability, which stack entry is which (same, pair). The builder takes them as given.
  • Verbs emitted here: fly, appear, vanish, emerge, flip, tap, strike, streak (damage only), count, set, dwell, announce (turn, scry, coin). Not emitted: showcase (a reveal has no event), point, mark, lift and mana streaks (by-w8gv.21.10).
  • Damage carries its own consequences: the engine emits no LifeLoss for damage to a player, no counters event for a planeswalker and nothing for marked damage, so strike and streak carry the record and a count life joins their beat.
  • Arena's order where the events' differs: a loyalty cost counts after its ability emerges; a trigger lifts out of a permanent before that permanent leaves; a counterspell leaves with the spell it countered; what a permanent held in exile returns with it.
  • Dwell is the opponent's only: your own spell resolves as soon as the opponent passes.
  • Reset at a seat's first view, an undo, the end of a replay and a concession that took a cast back (that view is never sent). A release build resets instead of leaving the stage out of step; a debug build panics.

Count gate

Untouched, by construction: scripts are built only in Game::draw_for (beryl_session). beryl_bench, beryl_search and beryl_engine do not depend on beryl_session (no beryl_session in their Cargo.toml), so the rollout benchmark's binary has no script code. cargo test -p beryl_bench rollouts_never_change passes; cargo test -p beryl_session --test corpus passes (5).

Measured

  • cargo test -p beryl_session: all pass with the assertion on. cargo test -p beryl_cli: all pass (spec generation plays every moment from both seats).
  • Cost of the check: beryl_cli's tests, three runs each way, 143/155/121 CPU-seconds with scripts and 147/135/131 without: within noise.
  • just check passed; it reported 81 s load-adjusted against the 60 s budget with the load average at 36 on 18 cores (rust tests 77 s). by-w8gv.21.8 saw 70 s the same way.
  • All 1,682 views of the recorded UI fixtures carry a script; just ui-test "Space passes priority" and npm run typecheck pass.

What the check found

  • Time Spiral: a spell item on the stack whose card was in exile (fixed in Table::of).
  • A replayed game's screen was left at an undo's table by the replay's own undo (fixed: a replay ends with fresh screens).
  • A stack whose order the events could not give (a spell with no event under an announced ability): settle now places the stack entry by entry.
  • Deviation: game.rs and protocol.rs may not grow (file-length allowlist), so the protocol's unit tests moved to protocol/tests.rs and new_agent to ai.rs; protocol.rs's entry fell to 2465.

For by-w8gv.21.10 (arrows, lines, marks, mana):

  • Add steps with Builder::emit(act, cause); it plays the step on the working table and opens or joins a beat (self.open). Spans change no table, so the replay check ignores them: hold open spans in Screen beside the table, and end an arrow before the step that moves its target (zone_change in moves.rs is where a card leaves; lift, announce and cast in build.rs are where an item arrives).
  • Mana: the Mana and ResolutionPayment arms of Builder::event are empty; pools are settled as count pool at the script's end. The item a streak pays into is Builder::spell (moves.rs) or the Ability event's.
  • Combat roles are on records already: Tap carries the attacker's role, Attack sets it for a vigilant one, blockers are settled as set. Lines hang off those steps.
  • infer::Told is per event; add a guess there, never in the builder.
  • tests/script_build.rs: scripts(card, scenario) gives every script of a card scenario for both seats; the ignored dump test prints them (SCRIPT_DUMP='card|scenario' cargo test -p beryl_session --test script_build dump -- --ignored --nocapture). Test views are built by player_view with no decision, so handling, looked cards and resolving are not exercised there; Game-level tests exercise them.
  • game.rs is at its allowlisted 2225 lines and protocol.rs at 2465: neither may grow.

For the stage (by-w8gv.21.14): read view.script; with no table yet, take the view's table whatever the script says (Table::of's rule for the stack applies); Reset.abilities numbers the abilities on that stack bottom first. A zone change with at none goes to the end of its pile; vanish with no object ends a token or an ability.

A reviewer should check: equality of views without the script; the settle pass as the way a script always replays (it makes the check a test of the steps' completeness and of Table::apply, not of the events); the guesses in infer.rs against beats.ts; that emit drops a step the table cannot take (the check then fails in debug, a reset follows in release).
