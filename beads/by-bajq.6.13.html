count gate rollouts 381,086,774 -> 379,934,379 on cc0ada10 (-1,152,395): layer 1 tests Flag::Copy once, move_object one Option; match_event's ~300K codegen cost left, explained on the bead

Description

Two beads of the copies group raised the absent-cost count (just count-gate, the WU Control mirror's rollouts under Callgrind) by more than 0.05% without saying where the cost was:

  • by-bajq.6.2 (commit 7518451, entering as a copy): 395,479,184 -> 396,201,947, +722,763 (+0.18%).
  • by-bajq.6.4 (commit 3cfaa15b, spell copies and storm): 395,691,316 -> 396,240,273, +548,957 (+0.14%).

The WU mirror has no copy card, so by the gate's rule (rust/crates/beryl_bench/count-gate.toml) a mechanism it doesn't use must cost it nothing. The staging tip still passes (384,120,994 on e86b9c75, -0.02% against the bar of 384,206,865), but only because other work lowered the count; the slack these two used is gone for the next bead.

Suspects from reading the diffs, unmeasured:

  • 6.2: triggered abilities on the stack and waiting are now AbilityRef<L, TriggeredAbility> (beryl_kernel/src/stack.rs), and trigger::ability goes through Face::ability(FaceAbility), a branch on every lookup where it used to index face.abilities. replace::entering calls copy_to_enter for every entering permanent whenever Capability::ChoosesAsEnters is set, which an Aura in the deck sets (beryl_kernel/src/table/capability.rs); it scans the face's abilities and calls layers::lost_entering. StackEntry::ability decodes TriggeredAbility. move_object's new restore of Memo::Really (effects/copy.rs leaving_copy).
  • 6.4: trigger::cast_before filling TriggerInfo.amount on Casts triggers; event::move_batch letting a token leave the stack; sba::doomed no longer sweeping stack tokens; State::copiable_base and copiable_colors reading copy exceptions in layer 1 and off the battlefield.

Measure, don't guess: build the gate's benchmark at each commit and its parent, and diff the two Callgrind profiles per function (callgrind_annotate --diff, or Gungraun's output in the VM's GUNGRAUN_HOME; see tools/src/beryl_tools/bench.py count_script). Move each cost found behind a capability bit (a separate EntersAsCopy capability instead of sharing ChoosesAsEnters, for example) or out of line with #[cold], per docs/benchmarking.md.

Acceptance criteria

Each function whose count rose with 6.2 or 6.4 is named in a comment on this bead with its count before and after. The costs a game without copy cards pays are removed, or a comment says why one cannot be. just count-gate reports the count before and after in the close reason; it does not rise.

Measured with Gungraun/Callgrind in the beryl-bench VM, rollout_counts::cube_rollout::rollouts::corpus, each commit and its parent built in its own detached worktree, profiles diffed per function (callgrind_annotate, exclusive Ir, inlined code folded into its caller) and per source line.

6.4 landed before 6.2: 3cfaa15b's parent 34ced856 counts 394,035,754, 3cfaa15b counts 394,440,106 (+404,352), and that is exactly 6.2's parent 6e27d714. 7518451 counts 395,568,033 (+1,127,927).

6.4 (spell copies, 3cfaa15b), by function, before -> after:

  • beryl_rules::layers::recompute 19,703,253 -> 20,286,989 (+583,736). apply_layers called the new State::copiable_base (power, toughness and colors behind Flag::Copy) instead of copiable_pt; inlined into the loop, it cost more than the call it replaced.
  • beryl_rules::engine::advance 24,043,507 -> 23,847,937 (-195,570): inlining moved.
  • beryl_rules::event::move_batch_to 10,047,217 -> 10,087,960 (+40,743): the token-off-the-stack test, about 2,300 by line; the rest is layout.
  • State::in_game_order 2,343,042 -> 2,319,172 (-23,870); the rest under 7,000 each.

6.2 (entering as a copy, 7518451), by function, before -> after:

  • beryl_rules::layers::recompute 20,286,989 -> 20,834,558 (+547,569): a second Flag::Copy test per permanent for the copy's subtypes (119,815 for the flag read plus 119,815 for the test, by line) and loop layout.
  • beryl_rules::trigger::match_event 9,608,951 -> 9,895,470 (+286,519): no work added on the WU mirror's path (TriggeredAbility::own wraps an index; the GivesTriggers pass is behind its capability). Lines in trigger.rs with no source line +295,470 and the listens_away read +83,376: code generation.
  • State::move_object 1,668,325 -> 1,770,806 (+102,481): building (carried, really), a pair of options, on every move (+86,556 by line) and the restore test (+14,426).
  • cast::costs::total_cost 439,250 -> 512,693 (+73,443), cast::parts::pay 676,698 -> 726,982 (+50,284) and cast::steps::pay_mana 240,168 -> 188,326 (-51,842): inlining moved between them (stack entries' ability() decoding TriggeredAbility).
  • State::in_game_order 2,319,172 -> 2,373,542 (+54,370), with its sort closures moving (+48,568 / -42,884): layout.
  • event::move_batch_to +45,491, trigger::enqueue +33,075, trigger::fires -33,059: layout.
  • replace::entering's copy_to_enter does not show: it is already #[cold] behind ChoosesAsEnters (which the WU mirror's Aura sets), and layers::lost_entering moved only -524.

Fixed: layer 1 reads the flag once and a copy's values come from one cold call (State::copy_layer_one); leaving_copy restores the card a card copy really is itself, so move_object is back to one Option. Not fixed: match_event's code-generation cost, which has no source-level work to move behind a capability. Result on staging cc0ada10, same VM: 381,086,774 -> 379,934,379 (-1,152,395): recompute 20,669,657 -> 19,575,397, move_object 1,939,626 -> 1,881,511.
