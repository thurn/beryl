Close reason

Six tests read CARGO_MANIFEST_DIR at run time (26a8535); binaries from a removed worktree pass

Description

Six tests in rust/crates read files via env!("CARGO_MANIFEST_DIR"), which bakes the building worktree's path into the test binary. Worktrees share a warm rust/target (warm.py clones it), and cargo does not rebuild a crate whose sources are unchanged, so a test binary built in a since-removed worktree keeps its path. On 2026-11-06 by-0w2.24's enact push failed its fast check: beryl_engine tests::banned::the_engine_crates_use_no_banned_types panicked with NotFound in read_dir, because the binary held /Users/dthurn/beryl/.worktrees/ci-8640e6bcd21f/rust/crates/beryl_engine (a removed CI worktree). Touching banned.rs to force a rebuild made it pass. Fix: read the directory at run time (std::env::var("CARGO_MANIFEST_DIR"), which cargo test and nextest set for the test process) in every such test, or otherwise stop cached binaries carrying another worktree's path.

Acceptance criteria

No test in rust/crates locates files through the compile-time env!("CARGO_MANIFEST_DIR"); a test binary built in one worktree passes when run from another after the first is removed; just check passes.
