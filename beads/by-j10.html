Derek Thurn2026-11-08

Cause: infrastructure, not code. This was the first slow-CI run ever on this Windows machine (cygnus), and enact push starts the detached CI runner before its remove hook saves the pushed worktree's rust/target and ui/node_modules into BERYL_CACHE (D:\beryl-cache). The cache was empty, so the CI worktree built everything cold with all lanes at once (clippy 308 s compiling deps such as thiserror); the rust lane hit the 600 s deadline. Every lane that finished passed. Verified: a fresh enact worktree at the same tip 21ec8df, with the cache now filled (cloned in 1.3 s), passes all lanes of by ci in 177 s (budget 300 s). No code change; 21ec8df reaches master with the next staging tip's slow-CI run. Possible Enact follow-up: run the worktree remove hook before starting the CI runner, so a machine's first CI run starts warm.
