Handoff (staging d1560b5ef): Beryl 3D's bug report works end to end.

What was built:

  • beryl_scene screens/bug_report.rs (BugForm, BugStage: Capturing, Select, Describe, Saved) and client/bug.rs. Cmd+B freezes the table's clock (Bug::table) and sends Request::FreezeFrame. Nothing of the report is drawn for two frames, then the region chooser appears. A drag chooses a region; a click, Space, Return or "Whole window" takes the whole window. The describe stage has the description field (focused), "AI play" and Submit (or Cmd+Return), which sends Request::SaveBug { description, ai, region, window }. The host answers with the new Input::BugSaved(Result<(), String>). On Ok, "Saved" shows for 900 ms and the report closes; on Err, the error shows under the field. Escape or "Close" closes the report at any stage. After it closes, the table's clock runs behind by the frozen time, so a script resumes where it stopped.
  • beryl_3d src/bugs.rs: on FreezeFrame the app reads back the next frame, sharing the read-back queue with the live socket, and keeps tree(client.last_frame()) as tree.txt. SaveBug writes with the new beryl_session::bugs::write_attached (adds tree.txt and frames.jsonl). In a live game it runs on the session thread (Commands::save_bug, Session::save_bug); for a replay it runs on its own thread. ExportBugs writes ~/Downloads/beryl-bug-reports.zip and prints beryl3d: bug reports exported to <path>.
  • The key action of drive scripts and just b3d live do takes modifiers (KeyChord, as in key Cmd+B). Picture::png and Picture::crop were added in beryl_render, and the WHOLE icon in beryl_assets.

Deviations from the bead:

  • The sheet shows the frozen table itself, not the read-back picture as a flat image. The client keeps drawing the frame that was read back, which is the same image, and the renderer needs no window-sized texture path. For the same reason there is no thumbnail of the region in the describe stage. docs/beryl-3d.md "Bug reports" now says this.
  • While the report is open, the flat layer counts as drawn (Client::open), so the report shows even if the table froze mid-script. The screen under it is shown only if it was drawn at the freeze. Floats (life totals, pile counts, the gear) show only while the picture is taken, because floats are drawn over the screen and would otherwise cover the report.
  • The scene tests are in a new tests/all/bug_report.rs, not screens.rs. The beryl_3d test (tests/all/bugs.rs) checks the files and report.md's status: open. It does not run just bugs list; that was run by hand (below).
  • A report from a replayed recording has no replay.json or view.json, because there is no session game. A web report from a fixture page has none either.
  • The phone keeps the desktop's "Saved then close" behaviour, not the web's Share/Done panel.
