Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Two apps on one machine'.

Add the developer command for a person (agents never run it: it opens windows).

  • just table-pair in the justfile, implemented in tools/ (by, Python, standard library; follow an existing subcommand such as the one behind just dev). It builds the debug app once, then starts two instances: BERYL_PROFILE=host and BERYL_PROFILE=guest.
  • The host instance is started with BERYL_TABLE_PAIR=host: at launch it imports the WU Control list (docs/sample-decks/2025-11-18-17lands-cb8d5d5f-wu-control.txt) as its deck, calls table_host { link: "local" } and writes the invite to $BERYL_CACHE/table-pair/invite. The guest instance, with BERYL_TABLE_PAIR=guest, waits for that file, imports the same deck, and calls table_join. Both then start the game so two windows show a table. Put the launch handling in rust/crates/beryl_app/src/pair.rs, active only in debug builds.
  • Like just dev, the command refuses to run for an agent; find how just dev detects one and reuse it.
  • Document the command in rust/AGENTS.md beside just dev.

Tests: a pytest for the tool's argument handling and its refusal for agents; a Rust unit test for the pure part of pair.rs (what to do for each variable value). Run just check. State on the bead that the command itself was not run.
