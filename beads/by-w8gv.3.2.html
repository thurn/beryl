Close reason

Interpreter runs every Effect, Objects, Players, Amount and Condition entry through EffectCtx's primitives (staging 6506eacc); five cards written as body and as data give identical events and state hashes over their scenarios; may_pause and removal derived from data; allocation tests pass; count gate 405,672,852 (+0.10%, no bump)

Description

In beryl_engine, resolve Behavior::Data by walking the Effect tree and calling the same primitives EffectCtx's methods call today (effect.rs, event.rs, zone.rs), so a card ported to data produces the same events in the same order as its Rust body did.

  • Generic over the layout once (fn run<L: Layout>); effect data itself is not generic, so bodies! disappears for data cards.
  • Pausing: choices inside the tree go through the same answer source (Answers, the choice record, architecture §7.3). may_pause is derived from the data (does the tree contain a choice?), and a debug assertion compares it with the declared flag while both exist.
  • Derive what cards declare by hand today where the data says it: .removal() on a target spec, Needs.
  • Coverage (beryl_engine coverage feature) records a data ability as it records a body.
  • Keep it out of line of the no-ability fast paths; no allocation (the counting-allocator test must pass).

Acceptance criteria

A test card defined once as a Rust body and once as data produces identical event streams and state hashes across its scenarios; allocation test passes; count gate unchanged.

Decisions and deviations (executor):

  • may_pause: the engine now reads Ability::asks() (resolve.rs, effect.rs's assertion, beryl_session game.rs), which for effect data is Effect::asks() and for a Rust body the declared flag. So a data ability declares nothing. The debug assertion (interpret::data) is one-way: a data ability that declares may_pause must contain an instruction that asks. Strict equality would have forced every data card to keep declaring it.
  • .removal(): derived by Ability::removes_target (declared, or the data moves a target whose spec may be a permanent); cast::target_removes_permanent reads it. Effect::removes alone is not enough: Reprieve returns a target spell, which is not removal.
  • Needs: nothing derived. Its only variant is ExiledWithSource and the vocabulary has no reference to the cards exiled with the source, so the data cannot say it yet; it stays declared.
  • Targets: legality is settled once as the resolution begins (CR 608.2b), not at each use as bodies do. What is known of a target is captured as the effect moves it (controller, power, toughness, mana value, counters), so ControllerOf/Power/... of a moved target read last known information (CR 608.2h). Objects::Those and All read objects as they are now.
  • May asks a YesNo with Ask::Plain: there is no generic ask until M6's prompt shapes.
  • not_yet is gone. One panic remains (run.rs no_primitive): CopyException::PowerToughness other than 1/1, since the engine's tokens carry only the ONE_ONE mark.
  • Condition::Paid on a source that has left keeps entered_with's answer (true), as today's bodies have it; right for an intervening if, a guess inside an Effect::If.
  • An instruction acts on all its objects in one batch where the primitive is one (destroy, sacrifice, exile, hand, library); otherwise per permanent in battlefield order (exile until, counters, Modify: one floating effect and timestamp per object, as the engine's effects are per object).
  • beryl_scenario gained watch() (state and events per action) for the parity test; Failure moved from run.rs to lib.rs to keep run.rs under its allowlisted length.
  • beryl_cards now depends on beryl_card (3.3 needs the builders).
  • Counts: just count-gate gives 405,672,852, +0.10% against the bar (405,276,238), no bump.
  • Seen once, unrelated: beryl_cli longthink::files::tests::a_second_lock_names_the_first_holder failed in a full workspace run under load and passed alone and on rerun.

What exists

  • rust/crates/beryl_engine/src/interpret/: mod.rs (resolve, data, mana_ability, add_mana, intervening_if), scene.rs (Scene: reads Objects, Players, Amount, Condition against a game; Who, Outcome, Known, Registers), run.rs (Run: carry_out runs every Effect entry through EffectCtx's methods and event::move_batch_to).
  • beryl_card: Effect::asks(), Effect::removes(target), Ability::asks(), Ability::removes_target(target).
  • beryl_engine: filter::mana_value (extracted from Filter's evaluator), cast::spells and cast::in_zone and EffectCtx::check are pub(crate).
  • beryl_scenario::watch(cards, scenario, |state, events|); Failure now lives in lib.rs.
  • Tests: beryl_cards/src/tests/effect_data.rs (Mana Tithe, Oust, Get Lost, Portable Hole and Reprieve, each with its own copy of the Rust body and a data twin: same events and state hashes over the card's scenarios, coverage hit, derived asks and removal); beryl_engine/src/tests/effects.rs (nine tests of the entries no card uses yet).

For by-w8gv.3.3 (porting the corpus)

  • Write a card's ability as body: Behavior::Data(&EFFECT) with builders from beryl_card::effect::build (beryl_cards depends on beryl_card now). Drop may_pause and .removal() from a ported ability: both are read from the data. An effect naming another static (a token's CardDef) must be a static of its own, not an inline &sequence(&[..]).
  • The five twins' data in effect_data.rs is ready to copy into the cards' files; keep that test's own body copies, they are its reference.
  • Objects::Target(n) and Players::Target(n) count instances of the word target (Target::spec), not places in the entry's list as ctx.target(i) does.
  • Not expressible yet, so these stay Rust bodies: counter-and-exile (No More Lies), anything reading the trigger's object or the cards exiled with the source (Currency Converter), searches, looks, choices among objects, untap, damage, gain control, emblems, delayed triggers. May asks a plain yes or no (Ask::Plain), so a may whose prompt needs more than that waits for M6.
  • Counts: just count-gate gave 405,672,852 here (+0.10% on the bar). The interpreter builds a Run (legality of each target, about 150 bytes of registers) for every data resolution and is out of line (interpret::data is inline(never)); mana abilities never reach it.

What a reviewer should check

  • run.rs against the bodies it replaces: each instruction's primitive and Reason (destroy_all, move_all Sacrifice, move_batch_to for hand and library, cast::counter), and unstack's flashback exile against EffectCtx::return_to_hand and put_spell_into_library.
  • scene.rs: last known information is kept for targets only; ControllerOf(Those) and of All read the objects where they are now (owner off the battlefield and stack, CR 108.4a).
  • That legality is settled as the resolution begins (Run::new), where bodies ask at each use.
  • The one remaining panic (CopyException::PowerToughness other than 1/1) and the decisions in the comment above.
