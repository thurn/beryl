Description

The module

rust/crates/beryl_card/src/: effect/, ability.rs, ability/, cost.rs, trigger.rs, filter.rs, target.rs, continuous.rs, continuous/, characteristics.rs, definition.rs, decision.rs, prompt.rs, counter.rs, mana.rs, mana_notation.rs, words.rs, ids.rs, index.rs, facts.rs.

The vocabulary implements no rule, so it declares none; each entry's doc comment cites the rule it stands for, and those stay. There is no move and no typed-reference commit here. This pass is the simplify commit alone, aimed at the card writer:

  • Every builder a card file calls reads like the clause it stands for. Where a card file must write a long form (Filter::Not(&Filter::Types(Types::LAND)), Objects::All { zone: Zone::Battlefield, filter: .. }), add the short builder (nonland(), permanents(filter)) and use it in the card files and in beryl_card::phrases (the phrase library, built in the card-workflow milestone: do not duplicate a phrase as a builder; a builder is a vocabulary word, a phrase is a wording).
  • effect/mod.rs and ability.rs are at the line limit (800 and 794 lines): split them by kind of entry, one file each for zone changes, damage and life, counters, tokens and copies, control and continuous effects, casting, and flow (Sequence, If, May).
  • The predicates the lint sweep added so that readers need no wildcard arm (Effect::moves_objects and the like) sit beside each enum, each an exhaustive match.

card-text must pass with no allowlist change and the mutation check with no new EQUIVALENT entry. The close reason gives the median definition length of a card file before and after, and the crate's non-test lines.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.

Acceptance criteria

Card files use the short builders; no vocabulary file is over 700 lines; card-text passes with no allowlist change. The close reason gives card definition length and crate lines before and after.
