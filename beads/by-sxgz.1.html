Close reason

Mutation check now mutates tokens' and emblems' abilities; all 5 new mutants killed

Description

The mutation check (every_mutant_of_a_card_is_killed_by_its_scenarios, rust/crates/beryl_cards/src/tests/mutation.rs and mutation/neighbours.rs) mutates only the abilities on a card's own faces. A token or emblem the card makes (CardDef::tokens, reached by pointer from Effect::CreateTokens, CreateAttackingTokens and GetEmblem) is a CardDef of its own and is never mutated, so a wrong Map token explore (Get Lost), Rogue/Treasure (Currency Converter) or Teferi, Hero of Dominaria's emblem trigger passes unseen. Extend neighbours::mutants: for each token t of def.tokens and each mutant of t, rebuild the card with t replaced by the mutant both in def.tokens and in every CreateTokens/CreateAttackingTokens/GetEmblem node that points at t (std::ptr::eq), then run the card's scenarios as today. Fix each survivor with a witness (derive/witness.rs) or a scenario, or list it in EQUIVALENT with a reason.

Acceptance criteria

Mutants of every token and emblem a card file makes are built and played; the check passes with each survivor killed or listed with a reason; the check stays a few seconds.

Handoff: rust/crates/beryl_cards/src/tests/mutation/neighbours.rs: mutants() = own_mutants() (the old face-only body) plus, for each def.tokens[k], each own_mutants(token) rebuilt into the card by making(), which replaces the token in def.tokens and, via swapped()/replaced(), in every CreateTokens/CreateAttackingTokens/GetEmblem node that points at it (std::ptr::eq), walking the same children as Effect::any. Node names are prefixed with the token's name, e.g. 'Teferi, Hero of Dominaria Emblem: ability 0, target 0'. Five new mutants (Jace VP emblem x3, Teferi emblem, Get Lost Map); all killed by existing scenarios with real outcome differences, not panics, so no witness or EQUIVALENT entry was needed. New test a_mutant_of_an_emblem_is_a_mutant_of_its_card. Gotcha: run the check in debug, not --release: Jace, the Mind Sculptor's Fateseal count mutants (2 and 0) survive in release because the engine checks the count only with debug_assert_eq! in beryl_rules actions/fateseal.rs. Tokens made by a Custom (Rust) body are not rewritten; none exist today. Check takes ~2.9 s in debug.
