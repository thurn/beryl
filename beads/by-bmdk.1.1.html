Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'The table', 'Hidden information', 'Placement', 'Actions'.

Create the crate rust/crates/beryl_table that every other table bead fills in. This bead fixes the types, so later beads only add function bodies in their own files.

Build

  • src/state.rs: Seat(u8), ObjectId(u32), Card::{Named(String), Custom{..}}, Face::{Front, Back, Down}, Row::{Auto, Creatures, Others, Lands}, Zone (per seat: Library, Hand, Graveyard, Exile, Sideboard; shared: Battlefield, Stack), Object with exactly the fields of the doc's example, AbilityMarker { source, text }, Player { life, counters: Vec<(String, i32)> }, Phase (the eleven phases in the doc), Arrow { from, to, by, kind }, Match (decks, sideboards, starting life and hand size, score), Proposal { assist, lines: Vec<Line> } with Line { text, whose: Seat, on: bool, actions: Vec<Action> }, and Table holding all of it. Every zone is an ordered Vec. Counter counts are 0 to 999. Everything derives Serialize, Deserialize, Clone, PartialEq.
  • src/action.rs: enum Action with one variant per name in the doc's Actions table (move ... batch), serialized exactly as the doc's JSON examples (externally tagged, snake_case, objects plus the zone the sender saw them in). move's to also accepts "play" and "resolve" (epic, Defaults). Write a round-trip test with the doc's two examples copied verbatim.
  • src/change.rs: enum Change, the reversible primitives listed in the epic's Contracts, with fn perform(&self, &mut Table) and fn inverse(&self) -> Change. Knowledge changes (known_to gaining a seat) invert to nothing: undo never removes knowledge.
  • src/chance.rs: Chance with two modes, fresh(seed) and replaying(recorded).
  • src/apply/mod.rs: pub fn apply(..) as in Contracts. It checks permissions and staleness by calling permissions::check (leave that function returning Ok(()) with a todo comment naming bead "permissions"), dispatches each Action variant to a function in apply/cards.rs, apply/library.rs, apply/players.rs or apply/game.rs, performs the returned changes, and returns the Entry. Implement move (all positions, faces, tapped) and tap fully, with the consequences in the doc's list after the Actions table (leaving the battlefield clears state, a token leaving ceases to exist, arrows touching a moved card are removed, a card entering a hand gets a new id and known_to of its owner only). Every other variant returns Err(Refusal::Invalid) from a stub in the right file.
  • src/lib.rs: a doc comment that is the crate's contract: what the table is, that it never interprets a card name, and the two places knowledge is removed.

Tests

just test-rust -p beryl_table. Cover: JSON round trip; move to each zone and position; each consequence above; perform then inverse().perform restores the table for every Change variant.

Not in this bead

Permissions, redaction, log, undo, the other actions. Do not read beryl_kernel or beryl_session: nothing here resembles them on purpose.

Acceptance criteria

The crate builds with workspace lints; every Action name in the doc's table is a variant that round-trips through the doc's JSON shape; move and tap are implemented with their consequences and tested; every other variant is routed to a stub in its apply/ file; Change::inverse is tested for every variant.
