Close reason

one mirrored life orb; flare marks the active player (1332287)

Description

The docs/ui_mockups images are generated references, not a pixel spec: they are not consistent with one another, and earlier pixel-matching work fitted code to each one separately. This bead removes one such fit. Prefer one rule that holds in every state over matching any single mockup. just ui-compare verdicts for the affected regions may get worse; that is expected, so do not tune values back toward the mockups.

ui/src/components/Player.tsx's LifeOrb draws each seat separately. BLADES and CORE give the two seats different blade curves, thicknesses, tones and tip shapes, and different core sizes and offsets. Only your orb has the arch and the bevel filter, and only the opponent's has glints. Make it one orb, mirrored vertically for the opponent (blades sweeping toward that player's edge), with one set of blades, tones and core.

Also, game/Board.tsx lights an orb only when its player is active and also holds priority (active === side && view.turn.priority === side), so neither orb is lit while the non-active player holds priority. Decide what the flare means (the active player is the natural choice), apply it to both seats, and say so in the code.

Acceptance criteria

Both seats draw the same orb geometry and tones, mirrored; the flare has one documented meaning for both seats. just check and just ci pass, with no new constants tuned to a single mockup.
