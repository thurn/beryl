Acceptance verified by running: beryl_session tests (scripted human vs random, replay reproduces; no-hidden-identity determinization test), ts-rs staleness test, ui typecheck, just smoke, just ui-shots (game-first-target renders the recorded fixture). Fixed in 1a5184f: (1) Game::from_replay kept every event of the replayed game in the resumed view; it now drains at each human decision as live play does, and both replay tests now compare whole views including events (they failed before the fix). (2) Replacing a game left the old session thread playing all the agent's decisions to the human's next and then emitting a stale game-update the UI showed over the new game; GameSession now sets the Game's stop flag on drop (agent stops between decisions, nothing emitted after), start_game drops the old game before starting the new one, session numbers are monotonic even after a failed start, and useGameUpdates drops views from older sessions. New test a_stopped_game_lets_the_agent_decide_no_more. Left alone: deviation 1 (stops apply to both seats; every profile is sound per arch §15, so it only widens or narrows the agent's options), set_stops racing a choose re-emits an already answered view (harmless), Game.tsx stopgap UI, the session thread dying silently on an engine panic (engine bug, not protocol). A search agent's single in-progress decision still runs to completion after a drop; the stop flag only prevents later ones.
