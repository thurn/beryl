Warden review of the prompt shapes (beryl_scene src/prompts, client/own.rs, carry.rs, input.rs drop_held, play/tray.rs) against the web's prompt.ts, PromptBar/Choose/Tray/Aim and docs/beryl-3d.md 'Timing a script'.

Faults found and fixed (992e0c61d):

  1. A closed prompt's tray let-go did not hold its beat. The web's lowered puts the let-go first in the answering script's beat, so that beat lasts until the 300 ms let-go is over; native placed the let-go there, but the next beats began when the script's own steps ended. This hid behind parity entries whose differing steps were script steps (shape-yes, shape-split, verbs-scry, flashback, most of combat-attackers and late-game), so the "no entry whose differing steps are all own steps" test of by-q44s.5.54 missed it. Fix: beat::lay takes an optional leading step's timing (a Cursor refactor with the same arithmetic); Show::relay lays the awaited script's beat out again with OwnStep::TrayLetGo's timing first (Show::let_go_timing, from own_timings() at Show::new, so frames allocate nothing) and shifts the rest. The debug check waiting_steps_move_nothing moved from shift to relay's call site and accepts the uniform shift from the next beat on. Parity: 111 steps in 21 recordings -> 82 in 17; allowlist lowered, nothing raised. Test: motion.rs a_leading_step_is_laid_out_first_in_its_beat; the parity list holds the recordings.
  2. An order item carried while its prompt closed stayed drawn under the pointer until release, and the drop went to whatever prompt was open then (state kept in the client across a reply). carry.rs now ends the carry when the item leaves the open prompt or the table stops taking presses, and on a second press. Test: prompts_order.rs a_trigger_carried_as_the_prompt_closes_goes_back_and_is_not_dropped (fails without the fix).

Checked, no fault: every own step is timed by own_timings (Steps::next; one with no entry plays at once, as the web's UNTIMED); disabled buttons and ways take no press (press_at's enabled bit on release; hover only suggests on an enabled button); drop_held's slot matches tray.ts landing (same box test, middles of the pile's cards, library_at for a put-back), plus a closed-pile guard the web leaves to the session; aim lines follow only a mouse (a touch never sets owned.mouse) and none while a tray is up; the parity list's history only ever went down (491b1b47d added verbs-tuck-theirs, which .54 removed).

Left alone, with reasons: after_ends is never applied, but no own beat can need it today (arrow ends are battlefield objects, and the only moving own step is the tray, whose cards are off the battlefield). The web timelines hold no own arrow steps at all, so the closing path for an arrow the answering script draws again (the web's begun) is unexercised on both sides. A reset script with the same decision still open loses its marks (the web marks them again); that is reachable only through a release build's desync fallback.
