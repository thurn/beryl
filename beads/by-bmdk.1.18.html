Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Connecting over the internet'. iroh's documentation: https://docs.iroh.computer/ and https://docs.iroh.computer/concepts/relays . Read the documentation of the version you add; do not write its API from memory.

Create rust/crates/beryl_link_iroh, depending on beryl_link and iroh.

  1. Measure first. Before writing code, add the dependency and record on this bead: the number of crates it adds to Cargo.lock, the cold and warm build time of this crate, and the release binary's size change once beryl_app depends on it. Then run just check. If a check lane goes over its budget because of the dependency, put it behind a cargo feature iroh on beryl_app that the check lanes leave off and just dev, just smoke and release builds turn on, and move this crate's tests to the nightly lane (docs/checks.md). Never raise a budget.
  2. Identity: a key pair created on first use and stored in a file whose path is passed in (the app chooses the directory). The file is created readable by the user only.
  3. IrohHost::open(identity, relay: RelayChoice) -> (IrohHost, Invite), accept(), and IrohLink::connect(identity, invite, relay), implementing beryl_link::Link over one bidirectional stream with the same length-prefixed frames as TcpLink. RelayChoice::{Default, Url(String), Disabled}: the default is n0's public relay; a URL is a self-hosted relay; Disabled is for tests.
  4. The invite beryl:<text> encodes the host's public key, its relay address and the table secret (base32, lowercase, no padding). Decode failures are a clear error, never a panic.
  5. peer() reports Route::Direct or Route::Relayed and the round trip.
  6. iroh is async. Run it on a small runtime owned by this crate behind the blocking Link methods; beryl_app already includes tokio through Tauri. Comment what the dependency replaces: router traversal and a relay protocol written by hand.

Tests (tests/iroh.rs): two endpoints in one process with RelayChoice::Disabled, connecting by direct address, exchanging frames both ways; a wrong invite fails cleanly; invite encode and decode; identity persists across two opens. No test may touch the internet. If two endpoints cannot connect in one process with the relay disabled, test through iroh's own local test relay if the crate ships one, record what you did on this bead, and keep the rest. Run just test-rust -p beryl_link_iroh.

Acceptance criteria

IrohLink implements Link and passes an offline two-endpoint test; invites encode key, relay and secret; the measured build cost is a comment on the bead and no check budget is exceeded or raised.
