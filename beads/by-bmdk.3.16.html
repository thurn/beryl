Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'The command list' and 'Keyboard shortcuts', and the appendix's key columns.

How interface beads in this milestone fit together: ui/src/table/client.ts (bead "Table screen") is the manual table's pointer client. It owns the selection, sends actions with tableAct from ui/src/ipc.ts, and lets each interaction register handlers from its own file. Put your code in the file this bead names and register it; change client.ts only to add a registration point it lacks. Check your work on a live manual table in a headless browser: ui/scripts/table.mjs (same bead) starts one through the HTTP server and gives a Playwright page. Add one scripted check per behavior to ui/scripts/kept-table-<topic>.mjs and run it with just ui-test <title>.

File: ui/src/table/keyboard.ts and TablePalette.tsx.

  • One keydown listener on the window while the table screen is mounted, capture phase. It ignores events whose target is a text field. It calls resolve from ui/src/table/shortcuts.ts with scope table, and runs the command through the same path as a menu row (allowed, fill, prompt or target, send). It calls preventDefault for a resolved key and for claims(event) (ui/src/table/keys.ts). On mount it calls tableKeys(true) and on unmount tableKeys(false), and tells the bug report listener a table is open.
  • A shortcut applies to the selection, or to the card or pile under the pointer when nothing is selected (stage.pointer.hovered).
  • Cmd+K opens CommandList with every command allowed for the current target, saying what it will act on. Running one that asks opens the prompt after. Option+Return opens a small "press a key" capture and calls bind; show which command lost the key if one did.
  • "Every action…" in the context menu opens the list filtered to that card.
  • A key hint shown in a menu or the list comes from the current bindings, not the defaults.
  • A "Shortcuts" entry in the gear menu (ui/src/game/Corner.tsx) opens the command list with a "Reset shortcuts" command.

Checks (kept-table-keys.mjs): Cmd+D draws; Cmd+E then 3 then Return draws three; Cmd+U untaps all; Cmd+S shuffles; Cmd+W opens the top-cards prompt and the page is still there; Cmd+K, type "top", run "Look at top cards…" with 3; bind a key, reload the page, the key works. Each appendix key that is not covered by another bead's check gets one line in a table-driven check that presses it and asserts the action sent (intercept tableAct). A fixture or kept moment with the command list open for the generic audits.

The existing widget tests are in ui/scripts/kept-command-list.mjs. Keep their focus-return coverage and add a focused live check for the table dispatcher. library.stack_until (Cmd+Shift+Y) in data/table-commands.json currently has a move template. Collect the card name or type and hit count and route this command through the host, which can inspect the hidden library. Verify the host moves the expected prefix and the client never reads or sends its hidden names.

Acceptance criteria

Shortcuts resolve by scope and act on the selection or the thing under the pointer; Cmd+K lists allowed commands and can bind keys that persist; the table-driven check presses every appendix key not checked elsewhere; the open command list is under the generic audits.

Handoff: keyboard.ts resolves physical keys in the table scope and captures the selected cards or pointer target before TableCommands opens an overlay. TableMenu.tsx shares its action and prompt path with TablePalette.tsx, which uses per-profile Bindings.
