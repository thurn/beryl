Beryl 3D: keep the played table across scripts so steps find numbered abilities

Close reason

Show keeps the table each script ends with; no recorded or live-game step is unplaced (94b9d3bb7)

Description

Symptom: in a live game (beryl3d --window none --agent expert), steps that name an ability on the stack by its number (Fact::Item, Vanish of an ability, Emerge onto an existing entry) fail on the client's table, so the step is placed whole and its motion is lost (cards jump instead of animating). Before by-q44s.1.57 this panicked: 'an ability on a table is numbered' in beryl_protocol's Entry::subject, and then an index panic in Motion::commit (rust/beryl3d/crates/beryl_scene/src/play/compile.rs).

Why: Motion::new builds the client's played table from the view before with Played::of(before) (beryl_protocol's Table::of), which numbers no engine ability: those numbers come from the scripts before (Emerge { id }) and from a reset's abilities (beryl_protocol script::replay::number). The session's Screen keeps its table across scripts (rust/crates/beryl_session/src/script/build.rs, Screen::script), so its steps use numbers the client never learns. by-q44s.1.57 numbered unnamed abilities by place (numbered in compile.rs) so the lookup fails cleanly instead of panicking.

Do: keep the played table each script ends with, in Show (rust/beryl3d/crates/beryl_scene/src/play/mod.rs: push, resize, before_next, the Waiting/Playing/shown entries), seed it from a reset (script::replay::number) and pass it to compile in place of Table::of(before). Remove numbered once no step needs it.

Acceptance criteria

A beryl_scene test plays a script whose Emerge numbers an ability and a later script that changes or removes that ability by number, and the second script's steps are not placed whole (its tracks animate the step). beryl3d --window none --agent expert --for 600s plays to 'game over' and no step of the game is placed whole for want of an ability's number (count it with a debug line or a test over the recordings pack).
