Refresh browser coverage so slow CI can map ui/src changes

Close reason

Each passing hourly full sweep refreshes browser coverage in the background; day-long measurement deferred to by-gdn3.14

Description

What we see

Slow CI now runs only the browser checks a change can break (by ui-test --affected BASE, tools/src/beryl_tools/selection.py, slow_ci.py). But when a change touches a ui/src line that the coverage data cannot place, the selection falls back to running every check of the lane. A replay of 3 days of slow-CI runs (by-gdn3.6) kept about 77% of the browser lanes' seconds for that reason. The browser lanes are about half of slow CI's check time, so this decides whether slow CI's cost halves.

Why

Coverage (by coverage, coverage.py) runs only in the nightly. A line changed since the coverage commit, or a file absent from it, sets Choice.fill, and Chooser.unboxed then runs everything.

Change

Refresh the coverage data more often, for example after each passing hourly full sweep of slow CI (slow_ci.py, when Plan.full is set), or from the full sweep's own browser runs if they can record coverage cheaply. Keep selection.STALE_DAYS semantics.

Done when

Over a day of normal work, the run log's ui-test and shots records from slow CI (script: ci, chosen starting every:) are under a third of browser-lane runs, and slow CI's median check-seconds per run is recorded against the 3,692 s baseline on by-gdn3.6 and here.

Acceptance criteria

Coverage refreshes at least hourly while staging moves; a day's run log shows fewer than a third of slow-CI browser runs falling back to every check; the median check-seconds per slow CI run is recorded on this bead and by-gdn3.6.

Handoff: commits d3742de4 (feat) and 2f5f5ad7 (docs) on staging. New coverage.refresh(commit) in tools/src/beryl_tools/coverage.py starts uv run --project <main>/tools by coverage --commit <sha> detached (start_new_session) at utility priority from the main checkout, logging to $BERYL_CACHE/ci/coverage/refresh.log. It returns early on Windows, when latest.json already names the commit, or when the coverage .lock is held. Note that the nightly holds that lock for all its in_tree steps (specs, fuzz, oracle and the rest), so no refresh starts while a nightly runs. slow_ci.slow's passed callback calls it after a full sweep (not by ci <lanes>) in which both ui-test and shots passed (BROWSER). It launches from the main checkout because Enact deletes the ci-<sha> worktree and reaps the processes inside it. Tested: unit tests in tools/tests/test_coverage.py; by hand, the lock-held skip against the real cache, and a real launch in a scratch cache (stopped after it started).
