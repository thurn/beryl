Close reason

Debug next/apply check invariants (references every 32nd step; search unchecked); scenarios trace the same under 3 slot numberings; fixed slot-order attacker taps

Description

Two checks from the plan's Verification section, in the existing engine.

  1. State::check_invariants (beryl_engine/src/invariants.rs) and check_references (reference.rs) run today only where a caller remembers: beryl_cli/src/game.rs, beryl_scenario/src/run.rs:277 and 280, a few tests. Run both inside apply and next under cfg(debug_assertions) (engine.rs), panicking with the violation, and remove the call sites that become redundant. Release and search builds must be unchanged: the count gate runs a release profile, so its count must not move.
  2. Slot numbers are random and must never decide anything the rules can see (docs/bugs.md has four entries of this class). beryl_session has perturbation hooks for saves (perturb.rs, State::reverse_deck_slots). Make the scenario runner (beryl_scenario/src/run.rs) able to run a scenario under a permuted slot assignment, and have every_card_has_scenarios_and_they_pass (beryl_cards/src/tests.rs) run each scenario under the default and at least two permutations, asserting the same public outcome and assertions.

A scenario or game that fails either check is a rules bug: fix it and add its docs/bugs.md entry, or, if the fix is large, file it as a child of this milestone and list the scenario in a skip list the test prints.

Acceptance criteria

Debug-build tests panic on a seeded invariant violation; every card's scenarios pass under three slot assignments; just count-gate reports no change.

Derek Thurn2026-11-11

Deviation, with measurements (nextest, whole workspace, debug): check_invariants + check_references at every next/apply made the suite 6.4x slower in total CPU (5417 s vs 840 s baseline from ci/runs.jsonl; individual tests 30-100x, e.g. hunt::collected_positions 3.5 s -> 378 s). References cost ~30x a debug step; in search-heavy tests (MCTS simulations) ~100x, and invariants alone ~2.5x there. So: (1) debug next/apply check invariants on every state they return or are handed; (2) references run on every 32nd checked step (REFERENCES_EVERY in engine.rs), and the scenario runner and the fuzz test keep their explicit reference check at every decision (only their invariant calls were redundant and were removed); (3) search agents' own simulations run on Scratch::unchecked() (mcts, long, expert, frozen expert, bench rollouts), which skips the debug checks; the game the agent plays is still checked at each step. Result: suite total 505 s vs 840 s baseline (lower load), slowest ratio hunt test 2.4x (8.5 s), cards scenario test 1.8x (three numberings). Also: next_in_step checks only when it returns a step (stopped at a new step, SBA haven't run yet), and a Capacity stall is skipped (the session replays it in Large).
