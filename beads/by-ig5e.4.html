Close reason

Dollars per request from a dated price table, context split, carrying cost and window_dollars splits; pushed 5545734c

Description

Turn each request's tokens into dollars, and split each request's context so that a bead's cost can be traced to what was in the context.

Design sections: "Token accounting" ("Price", "Where a request's cost comes from").

What to build

  • data/efficiency-prices.json with its entry in data/AGENTS.md: dated tables of price per million tokens for the four classes of each model that appears in the store. Copy the values from the providers' published price pages on the day you write it, and record that date and the page addresses in the file. Do not write prices from memory.
  • Dollars per request, priced by the table in force on the request's date. A model with no price gives null dollars, is listed by coverage, and marks any sum that includes it as a lower bound.
  • Per request: context size, the fixed prefix (the context of the transcript's first request), new content and carried content.
  • Growth between consecutive requests, less the previous output, assigned to the tool calls whose results arrived between them in proportion to result size in bytes.
  • Carrying cost per tool call: tokens added, times the cache-read price, times the number of later requests that read it; it stops at the end of the transcript or at a compaction, detected as a drop in context size of more than half.
  • Wake-up requests: a request whose only action is a wait command of kind "orchestration wait" or "slow CI wait".

Why this matters

On 2026-11-15 the store's sources held 19.3 billion cache-read tokens against 60 million output tokens, about 227,000 tokens of context per request. Nearly all cost is context read again, so these splits are the tool's main result.

Shared context

  • The design is docs/efficiency-dashboard.md. Read the sections named above before anything else; the rest can wait. The decisions taken with the user are in the epic, bd show by-ig5e.
  • The dashboard's code is the separate Python project in efficiency/ (package beryl_efficiency, standard library only, pyre strict, black). It imports nothing from tools/ and nothing imports it. Read efficiency/AGENTS.md first once it exists.
  • Tests use small synthetic sources built in the test itself or kept under efficiency/tests/. The repository is public: never commit a real transcript, session record or command line from this machine.
  • Real data exists only on the main Mac (host jarvis). Where the acceptance criteria name a check against real data, run it there; if this session is on another machine, record that the check was not run in a comment on this bead and close on the tests.
  • Collection must stay free for agents: no hook, wrapper or prompt text may be added to any session, and ingest must never run inside another command.

Acceptance criteria

Tests: dollars of a fixture request equal the hand-computed sum of four classes times price; an unknown model gives null dollars and a lower-bound mark; the three context parts sum to the context for every request; growth is assigned in proportion to result size; carrying cost stops at a compaction; for every fixture bead the splits by class, by part of the context and by purpose each sum to the bead's dollars. On the main Mac, the store's total tokens by class match a direct count over the transcripts within 0.1%.
