Description

What to do

Every agent must play every keystone of this family legally and never stall, and the session must show it with what the UI already has (decision P13 of the plan).

  • beryl_search: the agents choose a face, a half, fuse, an Adventure, a prototype and a morph when casting (Decision::Cast { slot, face, costs } already carries a face; the candidates and their signatures must tell two ways of casting one card apart and treat two identical ways as one). Card values (values.rs, estimate.rs) read both faces and the shape, so that no two-faced card is valued as its front alone. Hidden face-down spells: the search's determinization deals an opponent's face-down card from what it could be.
  • beryl_session: views for a two-faced card in each zone, a transformed and a flipped permanent, a melded permanent, a face-down spell, a Saga's chapters, a Class's level, a solved Case, a prepared creature, and a sideboard pick, each with fields the view has after the shape bead. Scripts use existing verbs (a transform is the existing turn-over verb if there is one for turning face up; otherwise list it under "Not seen in Arena" in data/ui-conventions.json; never add a numbered exception).
  • Rendered rules text for abilities a card does not print (beryl_session) covers chapter abilities, level bands and the morph special action.
  • beryl_cli script-check passes for each keystone's spec moments from both seats; the session fuzz plays the pool; saves replay under each perturbation with each keystone. A save's description of a card names its face and its shape state, so that two saves that differ only there differ.
  • The census: add each new vocabulary entry to data/census-coverage.json and report the share of pool cards now fully covered against the 19.0% the plan started from.

Fix what you find; file what is large as a child of this milestone.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.

Acceptance criteria

Every agent plays 500 pool games containing each keystone of the family with no illegal choice and no stall other than a budget. script-check and the save perturbation tests pass for each keystone. The close reason gives the census share.
