Close reason

Order rows and stack items word a trigger by its paragraph: abilities sharing a paragraph count once (f720b762)

Description

On the stage, the order prompt lists each waiting trigger as its source's frame with the ability's words (ui/src/stage/Tray.tsx OrderRow: abilityText(face.text, true, candidate.nth ?? 0), ui/src/game/faces.ts abilityText and abilityParagraph). A triggerOrder candidate carries no nth (its option is {kind: trigger, source, ability, index}), so every trigger is worded as its card's first triggered paragraph. For Overlord of the Mistmoors' attack trigger that is the tail of impending's reminder text: the shot stage-order-long (fixture order-long, board in rust/crates/beryl_cli/src/boards/combat.rs) shows "At the beginning of your end step, remove a time counter from it.)" where the card says "Whenever this creature enters or attacks, create two 1/1 ... Insect ... tokens". Two triggers of one card would read alike.

Find which paragraph the candidate's ability is: the stack's own items carry nth (StackItem ability: nth; rust/crates/beryl_session/src/protocol.rs), so either the session gives a triggerOrder candidate the same nth it gives the stack item (preferred: the UI then has nothing to work out), or the row reads it from where the stack item gets it. Check what the item shows once the trigger is on the stack (Faces.tsx AbilityFace uses ability.nth) and make the two agree. Regenerate ui/src/generated/protocol.ts if the protocol changes (its header says how).

Acceptance criteria

In the fixture order-long each listed trigger shows the words of its own ability (Overlord's: enters or attacks), the same words its item shows on the stack after Done; a test holds it (a session test of the candidate's nth, or a shape or screen rule that the row's text is the stack item's); just check passes.

Deviation: the bead's premise was wrong. A triggerOrder candidate already carries nth (candidates.rs ability_nth handles Opt::Trigger), and it equals the stack item's. Both were 2 for Overlord's attack trigger, because the face lists two triggered abilities (ENTERS, ATTACKS) for one paragraph ('enters or attacks'). abilityParagraph found only 2 triggered paragraphs, so nth 2 matched none, and the delayed-trigger fallback picked up impending's reminder text. The stack item showed the same wrong words. Fix: Ability::in_paragraph_before() / shares_paragraph() (beryl_card ability.rs, a bool that fits in padding; the power-of-two size assert holds). Overlord's ATTACKS trigger is marked. The session counts paragraphs rather than abilities: build.rs paragraphs_before, used by ability_order (stack items, candidates) and outcome.rs ability_ref. Overlord's attack trigger now has nth 1 in both places.
