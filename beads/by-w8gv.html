Description

Rebuild Beryl's engine, card and UI structure so it would still work with the full Comprehensive Rules and 50,000 card definitions. Architecture only: no new rules features (the next project, docs/rules-coverage.md) and no new cards beyond the ten of the closing authoring pilot.

Plan

docs/project-50k.md is the plan: the audit, decisions K1 to K21 with their reasons, the target architecture, the eight milestones, acceptance and the measurements. Read it before any bead here. docs/engine-architecture.md is the engine as built; it stays authoritative for anything the plan does not change (flat Copy state, no heap, exact rules, the count gate).

Decisions from the user (design interview and plan audit, 2026-11-10)

All twenty-one are in the plan's Decisions table; K18 to K21 (the checks) came from a second interview the same day and are detailed on the CI track's epic (by-w8gv.20). The audit changed K1, K2, K14, K15, K16 and K17; where an older bead disagrees with this section, this section wins. The ones with conditions attached:

  • K1 effect data: accepted "if you think we can hold the current performance on rollouts". Milestone 2 proves it on the count gate with no bump. There is no fallback: if it cannot hold after three attempts, record the measured counts and profiles on the M2 epic, mark the bead blocked and stop for the user, because generated scenarios, derived AI knowledge, render-and-diff and the derived exporters all read effect data. Milestone 2 also tests the vocabulary's reach with a 60-card paper test (by-w8gv.3.1).
  • K2 naming: "please don't name a method .statik()". Spell words out; never misspell to dodge a keyword.
  • K2 stubs: an unimplemented card is a record in the card store, never a file. A card gets a Rust file when it gets written abilities.
  • K14 scope: parity, the scale rehearsal and a ten-card authoring pilot at the end of milestone 8 (ten Legacy cards today's mechanics can express, written by Sonnet from the brief; passing cards are kept). No other new cards. Never delete a card implementation (AGENTS.md).
  • K16 Forge: no translator and no relicense; Beryl stays Apache-2.0. The user's condition stands: "it's important to me that we don't just end up porting Forge to Rust. The goal of this project is to build a fast rules engine with a great, scalable architecture." Forge is a test oracle and a census of mechanics only: no definition, vocabulary entry or brief is derived from a Forge script, and no Forge engine code is ported or used as a design reference. A brief's reference is the XMage class (MIT). Measured in the audit: a clean mapping for 83% of Forge's scripts needs about 1,600 script entries (plan, Measurements).
  • New cards and engine mechanics wait until milestone 5 lands. Mobile (by-7pm) and AI ladder (by-97g) work continue, and so does UI work outside K30 (banked reports); rebase over them.

• No approval steps (K31, 2026-11-10): "please don't give me approval steps as part of the plan, you can file human beads asynchronously, just not blocking things." It holds for every track and every bead filed under this epic: where his judgement might be wanted, proceed on a default and record it in the bead being worked; never file a bead asking him to look at something (2026-11-11). The one exception is K1's count gate above, which is his earlier explicit condition and still stops the run.

Defaults for anything measured on samples

  • Scale budgets (plan, Acceptance) are bars. A budget that cannot be met after three attempts is recorded with its measured value and cause on the milestone epic, a follow-up bead is filed, and the run continues.
  • Reported with no bar: the paper test's split; render-match rate on the 47 cards; the pilot's pass count, cards blocked by missing vocabulary and tokens per card; the Forge census; derived-only agent results. Never tune to these.
  • The per-deck AI overlay's acceptance is deterministic: with the overlay, rollouts_never_change holds. No tournament gates anything. The derived-only comparison is one reported-only pairing (AGENTS.md, Tournaments: Wardens never rerun reported-only pairings).

Tracks (K15)

Six tracks. Five run in parallel after milestone 1 (by-w8gv.1); the CI track starts at once:

  • Engine, in order: M2 (by-w8gv.3), M3 (.5), M4 (.7), M5 (.9), each followed by its Mason gate (.4, .6, .8, .10), which blocks only the next engine milestone.
  • Prompts: M6 (by-w8gv.11) starts when M2 closes, runs beside M3 and M4, and blocks M5, so the rules library and the 47 cards are written once against the final prompt shapes.
  • Data: M7a (by-w8gv.18) starts after M1 and touches no engine-track file.
  • Hygiene: file splits (by-w8gv.19) start after the file-length check (by-w8gv.1.3).
  • CI: by-w8gv.20 (K18 to K21) waits on nothing and blocks nothing. Step one logs every check's every run, infers a verdict for each failure, pauses the browser harness's clock, reruns and quarantines flakes, and prunes the existing checks once from their history. Step two, decomposed by by-w8gv.20.5, adds coverage-based selection of browser checks to the fast check, bisection of slow-CI failures and the weekly prune.
  • Presentation: by-w8gv.21 (K22 to K30) starts after M1 and must cut over before the final gate (.16). Arena is the reference for the UI's flow, motion, timing, layout and wording, with numbered Beryl exceptions in docs/ui-conventions.md. Step one: the session builds a per-seat script of motion verbs for every visible change, held to invariants; an imperative stage plays it on a clock tests can step, behind a switch, and cuts over once, deleting beats.ts and the old animation code; each prompt shape is built on the stage after M6's protocol lands. Step two, after M5: causes come from the interpreter. Reports about motion, arrows and combat lines are banked from by-w8gv.21.2 until the cut-over. No bead waits on the user: judgement calls file a bead labelled human.
  • Tail: M7b (by-w8gv.13) after the M5 gate, then M8 (.15), the final gate (.16) and the Archivist (.17).

Tracks overlap in a few files (decision.rs, relayout.rs, the ask sites in effect.rs). enact push rebases; the later push fixes the conflict. Never hold a bead back to avoid one.

Roles (K15)

Executor; one Warden per milestone (not per lane), depending on all of that milestone's implementation beads; a Mason audit in a gate epic after milestones 2, 3, 4 and 5 and one final audit; no Sage; one Archivist at the end. Later milestones are decomposed by a bead in each, against the code as it then stands, following this policy.

Models

Every bead in this epic carries a tier label, which picks its session's model (all three tiers are built into Enact). Revised 2026-11-12 at the user's request, because of cost: Opus is the default for design work and Sonnet for mechanical beads. Never label a bead tier:fable, nor start a session or subagent on a Fable model, unless the user has explicitly asked for it.

  • tier:opus: any bead that designs or writes the rules engine or the game UI's logic (the card vocabulary and interpreter (lane:effects), the kernel, the stores, the rules library, Game and Resolution, the card port, prompts and their shapes, beryl_session's protocol, the stage and its scripts and clock, and prompt rules in the UI), tooling and infrastructure (the CI track, exporters, the card pool data pipeline, benchmarks and measurement, the Archivist), every decompose bead, every Mason audit, and every Warden.
  • tier:sonnet: only work that is mechanical and fully specified, such as a check, a rename, a file split, wiring or a documentation edit, even inside the engine; and the authoring pilot's card writers (K14).
  • tier:fable: only when the user has explicitly asked for it for that bead.

Anyone filing a bead under this epic (decompose beads, Mason findings, follow-ups) labels it the same way. Beads sharing a lane share a tier, since one session works the lane. Do not put a tier label on an epic: children inherit an epic's labels.

Whole-run acceptance

  • Parity: all 47 cards in the new structure; frozen saves replay exactly; rollouts_never_change holds; count gate holds with no bump.
  • The card-names allowlist (milestone 1) is empty outside the expert system (beryl_search/src/expert, frozen) and the per-deck overlay.
  • The file-length allowlist (milestone 1) is empty: no source file over 800 lines outside tests, the Playwright test drivers in ui/scripts, generated files, the expert system and the retired long-think code.
  • Scale rehearsal: every in-scope Scryfall card has a record in the card store (no stub files); just scale on 50,000 cloned implemented definitions meets cold check 60 s, release build 180 s, one-card rebuild 2 s, largest compiler process 4 GiB; app startup and UI bundle size do not grow with the card store.
  • Checks (CI track): over the two weeks after it lands, at most 2 Steward beads per 100 landed commits (12 on 2026-11-10), with the fast check within 60 s for a UI change. Verdict shares, flakes, deletions and seconds per lane are reported with no bar.
  • Presentation (by-w8gv.21): beats.ts and the per-component animation effects are gone; the script invariants hold over every scenario and the nightly fuzz; every banked report and the five repeated themes pass as stage cases; every verb passed the independent motion review (by-w8gv.21.43) and the stepped capture holds it to Beryl's own values (by-w8gv.21.42). Reports per game played and repeats are reported with no bar.
  • docs/engine-architecture.md describes the shipped structure and docs/project-50k.md is retired (Archivist).

Code map

Tests in src/tests. cargo test -p beryl_engine.
  • rust/crates/beryl_cards/src: one file per card under color directories, lib.rs (CARDS, SCENARIOS), names.rs (generated), tests.rs. cargo test -p beryl_cards.
  • rust/crates/beryl_scenario: scenario types and the strict runner (run.rs).
  • rust/crates/beryl_search/src: values.rs (name-keyed tables), rollout.rs, mcts.rs; expert/ and frozen/ are exempt from this project.
  • rust/crates/beryl_session/src: protocol.rs (PlayerView, AskView, mirror!), game.rs, preview.rs, save.rs, checkpoint.rs, migrate.rs; tests/saves (frozen corpus), tests/corpus.rs.
  • ui/src: cards.ts (bundled card data), game/Board.tsx, game/choices.ts, generated/protocol.ts.
  • tools/src/beryl_tools: checks.py (lanes, budgets, card-names step), cards.py (Scryfall), xmage.py, forge.py, oracles.py.
  • Checks: just check (60 s), just ci (300 s), just oracle <cards>, just fuzz, just bench-count, just count-gate.
