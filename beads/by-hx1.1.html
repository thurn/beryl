Audio pipeline (just audio), Web Audio engine with music rotation, volume/mute, credits and shared click path; pushed 46b04964

Description

Build the audio foundation: asset pipeline, a typed sound engine, music, volume controls and credits. The next bead (same lane) wires sounds to every UI event; this one only needs enough cues to prove the engine (button clicks, start-game).

Read the epic first for decisions, source locations and the code map.

Asset pipeline

  • A by audio subcommand (Python, standard library, typed for pyre strict; tools/src/beryl_tools/, wire into the justfile as just audio) that reads a manifest and transcodes from $BERYL_CACHE/audio-sources into ui/public/audio/ with ffmpeg (at /opt/homebrew/bin/ffmpeg; afconvert also exists). Commit the outputs; the tool exists so the selection is reproducible and editable.
  • Manifest (e.g. ui/src/audio/manifest.json or data/audio.json): each committed file with its source pack, original filename, license, author, source URL and a gain. The credits UI and the engine's typed cue list come from it (or the TS cue list is the source of truth and the manifest maps it; your call, but one place).
  • Formats must decode in WKWebView (Tauri on macOS) and in Playwright WebKit. Safe default: music as AAC .m4a (~128 kbps stereo); SFX short and click-free with no leading silence (AAC adds encoder priming, so prefer WAV/16-bit mono or confirm the padding is trimmed). Loudness-normalize (ffmpeg loudnorm/ebur128) so cues sit at consistent levels. Total committed audio at most 12 MB.
  • Music picks: ChillMenu_Loopable for the start screen; for games, a rotation of 3-5 of the steadier Loopable tracks (analyze with ffmpeg: avoid the most frantic, e.g. CrashingOut, MeltdownTheme, CriticalTheme); VictoryLap (Standalone) as a win sting; something subdued for a loss. Use the _Loopable files for looping and keep their exact loop length (no fades baked in).

Engine (ui/src/audio/)

  • One module: a typed Sound id union, play(sound, opts?) (variants picked at random for repeated cues like card slides, light pitch/volume jitter, per-cue max concurrency so ten cards landing are not ten stacked slams), music controller with crossfades and gapless looping (Web Audio AudioBufferSourceNode.loop with buffers, or equivalent), separate music and SFX gain buses.
  • Audio contexts are locked until a user gesture: unlock on the first pointer/key event and start music then.
  • Automation: under Playwright/fixtures (navigator.webdriver, the fixture transport, just ui-shots/specs), never fetch or decode audio and never output it, but still record every requested cue in a page-visible log (e.g. window.berylSounds: {sound, at}[]) so the next bead's CI check can assert on it. No page errors or unhandled rejections from audio in any mode (ui-shots fails on page errors).
  • Settings: music volume, SFX volume, mute; persisted in localStorage with try/catch; sensible defaults (music ~35%, SFX ~70%).

UI

  • A small speaker control on the start screen and in game (popover with two sliders and mute). AGENTS.md: halve the words; icons over labels.
  • Credits on the main menu: a quiet link/button opening a panel listing "Music: NotJam (CC0)" and "Sound: Kenney (CC0)" with links, built from the manifest.
  • Button clicks: give every button a click sound in one shared place (a shared Button component or a delegated listener on the document), so later buttons get it for free.

Verify

cd ui && npm run typecheck, just ui-shots game-start (credits/speaker visible, no page errors), just ui-test, just smoke, just check. Agents cannot hear: check durations, loudness and loop lengths with ffprobe/ffmpeg instead.

Acceptance criteria

Committed audio under ui/public/audio (<= 12 MB) is reproducible with just audio from the manifest; the start screen and game play looping music with crossfades after the first gesture; a speaker control sets music/SFX volume and mute, persisted; the main menu credits NotJam and Kenney (CC0) with links; buttons click through one shared path; under automation no audio is fetched but cues are logged; typecheck, ui-shots, ui-test, smoke and just check pass.

Handoff: Assets: ui/src/audio/manifest.json (sources, music, sounds; each cue has variants, optional gain dB / voices / loop) -> just audio (tools/src/beryl_tools/audio.py) writes ui/public/audio/{music/<cue>-<n>.m4a, sfx/<cue>-<n>.wav} and ui/src/audio/loops.json (exact loop lengths; WebKit keeps AAC end padding up to 23 ms, so the engine sets loopEnd from it). Transcode is byte-stable; 8.2 MB used of the 12 MB budget (music ~7.9 MB), so ~3.8 MB left for SFX: WAV mono is ~88 KB/s, keep cues short. tests/test_audio.py fails on a missing/stray file, a loops.json mismatch or the budget. To add a sound: add a manifest entry (Kenney packs under $BERYL_CACHE/audio-sources/kenney; add the pack to sources), run just audio; the Sound type is keyof manifest.sounds, so tsc checks every play() call. Engine: ui/src/audio/sound.ts: play(sound, {gain}), setMusic(cue), installAudio() (main.tsx). Automation (navigator.webdriver; ipc.ts audioAvailable) never fetches audio and logs window.berylSounds [{sound, at}] and window.berylMusic [{music, at}]; audible only in Tauri, ?live= or ?audio. One delegated document listener: every button click -> click, checkbox/radio input -> toggle, range input -> tick (throttled). StartScreen start() plays start. Music: App.tsx Main picks menu / game (4-track rotation, crossfade after 2 plays) / win / loss sting from the displayed status. UI: audio/SoundControls.tsx (SoundPanel in the game's gear settings; SoundCorner with Credits + speaker at the start screen's bottom right). beryl_app links.rs: a plugin opening http(s) navigations in the system browser; tauri.conf.json connect-src gained 'self' (fetching /audio was blocked by CSP). Verified in WebKit: decode, unlock on first gesture, loopEnd 64.000 vs 64.017 s buffer, settings persist, no page errors.
