Format: the shape of a game as data

  • Description
  • Acceptance criteria
  • Blocking4
  • Changelog

Description

Why

Starting life, hand size, who goes first, the skipped first draw, the land drop and the loss conditions are numbers written into the start and turn code. Subgames and restarts start a game with different contents, and Commander, Planechase, Archenemy, Two-Headed Giant and DanDân are other shapes of the same thing. Decision P10 of the plan; Designs F.

What to build

  • Format in rust/crates/beryl_kernel/src/ (a new format.rs), a const value the GameTable holds (table.rs): seats, teams, starting life, opening hand, maximum hand size, lands each turn, the mulligan rule, the first-draw rule, the turn's steps, which zones are per player and which shared, the roles of a player's card lists (library, sideboard), and the loss conditions. Format::CONSTRUCTED is the only value.
  • Replace each hard-coded value with a read of it:
    • new.rs:28 life: 20; start.rs:14 STARTING_HAND (it is also the mulligan floor and the redraw size); turn.rs (rules) MAX_HAND_SIZE and lands_played() < 1;
    • the starting player's coin, below(2) in new.rs and chance.rs, and the play-or-draw answer in engine.rs;
    • the skipped first draw, s.turn().number() > 1 in the rules' turn.rs, which keys on the game's turn number and should key on the starting player's first turn;
    • sba.rs end(), which ends the game whenever one player loses: it asks the format whether the players left are one side. With two seats the answer is what it was.
  • Seat stays a two-value enum and PerSeat a two-entry array. Do not add a third seat: two_player.rs says what that breaks, and it stays the list.
  • The kernel contract gains a "Format" section: what the format owns, and that a value read on a rollout's path is a const so the mirror's count does not move.
  • GameTable::new takes the format, defaulting to CONSTRUCTED for every existing caller. Scenarios (beryl_scenario_types) gain nothing yet.

Everything is a const read, so the count should not move at all. If it does, find out why before going on.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.

Acceptance criteria

No rules or kernel code holds a literal for life, hand size, land drops or the first draw. rollouts_never_change holds and the count is unchanged; the close reason gives it.
