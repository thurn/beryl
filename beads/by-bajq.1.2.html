Description

What is wrong today

  • Every waiting trigger, stack entry and delayed trigger carries an 8-byte Lki (beryl_kernel/src/stack.rs: card, power, toughness, types, controller, token). That is about 1,280 bytes of State<Small> for 160 records that are nearly always empty, and an effect can read only those five things about an object that has left.
  • trigger::match_leaving (beryl_rules/src/trigger.rs) matches one thing, "when this dies", for the leaving permanent alone. "Whenever a creature dies", "when this leaves the battlefield" and one creature seeing another die in the same event cannot be written.

What to build

Plan: Designs 1, "Look-back" and "Last-known information"; decision R4.

  1. The table. State gains a table of up to 16 rows in Small (a Vec in Large), each keyed by the ObjectRef of an object that left the battlefield and holding a copy of its Derived row, its three counters kept in fields, its token flag, its copiable record and what it was attached to. State::last_known(ObjectRef) reads one. TriggerInfo::lki goes: a reader looks the row up by info.object. A row is written only where a look-back ability matched or a resolving effect names the object. The table empties when no waiting trigger, stack entry or delayed trigger names any row (check where the stack and the waiting triggers become empty). A full table is Full. trigger::equivalent compares rows where it compared info.lki. The store plumbing (hash, relayout, invariants, observation) follows what store::Store does for the others.
  2. Look-back matching (CR 603.10a). Before any object of a batch moves (event::move_batch_to), match every look-back trigger of every permanent that listens, leaving permanents included, against each leaving permanent as it is now: "dies" and "leaves the battlefield", with Subject::This or Subject::A(filter). Add TriggerEvent::Leaves. The filter is read against the layer results, so a creature that has lost its abilities has no trigger and one that is no longer a creature does not "die" as one.
  3. The interpreter's reads of an object that has left (interpret/scene.rs, beryl_rules/src/reference.rs) go through State::last_known.

Expect

State<Small> shrinks by roughly 900 bytes. Allotment: it must not grow. The WU mirror has cards with dies triggers and a sweeper, so check that 16 rows never fills in the corpus.

Files

beryl_kernel/src/{stack.rs, state.rs, store.rs, zone.rs, relayout.rs, invariants.rs, observation.rs, lib.rs}, beryl_rules/src/{trigger.rs, event.rs, interpret/scene.rs, resolve.rs}, beryl_card/src/trigger.rs, tests in beryl_rules/src/tests/triggers.rs.

Derek Thurn2026-11-14

Decisions: (1) The table is a plain State field (beryl_kernel::last_known), not a store::Store: its keys are stale ObjectRefs, so keys/forget/expire do not apply. It follows the store plumbing for hash, relayout, fits, invariants (rows unique, none current) and off_board. (2) Rows are forgotten in engine::settle when the state-based check finds nothing (State::forget_last_known), keeping rows any waiting trigger, stack entry or delayed trigger names. Clearing on take_top_of_stack would drop rows the resolving body still reads, because resolution takes its entry off the stack first. (3) The interpreter's resolution-local Known record (CR 608.2h, targets an effect moves) stays: it holds every counter kind and mana value, which a row does not. Only is_a_token read Lki, and it now reads State::last_known. (4) Dies with Subject::This no longer requires a creature (CR 700.4). (5) Humility: there is no ability removal yet (layer 6 is group 2), so the matcher reads abilities from copiable values like match_event. Plan amended. Size: 20,112 -> 20,056 (-56, not ~900, because Derived is 40 bytes and a row 56). That leaves 424 bytes under the limit for later groups, not ~1300. Count 390,652,867 -> 390,942,553 (+0.07%). rollouts_never_change holds, so 16 rows never filled in the corpus.

Handoff: New beryl_kernel/src/last_known.rs adds LastKnown<L> (object, derived, counters, token, copiable, attached_to) and State.last_known: Queue<_, 16>, with last_known(r), last_known_rows(), record_last_known(slot) and forget_last_known(). TriggerInfo::lki, Lki and PermanentTypes are gone. beryl_rules/src/trigger.rs: match_look_back(s, t, &[(slot, dest)]), called once from event::move_batch_to before anything moves. It matches EventKind::Dies (dest == Graveyard) and the new EventKind::Leaves / TriggerEvent::Leaves, with Subject::This or Subject::A(filter) (listener::About::Either). It records a row only if a trigger was queued. equivalent() compares rows with LastKnown::alike. engine::settle calls forget_last_known after a state-based check that finds nothing. scene::is_a_token reads the row by of.source. Copiable now derives Default and Hash and has a Relayout impl in query.rs. Tests are in beryl_rules/src/tests/triggers.rs (Test Mourner, Test Keepsake). Corpus and family-corpora hashes were repinned. A reviewer should check that a row is never needed after forget_last_known runs: a resolving entry that names a row is off the stack while it resolves, but Pending is not None then, so forget does not run.
