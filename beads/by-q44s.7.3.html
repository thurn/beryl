Phone C functions for input, requests, wake and live games; header tested from C; all three phone smokes pass; staging 92746425b

Description

Read first: docs/beryl-3d.md 'Hosts' (the C functions, Input, Pointer, Key, Request) and 'Threads'; the phone spike's report and handoff in the comments of by-q44s.1.23; rust/beryl3d/AGENTS.md 'Phones'.

Why. Milestone 1's phone spike exported five C functions that replay a recording. Both phone hosts of this milestone (the Swift and the Kotlin bead) write against the header this bead finishes, so it lands first and alone. It is the contract of the hosts' track: every later host bead only calls what is declared here.

What exists: rust/beryl3d/crates/beryl_3d/src/ffi/mod.rs (beryl3d_new, beryl3d_surface, beryl3d_surface_lost, beryl3d_lifecycle, beryl3d_frame, struct Beryl3d { phone: Phone, window }, report, log_errors_in), src/ffi/android.rs (JNI wrappers, Window, string), include/beryl3d.h (hand-written), beryl_host/src/phone.rs (Phone, its inbox() whose wake is || true), beryl_3d/src/app.rs (phone_feed, AppFeed, Source::Live, Source::Fixture), beryl_3d/src/session.rs (spawn, Live, Live::begin), beryl_scene/src/input.rs and src/command.rs (Pointer, Key, KeyCode, TextChange, Request, Haptic).

Build, all in beryl_3d except the thin Phone methods:

  1. BerylConfig gains, in this order after data_dir:
    • const char *stand_in: debug builds only (cfg(debug_assertions)): the name of an agent (beryl_search::AGENTS) that answers the human's decisions, for unattended runs. NULL for a person. Ignored in release builds.
    • float display_hz: the display's highest refresh rate, which the host reads (iOS UIScreen.maximumFramesPerSecond, Android the largest Display.Mode.refreshRate). Stored on the Phone for the pacing bead; this bead only passes it to Opened::display_hz in place of the hard-coded 60.
    • void (*wake)(void *context) and void *context: called from any thread when an input arrives from another thread (a session update, a finished asset) while the host may have paused its ticks. May be NULL. Phone::inbox's wake closure calls it instead of || true. The host must treat it as 'ask for a frame soon' and hop to its main thread itself. When fixture is NULL the app plays a live game: Source::Live(session::spawn(...)) exactly as app::source does on the desktop, with data_dir as the sessions' data folder (replays and games.jsonl). With stand_in set, Live starts the game with Sessions::start_game(&start, Some(stand_in)), building the StartGame the way Sessions::start does from a StartRequest { agent: "expert", seed: None, fair: false }; add Live::with_stand_in(name: String). A NULL fixture path needs a new app::phone_live_feed(data_dir, inbox) beside phone_feed.
  2. BerylWake gains float hz: the rate the host should ask its display for from now on. This bead fills it from a new Phone::hz() that returns 60.0 until the pacing bead makes it the rate rule's choice.
  3. Four new functions, declared in include/beryl3d.h and defined in src/ffi/mod.rs with the same # Safety and // SAFETY: comments as the existing five:
    • void beryl3d_pointer(Beryl3d *, BerylPointer event). BerylPointer { uint32_t id; uint32_t kind; uint32_t phase; float x; float y; uint32_t button; float wheel_x; float wheel_y; uint32_t modifiers; }, positions in logical points from the surface's top left. Constants BERYL_POINTER_MOUSE/TOUCH/PEN, BERYL_PHASE_DOWN/MOVE/UP/CANCEL/LEAVE/WHEEL, BERYL_BUTTON_PRIMARY/SECONDARY/MIDDLE/NONE numbered in the order of the Rust enums from 0, and modifier bits BERYL_SHIFT = 1, BERYL_CONTROL = 2, BERYL_ALT = 4, BERYL_COMMAND = 8. An id over 255 or any unknown value drops the event (as beryl3d_lifecycle drops unknown values), so no C value can make an invalid Rust enum.
    • void beryl3d_key(Beryl3d *, BerylKey event), BerylKey { uint32_t code; uint32_t phase; uint32_t modifiers; }. BERYL_KEY_A = 0 through BERYL_KEY_BACK, numbered in the order of KeyCode in beryl_scene/src/input.rs (A to Z, Digit0 to Digit9, Enter, Escape, Space, Tab, Backspace, Delete, ArrowUp, ArrowDown, ArrowLeft, ArrowRight, Back). BERYL_KEY_DOWN/REPEAT/UP for the phase.
    • void beryl3d_text(Beryl3d *, const char *utf8): the edited field's whole new contents, as Input::Text(TextChange).
    • bool beryl3d_next_request(Beryl3d *, BerylRequest *out): the next Client::next_request, or false. BerylRequest { uint32_t kind; uint32_t haptic; float x; float y; float width; float height; const char *text; }. Kinds BERYL_REQUEST_BEGIN_TEXT_ENTRY = 0, END_TEXT_ENTRY = 1, SHARE = 2, HAPTIC = 3, OPEN_URL = 4; haptic is BERYL_HAPTIC_LIGHT = 0 or MEDIUM = 1; the rectangle is the field's, in points; text is the field's contents, the path to share or the URL, as a NUL-terminated UTF-8 string the app owns and keeps valid until the next call of beryl3d_next_request or beryl3d_frame, else NULL. The element id of BeginTextEntry does not cross: one field is edited at a time and the client remembers which. The new Phone methods (pointer, key, text, next_request, hz) only hand an Input to the FrameLoop or read from its client; when no surface has been given yet, pointer, key and text inputs are dropped and next_request returns None.
  4. android.rs: one JNI function for each new C function, named for Kotlin's object Native in ca.thurn.beryl3d: pointer(app: Long, id: Int, kind: Int, phase: Int, x: Float, y: Float, button: Int, wheelX: Float, wheelY: Float, modifiers: Int), key(app, code: Int, phase: Int, modifiers: Int), text(app, text: String), nextRequest(app, rect: FloatArray): Int (the kind, or -1 for none; writes x, y, width, height into rect, or for a haptic its strength into rect[0]), and requestText(app): String? (the last request's text). create takes (fixture: String?, dataDir: String, standIn: String?, displayHz: Float, waker: Any): Rust keeps the JavaVM and a JNI global reference to waker, and the wake callback attaches the calling thread as a daemon (AttachCurrentThreadAsDaemon) and calls the waker's void wake() method. Update the Kotlin object Native declarations in android/app/src/main/java/ca/thurn/beryl3d/MainActivity.kt and the Swift call of beryl3d_new in ios/Beryl3D/App.swift to compile against the new signatures, passing the values the spike already has (the replayed fixture, NULL stand-in, the display's highest rate, a NULL wake on iOS and a waker object whose wake() does nothing on Android). The host beads replace these.
  5. The frame log (src/frame_log.rs, written from AppFeed::input) records each Pointer, Key, Text, Surface and Lifecycle input as a line {"input": <kind>, ...} with its fields (a Text line holds its length in characters, not the text). The host beads' smoke tests read these lines to prove their events arrived. Add the line type to frame_log::read.
  6. The test of the header. A test cannot give the app a native surface, so under the tools feature only (which the crate's dev-dependency on itself already turns on, and which phone and release builds leave off), beryl_3d exports one more function, void beryl3d_offscreen(Beryl3d *, uint32_t width, uint32_t height), declared in tests/c/offscreen.h and not in include/beryl3d.h. It gives the Phone an offscreen target in place of a native surface: add Phone::offscreen(width, height) behind beryl_host's headless feature, drawing into the renderer's offscreen Target as Windowless does (make Screen hold either a Surface or a Target). The C program, rust/beryl3d/crates/beryl_3d/tests/c/header.c, includes include/beryl3d.h and tests/c/offscreen.h and defines int beryl3d_header_test(const char *data_dir). It creates an app replaying verbs-zones from data_dir, calls beryl3d_offscreen(app, 800, 600), sends one pointer down, move and up with id 1, one key BERYL_KEY_BACK down and up, a text "héllo", one lifecycle BERYL_LOW_MEMORY, a pointer of kind 99 and a key of code 999, calls beryl3d_frame twice, drains beryl3d_next_request, and returns 0 when every call returned what the header says (a wake kind the header names, hz greater than 0). A build script, beryl_3d/build.rs, compiles it with the cc crate (cc = "1.11.2", the release already in rust/beryl3d/Cargo.lock, as a build-dependency whose comment says it replaces invoking the system compiler by hand) and links it into the test targets only (cargo:rustc-link-arg-tests), so the phone libraries and the desktop binary do not contain it. tests/ffi.rs writes verbs-zones into a temporary folder with fixture::write, calls beryl3d_header_test through extern "C", then reads the frame log the app wrote there and asserts: three Pointer lines with id 1, two Key lines, one Text line of length 5, one Lifecycle line, one Surface line of 800 by 600, and nothing for the two invalid events. Write the conversion of a Request as its own function, fn request_to_c(request: &Request, text: &mut CString) -> BerylRequest, and test it in src/ffi/mod.rs on each Request variant by value.
  7. docs/beryl-3d.md 'Hosts': replace the C block with the header as built, and rewrite the spike paragraph ('What exists so far') to say what the library exports now. Say there that the phone app plays a live game when no fixture is named.

Not in this bead: changing the frame rate (the pacing bead, by-q44s.7.4), pausing ticks in the hosts, anything in Swift or Kotlin beyond compiling against the new signatures, low memory.

Run: cd rust/beryl3d && cargo test -p beryl_3d --test ffi && cargo test -p beryl_3d; just b3d ios-smoke; just b3d android-smoke; just b3d android-smoke --gles (the spike's smokes must still pass after the signature change).

Deviations from the bead, with reasons: (1) The test is tests/all/ffi.rs (run: cargo test -p beryl_3d --test all ffi), not tests/ffi.rs, because rust/beryl3d/AGENTS.md puts every integration test in the one tests/all binary. (2) request_to_c returns Option<BerylRequest>: Request also has SaveSettings, Music and Audio, which the bead's five kinds do not cover. They never cross; beryl3d_next_request skips them (the desktop host ignores them too). (3) The frame log's input lines are {"input": {"pointer": {...}}} (serde's external tag, like the run/late/summary lines), not a flat {"input": <kind>, ...}; enumerated values are their Rust names ("Down", "Back", "LowMemory"). (4) tests/c/offscreen.h also declares beryl3d_close (tools feature only), which drops the app; AppFeed's Drop finishes a phone's frame log synchronously, so the test reads a complete log without waiting on the writer thread. (5) build.rs compiles header.c to an object with cc and passes it with cargo:rustc-link-arg-tests (an object, not an archive, so the linker always takes it); it compiles nothing for iOS or Android targets. (6) Added a second test: with a NULL fixture, beryl3d_new starts the session thread and its first view calls the host's wake callback. (7) Phone::new now takes the display rate, the wake and a closure that makes the feed from the inbox, since the live feed needs the inbox before the Phone exists.
