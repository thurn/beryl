Close reason

Desktop layout moved to space.json, read by one generic build rule; output identical

Description

Symptom. Rule 6 of the epic says spatial values are data in data/beryl3d/space.json, never literals in code. The whole desktop layout is a Rust literal instead: DESKTOP in rust/beryl3d/crates/beryl_scene/src/table/mod.rs holds the camera (pitch 24 degrees, field of view 30, target, required area), the battlefield rows, the piles, the stack and both hands as numbers, and CARD_WIDTH, CARD_HEIGHT and LAYER sit beside it. space.json holds only verbs.fly.arc, catch_up and frame_rate.

Why it matters now. Milestone 2's tracks each move part of DESKTOP into space.json as they go: by-q44s.3.25 the hands, by-q44s.3.26 the piles, by-q44s.3.7 the camera, and by-q44s.3.2 adds players to Layout with literal values. Each of those beads also edits beryl_scene's build.rs, because the build script has a hand-written rule per top-level key (verbs becomes modules of f32, catch_up usize, frame_rate 'a whole number becomes usize and any other f32'). So four parallel beads edit the same two files (table/mod.rs and build.rs), against planner rule 2, and the build script grows one ad hoc rule per key. Milestone 4's phone layout would add a second literal Layout.

Proposed design.

  1. One rule in build.rs for all of space.json: an object becomes a pub mod <key>; a number becomes pub const <KEY>: f32; an array of two or three numbers becomes glam::Vec2 or glam::Vec3 (Vec2::new is a const fn); a key ending in _count or listed under a top-level "counts" object becomes usize (choose one of the two and say which in the build script's doc comment). Delete the per-key rules. Existing constant paths (data::space::verbs::fly::ARC, data::space::catch_up::*, data::space::frame_rate::*) keep working, or their few callers are updated in the same change.
  2. Move every number of DESKTOP, and CARD_WIDTH, CARD_HEIGHT and LAYER, into space.json under layout.desktop and card, with the same values. DESKTOP stays a const Layout in table/mod.rs, built from the generated constants, so callers do not change.

After this, a milestone 2 bead that adds or tunes a spatial value edits only space.json, and Layout's fields.

What it eliminates: the literals rule 6 forbids; the per-key code in build.rs; the build.rs and table/mod.rs edits in by-q44s.3.2, .3.7, .3.25 and .3.26.

Behavior that must not change: every resting place and the camera are bit-for-bit the same. just b3d tree verbs-zones --at step:6.1.0 prints the same lines before and after, and the work counters in data/beryl3d/gates.json do not move (just b3d gate).

Files: rust/beryl3d/crates/beryl_scene/build.rs, src/data.rs, src/table/mod.rs, src/table/camera.rs; data/beryl3d/space.json; rust/beryl3d/AGENTS.md ('Data files', which describes the build script's rules) and docs/beryl-3d.md 'Space and camera'.

Acceptance criteria

grep finds no numeric literal in DESKTOP or for CARD_WIDTH, CARD_HEIGHT and LAYER in beryl_scene/src/table/mod.rs; build.rs has no rule naming a particular key of space.json; a beryl_scene test asserts DESKTOP's camera pitch equals space.json's value; just b3d tree verbs-zones --at step:6.1.0 prints identical output before and after (compared in a comment on the bead); just b3d lane passes.
