Close reason

Outline quads sized from the sprite's ring; life totals hidden during the opening; tests fail without the fix

Description

Symptom: in the desktop app, things are drawn in the wrong place.

  • The outlines that mark cards you can play sit to the right of the cards instead of around them.
  • Text overlaps other text: on the start screen, the life total is drawn on top of the "on the play" text.

Both look like the scene and the flat layer disagreeing about coordinates. The likely cause is a mismatch between logical points and physical pixels (the display scale), or between where a mark is placed and where its card is drawn. Find the cause for each symptom; if they share one, fix it once.

Files: rust/beryl3d/crates/beryl_host/src/desktop.rs (Translator, scale_factor), beryl_scene/src/input.rs, beryl_scene/src/layout/mod.rs, beryl_scene/src/frame/draw.rs, beryl_scene/src/light/marks.rs (the playable mark, by-q44s.3.20), beryl_scene/src/hud/players.rs (life orb and life total, by-q44s.5.20), beryl_scene/src/hud/steps.rs, the start screen from by-q44s.5.24 (beryl_scene/src/client/screen.rs and the screens module).

Reported by the owner on 2026-11-16 from the desktop app (just b3d app, a real window on a Retina Mac). Every interface test and Warden passed on this code, so the headless tools do not see it. Reproduce in the real window path first: just b3d live against a running debug build (live tree, live png), not only just b3d png / tree, which use the headless host. A likely difference is the display scale: the desktop host (rust/beryl3d/crates/beryl_host/src/desktop.rs, Glyphs::start(window.scale_factor()), glyphs.rescale, Translator::new(size, window.scale_factor())) runs at scale 2 on a Retina display, while the headless host and the test matrix may run at scale 1. Confirm or rule this out.

Rules: the epic by-q44s ('Rules for every bead'), rust/beryl3d/AGENTS.md, docs/beryl-3d.md. A UI bug fix adds the broken state to a check that runs on every push (root AGENTS.md, 'Checks'), so the fix includes a test that fails before it at the scale and host the owner used.

Note from by-q44s.9.39: no headless tool runs at scale 2. The driver sends Input::Surface scale 1.0 (beryl_scene/src/driver/mod.rs begin), Headless asks for glyphs and icons at 1.0, and png --scale only enlarges the target. It also loses clipped content: png screen/start --at end --scale 2 shows an empty opponent list. The windowless app is hardcoded to scale 1 (beryl_3d/src/app.rs). The owner's screenshot shows the live app drawing 'You won the ip' (the fl ligature is missing), while png opening-play --at prompt:1 at scale 1 draws it correctly. A scale-2 test therefore needs the Surface scale fed through the driver (by-q44s.9.43 makes that general).

Derek Thurn2026-11-17

Handoff: Neither symptom depends on display scale: both reproduce in just b3d png at scale 1 (pay-default --at prompt:1 for outlines; opening-keep --at prompt:1 for the overlap). (1) Outlines: the OUTLINE sprite already draws a card-shaped ring in its square cell, but light::marks::write, table::own (stolen permanent) and effects::light (glow) scaled the quad to the card's width x height, applying the aspect twice, so the ring was ~70% of the card's width (looked shifted on a fanned hand). Added frame::draw sprites::OUTLINE_LINE (ring half-size in quad units, which beryl_assets::light::outline now draws from) and sprites::outline_size(half); all three callers use it. Test: verbs_mark::an_outline_encloses_its_card_through_a_flight now checks the drawn line (not the whole quad) encloses the card and stays within 1.2x of it; it fails with the old sizing. (2) Overlap: the opening hid the life orbs but not the life-total floats (hud::counts, floats::LIFE), so the opponent's '20' sat on 'On the draw'. client/mod.rs now passes counted && !self.viewing.opening to counts.write. Test: beryl_inspect tests/all/opening.rs asserts no player life element during the opening. Pictures checked: pay-default prompt:1 at scale 2 and opening-keep prompt:1, before and after ($BERYL_CACHE/b3d/out). Not compared side by side with the web interface's picture. Reviewer: the outline is now about 40% wider than before, so blended fragment counts may move in the sweep's --gpu gate; check the glow effect's halo still looks right. Pushed c7b2adb60.
