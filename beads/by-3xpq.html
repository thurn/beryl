Beryl 3D build directories grow to 40-50 GB each with stale artifacts

  • Close reason
  • Description
  • Changelog

Close reason

Fixed in a2003d82: sweep.save_target runs warm.prune on the saved copy (15 GB budget); beryl3d cli.warm_target tidies a crowded rust/beryl3d/target before each cargo command and marks a fresh clone's fingerprints unread so used units survive eviction. Hand-pruned the cache 44->14 GB and crowded worktree targets (~75 GB more), coordinated with the disk-full Justiciar (by-g2xcc). Free disk shows little change until the Arq APFS snapshot is released.

Description

Symptom: free disk fell from 306 GB (2026-11-14) to 162 GB (00:10 UTC 2026-11-16) to 132 GB (02:10 UTC). $BERYL_CACHE/b3d/target is 44 GB, and rust/beryl3d/target in slot-01, -03, -04, -06 and -08 is 46-53 GB each (du, which counts APFS clones at full size, so shared blocks are counted more than once). The b3d sweep's four work trees hold 37-49 GB each. The main workspace's targets are 8-14 GB.

Cause: $BERYL_CACHE/b3d/target/debug/deps holds 77,077 files, with 5,000-6,000 files each for beryl_session, beryl_search and beryl_scene (nine copies of libberyl_scene-*.rlib at 122-157 MB). sweep.save_target (tools/src/beryl_tools/beryl3d/sweep.py) removes incremental folders but never removes artifacts that the current build no longer uses, so every saved cache carries all earlier builds, and every worktree clones it in cli.warm_target. The main workspace's cache is pruned by warm.prune (BUDGET_GB = 15); the Beryl 3D one is not.

Proposed: prune deps/ and build/ to the artifacts the last build used (for example by the newest fingerprint per unit, or by atime/mtime since the build began) before saving, and apply the same budget eviction to worktree and sweep work-tree targets. Done when the saved cache is under 15 GB and free disk stops falling day over day.
