Beryl 3D: a hold after a catch-up script counts real time as script time

Close reason

Holds measured on a script clock across catch-up scripts; parity entries removed in 3fb382993

Description

Symptom: timeline parity lists no-more-lies/declining-to-pay-exiles-the-spell/opponent (4 steps) and verbs-place-theirs/you (3 steps). In both, view 4's stack-arrow end (point, case "end") starts 105 ms into its script in just b3d timeline and at 0 in ui/scripts/timeline.mjs, and every later step of that script is 105 ms late.

Why: the recording gives 12 views at once (all "thinking"/"playing"), so Beryl 3D's script clock plays the first scripts at twice the speed (catch_up.double in data/beryl3d/space.json, the rate chosen in beryl_scene src/play/mod.rs around let rate = match self.waiting.len() + 1). The web stage has no catch-up. The arrow of view 3 stands whole at script time 403 and script 3 ends at 773, so it has stood 370 script-ms when script 4 starts, past its 290 ms hold, and the web plays the end at once. Beryl 3D measures how long the span stood from Lit::whole_since (src/light/mod.rs, real nanoseconds since the client started) and converts it with the NEW script's rate (Starting::clock in src/play/relay.rs, used by again's whole closure). Script 3 ran at rate 2, so only 185 real ms passed, script 4 runs at rate 1, and 185 converts to 185 script-ms: it waits 290 - 185 = 105 ms.

Fix: measure how long a span has stood in script time across the scripts that played since it stood whole (each at its own rate, and rest between scripts at rate 1), for example by keeping a running script clock in the show beside real time and recording whole_since on it. Add a beryl_scene test under tests/all/ with two scripts, the first played at rate 2 (more than catch_up::DOUBLE updates waiting) that begins an arrow and the second that ends it with a hold, asserting the end waits only for the hold's remaining script time. Then just b3d timeline-parity --update and remove both entries. Also document catch-up in docs/beryl-3d.md 'Timing a script' (it is in no section today) and say there that holds are measured in script time.

Found by the milestone 2 warden (by-q44s.3.38).

Acceptance criteria

The new test passes and fails on the present code; just b3d timeline-parity passes with no entry for no-more-lies/declining-to-pay-exiles-the-spell/opponent or verbs-place-theirs/you; docs/beryl-3d.md describes catch-up and holds in script time.
