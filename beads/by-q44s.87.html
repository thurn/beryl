beryl_scene builds only with the driver feature

Description

Symptom: just b3d cargo-test -p beryl_host (or any build of beryl_scene without its driver feature) fails with 'unresolved import serde_json' in rust/beryl3d/crates/beryl_scene/src/manual/{arrows,ask,commands,drop,tokens}.rs and src/client/manual_overlays.rs. Cause: those files use serde_json unconditionally, but rust/beryl3d/crates/beryl_scene/Cargo.toml makes serde and serde_json optional, enabled only by driver. Building together with beryl_3d hides it, because beryl_3d enables driver and cargo unifies features, so the lane passes. Fix: either make serde_json a plain dependency (updating its Cargo.toml comment to say what it replaces) or gate the manual-table JSON code behind driver; prefer whichever keeps the release app's dependencies the same (beryl_3d already enables driver).

Acceptance criteria

just b3d cargo-test -p beryl_host and just b3d cargo build -p beryl_scene both build and pass on their own; just b3d lane passes.
