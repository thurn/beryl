Close reason

One card frame: per-card CSS fits removed, tapped uses the same rules, rules box derived from bar color (beda462)

Description

The docs/ui_mockups images are generated references, not a pixel spec: they are not consistent with one another, and earlier pixel-matching work fitted code to each one separately. This bead removes one such fit. Prefer one rule that holds in every state over matching any single mockup. just ui-compare verdicts for the affected regions may get worse; that is expected, so do not tune values back toward the mockups.

The card frame CSS (ui/src/design/components.css and the card rules in ui/src/screens/screens.css) has collected rules fitted to individual cards in the mockups: a greyer rules box for black cards (Doom Blade), a silver rim for a black land (the basic Swamp), a bright rule under the art only for a white land on the battlefield (Plains), a copper bevel only on land rims, a different top padding and name bar inset for untapped nonland battlefield cards than for tapped ones and lands, a different name size for tapped cards, and hand cards with their own border, name bar and art proportions (.hand-card rules). Each is small, but together the frame is a set of specific cards rather than a system.

Reduce the frame to one set of rules: the color palettes in .frame-* tokens; one battlefield frame whose tapped state is the same frame turned; one full frame used the same way in the hand, the stack and graveyards, scaled as a whole. Keep a land or color variation only where it carries meaning a player needs. by-kq9 handles rules text size and the .pile-card and .hand-card .card-art overrides; leave those to it.

Acceptance criteria

The frame's per-card rules are gone; tapped is the same frame turned; the full frame is one frame wherever it shows. just check and just ci pass, with no new constants tuned to a single mockup.

Decisions: (1) 'Tapped is the same frame turned' = no tapped-only CSS; the field frame keeps its footprint when turned (Card.tsx keep), since layout.ts rows assume it, so the name bar runs up the left at the untapped bar's size. (2) Rules box color derives from the bar (color-mix 44% bar into #f8f5ec, least-squares fit over all seven old palettes, RMS ~9/channel) instead of seven sampled --box tokens, so black's box is no longer special. (3) Also removed, as single-card fits of the same kind: the colorless name-bar keyline (Plateau), the full-art Island frame (scry.png; samples now use the plain Island), the gallery mini-hand overrides and .at's slimmer foot, and the .on-table-only P/T and ability badge sizes (now the one plaque/badge everywhere). Left for by-kq9: .hand-card .card-art flex-basis, .pile-card .card-rules, which still use the card-land class. Kept: the multicolor first-color accent (carries color meaning).
