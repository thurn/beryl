For each check, first ask: could a fast, deterministic test (a Rust unit test, a Node test with no browser, a check against a recorded fixture) keep most of what this end-to-end check protects? If so, write that test, then delete the check. If not, delete it when it caught nothing (delete above), or move it to the nightly (a step in nightly.STEPS, tools/src/beryl_tools/nightly.py) when it caught something (move to the nightly above). Either way the check leaves slow CI: when the fast check (by check) runs it too, keep it there and take it out of slow CI alone. Checks listed together failed in the same runs and go together. Make the cuts without asking anyone, and record on this bead what you did with each check and why. The cifix skill (.agents/skills/cifix/SKILL.md) says how to work this bead.

No cut bead names these checks, which guard something no other check does:

  • app:smoke: the desktop app builds and starts at all
  • ui-test:Enter on the start screen starts a game: the browser UI starts a game
  • ui-test:a land pressed while a script plays on to it is played: the browser UI plays a step of a game
  • rust:clippy: the whole workspace builds and passes clippy
  • ui:tsc: the UI type-checks in strict mode
  • names:*: the repository rules AGENTS.md names, a few CPU seconds in all

Notes

Commit 8d8d280e (worktree .worktrees/ci-cut-rust, not yet pushed). Mechanism: no way existed to take a Rust test out of slow CI alone, so slow_only.py gained FAST_ONLY (re-exported as verdicts.FAST_ONLY), the reverse of SLOW_ONLY; slow CI's tests step leaves those tests out of its nextest filter and skips the doctests/allocations steps when listed. Tests run by slow CI alone were moved to the nightly with #[ignore] plus --include-ignored in just fuzz, or deleted.

FAST-CHECK ONLY (the fast check runs them before every push; slow CI no longer does): rust:doctests (holds the compile_fail index-type blocks); rust:allocations; waste_declines_opposing_permanents_in_softmax_mirrors; every_card_has_scenarios_and_they_pass; chance::a_save_replays_the_same_under_another_seed; playground first_example_offers_the_card_in_hand; playground every_prepared_example_reaches_its_interaction; exhaust every_scenario_keeps_the_invariants_to_a_depth; replay inline_and_replayed_answers_reach_the_same_state_at_every_decision; long every_family_plays_a_game_to_its_end; ladder positions_start_four_pairs_in_five; derive generating_twice_gives_the_same_scenarios; derive generated_scenarios_pass_in_every_slot_order; screen a_log_that_no_longer_fits_is_refused_before_any_search; chance games_that_found_slot_order_ties_replay_the_same_under_another_seed; mcts an_agent_asked_again_searches_a_decision_as_it_did; the_dump_is_valid_json_with_every_scenario; mutation every_mutant_of_a_card_is_killed_by_its_scenarios; sessions no_view_shows_an_identity_its_viewer_does_not_know. Reason: rule 2, the fast check already runs each, so the card-scenario, mutation and hidden-information coverage stays. No replacement was written: each is already in the fast check, so a cheaper copy would add nothing.

NIGHTLY (#[ignore]; just fuzz, run nightly at 10,000 games, now passes --include-ignored; removed from SLOW_ONLY): games random_games_keep_the_invariants, shrink fuzz_games_keep_the_invariants, session fuzz a_planted_builder_fault_shrinks_to_a_few_choices. Reason: they were slow CI alone, are invariant fuzzing, and the nightly fuzz already played them at length.

DELETED (slow CI alone, 0 catches, removed from SLOW_ONLY): positions a_seed_rebuilds_its_set_and_each_position_plays_on and lingering_rejects_a_cut_and_known_cards_stay_known (positions::build and starting games from positions stay covered by ladder positions_start_four_pairs_in_five in the fast check); hunt collected_positions_replay_and_detect_drift (an AI research tool, hunt keeps 5 other tests); screen the_champion_against_itself_differs_nowhere and one_crafted_difference_counts_and_duels_once (an AI research tool; screen keeps a_log_that_no_longer_fits in the fast check); mcts a_rebuilt_agent_plays_on_as_the_uninterrupted_one (resume is covered by sessions resume tests and an_agent_asked_again). Reason: research tooling, not game correctness, and making each cheaper would have needed a redesign.

Guard: tools test test_no_check_is_left_to_both_slow_ci_and_the_fast_check_alone fails if a check is in both lists. docs/checks.md and the cifix skill name FAST_ONLY.
