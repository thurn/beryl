file-length check (800 lines) with shrinking allowlist of 31 files

Description

Add a step to just check (tools/src/beryl_tools/checks.py) that fails when a source file exceeds 800 lines (plan K17).

  • Scope: .rs, .ts, .tsx, .css, .py and .mjs under rust/crates, ui/src, ui/scripts and tools/src. Exempt: tests (rust tests/ directories and src/tests, files named tests.rs, tools/tests), generated files (ui/src/generated, beryl_cards/src/names.rs), frozen copies (beryl_search/src/frozen), the Playwright test drivers (ui/scripts/interactions.mjs, audit.mjs, drive.mjs), the expert system (beryl_search/src/expert) and the retired long-think code (beryl_search/src/long.rs, beryl_cli/src/longthink). The user approved these exemptions on 2026-11-10; add no others.
  • Seed an allowlist with every file over the limit and its current length. A listed file may not grow; the check fails when a listed file is now under its recorded length (lower the number) or under 800 (remove the entry).
  • Expect about 30 entries, led by ui/src/game/Board.tsx (3,522), ui/src/screens/screens.css, beryl_session/src/protocol.rs (2,489), game.rs (2,225), beryl_engine/src/cast.rs (1,840), mana.rs (1,812), beryl_cli/src/boards.rs, effect.rs (1,520), card.rs.
  • It runs in the repo lane so it always runs. Keep it under a second.

Acceptance criteria

just check fails in a pytest when a file crosses 800 lines or an allowlisted file grows, and passes on staging with the seeded allowlist.
