Beryl 3D record build fails to link after main-crate changes

  • Description
  • Acceptance criteria
  • Changelog

Description

Symptom: on 2026-11-17, during by-q44s.7.41's push, every fast-check lane of a Beryl 3D change failed at its record step. Linking beryl_record (and beryl_3d's tests) stopped with ld "symbol(s) not found for architecture arm64". The missing symbols were _anon.<hash>.<n>.llvm.<hash>, referenced first from libberyl_scenario-*.rlib and, after a clean, from libberyl_cli-*.rlib. The worktree had just been rebased onto staging commits that changed beryl_kernel and beryl_rules. Cleaning only those crates did not help. cargo clean of every main-workspace package under rust/beryl3d/target (test profile) fixed a direct cargo build --workspace --profile test, yet the next enact push failed the same way in beryl_cli. What finally worked was cleaning those packages again and pushing with CARGO_INCREMENTAL=0.

Why, most likely: _anon...llvm symbols are locals that ThinLTO promotes so one codegen unit of a crate can use another's. Cargo builds path dependencies incrementally, and that includes the main workspace's crates that rust/beryl3d builds at opt-level 1. When incremental compilation reuses some codegen units of a crate and recompiles others, a reused one can refer to a promoted symbol that no longer exists. This is a known rustc incremental bug.

Read: rust/beryl3d/Cargo.toml ([profile.dev] and the per-package opt-levels), tools/src/beryl_tools/beryl3d/cli.py (SHARED_BUILD, shared_build), tools/shims/cargo.

Fix: stop the main-workspace crates from being built incrementally in rust/beryl3d's dev and test profiles, for example with incremental = false in [profile.dev.package."*"] or per-package overrides, or a CARGO_INCREMENTAL setting in the shared build. Keep beryl_scene's fast rebuild after a one-line edit. Measure that rebuild and a cold build before and after, and record both numbers.

Acceptance criteria

After a rebase that changes beryl_kernel or beryl_rules, just b3d record and cargo build --workspace --profile test in rust/beryl3d link with no manual clean and no CARGO_INCREMENTAL in the environment. The commit body gives the measured rebuild time of beryl_scene after a one-line edit, before and after the change.
