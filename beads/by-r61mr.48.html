Close reason

Fixed both Cargo token tests and passed the full Python lane; delivered 1642115e4 to staging.

Description

The fast check for by-r61mr.27 deferred pytest at its 180 s hard limit. The fixture for test_a_test_run_keeps_its_tokens in tools/tests/test_cargo_pool.py never marked its fake Cargo child for release. Its push thread calls Pool.holders without the lock required by tools/src/beryl_tools/tokens.py. It can read a token file before Pool.grant finishes writing it, then delete it as invalid. The process held three token files while the test waited for six. test_a_build_gives_tokens_back_while_a_push_waits has the same poll. In each test, set FAKE_CARGO_STARTED to a started marker under tmp_path and wait for the marker in the push thread instead. The fake child writes the marker after Cargo has acquired its lease. The patch at /tmp/beryl-r61mr27.itlQ2f/test-cargo-race.patch passed both tests locally. The original bead used Enact to deliver the ticket tools, but a second worktree request for that bead is fenced because its recorded slot was recycled. Deliver the independent test fix in a fresh worktree.

Acceptance criteria

Both Cargo token tests pass. Run the full Python lane to cover the pytest step deferred during delivery of by-r61mr.27 and fix or report any remaining blocker.
