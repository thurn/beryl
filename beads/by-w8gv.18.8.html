Description

just card brief <name> prints the packet a cheap model writes a card from (plan: docs/project-50k.md, Authoring tools, step 2; K16). just card new and just card check are milestone 8's; build the command so they can join it.

Read first: docs/project-50k.md, Authoring tools and K16; tools/src/beryl_tools/specs.py lines 96 to 156 (implemented, words, oracle, nearest: the rules-text ranking, on the card store since the tools bead); the pipeline bead's handoff (the store's reader and the bulk-file helper); tools/src/beryl_tools/xmage.py (class_name, xmage_cards) and oracles.py (checkout, XMAGE); rust/crates/beryl_card/src (3,349 lines: the vocabulary; skim lib.rs and the doc comments in effect/mod.rs, trigger.rs, cost.rs, filter.rs, continuous.rs, ability.rs, target.rs). Need not read: the engine, the UI, forge.py.

The packet, in this order

  1. Oracle text: each face's name, mana cost, type line, rules text, power and toughness or loyalty, from the card store. A card not yet implemented is a record there, so the brief works for any card in the pool.
  2. Rulings: Scryfall's rulings bulk file, fetched into $BERYL_CACHE/scryfall with the pipeline's helper on first use and joined by oracle id. Offline with no cached file, say so and go on.
  3. Matching vocabulary entries: the entries of beryl_card this card's text most likely needs, each with its file and line and its doc comment. Read the crate's source as text (no cargo build: a brief should be instant, and the vocabulary keeps changing until milestone 5): each public enum variant and builder function with its doc comment is an entry, ranked against the Oracle text with the same word overlap nearest uses. If listing the entries the nearest implemented cards use works better, do that as well or instead, and say why on the bead.
  4. The nearest implemented cards: specs.nearest's ranking over the implemented cards, each with the path of its file under rust/crates/beryl_cards/src. Move the ranking to a module both commands share if specs.py is the wrong home.
  5. The XMage class: its path under the oracle checkout (Mage.Sets/src/mage/cards/<letter>/<Class>.java, by xmage.class_name) and its source. With no checkout (just oracle-setup not run), say so and go on.

Never the Forge script, and nothing derived from one (K16: "no definition, vocabulary entry or brief is derived from a Forge script"). The module does not import forge.py, and a test asserts a brief reads nothing under the Forge checkout.

Do

  • A new module (suggested tools/src/beryl_tools/card.py) registered in cli.py, and a card recipe in the justfile whose first argument is the subcommand.
  • An unknown name exits non-zero naming the closest names in the store.
  • Typed (pyre strict) and tested with a small fake store, cache and checkout; no test touches the network or $BERYL_CACHE.
  • One line in AGENTS.md's Testing section naming the command, since card authors start from it.

Verify

pytest; just card brief "Lightning Bolt" (in the pool, not implemented) prints all five parts; just card brief Counterspell (implemented) does too and lists other counterspells among its nearest; just check.

Parity and policy

This is the data track: it edits no engine-track file (nothing under rust/crates/beryl_engine, beryl_kernel, beryl_card or a card file), and nothing here creates a Rust file per card (K2: an unimplemented card is a record in the store). Parity (plan K11) at the push: just check passes; the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds; slow CI's counts lane (just count-gate, bar 405,276,238 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. Nothing waits on the user (K31): proceed on a default and file a non-blocking bead labelled human, parented to by-w8gv.18, where his judgement is wanted. Record decisions and deviations as comments on this bead.

Decisions: (1) Ranking moved from specs.py to tools/src/beryl_tools/nearest.py (slug, card_files, implemented, words, overlap, rules_text, nearest); specs.py now calls it. The implemented cards' names come from beryl_cards/src/names.rs matched to card files by slug, instead of the decklists (same set today; works with a fake crate in tests). (2) Vocabulary (vocabulary.py): each documented pub enum variant, pub fn and pub const in beryl_card/src, read as text by brace tracking; ranked by the same Jaccard overlap, but on what the entry says a card says: CR citations and the rules they quote are dropped from the doc, and both sides drop plural/third-person 's' (draws/draw), since otherwise long CR quotes swamp the card wording. (3) Word overlap alone misses things (Brainstorm ranks Place/LibraryPosition over Effect::Draw), so the nearest-cards part also lists, for each card, the vocabulary entries its definition (code before SCENARIOS, comments stripped) names: both, as the bead allowed. (4) XMage class: xmage.card_class (shared with class_name), with accents folded, by full name then first face, falling back to scanning set files' SetCardInfo lines. xmage.checkout() duplicates oracles.checkout(XMAGE) because importing oracles imports forge; a test keeps them equal. (5) Rulings: the bulk helper's rulings file, scanned with a byte search for the oracle id before parsing; a stale cached file serves when fetching fails. (6) tests/test_card.py and tests/test_specs.py added to checks.CARD_READERS, since both now read beryl_card/beryl_cards sources.
