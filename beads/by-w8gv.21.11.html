Derek Thurn2026-11-11

Measured (staging 4ff72844, debug build, jarvis 18 cores): the whole script run, all 334 spec moments from both seats (668 checks) plus all 80 UI fixture recordings (748 checks), takes 1.3-2.3 s in process and 2.7 s process wall; 'by ci script' 3 s on the clock (4 s load-adjusted, load 24); in the fast check at the push 4 s (16 s on an earlier attempt that contended with a cold clippy build). Well inside 60 s and 300 s. Under a probe that panics in every reset (every session's first view) the run still finishes in 2.3 s with 1331 failing checks, each named.

Decisions: (1) The rust lane has no affected-crate selection today, so the new 'script' lane runs in the fast check when a path in beryl_cli's path-dependency closure changes (cli, session, engine, cards, card, card_store, kernel, scenario, search), or Cargo.toml/lock, ui/fixtures.json, the card store; then it runs every scenario, since the full sweep costs ~3 s and any of those crates can change every script. (2) Ids: script:<card slug>/<moment name>/<yours|theirs>; recordings script:fixtures/<fixture>/<seat of its human>; a panic before any waiter could be told is script:unwatched (then the rerun is whole). A candidate that panicked is reported even though generation drops it (it never becomes a moment). (3) Fixture recorder: slow CI's shots/ui-test lanes already record via cargo run (debug), but a session-thread panic made record() block forever on recv(); it now fails with the panic, and every recording is also a per-id check in the script lane. (4) longthink's panic hook set PANICKED for any panic in the process, so the new deliberate-panic tests broke its tiny-run test in the same test binary; it now ignores panics on beryl_session's thread (beryl_session::SESSION_THREAD), which a long-think run never starts.
