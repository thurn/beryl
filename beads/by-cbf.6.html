Close reason

Mana solver capacities are layout types; Large payments past 16 classes and 128 sources play on (e979d80)

Description

Follow-up to by-cbf.5, which made slots, bitboards, nested queues, decision options and the engine's temporaries layout types, so Large grows them. The mana solver (rust/crates/beryl_engine/src/mana.rs, architecture §10) still has fixed capacities in both layouts, and each returns Err(Full), which stalls a player game for a capacity even after the session promotes it to Large:

  • CLASSES = 16: Sources.classes is Fixed<Class<L>, CLASSES>, Plan.taps is [u8; CLASSES], and Funds::of counts classes in a Fixed<_, CLASSES>.
  • MAX_SOURCES = 128: Funds::of returns Full past 128 untapped sources (reachable in Large with Treasures from Beza or Currency Converter).
  • plans() keeps Fixed<Plan, 64>, later_costs() Fixed<Later<L>, 32>, and the unit/assignment lists Fixed<_, 64>.

Make these capacities the layout's (as by-cbf.5 did for the engine's temporaries: L::Queue with a Small capacity, Vec in Large; Plan's per-class arrays need a layout-sized type), keeping Small unchanged. Related, not a stall: x_options offers at most 64 values of X.

Acceptance criteria

  • A player game past each mana capacity (more than 128 untapped sources; more than 16 source classes) continues in Large instead of stalling: a test in rust/crates/beryl_session/tests/promotion.rs per capacity, failing with promotion disabled.
  • size_of::<State<Small>>() unchanged (20,440); just count-gate passes with the bar unchanged.

Delivered: mana solver capacities are the layout's. Sources.classes, Funds' class count, plans/scores/kept, later_costs, pay's units and tapped lists, and assign's symbol/slot/owner/seen lists are L::Queue (Small: the same Fixed capacities; Large: Vec). Plan<L>.taps and spent_by_class are L::Table (Small: [u8;16]/[u32;16] as before; Large: an entry per slot, since every class has a member). A class holds at most 255 sources in a layout of more slots (taps stay u8; compile-time no-op in Small). complete() returns the left-over mana and wasteful() decrements in place, so the walk never copies plans. Opt::Plan is L::Index (u8 in Small, u16 in Large), so Large can name more than 255 plans; Pick::Plan, protocol Candidate::Plan and Payment.plan are u16 (TS unchanged: number).

Deviation: MAX_SOURCES (128) removed, not made a layout capacity. Sources never had a source limit; MAX_SOURCES was left over from Funds' old Fixed<_, 128> source list (825f343). Small can't reach it anyway (its battlefield holds 128 permanents across both players), so Small behavior is unchanged.

Tests: tests/promotion.rs source_classes_past_small_play_on_in_large (17 Strip Mines + an Island = 18 classes, casting Snapcaster) and sources_past_small_play_on_in_large (40 Islands + 90 Treasures from a test-only Hoard card = 130 sources; Small's battlefield overflows first, then Large used to stall on MAX_SOURCES). Each fails when its old cap is put back (checked by reinserting the cap).

Measurements: State<Small> untouched (no State field changed; const assert holds). just count-gate 405,777,238, +0.16% against the unchanged bar 405,147,828. just fuzz 400 passes. just check 31 s.

Not done (the bead calls it related, not a stall): x_options still offers at most 64 values of X.
