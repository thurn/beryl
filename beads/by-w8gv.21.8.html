  2. The script type. Ordered steps; steps that happen together grouped; each step a verb applied to objects, stack items or players. An arrow, a combat line or a mark is a step with a beginning and an end (decide: a begin step and an end step, or a span), never something recomputed from a view. No geometry and no timing: the script says what and in what order, the design-language data says how long. Decide and write down:
    • Identity. Views key objects by public slot (ObjectView.slot), and a slot is reused after a zone change. The stage keeps one node per game object for the game's life, so say what names an object across steps and across scripts.
    • Replay (K24). Each step carries enough that replaying a script over the previous view's table gives the next view's table exactly, and that the stage can show the state after each step without seeing the view after. Define which part of PlayerView is the table (objects, battlefield, stack, players' life, pools and counts, turn) and which is prompt and chrome (status, decision, stops, previews), replaced whole when the script ends.
    • Reset. A seat's first view and an undone view (PlayerView.undone) are a snap with no motion.
    • Hidden information. The script is per seat: what the viewer may not see is absent, not masked.
    • Cause. Each step names its cause where one exists (the stack item or object responsible). Step one infers it; step two (by-w8gv.21.5) takes it from the interpreter. Shape the field so that swap changes no consumer.
    • Sound. ui/src/audio/events.ts picks a sound from a GameEvent kind today; after the stage it follows a step, so a step must carry enough to pick it.
  3. The closed list of marks (K26): eligible, selected, suggested, friendly target, hostile target and the rest, each with one look. Scripts use them (a mark is a step with a beginning and an end) and so will milestone 6's prompt state: by-w8gv.11.1 says whichever lands first defines the list in beryl_session and the other uses it. Survey every outline, glow and badge today's UI puts on a card (grep the class names in ui/src/components/Card.tsx, ui/src/game/CardLayer.tsx, Board.tsx and ui/src/screens/screens.css) and what Arena shows, and name the list.

Design: the script type (answers to "What to settle", 2)

Code: rust/crates/beryl_session/src/script/ (mod.rs has this as its module doc; act.rs the acts; verb.rs the closed lists; text.rs the text form). Tests: rust/crates/beryl_session/tests/script.rs.

  • Shape. Script { reset?, beats: Vec<Vec<Step>> }: beats in order, the steps of a beat together, in stagger order. Step { act, cause? }. Act is one variant per verb. One subject per step: a batch is a beat of steps.
  • A span (arrow, line, mark, lift) is two steps, Begin and End (Span), not a range: an arrow outlives its script while players respond. The End repeats its Begin exactly; no span ids.
  • Identity. Subject = Object{slot} | Ability{id} | Player{player}. A card keeps its slot through every zone for the whole game (engine deck_slot; a shuffle re-deals identities among library slots, which a card back does not show). Only token/copy pool slots are reused, and only after a vanish with no record: from appear to that vanish a slot is one node. A view's stack gives abilities no name, so a seat's scripts number them from 1 at emerge, never reused; a reset lists the numbers of the abilities already on the stack (Reset.abilities, bottom first).
  • Replay (K24). Every step that changes an object carries the object's whole ObjectView after the step, so replay and the stage both replace a record and neither applies a patch: one meaning, no second implementation to drift. The table: objects, battlefield, stack, each player's life, mana, library and graveyard, and the turn's number, active and step. Order: a zone change takes the slot out of its old zone's list and inserts it at at, or at the end (top of pile, last permanent); same zone and no at leaves the order. An object leaving the stack takes its item; one arriving brings item. emerge pushes its item, vanish of an ability removes it (replay keeps the ability ids beside the stack). count sets life, pool or (by record) counters and stats. set carries what no motion shows: the turn (number, active, step), an object record (sickness, marked damage wearing off, derived characteristics, combat roles), a library's order after a shuffle, a stack item's changed targets.
  • Chrome, replaced whole when the script ends: status and its decision, stops, pending_attackers, undone, events, turn.priority/starting/flip_winner, each player's lands_played, mulligans, mulligan and emblems, and how the game ended. handling is neither: it is the lift span.
  • Combat roles (ObjectView.combat) ride on records (tap for an attacker, set for a vigilant one or a blocker); the chevron is the record's face. The attack and block lines are point spans beside them, held to the rule invariants (by-w8gv.21.10), not to replay.
  • Reset. Script.reset is set for a seat's first script and beside an undone view: the stage drops table and spans and takes the view's table with no motion; the script's steps are then only span Begins, shown at once.
  • Hidden information. A script is built from its seat's views and events and carries that seat's ObjectViews, so an unseen card has no name in a step either; what the seat may not see has no step.
  • Cause. Step.cause: Option<Subject> (spell = its object, ability = its number, a permanent, or a player for their own action); none = the rules (turn-based, state-based). Inference now, interpreter later (by-w8gv.21.5): same field.
  • Sound. Picked from the verb plus what the step already carries: from/to zones and Why for fly/appear/vanish (today's ARRIVING table and resolve/shatter), tapped for tap, the Tally kind for count (rise or fall against the stage's own table), Stream for streak, the Notice for announce; whose it is from cause or the record's controller.
  • Text. Display only (tests write expectations by hand; nothing parses it). One step a line, & joins a step to the beat above, <- gives the cause, +/- begin and end a span, #12 (Name) a card, a3 an ability. It prints what a step shows, not every replay field (a shuffle prints the library's size, not its order): replay is the exact check, text the readable one.
  • Not in protocol.rs; TS names: the step is ScriptStep (protocol has Step), the number is Tally (TS has Number).

A pile shows the marks of the cards in it. Arena has one cyan for "can play now" and "legal pick", so today's green card-playable and cyan card-target are both eligible; Arena shows no glow on a stack item's target or on an ability's source (arrow and thin line only), so today's gold source glow has no mark.

For by-w8gv.21.9 (builder and replay):

  • Every object-changing step carries the object's whole ObjectView after the step. Keep a working table, mutate it per event, clone the record into the step, and reconcile against the next view at the end (patch the last step that touched the slot, or emit set). Intermediate records for a card that enters and leaves within one update have to be synthesized (the views never held them); replay checks only the final table.
  • The table for replay is in mod.rs: objects, battlefield, stack, players' life/mana/library/graveyard, turn number/active/step. Everything else is chrome and not replayed. set Fact::Turn carries number, active, step; priority is chrome.
  • ObjectView.combat is in the table, so 21.9's replay needs the attack/block roles on records (tap, or set) even though the lines are 21.10's point spans. I did not couple spans to the table.
  • Ability ids: number at emerge per seat, keep the id list beside the stack for replay, and give Reset.abilities at a reset. A view's Thinking moment pushes the resolving entry back on the viewer's stack (protocol.rs player_view): the builder has to treat that as the same ability, not a new emerge.
  • A shuffle is set Fact::Library with the order; a known library card going unknown is a flip (or a set record).
  • Pool: count Tally::Pool only for mana that stays; the cast's streaks are 21.10's and change no table.
  • Put Script beside the view (GameUpdate or PlayerView) as an optional field; Script derives Default and reset is skipped when none.
