Close reason

Typed, viewer-relative session protocol: Status/DecisionId/Side, one answer check, Sessions in beryl_session, generated Commands map, engine names in card data (7fedce1, 9fbfce8)

Description

Mason finding (by-b0q.2.1). M1b's three game-screen beads (by-b0q.3.4, .3.7, .3.8) build the whole UI on PlayerView and the choose command, so fix the protocol's shape first.

Current design

  • Three-way status as two Options. PlayerView has seq: u32, decision: Option<DecisionView> and outcome: Option<OutcomeView> (beryl_session/src/protocol.rs:22,35-36) for three states: deciding, stopped (game.rs:201-202, undocumented) and over. Both-set is representable; seq means nothing unless deciding.
  • Answers are three loose integers validated three times. The UI calls choose(session, seq, index) (ui/src/ipc.ts:130, beryl_app/src/games.rs:76, index: usize, later Choice(index as u8) at game.rs:138). The same stale/range check runs in GameSession::choose against a mirrored Arc<Mutex<Option<(u32, usize)>>> (session.rs:21,59-73), again in Game::choose (game.rs:124-136), and again in from_replay (game.rs:98-102).
  • Session logic in the Tauri shell. beryl_app/src/games.rs numbers sessions, checks stale session ids, picks deck, seat and stops, seeds from the clock and names replay files; SessionError is flattened to String (games.rs:68,94) so a harmless double-click StaleDecision reaches the user as an error. beryl_cli/src/fixture.rs re-implements the wrapper (SESSION = 1, GameUpdate, command and event names as literals, fixture.rs:16,136-159). AGENTS.md wants beryl_app thin.
  • Seat arithmetic and duplicated fields in the view. viewer: u8 makes the UI compute 1 - view.viewer (ui/src/screens/Game.tsx:84,107); DecisionView.player always equals the viewer (protocol.rs:486); PlayerState.hand/exile repeat objects filtered by zone while ObjectView.zone repeats the lists; a spell's StackItem.name/controller repeat its ObjectView and ability: Option<u8> doubles as the spell/ability flag; power/toughness are independent Options the UI assumes are set together (Game.tsx:195); mana: Vec<u8> is positional; Stalled { reason: String } is English.
  • Events skip the Observation. Game::events drains the full engine's events and From<&Event> for GameEvent takes no viewer (protocol.rs:757); the information independence test removes events before comparing (tests/sessions.rs:37,172). Safe today only because no event names a card identity.
  • Card names are an unchecked string join. The UI looks names up in data/cards.json (ui/src/cards.ts:38-47) and patches token naming ("Samurai Token" vs Scryfall's name, cards.ts:34-41); nothing checks every engine face, token and emblem name resolves, so a mismatch is a silent placeholder. M1a fixed one such mismatch (24dca83).
  • Hand-kept twins in TS. invoke<T>(command: string, ...) with per-wrapper casts and payload as never (ipc.ts:19,34); AppInfo and FixtureMessage are written on both sides.

Proposed design

enum Status { Deciding { decision: DecisionView }, Stopped, Over { outcome: OutcomeView } }
struct DecisionId { session: SessionId, seq: u32 }  // opaque to the UI, echoed back
struct CandidateIndex(u8);
enum Side { You, Opponent }                          // players: { you, opponent }
enum StackItem { Spell { slot }, Ability { source, ability, name, controller: Side, .. } }
pt: Option<PowerToughness>; mana: ManaPool { white, blue, .. }; Stalled { reason: StallReason }
// beryl_session::Sessions { start(StartRequest) -> SessionId,
//   choose(DecisionId, CandidateIndex) -> Result<(), SessionError>, set_stops(..) }
// SessionError: Serialize + TS, a tagged enum; command and event names are constants.
fn game_event(obs: Observation, e: &Event) -> Option<GameEvent>

Validation happens once: only the open-decision record turns (DecisionId, CandidateIndex) into an answer Game applies without re-checking. beryl_app keeps Tauri commands that delegate, and the art cache. The CLI fixture recorder uses the same Sessions. TS gets one generated or typed Commands map tying each command to its args and result; AppInfo and FixtureMessage come from ts-rs. Keep the ordered zone lists (library, graveyard, battlefield, stack) and drop whichever of zone / unordered lists the UI does not need. by cards (or a mapping in Rust) gives tokens the engine's names so the TS special case goes.

What it eliminates

Impossible view states, two of three validations, the usize→u8 cast, stringly errors, logic in beryl_app, the CLI's duplicate wrapper, seat arithmetic in the UI, duplicated view fields, the token-name patch in TS, and the per-command casts.

Must not change

The Observation-only rule; the information independence test (now covering events too); replay files resume to the same view; just ui-shots fixtures still render (they are re-recorded with beryl_cli, never hand-edited); just smoke passes.

Conflicts with the engine identifier bead filed alongside are expected; rebase onto whichever lands first.

Acceptance criteria

  • PlayerView carries a tagged status (deciding with its decision, stopped, over with its outcome) instead of independent Options, and is viewer-relative (no seat number the UI must do arithmetic on); ui/src has no 1 - view.viewer or equivalent.
  • The UI answers with a DecisionId it received and a candidate index; the stale and range checks exist in exactly one place in Rust. A test answers with a stale id and an out-of-range index and gets distinct typed SessionError variants, which reach the UI typed (not String).
  • Session lifecycle (numbering, stale-session rejection, start parameters) lives in beryl_session; beryl_app/src/games.rs only delegates, and beryl_cli uses the same API with no duplicated command or event name literals.
  • Events reach the view through the viewer's Observation, and the information independence test compares events too instead of stripping them.
  • A Rust test asserts every face, token and emblem name in beryl_cards::CARDS resolves in data/cards.json; ui/src/cards.ts has no token-name special case.
  • ipc.ts has no as never cast and no hand-written copy of a Rust type.
  • just ci passes (smoke and ui-shots included).

Inline review (cold subagent): no correctness bugs found; checked the session thread/mirror ordering, stops re-emit, replay resume, stand-in shutdown, wire shapes vs generated TS. Findings and what I did:

  1. The event half of the independence test passes the same raw engine events to the redealt view, so it only covers what the conversion reads through the observation. Accepted as the design's limit: game_event takes no table and engine events carry only slots, so an identity could only come from obs (caught). Documented on game_event and in the test; moving events into Observation would be an engine change colliding with by-b0q.2.4.
  2. Command and argument names had two unchecked copies (Tauri fn/param names vs ipc constants and the generated Commands map). Fixed: each game command takes one generated request struct (StartRequest, ChooseRequest, SetStopsRequest) under the param name request, and beryl_app registers handlers through a macro whose const assert fails the build when a function is not named as its ipc constant (verified by mis-mapping one).
  3. The stops checkbox stayed enabled after game over and showed a raw Ended error. Fixed: disabled unless deciding. just ci passes locally after the fixes.
