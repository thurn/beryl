Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'Hidden information' and 'Actions'.

Fill rust/crates/beryl_table/src/apply/library.rs: draw, mulligan, shuffle (a whole library, or its top or bottom n), look (top n, bottom n, or all), reveal (chosen cards, a whole zone, or n random cards, to named seats), lend, always_reveal_top, always_look_at_top, sort_hand (by name, type line, or mana value, read from the store).

The knowledge rules are the point of this bead. Implement each as stated in the doc:

  • A card entering a hand: new id, known_to = the hand's owner only.
  • A shuffle: every shuffled card gets a new id and an empty known_to. The new order comes from Chance and is recorded in the entry as a random outcome. A shuffle also ends a lend.
  • look adds the looker to known_to. reveal adds the seats revealed to.
  • A card entering a library keeps its known_to.
  • Nothing else ever removes a seat from known_to. Add a debug assertion in apply/mod.rs that the only changes shrinking known_to come from a hand entry or a shuffle.
  • always_reveal_top keeps the top card known to all seats after every later action; always_look_at_top keeps it known to the owner. Apply them in apply/mod.rs after each action's changes, as extra changes in the same entry.
  • Drawing from an empty library draws what is there and is not an error.
  • mulligan moves the hand to the library, shuffles, draws n.

Tests: each action; each knowledge rule as its own named test; a shuffle replayed with Chance::replaying gives the same order. Run just test-rust -p beryl_table.

Acceptance criteria

All nine actions are implemented with tests; each bullet of the doc's Hidden information list has a named test; a replayed shuffle reproduces its order; the known_to assertion exists.

Handoff: apply/library.rs implements the nine actions through apply, using the card move planner for draw, mulligan, and library reordering. Change::Lend, AlwaysRevealTop, and AlwaysLookAtTop are reversible indexed list edits. Shuffle records forward Fisher–Yates offsets in Change::Random before position/ID edits. Top-card Learn changes go at the end of the same Entry and remain known when a setting is switched off. Hand sorts are stable for ties and ignore case for names and type lines. Lend grants access without teaching card identities. Redaction and general undo are the downstream beads; ensure shuffle random outcomes and old-to-new identity links remain host-only, and include the three list edits in undo conflict detection. The debug guard validates hand entries and library resets for Shuffle/Mulligan. The game actions can reuse library::shuffle and draw; if Start shuffles pre-known cards, extend the guard for that path.
