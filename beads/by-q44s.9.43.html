Close reason

b3d tree/check/png/film honour --scale through Page::with_scale; test plays 1600x900@2; windowless app --scale (2 on macOS)

Description

Symptom: on a Retina Mac the desktop app (scale 2) drew "You won the ip", with the "fl" ligature missing. just b3d png opening-play --at prompt:1 drew "You won the flip" correctly, and so did every other headless tool, because none of them runs at scale 2 (by-q44s.9.39).

Why: the test driver tells the client scale 1 whatever the options say (rust/beryl3d/crates/beryl_scene/src/driver/mod.rs begin, Input::Surface { scale: 1.0 }). Headless::new (beryl_host/src/headless.rs) asks for the Latin glyphs and icons at 1.0 and only makes its target --scale times larger, so png --scale 2 stretches a scale-1 frame. It also loses clipped content: just b3d png screen/start --at end --scale 2 draws the start screen with the opponent list empty, because the list's clip stays in scale-1 pixels while the target is twice as large. The windowless app that agents run (just b3d app with no window) is hardcoded to scale 1 too (beryl_3d/src/app.rs, WindowlessOptions { scale: 1.0 }). just b3d test runs only scale-1 windows (beryl_inspect/src/pages.rs).

Change:

  • Make Options::scale (beryl_inspect/src/cli/options.rs) reach the client through the driver's Input::Surface, and have Headless ask for glyphs and icons at that scale. Clips then come out in physical pixels.
  • Give just b3d app a --scale option for the windowless host (tools/src/beryl_tools/beryl3d/app.py and beryl_3d options), defaulting to 2 on macOS, the scale of the owner's display.
  • Add scale 2 to the desktop window matrix of just b3d test (one size at least, for example b3d:<rec>/<seat>/1600x900@2) so that it runs on every push, and keep the lane inside its time budget.

Files: beryl_scene/src/driver/mod.rs, beryl_host/src/headless.rs, beryl_host/src/windowless.rs, beryl_3d/src/app.rs, beryl_inspect/src/cli/options.rs, beryl_inspect/src/pages.rs, beryl_pictures/src/main.rs, tools/src/beryl_tools/beryl3d/app.py.

Acceptance criteria

just b3d png and tree honour --scale (the client gets that scale and glyphs are prepared at it); png --scale 2 of screen/start --at end shows the opponent list; just b3d app runs windowless at --scale 2; just b3d test runs at least one scale-2 window per recording on every push within the lane's budget.

Handoff: the headless tools and the windowless app now run at the display's scale. Commits c5742afe6, eb4721ab7, 315a87e33 (staging).

What changed:

  • beryl_scene driver: Page::with_scale(scale) and Page::scale(). The driver gives the client Input::Surface { scale }, which used to be hardcoded to 1.0. Element positions stay in logical points, while the client asks for glyphs at that scale and gives clips in physical pixels. Element moved to driver/element.rs to keep mod.rs under 800 lines.
  • beryl_inspect: cli::open applies Options::scale, so tree, check, png and film all honour --scale. Test names take @<scale> (b3d:<rec>/<seat>/1600x900@2), and Options::test_name parses it. Test has a scale field. pages::Windows::windows() replaces sizes() and returns Window { size, scale }.
  • just b3d test plays the 1600x900 desktop window at scale 2 instead of scale 1 (pages::RETINA_WINDOWS, RETINA_SCALE). This is a deviation from the bead's "add". The test count stays at 8280, so a fast check starts the same share of tests as before. Scale 1 is still covered by the 1440x900, 1920x1080 and 2560x1080 windows, and by every unit test that uses 1600x900 directly.
  • beryl_host Headless::new lost its scale argument and reads the page's scale; glyphs and icons are prepared at that scale.
  • beryl_3d: --scale <1-4> for the windowless host, defaulting to options::WINDOWLESS_SCALE (2 on macOS, 1 elsewhere). just b3d app --scale passes it through (tools/src/beryl_tools/beryl3d/app.py). Window modes ignore it.
  • Docs: rust/beryl3d/AGENTS.md, the b3d skill ("What these tools cannot show"), and docs/beryl-3d.md.

Evidence:

  • png screen/start --at end --scale 2 (3200x1800) draws the opponent list. New test a_picture_at_scale_2_draws_what_its_clips_hold (beryl_pictures/tests/pictures.rs) fails with 0 pixels drawn in the list when the driver is forced back to scale 1.
  • Before rebasing onto by-q44s.9.35's atlas fix (8132a4d90), png opening-play --at prompt:1 --scale 2 drew "You won the ip" without the menu gear, which reproduces the owner's report. After the rebase it draws "You won the flip" and the gear.
  • New test a_retina_tests_name_opens_the_same_scale_in_test_tree_and_check (beryl_inspect tests/all/runner.rs). The bug-report test now expects window.png at 1600x900 times WINDOWLESS_SCALE.
  • The full just b3d test passed with the scale-2 window (no faults at @2). The tests of beryl_inspect, beryl_3d, beryl_pictures, beryl_host and beryl_scene passed (703), and clippy is clean.

Not met as written: the acceptance asks that a scale-2 window run for every recording on every push. The push's fast check (load 29) started about 1640 of 8280 interface tests before --stop-after and deferred 6641 to the sweep. That deferral predates this change and affects every window equally; by-oafqa audits the lane being over budget. The @2 tests ran in that check (stress-hand@2 was among the slowest), and the sweep runs all of them.

For the reviewer:

  • The windowless app now draws 4x as many pixels on macOS. That affects just b3d smoke, tiers, stand-in and play, and could change which tier tiers chooses at startup. It is closer to the owner's display, but watch the sweep's tier and smoke steps.
  • Phone windows still play at scale 1, while real phones run at 2-3.
