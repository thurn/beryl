Implemented and tested reversible card actions and printed-face play and resolve. Enact fast checks passed and 29721a64 landed on staging.

Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'The table', 'Placement', 'Actions'.

Fill rust/crates/beryl_table/src/apply/cards.rs. Each function returns Vec<Change> and never touches the Table directly (see apply/mod.rs and how move does it).

Implement: reorder, pin, give, face, flag, peek, counter, stats, damage, note, attach, unattach, clone, token, marker, remove. Also the two computed move destinations "play" and "resolve", and the consequence "a permanent with a printed loyalty or defense enters with that many counters".

Rules to follow exactly:

  • Every action takes one object or many and produces one Entry.
  • counter adds to or sets a named count, clamped to 0..=999. A count of 0 removes the name.
  • stats sets or clears the manual power and toughness. The shown value is computed by beryl_card_store::facts (bead "card facts"), not stored.
  • peek adds the acting seat to a face-down card's known_to.
  • face: a card turned Down keeps its known_to; turned up in a public zone it becomes known to every seat.
  • attach puts cards under a host permanent; they move with it; unattach or leaving the battlefield detaches them. A host leaving detaches what it carries.
  • clone creates a token copy of a card. token creates a store token or a custom one, optionally attached. marker puts an AbilityMarker on the stack. remove is allowed only for tokens and markers.
  • give sets controller. On a table with one seat it is Refusal::Invalid.
  • "play": use facts::is_land and facts::enters_tapped. "resolve": use facts::is_permanent; a marker ceases to exist.

Tests in src/apply/cards/tests.rs (or tests/cards.rs): one per action, plus many-object forms, the 999 clamp, a host leaving, and play/resolve for a land, a creature, an instant and a marker. Run just test-rust -p beryl_table.

Acceptance criteria

Every action listed is implemented through Change values with a test each; play and resolve use the card facts; no stub for these actions remains in apply/cards.rs.
