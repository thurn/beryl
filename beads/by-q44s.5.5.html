Scrolling, clips, transitions, focus and shortcuts on staging at 441c277

Description

Read first: the epic by-q44s ('Rules for every bead'); rust/beryl3d/AGENTS.md; docs/beryl-3d.md 'Elements', 'The frame' (clips are scissor rectangles; at most 15), 'Determinism', 'Interface checks' (clips fit). Code: beryl_scene src/layout/mod.rs and write.rs, src/frame.rs (FrameBuilder::clip), src/motion.rs and src/pose.rs (segments: how the table animates on the show's clock), src/client.rs (point, key inputs, Input::Key), src/input.rs (Key, KeyCode, Modifiers). Web behavior: ui/src/table/shortcuts.ts (bindingChord, resolve, bindingFor, describe: a chord string such as Cmd+Shift+L becomes a modifier mask and a physical key; Cmd is Ctrl off the Mac) and ui/src/table/bindings.ts (class Bindings: get, lookup, bind, reset); ui/src/components/bugReportKeys.ts (isBugReportShortcut: Cmd+B, Cmd+Shift+B while the table is open).

Build, in beryl_scene:

  1. overflow: Scroll and Clip (src/layout): a scrolling element keeps a scroll offset per element id, moved by the wheel and by a drag on a touch pointer, clamped to its content, and its children are written under a clip rectangle from FrameBuilder::clip. Scrolling moves records and changes no layout. Nested clips intersect. An element scrolled out of its clip is not in the frame's interactive set.
  2. Transitions: when a matched node's opacity or its laid-out position changes, the layer plays the change as a segment over the duration and curve in data/beryl3d/space.json under a new key flat.transition (180 ms, ease-out, the web's dock ease in ui/src/screens/styles/controls.css). A new node fades in over the same; a removed node is gone at once. Transitions are computed in frame from start and end values with no allocation.
  3. Focus: one focused element, set by Press::Focus and by a press on an element with focus: true; Tab and Shift+Tab move it among focusable elements in tree order; Return presses the focused element; Escape sends the press of the element named close in the top sheet or menu, if there is one.
  4. Shortcuts, in a new file src/element/keys.rs: Chord { key: KeyCode, modifiers } parsed from the web's strings by the rules of shortcuts.ts, and Shortcuts, a table from chord to Press, given by the screen function beside its tree (Element::shortcut(chord, press) on the root). A key input that matches presses it; the bug report chord is Cmd+B (Cmd+Shift+B while Screen::Table is shown), sending Press::Sheet(Some(Sheet::BugReport)). Persisted rebinding is not built (the web keeps it in localStorage for the manual table).

Do not build: the text field's keys (the field bead), menus (the widgets bead).

Tests, in beryl_scene/tests/flat_layer.rs: a column of 30 rows in a 200-point scroll box, scrolled by 300 points, moves its rows by 300 with no layout work and leaves only the visible rows interactive; nested clips write one clip that is their intersection; a node whose opacity changes from 1 to 0 is at 0.5 opacity halfway through the transition; Tab moves focus to the next button and Return presses it; Cmd+B gives Press::Sheet(Some(BugReport)) and Ctrl+B does too on a non-Mac platform flag; a frame mid-transition allocates nothing.

Run: just b3d cargo-test -p beryl_scene; just b3d test; just b3d lane.

Handoff: beryl_scene src/layout gains scroll.rs (Node.scroll and scroll_room from taffy's scroll_width/height; Layer::scroller_at, Layer::scroll clamps), motion.rs (Motion on Node; Layer::tick(now) stamps and evaluates transitions, returns whether any run; Client::frame calls it first and wakes Now while it returns true), focus.rs (Layer::focused/focus/focusable_at/move_focus/focused_press/close_press/shortcut). Layer::hit is the one generic search behind press_at, scroller_at and focusable_at; it applies each node's own transition offset and its ancestors' scroll offsets. write.rs: a Look struct carries the point, opacity, tint and (clip rect, clip entry). Overflow Clip/Scroll writes children under builder.clip(rect cut to the outer clip, in physical pixels), offset by -scroll; BlockLook.clip clips glyphs and symbol discs. Resolved.interactive is false when the element lies outside its clip or is at opacity 0. Transitions: only the screen tree transitions (Layer.animating is set during show), never floats. A new node fades in, and its new children don't fade separately. A kept node moves when its corner on the window changes and its size doesn't (a resized box jumps, so a right-anchored bar can't slide off screen). Offsets apply to the node alone, not inherited. Opacity changes fade from the shown value. Duration is data/beryl3d/space.json flat.transition.ms (180) with Curve::EASE_OUT. Keys: element/keys.rs Chord::parse(binding, mac) follows shortcuts.ts. Shortcuts(Vec<(String, Press)>) sits on Element.shortcuts, built with Element::shortcut, and only the screen root's are read. Client::key handles shortcuts, then Tab/Shift+Tab, Return, Escape (the element named close), then Cmd+B (Cmd+Shift+B on Screen::Table) for the bug report. Other keys still go to inputs. New Input::Platform { mac } (Client defaults to Mac); beryl_host desktop sends it at startup. Phone hosts don't send it yet. Deviations: the tests are in tests/all/elements.rs (flat_layer.rs is near 800 lines). The fade test checks 1 - ease_out(0.5) at half the duration, not literally 0.5, because the curve is ease-out. The allocation case is in tests/frame_allocation.rs. flat_layer tests that checked interactivity or equality at frame 0 now look after the 500 ms fade. test-faults for choice-trigger-order/you/2560x1080 is lowered to 18 (upstream had also lowered it).
