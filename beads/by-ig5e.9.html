Description

Finish CI accounting with the two parts that connect CI to beads: what the fast check costs each push, and what a slow-CI failure costs after the failing check itself.

Design sections: "The fast check", "What a slow-CI failure costs", and "Inside a push" under "Time accounting".

What to build

  • Inside a push: the run-log lines with the bead's worktree (the worktree field the previous bead added) and a time inside the enact push tool call give the seconds of each check lane; the rest of the call is rebase, waiting and push. Lines written before the field existed cannot be joined: report those pushes as not split.
  • The fast check view: per push wall seconds, CPU seconds, seconds queued for cores and check lanes run; steps deferred or cut at the time limit (the fast check logs deferred: <lane> <step> and cut steps, see tools/src/beryl_tools/deadline.py); pushes that lost the race to staging and checked again, with the repeats' cost; failures before a push by verdict.
  • Per slow-CI failure: the Steward bead's cost (beads labeled role:steward, with enact_ci_range), the CPU of bisection (script bisect), the time master stayed behind staging because of it, and each miss with its check.
  • Metrics push.wall-seconds, push.repeats, slow-ci.failure-cost-per-day, staging.minutes-to-master.

Shared context

  • The design is docs/efficiency-dashboard.md. Read the sections named above before anything else; the rest can wait. The decisions taken with the user are in the epic, bd show by-ig5e.
  • The dashboard's code is the separate Python project in efficiency/ (package beryl_efficiency, standard library only, pyre strict, black). It imports nothing from tools/ and nothing imports it. Read efficiency/AGENTS.md first once it exists.
  • Tests use small synthetic sources built in the test itself or kept under efficiency/tests/. The repository is public: never commit a real transcript, session record or command line from this machine.
  • Real data exists only on the main Mac (host jarvis). Where the acceptance criteria name a check against real data, run it there; if this session is on another machine, record that the check was not run in a comment on this bead and close on the tests.
  • Collection must stay free for agents: no hook, wrapper or prompt text may be added to any session, and ingest must never run inside another command.

Acceptance criteria

Tests: a push whose window holds run-log lines for two check lanes shows both and a remainder that sums to the call's length; a push with no joinable lines is reported as not split; a fixture failure's cost is the sum of its Steward bead, its bisection CPU and its stalled time. On the main Mac, a closed Steward bead appears under the failure costs with non-zero dollars, and a recent bead's push shows its fast-check part matching just ci-report for that time.
