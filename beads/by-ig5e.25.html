Close reason

Dolt 2.7.3 push no faster than 2.2.0 on a store copy (median 7.6 s vs 7.0 s, same CPU); not upgraded

Description

Enact's Beads syncs hold the ownership lock, and Dolt's push is 74% of that time on the main Mac: median 11 s, up to 50 s (see 'Where a sync's time goes' in ~/enact/docs/design.md, and the push_s field of .git/enact/lock-waits.jsonl). The Dolt CLI is 2.2.0, and 2.7.3 is out. Within dolt push, a traced push ran four git pushes to GitHub, 530 git cat-file calls and seven fetches. Install a newer dolt on a copy of the Beads store (cp -cR .beads/embeddeddolt/by plus a scratch git remote, never the live remote), time a commit-and-push there against 2.2.0 on the same copy, and upgrade the machine's dolt only if pushes are faster and enact's tests pass (python3 -m unittest tests.test_unit tests.test_integration in ~/enact). Record the before and after push_s medians on this bead.

Acceptance criteria

Push time on 2.2.0 and the newer Dolt, measured on the same store copy, recorded on the bead; dolt is upgraded only if faster and Enact's slow tests pass with it; a day of push_s from lock-waits.jsonl after an upgrade is compared with the 11 s median.

Derek Thurn2026-11-16

Measured, no upgrade. Method: copied the live store (cp -cR, 1.2 GB), pointed the copy at a scratch local bare git remote (git+file, seeded by one full 2.2.0 push), then per trial re-cloned store and remote from the same pristine copies, committed one row and timed 'dolt push origin main'. Three alternating trials each at load 65-75. Dolt 2.2.0 wall: 5.2, 7.0, 7.0 s (median 7.0); user+sys CPU 3.4, 3.6, 3.6 s. Dolt 2.7.3 wall: 4.8, 7.6, 8.3 s (median 7.6); user+sys CPU 3.5, 3.8, 3.8 s. Same CPU, wall differences are load noise, so 2.7.3 is not faster. Caveat: a local file remote omits the GitHub network share (~6.7 of 14 s in the traced push), but the git-cache CPU work in Dolt is the part a newer CLI could have cut and it did not change. Decision: dolt stays at 2.2.0 (~/.local/bin); nothing changed in ~/enact or the repo, so slow tests and the lock-waits comparison were not run. The downloaded 2.7.3 binary was only in the scratchpad.
