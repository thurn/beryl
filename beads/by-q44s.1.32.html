Close reason

beryl_cli is now a library; record, definitions and trace are public

Description

Read first: rust/crates/beryl_cli/src/main.rs, fixture.rs (record turns a definition from ui/fixtures.json into FixtureMessages), specs/ (how each card's spec moments are recorded) and boards.rs.

Beryl 3D's tools record fixtures with the code beryl_cli already has, and beryl_cli is a binary only. This is one of the few changes this epic makes to the main workspace (doc 'Checks and isolation', the exceptions).

Add rust/crates/beryl_cli/src/lib.rs. Move the mod declarations of fixture, boards, specs and what they need from main.rs into it, and have main.rs use beryl_cli::.... Make public: fixture::record, the function that loads ui/fixtures.json's definitions, and the function in specs/ that records one card spec moment for one seat. Do not change what any beryl_cli subcommand does.

Run: just test-rust -p beryl_cli; just check.

Acceptance criteria

just test-rust -p beryl_cli passes and beryl_cli record-fixture and beryl_cli script-check behave as before; the three functions are public from the library; nothing else in the main workspace changed.
