Close reason

Sweep beads no longer pinned with enact_host; enact_ci_host kept

Description

Beads the Beryl 3D sweep files on this Mac (for example by-q44s.65 and .66) carried enact_host=dereks-macbook-pro, but Enact's viziers on this Mac call the host jarvis (socket.gethostname() in an interactive shell returns JARVIS.local). Enact only hands a bead pinned with enact_host to a vizier on that host, so no vizier ever started them; the vizier unpinned .65 and .66 by hand on 2026-11-16.

Cause: tools/src/beryl_tools/nightly_failures.py host() uses ENACT_HOST or socket.gethostname(), and the sweep process (probably started by launchd or another background job) sees a different hostname from the shell the viziers run in. by-q44s.54 added the pinning; since by-q44s.72 the sweep only runs on the Mac, so the pin is not needed to keep Windows failures off this machine.

Fix: either stop pinning sweep beads with enact_host (keep enact_ci_host as a record), or make host() return the same name Enact's host_name() returns in every context (for example by setting ENACT_HOST in the sweep's job definition). Update tools/tests for the sweep. Done means a bead filed by a sweep on this Mac is offered to a vizier on this Mac.
