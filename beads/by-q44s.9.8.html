Description

Read first: .claude/skills/specs/SKILL.md (what the web skill gives: a card's moments as text descriptions, filmstrips, an animation audit and a driver); .claude/skills/b3d/SKILL.md; tools/src/beryl_tools/specs.py (resolve, nearest, specs: how the web side names a card and its moments); docs/beryl-3d.md 'The agent interface'.

Card spec moments are already recordings of Beryl 3D's pack, named <card>/<moment> (just b3d list <card>). What is missing is one command that shows a card's moments the way the web skill does.

Build just b3d spec <card> [moment] in a new module tools/src/beryl_tools/beryl3d/spec.py:

  • Resolves the card as specs.py's resolve does (reuse it, with its nearest-name error).
  • For each moment (or the one given), from the seat given by --seat you|opponent|both (default both): the just b3d info lines of its prompts, the just b3d tree at each prompt (--at prompt:<n>), cut to 40 lines with the doc's cut notice, and the result of just b3d check (faults, or no fault). Output is bounded and begins with the command that reproduces it.
  • --film also runs just b3d film <card>/<moment> --frames 12 for each moment and prints each picture's path.
  • Reuse cli.py's run_b3d and run_render helpers to run the two programs.

Skill: a section "Beryl 3D" in .claude/skills/specs/SKILL.md: when to use it, just b3d spec with two examples, and how to go on with just b3d tree, diff, png and check on one moment.

Test in tools/tests/test_beryl3d_spec.py: with the b3d program replaced by a stub (as tools/tests/test_beryl3d_cli.py stubs it), spec <card> runs info, tree and check for each moment and both seats, and a misspelt card exits 2 naming the nearest. Run: just test-py tests/test_beryl3d_spec.py.

Each skill keeps working for the web interface until the switch: add a Beryl 3D section, never replace the web instructions. Register any new command through MODULES in tools/src/beryl_tools/beryl3d/cli.py with a COMMANDS tuple in your own module, --help and two examples (rule 19). When the job works, set this job's b3d in data/beryl3d/parity.json's tools to the command or skill section that does it. Rule 17: no new recipe in the justfile and no change to tools outside tools/src/beryl_tools/beryl3d except the skill's own files.

Acceptance criteria

just b3d spec counterspell prints every moment of the card from both seats with its trees and check results (output in a comment); just test-py tests/test_beryl3d_spec.py passes; parity.json's specs job names the command; enact push passes.
