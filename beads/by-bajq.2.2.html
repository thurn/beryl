Description

What to build

Plan: Designs 2, "Ability removal" and "Continuing once begun"; principle 7.

  1. The mask. Derived gains a 16-bit mask of the face's abilities the permanent has lost, all set for "loses all abilities". An effect that removes abilities also clears the keywords and grants that effects before it applied; those applied after it stay (timestamp order within layer 6, CR 613.1f). A face with more than 16 abilities stalls into Large, whose mask is wider.
  2. One question. State::has_ability(slot, FaceAbility) is what every reader asks: trigger::match_event and look-back matching, cast/legal.rs's activations, the layers' own scan for static abilities, the replacement lookup, mana/sources.rs, sba.rs. With no removal in effect (a flag the recompute stores) it is constant true. The listener masks the recompute folds leave out lost abilities.
  3. New modifications in beryl_card/src/continuous.rs, each with its LayerChange: LoseAllAbilities, LoseAbility(AbilityIx) (layer 6); SetColors, AddColors (layer 5, new Layer::Color); SetBasePt(power, toughness) with a fixed number or an amount (layer 7b, new Layer::PtSetting); SwitchPt (7d). For a resolved effect an amount is settled as the effect begins (CR 608.2h); for a static ability it is read for each affected permanent as the layer applies.
  4. CR 613.6. An effect with parts in several layers finds what it applies to once, where it first applies, and keeps applying to that set in later layers though its ability has been removed in between. The recompute's list carries the set from part to part. A static ability begins only if its permanent still has it when its first layer is reached.
  5. Modification::SetPower's special path (LayerChange::DefinedPower, Unapplied::SetPower) folds into layer 7a's general form where it is simpler.

Cards

  • Humility: "All creatures lose all abilities and have base power and toughness 1/1."
  • Dress Down: flash; draws as it enters; "Creatures lose all abilities."; sacrificed at the beginning of the end step.
  • Scenarios: a creature with an enters trigger entering under Humility triggers nothing; a lord's bonus disappears; an Aura's grant applied after Humility stays; an activated ability can't be activated; a mana creature makes no mana.

Decisions: (1) LayerSpec.modification became modifications: &'static [Modification] so one static ability holds every part of one effect (CR 613.6); Swift Reconfiguration keeps its three single-part statics to leave its ability indices alone. (2) Derived::lost is packed into Derived with #[repr(Rust, packed(2))]: unpacked, the 2-byte mask rounds each 40-byte row to 48 and State<Small> overflows 20 KiB. Packing measured free in the count gate. Fields must be copied before borrowing ({ d.granted }.iter()). (3) No W/U/B creature lord fits the vocabulary (all say 'other', no Filter::Other), so the 'lord bonus disappears' scenario uses Adeline's characteristic-defining power (Humility: 1/1; Dress Down: 0/4) instead; grant-after-removal and Humility+Opalescence are rules tests (beryl_rules/src/tests/ability_removal.rs) because no animator or Opalescence is implemented. Gold Myr implemented for the mana-creature scenario. (4) has_ability's flag test cost up to 0.9% of the count at hot sites; activation now checks once per permanent in activation_options and the slow paths are #[cold], bringing the change to +0.07%.
