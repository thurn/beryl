Landed the manual table command registry and verification on staging at 1f948020.

Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Interaction' (the paragraph defining a command and its JSON example), and the whole of docs/manual-multiplayer-cockatrice.md ("the appendix").

The context menu, the command list and the shortcuts are generated from one list. Create it as data: data/table-commands.json, with a line about it in data/AGENTS.md.

Each entry: id ("library.look_top"), label (the wording in the doc or the appendix's "In Beryl" column, e.g. "Look at top cards…"), applies_to (one of permanent, their_permanent, hand_card, stack_entry, pile_card, library, graveyard, exile, sideboard, hand, life, player, table, lobby, viewer_card), scope (table or lobby), asks (none, number, text, stats, target, token), action (a template of a beryl_table::Action in its JSON form with placeholders "$objects", "$seat", "$number", "$text", "$target"; or client with a name for commands that are interface-only such as "select all" and "open command list"), key ({mac, other} or absent), menu (absent, or {group, order, submenu?} saying where the context menu shows it), group (the heading in the command list), assist (absent, or the assist that must be on).

Transcribe every row of every table in the appendix whose last column is not "Not carried over". The appendix's "In Beryl" column says whether a row is in the menu ("Menu"), key only ("Key") or command list only ("List"). Keys are in its key column, written for macOS: Cmd becomes Ctrl and Option becomes Alt in other. Apply the doc's 'Keyboard shortcuts' collision table (Cmd+Space is not bound; Space and Tab advance the phase; Cmd+Z is undo; Cmd+Shift+B is the bug report at a table). The first rows per applies_to follow the doc's "First rows" table.

Then:

  • ui/src/table/commands.ts: import the JSON, export its type and commandsFor(appliesTo, context); keep it pure.
  • A Rust test in rust/crates/beryl_table/tests/commands.rs that reads the file, fills each template's placeholders with sample values and deserializes it as an Action: a template that is not a valid action fails the test.
  • ui tests (npm test): ids unique; within one scope no two commands share a key; every key in the appendix's key column appears; no entry's label mentions chat, spectators or judges.

Run just test-rust -p beryl_table and cd ui && npm run typecheck && npm test.

Acceptance criteria

data/table-commands.json has an entry for every appendix row not marked 'Not carried over', with keys, menu placement and action templates; the Rust test proves every template is a valid Action; the uniqueness and coverage tests pass; data/AGENTS.md describes the file.

Handoff: data/table-commands.json is the source for 209 commands. The inventory's gesture-only and automatic rows remain covered by their own interaction code. ui/src/table/commands.ts exports commands, commandsFor, and the types. Each command has one canonical key and optional key_aliases, which behave as defaults for that same command (Space and Tab; + and = where documented; F11/F12 and their punctuation alternatives). also_applies_to carries per-target menu placement without duplicating a keyed command. The UI supplies when conditions and contextual placeholders. Undo with an explicit draw entry is allowed for the drawing seat and uses existing history conflict checks. Cmd+Shift+Y will need the host to choose the hidden library prefix matching name/type and hit count in the later dispatcher, noted on by-bmdk.3.22. Node and Rust tests passed, including the 263-test UI suite.
