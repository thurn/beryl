Close reason

Landed solo table click actions and feedback on staging. Nine live headless checks passed across the desktop and phone boards.

Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'Interaction' (opening), 'Click', 'Hover', 'Responsiveness', 'What stays the same as engine games'.

Build the screen a manual table is played on, and the click.

  • ui/src/screens/Table.tsx: mounts the stage exactly as ui/src/screens/Game.tsx does (StageBoard, or PhoneStageBoard on a phone), fed by onGameUpdate, with no engine prompt bar. Read Game.tsx and ui/src/stage/StageBoard.tsx first and share their code by extracting what both need; do not copy it.
  • A way in for now: a "Solo table" button on ui/src/screens/StartScreen.tsx that calls deckImport with the WU Control list (docs/sample-decks/, read through a new command or bundled as test data only if no command can read it; say which on the bead) then tableSolo. The lobby replaces this later.
  • ui/src/table/client.ts: class TableClient. It calls stage.pointer.listen and sets stage.pointer.holdable (see how ui/src/stage/prompt.ts:216 does it; the two clients are never active at once). It holds the selection (empty for now), the last view, and a registry: onClick(kind, handler), onSecondary, onDrop, onAim, onSweep, onKey, so each later interaction lives in its own file. It classifies what a stage node is (permanent, their_permanent, hand_card, stack_entry, library, graveyard, exile, life, counter, step, viewer_card) from the view and the node's name (ui/src/stage/layout.ts, Name). send(action) calls tableAct. Send a generated TableAction. Resolve each stage subject through the current TableView.objectActions and copy its reference and expected zone into the action or target. If a subject has no entry, it is unavailable for object actions. Look up a marker by its ability subject, even when its source and text match another marker. Capture each reference from the view that supplies the gesture target. If a held gesture outlives a view, keep its captured references or cancel it. Clear a stored selection when a slot is replaced so it cannot silently pick the next occupant.
  • ui/src/table/click.ts: the doc's Click table, each row one handler: a permanent taps or untaps; a card in hand is move to "play"; a stack entry is move to "resolve"; a library draws; a graveyard or exile pile opens its viewer (the existing ZoneViewer in ui/src/game/Piles.tsx); a card in a viewer plays; a mana symbol or counter adds one and a right-click removes one. Shift held plays face down to the battlefield. Life total and step clicks are later beads.
  • A refused action shakes the card: use the stage's existing refusal motion (ui/src/stage/Refusal.tsx). Nothing else changes.
  • The pressed state shows at once (the stage's existing press feedback); the effect arrives with the update.
  • Hover shows the existing enlarged preview; a card the viewer does not know shows none.
  • ui/scripts/table.mjs: a helper for headless checks: starts beryl_cli serve, opens the page with ?live=, starts a solo table with a given decklist and action list, returns the Playwright page. Use tools/src/beryl_tools/shots.py::ui_live for the loopback launch and URL, and ui/scripts/kept-harness.mjs::check for a fresh browser context, fake clock, title filtering, page errors and per-check timing. The current harness always inserts ?fixture=; give it a route override for live tables and keep the fixture default. Start one server per test run and close it on exit. Each check must start a fresh table.

Checks (ui/scripts/kept-table-click.mjs): each row of the Click table once; a refused click shakes and changes nothing; no preview on an unknown card. Add no-equivalent entries to data/ui-conventions.json: "Manual table: a click acts". Run cd ui && npm run typecheck && npm test and just ui-test for the new checks.

Acceptance criteria

A solo table opens from the start screen and is drawn by the stage; TableClient is the pointer client with a registry later beads use; every Click row in this bead's list works and has a headless check; refusals shake; table.mjs exists.

TableScreen has its own stage and feed, subscribes before reading tableCurrent, and attaches TableClient.gestures through useSurface. Put gesture handlers in ui/src/table and register them when the client is constructed. TableClient.card returns the subject’s captured TableObjectAction with reference and zone.
