Browser lanes compile beryl_cli a second time

  • Close reason
  • Description
  • Changelog

Close reason

Fixed by 61448988 (perf: checks' beryl_cli shares the tests step's build). The script, fixture and spec builds now use paths.CLI_BUILD (--profile test over BUILD_SCOPE with --lib --bin beryl_cli), and no feature is turned on only by a dev-dependency (coverage keyed on debug_assertions, beryl_table's testing feature removed, getrandom and crossbeam-utils features pinned in normal deps; guarded by tools/tests/test_cli_build.py). After a beryl_kernel + beryl_table edit and the test build, the CLI build only links the binary (2 s), against 10-68 crates and 14-45 s before.

Description

Symptom

In the fast check, the shots and ui-test lanes finish at the same moment as rust:clippy while using 10-16 CPU-seconds of 150-319 wall seconds (runs.jsonl, commits 7b19e55d, cefc376a, c7b662f6 on 2026-11-14). They record their fixtures with cargo run --package beryl_cli (record_fixtures in tools/src/beryl_tools/shots.py), in the same target directory as the rust lane, so they wait on cargo's build-directory lock while clippy or the test build holds it.

Why it costs a whole compile

-p beryl_cli resolves features over that one package, so beryl_rules is built without coverage (which beryl_cards' and beryl_search' dependencies turn on in the workspace build; see BUILD_SCOPE in rust_tests.py). After a beryl_kernel edit, cargo build -p beryl_cli rebuilt kernel, rules, engine, scenario, cards, search, session and the CLI one after another: 17-39 s wall in a warm worktree. That is a third compile of the chain, beside clippy's check build and the tests step's test-profile build.

Work

Give the fixture recording a binary the rust lane already builds, or one built with the same features. Options: build it with the tests step's scope and profile (cargo build --profile test --workspace --exclude beryl_link_iroh --all-targets, whose artifacts cargo test --no-run shares) and run target/debug/beryl_cli; or have the browser lanes wait for the rust lane's test build when both run. Check that fixture recordings are unchanged (coverage only records which abilities a game used). Measure the fast check's browser lanes after a kernel edit before and after.

Done

After a beryl_kernel change, the browser lanes no longer wait on a separate beryl_cli build.
