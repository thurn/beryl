Close reason

Build and expose the generated protocol wire hash, with tested support for additional definitions.

Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Builds must match', read with the epic's decision that builds match by a hash of the wire types, not the commit.

Two builds may share a table when the guest can parse what the host sends. That is exactly the generated protocol file plus the table's own message types.

  • In rust/crates/beryl_session, expose pub const WIRE_HASH: &str: a hex hash of the bytes of ui/src/generated/protocol.ts. Compute it in the crate's build.rs (create one if absent; emit cargo:rerun-if-changed for that file) with a small hand-written FNV-1a 64 or by std::hash::DefaultHasher if its output is stable across builds; do not add a dependency. Phone builds compile this crate too, so read the file by a path relative to CARGO_MANIFEST_DIR.
  • Add wire: String to AppInfo in src/ipc.rs and fill it where AppInfo is built (rust/crates/beryl_app/src/lib.rs, near bugs::set_build_commit). Regenerate the TypeScript (epic, Rules, 6).
  • The table's own types (beryl_table::Action and the lobby types) are added to the hash by a later bead when beryl_table_session exists; leave a function pub fn wire_hash(extra: &[&str]) -> String that mixes extra strings in, and use it.

Tests: the constant is 16 hex characters; changing the input bytes changes wire_hash. Run just test-rust -p beryl_session.

Acceptance criteria

WIRE_HASH is computed at build time from protocol.ts with no new dependency, is carried in AppInfo, and wire_hash(extra) is tested.

Handoff: beryl_session exposes WIRE_HASH and wire_hash(extra). build.rs hashes the checked-in protocol.ts with 64-bit FNV-1a. The helper continues that hash with each extra UTF-8 definition prefixed by its byte length as a little-endian u64, preserving list boundaries across platforms. Native and headless app_info use wire_hash(&[]). The table-session bead can pass its action and lobby definitions to the same helper. The current TypeScript export test lives under --test session, so I used that target to regenerate the binding. Session tests, UI typecheck and tests, and a loopback app_info request checked against an independent hash all passed.
