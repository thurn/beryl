Close reason

iOS shell: just mobile-setup (idempotent), just ios-smoke passes (cold sim build 114 s, warm 15-26 s, smoke ~20 s warm, +9 s from a shut-down sim; debug sim app 120 MB), card art loads in the simulator, just ios-device --no-sign builds the release ipa (131 s, 13.4 MB); signed build needs the user's one-time Xcode account login; just smoke, test-rust, clippy (macOS, ios, ios-sim) pass

Description

Make beryl_app build and run as an iOS app in the iOS Simulator, with the existing UI, through Tauri 2's iOS target. Read the run epic's Decisions and Code map first.

What to do

  • Toolchain: add just mobile-setup (Python in tools/src/beryl_tools/, e.g. a new mobile.py wired into cli.py; standard library) that idempotently installs what iOS needs: Rust targets aarch64-apple-ios and aarch64-apple-ios-sim (sim is already installed), xcodegen/cocoapods via Homebrew if Tauri's iOS init needs them. Xcode 26.6 and iOS 26.x simulator runtimes are installed. The Android half of this recipe comes in the Android bead; structure it so that bead adds a section.
  • cargo tauri ios init equivalent through the UI's @tauri-apps/cli (ui/package.json has "tauri": "tauri"; Tauri config is rust/crates/beryl_app/tauri.conf.json, so check how tools/src/beryl_tools/app.py invokes the CLI for desktop and mirror that). Commit the generated gen/apple project (check .gitignore and Tauri's own gitignore advice; don't commit build output).
  • Cargo.toml: crate-type gains staticlib (and cdylib for Android later); lib.rs's run() gets #[cfg_attr(mobile, tauri::mobile_entry_point)].
  • Gate desktop-only code: snapshot.rs's macOS/Windows capture (iOS returns an error for now; the bug-report bead implements iOS capture), app.set_activation_policy, the window's show()/hidden-window logic, and anything reading ~/Library. beryl_session::bugs::dir() hard-codes ~/Library/Application Support/...: on mobile it must come from Tauri's app_data_dir() (e.g. set once at setup through a setter in bugs.rs, keeping desktop's path unchanged). Check journal and art.rs cache paths use Tauri's path API (they do: app_log_dir, app_cache_dir).
  • ureq uses native-tls; that works on iOS but check it links. Card art must load in the simulator (Scryfall download into the app cache).
  • Portrait only: iPhone orientation in Info.plist (via tauri.conf.json's iOS section or the generated project). The webview must respect safe areas (viewport-fit=cover in ui/index.html so env(safe-area-inset-*) works) without breaking desktop.
  • Bundle identifier ca.thurn.beryl; app icon from the existing icons/ (Tauri's icon command generates iOS/Android sets from one source image).
  • Recipes in justfile (group app): just ios builds a debug simulator app, boots a simulator (pick an iPhone 17/16 class device, create one with xcrun simctl create if none exists), installs and launches it. just ios-smoke: same headless (no Simulator.app window; simctl works without it), launching with SIMCTL_CHILD_BERYL_SMOKE=<seconds> so lib.rs's smoke mode applies, and passing once the UI reports ready (read the app's stdout via simctl launch --console-pty or the journal in the app container from xcrun simctl get_app_container booted ca.thurn.beryl data). Smoke mode currently also requires a window snapshot PNG; on mobile skip that half until the bug-report bead adds capture (leave a clear TODO-free branch: cfg(mobile) passes on ui-ready alone). just ios-device: signs with the identity in the epic (team FYHM4Q335L, automatic provisioning, -allowProvisioningUpdates) and installs to a paired device via xcrun devicectl; build it and check it builds/signs as far as possible WITHOUT installing to the user's phone (epic Decision 3). If signing needs an Xcode account login an agent can't do, make the recipe print what the user must do once and move on.
  • Desktop must be unchanged: just smoke and just test-rust still pass; clippy pedantic clean on the macOS target.

Notes

  • Frontend for device builds is ui/dist (frontendDist); beforeBuildCommand is npm run build. Dev-server mode on device isn't needed.
  • The CSP in tauri.conf.json allows ipc: and http://ipc.localhost and beryl-art:/http://beryl-art.localhost; on iOS custom schemes are served as beryl-art://localhost. Check ipc.ts's artSchemeUrl produces URLs that work on iOS (and later Android, which uses http://beryl-art.localhost). The audio uses the art scheme too (audioAvailable).
  • Record in your close reason the exact commands, build times (cold and warm), and app size.
  • Don't add Markdown files. Update AGENTS.md's "Testing your work" briefly with the new recipes (one line each).

Handoff: iOS shell on staging (417aef13, aaac65d4).

  • rust/crates/beryl_app: crate-type += staticlib; run() has cfg_attr(mobile, mobile_entry_point); setup calls bugs::set_dir(app_data_dir/bugs) on mobile (new setter in beryl_session/src/bugs.rs; desktop path unchanged). ui_ready on mobile journals 'ui ready' and std::process::exit(0): tao PANICS on app.exit on iOS, and Tauri's iOS entry point redirects stdout to os_log, so simctl's console never sees println. snapshot.rs's non-macOS/Windows stub already errors on iOS (clippy allow added).
  • gen/apple is committed (.gitignore now ignores only gen/schemas). project.yml and project.pbxproj were hand-patched so the 'Build Rust Code' phase cd's to ui/ (Tauri assumed package.json beside gen/apple) and defaults TAURI_APP_PATH; portrait-only orientation in project.yml + Info.plist. If you rerun 'tauri ios init' or xcodegen, keep those patches (xcodegen also picks up junk TEMP groups from a built Externals/: patch pbxproj by hand instead). Andoid bead: Tauri's android init will likely need the same cd-to-ui fix in its gradle task.
  • tools/src/beryl_tools/mobile.py: mobile-setup (rustup targets FROM rust/ so the pinned 1.98.1 toolchain gets them; brew cocoapods/xcodegen; xcodebuild -downloadPlatform iOS when xcodebuild -showdestinations lists no simulator: Xcode 26.6 refused the installed 26.5 runtime 23F73 until 23F77 was downloaded, ~8.5 GB). ios / ios-smoke use a dedicated 'Beryl iPhone' simulator (iPhone 17); ios-smoke reads the journal in the app container for the launch's pid. ios-device: signed release build + devicectl install; refuses install for agents; --no-sign builds unsigned.
  • ui: viewport-fit=cover (insets measured 62/0/34/0 on iPhone 17); .bug-button offset by env(safe-area-inset-*).
  • Driving the sim unattended: the iOS Simulator MCP tool needs a user grant nobody can give in an Enact run. What works: brew install ios-webkit-debug-proxy; ios_webkit_debug_proxy -s unix:<path of com.apple.webinspectord_sim.socket from 'lsof -U | grep webinspectord_sim'> -c null:9221,:9222-9322; then a WebSocket to ws://localhost:9222/devtools/page/1, wait for Target.targetCreated, send Runtime.evaluate wrapped in Target.sendMessageToTarget (debug builds are inspectable). Screenshots: xcrun simctl io <udid> screenshot.
  • Signing: no Xcode account is logged in (only profile on disk is another team's), so signed builds fail with 'No Accounts'; the recipe prints the one-time steps for the user.
