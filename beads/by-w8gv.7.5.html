Description

Milestone 4 of Project 50k (plan K4, epic by-w8gv.7). The last affected side of the Effects store: a set of objects locked in as the effect begins (CR 611.2c: "the set of objects it affects is determined when that continuous effect begins. After that point, the set won't change."). Today "creatures you control get +1/+1 until end of turn" would be one queue entry for each creature.

Read first

  • docs/project-50k.md: decisions K4, K6, K11, and "State" and "Kernel rules" under Target architecture.
  • rust/crates/beryl_kernel/src/lib.rs: the kernel's contract. Its "Stores" section (written by by-w8gv.7.2) is the design this bead follows: kinds, shapes, capacities and byte allotments, expiry, indexing, capability bits, and what a store implements once. The same numbers are in a comment on by-w8gv.7.2, and enact brief shows that bead's handoff. Where the code proves the contract wrong, change its text in the same push and say so on the bead.
  • rust/crates/beryl_kernel/src/legacy.rs: the table of what M4 deletes. Delete each Legacy method this bead replaces; the struct itself goes in by-w8gv.7.10.

Need not read: cast.rs, mana.rs, the Memos, Trackers and counters code, beryl_session, ui/.

Scope

  1. The set side as the contract shapes it. A set is a 32-byte bitboard in Small, so the contract keeps sets in their own small table named by index, or caps how many effects affect one: build what it says, within its byte allotment.
  2. Run::modify (beryl_engine/src/interpret/run.rs) starts one effect for the set it locked in, with one timestamp (CR 613.7), where it now calls ctx.add_effect once for each permanent. A set of one object may stay an object-side entry if that is what keeps the count.
  3. The layers (beryl_engine/src/layers.rs recompute) apply a set's effect to each member on the battlefield.
  4. A member that leaves its zone is a new object (CR 400.7) and is no longer affected; the others still are. An effect whose set is empty ends. The zone move pays for this only when a set is in use.
  5. Relayout: a set's members keep their places from Small to Large; a set table that does not fit the target is a Misfit (fit.rs).

Gotchas

  • No card of the 47 modifies more than one object today (Jace, Vryn's Prodigy's -2/-0 and The Wandering Emperor's effect each affect one target), so parity cannot show a mistake here: the tests are this bead's. Write them through the engine (an ability that affects two permanents, one of which then leaves) and in the kernel (expiry, relayout, a full table returning Full).
  • Timestamps: every object-side effect takes the next timestamp as before, so existing games keep theirs.

Parity and checks

No behavior changes: no rules fix, no new card, no new mechanic (K14). A rules bug you do find and fix gets a docs/bugs.md entry (AGENTS.md).

Work the card-names and file-length allowlists down as files are touched (data/card-names-allowlist.json, data/file-length-allowlist.json: a count only falls; a new file is under 800 lines). cast.rs (1,795), effect.rs (1,216), mana.rs (1,586) and engine.rs (830) of beryl_engine are on the file-length list: do not grow them. beryl_kernel/src/relayout.rs is at 730 of 800 lines, so a store implements Relayout in its own file. by-w8gv.19.8 may split those engine files while you work: enact push rebases, you fix the conflict.

Measurements and decisions (by-w8gv.7.5), base staging 6b253808.

COUNT (just count-gate, rollout_counts rollouts subject, as .2 to .4 measured; not the full just bench-count), same VM, back to back:

  • before: 396,070,902
  • after: 396,362,463 (+291,561, +0.07%; -0.64% against the bar of 398,897,988, inside the 1% tolerance, so the bar stays; no bump)
  • By profile (callgrind_annotate, exclusive, base against after): layers::recompute +265k with layers::apply -43k (the loop over resolved effects now matches on the affected side, and the compiler moved part of apply into it: about 7 instructions a recompute); State::expire +34k (the store's end tests each entry for a set and trims the table); State::start_effect is its own symbol now, +31k, with its callers lighter by about half that; the rest is drift under 50k a function. memcpy +1.5k: the 136 bytes are not what costs.
  • Tried and rejected: the set's arm of the layers' loop out of line (#[cold]) counted 397,223,204, worse by 0.2%, so the arm stays inline.
  • No card of the WU mirror affects two permanents at once, so the set path itself never runs in the benchmark: this is the cost of having it.

SIZE: size_of::<State<Small>>() 19,832 -> 19,968 (+136; allotment +136). Effects<Small> is 1,688; an entry is still 24 bytes and Affects 4.

DECISIONS, with the contract's text changed to match (beryl_kernel/src/lib.rs, 'Stores', 'Affected sides and payloads'):

  1. Affects::Set(LockedIn) names a place in a table of sets inside Effects (L::Queue<Bitboard, SETS = 4>; a Vec in Large). LockedIn's field is private: only the store makes one. An empty set is a free place and the table ends at its last set in use, so a store with no set live equals an empty one.
  2. State::start_effect_on_set(source, members, LayerChange, duration) is the one way to lock a set in. Two members or more: one entry, one timestamp, one place. One member: an entry on that object through start_effect (the same effect; Jace and The Wandering Emperor keep their object entries and their timestamps, and the four places stay for real sets). No member: nothing begins and no timestamp is taken, as before.
  3. A set is affected by a layer change alone (the store's invariant), as a player is by a rule change alone: the mutator takes a LayerChange, so move_replacements, cost_increase, cast_permissions, told_apart_by_effects and rule_applies need not search sets. State::start_effect panics on Affects::Set: an effect cannot be started on another effect's set.
  4. A set holds slots, not incarnations. A member leaves its set in Store::forget, where everything stored about an object ends, behind the keyed-slots bit test: keys() includes the sets' members, so the zone move pays only when a keyed object moves. An effect whose set is empty ends in the same pass (Effects::end), as does one whose duration ended, and its place is freed.
  5. Hash: the entries, then the members of each set an entry names. A state with no set hashes as before: corpus_never_changes and rollouts_never_change hold unchanged, and the frozen save corpus replays.
  6. Invariants (Store::check): a set entry names a set with a member, is a layer change, shares its set with no other entry, and every member is on the battlefield; the sets in use are exactly those named, and the table is trimmed.
  7. A checkpoint's lingering words for an effect on a set: 'an effect of <card> on <n> permanents lasting <duration>'.
  8. Relayout: a set keeps its place in the table and its members their places (relayout::bits); more places than the target's table is Misfit::ListTooLong 'the locked-in sets'. A Large table with holes past Small's four places does not fit though fewer than five sets are live: not compacted, since entries name places.
  9. Files: effects.rs would have passed 800 lines, so the Store and Relayout implementations moved to effects/store.rs and the sets are effects/sets.rs. Engine: add_effect, gain_control and the new EffectCtx::add_effect_on_set are effect/continuous.rs (effect.rs 1170 -> 1126 on the file-length list); the layers' loop over resolved effects is layers::resolved_effects (recompute was past clippy's 100 lines).
  10. No Legacy method is replaced by this bead; legacy.rs is untouched.
  11. Not built: Observation has no read of a set's members (no view reads effects yet); State::locked_in is public.

Handoff: kernel: beryl_kernel/src/effects/sets.rs (new: LockedIn, SETS, the Sets table, State::start_effect_on_set, State::locked_in), effects/store.rs (new: Effects' Store and Relayout implementations, moved from effects.rs, with the set invariants and Store::forget removing a member), effects.rs (Affects::Set, Effects::sets, Hash, Effects::end ends an entry whose set is empty and frees its place), store.rs and lib.rs ('Stores': 'Affected sides and payloads', the shapes and allotments tables). Engine: effect/continuous.rs (new: add_effect and gain_control moved from effect.rs, and EffectCtx::add_effect_on_set), interpret/run.rs (Run::modify starts one effect), layers.rs (resolved_effects, split from recompute, applies a set's effect to each member on the battlefield), rule_change.rs (a Set arm). Tests: beryl_kernel/src/effects/tests.rs (four on sets: duration and last member, one or no member, Small to Large and back, a full table), beryl_engine/src/tests/effects.rs (two through a resolving ability: one effect on those that were there, a creature that leaves and returns or arrives late is not affected, the end of turn ends it; an indefinite one ends with its last member). Gotchas: (1) Affects has a third variant, so a match on it needs a Set arm; as_object() is None for a set. (2) A set is a layer change alone: a new payload that should affect several objects must teach its query to search the sets, and change the invariant in effects/store.rs. (3) State::start_effect panics on Affects::Set. (4) A new store's keys() must stay in store_keys(); Effects::keys() now includes the sets' members. (5) The layers' loop is sensitive to shape on the count: the set arm out of line (#[cold]) cost 0.2% more than inline. A reviewer should check: Effects::end and Store::forget in effects/store.rs and effects.rs (an entry on a set ends when keep refuses it or its set is empty, and its place is freed; the table is trimmed); the Hash of Effects (members hashed per set entry, nothing for a store with no set); that no reader of Affects elsewhere (beryl_search/src/mcts/tree.rs compares only effects that are no layer change) needs a set's members.
