Description

Read the epic's contract first; this bead builds against it. Doc: docs/beryl-3d.md, 'Migration and compatibility' and 'The agent interface'.

Today just b3d compare only produces two pictures side by side. Nothing records what each client drew as data, so no tool can say which element differs or by how much.

Change: add just b3d match snapshot <target>, which writes the contract's snapshot directory.

  • Web side. Reuse compare.py's export and shoot steps: b3d export --only, the fixture under shots.RECORDED, and the page ?fixture=<name>&at=<n>#/game in WebKit at the target's size and scale. Then evaluate a dump script in the page. Put it in tools/src/beryl_tools/beryl3d/match/dump.mjs, run with node from ui/ so that Playwright resolves. The script walks the DOM and writes the contract's element records: the role from the ARIA role or from data/beryl3d/match/roles.json (a CSS selector to b3d role table this bead creates), the name from the accessible name, object from data-card and the other data-* ids the stage sets (ui/src/stage/dom.ts), the box from getBoundingClientRect, getComputedStyle normalized for the contract's properties, and text lines from Range rects. No change under ui/.
  • Mid-animation moments. Install Playwright's page.clock before the page loads and advance it to the moment's time, so a --at 1500ms moment shows the same animation progress on both sides. compare.py currently shoots only the view at rest.
  • Beryl 3D side. Add a --json output to b3d tree (rust/beryl3d/crates/beryl_inspect/src/cli/view.rs, beryl_scene/src/agent/tree.rs) that emits the same records from the resolved elements and their Style, with style in CSS names. Write b3d.png with b3d-render png at the same scale.
  • Same inputs. Before shooting, check that the bundled TrueType fonts in rust/beryl3d/crates/beryl_scene/fonts are the same faces and versions as the web's WOFF2 fonts (compare name tables), and that both sides use the same scan cache. Print a warning line in report.txt for anything that differs.

Files: tools/src/beryl_tools/beryl3d/compare.py, cli.py, tools/src/beryl_tools/shots.py, ui/scripts/shots.mjs (read it, don't edit it), ui/src/ipc.ts (fixtureTransport), rust/beryl3d/crates/beryl_inspect/src/cli/, beryl_scene/src/agent/tree.rs, beryl_scene/src/element/style.rs, beryl_scene/src/tokens.rs.

Handoff: just b3d match snapshot <target> --at <moment> is on staging (63b68aee8). It writes web.png, web.json, b3d.png, b3d.json and report.txt to $BERYL_CACHE/b3d/match/<slug>/. joined.json is left to the matcher bead.

Verified: desktop and phone, at rest and mid-animation (opening-play prompt:1 at 1600x900@2 and 393x759; verbs-zones 1500ms at both sizes). Both records files pass records.faults. A second run reuses the snapshot in 0.4 s. The fonts check runs, and the three bundled faces match fontsource's WOFF2 name tables (same family and version).

Where things are:

  • Python: tools/src/beryl_tools/beryl3d/match/. __init__.py holds the match command and its SUBCOMMANDS registry; a new subcommand is a Command added there. target.py parses targets (test names with @scale; the layout follows the window via space.json flat.phone_under) and builds the slug. snapshot.ensure(target, fresh, art) is the entry point later subcommands call. records.faults checks the contract. fonts.py and fonts.mjs read name tables (Node, because WOFF2 needs Brotli). dump.mjs is the web side.
  • Rust: b3d tree --records (beryl_inspect/src/cli/records.rs). I used a new switch rather than --json because tree --json already prints tree lines. Frame::looking, set through Page::set_looking and Client::set_looking, records an ElementLook for each flat-layer element (panel tint, border, radius, ink, type), and each TextLine gets its baseline and, while looking, its words. text::Block::lines is now Vec<Line> (box, byte range, baseline), and text::shaped_words rebuilds the shaped words only while looking. Page::view_given_at gives the time the latest view arrived. The gate's handle_allocations still pass with no limit raised.
  • Records: web object is the numeric data-stage (the card's slot in the view), and Beryl 3D's is the card element id mod REVEALED_FACE, so the two match. Opacity is cumulative on both sides. No panel is written as transparent [0,0,0,0]. What Style can't say is written as "none" on the Beryl 3D side.

Decisions and limits, for reviewers:

  • Card scans: by default neither side draws scans. The web draws its placeholders, and Beryl 3D runs with an empty BERYL3D_SCANS dir. --art routes cards/backs.scryfall.io to ~/Library/Caches/ca.thurn.beryl/art in Playwright, so both sides read the same cache. The report notes this.
  • Mid-animation: the web clock runs t_ms - view_given_ms after the stage and fixture exist. The page's loading frames make the start approximate. In verbs-zones at 1500ms the web's card was a little further along than Beryl 3D's. CSS animations are finished, not stopped at the moment.
  • The web keeps many more elements (350 against 49) because it records every painted or labelled element. The matcher must expect unmatched web elements.
  • Observed, not fixed: the web computes font-family "Times New Roman" for --font-serif (ui/src/design/tokens.css), where Beryl 3D uses Crimson Pro. The style diff will report it.
  • Pre-existing failures, not caused by this change: beryl_scene inspect::a_graveyard_of_thirty… and beryl_inspect differential::the_check_times_find_every_planted_fault fail on staging (open bead by-q44s.9.54). The fast check deferred cargo-test, so slow CI's cargo-test will show them until that bead lands.
