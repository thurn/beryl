Description

What is wrong today

layers::counters_matter answers one question by hand: whether a change in counters can change a layer result. A characteristic-defining ability can read anything: Tarmogoyf's power is the number of card types among cards in all graveyards, so a card entering a graveyard must mark the results stale, but only while a Tarmogoyf is on the battlefield.

What to build

Plan: Designs 2, "What makes the cache stale".

  • Each ability whose layer effect reads something no layer writes declares it, as a set of inputs: counters of a kind on its own permanent, the contents of graveyards, a hand's size, a life total. GameTable holds the set for each card's face.
  • The recompute folds the inputs of the permanents on the battlefield as it folds the listeners, and stores the set. A mutator marks the results stale only when its input is in the set: the zone move for a graveyard, the counter mutators (replacing counters_matter's argument), the life mutators.
  • A characteristic-defining ability may define power and toughness together (Modification::SetPt with two amounts), and an amount may be the number of card types among cards (Amount::CardTypesAmong).

Card

Tarmogoyf: "Tarmogoyf's power is equal to the number of card types among cards in all graveyards and its toughness is equal to that number plus 1." This bead plays it on the battlefield; reading it in other zones is group 4's.

Scenarios: it grows as a land is put into a graveyard in response to damage; under Dress Down it is 0/1.

Derek Thurn2026-11-14

Decisions: (1) Inputs is a u8 set {COUNTERS, GRAVEYARDS} per face (FaceFacts::inputs), not per counter kind: there are 238 counter kinds, so COUNTERS gates the old per-face scan for which kind, now State::layers_read_counters in the kernel. The counter mutators keep their layered bool argument (many kernel tests call them without a table); the answer now comes from the folded set, and rules' layers::counters_matter is gone. Off-battlefield counters still mark stale, as before, so WU recomputes cannot change. (2) Hand size and life are not inputs: no CDA of the cards reads them; adding a bit is one line when one does. (3) The fold is gated on a new Capability::LayerInputs so games with no such card pay nothing. (4) State::layer_inputs is left out of the state hash (derived from the battlefield's faces), so no frozen pins move. (5) The build parsed printed '1+' as no number; it now reads N+ and *+N as N (CR 208.2). (6) The render diff now treats 'Name's' as the card naming itself, like 'this creature's'; no other card's render result changed. Objects::All in a graveyard with no owner filter renders 'cards in all graveyards'.
