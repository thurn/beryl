Close reason

Web stage plays the sent StepTiming and own_timings; web rules and timing-parity deleted; staging 638f4b122

Description

Read first: docs/beryl-3d.md 'Timing a script' (this bead is change 3). Then ui/src/stage/stage.ts (the timings and effects options of ScriptStage and where they are called), beat.ts (laid, which calls timings for each step), playback.ts, table.ts (sent, which turns a step the session sent into the stage's own), prompt.ts (the seven places that make the stage's own steps), timing.ts, feed.ts and ui/src/ipc.ts. Read tools/src/beryl_tools/motion.py's case_of, which is a second copy of caseOf in Python.

Why. The session now sends each step's timing, proved equal to what the web interface computes. This bead makes the web interface play what it is sent and deletes its own rules, so that the rules exist once, in Rust.

  • Where a sent script enters the stage (playback.ts and table.ts sent), attach each step's StepTiming from script.timing to the stage's step, converting it to the stage's Timing and Effect types: the curve's name to its easing function (keep CURVES for this), each Subject in after and in an effect's on to a name with namedBy.
  • ScriptStage's timings and effects then return what is attached to a sent step. For a step the stage made itself (prompt.ts), they return the entry of the OwnTimings table for that step's shape, with after filled from the arrow's ends where the entry has after_ends. Fetch the table once at startup through stage_timings in ui/src/ipc.ts, before the first view is played.
  • Delete caseOf, timingOf, effectsOf, NOTICES, FINISHED and the verbs, cases, looks and uses tables from timing.ts. Keep CURVES, snap and RELEASE (RELEASE reads the fly verb's values from the data, as now). Delete from tracks.ts whatever only they used, and nothing else: tsc reports what is now unused.
  • tools/src/beryl_tools/motion.py: delete case_of and read each step's case from the timing the capture's recording carries.
  • Delete the timing-parity check: ui/scripts/timings.mjs, beryl_cli step-timings, tools/src/beryl_tools/timing_parity.py, the just recipe, its lane in checks.py and its paragraph in docs/checks.md and ui/AGENTS.md. Its job is done once nothing in TypeScript computes a timing. Move the cases it covered into Rust tests only where beryl_session's tests do not already cover them.
  • ui/AGENTS.md: in 'Source', say that the session sends each step's timing (script.timing, from beryl_session/src/script/timing.rs) and the stage only lays a beat out in time (beat.ts laid).
  • data/AGENTS.md or the intro of data/ui-conventions.json's verbs list, whichever says who reads the verbs' values: say the session reads them.

Before deleting anything, prove the switch changed nothing. With the web stage playing the sent timing but its own rules still present, run a Node script that plays every fixture through ScriptStage twice, once with each source of timing, and compares every step's start and end from stage.follow. They must be identical. Then delete, and do not commit that script.

Run: just ui-typecheck; just ui-unit; just ui-test verb:; just ui-test shape:; just motion; just test-rust -p beryl_session; just smoke.

Acceptance criteria

No TypeScript or Python code chooses a step's case, waits or effects: caseOf, timingOf, effectsOf and motion.py's case_of are gone; every fixture plays with identical step start and end times before and after the switch (the comparison's result is in a comment on this bead); just ui-unit, just ui-test verb:, just ui-test shape:, just motion and just smoke pass; the timing-parity check is deleted.
