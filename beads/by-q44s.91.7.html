Close reason

just b3d match pixels attributes pixel differences to elements, with --only isolation (5f864b449)

Description

Read the epic's contract first; this bead builds against it. Doc: docs/beryl-3d.md, 'Migration and compatibility' and 'The agent interface'.

Once boxes and styles agree, what is left shows only in pixels: a glow drawn too faintly, a missing outline, a panel drawn behind the wrong layer. A difference picture alone doesn't say which element is at fault.

Change:

  • Add just b3d match pixels <target> in b3d-render (beryl_pictures). It computes the per-pixel difference of web.png and b3d.png at scale 2. It masks glyph pixels: the text line boxes from both records, shrunk to their ink. It groups differing pixels (over 8 levels) into regions and attributes each region to the topmost element at that point on each side, using z and boxes from the records and, on the Beryl 3D side, the hit test (beryl_scene/src/agent/hit.rs). It prints elements worst first, by differing pixel count, with a hint when one side drew nothing there. For the top ten it writes crops of web, b3d and the amplified difference, magnified 4 times.
  • Add --only <locator> to snapshot and pixels. It draws a single element subtree alone on both sides. On the web, everything else is hidden with an injected style (visibility: hidden outside the subtree, keeping layout). In Beryl 3D, only that subtree's draws are kept. This separates an element's own error from what lies behind it.

Files: rust/beryl3d/crates/beryl_pictures/src/, beryl_scene/src/agent/hit.rs, tools/src/beryl_tools/beryl3d/match/.

Acceptance criteria

match pixels prints attributed regions and writes crops for desktop and phone targets, and --only isolates one element on both sides.
