Description

just cards becomes the whole card pool, built offline from Scryfall's bulk data into an indexed card store (plan: docs/project-50k.md, Card pool pipeline; K2). First bead of lane:card-store; the Rust reader (next in the lane) and every later M7a bead build on the format you settle here.

Read first: docs/project-50k.md (intro "The card pool", K2, Card pool pipeline, Acceptance "Scale rehearsal"); tools/src/beryl_tools/cards.py (546 lines, all of it); tools/tests/test_cards.py. Need not read: any Rust, the UI.

Today

cards.py reads two decklists (m1_names), finds each card's printing with a Scryfall search at 0.6 s a card (printing, first_of, shows_original_art; pins in data/card-printings.csv), fetches the cards and their tokens from /cards/collection, and writes data/cards.json: 49 cards and 13 tokens, 65 KB, which the UI bundles. At 30,000 cards the searches alone take five hours.

Do

  • Bulk data: https://api.scryfall.com/bulk-data lists the files. Download default_cards (every English printing, about 500 MB) into $BERYL_CACHE/scryfall, reusing it until --refresh or it is a week old. Keep the helper general (a bulk file by its type): just card brief will fetch rulings with it. Scryfall writes one card object per line; read by line rather than loading the file whole. Keep cards.py's User-Agent and Accept headers (Scryfall's API guidelines).
  • The pool: every card in Scryfall's Oracle data except un-set cards, dexterity cards and Alchemy cards. Default rule: a card is in the pool when its Vintage legality is anything but not_legal (that drops un-cards, Alchemy and digital-only cards, tokens, art cards and oversized cards in one test), less the dexterity cards, which a data file under data/ names with the reason. Print the count kept and the count dropped per reason, and put them in your handoff. Tokens and emblems: every one a pool card makes (all_parts; token_parts, engine_name and token_entry already do this for a list).
  • Printings: run the existing rule (first_of, shows_original_art, BASIC_PRINTINGS, TOKEN_PRINTINGS, printed_name) over the bulk file's printings grouped by oracle id, with no searches. data/card-printings.csv stays as the pins it is; do not pin 30,000 cards.
  • The store, under data/: one record per card and per token, findable by card name, by any face's name and by a token's engine name without reading the whole store or an index that grows with it. A card and a token can share a name (Thundertrap Trainer's offspring): keep them apart. Default format: one file of lines sorted by key (<key><tab><json record>, alias lines for face names), which Python, Rust and Node can each binary search by seeking; choose otherwise if you find better, and describe the format in the module's header, since three readers follow it. A record holds what data/cards.json holds per card today plus oracle_id, Scryfall's keywords, and each face's characteristics as CR 109.3 lists them (color indicator and defense included), so M7b can generate printed characteristics from the store alone. No volatile fields (prices, legalities, rankings, image-URL timestamps): a refresh must change only the lines of cards that changed. Image URLs follow from the Scryfall id, the face's side and the version (rust/crates/beryl_app/src/art.rs documents the path), so store what derives them, not three URLs a face.
  • Commit the store if it is under 50 MB (GitHub warns above that), with a name no formatter or lint globs (check just fmt and the repo lane in tools/src/beryl_tools/checks.py). Over 50 MB, keep the whole pool in $BERYL_CACHE and commit the records of implemented cards only, and say so in the handoff.
  • A Python reader module (lookup by name, records for a list of names, iteration) with tests. The tools still on data/cards.json move to it in a later bead; name the module and its functions in your handoff.
  • Until the UI stops importing it (a later bead deletes it), keep writing data/cards.json for the same names from the same data. Regenerated, it must differ from today's file only where Scryfall's data changed; list each difference in the handoff.
  • Tests: replace the recording-based tests with a small pruned sample in the bulk file's shape under tools/tests/fixtures (well under 1 MB); keep every behavior test_cards.py pins today (pins honored, the printing rule, printed names, token names, the card back) and add the pool rule and the store's round trip. No test touches the network.
  • The justfile's cards comment and cards.py's header say what the command now does.

Parity and policy

This is the data track: it edits no engine-track file (nothing under rust/crates/beryl_engine, beryl_kernel, beryl_card or a card file), and nothing here creates a Rust file per card (K2: an unimplemented card is a record in the store). Parity (plan K11) at the push: just check passes; the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds; slow CI's counts lane (just count-gate, bar 405,276,238 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. Nothing waits on the user (K31): proceed on a default and file a non-blocking bead labelled human, parented to by-w8gv.18, where his judgement is wanted. Record decisions and deviations as comments on this bead.

Acceptance criteria

just cards builds the store offline from Scryfall's bulk file with no per-card search; every in-scope card and every token a pool card makes has a record, with the counts kept and dropped per reason in the handoff; the store has no volatile fields (a second run on the same bulk file changes nothing); a Python reader looks a record up by card, face or token name without reading the whole store, with tests; data/cards.json regenerates from the same data, differing from today's only where Scryfall's data changed, each difference listed; no test touches the network; just check passes.

Decisions: (1) Store format as the bead's default: data/card-store.tsv, sorted <key>\t<json> lines, keys card:<name> and token:<engine name> (token keys may repeat: one line per linked token printing, e.g. 44 Treasure Token records), alias lines {alias, scryfall_id} for face names and, for printed-name printings, the oracle names; an alias never shadows a card key (20 do, all 'prepare' back faces named like old cards, e.g. Ancestral Recall). (2) Scryfall's bulk API now serves gzipped JSON Lines (jsonl_download_uri, 81 MB); cached as $BERYL_CACHE/scryfall/<type>.jsonl.gz and read compressed, line by line. (3) Card records list the tokens they make as {name, scryfall_id}; token records carry no made_by (it would rewrite Treasure's line whenever any card gains a Treasure). (4) Tokens are the printings the shown printing links (all_parts, TOKEN_PRINTINGS), not deduped by oracle id, which keeps data/cards.json identical. Checked: no pool card lacks a token link on its shown printing that another printing has. (5) Pins are read, never written; the bulk rule reproduces 141 of 142 pins (the other is the om1 printed-name pin). (6) data/cards.json is written from the raw bulk printings in the same pass, not from the store, because its image URLs keep Scryfall's ?timestamp, which the store drops as volatile. (7) Printed names apply only to English printings. (8) Un-set cards legal in Vintage (103: Unfinity 98, Unstable 5) stay in the pool by the default rule; filed human bead by-w8gv.18.10.
