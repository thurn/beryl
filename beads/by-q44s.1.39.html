Recordings pack on staging at 96e66622: recordings::messages/list, shared pack in $BERYL_CACHE/b3d, 9.1 MB, 23 s to build

Description

Read first: docs/beryl-3d.md 'Test speed' ('Recordings') and decision C14. Then rust/crates/beryl_cli/src/fixture.rs, specs/ and script_check.rs (how every card's spec moments are recorded from both seats today, about 14 ms each in a debug build), and inputs in tools/src/beryl_tools/script_checks.py (the crates a recording depends on).

Recording means playing the engine, which costs more than any test that reads the result. This bead makes it happen once per state of the sources, for every worktree on the machine.

In rust/beryl3d/crates/beryl_inspect (add the path dependency on beryl_cli and postcard 1.1.3, saying in Cargo.toml that it replaces a hand-written binary format):

  • pack::build() records every fixture in ui/fixtures.json and every card spec moment, from both seats, with beryl_cli's library, and writes them as one file, $BERYL_CACHE/b3d/recordings-<hash>.bin.
  • The hash covers what a recording depends on: the source files of beryl_cli and of every crate it depends on by path, ui/fixtures.json, docs/sample-decks, data/ui-conventions.json and data/card-store.tsv. Hash file contents, not times.
  • Two sessions at once: the builder holds a lock file beside the pack, writes to a temporary name and renames. A second session waits on the lock and then reads the finished file. Keep the newest three packs and delete older ones.
  • recordings::messages(name, seat) -> Arc<[ipc::FixtureMessage]>: on the first call it computes the hash, builds the pack if the file is missing, and maps the file. recordings::list() -> Vec<Listed> gives every name with its length in milliseconds and its number of views, for just b3d list. Nothing else in Beryl 3D may call the recorder.
  • When it builds, it prints one line saying so and how long it took, so that a test run's own time is reported apart from it.

Tests in beryl_inspect/tests: a second call with unchanged sources calls the recorder zero times (count the calls); two processes started together leave one whole file; a changed byte in ui/fixtures.json changes the hash.

Report in a comment, each as the median of five runs with the load beside it: the time to build the pack from nothing, the file's size, and the time to open it and read one recording.

Run: just b3d cargo-test -p beryl_inspect.

Acceptance criteria

Every fixture and card spec moment is in the pack from both seats; a second run with unchanged sources records nothing; two sessions building at once leave one whole file; recordings::messages is the only path to the recorder; the numbers are in a comment.

Derek Thurn2026-11-15

Measurements (2026-11-15, dev build, median of five runs, load 40-50 on 18 cores): building the pack from nothing takes 23.1 s on the clock (runs: 22.8, 21.1, 21.0, 23.1, 33.0 s), with about 64 s of CPU time and a peak of 3.3 GB resident, for 1,532 recordings (about 140 fixtures from one seat each and about 696 card spec moments from two seats each, none failing). The file is 9.1 MB (9,273,147 bytes). Opening it and reading one recording (verbs-zones, 50 messages) takes 0.19 s (0.282, 0.171, 0.169, 0.189, 0.211 s), most of it hashing about 35 MB of sources at opt-level 0.

Deviations: (1) Each recording is kept as deflated JSON (miniz_oxide level 6) inside the postcard index. A message holds serde_json::Value and internally tagged enums, which postcard cannot deserialize, and the raw JSON came to 261 MB (level 1: 16 MB; level 6: 8 MB). (2) The pack format version is part of the hash, so a format change builds a new pack instead of misreading an old one. (3) A fixture is recorded from its own seat only: beryl_cli::fixture::record cannot seat the viewer across the table, and changing it is a main-workspace change. Filed by-q44s.1.47 for it. (4) 'Maps the file' means reading it into memory once: unsafe is denied in beryl_inspect, so there is no mmap. (5) list() gives one Listed per recording and seat; its length comes from playing the recording through the client (Page::moments), so it follows client timing and is not stored in the pack. Today most lengths are 0 to 800 ms because the client has no script clock yet. (6) scene-purity now fails on any Beryl 3D code other than beryl_inspect/src/recorder.rs that names beryl_cli, and on any other crate depending on it.

Handoff: rust/beryl3d/crates/beryl_inspect: pack/mod.rs (ensure: lock, temporary file, rename, prune to KEPT=3; encode/read/messages; cache_dir), pack/sources.rs (sources follows beryl_cli's path dependencies, not dev-dependencies, plus DATA; hash is FNV-1a 64 over path, length and contents, seeded with VERSION), recorder.rs (Cli: fixtures plus every specs::cards() moment from both seats, on all cores), recordings.rs (messages/find/list; parsed recordings cached by index). Spec moments are named <slug>/<moment>, and their messages are the card-records message followed by one game-update per view from specs::trace, with SessionId(1) and no recorded responses. tests/pack.rs uses a stand-in recorder; the two-process test re-runs its own binary with an ignored child test. Card specs complete from the card store (with no card file) are not included, the same as script-check. Stress boards (stress.rs, landed in parallel) are not in the pack.
