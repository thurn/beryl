Description

Read first: docs/beryl-3d.md 'Hosts' ('Text entry', Request::BeginTextEntry, EndTextEntry, Input::Text) and 'Bug reports'; include/beryl3d.h (BerylRequest, beryl3d_text); the Swift host's perform(_:) and the Kotlin host's perform as the touch beads (by-q44s.7.6, by-q44s.7.8) left them; milestone 3's bug report bead and text field widget bead (find them under by-q44s.5: the form from ui/src/components/BugReport.tsx, and the field 'edited in place with parley's editing support'), for which element sends BeginTextEntry and how the form is opened; ui/src/components/BugReport.tsx and ui/src/mobile/bug-report.css for the web interface's description field on a phone.

Why. On a phone the system keyboard, autocorrect, dictation and input methods only work in a native text field. The client asks for one with BeginTextEntry; the host lays a native field over the element's rectangle and sends the whole new text on every change.

Build:

  • iOS, a new file ios/Beryl3D/TextEntry.swift: a UITextView (the description field is several lines; one control serves every field) added over the Metal view at the request's rectangle in points, with a clear background, the system font at 16 points, the request's text, autocorrectionType = .default, and becomeFirstResponder(). Its delegate's textViewDidChange calls beryl3d_text with the whole text. EndTextEntry resigns first responder and removes it. A second BeginTextEntry while one is shown moves and refills the same view. When the keyboard covers the rectangle, the host does nothing: moving the form is the client's work (the phone layout bead's), and the host reports the keyboard's height as a smaller bottom safe-area inset by passing beryl3d_surface again from keyboardWillChangeFrame with bottom = max(safeAreaInsets.bottom, overlap).
  • Android, a new file TextEntry.kt: an EditText added to the activity's content as an overlay (FrameLayout over the SurfaceView; switch the content view to a FrameLayout holding both), positioned at the rectangle converted from points by displayMetrics.density, multi-line, with a transparent background; requestFocus() and InputMethodManager.showSoftInput. A TextWatcher's afterTextChanged calls Native.text with the whole text. EndTextEntry hides the keyboard and removes the field. The keyboard's height reaches the library as a larger bottom inset through the insets listener (WindowInsets.Type.ime() on API 30 and above; adjustResize below, which changes the surface's size instead).
  • The two cases of each host's perform call these. That is the only change to App.swift/Table.swift and MainActivity.kt; if a lifecycle bead edited the same switch first, keep both.

Smoke tests: just b3d ios-smoke --text and just b3d android-smoke --text play a live game with the stand-in agent (BERYL3D_STAND_IN / the standIn extra set to greedy), open the bug report with the input milestone 3's bug report bead binds to it (send that key through each host's debug test hook: add ca.thurn.beryl3d.test.report on iOS and what=report on Android, which call beryl3d_key with that binding), wait until the client has sent BeginTextEntry for the description field (host.log, debug builds, records each request), then type: on iOS the UI test bundle from the iOS touch bead (by-q44s.7.6) gains a test that types Beryl test into the focused text view with typeText; on Android adb shell input text Beryl%stest. The command fails unless the frame log has Text lines and the last one has length 10, host.log records BeginTextEntry, and the app is still running. It then sends Escape through the same hook (.test.escape / what=escape) and requires EndTextEntry in host.log, so the field is removed when the form closes.

Not in this bead: the bug report form itself, its phone layout, or moving it above the keyboard (milestone 3 and the phone layout beads).

Run: just b3d ios-smoke --text; just b3d android-smoke --text; just b3d android-smoke --text --gles; just test-py tools/tests/test_beryl3d_phone.py.
