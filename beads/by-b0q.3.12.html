Derek Thurn2026-11-05

Warden review of 59c1ffd (MCTS):

  • Read mcts.rs, the Observation root/observe change, resolve.rs inline-record fix, CLI/session wiring. UCT is sound: rewards stored per mover, fresh children tried at random, root visits summed in tree order (deterministic regardless of thread finish). next() already settles single-candidate decisions under smart stops (engine.rs forced), so the tree never holds them. The determinized root offering the same decision is covered by games.rs agents_decide_the_same_on_a_redeterminized_state.
  • Fixed (393252b): tests/mcts.rs was the slowest test binary in the Rust suite (8.4 s in CI, ~20 s loaded) because its positions came from early in the game (long debug rollouts). Now late positions per test; dropped a redundant second parallel run (parallel==sequential already pins determinism). The paused-resolution test now selects pauses followed straight by another question; mutation-checked: with the resolve.rs record replay reverted it fails (the old 'first two pauses' selection only caught it by luck; 'last two pauses' did not). Hidden-information test mutation-checked: making the hidden search read the unmasked root fails it. Loaded timings: 0.8 s / 5 s / 1.3 s, was 11 / 19 / 4.5 s.
  • Left alone: a paused root whose body is random before its question (Time Spiral: wheel, then untap lands) is replayed under a reseeded rng by both searches, so the tree's new hands differ from the true ones. The question (tapped lands) is unaffected, so it is only a small strength loss on one card.
  • Not re-measured: the 2 s UI default (machine at load ~80 from parallel sessions).
