Warden review of d96c3e8 (Trinket Mage, Beza, Currency Converter). Checked: all three against Scryfall Oracle text (cards.json) and CR 701.23/701.24, 608.2h, 607.2a, 400.7, 111.10a, 603.2c; the engine additions (search_library, exile_linked/exiled_with_source with forget on slot reuse, Trigger::YouDiscard via every ZoneChange in move_batch_to — kind() is 0 for other moves so the extra match_event is a cheap early return; Enters can't misfire on discards), Treasure sacrifice options at priority and in manual payment, the UI (mana candidates attach to the Treasure's slot), and the XMage divergence (plausible, CR-cited). No rules bugs found. Added (b5ba02e): (1) Rust test a_cleanup_discard_triggers_currency_converter: a cleanup hand-size discard triggers the Converter, priority in cleanup, then another cleanup ends the turn (CR 514.3a); not an oracle scenario since Forge can't script cleanup discards. (2) Scenario 'Currency Converter's ability returns a card after the Converter left' (CR 607.2a: the {T} on the stack still finds the cards after Sink into Stupor bounces the Converter); passes XMage and Forge (6/6 each). Note: Forge lists an ability on the stack as a Sink into Stupor target, so the scenario gives P0 a tapped Jace so the target is a real, scripted choice. Left alone: the solver never spends Treasures (documented design; manual payment only offers one if simple sources pay the rest); Treasure options make every priority a decision under Exact stops for their controller (legal, AI-cost only); Enters arm not narrowed to to==Battlefield (unreachable).
