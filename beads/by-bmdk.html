Description

A manual table for Beryl: a game where the app keeps the cards, zones, counters and life totals and applies no rules, so two people can play any deck against each other the way they would in Cockatrice, over a peer-to-peer connection. The design is docs/manual-multiplayer.md ("the doc") and its appendix docs/manual-multiplayer-cockatrice.md ("the appendix"). Every bead here is written against them. The doc was revised on 2026-11-13 (commit e7b01208) to carry every decision and default listed below, so the doc and the beads agree. If a bead and the doc still disagree on a detail, the bead wins, and the session that notices corrects the doc.

Beads are written to be executed from their description alone. Each names the files to create or change, the helpers to reuse, the tests to write and the command that runs them.

Decisions taken with the user (design interview, 2026-11-13)

  • Scope. The whole doc on the desktop. Touch gets every gesture in the doc's Touch table, built late and checked only by one headless smoke test per gesture group. Engine games over the link (the doc's "Engine games over the same connection") are out of scope.
  • Phone apps. They get the solo table and can join a table as the guest. They cannot host. They are verified only by just ios-smoke and just android-smoke.
  • iroh is in scope, tested offline. No check may touch the internet. The iroh link is tested by two endpoints in one test process with the relay switched off. just table-pair is built for the user and never run by an agent. Nobody in this run tests two machines on different networks: the Archivist's close note says so.
  • Builds match by wire hash, not by commit (replaces T19). The handshake compares WIRE_HASH, a hash of the generated protocol types and the table's message types. Two builds whose wire types are identical may play. The refusal message is unchanged: "Both players need the same version of Beryl."
  • T20 to T24 stand as the doc states them.
  • Review. Full Enact roles: three milestones, a Mason and a Sage audit in a gate epic after each, a Warden per area, one Archivist. Milestones are few and wide on purpose.
  • Models. The run is expected on Codex (Sol 6.1 High for every role, per .enact.toml). Beads still carry tier:opus (contracts others build on, and every review) or tier:sonnet (everything else) so a Claude run works too. Nothing is tier:fable. A bead filed later follows the same policy.

Defaults recorded without asking

  • The stage cutover the doc waits for is done (by-w8gv.21.32, closed 2026-11-12), so the doc's "bound part" does not wait for anything outside this epic.
  • The table's menu is the existing gear at the top right (ui/src/game/Corner.tsx). The doc says "top left"; no such button exists.
  • move has two destinations the host works out from the card store: "play" (a land to the battlefield, anything else to the stack; tapped if its text says it enters tapped) and "resolve" (a permanent to the battlefield, anything else to its owner's graveyard, an ability marker ceases to exist). The doc has the interface decide this; the host deciding keeps it in one place and gives the guest nothing to compute.
  • Every applied action records primitive changes (Change, see Contracts). Undo inverts them and the adapter turns them into animation steps. The doc does not say how either works.
  • The guest is a Rust session behind the same app commands, not a new TypeScript transport. The interface calls table_act and listens to game-update whether the table is local, hosted or joined. The doc's "fourth implementation" is this.
  • Manual-only view data sits in one optional field, PlayerView.table, so engine games are untouched.
  • Typed entry in the number prompt is for the manual table only. Engine prompts keep Arena's two steppers (UI Conventions, "Choosing X").
  • No numbered UI exception is added. New interface goes in data/ui-conventions.json under "No Arena equivalent" or "Not seen in Arena".
  • If iroh's build cost breaks a check budget, it goes behind a cargo feature that the check lanes leave off and release builds turn on (bead "iroh link"). No budget is raised.
  • The design doc is kept and kept current. It already states the decisions here; the Archivist updates it to what shipped. It is not deleted.

Rules for every bead

  1. Follow the root AGENTS.md and the AGENTS.md of the directory you change: work in an Enact worktree, commit with a Conventional Commits subject of at most 60 characters and a body, land with enact push.
  2. Nothing in beryl_kernel, beryl_rules, beryl_engine, beryl_cards, beryl_card, beryl_card_shared or rust/cards/ may be changed or may refer to the manual table. beryl_table and beryl_link must not depend on any of them, nor on beryl_session.
  3. A new crate goes in rust/crates/<name>/ (the workspace picks it up by glob), has [lints] workspace = true, and every dependency in its Cargo.toml has a comment saying what it replaces.
  4. No source file over 800 lines. Split by topic before you reach it.
  5. Card names appear only in tests and test data, never in table, adapter or interface code.
  6. The interface calls Rust only through typed wrappers in ui/src/ipc.ts. A new command is a name constant and a row in the Commands table in rust/crates/beryl_session/src/ipc.rs, a handler in rust/crates/beryl_app/src/lib.rs (handlers![...]), a route in rust/crates/beryl_cli/src/serve.rs so headless checks reach it, and a wrapper in ipc.ts. Regenerate types with BERYL_UPDATE_TS=1 just test-rust -p beryl_session --test session typescript.
  7. Never open a window. Interface work is checked with cd ui && npm run typecheck, npm test and the headless checks named in the bead (just ui-test <title>).
  8. On-screen wording comes from the doc and the appendix exactly. Where they give none, write the label, then cut it to half the words.
  9. A new interface element adds an entry to data/ui-conventions.json (kind no-equivalent or not-seen), then just conventions. Never add a number.
  10. A bug fixed in interface code adds the broken state as a fixture (see Code map, Fixtures).
  11. No step waits for the user. Choose the least surprising default, write it in a comment on your bead (bd comments add), and go on. Work that will not fit is filed as a new bead under the same milestone epic with the same labels policy, never left as a TODO.
  12. The engine game must be unchanged: just test-rust and the ui lane pass, and no existing fixture's recording changes unless the bead says so.

Contracts

These names describe the shipped interfaces. A bead that changes one updates this section when the change lands.

Crates

  • beryl_table owns the manual state, actions, permissions, redaction, change log, undo, saves, deck formats and assists. It depends on beryl_card_store, serde and serde_json. Feature ts adds ts-rs for the action schema. Printed facts and name and token search come from the store.
  • beryl_link owns Link, LinkSender, the memory and loopback TCP transports, the wire envelope, the host and guest loops and the fair host queue. It depends on serde, serde_json, flate2 and parking_lot.
  • beryl_link_iroh implements the internet transport through IrohLink, IrohHost, profile identity and encoded invites. It uses beryl_link, iroh (a separate pinned iroh revision on iOS), tokio, data-encoding, getrandom and tempfile. The app's optional iroh feature enables the adapter's iroh feature. The offline transport suite runs nightly.
  • beryl_protocol owns the shared view and script types, neutral view constructors, IPC, viewer-facing TableAction, script span validation, SessionIds and WIRE_HASH. beryl_session re-exports the shared types and functions for engine callers.
  • beryl_table_session projects the table to views and scripts, owns host prompts and match setup, and provides deck and card search commands. TableSessions holds the current solo, hosted or joined session. TableConnections wires those sessions to invites, settings and saves. Its production dependencies are beryl_card_records, beryl_card_store, beryl_protocol, beryl_table, beryl_link, serde, serde_json, tempfile, url and optionally beryl_link_iroh. A test uses beryl_session to verify the shared ID sequence. Manual token facts and art use the selected printing or the first store printing for a name-only token. Engine token lookup keeps its preference for the printing linked by an implemented card.

Table actions and saves

pub fn apply(table: &mut Table, by: Seat, action: &Action, chance: &mut Chance)
    -> Result<Entry, Refusal>;

For a live table use Log::new(&table) and Log::apply. Standalone apply accepts ordinary actions and batches. The log also handles undo and rewind. Entry records the sequence number, actor, action, primitive changes, undo target, touched state and visibility. Change advances object IDs when needed; the log stages batches and commits their number only on success.

Action::Undo { entry: None } selects the shortcut target. Use Action::Undo { entry: Some(n) } to address a row or a player's own draw. Log::undo_target, Log::last_draw and Log::visible_history supply the viewer-safe controls. Refusal::Invalid { blocking } preserves the blocking entry numbers, and Refusal::INVALID has an empty list. The adapter formats viewer-relative actor labels and lists the blockers in TableView.log.

save::write_header records the initial table and seed, and save::append writes committed actions, random outcomes and replay data. Replay derives the changes. save::open_for_append restores the table, log and chance stream and positions the save after the last complete entry. A hosted save adds the original invite and guest reservation. A joined profile saves its invite, guest name and host label for the start screen's Resume table command. Quitting disconnects; explicit guest leave clears the local resume entry.

Seats, projections and action references

Seat(u8) indexes the table's seats from zero. PublishedTable::new admits one or two seats, and the hosted session requires exactly two. A PublishedTable owns the table, log, chance and one SeatPublication per seat. The adapter uses its viewer-scoped references and slots to translate client actions from TableAction to host IDs. Clients copy an object reference and expected zone out of TableView.objectActions. The after_move hint lets an arrow follow an object moved earlier in the same batch. Host actions and saves use host IDs.

apply_client accepts the authenticated seat and applies requests through TableActionRefs::apply_checked. apply_host applies trusted actions. Every projection must succeed before the entry or any publication is committed. apply_host_with_marks supplies per-seat proposal marks. The script builder uses redact::visit_animation for each staged batch member. Rewinds and reconnect snapshots reset the stage to a complete redacted view. The host sends publication(seat).view() to the matching seat only.

PlayerView::neutral supplies defaults for shared fields. Status::Free indicates no engine decision. The optional PlayerView.table carries manual controls, history, host-held prompt, assists and link status. The guest sends intent and consumes its own publications. It allocates a local session number and displays link state as the local connection changes.

Wire and app commands

beryl_link::wire carries Hello { wire, secret, name }, Welcome { seat, table, host } (table is new or resumed), Mismatch { reason }, Act { n, action }, Done { n }, Refused { n, reason }, Update(payload), Lobby(payload), Leave, Ping { n } and Pong { n }. Payloads are opaque JSON at this layer. Inside Act, the table adapter accepts an ordinary TableAction, a TableAnswerRequest or a TableLobbyRequest. The link transports bounded DEFLATE-compressed JSON frames. TCP and iroh add length prefixes. beryl_protocol::WIRE_HASH is computed from the checked-in generated protocol and the Rust wire envelope. The optional wire_hash(extra) helper can extend it and is unused in the live handshake.

All three session kinds share table_act, table_answer, table_current and table_leave. The app also exposes table_solo, table_host, table_join, table_resume, table_saved, table_lobby, table_settings_get, table_settings_set, table_keys, table_quit, deck_import, deck_list, deck_delete, deck_open_file, card_search and card_tokens. table_act and table_answer return TableActReply. table_current returns an optional GameUpdate, the same type sent through game-update. table-lobby carries a LobbyUpdate with an editable lobby or in-game lobby information. table-link reports connection state and round trip. Phones can play solo, join and resume as a guest.

Interface

ui/src/screens/Table.tsx and ui/src/table/ wire the shared stage to manual gestures, commands, lobby and link events. The pointer's client interface is implemented by both engine prompts and the manual TableClient. The latter uses typed wrappers in ui/src/ipc.ts for all sessions. Commands and default keys come from data/table-commands.json. TableCommands dispatches menu and shortcut actions.

Whole-run acceptance

  • A host and a guest over MemoryLink play a scripted game in one test process: load decks, start, draw, play, attack, apply a combat proposal, undo it, disconnect and resume (beryl_table_session, test a_host_and_guest_play_a_scripted_game).
  • Redaction: after every action of a long random sequence, nothing sent to a seat (view, script, log line, proposal) contains the name of a card whose known_to excludes that seat.
  • Undo: applying any action then undoing it restores every object's zone, position, state and id, and no known_to is smaller than before.
  • Replay: a saved log with undos and rewinds rebuilds the table it was saved from.
  • Scripts: every script the adapter builds replays over the previous view to the next view.
  • Every row of the doc's Permissions table has a test for the allowed and the refused case.
  • Every appendix row not marked "Not carried over" is reachable by the route it names, checked by a test over data/table-commands.json, and no "Not carried over" row is reachable.
  • The context menu for each kind of thing, the command list, a pending proposal, a selection and the lobby are fixtures the generic interface audits run on, on the desktop layout.
  • just check, just ci, just smoke, just ios-smoke and just android-smoke pass, within their existing budgets.
