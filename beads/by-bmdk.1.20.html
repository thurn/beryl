Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Two apps on one machine'.

Two app instances on one Mac need separate identity, saved tables, decks and settings.

  • In rust/crates/beryl_app/src/, add profile.rs: the profile name comes from the environment variable BERYL_PROFILE (letters, digits and - only; anything else is ignored with a journal line). pub fn data_dir(app) -> PathBuf returns app.path().app_data_dir() with no profile, and <app_data_dir>/profiles/<name> with one.
  • Replace direct uses of app.path().app_data_dir() for per-user state with profile::data_dir: start at games.rs:13 (sessions()), then search the crate for app_data_dir. Leave the art cache (app_cache_dir) shared: card images are the same for every profile. Bug reports follow the profile.
  • The interface keeps settings in localStorage, which two instances of one app share. Search ui/src for localStorage and give every key a profile prefix through one helper ui/src/profile.ts (key(name)), reading the profile from AppInfo (add profile: Option<String> to AppInfo in beryl_session/src/ipc.rs and regenerate the TypeScript). With no profile the keys are unchanged, so nobody loses settings.

Tests: profile::data_dir with and without a name and with a bad name (unit tests on a pure function taking the base path and the variable's value); npm test for key(). Run just test-rust -p beryl_app and cd ui && npm run typecheck && npm test.

Acceptance criteria

With BERYL_PROFILE unset nothing moves; with it set, app data and localStorage keys are separate per profile; tests cover the path function and the key helper.

Handoff: beryl_app::profile::data_dir returns the profile root for future table, identity and deck storage. The profile name is lowercased so the filesystem and localStorage agree on case-insensitive volumes. Named profiles use their own journal so concurrent launches rotate logs independently. BERYL_BUGS keeps precedence as the explicit report-directory override. AppInfo.profile is available before the native UI mounts or loads audio preferences. Verified with beryl_app and generated TypeScript tests, UI typecheck and 241 UI tests, and two headless launches that used separate report and journal paths.
