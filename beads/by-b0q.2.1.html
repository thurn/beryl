Mason audit of M1a at staging 42920ed. Ranked summary.

Conformance with docs/engine-architecture.md: sound. State is a flat Copy value under the 20 KiB assert; every zone move outside setup/mulligan goes through the event pipeline (event.rs move_batch_to); layers recompute from base behind derived_dirty; transactional replay follows §7.3 (resolve.rs), with keep_what_was_seen for knowledge; agents and session views see only Observation (beryl_search Agent, protocol.rs player_view); beryl_app is close to thin but holds session lifecycle logic (filed below). CI: slow 45 s of 300 s, fast lanes well under 60 s; no Steward beads, no flakes, no #[ignore]d tests; only just fuzz (10k games), oracles, benches and ui-compare stay out of CI by design.

Filed (gate children, role:executor, review:inline):

  1. by-b0q.2.4 Engine identifier types: Slot/Seat/CardIx newtypes, Option<Slot> relations instead of NONE (155 uses), typed Derived bitfields (34 rewraps), two types for the double-meaning GRANTED index, base controller not readable as controller outside the engine. Bug classes it closes from M1a: slot 255 = NONE (8b3a215), dangling attached_to (e510c4e), base vs layer-2 controller read twice (8b3a215, 71f99eb), unvalidated seat (71f99eb). Lands before M1b agents write slot/seat code.
  2. by-b0q.2.5 Session protocol: tagged Status instead of two Options, DecisionId + CandidateIndex validated once (now three times), session lifecycle and typed SessionError moved from beryl_app into beryl_session (CLI shares it), viewer-relative PlayerView without duplicated fields, events through Observation, a test that every engine card/token/emblem name resolves in cards.json, typed TS command map. Lands before the three M1b game-screen beads build on the view.

Considered, not filed (lower value for this run; mostly pay off when more cards arrive):

  • Ability body split: enum Body { Plain(fn(&mut EffectCtx)), Asks(fn(&mut AskCtx) -> Flow) } would turn the debug-only may_pause assert into a compile error (13 flags, all correct today) and drop clippy::unnecessary_wraps; with it, EffectCtx returning ObjectRef from choose_* and ctx.select/controller_of/zone helpers (~17 sites reach into ctx.state()).
  • Scenario DSL: &'static CardDef instead of names.rs strings (553-line generated file, 48 aliases), Action::Seq and shared assertion shorthands (7 copies of count, 3 macro_rules), Pick/assertions scoped by controller, casting options by kind instead of the costs bitmask, loyalty abilities by cost; single card registration instead of CARDS + SCENARIOS.
  • engine.rs perform: DecisionKind and Pending are parallel tags, so dispatch re-destructures pending under ~6 unreachable!; matching on Pending alone would be simpler. Ability and Casting are flat structs with kind-specific fields (Trigger::None, Replacement::None, Rule::None, Casting.triggered/free/resolving) that could be enums.
  • ManaCost::new(1,[2,0,0,0,0,0]) positional colors (24 sites): a const parser of "{1}{W}{W}".
  • StackEntry and PendingTrigger repeat (source, card, face, ability, controller, info).
  • Tests sensitive to option order (three-lands decking test, 22 Decision{candidates} count assertions); perf_counts bands are an intended regression guard.
