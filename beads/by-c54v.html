Derek Thurn2026-11-14

Diagnosis: the oracle lane failed on Forge 'Generated 82' and XMage 'Generated 45'. Both scenarios are byte-identical at the last green commit 65d9d78e, and running 65d9d78e's tools against the same cached oracle builds fails both the same way. The lane only plays generated scenarios when exporters or harnesses change (oracle_selection.HARNESS); 2d82c218 and 3a3fced4 changed them, so the failures were already there but hadn't been played. Causes: (82) Forge GameState.setupPlayerState puts battlefield cards in with moveToPlay/moveTo, which applies replacement effects, so p0's Containment Priest exiles p1's Griselbrand during setup; (45) XMage picks its own sources for Jace's payment (five skipped Tapped steps) and leaves no white for Get Lost. Neither is a rules difference: added both to data/oracle-exporter-gaps.json. XMage 'Generated 26' also failed once in my local run (it passed in the CI run). It is the known flake by-ovgn, so I left it to that bead.
