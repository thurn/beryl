Description

Read the epic by-r61mr first: it holds the decisions, the code map and the directory layout this bead assumes. The work is in the Enact repository (~/enact) unless this bead says otherwise, delivered with that repository's own enact worktree create and enact push.

The dashboard will be rendered by the Worker, which cannot run Python, so cirrus, the design system in Beryl's status/src/cirrus/, moves to Enact and its renderers are ported.

  • Copy status/src/cirrus/static/ (cirrus.js, sw.js, css/1-tokens.css to css/4-motion.css) unchanged into server/static/.
  • Port components.py (329 lines) and markdown.py (198 lines) to TypeScript under server/src/cirrus/, producing the same HTML. Port status/tests/test_markdown.py with them.
  • Copy the design principles and priorities from Beryl's status/AGENTS.md into an AGENTS.md beside the new code: measured performance first, then cirrus, with every page built from its components.

Leave Beryl's status/ in place; a later bead removes it. To prove the port, render each component and a set of Markdown samples with the Python code and commit the HTML as fixtures the TypeScript tests compare against.

Acceptance criteria

TypeScript tests show every component and the Markdown renderer produce HTML identical to fixtures generated from the Python code. The static files are served by the Worker in the local simulator with content-hashed names and a one-year cache header.
