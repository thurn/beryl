Close reason

Enact 363fe10 passed slow CI and reached master with the WebSocket feed, expiry wakeups, token lookup, and journal-aware daily quota checks.

Description

Read the epic by-r61mr first: it holds the decisions, the code map and the directory layout this bead assumes. The work is in the Enact repository (~/enact) unless this bead says otherwise, delivered with that repository's own enact worktree create and enact push.

Add the Worker's outer layer in server/src/:

  • A WebSocket change feed using the Durable Object's hibernation API, so idle connections cost nothing: subscribers receive the IDs and versions of tickets, leases and events that changed.
  • Waiting without polling: a client waiting for a ready ticket or a lease holds a WebSocket and is woken by the feed.
  • Routing by project path, so one deployment serves Beryl (by) and Enact (en), each with its own Durable Object.
  • Token checks: reads are public; writes, claims and leases need a bearer token whose SHA-256 is in the project's accepted set. Loading that set from GitHub is the token bead's job; here it is an interface with a test double.
  • Refusing a write that would pass a daily limit with the distinct error the contract names, rather than letting Cloudflare fail it.

Acceptance criteria

Simulator tests show a subscriber is told of a change within one event-loop turn, a waiter wakes when a ticket becomes ready, a write without a valid token is rejected and a read is not, two projects cannot see each other's tickets, and a write past the configured daily limit returns the contract's error.

Notes

The contract's section 6 gives the feed's messages exactly, section 8 the token check, and section 3 the 429 answer; build those, with routing by project path.
