Query layer (scope, facts), summary/epic/bead/session/time/dollars/metrics queries; ingest fix for killed runs; pushed 82c9903c

Description

Build the layer that every view goes through: a query is a function from a time range and filters to a plain result, and renderers turn a result into text or JSON. The page added later renders the same results, so nothing may compute a number inside a renderer.

Design sections: "Units", "The command", "Design overview".

What to build

  • The result shape: numbers, rows, a description of each field (the page shows it on hover), and more: the queries that drill into this one.
  • --since (24h, 7d, all, a date) and cohort filters (--where label=value, --epic, --role, --tier, --host, --provider) on every query.
  • Queries summary, epic <id>, bead <id>, session <id>, time --by ..., dollars --by ... with the --by values of the design, and metrics, a registry of named series (for example bead.dollars, bead.agent-minutes, request.context-tokens) that later beads add to.
  • Medians for per-bead figures, with the 90th percentile in the JSON.
  • "(no bead)" and "orchestration" as lines of every roll-up, so parts sum to the total.
  • Text renderer: compact tables that a model can read, ending in a more: line. JSON renderer: the result itself.
  • Sums that include a null price are marked as lower bounds; unknown values print as a dash.

The text format in the design's example for bead is the target.

Shared context

  • The design is docs/efficiency-dashboard.md. Read the sections named above before anything else; the rest can wait. The decisions taken with the user are in the epic, bd show by-ig5e.
  • The dashboard's code is the separate Python project in efficiency/ (package beryl_efficiency, standard library only, pyre strict, black). It imports nothing from tools/ and nothing imports it. Read efficiency/AGENTS.md first once it exists.
  • Tests use small synthetic sources built in the test itself or kept under efficiency/tests/. The repository is public: never commit a real transcript, session record or command line from this machine.
  • Real data exists only on the main Mac (host jarvis). Where the acceptance criteria name a check against real data, run it there; if this session is on another machine, record that the check was not run in a comment on this bead and close on the tests.
  • Collection must stay free for agents: no hook, wrapper or prompt text may be added to any session, and ingest must never run inside another command.

Acceptance criteria

Tests: for every query and fixture, each number in the text output equals the number in the JSON; summary parts (epics, no bead, orchestration) sum to its total; a cohort filter on a label changes the bead set as expected; --since bounds are applied to every part of a result. On the main Mac, just efficiency epic by-bajq lists its closed beads with agent minutes and dollars, and just efficiency summary --since all sums to the store's total dollars.
