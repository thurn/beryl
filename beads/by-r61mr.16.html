Description

Read the epic by-r61mr first: it holds the decisions, the code map and the directory layout this bead assumes. The work is in the Enact repository (~/enact) unless this bead says otherwise, delivered with that repository's own enact worktree create and enact push.

Today an open page polls version.json and cirrus.js swaps in what changed. Replace the poll with the server's WebSocket change feed: the page subscribes, is told which tickets changed, fetches those fragments and swaps them in without moving the reader, within a second of the change. Reconnect with backoff, and fall back to one refresh on reconnect, never to polling.

Add what the server now knows and the old site could not show, each as a cirrus component: who is working on what (session events), slow CI's latest result per operating system, who holds the staging lease and who is waiting for it, the cutover state, and today's requests and rows written against the free plan's limits.

Acceptance criteria

A browser test against the local simulator changes a ticket through tk and sees the open home page and the ticket's page update within one second with no reload and no scroll movement. The page makes no periodic requests while idle. The new panels render from seeded events and honour prefers-reduced-motion.
