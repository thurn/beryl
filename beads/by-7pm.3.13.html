Description

On the Android emulator, a long expert game showed repeated native “Beryl isn't responding” dialogs. Seed 13111305 used the WU Control mirror against Expert. After casting Mana Crypt, Trinket Mage, Portable Hole, Staff, and an evoked Subtlety, the app stopped responding to a tap near the lower-right action button at 21:48:23 on 2026-11-13. Android's events log records am_anr for ca.thurn.beryl/.MainActivity: input dispatching waited 5001 ms for a MotionEvent at (895, 2020). Choosing Wait recovered once; a later ANR covered the natural Defeat result, so View Battlefield, Back to Defeat, and New Game could not be used. Force-stopping and relaunching returned to the start screen without a Return Game option.

The Android Searcher game with seed 13111306 reached a natural Victory on turn 10 and completed View Battlefield, Back to Victory, and New Game without an ANR. This makes the expert game or the late-game state relevant; the cause is not established.

Reproduce from the phone start screen on the Android emulator with seed 13111305 and Expert, play the WU Control mirror through the described spells and game over. Capture Android logcat and a main-thread trace at the first ANR. Inspect Tauri game command execution and UI main-thread work, particularly rust/crates/beryl_app game commands and ui/src result rendering. Ensure touch input remains responsive through game over and result navigation, and add the cheapest deterministic regression check for the confirmed cause. Run just android-smoke and the relevant UI/Android checks.
