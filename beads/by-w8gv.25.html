Close reason

citations shorten keeps line-start citations inline; just citations flags line-start [CR x]: non-definitions; tests added

Description

Symptom: just citations shorten <paths> rewrites a doc-comment line that begins with an inline citation, such as /// [CR 506.4](https://yawgatog.com/resources/magic-rules/#R5064): "A creature ...", into /// [CR 506.4]: "A creature ...". Markdown reads a line-start [label]: ... as a link reference definition, so rustdoc drops the quote from the rendered docs, and just citations still reports 0 problems. by-w8gv.16.6 hit this in nine files (beryl_rules combat.rs, trigger.rs, tokens.rs; beryl_kernel zone.rs, event.rs, mutate.rs, query.rs, rule_changes.rs, object.rs) and fixed them by hand by keeping those lines' links inline. It also rewraps paragraphs, so lines restored by hand can exceed 100 columns.

Fix in tools/src/beryl_tools (the citations module behind by citations): when a citation starts a doc line, keep it inline (or write it so the line doesn't begin with [label]:), and make just citations fail on a doc line that starts with [CR x]: followed by anything other than a URL. Add a test for both.

Acceptance criteria

Shortening a file with a line-start citation leaves rustdoc-valid text; just citations flags a line-start [CR x]: that is not a link definition; tests cover both.
