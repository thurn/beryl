Close reason

Delay carries an object (Objects::Carried) and ReturnToBattlefield added; count gate 391,015,822 -> 391,037,996 (+0.01%), State size unchanged

Description

Why

Flickerwisp was escalated (data/card-escalations.json, commit 4d906d0e; by-bajq.3.6): "When this creature enters, exile another target permanent. Return that card to the battlefield under its owner's control at the beginning of the next end step." The vocabulary cannot say the second sentence for two reasons:

  1. Effect::Delay { ability, carrying: Amount } (beryl_card/src/effect/mod.rs) carries only a number into the delayed triggered ability. "That card" needs the delayed ability to carry an object: the card the first instruction exiled, as the new object it became in exile (CR 400.7), not the permanent that left.
  2. There is no instruction that returns a card from exile to the battlefield under its owner's control.

Containment Priest (by-bajq.3.5) needs Flickerwisp for its classic scenario, so this bead builds the vocabulary, a Sonnet session then writes Flickerwisp (by-bajq.3.6, reopened), and by-bajq.3.5 waits for the card.

What to build

  • Let a delayed ability carry an object as well as (or instead of) a number. A natural shape is a carrying that can name "what the instruction before acted on" (an Objects form such as the one Exile already produces for "that card"), settled as Delay is reached (CR 608.2h) and stored with the waiting ability in the game's store for delayed abilities (K4: a store, not a new field on Player, Object or State). Size the store so State<Small> stays under its limit; a full store returns Full (never a discarded push).
  • The delayed ability does nothing to the object if it has left the zone it was expected to be in (CR 603.7c, CR 400.7). A token exiled by Flickerwisp has ceased to exist (CR 111.7, CR 704.5d), so nothing returns.
  • An instruction that puts a card onto the battlefield from exile under its owner's control (CR 110.2a for who controls it). It enters through the existing entering path (event::Entry/zone.rs mutators), so that by-bajq.3.1's pipeline and by-bajq.3.5's "wasn't cast" proposal apply to it unchanged. It enters untapped, as a new object with no memory of its earlier one (CR 400.7).
  • Render text for both, so the card's rendered text matches its Oracle text (beryl_card/src/render/), and the table check (beryl_card/src/check.rs) for the new forms.
  • Remove nothing from the escalation file: the Flickerwisp card bead does that.

Tests

Unit tests in beryl_rules/src/tests/ with a test-only definition: an enters trigger exiles a permanent and a delayed "at the beginning of the next end step" ability returns it; the returned permanent is untapped and controlled by its owner when someone else controlled it; an exiled token does not return; a card that left exile before the end step is not returned from its new zone.

Handoff: Effect::Delay gained object: Option<Objects> (builder delay_with(ability, objects)), settled as Delay is reached: the first slot of what the expression names, as an ObjectRef to its current incarnation (so after exile(target()), those() is the card in exile, CR 400.7). It is stored in the existing PendingTrigger.info.object of the delayed queue: no new store, State<Small> size unchanged, and last-known/naming/equivalence code already handles that field. The delayed ability reads it as the new Objects::Carried (builder carried_object()), which is empty once the object is no longer current (CR 603.7c; this covers a token that ceased to exist and a card that left exile). Check table: Carried only in a delayed ability (Malformed::Carried); a Delay carrying a set (All/InZoneOf/CardsIn/ExiledWithThis) is Malformed::Delayed. New Effect::ReturnToBattlefield(Objects) (builder return_to_battlefield, rules zones::return_instruction): any source zone, so it covers ExiledWithThis for Fiend Hunter and a graveyard for Bloodghast. It moves the cards in one event::move_batch with Entry::default(), so they enter untapped under their owners' control. Instants and sorceries stay where they are (CR 400.4a). Render: 'return [cards] to the battlefield under their owners' control', and a delayed ability whose one instruction acts on Objects::Carried puts its trigger last ('... at the beginning of the next end step'), as 98 of 111 such Oracle texts do. Unit test render::tests::a_delayed_ability_on_a_carried_object_says_its_trigger_last renders Flickerwisp's exact Oracle text. Tests: beryl_rules/src/tests/delayed.rs (return untapped under its owner's control from a stolen, tapped permanent; an exiled token does not return; a card moved from exile to the graveyard stays there). Removing the is_current filter fails two of them. The mutation neighbours cover Delay.object and ReturnToBattlefield. Count gate: 391,037,996 instructions, against 391,015,822 at the last staging tip measured (+0.01%, no bump). The escalation file is untouched: the Flickerwisp bead (by-bajq.3.6) removes its entry. Bloodghast's 'you may return this card from your graveyard' wording is not rendered yet; by-bajq.1.13 should extend the template.
