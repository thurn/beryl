Close reason

Manual markers retain their controller, redacted preview and stable ID through source removal, view reset and replay.

Description

6770658e captures a marker source's card, face and visibility, but AbilityMarker in beryl_table/src/state.rs retains no controller and apply/cards.rs constructs the marker from a selected card. StackItem::ability in beryl_session/src/protocol/neutral.rs requires a controller. After placing a marker and removing its token source or changing who controls it, by-bmdk.3.1 has no reliable controller to use. Separately, script/table.rs::Table::of strips ability numbers and Act::Vanish requires one, so testing removal from only the previous PlayerView cannot distinguish two identical markers. The stage also needs the same id after a reset.

Capture the marker controller as stack state when placed, independently of the optional, redacted preview. Carry a stable manual marker id through projection and numbered replay/reset. Prefer retaining the existing ability subject and numbered-table mechanism (for example a manual stack id field or a typed adapter replay input that builds Table::named consistently) to another stage identity system. For the source preview, use the captured face and permit no source object when it has left. Preserve old table saves and engine ability wire behavior.

Acceptance criteria

Create two markers with the same text on a borrowed token, remove or change control of the source, reset the view, then remove only the second marker by id. Its controller remains the captured seat, its allowed viewer can still see the captured face/text, a viewer with no permission cannot, and replay retains the other marker.

Handoff: beryl_table captures AbilityMarker.controller from the source when placing it. Save replay captures it from the original action; older headers use the saved source controller, or the saved active seat when the source is gone. In the adapter, project only the redacted display_source to MarkerPreview (name, original face, marker text), pass a source slot only when that object exists in the projected view, and pass marker.controller as the viewer-relative side to StackItem::ability. Use the beryl_table marker ObjectId's full u32 for the stack item, Subject::Ability, Emerge and Reset. Reset lists the projected stack bottom first. The desktop and phone share the stack frame for manual previews. The regression tests cover save/replay, visibility from an informed and uninformed seat, and deleting just the second duplicate on the stage after a reset.
