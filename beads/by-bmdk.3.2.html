Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Views and animation' (the table mapping every action to a verb).

In rust/crates/beryl_table_session/src/script.rs: pub fn script(before: &PlayerView, entry: &Entry, after_table: &Table, seat: Seat, slots: &mut Slots) -> Script, built from the entry's changes, for the seat watching.

This bead covers the rows: move, draw, give, mulligan, reorder, pin, sort_hand, attach, unattach (verb fly); tap (tap); face, peek (flip); counter, stats, damage, life, player_counter (count); token, clone (appear); marker (emerge from its source); remove (vanish); flag, note (set).

  • Read beryl_session/src/script/act.rs for each Act's payload and script/moves.rs for how the engine builds a fly. Build Steps with the same public constructors; if one is private, make it pub in beryl_session without changing it.
  • Both seats get a script for every action. A seat that does not know a moved card gets the same motion with a hidden card.
  • Steps that happen together (a selection moved in one action) go in one beat.
  • The replay rule: after building, call beryl_session::script::replay::failure(before, &script, &after_view). In a debug build a failure panics with its text; in a release build return a script with reset set (see how script/build.rs::Builder::script does it) so the stage takes the new view whole.

Tests in tests/script_cards.rs: for each action above, on a small table, the script has the expected verbs for each seat and replays (failure returns None). Then a random test: 1,000 random actions restricted to this bead's kinds, asserting replay for both seats after each, and that no step's JSON names a card the seat does not know. Run just test-rust -p beryl_table_session.

Acceptance criteria

Every action row listed produces the doc's verb for both seats; every script replays over the previous view to the next; the random replay and redaction test passes for these action kinds.

The adapter uses the ordered per-seat animation projection, which needs the pre-action host table. Its script function takes both published views and their slot snapshots. This lets the existing view API publish action refs once and lets a mulligan animate against each redacted intermediate table. Anonymous flights use a zone origin and retire old slots together, so the payload carries no old-to-new slot pairs. The local Arena archive has no recordings, so the opponent draw uses the existing Beryl timing and pile anchor.
