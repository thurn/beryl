Description

Read first: docs/beryl-3d.md 'The agent interface' ('Times, moments, locators and actions' and 'The test driver'). Read fixtureTransport in ui/src/ipc.ts for which recorded response answers which request, and what happens when none matches. The bead before this one gave tree, locate, hit and uncovered.

In rust/beryl3d/crates/beryl_scene, src/driver, behind the driver feature (the app does not enable it):

  • Recording: one recording's messages for one seat, a newtype over Vec<ipc::FixtureMessage>. Page::new(&Recording, seat, layout, size). beryl_scene never records and never names beryl_cli.
  • A recording plays on a clock of its own: each recorded reply is given 400 ms after the table comes to rest in the view it answers.
  • Duration parses 850ms and 1.25s and prints milliseconds. Moment parses a duration, start, end, view:N, prompt:N, step:V.B.S, and any of the names with an offset (view:12+250ms). page.moments() lists every moment of the recording with its time, and page.seek(moment) goes to one.
  • Methods named as the doc's actions: press, hover, drag, type_text, key, move_to, step(duration) and still(). page.run(script: &str) takes the same actions as lines of text and calls the same methods. find(locator) returns an element with zone(), rect() and states(). Also frame(), tree() and check().
  • Actions enter through Client::handle as Pointer and Key inputs at the centre of the element's uncovered rectangle. A press is a Down and an Up at one point. A drag is a Down, eight Moves evenly spaced along the straight line with a 16 ms step after each, and an Up.
  • Nothing waits by itself. When a locator or an assertion fails, the message ends with the clock's state, for example t=850ms view 12, animating (fly "Counterspell" 62%): call still() first?.
  • A press sends a command, and the driver answers it from the recording's response for that request, by fixtureTransport's matching rule. When none matches, the error names the command.

Tests in beryl_scene/tests, on a Recording built by hand from two views (the testing builders of the table bead): durations and moments parse and their errors say what was expected; run of a five-line script makes the same inputs as the five methods; a press lands inside the element's uncovered rectangle; a failed find prints the nearest names and the clock's state; a build without driver has no Page.

Run: just b3d cargo-test -p beryl_scene.

Acceptance criteria

A test drives a hand-built recording with locators and actions, both as methods and as text; the driver is absent from a build without the driver feature; beryl_scene has no dependency on beryl_cli; every action name in the doc's list is a method and a line run accepts.
