Description

Bisect a slow-CI failure that survives the rerun, and end the log with the answer (plan K21; docs/project-50k.md, Target architecture, Checks, "After a merge"). Step two of the CI track (by-w8gv.20).

Context

Enact runs by ci (.enact.toml [checks] slow) on each staging tip in a detached ci tree. On failure it files a P0 Steward bead whose description holds the last 60 lines of the output (enact.py run_ci: splitlines()[-60:]), so the answer must come last and fit in about 25 lines. Enact kills the whole check at slow_timeout = 900 s. by ci's own deadline is twice its 300 s budget (Steps in checks.py). No Enact change is wanted (epic decisions).

What

  • After run_lanes in checks.slow(): if any check failed after its rerun (run_lane's rerun, by-w8gv.20.7) and was not excused (verdicts.excused), find the commits in git rev-list --first-parent origin/master..HEAD and bisect: in a detached worktree at a commit (under the cache, warm.ensure()), rerun only the failed checks with the lane's existing narrowing (failed_titles, failed_shots, failed_cards, nextest filter in rust_tests_step). Binary search for the first failing commit. Each check is bisected; checks failing at the same culprit share one search. Bound it with the time Enact leaves (900 s minus elapsed, with a margin). Out of time, report the narrowed range.
  • A check that passes at the tip on its bisection rerun is a flake: report it as such and do not blame a commit.
  • End the log with one block, last:
  bisect: <check>  culprit <sha> <subject>  (<n> commits since master)
  record: <check>  runs <r>, failures <f>, flaky <a>, stale <b>, catch <c> (30 days)

The record comes from ci-report's Tally and the ci-check beads (verdicts.STORE). The culprit commit's enact_commits bead, if one names it, is useful too: bd list --json metadata.

  • Over budget with no failed check: if the load average went above the core count during the run (load_note) or warm.ensure() had to build a cold cache, rerun the whole run once. If the rerun is also over budget under load, exit 0 with an excused: over budget under load line (files nothing). Over budget on a quiet, warm machine still fails, as today. Make warm.ensure() report whether it cloned warm or built cold.
  • Each bisection rerun's records go to runs.jsonl with script bisect and their commit.

Files

tools/src/beryl_tools/checks.py (slow, run_lanes, run_lane, Steps, Clock, load_note, the failed_* helpers), warm.py (ensure, ensure_target), runlog.py (Run, Tally), verdicts.py (STORE, excused). Split checks.py if it passes 800 lines: a new bisect.py.

Tests

pytest with a fake repo of 5 commits and a fake check that starts failing at commit 3: the culprit, a flake at the tip, the time bound, and the over-budget-under-load path. By hand: in a scratch clone, make a staging with a commit that breaks one ui-test check and run by ci ui-test; show the log's last lines.

Acceptance criteria

A slow-CI failure surviving the rerun ends the by ci log with each check, the culprit commit and its record, within the last 25 lines and Enact 900 s; over budget under load or cold cache reruns and files nothing; pytest with a fake 5-commit repo covers culprit, flake and time bound.

Derek Thurn2026-11-11

Decisions: (1) Only steps a rerun can narrow (Step.failed set: pytest, rust tests, smoke, shots, ui-test, oracle, count-gate) are bisected; static checks, timeouts and CANNOT_RUN are listed as 'not bisected'. Their commands can't be mapped to another commit cleanly (markdown file lists, npm_bin paths). (2) Probes run each commit's own tools via PYTHONPATH=<tree>/tools/src with the CI run's interpreter. (3) The bisect tree is persistent under $BERYL_CACHE/ci/bisect-<hash of git common dir> so builds stay warm; hooks are off for its checkouts. (4) A culprit at the first commit is confirmed against the commit before it ('fails at <base> too' otherwise), so an environment break blames no one. (5) runlog.tally leaves out script=bisect records: a failure at an older commit is not the check's record. (6) Over budget, loaded or cold, with no wall time left for a rerun (first run's wall time > time left before Enact's slow_timeout): excused without a rerun. (7) checks.py would have passed 800 lines: the Rust tests step moved to rust_tests.py, CANNOT_RUN to reruns.py. (8) A run whose bisect finds only flakes still exits 1; the bisect line says flaky.
