Close reason

Scenarios behind beryl_cards' scenarios feature (app builds none); 9 designated props; a test holds scenarios to own card, tokens, basics and props; 20 marked interactions; oracles pass

Description

Milestone 5 of Project 50k (plan K5 and K3; epic by-w8gv.9): the rules library and the card port. Line numbers and counts below were read at staging f5034c58; the code as it stands wins over this text, and a deviation is a comment on this bead.

Plan, Crates: "Scenarios compile only for tests and tools. They are three quarters of today's compile cost and would add megabytes to the app." Plan, Verification: "Scenarios use basic lands and a small set of designated prop cards, so one card's change cannot break another card's tests." This bead does both. It touches the scenario half of every card file and no engine code, so it runs beside the engine beads of this milestone; the card port depends on it.

What exists

  • Each card file under rust/crates/beryl_cards/src/<color>/ ends with pub const SCENARIOS: &[Scenario] and imports beryl_scenario::{Action, Assertion, P0, P1, Permanent, Scenario, ...}; beryl_cards/src/lib.rs has the SCENARIOS table by card name; beryl_cards/src/generate.rs makes random positions for the oracles; beryl_cards/src/bin/beryl_scenario.rs dumps scenarios for XMage and Forge.
  • beryl_cards depends on beryl_scenario as a normal dependency, so beryl_app (through beryl_session and beryl_search) compiles every scenario.
  • Readers of SCENARIOS: beryl_cli (src/script_check.rs, src/specs/mod.rs, specs/playground.rs, specs/auto.rs), beryl_cards' tests (src/tests.rs, tests/exhaust.rs, tests/prompts.rs), eight test files of beryl_session (tests/common/mod.rs and others), beryl_search's tests.
  • Cross-card props today, by how many other cards' files name them: Plains 43, Island 43, Mana Crypt 18, Elite Spellbinder 11, Jace, Vryn's Prodigy 10, Oust 9, Tundra 9, Staff of the Storyteller 8, Counterspell 8, Thieving Skydiver 7, Timetwister 6, Teferi, Time Raveler 5, Mana Tithe 5, Reprieve 5, Mana Drain 5, and 23 more named by one to four files.

Scope

  1. A cargo feature on beryl_cards (say scenarios) behind which the scenarios, the SCENARIOS table, generate.rs, the dump binary and the dependency on beryl_scenario compile. Tests and tools turn it on (dev-dependencies, beryl_cli, the binary's required-features); beryl_app, beryl_session and beryl_search do not, outside their tests. A card's scenarios stay in its file (AGENTS.md): put them behind the feature there. Milestone 7b's set crates will copy the pattern, so keep it to one attribute or one inline module for each card.
  2. Designated props. No new card may be written for this (K14: the only new cards are the closing pilot's), so designate from the implemented pool: the basic lands, and one stable card for each role scenarios need (a creature to attack, block and be targeted; an artifact; an enchantment; an instant to counter; a planeswalker; a nonbasic land; whatever else the scenarios show). Prefer cards whose definitions are data only and whose text has nothing a scenario would trip over (Mana Crypt's upkeep coin flip is the counterexample). List them in one module with the role each plays. Record on the bead that vanilla creatures from the card store should take over when milestone 7b generates them.
  3. Rewrite each card's scenarios to name only its own card, its tokens, basic lands and designated props. A scenario about how two particular cards interact (Teferi, Time Raveler's static ability against The Wandering Emperor's flash) keeps both and is marked as an interaction, in a way a test can read.
  4. A test in beryl_cards fails when a card's scenario names a card outside that set and is not marked.

Constraints

  • A scenario changed here must still show what its name and comments say, replay in the strict runner (cargo test -p beryl_cards), survive permuted slots and the bounded exhaustive search (just exhaust), and agree with XMage and Forge: run just oracle on every card (it needs just oracle-setup once on a machine) and fix what a new prop changes. Keep each scenario's name: specs, beryl_cli script-check and the UI's spec routes key on card and scenario names.
  • A feature that any workspace member turns on is on for a whole-workspace build, so cargo build --workspace proves nothing. Prove the app's build: cargo tree -p beryl_app -e normal shows no beryl_scenario, and just smoke passes.
  • The port beads edit the same card files' definitions later; this bead leaves the definitions alone.
  • Engine code does not change, so the count gate cannot move; rollouts_never_change and the corpus still run in just check.

Record on the bead: cargo check -p beryl_cards time with and without the feature (clean), and the release app binary's size before and after.

Need not read: beryl_rules, beryl_kernel, ui/.

Parity and checks

Parity (plan K11) at the push: just check passes; the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds (cargo test -p beryl_bench rollouts_never_change); slow CI's counts lane (just count-gate, bar 389,343,295 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. Run just bench-count before and after and record both on the bead: the benchmark is the WU Control mirror, so what this milestone moves is on the counted path. No behavior changes: no rules fix, no new card, no new mechanic (K14). A rules bug you do find and fix gets a docs/bugs.md entry (AGENTS.md). A save or a rollout replays the decisions a game asked, in order: never change which questions a resolution asks, their order or their options.

Held by checks (AGENTS.md, Code structure): no card name in generic code; no source file over 800 lines (data/file-length-allowlist.json only shrinks, and a new file starts under the limit); rules code and card bodies ask the state for a player's opponents and never name the other of two; they change the state through a mutator, never the board door; a push whose bound is argued takes Queue::push_bounded and any other propagates Full; a count or position that grows with the layout is never narrowed with as. No procedural macro, and a macro_rules! only where a const fn cannot remove the repetition. beryl_card, beryl_kernel and beryl_rules take no runtime dependency. Rules code cites the Comprehensive Rules with a yawgatog link and a quotation; keep the citations of code you move, and check new ones against the pinned release with just citations. Forge is a test oracle only (K16): no entry, name or design comes from its scripts. beryl_search/src/expert and beryl_search/src/frozen are exempt from the project: edit them only where a call stops compiling, giving the answer the old read gave. Other tracks edit nearby files (presentation by-w8gv.21 in beryl_session and ui/, mobile, the AI ladder): enact push rebases and you fix the conflict.
