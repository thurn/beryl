Description

Milestone 5 of Project 50k (plan K5 and K3; epic by-w8gv.9): the rules library and the card port. Line numbers and counts below were read at staging f5034c58; the code as it stands wins over this text, and a deviation is a comment on this bead.

Third bead of the library lane: the methods that make something lasting, and the design step the M4 Mason audit left for this milestone.

The methods

  • effect/continuous.rs: add_effect(on, payload, duration), add_effect_on_set, gain_control.
  • effect/permit.rs: allow_cast(card, player, increase, free, exile_after), grant_flashback; permission.rs (59 lines, begin_on_spell, flashback_paid).
  • effect.rs: delay (line 1008, a delayed triggered ability, CR 603.7, over trigger::delay), create_emblem (line 998, CR 114), win_game (line 1027, CR 104.2), add_mana (line 336; interpret::add_mana, CR 106.4), and Run::modify in interpret/run.rs (line 573).

They become library functions over Game and Resolution: continuous effects from a resolving spell or ability (CR 611.2), control (CR 613.2), permissions to cast (CR 601.3), flashback in keywords/flashback.rs (CR 702.34), delayed triggers (CR 603.7), emblems (CR 114), winning (CR 104.2), adding mana (CR 106). All already write the state through kernel mutators (State::start_effect, start_effect_on_set); what is left is that they are EffectCtx methods.

An effect takes only a legal pair (M4 Mason audit, comment on by-w8gv.9.1, item 2)

State::start_effect(source, Affects, Payload, Duration) takes any pair of what is affected and what is done. The store's invariants say a player is affected by a rule change alone and a locked-in set by a layer change alone; the mutator holds the first with a debug assertion (in release the entry is stored and does nothing) and the second with unreachable!, a panic in release. Readers carry the dead arms: rule_applies and rule_change::maker (Affects::Set => false / None), layers::resolved_effects (Affects::Player => {}), cast_permissions (a filter_map over (payload, as_object)). A card body can write the wrong pair today (teferi_time_raveler.rs writes the right one by hand). One type removes all of it; the audit's sketch:

pub enum Effect<L: Layout> { Layer(Permanents<L>, LayerChange), // Permanents: One(ObjectRef) | Set(LockedIn), the second made only by the store Move(ObjectRef<L>, MoveReplacement), Rule(Subject<L>, Rule), // Subject: Player(Seat) | Object(ObjectRef) Cast(ObjectRef<L>, Permission), Cost(ObjectRef<L>, CostChange), }

It deletes two invariants of beryl_kernel/src/effects/store.rs, the debug assertion and the unreachable! in start_effect, and the dead arms above; rule_applies takes a Subject. Constraints: an entry is 24 bytes in Small (the const assertion in beryl_kernel/src/effects.rs) and the count gate holds, so measure both. If the nested enum does not fit 24 bytes, keep Affects and Payload as stored and make the typed enum the argument of the mutator and of the readers only. The name must not collide in a reader's mind with beryl_card::Effect, the instruction: choose one that says "continuous".

Decisions (executor).

The typed enum is the argument only, not what is stored. Measured in Small: the nested enum of the audit's sketch is 24 bytes by itself (LayerChange is 16 with an alignment of 8, so a variant holding it beside the four bytes of what it is on rounds to 24), and an entry holding it with source, timestamp and duration is 32. Affects (4) and Payload (16) apart keep the entry at 24, so they stay as stored, and the const assertion in beryl_kernel/src/effects.rs is unchanged. size_of State<Small> did not move (the copy benchmark is 13,481 before and after).

What starts an effect: State::start_effect(source, Continuous<L>, duration). Continuous is Layer(ObjectRef, LayerChange) | Move(ObjectRef, MoveReplacement) | Rule(Subject, Rule) | Cast(ObjectRef, Permission) | Cost(ObjectRef, CostChange), with Subject = Player(Seat) | Object(ObjectRef). Differences from the sketch: Layer takes one ObjectRef and not Permanents, because a caller could copy a LockedIn out of a reader and start a second effect on another effect's set; a set is started only by start_effect_on_set, which makes the set it names. Permanents (One | Set) is what the reader State::layer_effects gives. So the debug assertion about a player and the unreachable! about a set are gone from start_effect, which matches on the Continuous it was given. A compile_fail doctest on Continuous holds that a layer change on a player does not compile.

Readers: rule_applies and rule_change::applies/maker take a Subject (no Set arm); layers::resolved_effects matches Permanents (no Player arm); cast_permissions is filter_map(ContinuousEffect::permission). Because the pair is stored as two halves, three private decoders in the store's file (layer_change, permission, and player_rule which was there) read an entry 'if that is what it does': their fallthrough is the filter by kind. The two invariants in effects/store.rs (a player is affected by a rule change alone, a set by a layer change alone) stay as checks of the stored form; the mutators' arguments are now what keeps them, not a caller's care. Affects and Payload stay public to read (beryl_search/src/mcts/tree.rs compares them, EffectsOn gives a Payload); Affects::object and From<ObjectRef> for Affects are gone from the public surface.

Library modules (beryl_rules/src): continuous.rs (start, start_on_set, gain_control, the Effect::Modify arm as instruction; gain_control stays here, cited CR 613.1b and 302.6 as before: the pinned rules have no rule of their own for gaining control); casting.rs gains allow, permit, permission (was permission::of) and begin_on_spell; keywords/flashback.rs (grant, paid; lib.rs still exports flashback_paid); delayed_triggers.rs (create); emblems.rs (create); ending.rs (win); mana/add.rs (mana::add and the Effect::AddMana arm; mana is now a pub module, its solver still crate-private). Deleted: permission.rs, effect/continuous.rs, effect/permit.rs, Run::add_mana, Run::modify, interpret::add_mana, EffectCtx::add_effect_on_set (only Run::modify called it). EffectCtx::add_effect now takes (Continuous, Duration); every EffectCtx method is a delegation. casting::permit calls the mutator and not continuous::start, because the old permit never refreshed the layers.

As the design bead decided for moved arms, Effect::Modify now stops the resolution at Full rather than noting it and playing on.

Counts, just bench-count before (staging 1e06aa7d) -> after: copy 13,481 -> 13,481; next_apply 361,154,279 -> 360,866,181 (-0.080%); policy 1,746,603 -> 1,746,603; rollouts 388,633,629 -> 388,132,971 (-0.129%; under the bar of 389,343,295, no bump). Tests: beryl_kernel 67 + 2 doctests, beryl_rules 176, beryl_cards with every scenario unedited, the corpus replay, rollouts_never_change, clippy, just citations (0 problems).
