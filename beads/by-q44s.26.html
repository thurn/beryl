Handoff: the hang was a pipe deadlock in tools/src/beryl_tools/beryl3d/source.py run_with_sources. Python wrote the file list (67.7 KB, now over a pipe's 64 KiB buffer) to tar's stdin before starting the limactl shell that reads tar's stdout, so tar blocked on its full stdout and Python on tar's full stdin. tar now reads the list from a NamedTemporaryFile (stream_sources). This was not caused by a Beryl 3D code change: the list just grew past 64 KiB, which also explains why bisection found no culprit. The new test test_a_file_list_longer_than_a_pipe_holds_is_sent hangs and fails without the fix. Full just b3d gate --gpu passed end to end in the worktree. Commit 0a0ea135e.
