Description

Read the epic by-r61mr first: it holds the decisions, the code map and the directory layout this bead assumes. The work is in the Enact repository (~/enact) unless this bead says otherwise, delivered with that repository's own enact worktree create and enact push.

The bd stand-in built later in this epic must reproduce what the real bd does for every call that Enact, the prompts and Beryl's tools actually make. This bead captures those calls.

Add scripts/bd_record.py to Enact: a stdlib Python wrapper that is installed ahead of the real bd on PATH, runs the real bd (~/.local/bin/bd on the Macs) with the same arguments, stdin and environment, passes through its stdout, stderr and exit code unchanged, and appends one JSON line per call (arguments, working directory, stdin, stdout, stderr, exit code, duration, time) to a file under the clone's Enact state directory. It must add no more than a few milliseconds and must never fail a call because logging failed.

Add an enact subcommand or documented steps to install and remove it, install it on the machine this session runs on, and leave it recording. Then add a script that reduces a recording to a corpus: one entry per distinct subcommand and flag combination, with the bead store snapshot (bd export) taken at the start of the recording, committed under tests/corpus/ with bead text kept (the tickets are public).

The wrapper is also the first rehearsal of swapping bd on PATH, which is how the cutover works.

Acceptance criteria

With the wrapper installed, bd list --json gives byte-identical stdout and the same exit code as the real binary, and a line appears in the log. tests/corpus/ holds a corpus covering at least the subcommands create, show, list, ready, update, close, dep, label, comments, epic, defer, with a count of distinct flag combinations printed by the reducer. A unit test loads the corpus.
