Description

Part of the ladder epic by-97g. Read docs/ai-strategy.md first: §6.5.

Rung 7, build. Tree::select (long.rs) plays each new child of a node once, in random order, before UCB1 compares them, so a node's first visits average good and bad answers alike. With the option order set, new children are tried in the order greedy scores them, best first.

Where

  • rust/crates/beryl_search/src/long.rs: Tree::select (the fresh branch picks one unplayed child at random), Tree::iterate (which has the state s and the decision d at each node), Options, to_name, FromStr.
  • rust/crates/beryl_search/src/rollout.rs: RolloutPolicy::decide_by computes a score for every candidate and returns only the best.

Build

  1. Add pub fn scores<L: Layout>(&self, t, obs, d) -> Vec<Option<i32>> to RolloutPolicy: each candidate's score, by the same rules decide_by uses. For the kinds decide_by answers without scores (yes or no, numbers, the first), return 1 for the candidate it would choose and 0 for the rest.
  2. Add the option order, last in the fixed order of names: anchor, expert, guard, mid, means, hold, waste, combat, order (keep the ones already there).
  3. With order set, Tree::select's fresh branch picks the unplayed child whose candidate has the highest score (the first of equals), not a random one. iterate computes the scores only when the node has an unplayed child. The root is included.

Tests

  • families_round_trip covers …/anchor+order.
  • On a crafted decision, the first child tried is greedy's choice.
  • Without order, the trees grow exactly as before (an existing determinism test still passes untouched).
  • just test-rust, just check.
