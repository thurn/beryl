Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Touch'. The epic's decisions: phones get the solo table and can join; they cannot host; test lightly.

Interface code goes in ui/src/table/, registered with TableClient (ui/src/table/client.ts). Headless checks start a table with ui/scripts/table.mjs and go in ui/scripts/kept-table-<topic>.mjs; run one with just ui-test <title>.

  • Drag on touch starts after the short hold the pointer already implements, so scrolling a hand still works; drop targets and library halves are the desktop ones.
  • "Draw arrow" in the sheet, then a tap on the destination (pickTarget).
  • A search button in a corner of the phone table opens the command list full screen: implement presentation: "fullscreen" in ui/src/table/CommandList.tsx and pass it through TablePalette.tsx, the table-specific wrapper. Open it through TableCommands.openList in TableMenu.tsx so touch uses the same command dispatch as desktop. There are no shortcuts on touch: confirm every registry command with a key is also in the sheet or the list (a unit test over data/table-commands.json: no command is reachable by key only).
  • Number and text prompts work with the on-screen keyboard: the field must not be covered by it (use the phone layout's existing handling for a focused input, if any; otherwise place the prompt at the top on a phone).
  • The lobby and start screen on a phone: "Join a table" and "Solo table" only; paste a decklist (no file open). The lobby panel fits a phone screen in one column.
  • The reconnecting banner and the proposal panel must not cover the hand on a phone.

Checks (kept-table-touch-2.mjs, phone viewport): drag a card from hand to the library's bottom half; draw an arrow by the sheet; open the full-screen command list and run "Draw card"; join a hosted table from the phone layout with pair() (host on the desktop layout). Then run just ios-smoke and just android-smoke once and record the result on the bead; a failure caused by this epic is fixed, any other is noted and left.

Acceptance criteria

Touch drag, sheet-driven arrows and the full-screen command list work on the phone layout; no command is key-only; a phone-layout guest can join a desktop host in a headless check; the phone lobby has join and solo only; ios-smoke and android-smoke results are recorded.
