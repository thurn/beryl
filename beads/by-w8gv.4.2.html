Crates table flipped: kernel depends on beryl_card; docs and doc comments only

Description

From the M2 Mason audit (by-w8gv.4.1). A correction to the plan's crate graph, so M3's decomposition (by-w8gv.5.1) starts from one the code can reach. Documentation and doc comments only.

CURRENT docs/project-50k.md, Target architecture, Crates: beryl_kernel depends on nothing and beryl_card depends on "beryl_kernel's id types". M2 built beryl_card with no dependencies and put in it every value a definition shares with the state: ids.rs (Seat, Zone, TurnStep, CounterKind), characteristics.rs (Types, Supertypes, Subtypes, Colors, Keywords), mana.rs (ManaCost, ManaColor, ManaSet), definition.rs (FaceIx, AbilityIx, FaceAbility), cost.rs (Castings, CastingKind), continuous.rs (Modification). Its lib.rs and ids.rs say it holds the ids "until the kernel crate takes them". The files M3 moves into the kernel hold those types by value: beryl_engine/src/state.rs imports Castings, Colors, FaceAbility, FaceIx, Keywords, ManaColor, ManaCost, Modification, Subtypes, Supertypes, Types, CounterKind, TurnStep and Zone; event.rs, zone.rs, setup.rs, invariants.rs and reference.rs import more. M3's own scope (by-w8gv.5.1) also puts queries in the kernel that read a definition: the card behind an object, mana value with copies and faces, copiable values. Those need CardDef and Face, which reach Ability and Effect. So the table as written means moving half of beryl_card down into the kernel, splitting the vocabulary over two crates, and still leaves those queries unable to live in the kernel.

PROPOSED Flip the edge. beryl_card is the dependency-free bottom crate and keeps what it has; beryl_kernel depends on beryl_card.

beryl_card nothing beryl_kernel beryl_card beryl_rules beryl_kernel, beryl_card (unchanged) cards/<set> beryl_card; beryl_rules for bodies (unchanged)

WHAT IT ELIMINATES

  • Any move of ids, characteristics, mana or index types in M3, and a vocabulary split over two crates.
  • The contradiction between the table and M3's kernel queries.
  • A rebuild of every data-only card crate on every kernel edit: they depend on beryl_card alone, so only a vocabulary edit rebuilds them (scale budgets, plan Acceptance). K12 is about runtime dependencies from outside the workspace and is untouched: neither crate gains one.

CHANGES

  1. docs/project-50k.md, Crates table. beryl_card row: add to Holds "the ids and index types a definition shares with the state (seats, zones, steps, counter kinds; face, ability, target-spec and casting-option indices)"; Depends on: nothing. beryl_kernel row: Holds starts "Slots and object references, bitboards, fixed queues, ..." (drop the bare "Ids"); Depends on: beryl_card. Put the beryl_card row above the beryl_kernel row. Add one bullet under the table giving the reason in two sentences (the kernel stores vocabulary values and answers queries that read a definition; data-only card crates then rebuild only when the vocabulary changes).
  2. Same file, Kernel rules: after "Ability, target, mode and option indices are distinct types." add "Those a definition names are defined in beryl_card."
  3. rust/crates/beryl_card/src/lib.rs (the paragraph "This crate knows nothing of the game state...") and src/ids.rs (module header): replace "until the kernel crate takes them" / "The kernel crate takes them over in milestone 3" with what is now true: this crate holds them and the kernel depends on it.
  4. docs/engine-architecture.md: change only a sentence that states the old direction, if there is one (grep beryl_card, beryl_kernel).

MUST NOT CHANGE No Rust item moves, no Cargo.toml changes, no behavior. just fmt for mdformat's 80 columns.

AFTER PUSHING One line on by-w8gv.5.1 saying the Crates table changed and naming this bead, then enact sync.
