Description

Why

rust/crates/beryl_rules/src/tests/ is 14,150 lines of tests that define their own test cards ("Test Bear", "Test Rest") and arrange boards through the kernel's test door (s.board().begin_at(..), put(..)), because the scenario runner sits above the engine. A test that only drives decisions and reads the result is a scenario in disguise: as a scenario on a real card it is shorter, and XMage and Forge play it too. Plan: Designs C, "Rules tests".

What to do

In these files of rust/crates/beryl_rules/src/tests/: combat.rs (1,035 lines), combat/, library.rs, graveyard_return.rs, mulligan.rs, phasing.rs, regeneration.rs, effects.rs, game.rs, rules.rs, trackers.rs.

For each test:

  • If a real card's scenario already covers the same path (the close reasons of by-bajq's Wardens list, per group, which test definition each real card's scenario covers; the rulings ledger names scenarios too), delete the test and, if nothing else uses it, its test card.
  • If none does and the test only plays decisions and reads results, write it as a hand-written scenario in rust/crates/beryl_cards/src/library/ under the module of the rule it shows, on a real implemented card or a prop, then delete the test. If no implemented card has the behavior, implement the simplest real card that does (the card-writing skill, "Cards for scenarios").
  • If the test calls an internal function directly (event::settle with a hand-built event, a layer function, a solver function, an invariant check), it stays. Use the module's typed-reference functions as they now are.

Do not weaken what is tested: the scenario must fail if the engine did what the old test guarded against. Check five of your conversions by breaking the engine in a scratch branch.

just test-rust and just oracle for each card whose scenarios you added. The close reason gives tests deleted, tests converted, tests kept, test cards deleted, and the lines of these files before and after.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.

Acceptance criteria

Each test in the files is deleted as covered, converted to a library scenario that the oracles play, or kept because it calls an internal. The close reason gives the counts and the lines before and after.
