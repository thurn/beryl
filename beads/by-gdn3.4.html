Close reason

Cheap source checks run first in the fast check; just precheck for staged files

Description

What we see

In three days, 180 of 433 fast-check runs failed (42%). 80 of those failed repo:file-length, 19 failed python:pyre and 16 failed repo:markdown. Each failure costs the agent a full enact push cycle: a rebase onto origin/staging, the build, and the checks that ran before the failing one.

Why

These checks need no build and take about 3 seconds, but they first run during enact push, after the rebase and alongside the slow lanes.

Change

Run the cheap source checks before anything expensive, and stop the push if they fail.

  • Make by check run the repo and names lanes and the changed-file formatters first, and fail before starting the rust, ui-test and shots lanes when one of them fails.
  • Add a just recipe (and, if it fits the worktree setup, a git pre-commit hook installed by enact worktree create) that runs the same cheap checks on the staged files, so an agent sees the failure at commit time.
  • For file-length, print the file, its length and the 800-line limit, and mention the check in the worktree's instructions only if the root AGENTS.md does not already cover it.

Files

tools/src/beryl_tools/checks.py, file_length.py, hygiene.py, tools/tests/test_checks.py, justfile.

Done when

A commit that takes a file over 800 lines fails within 5 seconds, before any build starts, and a test in test_checks.py covers the ordering. The measurements behind this bead are in its parent, by-gdn3.
