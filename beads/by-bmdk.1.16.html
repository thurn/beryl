Landed and fast-checked dependency-free in-memory and localhost links at 606a16f1

Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'The link' and the beryl-local: invite form under 'Connecting over the internet'.

Create rust/crates/beryl_link with no dependency on any other Beryl crate.

  • src/lib.rs: the trait exactly as the doc gives it (send, blocking receive, peer), LinkError::{Closed, Refused(String), Io(String)}, PeerInfo { name, route: Route, round_trip: Option<Duration> } with Route::{Memory, Local, Direct, Relayed}. Add fn try_clone_sender or split into a sender and a receiver half if the host loop needs to send from one thread while another blocks in receive; choose one and document it in the trait's comment, because every implementation and the protocol bead follow it.
  • src/memory.rs: pub fn pair() -> (MemoryLink, MemoryLink) over std::sync::mpsc. A dropped end makes the other's receive return Closed. Add fn sever(&self) so a test can cut the connection without dropping the value.
  • src/tcp.rs: TcpHost::listen() -> (TcpHost, Invite) binds 127.0.0.1:0; TcpHost::accept(&self) -> TcpLink; TcpLink::connect(&Invite). Frames are a 4-byte big-endian length then the bytes; refuse a frame over 8 MiB.
  • src/invite.rs: Invite::Local { port, secret } printed and parsed as beryl-local:52114:3mxd; Invite::Remote(String) for anything starting beryl: (opaque here; the iroh bead decodes it). fn secret() -> String: 8 random characters. Use std::hash::RandomState or the system time and process id mixed, since there is no random-number dependency; say so in a comment. Parsing a malformed code is a clear error.

Tests in tests/: a frame round trip on each link; ordering of 1,000 frames; Closed on drop and on sever; an oversized frame refused; invite print and parse. The TCP test binds port 0 and must not be flaky: no sleeps, join threads. Run just test-rust -p beryl_link.

Acceptance criteria

Link, MemoryLink and TcpLink exist with the listed tests; the crate depends on no Beryl crate; no test sleeps or uses a fixed port.
