Description

Record which source lines each browser check executes (plan K19; docs/project-50k.md, Target architecture, Checks, "Selection", and Risks, "Selection misses"). Step two of the CI track (by-w8gv.20); read the epic first.

Why

The fast check cannot run the whole browser suite: slow-CI ui-test takes 92-158 s and shots 59-115 s against a 60 s budget. By-file choice fails because Board.tsx changes in a quarter of all commits. Measured coverage says which checks a diff can break.

What

  • by coverage (just coverage): runs every ui-test check and every shot in Chromium (BERYL_BROWSER=chromium; capture.mjs launch() already switches on it, and shots.py browser_env installs Playwright's browser) with Playwright's page.coverage.startJSCoverage({resetOnNavigation: false}) and startCSSCoverage, one page per check, so each check's coverage is its own.
  • Map V8 byte ranges to original source lines through Vite's source maps, so the result names ui/src files and line numbers, not served URLs. Probe this first. The dev server serves each module transformed with an inline source map. CSS imported by modules arrives as JS-injected <style> elements with no URL, so CSS may need vite preview of a build with build.sourcemap and css.devSourcemap, or file-level granularity. Pick what maps cleanly, say which on the bead, and keep JS at line granularity. A Node source-map decoder is a devDependency in ui/ only if it earns its place: a VLQ decoder is about 40 lines.
  • Write $BERYL_CACHE/ci/coverage/<commit>.json: per check id (the run log's ids: ui-test:<title>, shots:<name>, from runlog.py and recordResult() in capture.mjs), the set of {file: [line ranges]} executed. Add latest.json naming the newest and its commit and time. Also record, per check, the fixtures it loads (check()'s fixture option; for shots, shots.json's fixture or board), which the selection bead uses for Rust changes. Keep the format keyed on check ids, so later checks (verb:<name>/<seat>/<layout>, from the presentation track by-w8gv.21) need no format change.
  • Coverage runs are not checks: they write no runs.jsonl records and never fail on a check's failure. Record which checks failed in the coverage file.
  • Under utility QoS (system.py's taskpolicy helper, as just tournament uses), in a detached worktree of a given commit (default origin/staging), with warm.ensure().

Files

tools/src/beryl_tools/shots.py (ui_test, ui_shots, served_ui, record_fixtures, browser_env, BROWSER), a new tools/src/beryl_tools/coverage.py, cli.py (register), justfile. ui/scripts/capture.mjs (launch, workers, recordResult), interactions.mjs check() (about line 168; the body runs per fresh context), shots.mjs. Paths: paths.cache_root().

Tests

pytest in tools/tests for the line mapping (a tiny source map fixture) and the file format. By hand: just coverage once, then confirm that a check you know touches a component (e.g. a combat check and ui/src/game/combat.ts) lists that file's lines, and that a shot does too. Report wall time and file size on the bead.

Need not read

verdicts.py, oracles.py, the Rust crates.

Acceptance criteria

just coverage writes $BERYL_CACHE/ci/coverage/<commit>.json mapping every ui-test check and shot id to ui/src files and lines (and fixtures); pytest covers the source-map line mapping and the format; wall time and size reported on the bead.

Derek Thurn2026-11-11

Measured (jarvis, utility QoS, machine shared with other sessions): just coverage --commit HEAD (detached worktree, warm clone, fixtures, both lanes, mapping) took 377 s wall, 1347 s user; the file is 7.9 MB for 437 checks (321 ui-test, 116 shots). Mapping V8/CSS ranges to lines takes 2.3 s; the rest is the browser lanes under block coverage. An earlier --here run took 544 s on a busier machine.

Granularity: JS and CSS both at line granularity, from the dev server. Each module is served with an inline source map. CSS reaches the page as <style> elements with no URL, which Playwright's CSS coverage drops, so capture.mjs uses CDP CSS.startRuleUsageTracking, names each sheet by Vite's data-vite-dev-id attribute and maps through its inline map. That needed css.devSourcemap: true in vite.config.ts, which is unconditional and dev-only. No vite preview build is needed. No npm dependency: the VLQ decoder is in Python (coverage.py).

Fixtures are measured as the /fixtures/<name>.json requests each page made, not read from options.

Chromium-only failures: 'clicking a scried card sends it to the bottom' failed in all three runs (it passes in WebKit CI). The Staff's Spirit pair failed in one run. They are recorded in failed and still carry coverage.

files: null for two checks that run ui/src code in Node with no page (log names, untap picks), so no selection can rule them out.

Incident: while probing, I killed a stray Vite on port 5791 that belonged to worktree by-isv.4. Its run may have failed once.

Handoff: tools/src/beryl_tools/coverage.py holds the VLQ/source-map decoding (segments, line_starts in UTF-16 units, flatten for V8's nested ranges, Mapped), build() (raw JSONL to the per-check entries), write() (<commit>.json plus latest.json; a dirty --here run writes <commit>-dirty.json and leaves latest alone), measure_here(), and measure() (a detached worktree in $BERYL_CACHE/ci/coverage/trees, which runs that commit's own python -m beryl_tools.cli coverage --here with PYTHONPATH set). ui/scripts/capture.mjs: coverage(page) returns finish(); recordResult takes an optional covered argument and appends to $BERYL_COVERAGE/checks-<pid>.jsonl. It is wired into interactions.mjs check() and shots.mjs capture(). shots.browser_env takes a browser argument. Format: {format:1, commit, dirty, time, seconds, lanes:{ui-test,shots exit codes}, failed:[ids], checks:{id:{outcome, seconds, fixtures, files:{repo-relative path:[[first,last],...]}|null}}}. Selection bead: latest.json names a commit that may not be on staging if someone measured a local commit. Reviewer: check that a range starting mid-segment is ignored (segment start offsets decide) and that the JSONL only grows per process.
