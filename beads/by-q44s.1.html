Description

The workspace and its checks, the core's contract, step timing moved into the session, one recording's table drawn offscreen by the real renderer, the agent tool, one prompt bar through the flat layer, the frame gates, the desktop host, and the table drawn once in the iOS Simulator and the Android emulator. Doc: 'Components', 'The frame', 'Determinism', 'Hosts', 'The table', 'Rendering' (Baseline), 'Card faces', 'The agent interface', 'Performance gates', 'Checks and isolation'.

How it runs. Two beads come first and in order: the paths rule (by-q44s.1.1) and the workspace (by-q44s.1.45). The contract (by-q44s.1.2) follows, alone and small. After it, each crate and module is a track of its own, and the beads that play a whole recording or measure come last. The timing types, the recorder library and the image cache crate start at once, beside the first two.

Exit checks:

  • A change under rust/beryl3d or data/beryl3d runs the lanes repo, names and beryl3d and no other, and no other change builds or runs Beryl 3D's code.
  • just b3d lists its commands. just b3d tree verbs-zones --at 1500ms prints the table's cards with positions, and just b3d png verbs-zones --at 1500ms draws the same frame offscreen in the Baseline tier.
  • just b3d check verbs-zones runs the interface checks on every tick, and just b3d test runs every interface test from the recordings pack with no engine, as a step of the beryl3d lane.
  • After a one-line edit to the client core, just b3d tree answers within 3 seconds and just b3d png within 6, or a bead says what stops it.
  • The renderer draws every gated board with the GPU device's limits clamped to wgpu's downlevel defaults.
  • just b3d gate holds the work counters and zero allocations per frame in the lane, and the sweep holds instruction and fragment counts for stress-255, stress-1024, verbs-zones and pay-default in beryl3d-bench.
  • just b3d smoke starts the app with no window and sees its first frame, and an agent's run of the app writes a frame log it can read.
  • Every script the session sends carries one StepTiming per step, and no TypeScript code chooses a step's case, waits or effects.
  • just b3d tree pay-default --at prompt:1 and just b3d png show a prompt bar laid out by taffy with text shaped by parley.
  • verbs-zones plays in the iOS Simulator and in the Android emulator, on Vulkan and on OpenGL ES 3.0, or a bead says exactly what stopped a path.
  • The doc's 'Measurements' section holds numbers measured from Beryl 3D itself, and the prototype is deleted.

Spike answers (by-q44s.1.31, 2026-11-15). Measured in the new beryl3d-bench Lima VM (just b3d vm; Ubuntu LTS, Rust 1.98.1, gungraun-runner 0.20.0, Mesa 26.0.8 llvmpipe). The throwaway code was rust/beryl3d/spikes (deleted; its own [workspace] with taffy =0.15.1, parley =0.13.0 default-features off + std, wgpu =30.0.2, pollster =1.0.1, gungraun =0.20.0, Open Sans variable font from google/fonts ofl/opensans/OpenSans[wdth,wght].ttf, sha256 36643644…adb878). To reproduce, recreate it and run from a worktree: just b3d vm bash -c 'cd beryl3d/spikes && export CARGO_TARGET_DIR=$HOME/spike-target GUNGRAUN_HOME=$HOME/spike-gungraun; for i in 1 2 3; do cargo bench -q --bench text_counts; done' just b3d vm bash -c 'cd beryl3d/spikes && export CARGO_TARGET_DIR=$HOME/spike-target; cargo build -q --release --bins; for i in 1 2 3; do $CARGO_TARGET_DIR/release/fragments; done; $CARGO_TARGET_DIR/release/weights'

  1. taffy and parley do identical work on every run: YES. Instruction counts, identical on 3 of 3 runs: taffy row of one text and three buttons 19,795; parley "Pay {1}{U}" cold 119,859 / warm 36,114; 200-character rules text at width 300 cold 495,944 / warm 401,866 ("cold" = fresh FontContext and LayoutContext with system fonts off; "warm" = the same texts shaped once before counting). Decides: the design stands, no bead filed, by-q44s.1.36 keeps its dependencies. Caveat recorded in the doc: fontique and parley keep hashbrown maps with foldhash's per-process seed; the counts did not vary under Callgrind, so the gate's run-twice rule holds the dependencies and the no-seeded-hash rule binds Beryl 3D's own code.
  2. llvmpipe counts fragments exactly and leaves out depth-rejected ones: YES, both. wgpu 30.0.2 on Vulkan (adapter "llvmpipe (LLVM 21.1.8, 128 bits)", type Cpu, PIPELINE_STATISTICS_QUERY supported), 256x256 target, Depth32Float, compare Less, a 4,096-pixel opaque quad in front of a 16,384-pixel one: far first 20,480, near first 16,384, on 3 of 3 runs, with Limits::default() and with Limits::downlevel_webgl2_defaults() alike. Decides: the GPU-count bead reads the driver's pipeline-statistics count; the doc's fallback (counting in test code) is removed. Not measured: quads not aligned to 2x2 pixel blocks (helper invocations), which only changes what the count means, not its repeatability.
  3. parley selects a weight from a variable font file: YES. "Counterspell" and "Pay" at 400 and 700 from OpenSans[wdth,wght].ttf: same glyph ids; the 700 run carries normalized coords [10412, 0] (wght, wdth) and wider advances (Counterspell 95.031 -> 102.094 px at 16 px; Pay 26.531 -> 28.812). Decides: the flat-layer slice commits the variable files; its rasterizer must draw each glyph run with the run's normalized_coords().

Texture encoders (from by-q44s.1.15, for the card faces bead): use ctt 0.6.1 with default-features = false and features encoder-astcenc, encoder-etcpak and encoder-bc7f on every platform. iOS and Apple silicon: ASTC 4x4 sRGB through astcenc. Android: ETC2 RGBA sRGB through etcpak. Windows: BC7 sRGB through bc7f. ctt's default features fail on iOS and Android: no prebuilt ISPC kernels exist for them. No pure-Rust encoder is needed. Android must bundle libc++_shared.so. The Windows build is still unproven (by-yt9s, pinned to Cygnus). Also: rodio's playback (cpal over AAudio) cannot load below API 26, so on Android rodio is built without playback and the Kotlin host plays the mixed samples through an AudioTrack. This corrects the epic's 'silent below API 26' default; the doc was corrected in 925afa5.
