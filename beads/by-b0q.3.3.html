Design: a scripted Java harness (tools/oracles/BerylForgeHarness.java), compiled with javac against Forge's jar-with-dependencies and run from forge-gui. No Maven or TestNG. It loads each scenario's GameState text and runs Forge's own game loop, with a PlayerControllerAi subclass for both seats whose priority and questions come from the steps. Forge's gamesimulationtests harness was too thin: no targets, no costs, and it throws on modes and combat damage. With this harness combat is supported. Stopping rules mirror Beryl's runner (beryl_scenario run.rs Runner::position): stop at decisions with more than a pass, at the active player's next priority before a Resolve, and at an AdvanceTo's target. Beryl answers some decisions itself (single or interchangeable candidates, a forced waterbend tap, an optional pick asked as YesNo then which card); the harness does the same. Unchecked: Decision asserts (Beryl's decision surface). Forge-only questions keep the AI's answer and are logged as notes. A planeswalker's printed loyalty is spelled out in the GameState, because GameState otherwise gives it zero counters. Coin flips replay from the dump's trace by forcing Forge's random source. The Forge ability selectors (ABILITIES) and optional-cost labels (COSTS) are tables in forge.py; an unmapped one makes its scenario unsupported. by oracle (oracles.py) is written so XMage can sit beside 'forge' in the same summary.
