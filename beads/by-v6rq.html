Description

Playing Beryl in a window while the Mac runs builds and CI (load 20 to 50) drops frames: the Beryl 3D prototype's window waited 17 to 90 ms for macOS's window server to hand back drawables while its own work took about 1 ms (docs/beryl-3d.md, 'Measurements'). The web app suffers the same. macOS schedules by QoS class, so background work in the utility class lets the window server and the game's frame thread win the CPU even at a high load.

Tournaments already run under taskpolicy -c utility (tools/src/beryl_tools, see rust/AGENTS.md 'Tournaments'). Do the same for:

  • just check and just ci and the cargo builds and test runs they start (tools/src/beryl_tools/checks.py, step_runner.py, rust_tests.py);
  • just test-rust, just card check and other by commands that build or run tests;
  • browser checks keep their current priority, since docs/checks.md says they run above builds on purpose; check that rule still holds and keep it. Never apply it to dev, proto3d, smoke or anything that draws for a person.

The Enact CI runner lives in ~/enact, outside this repository: say in a comment on this bead what it would need (launching by ci under taskpolicy) rather than editing it.

Only while a game is open. The utility class also prefers efficiency cores and throttles disk I/O, so it would slow builds even when nobody is playing. The web app (beryl_app) and Beryl 3D therefore write a marker file, $BERYL_CACHE/playing/<pid>, while a game window is open and remove it on exit; the wrappers start work in the utility class only while a marker names a live process, and at full priority otherwise. A stale marker (dead pid) is ignored and removed.

Measure, with the load beside each number: time just check on a small change at full priority and in the utility class, once with the machine otherwise quiet and once at its usual load, and record all four on this bead. If the utility class costs more than about 10% on a quiet machine, that confirms the marker is needed; say so either way. Windows (Cygnus) has no taskpolicy: use the below-normal priority class there or leave it unchanged, and say which.
