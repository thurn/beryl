Description

Milestone 5 of Project 50k (plan K5 and K3; epic by-w8gv.9): the rules library and the card port. Line numbers and counts below were read at staging f5034c58; the code as it stands wins over this text, and a deviation is a comment on this bead.

Second bead of the library lane. Milestone 6 gave every decision a shape and a purpose (rust/crates/beryl_card/src/prompt.rs: Shape is Pick, Order, Split, YesNo, Number, Mode, Catalog, Divide, Pay, Declare; Purpose is the closed list of what a prompt is for; Prompt carries count, most, places and part). The milestone's scope says: write the library and port the cards against the prompt shapes, never the old Ask variants. This bead makes the library's way of asking a player something while an effect resolves (CR 608.2d: "If an effect of a spell or ability offers any choices ..., the player announces these while applying the effect").

What exists

  • effect/ask.rs (254 lines): ask_options, choose_yes_no, choose_up_to, choose_or_done, choose_object, discard_a_card, discard_cards, discard_one_of, may_choose_object.
  • effect.rs: unless_pays (line 243, about 85 lines: asks, then pays mana in the middle of a resolution, CR 118.12), offer_cast (a card the body lets a player cast as it finishes, CR 608.2g), flip_coin (CR 705, through chance), and the questions inside scry, explore, search_library*, manifest_dread and untap_up_to_lands.
  • The answer record on Resolution (the design bead): a function that asks returns Err(Pause) and the resolution runs again from the top, reading its earlier answers back in order.
  • Card bodies build prompts by hand and ask one object at a time (beryl_cards/src/blue/stock_up.rs asks for each card with Part::First and Part::Second; jace_the_mind_sculptor.rs's brainstorm does the same).

Scope

  1. The asking functions become free functions over Game and Resolution in one module, one for each shape a resolution uses, each taking a Prompt. A decision for a resolution's question is built in that module and nowhere else in rules code.
  2. unless_pays becomes "a player pays a cost or does not" for any cost the engine can take mid-resolution, used by Effect::Unless.
  3. flip_coin and offer_cast move to modules named for their rules.
  4. Say in the module's documentation how an effect that needs several answers asks them (the record replays them in order), so the port's dig, put-back and search entries follow one pattern.

The constraint that shapes this bead

A frozen save and a rollout replay the answers a game gave, in order. The number of questions a resolution asks, their order, their kinds and their options must stay exactly what they are today for every card. So the functions take the shape's vocabulary, but a body that asks five times still asks five times. Where today's sequence is not what a shape would ideally ask (one Split in place of several picks), leave it and list it in a comment on this bead: changing it is a save-format change (beryl_session/src/migrate.rs, data/save-breaks.json), outside this milestone.

Tests: cargo test -p beryl_session --test corpus, beryl_cards/tests/prompts.rs, beryl_session/tests/asks.rs and candidates.rs, cargo test -p beryl_cards.

Need not read: the stage and prompt-state code in beryl_session and ui/ (they read the shapes, which do not change).

Decisions and deviations (the contract in rust/crates/beryl_rules/src/lib.rs is amended to match; read choices.rs's module doc first).

Homes. choices.rs (CR 608.2d): yes_no, pick, pick_or_end, pick_up_to, may_pick, aim, pay, and the Effect::May arm (may_instruction). costs.rs (CR 118): may_pay, pay, and the Effect::Unless arm (unless_instruction). coins.rs (CR 705): flip(game, player, source). casting.rs (CR 601, 608.2g): offer(resolution, object, player, free). effect/ask.rs is deleted; Resolution keeps the answer record and one crate-private method, answer(game, &Decision), which only choices.rs calls.

"One function for each shape" is a small family for each shape, not one function. Why: (1) whether a pick offers an end was said by the decision's kind, not by the Prompt, and Pick has three ways today (one must be taken; one more or the end; a Whether first), so a single pick(prompt) would have to guess; (2) a Split's picks are asked between moves (scry puts each card on the bottom before the next question, and a rollout's policy and the UI look at that state), so one whole-run split function would change what a player sees at a question. So the functions are the question forms, grouped by shape in the module's table, and each checks in debug builds that the prompt's shape and part are ones its question can answer (yes_no: a YesNo purpose or Part::Whether/Instead; pick: Pick/Pick or Split/First|Second; pick_or_end: Pick/Pick or Split/First; aim: Attack/Aim; pay: a Pay purpose at Pick or Plan, which picks the kind). Shapes no resolution asks yet (Order, Number, Mode, Catalog, Divide) have no function; the first effect that needs one adds it there.

Paying. costs::may_pay(game, resolution, player, cost, prompt) is general in the player, the cost and the question (the caller's yes-or-no Prompt, to which it adds the cost); Effect::Unless and the shim's unless_pays call it with Purpose::UnlessPays. The cost is a ManaCost because that is the only cost an effect can name (Effect::Unless's operand) and the only one the engine can take mid-resolution; the cost bead (by-w8gv.9.12) gives a cost its parts and widens this parameter. As the design bead decided, a capacity that runs out now stops the resolution at once (the old unless_pays and pay noted a flag and played on).

Not moved: the cast offer's own question (Purpose::CastOffer, a Mode) is built in engine.rs from Pending::CastOffer after the resolution has ended; it is the engine's pending question, not one the record answers. resolve.rs still reads resolution.offer.

Shim. choose_yes_no, choose_up_to, choose_object, may_choose_object, discard_a_card, discard_cards, discard_one_of, unless_pays, offer_cast and flip_coin are single-call delegations in effect.rs; EffectCtx::ask_options and EffectCtx::pay are gone. No card file changed. Run::one and Run::carry_out_or_nothing are pub(crate) for the two arms.

Grep (no other rules module builds a Decision for a resolution's question). git grep -n "Decision {" -- rust/crates/beryl_rules/src ':!*/tests/*' gives choices.rs:94 and :162 (the two builders, options and objects) and the engine's pending questions, none of which the record answers: cast/steps.rs:454,483,512,537 (casting), combat.rs:128,298,319,477 (declaring, damage), engine.rs:410 (legend rule, cast offer, discard, mulligan), face_down.rs:131. git grep -n "DecisionKind::" over actions/, interpret/, effect*, resolution.rs and every library module gives choices.rs alone (plus one doc link in actions/search.rs). resolution.answer( is called at choices.rs:101 and :169 only.

Counts, just bench-count before (staging 7a9c4df6) -> after (4f84a003): copy 13,481 -> 13,481; next_apply 361,276,395 -> 361,155,665 (-0.033%); policy 1,746,603 -> 1,746,603; rollouts 388,754,359 -> 388,633,629 (-0.031%; under the bar of 389,343,295, no bump). The saving is pick_or_end filling its option list once where choose_or_done filled one and ask_options copied it.

Tests: beryl_rules 176 (3 new in tests/library.rs: may_pay for another player, cost and question; coins::flip for any source; a prompt asked through another shape's function is refused), beryl_cards with tests/prompts.rs unedited, beryl_session's corpus, asks and candidates unedited, rollouts_never_change, just citations (0 problems), just check.

Where today's question sequence is not what its shape would ask (all left as they are: changing one is a save-format change, beryl_session/src/migrate.rs and data/save-breaks.json).

Split (beryl_card/src/prompt.rs, Shape::Split: the first destination's cards at Part::First, then the order of the second's at Part::Second):

  1. Scry (actions/scry.rs) never asks for the last card of the top: with one card left its place is taken as given by the code, not by the one-answer rule, so the profile that stops at every question (Stops::Forced) is not asked it. Stock Up's bottom (item 2) does ask its last card. A shape function would treat both alike.
  2. Stock Up (beryl_cards/src/blue/stock_up.rs) changes Prompt::count through the run: the whole number looked at while it picks for the hand, then the number still to place at each Part::Second pick. Scry keeps count at N throughout. With two or fewer cards looked at it asks nothing for the hand and opens at Part::Second.
  3. Scry's Prompt::count is the N it was told, not the cards looked at, when the library holds fewer.
  4. Jace's brainstorm (jace_the_mind_sculptor.rs) is a split's first part alone (PutBack, places OnTop/None), two picks with most 2 then 1, each card moved before the next is picked; with fewer than two cards in hand it stops early. That is what the shape asks; listed because it has no Part::Second by design.

Pick (Shape::Pick: an optional Whether or Instead, then a Part::Pick for each object and for the end; Prompt::most is "the objects still to pick"):

  1. A pick of up to N (choices::pick_up_to: actions/search.rs with n > 1, actions/tap.rs untap_up_to) gives every pick the prompt unchanged, so most stays N as cards are chosen instead of falling. Discard's picks do fall (most = left).
  2. A pick of up to N asks no question for the end once N are chosen or no candidate is left; the run just stops. A shape that always confirmed would ask one more.
  3. Thirst for Discovery: after a yes at Part::Instead the one pick carries no object set (about is empty), while the pick after a Part::Whether (choices::may_pick) carries the candidates. The prompt docs require the set only after a Whether.
  4. Discard N with fewer than N cards in hand asks a pick for each card, the last silently (one answer), rather than discarding the hand unasked as Stock Up takes "two or fewer" unasked.

Yes or no, then another prompt (two prompts where one run could open with the yes or no):

  1. Trinket Mage asks MaySearch (a YesNo prompt of its own) and then the search's picks. By design (Purpose::MaySearch: the library is not looked at until the answer is yes), but it is the one place a decline is not the Pick's own Part::Whether.
  2. "Unless pays" is a YesNo (UnlessPays) and then a separate Pay prompt (Mana): by hand, one ManaPayment pick for each source with no end offered (the player said yes and must finish), or one PaymentPlan at Part::Plan. A Pay whose first pick could decline would be one prompt.

Declare:

  1. tokens::create_attacking asks one Part::Aim for all the tokens together (the object set is every token) and gives each the answer. CR 508.4 lets each creature attack something different; a Declare run would aim each. Not reachable with two players and no planeswalker (one answer, unasked), and no card makes several attacking tokens against a planeswalker in the corpus without this question having been recorded as one.

Not differences, for the record: Explore, Fateseal, TopOrBottom, Move, May are one YesNo each; ManifestDread is one pick (most 1, count 2), unasked with one card; may_pick (Thundertrap Trainer, Elite Spellbinder) is Whether then Pick, both carrying the candidates.
