Description

Milestone 7b of Project 50k (docs/project-50k.md, "Card pool pipeline": "Subtypes, counter kinds and similar lists are generated from Scryfall's catalogs, not written by hand"; the audit: "Subtype is a hand-written enum of 32 in a 128-bit set; Types has one free bit"). Lane set-crates, after characteristics are generated from the store (previous bead) and with data/catalogs.json in the tree (the data bead). The next bead builds the vanilla and keyword-only creatures from the store, which need every creature type.

Today

  • rust/crates/beryl_card/src/characteristics.rs:96: pub enum Subtype, 32 hand-written variants ("The cards that need more add them"); :215 pub struct Subtypes(pub [u64; 2]), a 128-bit set. Scryfall's catalogs hold roughly 300 creature types and 150 others, so the whole list does not fit 128 bits.
  • Types and Supertypes are bitsets in the same file; Types has one free bit. Check them against the catalogs' card-types and supertypes (Battle, Kindred and so on).
  • rust/crates/beryl_card/src/counter.rs: counter_kinds!, six hand-written kinds, one list from which CounterKind, its names and every per-kind table are written by macro_rules!.
  • Subtypes is in the flat Copy game state (objects' characteristics, layer results), so its size is in every rollout's instruction count.

What to build

  1. Subtype (variants, names, the card type each belongs to, CR 205.3) generated from data/catalogs.json by a build script in beryl_card, through the shared build helper; beryl_card keeps no runtime dependency. Variant names are spelled out from the catalog's (Subtype::TimeLord); the existing 32 keep their names, so no card file changes. Rules code that names a subtype (the basic land types of CR 305.6, Aura, Vehicle, Treasure, Map) compiles against the generated names. Rule comments stay cited: just citations passes.
  2. A representation that holds the count gate. The design is yours; record it on the bead with the numbers. The constraints: the count gate passes with no bump (405,276,238 instructions, 1%), rollouts_never_change holds, and state stays flat and Copy (docs/engine-architecture.md). Options, in the order I would try them:
    • (a) Per-game interning, as cards already get game indices from the decklists (beryl_kernel/src/table.rs, GameTable::new): the GameTable numbers the subtypes the two decks, their tokens and their effects can name; state keeps a 128-bit set of game-local indices; a game needing more than 128 fails GameTable::new with a TableError, as other bounds do. An effect that lets a player name any creature type (CR 205.3m) then needs the named type interned: none of the 47 cards has one, so say what a future one does.
    • (b) Widen Subtypes to cover the catalog ([u64; 8]) and measure with just bench-count. Take it only if it is inside the gate.
    • (c) A split: a small inline set for land, artifact, enchantment, spell and planeswalker types, and interned creature types. Changeling ("every creature type", CR 702.73) must be expressible as a set in whichever you choose.
  3. Types and Supertypes generated from the catalogs, or held to them by a test, with room for every card type in the pool. Widen the integer if needed, and measure.
  4. counter_kinds! generated from the catalog file's counter list in the same way, keeping the six kinds' variants and names (PlusOne = "+1/+1" and so on) and the $with! protocol other crates' tables use (grep -rn "counter_kinds!" rust). If per-kind tables in the state grow with the list (a count per object indexed by kind), that is the subtype problem again: apply the same answer and say so. If the whole list cannot hold the gate after three attempts, generate the type from the catalog, keep state keyed by the kinds a game uses, record the measurements, and file one follow-up under this epic.
  5. Saves: check how Subtype and CounterKind are written in saves and transcripts (beryl_session/src/save.rs, checkpoint.rs); by name is safe, by number is not once the list is generated. The corpus replay proves nothing moved. A save break goes in data/save-breaks.json only if no migration can carry it; expect none.
  6. The characteristics generator from the previous bead maps a store type_line to the generated Subtype for every pool card. A test parses every pool record's type line (32,496 cards; it is fast).

Files

  • rust/crates/beryl_card/src/characteristics.rs, counter.rs and a new build.rs; beryl_kernel/src/table.rs and wherever Subtypes is stored and combined (grep -rn "Subtypes" rust/crates/beryl_kernel/src rust/crates/beryl_rules/src first); the type-changing layer in beryl_rules (CR 613.1d).
  • just bench-count and docs/benchmarking.md for measuring; rust/crates/beryl_bench/count-gate.toml (never raise the bar).
  • Need not read: card files (they should not change), the UI, tools beyond the catalogs' reader.

Tests: just test-rust; just bench-count before and after, both on the bead; just fuzz for ten minutes; just citations. A rules-engine bug you find and fix gets a docs/bugs.md entry.

Parity at the push (plan K11)

just check passes; the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds; slow CI's counts lane (just count-gate, bar 405,276,238 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. Never delete a card implementation. Work the card-names and file-length allowlists down in the files you touch. Record decisions and anything this packet got wrong as comments on the bead; nobody answers questions (K31): proceed on the default given and record it.

Design (recorded per K31): option (a), per-game interning. beryl_card::Subtype (539 variants: 535 from Scryfall + 4 pool token artifact types) and counter_kinds! (238 kinds) are generated by beryl_card's build.rs through beryl_card_build::catalogs from data/catalogs.json. Faces keep a global beryl_card::Subtypes ([u64; 9], static data only). The state keeps beryl_kernel::subtypes::GameSubtypes ([u64; 2]) by numbers GameTable::new gives every subtype the game's cards print, ask about (Filter::Subtype) or give (Modification::AddSubtype, in static abilities or effect data; CardDef::subtypes walks them). Bit 127 = every creature type (changeling, CR 702.73a: Subtypes::every(Types::CREATURE) on a face takes that bit instead of 377 numbers). >127 numbered subtypes fails GameTable::new with TableError::Subtypes. A future 'choose a creature type' card (CR 205.3e): the table reserves a number per such choice and binds it as the choice is made; none of the 47 has one. A Rust body adding an unnumbered subtype trips a debug_assert. Option (b) measured first: [u64; 9] in Derived puts State at 27 KiB (128 derived slots x 56 bytes), over the 20 KiB assert, so rejected without benching.

Types: u16 with ARTIFACT..PLANESWALKER plus BATTLE, KINDRED in the low byte, INSTANT/SORCERY/CONSPIRACY above it (CR 110.4); Supertypes gains SNOW, WORLD (u8). Held to the catalogs by catalogs::tests::the_engine_types_are_the_catalogs; every pool card's and token's type line parses (catalogs::tests::every_pool_type_line_reads, 32k+ faces; python test_catalogs too). Lki stores PermanentTypes(u8) so stack entries/pending triggers stay their size: State is 20,216 bytes, exactly as before.

Counter kinds: kept PlusOne/MinusOne/Loyalty/Time/Story/Chorus names; P/T kinds spelled PlusOnePlusTwo etc. Saves and transcripts write kinds by name (checkpoint.rs CounterName), Subtype is in no save: corpus replays unchanged, no save break. Counter table rows stay 3 bytes (CounterKind u8, 238 < 256). CountersHeld (LKI in every resolution's 8 Known registers) was a count per kind: 238 bytes. Now fields + 6 table rows (15 bytes), debug_assert past 6. No budget fallback needed.

Catalog gap: Scryfall's artifact-types catalog lacks Heartwood, Lander, Mutagen, Vibranium (token types). catalogs.py with_pool_subtypes adds a pool subtype no catalog lists to its card type's catalog; just cards regenerated catalogs.json (only those 4 + the rule line changed).

Protocol: Counter mirror now has 238 variants (protocol.ts regenerated); UI log names any kind (P/T kinds as +1/+2), badges only the kinds with icons.

Counts (rollout_counts rollouts corpus, just bench-count in the VM): before 389,798,599 (staging 4804b7b4); first try 406,981,383 (+4.4%: runtime Subtypes::every in SubtypeNumbers::of, 238-byte CountersHeld); after const + compact LKI 396,486,992; after per-subtype test masks 395,991,562; after gating the SBA Aura check on the game having an Aura (WU Control has none) and face-down short-circuit 390,135,389 (+0.09% vs before, +0.20% vs the 389,343,295 bar). Bar unchanged. rollouts_never_change holds unchanged; corpus_never_changes pin moved 1187386380224025852 -> 18043264653755743742 because the state's bytes changed (Types u16, renumbered bits, game-local subtype numbers), not its games.
