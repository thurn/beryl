Long-think runner behind just longthink in staging fabd4d6: resumable mid-game (byte-identical after random kill -9), supervised, locked, upgradable in place

Description

Part of the long-think epic (its D2, D3, D6, D7). An open-ended, resumable tournament for the long-think ladder: a beryl_cli subcommand behind just longthink, which builds the search profile and runs under nice -n 10. The recipe needs no arguments: whenever it is run, it starts the ladder or resumes it. Whatever stops it (Ctrl-C, a kill, a crash, a reboot, a power cut), running it again loses at most the one decision being searched. just longthink --status prints the summary without playing.

This bead builds the tool and smoke-tests it. Nothing here runs the ladder itself.

  • Schedule: rungs 3k, 10k, 30k, 100k, 300k, 1M, ... (x~3). Seeds are 30 pairs, each played from both seats, the same on every rung. The cheap rungs (3k-30k) run their 60 games first; then the next rungs up alternate a seed pair at a time, so stopping leaves them on the same seeds. A new rung opens when the top one has 60 games against its opponent.
  • Opponents: expert-frozen on every rung. A rung that beats it 85%+ over 60 games also plays the rung below it. The top rung reached also plays mcts-omniscient at its budget against the expert, as a hidden-information diagnostic.
  • One game at a time, its search on all cores (parallel trees), so results arrive soonest.
  • Output, in the run directory under $BERYL_CACHE:
    • games.jsonl, a line per finished game: rung, opponent, seed, seat, outcome, turns, wall seconds, rollouts spent, decisions searched;
    • decisions.jsonl, a line per searched decision: game key, decision index, rung, the root's visit counts and mean reward per candidate, rollouts spent (training data: the games replay from the seed under the pinned binary, so states need not be stored);
    • transcripts per game;
    • summary.txt, rewritten after every game: per rung and opponent the win rate, Wilson 95% interval and games; Elo per tripling of budget; the rung-v-rung chain; cost per game.
  • Extraordinarily resumable:
    • Games resume mid-game. Each decision's answer (and, for searched ones, its root statistics) is appended to the game's log and flushed before the next decision. On resume the game replays from its seed through the logged answers, at engine speed (~4 µs a decision), and the search picks up at the first unanswered decision. A 1M rung decision is ~30 s of a ~72 min game: that is the most a stop can cost.
    • That needs agents with no hidden running state: by-2l8.2 seeds each search from (agent seed, decision index) rather than a stream advanced per call, and the expert replays its own decisions for real (cheap, deterministic). A replayed game must reach the same state as the uninterrupted one: a test kills and resumes games at random decisions and compares final states and transcripts with uninterrupted runs. Subtree reuse (by-2l8.2) is lost at a stop, so a resume inside a reused chain re-searches from the chain's first decision, keeping moves identical.
    • Crash-safe files: everything is append-only JSONL, flushed and fsynced per line; a torn last line from a power cut is detected and dropped. summary.txt is derived, written to a temporary file and renamed, and rebuilt from the logs whenever it is missing.
    • Its own binary: a run copies the binary it was started with into its directory and always resumes with it, so later commits never change a run's agents or mix results. just longthink resumes the latest run; when the current code would play differently (the git tree ids of beryl_engine, beryl_cards and beryl_search differ) it says so and keeps going on the old binary; just longthink --new starts a new run on the current code. Old run directories are kept, each resumable by just longthink --run <dir>.
    • In-place upgrades: just longthink --upgrade adopts the current code's binary into the running ladder's directory only if it plays identically: it replays every logged game through its logged answers to the same states, re-searches a sample of the cheapest rung's searched decisions (say 200) at their logged budgets and seeds, and gets the same answers. Then perf work (by-2l8.6, ai-strategy step 2) speeds a run without restarting it; anything else is refused with the first differing decision, and --new is the way.
    • One runner per run: an exclusive lock on the run directory (std's File::try_lock); a second just longthink says which process holds it and exits.
    • Supervised: if the runner dies abnormally (a panic aborts under the search profile), the recipe restarts it, and it resumes. A game that crashes twice at the same decision is recorded as crashed, with its seed and decision index for a bug report, and the run moves on.
    • Sleep: the recipe runs under caffeinate -i, so an idle Mac doesn't sleep mid-run.
  • The opponent is a configuration value. Until expert-frozen exists (by-2l8.1) the smoke tests use expert; by-2l8.4 makes expert-frozen the default.

Acceptance criteria

  • just longthink with no arguments starts a run in an empty cache, and resumes it when run again.
  • A smoke run of 4 games at a 1k rung writes games.jsonl, decisions.jsonl, transcripts and summary.txt, is killed mid-game, resumes, and ends with exactly the 4 games once each.
  • The schedule (cheap rungs first, then alternating pairs, new rungs, rung-v-rung once a rung passes 85%) is unit-tested without playing games.
  • Wilson intervals and Elo per tripling are tested against hand-computed values.
  • Kill -9 at random decisions (including mid-search and mid-write) across a smoke run at a 1k rung, resuming each time: games.jsonl, decisions.jsonl and transcripts end identical, byte for byte, to an uninterrupted run of the same seeds.
  • A truncated last log line is dropped on resume; a deleted summary.txt is rebuilt.
  • After a commit to beryl_search, just longthink resumes the old run on its stored binary and says the code differs; --new starts a fresh run directory.
  • A second concurrent just longthink on the same run exits naming the first.
  • An injected panic is restarted by the supervisor; a twice-crashing game is recorded as crashed and skipped.
  • just longthink --status prints summary.txt and plays nothing.
  • --upgrade adopts a binary that differs only in speed (a test builds a variant with a no-op change) and refuses one that changes a move, naming the first differing decision.

Design as built (executor): • beryl_cli longthink (supervisor, fresh binary) picks the run ($BERYL_CACHE/longthink/run-NNN; latest, --new, --run DIR), copies itself in on start, records git tree ids of beryl_engine/cards/search (working tree included, via a temp index) in code.json, then runs <run>/beryl_cli longthink-run <dir> and restarts it on exit 101 or SIGABRT/SEGV/BUS/ILL/TRAP (gives up after 10 crashes with no game finished). Any other stop (Ctrl-C, kill, an error) ends it. • --games N means: stop once the run holds N games in total (so smoke runs and resumes compose). • Schedule (pure fn of committed games): cheap rungs in order, each to its pairs (plus the rung below if it scored 85%+ over its first pairs); then rungs above open one at a time when the one below has its pairs v opponent; the newest and the one below alternate a pair at a time; the lower one's turns go to whichever of {opponent, omniscient at its budget, rung below if 85%+} has played least. Read 'alternate' as top-two strict alternation: every other reading I tried degenerates into pure climbing. • Resume: every decision logged per game (logs/<key>.jsonl: seat, choice, the search's resume_point, root stats, ms). Replay takes a search's logged answers up to its last line's resume point (inside a reuse chain, the chain start) and re-searches from there, comparing to the log; other agents are asked for real and must match. Lines carrying a search are fsynced; others are written unsynced (a sync is ~9 ms here; a power cut loses only answers replay recomputes at engine speed). Commit order: transcript (tmp+rename+dir sync), decisions.jsonl, clock.jsonl, then games.jsonl as the commit point; on start the runner cuts torn tails and any uncommitted game's suffix from decisions/clock, and always rewrites summary.txt. • Deviation: wall seconds are in clock.jsonl, not games.jsonl, so games.jsonl, decisions.jsonl and transcripts depend on the seeds alone (the kill-and-compare criterion asks for byte identity). • Crashes: a panic hook appends {game, decision} to crashes.jsonl; a game with two crashes at one decision is recorded outcome crashed, crashed_at, and skipped. Fault injection for tests: BERYL_LONGTHINK_PANIC=<game>@<decision>. • --upgrade: replays every committed game through its log (other agents for real) and compares transcripts byte for byte, replays the game in progress, re-searches up to 200 evenly spaced fresh searches (chain == decision) of the cheapest rung and compares choices, then copies the binary in and rewrites code.json. Tests cover this in-process with substituted agent builders; the binary-level check was done by hand (below). • beryl_search now exports Search; tournament::wilson takes f64 wins (draws count half).
