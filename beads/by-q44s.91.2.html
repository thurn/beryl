Description

Read the epic's contract first; this bead builds against it. Doc: docs/beryl-3d.md, 'Migration and compatibility' and 'The agent interface'.

Layout differences (a label 6 points to the right, a line wrapped onto two lines, a life total drawn over "on the play") are exact numbers once each web element is paired with its Beryl 3D element. Today an agent has to spot them by eye.

Change:

  • Matcher. Write joined.json from a snapshot. First pair elements by key. Then pair keyless elements by role, name and parent, and then by role and the nearest box within a tolerance. Everything left over is listed as unmatched, on each side, with its role, name and box.
  • Box diff. Add just b3d match boxes <target>, which prints one line per paired element whose box differs by more than 0.5 points or whose number of text lines differs, worst first. The line format is: key, web box, b3d box, then dx, dy, dw, dh, then WRAP or LINES n/m. Also print overlaps that one side has and the other doesn't: two elements whose text boxes intersect in Beryl 3D but not on the web. That catches the text-over-text bugs (by-q44s.9.52) directly.
  • --all runs every desktop and phone test target (just b3d test's names) in parallel, sized by beryl_inspect::runner::threads, and prints a total per target.

Files: tools/src/beryl_tools/beryl3d/match/, rust/beryl3d/crates/beryl_scene/src/agent/text_overlap.rs (for reference), data/beryl3d/match/roles.json.

Acceptance criteria

match boxes prints paired box differences, unmatched elements and one-sided overlaps for any target, and --all runs every test target. A test covers the matcher's three pairing passes.

Handoff: just b3d match boxes <target> and --all [prefix] are on staging (760932a29).

Where things are:

  • tools/src/beryl_tools/beryl3d/match/joined.py: join(web, b3d) makes the three passes (key; identity = role + name-or-object + "same parent"; box = same role, nearest box within TOLERANCE = 24 pt). "Same parent" means the nearest already-paired ancestors are each other's pair (or neither side has one), because the web nests far more unnamed wrappers. Only elements with a name or an object take part in the identity pass. ensure(dir) writes joined.json each time (cheap, not cached). as_box/index are typed helpers that later subcommands can reuse.
  • match/boxes.py: differences (box over 0.5 pt, or WRAP/LINES n/m, worst first), one_sided_overlaps (paired elements whose text lines intersect on one side only, with 1 pt of slack as in agent::text_overlap, leaving out an element paired with its own ancestor), find(dir) -> Found with .total() for a score bead to reuse, and run_all.
  • An element's lines include those of its unpaired descendants (gathered), because the web puts a button's label on a span inside it. Line counts are compared only when both sides have text: a full-window scrim paired by box otherwise gathered every unpaired line under it. Text missing on one side shows up as an unmatched element instead.
  • Rust: b3d test --list (with --phone-only, a prefix) prints test names without playing them. --all reads it twice, so it covers desktop and phone.
  • snapshot.py: the new shared() builds both programs once and starts one Vite server; ensure(..., serving) uses them. dump.mjs now serves the fixture from the snapshot directory through a Playwright route, because a server running with BERYL_UI_FIXED watches no files and returned index.html for a fixture written into ui/public after it started (the page error was "The string did not match the expected pattern"). Snapshot no longer writes anything into ui/public. Fixture names have a uuid, so threads don't collide.
  • --all takes a CPU lease (tokens.acquire, largest of the pool) and runs that many threads. Pages also wait for browser slots.

Verified: unit tests for the three passes, the box diff, WRAP, ancestor exclusion, and a child label counting as its button's text. boxes ran on opening-play prompt:1 desktop@2 and on verbs-zones 1500ms phone. --all opening-play ran 14 targets in 14 s with 0 failures. Pyre and clippy are clean, and the fast check passed.

For reviewers and later beads: web keys are always null today, so the key pass pairs nothing yet; identity and box do the work. The web keeps about 10 times as many elements, so the unmatched-web count is large (220 on the opening prompt) and the score bead should probably not ratchet on it as is. The full --all (about 680 targets) has not been run end to end. At about 1 s per target with parallel threads, it should take roughly 10–15 minutes.
