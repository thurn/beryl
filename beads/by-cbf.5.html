Close reason

Large has 1,024 u16 slots, grown nested queues, options and temporaries; promotion tests per kind; State<Small> 20,440 B; count gate 405,147,828 (bar lowered); follow-up by-cbf.6 for mana solver capacities

Description

Follow-up to by-cbf.2, which added the Large layout (Vec queues, per-slot tables) and session promotion on Stalled(Capacity). Large still shares these Small capacities, so a player game past them still ends Stalled(Capacity):

  • Object slots: Slot is NonZeroU8 (255 slots: 120 deck slots, 135 for tokens and spell copies) and Bitboard is [u64; 4]. Make the slot and bitset types Layout associated types (Large: u16 or wider slots, a growable bitset), which reaches Object, ObjectRef, Target, Pending, Decision/Opt, events and Observation (the spike's notes on by-cbf.1 list them).
  • Queues nested in values rather than in State: StackEntry.targets (8), Player.emblems (4), Resolving.record (32).
  • A decision's options (Candidates::Options is Fixed<Opt, 64>, Choice is u8, Opt::Trigger(u8)): more than 64 waiting triggers or targets stalls in either layout.
  • Engine-local Fixed temporaries sized to Small (combat.rs 128, layers.rs 192, trigger.rs next_to_stack 64, effect.rs 64/60, event.rs 128) and the battlefield_index u8.

Keep Small unchanged (size, count gate). Extend crates/beryl_session/tests/promotion.rs with a scenario past one of these (for example a token count past 135, or more than 64 stack entries).

Acceptance criteria

  • A player game past any capacity listed continues instead of stalling (a session test per kind: slots, a nested queue, decision options).
  • size_of::<State<Small>>() unchanged; just count-gate passes with the bar unchanged.
  • just fuzz still covers Large games.
