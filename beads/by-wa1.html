Description

The docs/ui_mockups images are generated references, not a pixel spec: they are not consistent with one another, and earlier pixel-matching work fitted code to each one separately. This bead removes one such fit. Prefer one rule that holds in every state over matching any single mockup. just ui-compare verdicts for the affected regions may get worse; that is expected, so do not tune values back toward the mockups.

The phase tracker (ui/src/components/Controls.tsx) has two unrelated icon sets: icon for the full tracker, which the gallery shows as the design system, and glyph for the compact tracker the game draws on the table. The same phase looks different in the two places. The compact tracker's CSS (design/components.css, the .phase-tracker-compact rules) is fitted glyph by glyph to battlefield.png and combat.png: nth-child rotations and nudges on the second and fourth glyphs, a different stroke for the third when unlit, a 1.1 scale on the lit combat glyph, a lit tab drawn only for the third child, and a tab filled with #5a4d46, a hard-coded copy of the table's local color, so the rule breaks under it. The full tracker's arrows have deliberately uneven margins ("Spaced as in the mockup, which is not quite even").

Use one icon set for both trackers, with the compact one differing only in size and in the lit state's treatment. Style every phase the same, with no nth-child exceptions; give the tracker even spacing; draw any tab without a hard-coded background color.

Acceptance criteria

Both trackers draw the same icons; no nth-child exceptions or hard-coded table colors in the tracker's CSS. just check and just ci pass, with no new constants tuned to a single mockup.
