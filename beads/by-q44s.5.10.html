Description

Read first: the epic by-q44s ('Rules for every bead'); rust/beryl3d/AGENTS.md; docs/beryl-3d.md 'Elements', 'Text', 'Hosts' (text entry: on phones a native field over the element, Request::BeginTextEntry; on the desktop the field is edited in place). Code: beryl_scene src/widgets/field.rs (field, FieldState), src/text/mod.rs, src/input.rs (Input::Text, TextChange, Key), src/command.rs (Request); beryl_host src/desktop.rs and src/events.rs (how winit's events become Input). Read parley 0.13's editing support (parley::editor::PlainEditor or the module of that version that offers cursor, selection and editing on a layout) and winit 0.30's WindowEvent::Ime and Window::set_ime_allowed.

Build:

  1. beryl_scene src/widgets/field.rs: field(name, state) is role Field, focusable; typing, Backspace, Delete, left and right (with Shift to select), Home and End, double-click to select a word, a drag to select, Cmd+A (Ctrl+A off the Mac). The editing is done with parley's editor over the field's laid-out text, in handle; the caret and selection are drawn as Panel records. The field's text lives in a FieldState the screen owns; the client sends each change as the field's press, Press::Field(ElementId, String) (add the variant).
  2. Copy and paste: Cmd+C and Cmd+X send Request::Copy(String); Cmd+V sends Request::Paste, and the host answers with Input::Paste(String) (add both).
  3. Input methods: Request::BeginTextEntry on the desktop host calls set_ime_allowed(true) with the field's rectangle as the candidate area; Ime::Preedit shows the composing text underlined at the caret, and Ime::Commit inserts it, both as Input::Text. EndTextEntry turns it off.
  4. beryl_host: the clipboard through arboard 3.4.1 (Cargo.toml comment: replaces hand-written pasteboard calls), on the host's thread, never the frame's work.

Do not build: the phones' native field (milestone 4).

Tests: in beryl_scene/tests/widgets.rs, typing 'abc' then left, left, Backspace leaves 'bc' with the caret at its start (write each test with the driver's type_text and key actions); Shift+left twice then Cmd+X sends Request::Copy of the two letters and leaves the rest; Input::Paste("xy") inserts at the caret; a preedit shows underlined and leaves the field's text unchanged until committed; a field passes 'named' and 'text fits'. In beryl_host, a unit test maps an Ime::Commit to Input::Text.

Run: just b3d cargo-test -p beryl_scene; just b3d cargo-test -p beryl_host; just b3d lane.

Deviations from the bead: (1) The field's state lives in a client-held Fields map (by field name) that ScreenIn::fields hands the screens, since screens are plain functions; Press::Field(id, text) updates it. The caret moves in the layer's PlainEditor without a rebuild, so Client::field/Page::field overlay the live caret. (2) TextChange became an enum (Replace for phones, Insert for typed/committed text, Preedit) because desktop typing inserts at the caret while a phone sends the whole text. (3) Tests are in tests/all/widgets.rs (the one-binary rule), driven with Page::type_text, Page::key and a new Page::chord("Shift+ArrowLeft"). (4) The editor lives in beryl_scene src/layout/edit.rs, the client side in src/client/editing.rs; client.rs's pointer/key code moved to src/client/events.rs to stay under 800 lines. (5) Fields are now interactive in the frame (focus counts like a press) so the driver can press them. (6) The bug report sheet now shows its description field (placeholder 'What went wrong?', .bug-text style). (7) Phones: Copy/Paste requests do not cross the FFI; Home/End are desktop keys only. Checks: beryl_scene 283 and beryl_host 28 tests pass; just b3d lane: tests, gate, interface (8220 tests, 0 failed, 0 different faults) and timeline passed (fmt fixed after). just b3d app --for 5s: 'first frame shown at 1.2 ms; 13 frames in 5.0 s, each on a tick of the 60 Hz display (none window); late: 0'.
