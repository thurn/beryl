Oracle lane pays ~20 s of fixed Java cost per run

Description

Symptom

After d9bc66be (the scenario dump now runs the opt-level-1 beryl_scenario that paths.CLI_BUILD builds), by oracle --new --no-sim in a warm worktree with no scenario to play still takes 27 s, measured 2026-11-15 at load 30-40. The dump and its build take 5 s of that. Almost all of the other ~20 s is spent in Java even though no scenario is played.

Before d9bc66be the same run took 78 s. In the fast check, the oracle step was cut off at the 180 s hard limit in 40 of 43 runs between 2026-11-14 16:00 and 2026-11-15 16:00 UTC (runs.jsonl, check oracle:oracle, outcome fail, timeout wall). It also waited 4-69 s for CPU tokens (transcript lines "after waiting N s for CPU tokens").

Where the time goes (to confirm with timestamps in $BERYL_CACHE/oracles/logs)

  • forge.compile_harness runs javac on the Forge harness on every run, whether or not its source changed. Then forge.play starts a JVM that loads Forge's card database, even when it is given an empty scenario list.
  • check_xmage skips Maven when no classes were written, but it still loads xmage_java.Faces and runs the exporter.
  • oracle() in tools/src/beryl_tools/oracles.py only returns early on an empty selection inside a fast check (after oracle_selection.fitted). Slow CI's --select and plain --new runs with nothing new still start both oracles.

Work

  1. Return early from oracle() whenever the selection is empty, in every mode, logging nothing to play.
  2. Cache the compiled Forge harness by a hash of its source, the Forge jar and the JDK, as the outcome memory does (oracle_memory.py). Skip javac when the hash matches.
  3. Measure the XMage side for a single scenario (Maven -o offline and incremental compilation of Mage.Tests) and record the per-scenario cost against oracle_selection.SCENARIO_SECONDS (8 s).

Done when

  • by oracle --new --no-sim with nothing to play takes under 8 s in a warm worktree.
  • The fast check's oracle:oracle step is cut off in fewer than 10% of runs over a day of runs.jsonl, compared with 40 of 43 before d9bc66be.
