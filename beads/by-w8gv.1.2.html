Close reason

card-names check over all generic code with shrinking allowlist and one-card mechanics list

Description

checks.py already has a card-names step (tools/src/beryl_tools/checks.py, around lines 447 to 474) that fails when a file under ui/src/game names a card. Widen it to the rule in the plan (Conventions): no card name in the kernel, rules, session, generic search or UI.

  • Scope: rust/crates/beryl_engine/src, beryl_session/src, beryl_scenario/src, beryl_search/src (not expert/ or frozen/), beryl_app/src, ui/src, and non-test code in tools/src/beryl_tools. Tests, fixtures, beryl_cards and beryl_cli/src/boards.rs are out of scope for now.
  • Match card names from data/cards.json and names:: constants. Doc comments citing a card as an example of a general rule do not count; code, identifiers and string literals do. The current step builds one regex alternation of every name; make it scale (a set lookup over tokens) since the pool will be 50,000 names.
  • Seed an allowlist file (data/ or tools/) with every current hit, as path plus count. The check fails when a path's count rises or a new path appears, and when an entry's count could be lowered but was not. It is the project's burn-down list.
  • Known offenders to expect: beryl_search/src/values.rs (61 entries), rollout.rs and long.rs readers; beryl_cards/src/generate.rs OUTSIDE_CUBE; sessions.rs:36 and CLI defaults hardcoding WU_CONTROL; xmage.py and forge.py name-keyed tables and the Mana Crypt branch at xmage.py:498; beryl_cli/src/specs/auto.rs fixture cards; ui/src/screens/samples.ts.
  • Also list, as a second section of the same allowlist, the one-card mechanics by identifier so their removal is tracked: Rule::OpponentsCastAsSorceries, Rule::InstantLoyaltyTheTurnItEntered, Player::sorceries_as_flash, Replacement::WinInsteadOfDrawingFromEmptyLibrary, Modification::PowerIsCreaturesYouControl, Needs::ExiledWithSource, Face::exile_from_graveyard, CounterKind::Story and Chorus, the Waterbend cost, step, decision and ask, and the one-card Ask variants (Take, Bottom, DiscardBasicLand, TopOrBottom, MayMove, MaySearch, ManifestDread). The check fails when a listed identifier no longer exists but is still listed.

Acceptance criteria

The step runs in the fast check's lanes, passes on staging with the seeded allowlist, fails in a pytest when a card name is added to an engine file, and fails when an allowlisted count is stale.
