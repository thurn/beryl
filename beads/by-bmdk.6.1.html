Boundary rules and reuse

  • Engine and card code. The protected engine/card directories are absent from the epic's recorded diffs. beryl_table/Cargo.toml, beryl_link/Cargo.toml and beryl_link_iroh/Cargo.toml have no rules, engine or engine-session dependency. The engine's State has no manual data. beryl_protocol/src/protocol/view.rs supplies the optional PlayerView.table field, which beryl_session/src/protocol/build.rs sets to None for engine views. The broader design boundary is incomplete: beryl_table_session/Cargo.toml reaches engine and cards through beryl_session. Its view/cards.rs also calls the engine token-record fallback in beryl_session/src/card_records.rs. The shared beryl_protocol and beryl_card_records crates can replace that edge. The adapter can then be tested without building the engine.
  • Script replay. beryl_table_session/src/script.rs builds each seat's script from the checked transition, rejects mismatches in debug tests and falls back to a snapshot in release. Explicit resets use the final projection. tests/script_history.rs, tests/publication.rs and the linked game exercise the two viewer projections; protocol scripts also have a checked-in TypeScript guard. The staged log/reference/publication path is sound. Retain the seat binding and all-or-nothing publication if the adapter is moved.
  • Guest authority. beryl_link/src/guest.rs handles frames and redial. beryl_table_session/src/guest.rs decodes per-seat GameUpdate and LobbyUpdate messages, tracks acknowledgments, applies a local session number and sets locally observed connection status. It has no authoritative Table, rules, prompt completion or random outcomes. ui/src/table/client.ts sends intent through typed wrappers and uses host-published grants and object references. Local drag/selection and construction of explicit actions are UI work. The guest and shared app still ship game-capable code for solo play; the joined path never owns the host's game.
  • Engine over the link. The ordered frame transport, Hello/Welcome, version check, heartbeat and guest redial can carry engine payloads as-is. beryl_link/src/host.rs takes a Hosted implementation, and wire/envelope.rs treats actions, updates and lobbies as JSON payloads. If the invite already selects its host, the envelope needs no mode discriminator. The table adapter's reconnect and lobby orchestration is manual-specific. beryl_table_session/src/{host,guest,connections,lobby,flow,saves}.rs assume PlayerView.table, TableAction and the manual prompt/lobby/save lifecycle. An engine mode needs a Hosted adapter and session-specific lobby/snapshot/save wiring for two humans. An engine join routed through the current manual GuestSession rejects views lacking PlayerView.table. Keep the current manual lobby until the engine use case identifies a real shared portion. There is no upcoming engine multiplayer milestone in this run.
  • Third seat. beryl_table/src/{state,apply/game,permissions,redact}.rs index per-seat zones and knowledge, and turn rotation uses the actual seat count. Below the adapter, beryl_link/src/host.rs keeps one reservation and serves one link until it closes, so a second guest has no session. Link framing and an individual guest loop can remain per connection. The table core has no three-seat acceptance guarantees; its parallel seat collections and Seat(0) host defaults require review along with match policy. At the adapter, PublishedTable::new rejects more than two, TableSessions::open_host requires two, and view.rs collapses all other seats to the one Opponent. The host/save store one guest, and flow.rs rolls two dice and chooses only one other player. Adding a seat would require changes well beyond increasing Table::new's count. A future expansion should first make seat membership and the viewer-facing set of players explicit.
  • Durable state. A live drop preserves prompts because reset_seat reprojects the existing prompt state. A full host reopen loads the table, log and chance, while PublishedTable::new fills its prompt vector with None. The guided opening's committed progress therefore vanishes from the interface on reopen. by-bmdk.6.3 asks for one durable setup state. An ordinary library prompt's still-unconfirmed edits can be abandoned on restart while its already-logged knowledge remains.

Rules for every bead, in epic order

  1. Recorded commits went through Enact. The delivered subjects fit the 60-character limit and fixes have bodies. This audit updates bead text only.
  2. No epic delivery edits the protected engine or card code. The table core and link have independent manifests. The adapter-level engine dependency is recorded above.
  3. The four epic crates live under rust/crates and inherit workspace lints. Dependencies have purpose comments, including shared comments for the Serde pairs. The iOS iroh pin is called out separately.
  4. The inspected source paths touched by the epic are under the enforced limit. The two raw counts above it were generated protocol.ts and tools/tests/test_checks.py, both excluded by the existing file-length check. TableMenu.tsx is the largest manual UI source; shared interaction routing through TableClient and the command registry is still simpler than extracting a second dispatcher.
  5. Runtime table actions, projections and UI dispatch use store records, generic characteristics and action IDs. The names check passed on the audited tip. Names needed by the test harness remain in tests and fixtures.
  6. The table/deck commands have constants and typed IPC definitions, Tauri handlers, CLI routes and wrappers in ui/src/ipc.ts. Native-only keys, quit and file selection have deliberate headless responses. The canonical IPC definitions moved to beryl_protocol/src/ipc.rs and ipc/table.rs, with beryl_session re-exporting them. The generated TypeScript check passed.
  7. This audit stayed headless. Relevant browser coverage is defined in kept-table-*.mjs and the manual fixtures. No live internet or native window was used.
  8. Checked representative menu, touch, lobby, opening and link wording against the design and appendix. The registry checks cover appendix routes; they do not prove every visible string matches prose. The Archivist owns the remaining wording reconciliation, including the actual gear menu and shipped resume flow.
  9. Manual conventions are unnumbered entries in data/ui-conventions.json and the generated docs. The unrelated numbered exception 8 came from 9038062c.
  10. The epic added solo fixtures and played the two-seat opening, link, proposal and touch cases through headless scripts. Some interaction fixes are guarded by scripted state setups instead of recorded fixtures. For example, 96709ae5 asserts the shake feedback and absence of an action at the end of a refused drag, which a static recorded view cannot observe. The lobby and proposals have runtime coverage. The fixture manifest is mostly solo gameplay, so the Archivist should describe recorded and live coverage accurately.
  11. Neither gate finding requires user input. Lower-value cleanup such as combining the per-seat storage vectors can wait until a change needs it; doing it now would add a save migration without fixing the shipped two-seat path.
