Description

Read first: .claude/skills/ui-review/SKILL.md and conventions.md (how a reviewer plays the web UI headless against the engine and what it measures); docs/beryl-3d.md 'Driving the running app' (app, --agent, --offer, live); tools/src/beryl_tools/beryl3d/live.py and stand_in.py (stand-in already starts the windowless app on a fresh game and answers prompts through live).

A reviewer needs to play a whole game as a player, looking at the tree and pictures between moves. just b3d live tree, live png and live do already drive a running app; what is missing is starting one for a person-like player and saying how.

Build just b3d play in live.py's module (or a new module play.py if live.py would pass 800 lines): starts the debug app windowless (--window none) on a fresh game against the opponent given by --opponent (default mcts-hidden), offering it with --offer as stand_in.py does, with --for required (at most 3600s), waits for the first live tree that shows the game region, prints the process id, the socket and the exact just b3d live ... --app <pid> commands to go on with, and returns while the app runs. Reuse stand_in.py's start and wait functions rather than copying them; move them to a shared function if they are private.

Skill: a section "Beryl 3D" in .claude/skills/ui-review/SKILL.md: start with just b3d play, read the table with live tree and live png, act with live do '<action>' (the doc's action notation), measure with just b3d frames, and quit with live quit. Say which of the web checklist's measurements map to which command, and which have none yet (name them; do not build them).

Test in tools/tests/test_beryl3d_live.py: with the app stubbed as the existing live tests do, play without --for exits 2, and play --for 60s prints the pid, socket and the follow-up commands. Run: just test-py tests/test_beryl3d_live.py.

Each skill keeps working for the web interface until the switch: add a Beryl 3D section, never replace the web instructions. Register any new command through MODULES in tools/src/beryl_tools/beryl3d/cli.py with a COMMANDS tuple in your own module, --help and two examples (rule 19). When the job works, set this job's b3d in data/beryl3d/parity.json's tools to the command or skill section that does it. Rule 17: no new recipe in the justfile and no change to tools outside tools/src/beryl_tools/beryl3d except the skill's own files.
