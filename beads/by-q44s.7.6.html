iOS host passes touches, safe area, rotation, frame rate, idles on wake; ios-smoke and ios-smoke --touch pass; staging b7109ac17

Description

Read first: docs/beryl-3d.md 'Hosts' (the iOS host, 'Choosing a frame rate', the C functions) and 'The flat layer' ('Sizes': safe area); include/beryl3d.h as the C functions bead (by-q44s.7.3) left it; rust/beryl3d/crates/beryl_3d/ios (project.yml, Beryl3D/App.swift, Info.plist, Bridging.h); tools/src/beryl_tools/beryl3d/phone.py (ios_app, run_ios_smoke, wait_for_log, lines, finish) and tools/tests/test_beryl3d_phone.py. The web interface's phone code, for what the platform gives the player: ui/src/mobile/report-taps.ts (how touches become taps, and why a second finger matters), ui/src/mobile/phone.css (--phone-safe-bottom, the safe-area insets it pads by).

Why. The spike's Swift host passes a surface and the display's time. This bead makes it pass touches, the safe area and orientation changes, carry out the frame rate the library asks for, and stop ticking while the library is idle. The host holds no game or layout logic: every decision is the library's.

Build, in ios/Beryl3D/App.swift (split into files of under 300 lines if it grows: App.swift for the app delegate, Table.swift for the view controller, Touches.swift for touch ids):

  • Touches. MetalView handles touchesBegan, touchesMoved, touchesEnded and touchesCancelled with isMultipleTouchEnabled = true. Each UITouch gets the lowest free id from 1 to 255 when it begins (0 is the mouse's), kept in a dictionary from ObjectIdentifier(touch) until it ends or is cancelled. Each becomes beryl3d_pointer with BERYL_POINTER_TOUCH, the phase, location(in: view) in points, BERYL_BUTTON_PRIMARY, no wheel and no modifiers. Coalesced touches are not sent; one event per touch per callback.
  • Safe area and orientation. Info.plist allows portrait, landscape left and landscape right (the spike allowed landscape only). viewSafeAreaInsetsDidChange and viewDidLayoutSubviews call beryl3d_surface with the view's size in pixels, the scale and view.safeAreaInsets in points; rotating passes a new size, never a new layer.
  • Frame rate. BerylConfig.display_hz is UIScreen.main.maximumFramesPerSecond. After each beryl3d_frame, when the returned hz differs from the last applied, set link.preferredFrameRateRange = CAFrameRateRange(minimum: hz, maximum: hz, preferred: hz). iOS 15 has this API; nothing older is supported. Add CADisableMinimumFrameDurationOnPhone = true to Info.plist, which ProMotion iPhones need to go above 60 Hz.
  • Idle. When the wake is BERYL_WAKE_NEVER, set link.isPaused = true. When it is BERYL_WAKE_AT, pause and schedule a one-shot DispatchSourceTimer on the main queue for that time (the wake's at is in the same clock as CACurrentMediaTime() * 1e9) that unpauses. Any touch, surface change or lifecycle call unpauses before calling the library. BerylConfig.wake is a C function that does DispatchQueue.main.async { link.isPaused = false } through the controller passed as context (Unmanaged.passUnretained(self).toOpaque(); the controller lives as long as the app).
  • The audio session. At launch, AVAudioSession.sharedInstance().setCategory(.ambient) and setActive(true): Beryl's sounds mix with the player's music and respect the silent switch. Errors are printed and ignored. No sound plays yet (milestone 3's sound bead).
  • Live game or replay. BERYL3D_FIXTURE set in the environment replays that recording, as now; unset, the app passes a NULL fixture and plays a live game. BERYL3D_STAND_IN, read only in debug builds (#if DEBUG), is passed as stand_in.
  • Requests. After every frame, call beryl3d_next_request until it returns false and pass each to perform(_ request: BerylRequest), a switch on the kind whose cases this bead leaves empty except a debug log line naming the kind. The lifecycle bead fills share, haptic and URL; the text entry bead fills the two text cases.

Smoke test, in tools/src/beryl_tools/beryl3d/phone.py: just b3d ios-smoke --touch (with --help text and two examples, rule 19). It also builds an XCUITest bundle, Beryl3DUITests (a bundle.ui-testing target in project.yml with one file, ios/Beryl3DUITests/Touches.swift), and runs it with xcodebuild test-without-building against the same simulator, with a 10-minute limit. The UI test launches the app replaying verbs-zones, waits 2 seconds, taps at (100, 100), drags from (100, 300) to (200, 300) over 0.5 s, does a two-finger tap (twoFingerTap), rotates to landscape left with XCUIDevice.shared.orientation and back to portrait, and ends. The command then reads the app's frame log from its Documents folder and fails unless it holds: Pointer lines with phases down and up for id 1; Down lines for ids 1 and 2 that overlap (the two-finger tap); at least two Surface lines whose width and height swap; and a nonzero top safe-area inset on an iPhone model with a notch (the Beryl iPhone simulator that mobile.simulator() uses is an iPhone 17, whose Dynamic Island gives a nonzero top inset). It also prints how many frames the log has after the last input: with nothing animating, the app must have paused, so the frame log's frames in the final 2 seconds of idle must be 0 (frames drawn on demand). Add tests in tools/tests/test_beryl3d_phone.py for the log-reading function, on log lines written by hand.

Not in this bead: suspend and resume, low memory, share, haptics, URLs (the iOS lifecycle bead, by-q44s.7.7); text entry; the phone layout.

Run: just b3d ios-smoke; just b3d ios-smoke --touch; just test-py tools/tests/test_beryl3d_phone.py.

Deviations from the plan, decided while building:

  1. The touch UI test drives a live game (no BERYL3D_FIXTURE), not a verbs-zones replay. A phone replay finishes its frame log when the recording ends (~21 s, animating throughout), so inputs after it are not logged and the replay never idles. A live game without a stand-in waits on the player's mulligan, so the table settles and the log stays open.
  2. Idle proof: the frame log had no per-frame lines, so 'frames in the final 2 s' could not be read from it. frame_log.rs now writes since_frame_ms (time since the last frame was drawn) on every input line, and the UI test ends by pressing Home; the smoke requires the Suspended line's since_frame_ms >= 2000. First run: 7216 ms.
  3. Surface log lines now carry safe_area [top,right,bottom,left]; they had only the size and scale, so the top inset was not checkable. iPhone 17 sim: top 62 in portrait.
  4. The host pauses for BERYL_WAKE_AT only when the wake is more than one display interval away; a timer could not wake it sooner than the next tick anyway.
  5. The host skips beryl3d_surface when layout passes the same size, scale and insets again (viewDidLayoutSubviews and viewSafeAreaInsetsDidChange both fire), and forgets the last surface on suspend.
  6. The UI test runner reinstalls the app, which moves its data container, so the smoke looks the container up again after the test.
