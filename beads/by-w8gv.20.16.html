Description

The weekly prune of K18 (docs/project-50k.md, Target architecture, Checks, "Pruning"). A recurring bead: each one files the next. No approval step (K31; epic decisions: "A weekly Sonnet bead applies the pruning rule with no approval step, in one commit listing what it removed with its numbers").

Steps

  1. In a worktree, run just ci-report --prune (built by by-w8gv.20.15). It prints each check the rule acts on, with its action and numbers.
  2. Apply every action in one commit, e.g. test: weekly check prune:
    • Delete: remove the check (its check() block in ui/scripts/interactions.mjs, its shots.json entry, its Rust test or its card scenario). If it guarded a state no generic audit sees, add that state as a fixture or shot for the audits instead (K20, AGENTS.md "Checks").
    • Fix: file one role:executor bead under by-w8gv.20 per check, naming it and its record. Do not fix it here.
    • Slow only: add it to SLOW_ONLY in tools/src/beryl_tools/verdicts.py with today's date and its numbers.
    • Keep: nothing. The commit body lists each check with its action, stale updates, catches and seconds per run. With nothing to do, make no commit and say so on the bead.
  3. enact push, then close.
  4. Before closing, file the next one: the same title, this description and labels, parent by-w8gv.20, --defer +7d and no dependencies. Nothing else schedules it.

Acceptance

One commit or a comment saying there was nothing to prune, and next week's bead filed with a defer date.

Acceptance criteria

One commit applying just ci-report --prune (or a comment that nothing qualified), and next week bead filed with --defer +7d.
