Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Prompts for numbers and text'.

Engine games ask for a number with Stepper in ui/src/stage/PromptBar.tsx (about line 209): a minus, a plus and a confirm button at the lower right. It has no typed entry, and it must stay that way for engine games (UI Conventions, "Choosing X").

Create ui/src/table/AskPrompt.tsx and ui/src/table/ask.ts: the same look and position (reuse the stepper's CSS classes and the Button from ui/src/components/Controls.tsx; do not copy styles), for the manual table only.

  • ask.ts: pure logic. parse(text, current?) -> number | undefined: digits replace the value; a leading + or −/- is applied to current when there is one ("+3" in the life prompt gains three). parseStats(text, current) -> {power, toughness} for "3/3" and "+1/+1". clamp(min, max).
  • AskPrompt props: kind: "number" | "text" | "stats", start (the likeliest value: 1 for most, the current value for "Set life…"), min, max, label(value) -> string for the confirm button so it says what will happen ("Draw 3"), onConfirm, onCancel. Typing digits replaces the number; Return confirms; Escape cancels; minus and plus step. A text prompt has a text field in place of the number. Focus goes to the field on open.
  • Add it to the component gallery (ui/src/screens/Gallery.tsx) in each kind, so the generic audits see it.

Tests (npm test): parse and parseStats for every form in the doc and the appendix's 'Power and toughness' note. Add a kept browser check only if the gallery is not already covered by the generic audits; find out by reading ui/AGENTS.md. Run cd ui && npm run typecheck && npm test.

Acceptance criteria

AskPrompt renders number, text and stats kinds with typed entry, relative values and a confirm label; engine prompts are untouched; parse tests cover every documented form; the prompt appears in the gallery.
