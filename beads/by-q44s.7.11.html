Close reason

Dropped from the plan at the user's request (2026-11-16): by-q44s will not be tested on Windows or phones. It adds the iOS Simulator and Android emulator smoke steps to the Beryl 3D sweep.

Description

Read first: docs/beryl-3d.md 'Checks and isolation' (the lane and the sweep) and rust/beryl3d/AGENTS.md 'Phones'; tools/src/beryl_tools/beryl3d/sweep.py (SweepStep, the STEPS tuple near line 100, chosen, the (MAC,) platform filter the gpu step uses) and tools/src/beryl_tools/beryl3d/phone.py (run_ios_smoke, run_android_smoke, run_ios_device, and the --touch, --lifecycle and --text options the host beads added); tools/tests/test_beryl3d_phone.py.

Why. The phone smoke tests are run by hand today. The Beryl 3D sweep runs every Beryl 3D check that is too slow for the lane after changes land; the phone steps join it so a change that breaks a phone is found within one sweep.

Build:

  • Three sweep steps, Mac only like gpu, each with a test in tools/tests/test_beryl3d_sweep.py that chosen lists it on macOS and not on Windows: ios-smoke running just b3d ios-smoke --touch --lifecycle --text, android-smoke running just b3d android-smoke --touch --lifecycle --text, and android-smoke-gles running the same with --gles. If the options cannot be combined in one run (each host bead built its own run), make them combinable in phone.py: one launch, then the touch, lifecycle and text phases in that order, each with its own checks, so a sweep step installs and boots once. Each step keeps phone.py's existing 10-minute limits on simulator and emulator commands.
  • The steps write only into folders named for the run (out_dir("phone") / f"{run_name()}-ios", as now), and their failure message names the step's command, so the bead the sweep files for a failure says how to reproduce it.
  • just b3d ios-device --user-asked keeps working: add a test in tools/tests/test_beryl3d_phone.py that builds its command line (with the subprocess calls replaced) and checks it still replays verbs-zones then stress-255 and copies the frame logs. No bead runs ios-device itself: the owner agreed to one install, in milestone 1.
  • rust/beryl3d/AGENTS.md 'Phones': list the three sweep steps and the smoke options.

Not in this bead: pulling bug reports off phones (the mobile-bugs bead, by-q44s.7.12).

Run: just test-py tools/tests/test_beryl3d_phone.py tools/tests/test_beryl3d_sweep.py; just b3d sweep --step ios-smoke --force; just b3d sweep --step android-smoke-gles --force.

Acceptance criteria

just test-py tools/tests/test_beryl3d_phone.py tools/tests/test_beryl3d_sweep.py passes, including that chosen lists ios-smoke, android-smoke and android-smoke-gles on macOS only and the ios-device command test; just b3d sweep --step ios-smoke --force and just b3d sweep --step android-smoke-gles --force pass; rust/beryl3d/AGENTS.md lists the steps.
