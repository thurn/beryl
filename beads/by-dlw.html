Close reason

Turn button: one fixed size/style, long labels shrink via useTextFit; pill under button so tracker stays (e90574e)

Description

The docs/ui_mockups images are generated references, not a pixel spec: they are not consistent with one another, and earlier pixel-matching work fitted code to each one separately. This bead removes one such fit. Prefer one rule that holds in every state over matching any single mockup. just ui-compare verdicts for the affected regions may get worse; that is expected, so do not tune values back toward the mockups.

The turn button changes size and typography with its label. Board.tsx adds .button-long when label.length > 8 (in two places: the pass button and Finish). In screens.css, .button-long makes the button 28px wider, drops the font from 29.5px to 24px, changes its weight, adds a text stroke and moves the label up 3px, and .turn-action:has(.button-long) shifts the container 2px. "End Turn" and "No Attacks" therefore get visibly different buttons. That came from combat.png's "Resolve Damage". The control also moves when waiting (.turn-controls-wait .turn-action has its own right and top), and a disabled button centers its label while an enabled one left-aligns it.

Give the button one fixed size, position and type style in every state. Shrink a long label to fit, the way Card.tsx's useNameFit fits names, rather than keying on character count. Remove .button-long and the waiting-state offsets.

While waiting, Board.tsx also replaces the phase tracker with the priority pill, which hides the phase exactly while the opponent acts. Show both: lay the pill out somewhere that does not displace the tracker.

Acceptance criteria

The turn button's size, position and font are the same for every label and state; long labels fit by shrinking; the phase tracker shows while waiting. just check and just ci pass, with no new constants tuned to a single mockup.
