Close reason

Staged explicit card-level reveal permissions with stale-grant, undo, save compatibility and two-seat action-reference coverage.

Description

The Drag handoff and review by-bmdk.3.22 found that a guest cannot act on an explicitly revealed library or sideboard card, even though the Permissions table in docs/manual-multiplayer.md allows it. beryl_table/src/permissions.rs grants card-level access only for hand cards. The host records Reveal in apply/library.rs and uses known_to for identity, but retained knowledge can also come from a public card entering a library or an old look. Introduce a host-authoritative distinction between a reveal grant and knowledge. Keep zone-wide actions gated by lend, and make reference_zone and the table view agree with the host. Check how always-reveal-top should expire as the top changes. Preserve save, replay, shuffle and undo behavior.

Acceptance criteria

A two-seat test shows the guest can move a specifically revealed library or sideboard card, cannot move a merely known library card, and cannot use a stale grant after a shuffle or hidden re-identification. Replay and undo preserve the intended grant lifetime. The UI gets an action reference only when the host would accept it.
