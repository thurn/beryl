Description

What is wrong today

"Does this object have this ability" has one query, State::has_ability(slot, AbilityIx) (beryl_kernel/src/query.rs), but "which abilities does this object have" has none. Every reader walks the face itself and must remember to ask has_ability of each entry:

  • beryl_rules/src/replace.rs (static_destinations, entering_destinations, dredge_of, life_asked, chooses), replace/damage.rs (two walks), replace/draws.rs, rule_change.rs:196, mana/sources.rs, mana/pay.rs:232, mana/lookahead.rs, reference.rs (the reference recompute), layers/together.rs, layers/mod.rs. Each repeats (0u8..).zip(face.abilities), AbilityIx::new(index), the kind test, has_ability, interpret::static_condition_holds and coverage::hit.
  • An ability granted by another permanent's effect (Modification::Grant, stored as Derived::granted with a GrantRef) is a second kind of ability that only activation (cast/legal.rs builds ObjectAbility::Own/Granted by hand; cast/timing.rs) and the layers read. Trigger matching never reads it: listener::of (beryl_kernel/src/listener.rs) collects only face.abilities, while table::found_where_they_work accepts a granted triggered ability. A card that grants a triggered or replacement ability ("creatures you control have 'When this creature dies, ...'") would load and silently do nothing. No card of the pool grants one yet.

Groups 4, 5 and 7 add more places an ability comes from: Underworld Breach grants escape to cards in a graveyard (by-bajq.5.5), a copy's exceptions can add "has this ability" (by-bajq.6.1, Face::excepts), Animate Dead's enchant ability is granted (by-bajq.8.2), and a merged permanent has every ability of each card under it (by-bajq.8.5, R7). With today's shape each of those must find and change every walker above, and a missed one is a silent rules bug (principle 7 of docs/rules-coverage.md).

What to build

  1. One query in the kernel for the abilities an object has now:
   impl<L: Layout> State<L> {
       /// Every ability the object in `slot` has, in a fixed order: its face's own that it
       /// has not lost, then those granted to it.
       pub fn abilities<'t>(&self, t: &'t GameTable, slot: L::Slot)
           -> impl Iterator<Item = (ObjectAbility, &'t Ability)> + '_;
       pub fn has(&self, slot: L::Slot, ability: ObjectAbility) -> bool;
   }

ObjectAbility (beryl_card/src/definition.rs) already names the two kinds. The face part costs what the walks cost today: with no ability lost (flags.abilities_lost clear) it yields the face's slice with no test, and with no grant on the battlefield (a flag the recompute stores beside it) the granted part is skipped.

  1. Move every walker above onto it, keeping their gates (may_replace, may_listen) in front. A helper in beryl_rules for the static replacement abilities of one kind (replace::statics(s, t, slot, kind), yielding ability, Replacement and controller, with the kind test, condition and coverage hit) removes the repetition in replace*.rs.
  2. Trigger matching: either match granted triggered abilities (a listener entry per grant, found from GameTable's grants, and Derived::granted read behind the battlefield's grant flag), or have the card table refuse a granted triggered or replacement ability (TableError) until it does. Choose by the count: refusing costs nothing now; record the choice in the bead.
  3. State::has_ability stays as the fast test for an own ability (has(Own(ix))).

What must not change

Every scenario, rollouts_never_change and the frozen saves. The count gate holds with no bump: the WU mirror has no lost or granted ability on its hot paths, so the walks must cost what they cost now (check just bench-count per function on replace::moving and the mana solver).

Acceptance

  • No file in beryl_rules/src outside layers/ walks face.abilities of a permanent for a rules decision; a grep in the bead's close reason shows it.
  • A rules test with a test definition that grants a triggered ability: either it triggers, or GameTable::new refuses the card with a named error.
  • just test-rust, just count-gate (count before and after in the close reason).

Files

beryl_kernel/src/{query.rs, derive.rs, listener.rs, table.rs, lib.rs} (the contract's Queries section names the new query), beryl_card/src/definition.rs, beryl_rules/src/{replace.rs, replace/damage.rs, replace/draws.rs, rule_change.rs, mana/sources.rs, mana/pay.rs, mana/lookahead.rs, cast/legal.rs, cast/timing.rs, reference.rs, trigger.rs}.

Acceptance criteria

No rules decision outside layers/ walks a permanent's face abilities itself; a granted triggered ability triggers or the card table refuses it; count gate holds with no bump.

Derek Thurn2026-11-15

Decisions: (1) Trigger matching: chose refusal. GameTable::new now refuses a card that grants anything but an activated ability or a static ability the layers apply (TableError::Granted, via listener::read_when_granted). That covers granted triggered, replacement, rule-change and mana abilities, all of which are read only through per-face table records (listeners, replacement/rule masks, mana facts). The only granting card in the pool (Swift Reconfiguration, crew) is activated, so this costs nothing. (2) replace::statics takes a pick closure (kind test + replacement match) and checks the condition after it; coverage::hit stays with each caller because entering_destinations hits only after layers::entered passes. Deviation from the bead text, same intent. (3) Face walks left outside layers/ are not of permanents: replace::entering/life_asked/chooses read the face an entering object would have (layers::lost_entering), mana/lookahead reads hand cards and land drops, damage.rs reads a spell ability of a shield's source card. (4) The 'any grant on the battlefield' flag is computed in Rederive::finish's existing loop (grants fill the first free place, so granted[0] suffices).

Derek Thurn2026-11-15

Handoff: commit 49edb8ba. New beryl_kernel/src/abilities.rs: State::abilities(t, slot) yields (ObjectAbility, &Ability) for the face's own abilities not lost, then the granted ones (Derived::granted), and State::has(slot, ObjectAbility). The granted part is gated by the new Capability::Grants (table/capability.rs), not a State field. listener::read_when_granted plus TableError::Granted (table.rs found_where_they_work) refuse a card that grants anything but an activated ability or a layer static, which covers triggered, replacement, rule-change and mana abilities. replace::statics(s, t, p, pick) is the shared walker for static replacements, used by static_destinations, entering_destinations, damage multipliers and draws. Moved onto the query: rule_change::maker_of, replace::dredge_of, mana/{sources,pay,lookahead}, reference.rs and cast/legal.rs (granted activations). For later beads (escape grant, merged permanents, copy exceptions): extend State::abilities and Abilities::next. A new kind of granted ability also needs listener::read_when_granted to allow it and its per-face reader to read the query. Test: table/tests.rs (Heraldry refused) and tests/events.rs (crew grant seen through the query).
