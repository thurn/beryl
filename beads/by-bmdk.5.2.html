Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'Networking' and 'Automated checks' (the first bullet).

In rust/crates/beryl_table_session, add src/guest.rs:

  • TableSessions::join(connect, name, emit): wraps beryl_link::guest::join. It runs no game logic. act(action) sends act and returns when done or refused arrives. Each Update payload is handed to emit unchanged as the game-update value. Lobby payloads go to the lobby emitter. Reconnecting and Resumed update a LinkState the interface is told on the table-link event; a resumed table arrives as a whole view with no animation. Mismatch surfaces the message "Both players need the same version of Beryl." to both players (the host's side shows it from Hosted).
  • TableSessions now has three kinds of open table (solo, host, guest) behind the same act, current and leave, so the app's table_act does not care which. Keep the existing typed IPC request and reply. Run the guest's reply wait away from Tauri's main thread and preserve the invalid-action blocker list from by-bmdk.4.4.

Then write the whole-run test, tests/scripted_game.rs, a_host_and_guest_play_a_scripted_game: one process, memory::pair, a real host and a real guest. Load two decks, start, both draw, each plays a land and a creature, seat 0 draws an attack arrow and seat 1 a block arrow, apply the combat proposal (beryl_table::assist::combat::proposal then apply_proposal), seat 1 undoes it, sever the link, the guest redials and resumes, and both seats' views agree with the host's table (seat 1's view equals view(table, Seat(1))). After every step assert the guest's view JSON names no card seat 1 does not know.

Run just test-rust -p beryl_table_session.

Acceptance criteria

A guest session forwards actions and hands updates on unchanged, reconnects and resumes; solo, host and guest share one act path; a_host_and_guest_play_a_scripted_game passes deterministically with no sleeps.
