Phone reporter delivered in 8d9a2096: iOS and Android showed a menu-free board frame, dragged middle-band crops, description and Submit above their keyboards, Saved with Share and Done, and native share sheets; six shots, full UI suite, checks, and both smokes passed.

Description

Make the bug reporter usable by touch. On a phone the menu's Report Bug (Menu in ui/src/stage/PhoneChrome.tsx calls requestBugReport()) opens the desktop's reporter: its region is dragged with a mouse, its hints name keys (⌘B, Space, Enter, Escape, ⌘Enter), its description box does not stay above the on-screen keyboard, and it closes itself 900 ms after saving, so there is nowhere to put Share.

Where the code is

  • ui/src/components/BugReport.tsx (about 450 lines): BugReporter (the state machine: idle, capturing, selecting, describing, saving, saved; its key handler), Frame (the frozen frame), Selector (the region drag, already on pointer events with setPointerCapture), Describe (the text box, the "AI play" checkbox, submit), Thumb, Tools, requestBugReport.
  • ui/src/freeze.ts (freezes the page, animations mid-flight included), ui/src/diagnostics.ts.
  • ui/src/ipc.ts: canReportBugs, canCaptureWindow, captureWindow, snapshotUrl, reportBug, and from by-7pm.3.11 shareBug(id) and canShareBugs().
  • usePhone() from ui/src/mobile/phone.ts; phone styles in ui/src/mobile/phone.css under body.phone.
  • Read the close reasons of by-7pm.3.5 and by-7pm.3.11 first.

What to build

Keep the reporter's state machine and the desktop's markup and behavior exactly. Branch on usePhone() only where a step below says so. Labels are the desktop's (D6) except where a step names a new one.

  1. Entry. The menu's Report Bug only; no gesture and no button on the board. Check that the menu sheet is gone before the page is frozen and captured (the frozen frame must show the board, not the sheet): if it is not, wait one animation frame after closing the sheet before requestBugReport().
  2. Select. The frozen frame fills the screen. A drag selects a rectangle; a touch that moves less than 10px takes the whole screen. At the top, under the safe area: the desktop's hint with its key names left out on a phone, at 13px, and at the right two 40×40 icon buttons, whole screen (aria-label="Whole screen") and close (aria-label="Close"). touch-action: none on the selector so the drag never scrolls.
  3. Describe. A sheet pinned to the bottom of the visual viewport so that it rides above the keyboard: track window.visualViewport's resize and scroll events and set the sheet's bottom to innerHeight - (visualViewport.height + visualViewport.offsetTop). In it: the region's thumbnail 64px high (a touch on it goes back to Select), the "AI play" control as a 44px-high toggle, a 40×40 close button, the text box with font-size: 16px (iOS zooms the page on focus below that) and three to six lines, focused when the sheet opens, and the desktop's submit button 40px high at the right. No key hints.
  4. Saved. On a phone the reporter does not close itself. The sheet shows "Saved" and two 48px buttons: "Share" (primary; only when canShareBugs(); calls shareBug(saved.id); a failure shows its message in the sheet at 13px) and "Done" (secondary), which thaws the page and closes.
  5. Text and targets. Every text of the reporter on a phone is 12px or more and every control 40×40 or more.

Shots

canReportBugs() is false under a fixture, so the reporter cannot be opened in a plain shot. Add a query parameter read only in development and headless runs, ?bugreport=select|describe|saved, which opens the reporter in that state over the page with a stub frame (the page's own screenshot is not available headless: use a plain dark frame) and a stub saved id; guard it so that the bundled app ignores it (import.meta.env.DEV or the fixture transport being active: follow how ui/src/ipc.ts tells a fixture page from the app). Then add to ui/shots.json, at 393×759 and at 375×647 with -se: phone-bug-select, phone-bug-describe, phone-bug-saved, each /?phone&bugreport=<state>&fixture=phone-main#/game. The keyboard cannot be shown headless: for phone-bug-describe that is accepted; step 3 is verified in the simulator.

Verify

  1. cd ui && npm run typecheck && npm test; just ui-shots with the six names: no phone:, screen: or page-error line; open each PNG.
  2. The desktop's reporter is unchanged: just ui-test passes, and git diff shows no change to the desktop's branch of the markup.
  3. In the iOS Simulator (just ios; the iOS Simulator tool's screenshot, tap, touch_path, text and set_keyboard): open a game, the menu, Report Bug; drag a region; with the keyboard shown, the text box and the submit button are both visible above it (screenshot); type a description; save; press Share and see the share sheet (screenshot); dismiss; Done. Then just mobile-bugs and just bugs: the report is listed and its screenshot.png is the region you dragged. Mark it done (just bugs done <id>).
  4. The same in the Android emulator (just android; adb -s emulator-5584 shell input tap|swipe|text, adb exec-out screencap -p).
  5. Describe the screenshots you checked in the close reason; commit none of them.
  6. Add the sentence D7 asks for to "The phone" in data/ui-conventions.json, run just conventions, then just check.
