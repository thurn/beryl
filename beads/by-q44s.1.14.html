Close reason

Desktop host: FrameLoop over pluggable ticks, macOS display link, three window modes; staging 1a159fee

Description

Read first: docs/beryl-3d.md 'Hosts' (the desktop host), 'Drawing only when something changes' and decisions C15 and C16. Read the prototype's src/window.rs and src/display_link.rs, which are a working example of everything below.

In rust/beryl3d/crates/beryl_host, the desktop host on winit 0.30:

  • It creates the window and the wgpu surface, turns winit's events into Inputs, and carries out the client's Requests.
  • A WindowMode the app passes: Background (never takes focus or keyboard input, opens behind the other windows), Foreground, or Fullscreen (decision C15). A key leaves and re-enters fullscreen.
  • On macOS, frames are paced by a display link (NSView's, macOS 14, with a preferred frame rate range up to the display's highest), through a small objc2 call. The epic's rule 11 allows unsafe here, on that call, with a comment naming it.
  • Frames are drawn only on the link's ticks. An input or a session update reaches the client at once and is drawn on the next tick. The host asks for ticks only while the client's wake() says a frame is wanted.
  • The frame thread asks for the platform's interactive class (on Apple platforms QOS_CLASS_USER_INTERACTIVE).
  • The loop is generic over where ticks come from, so a test can supply them.

Tests in beryl_host/tests, with no window: each winit event maps to the Input the doc's 'Hosts' gives; with a test source of ticks that sends 10 ticks while 50 inputs arrive, at most 10 frames are drawn; with the client's wake at Never, no tick is asked for.

Run: just b3d cargo-test -p beryl_host; just b3d lane.

What the prototype found (rust/prototypes/beryl3d, 2026-11-14; read its code for a working example, then build it properly):

  • winit 0.30 works as the doc says: ApplicationHandler with EventLoop::<()>::with_user_event(), a proxy's send_event to wake a still window from another thread, and ControlFlow::Wait or WaitUntil from the core's wake.
  • In a window on a 120 Hz Mac the prototype's frames mostly arrived at 60 Hz, each waiting about 16.3 ms for the drawable with under 0.3 ms of work: winit's on-demand redraws with wgpu's FIFO presentation do not ask macOS for the display's highest rate. The display link fixed it.
  • Drawing on every mouse move and session update as well as on ticks used up macOS's three drawables and made frames wait whole display intervals.
  • pthread_set_qos_class_self_np(QOS_CLASS_USER_INTERACTIVE) (libc 0.2.191 exports it) did not change a paced frame's cost.

Acceptance criteria

The tests pass with no window opened; unsafe appears only on the display link's calls, each with its comment; no frame is drawn outside a tick; the three window modes exist.

Decisions: (1) The QoS call (pthread_set_qos_class_self_np) also needs unsafe. The bead's acceptance says unsafe only on the display link's calls, but the epic's rule 11 allows it on any item that needs a platform call, with a comment naming it, so it sits beside the link in beryl_host/src/macos.rs. objc2's NSThread setQualityOfService is safe, but Apple allows setting it only before a thread starts, so it can't change the running main thread. (2) Windows gets no priority call (no safe API); its ticks come from winit's redraw requests. (3) Keys map by physical position (layout-independent bindings). F11, or Control-Command-F on macOS, toggles fullscreen, and the client never sees that key. (4) Background mode = macOS ActivationPolicy::Accessory + activate_ignoring_other_apps(false) + with_active(false); key events are dropped in that mode. (5) Hand check: a Background window, 663 inputs sent through Inbox over 1 s drew 109 frames on the 120 Hz display; a still half second drew 0. The probe and its temporary counter were removed before commit. (6) Surface format: first non-sRGB format, so window colors match the offscreen PNGs (sRGB values blended as stored).

Handoff: beryl_host (staging 1a159fee). frames.rs: FrameLoop<T: Ticks> { handle(Input) never draws; tick(now, &mut impl Draw) draws only when the wake wants a frame at now; schedule(now) -> Sleep runs the ticks iff a frame is wanted; client() for draining queues }. events.rs: Translator (window_event, key(PhysicalKey, ElementState, repeat), touch, scale_changed, surface); LINE_POINTS = 16 points per wheel line. desktop.rs: Desktop::new(Options{mode, title, size}) -> inbox() (Inbox::send wakes the loop; inputs sent before the window opens are drained when it opens) -> run(client, setup: FnOnce(&mut Renderer)). After each drawn frame it carries out Requests (text entry turns the IME on or off; Share reveals the file and OpenUrl opens the browser, each on a thread of its own; Haptic does nothing). NOT done, left for by-q44s.1.43: draining Client::next_command to a session thread, the frame log and a clock that pauses. macos.rs: DisplayLink (paused until wanted, CAFrameRateRange up to the monitor's highest video-mode rate) and interactive_thread(). beryl_render: surface.rs adds Surface, Renderer::for_window(W, w, h), present(frame, surface, before_present) -> Presented{Shown(Drawn), Skipped} and resize; render() now goes through a pub(crate) render_view.
