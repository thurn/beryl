Close reason

Enact lock waits and syncs are time kinds, with an enact query, page view, finding and coverage (965e0836a)

Description

Show how much agent time goes to waiting on Enact's ownership lock and to its remote syncs, so that Enact overhead can be reduced on evidence. Today enact and bd calls are one command kind each in data/efficiency-command-kinds.json; lock waits inside enact push, start, close and meta are invisible.

Bead by-ig5e.21 makes Enact append one JSON line per ownership-lock acquisition to lock-waits.jsonl in its clone state directory, with time, pid, command, waited_s, held_s, sync_s, outcome and holder. Read its handoff comment for the final path and fields.

Change (Beryl, efficiency/)

  • Ingest the lock log into a new store table (follow how leases or cpu rows are ingested: incremental, by file offset; see efficiency/src/beryl_efficiency/). Match each line to the tool call that ran it (host, time window, command text: enact <subcommand> <bead>), so each Enact call gets lock_wait_seconds and sync_seconds.
  • In time accounting, split a matched Enact call's minutes into enact lock wait, enact sync and the rest (keeping its existing kind for the rest), so the time split still sums to the window length. Apply it to push, orchestration wait and enact kinds alike.
  • just efficiency time --by kind shows the new categories. Add an enact view or a --by enact breakdown: per subcommand, calls, total minutes, lock wait, sync, and which commands held the lock longest (from holder).
  • Add a findings rule (see by-ig5e.12's rules) for Enact lock waiting in agent hours, with the top holders as evidence.
  • Show the same numbers on the page's Machine or CI view (efficiency/ page code from by-ig5e.13/.14), and keep "everything on the page is printable by the command".
  • Synthetic tests only (the repository is public): a small lock log and transcripts with matching calls; check the split sums to the window and unmatched lines are counted in coverage.
  • Add the source to the efficiency skill at .agents/skills/efficiency/SKILL.md and to efficiency/AGENTS.md.

Before the lock log has data, the real-data check can only show the new categories as zero; run one enact meta or enact sync yourself to get a line, then ingest and check it is matched.

Acceptance criteria

just efficiency time --by kind shows enact lock wait and enact sync minutes; an Enact breakdown lists per-subcommand lock wait, sync and top holders; a findings rule ranks lock waiting; time splits still sum to window lengths; the page shows the same numbers; synthetic tests pass in the efficiency lane.
