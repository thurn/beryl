Description

Milestone 8 of Project 50k (run epic by-w8gv; plan docs/project-50k.md, "Authoring tools", decisions K9). Read the plan's sections named here and enact brief on this bead before starting. This milestone starts once M7b (by-w8gv.13) closes: read its beads' handoffs for the set crates, the generated registry and characteristics, and the card store as they landed.

K9: "Generic agents derive card knowledge from definitions. Hand-tuned numbers survive only as an optional overlay for supported decks." Plan Acceptance: the card-names allowlist is empty "outside the expert system and the per-deck overlay".

Today

rust/crates/beryl_search/src/values.rs (250 lines, 61 entries in data/card-names-allowlist.json) builds CardValues, one CardInfo per game-table index, from seven name-keyed tables:

  • VALUES (hand-tuned value per card) and NEVER_CAST (Mana Crypt) and NEVER (Aang's Iceberg's ability 1): judgement, not facts. These move to the overlay.
  • WHEELS (Timetwister, Time Spiral), DRAWS (nine card/ability pairs), FRIENDLY (The Wandering Emperor's +1), EMPTIES (Jace, Wielder of Mysteries' −8): facts a definition already states. These are derived.
  • wins_instead is already derived (beryl_engine::wins_instead_of_drawing): follow that pattern.

Why it matters now (revised 2026-11-12, after the AI ladder's rungs ran; docs/ai-strategy.md, docs/ladder.md): the shipped champion, pimc72/hidden/rollout/tuned/anchor+guard@30M (DEEP_SEARCHER), reads these facts in every rollout through greedy's own scoring, with no policy rule set: Policy::action scores a spell with a triggered ability that draws, or an activated ability that draws, as 0 when drawing is not safe (may_draw, which also reads wheel and wins_instead). The hold and waste rules exist behind options that are off by default (both failed at the suite and were not promoted); hold also reads draws, and rollout/policy/hold_tests.rs and waste_tests.rs exercise the flags. docs/ai-strategy.md §5 asks that each policy rule be tested over every card in the pool with the property it reads, which a hand list like DRAWS cannot support honestly.

Knowledge::{Estimate, Tuned} picks the value source; the flags are the same in both. Readers of the flags: rollout/policy.rs (lines ~185-320), expert/mod.rs (.wheel, .draws), frozen/rollout.rs and frozen/expert/mod.rs (the frozen copies, which must not change behaviour), long.rs (never_cast; the family names estimate/tuned parsed at ~line 329 and printed at ~240), lib.rs (DEEP_SEARCHER and friends use Knowledge::Tuned), beryl_cli/src/evalfit.rs.

What to build

  1. Derived facts. Read each fact from the definition's effect data (beryl_card: Effect in effect/mod.rs, Ability/Behavior in ability.rs, costs in cost.rs; walk.rs shows how to visit a definition): an ability or spell that draws its controller cards or takes cards from their library by choice (draws); a spell whose effect has each player shuffle their hand (and graveyard) into their library and draw seven (wheel); an ability whose targets help its controller although the filter allows either side, such as putting a +1/+1 counter (friendly); an ability that draws a number of cards that can empty a library and has the win-instead replacement or wins on an empty library (empties). Define each by what the effect does, never by name, with a doc comment saying so; put general helpers where both beryl_search and later readers (the exporters' dump, the renderer) could use them, in beryl_card if they read only the vocabulary.
  2. Prove equality. A test over every implemented card (beryl_cards::CARDS) asserts the derived bits equal what the old tables gave, card by card and ability by ability. Write that test first against the old tables, make it pass, then delete the four fact tables. Where a derivation finds a fact the old table missed (or the reverse), decide per case from the card's Oracle text: if the table was wrong, the rollouts would change, so keep today's behaviour by putting that one entry in the overlay with a comment, and record the case on the bead.
  3. The overlay. Move VALUES, NEVER_CAST and NEVER into a per-deck overlay in a new directory rust/crates/beryl_search/src/overlay/, and add overlay to the card-names check's EXEMPT_DIRECTORIES (tools/src/beryl_tools/card_names.py). Not in expert/: the champion plays with these tuned values, and docs/ai-strategy.md treats the expert as a yardstick that is never promoted, so the champion's knowledge must not live in the expert's directory. Update the plan's Acceptance line in docs/project-50k.md (the card-names allowlist is empty "outside the expert system and the per-deck overlay") to name beryl_search/src/overlay/. The overlay is keyed by card name and applied on top of the derived CardInfo. "Per-deck": say in its doc comment which supported decks it was tuned for (decks::WU_CONTROL, decks::VINTAGE_WU_CONTROL). Default: Knowledge gains a tier, so Estimate = estimated values and derived flags, Tuned = derived plus the overlay (today's agents, unchanged); keep parsing the family name tuned and estimate so ladder records still read (long.rs). The frozen agents keep the overlay.
  4. No overlay works. Every registered agent (beryl_search::lib.rs registry) builds and plays a game to its end on a game whose cards have no overlay entry: a test with a deck of store-only cards (vanilla creatures from M7b's by-w8gv.13.7, basic lands) or the generated-scenario cards. No unwrap on an overlay lookup.
  5. values.rs leaves the card-names allowlist (its count goes to 0; python -m beryl_tools.checks card-names --shrink), and nothing in beryl_search outside expert/, frozen/ and overlay/ names a card.

Decisions (executor):

  • Derivation helpers live in beryl_card/src/facts.rs as Effect methods (vocabulary only): takes_from_own_library (Draw/Dig/ManifestDread for Players::You), wheels (ShuffleInto of each player's hand + Draw for each player), helps_target (+1/+1 counter, added keyword or non-negative +N/+N on the target), wins_by_drawing_out (Draw for You + WinGame(You)). Effect is now re-exported through beryl_engine::card.
  • Which abilities count as 'draws' is the AI's rule, in values.rs: spells and activated abilities, plus triggered abilities on a step or main-phase trigger (they keep taking cards every turn, as Abhorrent Oculus's upkeep manifest dread does). Enters and combat-damage triggers (Beza, Sphinx of False Conclusions, Thundertrap Trainer, Malcolm, Trinket Mage's search) are not counted; that matches the old DRAWS table, which left them out.
  • Flags are derived from the front face only, as the old bits were.
  • Table vs derivation: derivation found four abilities that draw by choice that DRAWS left out: Teferi, Time Raveler's -3 (bounce and draw a card), Spara's Headquarters' cycling, and Jace, Wielder of Mysteries' +1 and -8. By Oracle text the table was wrong (each draws its controller a card). To keep rollouts unchanged, the overlay clears those bits (Tuning::tuned_as_not_drawing) with a comment each; so Knowledge::Estimate (derived only) now holds those abilities back on a low library, while Tuned plays as before. For Jace, Wielder the difference never shows in activate(): with it on the battlefield may_draw is true. No other difference; overlay/tests.rs asserts both directions.
  • Knowledge keeps two tiers: Estimate = estimated values + derived flags (it no longer has Mana Crypt's never_cast or Aang's Iceberg's never), Tuned = derived + overlay (today's agents, unchanged). Family names 'estimate'/'tuned' parse as before. I read 'Knowledge gains a tier' as the overlay becoming what the Tuned tier adds; by-w8gv.15.3 can add a separate derived-values tier.
  • The frozen agents use their own frozen/values.rs tables, untouched.
  • No-overlay test (src/agents_tests.rs): every agent in AGENTS and RETIRED plays a 12-card store-only deck (Swamps and black vanilla creatures) to its end. The long-think agents ignore their budget, so the test builds their families at 2,000 steps a decision; lib.rs now names those families as constants (DEEP_SEER, DEEP_SEER_UNANCHORED) and deep_family takes the work. A 40-card deck took 57 s in debug (68-turn games inside every rollout); 12 cards takes about 3 s.
