Close reason

enact release pushes enact/<bead> so any host can resume (Enact 056200be, slow CI green)

Description

Symptom: by-q44s.3.53 was worked on dereks-macbook-pro, committed as 56f4a5ea, and released at 08:30 UTC on 2026-11-16 to wait for by-q44s.3.55. That commit existed only on that host. When a session on jarvis took the bead about 11 hours later, it had to redo the work from scratch. by-q44s.3.55 hit the same problem: its comment says the push of its branch to the remote was rejected, so commit 3b0b59322 stayed in a local worktree. Both beads blocked the milestone 2 Warden (by-q44s.3.38), which could not start until 20:08.

Why: enact release (cmd_release in ~/enact/scripts/enact.py) records the host, path, branch and HEAD in enact_recovery, but it does not push the branch. common.md's 'waits on another bead' default tells the session to commit and release, and says that the next session resumes from that branch, which only works on the same host.

Proposed change, in the Enact repository through Enact's own flow (sage.md, 'Improving Enact itself'): have enact release push the worktree's branch to origin as enact/<bead> (force-with-lease) when it has commits beyond its base. Record the pushed SHA in the recovery record. Fail loudly if the push is rejected, and report why (find out what rejected .3.55's push). recovery.md then fetches that branch on any host.

Files: ~/enact/scripts/enact.py (cmd_release, recovery_records), ~/enact/skills/enact/roles/common.md and recovery.md.

Acceptance criteria

A bead released with unpushed commits on one host can be resumed on another host from origin/enact/<bead>, shown by a test in the Enact repository; a rejected push makes release fail with the reason.

Delivered in the Enact repository as 056200be (staging, slow CI passed). Why .3.55's push was rejected: the beryl remote has no hooks or branch rules against enact/* (enact/by-q44s.3.52 exists on origin), and the session that saw the rejection is not on this host, so its exact message is lost. The likely cause is that its raw 'git push' was blocked by its own permission guard, since common.md forbids bypassing enact with raw git push. The fix makes the push part of enact release, so sessions never need a raw push.
