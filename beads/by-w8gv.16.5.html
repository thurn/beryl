Description

Current design

The prompt protocol (decisions K10 and K26: about ten answer shapes, a closed list of purposes, prompt state held in the session) is typed inside the engine and session, but flattened on the wire:

  • PromptView (rust/crates/beryl_session/src/prompt/view.rs:19-60) has shape: ShapeName and, separately, state: Option<ShapeView>, where ShapeView is itself tagged by shape (#[serde(tag = "shape")], line ~215). The two can disagree.
  • purpose: String (line 26), "so that a new purpose changes no type here", although beryl_card::prompt::Purpose is a closed enum with Purpose::ALL. The UI compares purpose strings, so a renamed purpose fails silently at run time instead of in tsc.
  • count: u8 and most: u8 are "zero where its purpose has no such number"; places: [PlaceName; 2] holds "none" placeholders; marks and buttons are "empty until the session holds this shape's state". Which fields mean something depends on the shape.
  • Object ids on the wire are bare u16 (about: Vec<u16>, the tray, and in src/protocol/view.rs attached_to, exiled_by, exiled_with at ~213-219 and source at ~274), next to newtyped SessionId, CandidateIndex and decision ids.

Inside the session the state is already a tagged enum (Shaped, src/prompt/held.rs:~43); only the wire form is flat.

Proposed design

pub struct PromptView { revision: u32, purpose: Purpose /* ts-rs enum */, part: PartName,
                        title: String, words: Words, about: Vec<ObjectId>, from: Option<Lies>,
                        body: ShapeBody }
#[serde(tag = "shape")]
pub enum ShapeBody { Pick { most: u8, tray: Vec<ObjectId>, marks, buttons, .. },
                     Split { places: [PlaceName; 2], .. }, Number { .. }, Pay { cost: String, .. }, ... }
#[ts(type = "number")] pub struct ObjectId(u16);

Each variant carries only its own counts, places, cost, marks and buttons, so shape, ShapeName, the Option<ShapeView> and the "zero/none/empty where unused" conventions go away. TypeScript gets a discriminated union, so ui/src code that reads a field another shape does not have stops compiling (about 32 reads of .purpose / .shape across 9 UI files today). If a shape's state is still held by the UI rather than the session, its variant says so explicitly rather than by an empty list.

Must not change

What the player sees and clicks; the stage's scripts; save files (prompts are not saved, but check save.rs). ui/src/generated/protocol.ts is regenerated by ts-rs.

Test

The existing shape tests (beryl_session/tests/clicks.rs, zone_picks.rs, payments.rs) and just ui-test for the prompt shapes pass unchanged in meaning; add one Rust test that each Purpose serializes to a TypeScript-literal string present in protocol.ts; npm run typecheck passes with no as casts added on prompt fields.

Acceptance criteria

PromptView carries purpose as the Purpose enum and a shape-tagged body with no shape/state duplication or unused-field placeholders; object ids on the wire are an ObjectId newtype; Rust and UI prompt tests and typecheck pass.

Derek Thurn2026-11-13

Design as built: PromptView keeps the fields every shape shares (revision, purpose, part, title, words, about, from, marks, buttons) and gains count: Option<u8> (None where the old wire said 0) plus body: ShapeBody, tagged by shape. ShapeBody is the old ShapeView plus a Candidates variant, which says explicitly that the session holds no state and the UI answers by candidate; it replaces state: Option<ShapeView>. shape/ShapeName, most, places, cost and PlaceName::None are gone from the wire: the session reads them from the engine's Prompt record when a shape opens, and a yes/no that sends a card carries its places in its own variant. The shape is a function of the purpose (Purpose::shape), so text snapshots still print it. marks and buttons stay top-level: with the Candidates variant marking an unheld prompt, an empty list now only means there is nothing to mark, so moving them into all ten variants would add churn and no type safety. purpose is the beryl_card Purpose enum, serialized by its name; typescript.rs writes type Purpose as the union of Purpose::ALL's names, because beryl_card has no serde or ts-rs. ObjectId is a transparent u16 newtype that is a number in TypeScript.
