Close reason

Whose is {You, AnOpponent} with rules cited; 7 cards audited (Winds says 'you don't control'); evaluation goes through filter::is_an_opponent and Who::each_opponent; parity holds

Description

Milestone 3 (plan K7): "Card data says what the card says ('each opponent', 'defending player'). The kernel's API is format-neutral. No multiplayer logic is written." This bead is the card-data half; it needs nothing from the kernel crate and can start at once.

Read first

docs/project-50k.md: Decision K7 and its reason ("Card data cannot be re-audited cheaply"). rust/crates/beryl_card/src/filter.rs (Whose), rust/crates/beryl_card/src/effect/mod.rs (Players: You, EachOpponent, EachPlayer, Target, ControllerOf, OwnerOf, ThatPlayer) and effect/build.rs. The M2 Mason found K7 already holds in Players and not yet in Whose (comment on by-w8gv.4.1).

Scope

  • Whose { You, Opponent } is the two-player shortcut in data: Filter::Whose(Whose::Opponent) means "controlled by the other player". Uses when this was decomposed: seven card files (rust/crates/beryl_cards/src: azorius/teferi_hero_of_dominaria.rs, blue/abhorrent_oculus.rs, blue/jace_vryns_prodigy.rs, blue/sink_into_stupor.rs, white/elite_spellbinder.rs, white/portable_hole.rs, white/winds_of_abandon.rs), rust/crates/beryl_engine/src/cast.rs:117 and :322, filter.rs:93, trigger.rs, and seven tests. Read each card's Oracle text in data/cards.json and give it the entry that says the same thing: "an opponent controls" (any opponent), "target opponent controls" (the chosen one), "defending player controls".
  • Players: add what the 47 cards' text says and today's entries cannot ("defending player", CR 506.2, if a card says it; "target opponent" as distinct from "target player" if the targeting restriction is in a filter today). Do not add an entry no card uses.
  • Evaluation: filter.rs:93 (Whose::Opponent => you.opponent()), cast.rs:322 and interpret/scene.rs:231 (Players::EachOpponent => Who::only(self.you().opponent())) are where data meets the two-player shortcut. Keep them as the only places it does, each a small function named for the entry. The by-w8gv.5.13 (player API) bead later points them at the kernel's opponents-of.
  • Triggers ("whenever an opponent casts"), Affected, StaticCondition and Cost are redesigned in milestone 5 (Mason's notes on by-w8gv.9.1). Modification::Control(Seat) is milestone 4's (Mason note 7 on by-w8gv.5.1). Leave all of those.
  • tools/src/beryl_tools/xmage.py and forge.py export definitions to the oracles; if they read Whose, follow the rename there. just oracle <card names> for each card whose data changed.

Constraints

  • No N-player logic and no new rule. With two players every new entry evaluates to exactly what Whose::Opponent did, so rollouts_never_change holds.
  • Name entries in words (AGENTS.md: spell words out).
  • The scale harness's Python tests read card files: just check runs them for a card change.

Parity and checks

Parity (plan K11) at the push: just check passes; the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds (cargo test -p beryl_bench rollouts_never_change); slow CI's counts lane (just count-gate, bar 405,276,238 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. No behavior changes: no rules fix, no new card, no new mechanic. Work the card-names and file-length allowlists down as files are touched (data/card-names-allowlist.json, data/file-length-allowlist.json; an entry moves with its file and its count only falls; a new file is under 800 lines). Rules code cites the Comprehensive Rules (AGENTS.md); keep the citations of code you move.

Acceptance criteria

Whose and Players in beryl_card say what a card says: an opponent's (any opponent), each opponent, target player or opponent, the defending player, with the rule each cites, and no entry whose meaning is 'the one other player'; every use in the 47 card files and the engine is the entry its Oracle text says (checked against data/cards.json); evaluation in beryl_engine goes through one function per entry, so a second opponent would change those functions and no card; just oracle passes for the cards whose data changed; parity holds.
