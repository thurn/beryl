Close reason

Phase drafts shipped to staging. Implemented (121): 8/121 drafted, compiled and exact (6.6% each). Unwritten commons and uncommons (seed 50113): 11% drafted, 11% compiled, 9% exact. Of compiled sample drafts, 82% rendered exactly (prototype 63%).

Description

Why

just card brief (tools/src/beryl_tools/card.py: brief, with vocabulary.py and nearest.py) shows the ten vocabulary entries and the five implemented cards nearest by word overlap, and the writer composes the definition by reading source. For Mind Rot that is about 150 lines, and none of them is the definition. The goal is a brief that is short and close to the correct code, so a cheap model (tier:haiku, see by-ptc7.3.10) can finish a simple common or uncommon. Plan: Designs E5.

Matching whole sentences against the rendered abilities of implemented cards (this bead's first design) reaches little: two thirds of cards have a sentence no other card has, and there are 121 implemented cards. Composing below the sentence needs a grammar of Oracle text, which the plan decided not to write (P1). phase.rs (https://github.com/phase-rs/phase, MIT/Apache-2.0) has written one, and publishes its output: https://data.phase-rs.dev/card-data.json (83 MB), every card's abilities as typed JSON. This bead drafts from that JSON first and falls back to sentence matching.

The prototype (2026-11-15)

A 470-line stdlib Python converter, mapping about 45 Phase node kinds to Beryl builders, is in $BERYL_CACHE/phase-draft-prototype/ (convert.py; the harness scripts and results are beside it). It is a prototype, not the code to land: read it for the node shapes and the traps below.

  • Mind Rot comes out of Phase as {"kind":"Spell","effect":{"type":"Discard","count":{"type":"Fixed","value":2},"target":{"type":"Player"}}}. Translating that to Ability::spell().target(&TargetSpec::player()).effect(&discard(target_player(), 2)) is a field mapping, not parsing.
  • The 121 implemented cards (mostly hard keystones): 21 drafted completely, 19 compiled, and 13 of those render exactly as the hand-written definition does. All six others were Phase dropping or misreading a clause (Force of Will's alternative cost, Thirst for Discovery's "unless", Cerebral Vortex's damage, Reprieve's target spell read as a permanent), and each rendered differently from the Oracle text.
  • 60 random commons and uncommons that the converter drafted completely, written into new card files with just card new and compiled: 52 compiled (7 named a keyword Beryl has no Keywords bit for, Kitchen Finks's hybrid cost does not print); 33 of 52 render exactly to their Oracle text. Of the 19 that do not, 6 were the converter's wording (a sequence rendered "Scry 2. Draw a card." where Oracle says "Scry 2, then draw a card"; this() where Oracle says "it"; Mourning's abilities out of order) and 13 were Phase dropping a clause (Lava Coil's "if that creature would die this turn, exile it instead", Hieromancer's Cage's "until ~ leaves the battlefield", Hungry Flames's second target). Every one of the 19 showed up in the render diff, which names the missing words.
  • Reach. Of 19,304 normal-layout commons and uncommons in the card store, Phase parses 89% with no gap. The 45-kind prototype drafts 1,577 (8%) completely, and 1,080 more have only keywords and are complete from the store. Phase's commons and uncommons use 637 distinct node kinds (a field and its type tag); the 200 most common cover 81% of the cards Phase parses fully, and 400 cover 97%. The largest gaps of the prototype, by cards: composite costs (1,383), trigger fields it does not read (1,193), GenericEffect (781), mana abilities beyond one color (594), tokens (482).
  • Beryl's const evaluation rejected a nonsense draft at compile time (an effect naming a target its ability lacks), so a draft that compiles has already passed the definition's own consistency checks.

Build and compile cost: none

A hard bar: no Phase Rust code and no slower builds. This holds by construction.

  • Only Phase's published JSON is read, by Python, at authoring time (card brief, card new, set plan). No Phase crate, no Cargo dependency, nothing in any build script, no card data committed. A drafted card file is the same one-expression definition a person writes, so card compile time does not change.
  • The JSON is fetched into $BERYL_CACHE/phase/card-data.json on first use, with stdlib urllib. data/phase-data.json (described in data/AGENTS.md) pins the card_data_hash from Phase's coverage-data.json, so a draft is reproducible and a refresh is a deliberate change. Never commit the JSON.
  • With no network or no cached JSON, the brief falls back to sentence matching and says so.

What to build

  • tools/src/beryl_tools/phase_draft.py: Phase card JSON to a Beryl definition.
    • A table from Phase node kind to Beryl expression, written as data where it can be (one row a node kind). Use an existing prelude builder when it expresses the node clearly, passing the fields that vary.
    • Strict fields. A Phase field the converter does not read raises, naming the field, because ignoring one silently drops a clause (the prototype drafted Thirst for Discovery without its "unless" until it was strict). Each Phase object is checked against the fields its row reads.
    • Keywords only where Keywords has the bit; a card name through set_groups.camel (accents: Déjà Vu is DejaVu).
    • Skip a card whose Phase oracle_text differs from the card store's after render_diff.NORMALIZATIONS: the two describe different card text.
    • Merge Phase's one-Spell-ability-per-sentence for an instant or sorcery into one ability with a sequence; read sub_ability chains as sequence.
  • tools/src/beryl_tools/draft.py: the draft for a card. Phase's draft when complete; otherwise Phase's draft for the abilities it covers, and for each other sentence the sentence match against rendered abilities from implemented cards, or report the unresolved sentence with the three nearest examples.
  • The brief, short. When the draft is complete, just card brief prints only: the Oracle text, the draft, each sentence marked as rendering exactly or with its word diff (the [-missing-]/{+extra+} form of card render), and the rulings if Scryfall has any. The vocabulary, nearest-cards and XMage sections print only for a sentence the draft does not cover. Rendering needs the card compiled, so card brief renders when the card has a file and card new writes the draft, runs rustfmt and prints the render diff.
  • just card new writes the draft into the file in place of the empty definition.
  • The drafter's check, the number that says whether this works: over the implemented cards (each drafted with itself left out of sentence matching) and over a fixed random sample of 100 unwritten commons and uncommons (seeded; the prototype's commons-sample.json is a start), report the share drafted completely, the share that compiles and the share that renders exactly. Write it to $BERYL_CACHE and put it in the close reason. The prototype's figures are the floor: 63% of compiled commons render exactly.
  • tools/tests/test_phase_draft.py and test_draft.py, on small checked-in JSON fixtures, never the full file.

The drafter never decides behavior: a draft that renders differently from the Oracle text fails card render, and a draft that renders correctly still has to pass just card check against XMage and Forge. It composes only existing vocabulary entries and prelude functions; it never adds a variant.

Decision recorded: Phase as a drafting source

Root AGENTS.md bars Forge's scripts as a source of card data or design (its code is GPL). Phase is MIT/Apache-2.0, and its JSON is used only to draft a file that is then checked by the renderer and the oracles; nothing of Phase is committed. Chosen: allowed, for drafting and for counting (by-ptc7.3.9), never as an oracle or a vocabulary design. Credit Phase in phase_draft.py's module docstring and in data/AGENTS.md's entry for phase-data.json. P1 ("Oracle text is never parsed") still holds: Beryl parses nothing.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.

Acceptance criteria

just card brief prints a short draft (Oracle text, draft, per-sentence render status, rulings) and just card new writes it. No Phase code, crate or build step is added; the only Phase input is its published JSON in $BERYL_CACHE, pinned by data/phase-data.json. The close reason gives, for the implemented cards and for a seeded sample of 100 unwritten commons and uncommons, the shares drafted completely, compiled and rendered exactly, against the prototype's 63%.

Notes

2026-11-15, prototype follow-up: of the 13 commons whose draft lost a clause, 11 are missing it in Phase's card-data.json itself (the engine's card database; all marked supported with no gaps and not in Phase's semantic-audit.json). Two were the prototype's fault: Hieromancer's Cage has duration UntilHostLeavesPlay, which the prototype's field allowlist accepted on every effect but read only for pumps, and Carnelian Orb of Dragonkind has a sub_ability that the prototype's mana-ability path never looked at. So the strict check must be per field per node kind: a field counts as allowed only where the row actually reads it. Preflight on the MacBook Pro: the published Phase JSON is validated and cached at $BERYL_CACHE/phase/card-data.json. The earlier phase-draft-prototype directory is absent on this host. Use the published JSON, checked-in code, and the examples and measurements in this bead to rebuild the converter if the prototype is unavailable.
