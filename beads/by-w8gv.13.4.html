Description

Milestone 7b of Project 50k (docs/project-50k.md: K8 "Card files are grouped by first-printing set, in many crates, with registries generated at build time"; the "Crates" table; "A build script lists each set directory. No registry is kept by hand"). Lane set-crates, after the scenario value types moved off the engine (previous bead in the lane) and after the store gained first sets and data/set-groups.json (the data bead: its handoff names the helpers).

Today

  • rust/crates/beryl_cards/src/<color>/<card>.rs: 47 card files under azorius, black, blue, colorless, multicolor and white, each a pub static CARD: CardDef plus #[cfg(feature = "scenarios")] pub mod scenarios { pub const SCENARIOS }. A few also define tokens (HUMAN in adeline_resplendent_cathar.rs) or reach another card's file (crate::white::…, crate::blue::… in thieving_skydiver.rs, damn.rs, fractured_identity.rs, library/tokens.rs, library/linked.rs, library/actions/explore.rs, tests.rs; beryl_search/src/rollout.rs names one module path).
  • Hand lists: beryl_cards/src/lib.rs CARDS (a CardTable of 47 &CARD) and SCENARIOS; the six <color>/mod.rs.
  • beryl_cards/src/names.rs: 193 committed constants generated from docs/sample-decks by the names_are_current test (tests.rs:83), used as names::X by card files, decks.rs and about 150 sites in beryl_session, beryl_search, beryl_cli and beryl_bench.
  • tokens.rs (shared tokens) and props.rs (the prop cards scenarios name) are reached from card files by crate::.
  • The workspace is members = ["crates/*"] (rust/Cargo.toml).

What to build

  1. Set crates. Move every card file to rust/cards/<group>/<set code>/<slug>.rs (git mv, so history follows), group and set from the data bead's helpers. One Cargo package per group that has at least one file (no empty crates for the other groups yet), depending on beryl_card alone, plus the scenario types behind its scenarios feature. Add cards/* to the workspace members. No mod.rs is written by hand: a build.rs lists the directory and writes the module tree and the crate's tables (its cards, and with the feature its scenarios by card name) to OUT_DIR, with cargo:rerun-if-changed on the directories. Put the lister in one shared build-dependency crate (say rust/crates/beryl_card_build, standard library only; its Cargo.toml comment says what it replaces: the hand lists), so a set crate's build.rs is a few lines and the scale harness reuses it.
  2. The registry. beryl_cards becomes "the generated registry over every set crate, and the decklists" (plan, Crates): its build script lists rust/cards/* and generates CARDS and SCENARIOS over the set crates' tables. Delete the hand lists and the color mod.rs files. decks.rs, generate.rs, derive/, library/ (the rules library's hand-written scenarios, which name cards of several sets) and the beryl_scenario dump binary stay in beryl_cards. props.rs and tokens.rs must be reachable from a set crate without depending on the registry: move them below the set crates (a small rust/cards/shared crate, or props into the scenario types crate; choose and record). The cross-card reaches listed above become a dependency on a shared item, not on another card's file (AGENTS.md: "Helpers shared by two cards live in the shared library, not in a card file").
  3. Table order. A GameTable assigns game indices from the decklists by first appearance (beryl_kernel/src/table.rs:255), so saves and rollouts should not see CardTable order; the Mason audit believed they do. Find out: generate the registry in a deterministic order (group, set, slug), and if the corpus replay, rollouts_never_change or the count gate moves, something iterates CardTable::cards() in a way that matters. Fix that reader to look up by name or sort, rather than pinning a hand order. Record what you found.
  4. Names. No committed list and no list anyone edits. Default: beryl_cards::names stays the import path for every outside caller (do not touch the ~150 sites), generated at build time by the registry's build script from the decklists in docs/sample-decks plus every card with a file. Delete names.rs, the names_are_current test and its entry in tools/src/beryl_tools/file_length.py:25; keep the constants_spell_names_plainly property as a test of the generator. A card file names its own card and the cards its scenarios use without the registry: the set crate's build script generates the constants that crate's files use (its own cards'; other names its scenarios need come from the shared props crate, or are literals a test checks against the store). A misspelled name stays an error at build or just check time. Do not compile a 32,000-constant module into every crate.
  5. Tools follow the move. just card path <name> prints a card's file, or says the card is a store record with no file (tools/src/beryl_tools/card.py beside brief; where() at card.py:187 and definition() at :112 use it). Update the path knowledge in card_names.py:26 and :279 (cards_in, by which the oracle and script lanes map changed files to cards), nearest.py:17, two_player.py:23, board_door.py, discarded_push.py, specs.py:98, selection.py and script_checks.py if they map card files, scale.py (BERYL_CARDS, sources(): a later bead reshapes the harness; here only keep just scale --cards 200 --crates 2 working), and beryl_cli's specs if they read source paths. grep -rn "beryl_cards/src" tools ui/scripts rust justfile docs AGENTS.md finds the rest. Update AGENTS.md ("Layout", rust/) and docs/engine-architecture.md §16 for the new crates in a few lines.

A second card in a set costs its author one new file and nothing else: prove it with a test of the build helper (a temporary directory with two files lists both).

Decisions (K31: defaults taken, nobody asked).

  1. Layout. 47 files moved by git mv to rust/cards/<crate>/<set>/<card>.rs, in 18 set crates (the groups of data/set-groups.json that have a file). A set crate is Cargo.toml, build.rs (one call), lib.rs (one include!) at its root, with [lib] path = lib.rs, so every .rs one directory down is a card and no set code can collide with src/. Each depends on beryl_card, beryl_card_shared (below) and, behind scenarios, beryl_scenario_types: no kernel, rules or engine.
  2. beryl_card_build (rust/crates, std only, a build-dependency): set_crate() writes OUT_DIR/cards.rs (pub use of the shared modules, names, a module per set directory, CARDS, SCENARIOS); registry() writes beryl_cards' tables.rs (each set crate's table) and names.rs. beryl_cards gathers the set crates' tables in a const fn into one array. The one hand-kept list left is Cargo's: beryl_cards' Cargo.toml names each set crate as a dependency and in its scenarios feature; registry() fails the build with that sentence when a new crate is missing.
  3. Names come from the card store. A file is found in data/card-store.tsv by (set directory, module); a names::X a file uses is found by its spelling. So each set crate compiles only the constants its files use, a misspelled file or constant fails the build with the reason, and a file in the wrong set says where it was first printed. beryl_cards::names (same path, no outside caller touched) = decklists + basic lands + every card file; identical to the old committed list (185 constants, diffed).
  4. One spelling rule, changed from by-w8gv.13.2: set_groups.card_module now drops apostrophes (lim_duls_vault, was lim_dul_s_vault), so a card's constant is its module in capitals and no existing file was renamed. A card of two faces is filed by its front face, the engine's name (jace_vryns_prodigy.rs, not jace_vryns_prodigy_jace_telepath_unbound.rs); a split card by both halves (set_groups.file_name). The Rust rule has a table of accented letters (std has no NFKD); a test reads the whole store, so a refresh bringing a new letter fails in cargo test, not in a build script.
  5. Shared items: new crate rust/crates/beryl_card_shared (props.rs, tokens.rs, moved). Props are now string literals (they sit below the cards), held to the table by beryl_cards' tests/props.rs as before. The five token names another card's scenarios or the rules library used (Human, Map, Samurai, Insect, Rogue) moved to tokens.rs; each token's CardDef stays in its card's file, which re-exports the name. No card file reaches another's.
  6. Relocatable output. A warm rust/target is copied between worktrees and counted fresh, so nothing generated holds an absolute path: the set modules use #[path] relative from OUT_DIR (on the inline set module, which is where rustc reads its files from), and rerun-if-changed paths are relative to the crate.
  7. rustfmt does not follow generated mod lines, so cargo fmt no longer reached card files: the rust lane's fmt step, just fmt and by edit now run checks.py rustfmt (cargo fmt --all, then rustfmt on rust/cards///*.rs).
  8. Packet corrections: names.rs had 185 constants, not 193 (193 was its line count). script_checks.inputs() assumed every crate under rust/crates; it now follows path dependencies wherever they lead.
