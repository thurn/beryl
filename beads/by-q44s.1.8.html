Close reason

card image cache and queue moved into beryl_art

Description

Read first: rust/crates/beryl_app/src/art.rs and its tests. It serves card images to the web interface over the beryl-art URI scheme from a disk cache, with one download queue that keeps Scryfall's limit of an image every 100 ms.

Both clients need the queue and the cache. This is one of the few changes this epic makes to the main workspace (doc 'Checks and isolation', the exceptions), and it must not make the Tauri app link anything of Beryl 3D's.

Create rust/crates/beryl_art in the main workspace and move into it the queue, the cache, the path rules (Image, Origins, VERSIONS) and their tests, with no Tauri type in the moved code. Its dependencies are only those art.rs already uses for this; name each in Cargo.toml. beryl_app keeps only the URI scheme handler, which calls beryl_art. Behavior does not change: the same cache directory, the same file names, the same interval, the same errors.

beryl_art gets one function Beryl 3D will call: ask for an image by its record path, and get the cached file's path now, or a notification through a channel when the download finishes.

Run: just test-rust -p beryl_art -p beryl_app; just smoke.

Acceptance criteria

beryl_app's art tests pass from their new home; just smoke passes; the web interface still shows card images; beryl_art has no Tauri dependency and depends on nothing under rust/beryl3d; cargo tree -p beryl_app differs from before only by the new crate (paste the difference in a comment).
