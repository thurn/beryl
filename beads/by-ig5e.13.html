Close reason

Page served on 127.0.0.1: summary, epic, bead with timeline strip, session drill-down; shot command; pushed 0ed34ab6

Description

Build the page a person reads: a quiet first screen and drill-down from the project to an epic, a bead, a session and a single request or command, all rendered by Python from the same query results the command prints.

Design sections: "The page", "Isolation" (tests), and the three requirements at the top of the document.

What to build

  • just efficiency serve: a standard-library server on 127.0.0.1 only, GET only. Each address is a query (/bead/<id>?since=7d is efficiency bead <id> --since 7d), and the same address with .json appended returns the JSON.
  • An HTML renderer over query results, with inline SVG for bars and trend lines. No build step, no framework, no external file. One small script fetches a section's content the first time it is opened.
  • The first screen exactly as the design lists it: the range control (24 hours, 7 days, all), beads closed, four per-bead medians each with a trend line, one bar for agent time, one for dollars, the epics with "(no bead)" and "orchestration", and the words that lead to the other views (those views arrive in the next bead; link only the ones that exist).
  • Drill-down in place: an epic opens to its bars and beads, a bead to its bars, its timeline strip (one bar as wide as its wall-clock time, coloured by category) with the context size at each request under it, and its sessions; a session to its requests and commands.
  • The quiet rules of the design: a number has only its heading as a label; a heading's definition (from the query's field descriptions) appears on hover; unknown is a dash; one small control per opened section copies the equivalent command; light and dark appearance; one colour per category everywhere.
  • just efficiency shot <address> [--dark] [--width N]: render one address to a PNG in the cache with the headless browser the UI's scripts already use (see how ui/scripts/shots.mjs starts it and takes a page slot). A development aid, in no check. Use it to look at what you build: agents never open a window.

Design quality

The user asked for a clean page without excess words or chrome, with information revealed progressively. Before writing styles, take screenshots of the first screen and one opened bead at desktop and narrow widths in both appearances, and iterate on them until spacing, alignment and type are consistent. No explanatory sentences on screen.

Shared context

  • The design is docs/efficiency-dashboard.md. Read the sections named above before anything else; the rest can wait. The decisions taken with the user are in the epic, bd show by-ig5e.
  • The dashboard's code is the separate Python project in efficiency/ (package beryl_efficiency, standard library only, pyre strict, black). It imports nothing from tools/ and nothing imports it. Read efficiency/AGENTS.md first once it exists.
  • Tests use small synthetic sources built in the test itself or kept under efficiency/tests/. The repository is public: never commit a real transcript, session record or command line from this machine.
  • Real data exists only on the main Mac (host jarvis). Where the acceptance criteria name a check against real data, run it there; if this session is on another machine, record that the check was not run in a comment on this bead and close on the tests.
  • Collection must stay free for agents: no hook, wrapper or prompt text may be added to any session, and ingest must never run inside another command.

Acceptance criteria

Tests: every page and section renders as well-formed HTML for the fixture store and for an empty store; for every query, each number in the HTML equals the number in the JSON; the server refuses any method but GET and binds only 127.0.0.1; a section's address returns only that section. On the main Mac, just efficiency shot / and a shot of an opened bead show the four numbers equal to just efficiency summary and just efficiency bead, with no overlapping or clipped text at 1280 and 420 pixels wide, in light and dark.
