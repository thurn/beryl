Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'Messages', 'Responsiveness', 'Dropped connections and saving', 'Builds must match' (read with the epic's decision that builds match by WIRE_HASH).

Add to rust/crates/beryl_link:

  • src/wire.rs: the message enum in the epic's Contracts, serialized as the doc's JSON examples ({"hello": {...}}, {"act": {"n": 118, "action": ...}}), with hello.build renamed wire. fn encode(&Message) -> Vec<u8> is JSON compressed with DEFLATE (flate2, already used by beryl_session; comment the dependency); decode is the reverse. action and payload are serde_json::Value: this crate does not know tables.
  • src/host.rs: pub trait Hosted that the table session will implement later: fn seat_for(&mut self, name: &str) -> Option<u8>, fn act(&mut self, seat: u8, action: Value) -> Result<(), RefusalReason>, fn update_for(&mut self, seat: u8) -> Value (a whole view, sent after a join or a resume), fn lobby_for(..), fn left(&mut self, seat), fn dropped(&mut self, seat). And pub fn serve(link, hosted, wire, secret): reads hello; closes the link before sending any table data if the secret is wrong; refuses a different wire with the reason text "Both players need the same version of Beryl."; answers welcome with table: new|resumed; then for each act calls Hosted::act and answers done or refused with the same n. Sending updates is the caller's: give it a Sender handle (fn update(&self, payload), fn lobby(&self, payload)), because the host applies its own player's actions too and must send each seat its update before applying the next action.
  • src/guest.rs: pub fn join(connect: impl FnMut() -> Result<Link, LinkError>, hello) -> Guest. Guest::act(action) -> n, and an event stream of Done, Refused, Update, Lobby, Left, Reconnecting, Resumed, Mismatch(String). When the link drops without a leave, the guest redials with the same closure every 3 seconds until it succeeds or leave is called. Take the delay as a parameter so tests use zero.
  • ping every 5 seconds from each side; three missed answers count as a drop. Take the interval as a parameter. Record the round trip in PeerInfo.

Tests in tests/protocol.rs, all over memory::pair with a fake Hosted that keeps a counter: handshake; wrong secret closes with nothing sent; wire mismatch gives the message to both sides; acts answered in order; a refused act; sever then automatic redial gives Resumed and a whole update; leave stops redialling; a missed-ping drop. No sleeps: use zero intervals and channels. Run just test-rust -p beryl_link.

Acceptance criteria

The wire messages match the doc's JSON; serve and join implement handshake, secret, wire-hash refusal, act/done/refused, ping, drop detection, redial and resume against a fake Hosted; all tests are deterministic.

Handoff: beryl_link now has wire.rs, connection.rs, host.rs and guest.rs. Reuse a host::Host across serve calls, call Host::restore_guest when reopening a saved table, and share Mutex<impl Hosted> with local actions so each action publishes its updates in order. Hosted::connected installs a Sender after the whole view and any lobby snapshot are queued. Guest::take_events transfers the event stream to the caller. Guest::act becomes available after the initial view and never resends unacknowledged actions. An initial dial or join error emits Failed, while a drop after Welcome starts redial. Wrong secrets get no reply, and authenticated wire mismatches use Mismatch. Pong echoes Ping, and the expanded JSON limit is 32 MiB. Focused clippy, all 19 link tests, 100 repeats of the protocol suite, and a localhost TCP probe passed. The wire contract in the epic and the design document reflect the direct update and lobby payloads, Mismatch and Pong.
