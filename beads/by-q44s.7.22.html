Close reason

Touch taps, holds, drags, second fingers and double-tap bug reports in Beryl 3D with scene tests

Description

Read docs/beryl-3d.md “Motion the pointer drives”, “Hosts” and “Interface checks”. beryl_host Phone::pointer and beryl_3d src/ffi/types.rs pointer_from_c already forward pointer IDs and logical positions. Keep gesture state in beryl_scene src/pointer (add touch.rs); route it through src/client/input.rs Client::point and the existing pointer::update/let_go, RowGesture::handle, Client::press and client/inspect.rs Inspector. Use one active gameplay finger; no hover or card raise for touch. Follow docs/ui-conventions.md “The phone”: a tap on a card the prompt can use follows its primary action, while an otherwise unhandled tap opens full-card inspection (including the hand). Tapping outside dismisses it. Use the web Pointer's #click unhandled viewer fallback and keep the hand drag available for casting. A stationary 500 ms hold opens the card inspector for gameplay or the existing secondary/menu action in the manual table; the release must not also select. Movement beyond 6 points cancels the hold. Engine hand drags can begin immediately after the movement threshold; manual-table drags of cards that support secondary menus have the 150 ms pickup rule. Drag a scrolling row instead of playing a card, preserve drop-to-play and return-to-hand behavior, and cancel all pending state on cancel/leave or layout/screen change. Route surface-triggered cancellation through the Input::Surface branch of Client::handle; the furniture bead owns Client::resize. Placement owns the 44-point strips, which touch must hit through the same resolved frame geometry. Keep any per-pointer state bounded by existing pointer IDs. Use the explicit stepped clock, existing Wake::or_at and pending input/command path; do not allocate or rebuild layout in a frame to show a held press.

Web references: ui/src/stage/pointer.ts Pointer's press setup, move and release distinguish engine prompt drags, delayed secondary gestures and up without move; ui/src/mobile/report-taps.ts ReportTaps.down/move/up/cancel gives 80 ms together, 300 ms tap, 300 ms gap and 30-point drift/slop. A bare-felt single-finger double tap or a double tap with two or more fingers beginning together opens the existing bug report (Press::Sheet). The latter cancels the first finger's game action; a second finger arriving after the 80 ms window leaves the original gameplay gesture alone. Use data/beryl3d/space.json pointer.touch for timing and distance. ui/src/mobile/asked.ts askedTop belongs to the furniture bead; it keeps tap targets clear by placing the prompt around the cards.

Tests in beryl_scene tests/all/touch.rs send Input::Pointer via Client::handle and an explicit clock. Cover quick tap, stationary hold fires once, moves on release, cancelled hold, immediate engine drag, delayed manual drag, row scrolling without click, late versus simultaneous second touch, and eligible/ineligible double taps over cards, controls and bare table. Include a fixed-frame hit test of a 44-point exposed strip with two cards. Run: just b3d cargo-test -p beryl_scene --test all touch; just b3d cargo-test -p beryl_scene --test all pointer::; just b3d gate.

Acceptance criteria

Deterministic scene tests cover tap/hold/drag arbitration, exact exposed-strip hits and multi-touch report gestures. The existing mouse tests and frame gate pass.
