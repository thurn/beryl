Close reason

Layout::Card is the game index a state stores: Small keeps the one-byte CardIx, Large a two-byte LargeCardIx (65,535); GameTable is unbounded and a table past a layout is Misfit::TooManyCards at deal and relayout; counts 404,920,385 -> 404,824,958, sizes unchanged

Description

Milestone 3 (plan "State"; audit: "a game [holds] 255 distinct cards"). CardIx is a NonZeroU8: a game's cards, tokens and emblems share 255 indices. That is ample for two Legacy decks and is what Small keeps; it is a ceiling for formats and tools that load more (a cube, a sealed pool, a test table over the whole card store). This bead makes the width a layout parameter, as the bead before it did for capacities.

Read first

docs/project-50k.md: Decisions K6, K7, K11 and K12, and "Crates", "State" and "Kernel rules" under Target architecture. rust/crates/beryl_kernel/src/lib.rs: its rustdoc is the kernel's API contract (who writes, mutator and getter naming, events, the board door, the legacy accessor, sets and orders); follow it, and change it in the same push when the code proves it wrong. enact brief shows the handoffs of the beads this one depends on.

Also read the handoff of the by-w8gv.5.14 (capacities) bead: it settled how a layout parameter that sizes storage is expressed, and where a game that does not fit a layout is refused.

Scope

  • CardIx (beryl_kernel, from ids.rs:179): stored in Object::card, StackEntry::card, PendingTrigger::card, Lki::card, GrantRef::card, FloatingEffect::source, Player::emblems, Event payloads, Chance's records, GameTable's indices (defs, decks, listens, faces, def(card), index_of). About 100 mentions across the workspace when this was decomposed, most in beryl_kernel's state, table and ids files.
  • Decide the shape with the count gate in mind: an associated type on Layout (as Slot and Index are) threads through every record that holds a card; a wide index in the GameTable's API with a per-layout stored form converts at the kernel's boundary. Other crates (beryl_search/src/values.rs and frozen/, beryl_session/src/checkpoint.rs, beryl_cards' tests) name CardIx: whichever shape, they should keep compiling with at most a mechanical change, and beryl_search/src/expert and frozen/ change only where they no longer compile.
  • Small is unchanged byte for byte. Relayout to a layout with a narrower index is a typed error when the table does not fit, as for capacities.
  • TableError::TooManyCards moves to where a State of a layout is made, beside the deck-size refusal.

If it does not fit

If after a real attempt the parameter cannot be threaded without moving Small's count or its sizes, stop, record on the bead what was tried and the counts measured, leave CardIx as it is, and close the bead with that as its outcome: the Mason (by-w8gv.6.1) reads it. Do not raise the gate's bar and do not widen Small.

Constraints

  • Run just bench-count before and after and record both.
  • Saves name cards by name, not by index; if the frozen corpus disagrees, the corpus wins and the encoding does not change.

Parity and checks

Parity (plan K11) at the push: just check passes; the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds (cargo test -p beryl_bench rollouts_never_change); slow CI's counts lane (just count-gate, bar 405,276,238 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. No behavior changes: no rules fix, no new card, no new mechanic. Work the card-names and file-length allowlists down as files are touched (data/card-names-allowlist.json, data/file-length-allowlist.json; an entry moves with its file and its count only falls; a new file is under 800 lines). Rules code cites the Comprehensive Rules (AGENTS.md); keep the citations of code you move.

Acceptance criteria

The width of a game's card index is a parameter of Layout: Small's is the one-byte CardIx it is today (sizes asserted in the kernel unchanged, Object<Small> 24 bytes, State<Small> within 20 KiB) and Large's holds at least 65,000 distinct cards; a test builds a GameTable of more than 255 distinct definitions (cloned from the 47, as the scale harness does) and plays a seeded game in Large with check_invariants after every step; a table too large for a layout is refused where a State of that layout is made, with a typed error; parity holds.

Decisions and deviations (base 41fa67de).

  1. Shape: an associated type, Layout::Card: CardId, as Slot is. Small's is the CardIx it was (NonZeroU8, 255 indices); Large's is LargeCardIx (NonZeroU16, 65,535). Chosen over "a wide index in the table's API, narrowed at the kernel's boundary" because with it Small monomorphizes to the types it had: no conversion sits on a path the rollout takes. Every record of a state that names a card stores L::Card, so Derived, GrantRef, Lki and Copiable are now generic over the layout (default Small), DefinitionKey over the card type, and the engine's layers::Apply likewise.
  2. GameTable is layout-neutral and unbounded: decks are kept as plain indices, lookups take impl CardId, and index_of, index_named (new: three crates had the same scan by name), deck and indices give whichever CardId the caller stores. TableError::TooManyCards is gone; Misfit::TooManyCards { cards, indices } is raised by State::deal and State::fits. deck() now returns an iterator and deck_len() its length.
  3. State::fits and State::try_relayout take the table. A state alone cannot say whether it fits a narrower index: a token the table holds and no object yet is would pass a scan of the objects and then be created past the index. Only tests called them.
  4. What is kept outside a state names a card by the widest index (CardId::wide): chance::Random::Reveal holds a LargeCardIx. A recorded reveal of a card the game's layout cannot name is a Mismatch, as a card in no slot is.
  5. CardId::from_index is checked in both widths (one comparison, as CardIx::new made of a byte), so a table index is never cut down to pass for another card. The invariant behind the unchecked-looking table API: a State of a layout exists only for a table that layout numbers (deal, try_relayout; State::empty is used only by the kernel and Scratch's spare).
  6. beryl_search: CardValues keeps its 255 flat rows, which a Small index reads with no bounds check, and spills the rest to a Vec; get takes impl CardId. expert/mod.rs changed in three signatures; frozen/ did not change (it is Small-only and still compiles).
  7. Saves: nothing changed. A save names a revealed card by name (Entry::Reveal) and the frozen corpus replays.

Counts (just bench-count, rollout_counts corpus, bar 405,276,238):

  • before: rollouts 404,920,385; next_apply 377,144,188; policy 1,753,410; copy 15,127.
  • after: rollouts 404,824,958 (-95,427, -0.02%); next_apply 377,235,428; policy 1,751,639; copy 15,127.
  • Sizes: Object<Small> 24 bytes and State<Small> within 20 KiB, their assertions untouched.

What the count took, for whoever threads the next parameter. The first build was +634,017 (+0.16%) with every type of Small's identical. Two causes, both found by diffing the two binaries' layers::recompute, not the profiles:

  • layers::apply had been a non-generic function, so out of line; generic, it was inlined into recompute (+0.07%). It is #[inline(never)] now, with the reason.
  • GameTable::face_down_copy converted its index to the caller's width with a check. Copiable::record is inlined into recompute's scan of every permanent, and the check's panic path there cost registers in the hot loop (+0.1%; out of line as a call it still cost +0.05%). The table now keeps that one index in each layout's width and Layout::of picks it: one load, as before. So face_down_copy is generic over the layout, not the card type. What is left is +91K in next_apply (sba::legend_group_in: the same derived PartialEq of Derived compiled to a ccmp chain where it had a branch), under the policy's and other drift the other way.

Gotchas: (1) bare Copiable, Derived, Lki and GrantRef in code generic over L mean Small's: write <L>. (2) t.face_down_copy needs its layout named where nothing infers it (::<Small>()). (3) A generic function is instantiated where it is used and inlined on other terms than the non-generic one it replaced: if the count moves with Small's types unchanged, diff the function's disassembly in the two bench binaries (objdump in the beryl-bench VM, $HOME/targets/<worktree>/release/deps/rollout_counts-*), which found both causes here; the profiles alone did not. (4) GameTable::deck is an iterator now; (5) LargeCardIx prints as CardIx(n), as LargeSlot prints as Slot(n).

A reviewer should check: that nothing reachable makes a State<Small> for a table past 255 without State::deal or try_relayout (CardIx::from_index would panic, not truncate); chance.rs settle_but's trade when a recorded card is unnameable; Small's size assertions untouched (object.rs, state.rs, stack.rs, decision.rs); the count on the rebased tree in slow CI's counts lane (measured 404,824,958 before the rebase, bar 405,276,238).
