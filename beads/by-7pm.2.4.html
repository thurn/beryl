just test-rust now runs 'by test-rust' (tools/src/beryl_tools/rust_tests.py session_command, session_tests): no arguments is the check's own rust_tests_step (nextest in parallel, allocations and doctests through cargo test beside it); -p and name filters go to cargo nextest run, kept off the harness-less allocations targets; --doc, --test allocations, flags after -- and a machine without cargo-nextest get plain cargo test. A fresh worktree clones the cached target first. Measured in one worktree at load 25 on 18 cores: cargo test --workspace 9:06, just test-rust 1:22 (819 tests). One change in behavior: a name filter that matches no test now fails (nextest's 'no tests to run') where cargo test passed with 0 run. Description

Measured (by-7pm.2.2 Sage, 2026-11-08, worktree at 72ef2db9, tests prebuilt, load ~55 on 18 cores): just test-rust (justfile line ~156, cd rust && cargo test "$@") took 138 s and 123 s for the whole workspace. The fast check's tests step (tools/src/beryl_tools/checks.py rust_tests_step: cargo-nextest over every test binary in parallel, plus cargo test --test allocations beside it) took 47 s on the same build, with the same CPU time (~185 s user). cargo test runs the test binaries one after another.

AGENTS.md "Testing your work" step 1 sends every session to just test-rust, and they use it: in M1 the phone board session (by-7pm.1.4) spent 323 s on two runs, the shells session 268 s. Each M2 executor will do the same.

Change: make just test-rust run the tests the way the check does.

  • No arguments: the same jobs as rust_tests_step (reuse it, e.g. uv run --quiet --project tools python -m beryl_tools.checks rust-tests, or a by test-rust subcommand that calls it), falling back to cargo test where cargo-nextest is missing, as rust_tests_step does.
  • With arguments (-p beryl_app, a test-name filter): pass them through to cargo nextest run, keeping the common uses working: just test-rust -p <crate>, just test-rust <filter>, just test-rust -p <crate> <filter>. Check what -- arguments callers use (grep -rn "test-rust" AGENTS.md docs tools .claude ~/enact/skills and the skills under .claude/skills) and keep them working or update the callers. The harness-less allocations targets cannot run under nextest, so with arguments run them only when asked for (--test allocations goes to cargo test).
  • Update the justfile comment and, if the usage changes, AGENTS.md's mention.

Expected gain: about 90 s per full run (2.7x), several minutes per executor session.

Verify: just test-rust passes and prints failures readably (try a deliberately failing test locally, then revert it), just test-rust -p beryl_session, just test-rust -p beryl_engine <some filter>, and just check.

Acceptance criteria

just test-rust with no arguments runs the workspace tests through nextest (allocations via cargo test) and takes about as long as the check's tests step; -p and filter arguments still work; just check passes.
