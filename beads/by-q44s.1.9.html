Card faces in beryl_assets: decode, two sizes, ASTC/ETC2/BC7 via ctt, disk cache, LRU full faces; on staging at 5f2fdd4d0

Description

Read first: docs/beryl-3d.md 'Card faces'. Read rust/crates/beryl_session/src/card_records.rs for how a face's image addresses are found, rust/crates/beryl_art (the download queue and scan cache), and the closing comment of the bead that built every dependency for every target: it names the texture encoder to use.

In rust/beryl3d/crates/beryl_assets, on worker threads (add the path dependency on beryl_art):

  • Decode a cached scan with the image crate already pinned here, and scale it to board size (256 by 360) and full size (672 by 936), with mipmaps.
  • Compress into the first format the device supports of ASTC, ETC2 and BC7, with the encoder the cross-target bead named (ctt 0.6.1 unless its comment says otherwise), and fall back to uncompressed RGBA with one log line. The formats a device supports are an argument, a small enum this crate defines.
  • A disk cache of compressed faces beside the scan cache, keyed by image id, size, format and an encoder version constant. A hit is a file read.
  • prepare_match(decklists, formats) -> Receiver<Prepared>: every face of both lists at board size. A Prepared holds the layer's bytes for the renderer and the AssetReady for the client core. Full-size faces are prepared on request, at most 16 kept, least recently used first out.
  • A face with no cached scan gets a plain placeholder for now (its name on a colored field). Beryl's drawn frame is milestone 3's.

Measure and record on this bead, with the load: encode time per face for each format on this Mac, the time to prepare 150 faces cold and from the compressed cache, and the bytes of 150 board faces per format.

Tests in beryl_assets/tests: the cache key changes with the encoder version; a second prepare_match reads only the cache; the seventeenth full-size face drops the least recently used; no test assumes a scan exists.

Run: just b3d cargo-test -p beryl_assets.

What the prototype found (rust/prototypes/beryl3d, 2026-11-14; read its code for a working example, then build it properly):

  • The image crate 0.25 with only its jpeg and png features decodes and scales the scans; the prototype decodes 31 faces on 8 threads within its 45 to 65 ms start.
  • The app's scan cache is ~/Library/Caches/ca.thurn.beryl/art/<version>/front/<a>/<b>/<id>.jpg, with the card back under backs/large/.... On this Mac only 20 of the WU Control list's 31 images were cached.

Acceptance criteria

prepare_match delivers every face of two decklists as compressed layers, from the cache on a second run; the measurements are on this bead; nothing here runs on the thread that calls Client::frame (the workers are this crate's own threads, and a test asserts the caller's thread does no decode).

Compress one face with its full mip chain (ctt 0.6.1): ASTC 4x4 board 77 ms / full 388 ms (astcenc 'fastest'; quality-35 took 190 ms board, 'fast' 110 ms); ETC2 RGBA board 3 ms / full 18 ms; BC7 board 19 ms / full 44 ms; RGBA board 4 ms / full 13 ms. Decode+scale a scan to board size: 14-24 ms. 127 board faces (every implemented card, each given one of 49 real scans round robin) on 4 workers: cold (decode, compress, write cache) ASTC 1.9 s, ETC2 0.95 s, BC7 1.2 s; from the compressed cache ASTC 8 ms, ETC2 6 ms, BC7 6 ms. Bytes: one board face with mips 123,168 for each compressed format, 491,460 RGBA; so 150 board faces = 18.5 MB compressed, 74 MB RGBA. One full face 839,664 compressed. Also added to docs/beryl-3d.md 'Measurements'.

Derek Thurn2026-11-15

Handoff: beryl_assets now has encode.rs (Format::{Astc4x4,Etc2Rgba8,Bc7,Rgba8}, Format::choose, decode, encode -> Layer with mip levels, ENCODER_VERSION), cache.rs (CacheKey::file: <faces_dir>/v<encoder>/<format>/<board|full>/<scryfall id>-<side>.face, atomic writes), faces.rs (MatchFaces::list(decklists): card back is FaceId(0) = CARD_BACK, then each distinct picture of the cards and their tokens; find(name) -> FaceId; board layer = FaceId.0), placeholder.rs (name in Crimson Pro on a color field, via swash), prepare.rs (Preparer::new(Config{art, faces_dir, workers, wake}), prepare_match(decklists, &[Format]) -> Receiver<Prepared>, full(face) -> Full::{Kept,Queued{layer,evicted}}, 16 full layers LRU). Merged into the glyph bead's shared Prepared: new Upload::Face{layer, source}; Source says Cache/Encoded/Placeholder. Decisions: (1) match prep builds board size only; full size only on request (the doc's step 3 says both sizes on a miss, but that would make a cold ASTC start pay ~390 ms a face). (2) A missing scan is queued with beryl_art and the receiver dropped: the download continues so the next match has it, but no mid-match replacement yet (that is the client's 'no animation playing' rule, later work). Placeholders are never cached. (3) Stale results are dropped: a job of an older match, or a full face whose layer was reassigned (per-layer assignment numbers in atomics; a worker-only send lock keeps order per layer). The caller thread takes no lock a worker takes. (4) faces_built_on_this_thread() is the test hook for 'no decode on the caller thread'. (5) Full-size jobs queue FIFO behind board jobs. Gotchas: the renderer still uploads Rgba8Unorm placeholders; Layer formats are the *_SRGB Khronos formats (Format::khronos).
