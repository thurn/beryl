Description

Read the epic's contract first; this bead builds against it. Doc: docs/beryl-3d.md, 'Migration and compatibility' and 'The agent interface'.

Beryl 3D's look was ported by hand, and many elements lost their gradients and shadows because Style can't say them. Nothing lists which properties differ or which are missing.

Change:

  • Style diff. Add just b3d match styles <target>, which prints each paired element's differing properties (contract list), as key property web-value b3d-value. It compares normalized values: colors within 1 level per channel, lengths within 0.25 points, and shadow and gradient structures field by field.
  • Gaps. Add just b3d match gaps [--all]. Over the target or all test targets, it lists every web property value that Beryl 3D can't express, grouped by property and value shape (for example "box-shadow, 2 layers, one inset"). Each group is ranked by the total screen area of the elements that use it, and the report names three example elements. This list is the input of the conformance suite and the vocabulary beads, so write it as JSON too ($BERYL_CACHE/b3d/match/gaps.json).

Files: tools/src/beryl_tools/beryl3d/match/, beryl_scene/src/element/style.rs, beryl_scene/src/layout/style.rs, ui/src/stage/*.css (for the shapes in use).

Acceptance criteria

match styles and match gaps --all run, and gaps.json lists the unsupported property shapes by area. Parsing tests cover multi-layer shadows, gradients with stops and drop-shadow chains.
