Close reason

findings query with 15 rules in three unit groups and --rule detail, pushed cd5889f3

Description

Add the rules that point at waste, so that a reader or an agent starts from a ranked list and not from raw breakdowns. Findings never file beads.

Design section: "Findings".

What to build

  • The finding shape: rule, summary, saving_per_week (dollars, agent hours or core hours over the last seven days, above the rule's stated reference), evidence (the command that prints the numbers behind it) and examples (bead ids).
  • The rules of the design: wake-ups, fixed-prefix, carried-logs, small-reads, queued, narrow-leases, compile-share, repeated-command, outlier-beads, tier-gap, never-caught, flake-cost, misses, waiting-on-person, chained-commands. Each rule is one function over queries, with its reference written in its description.
  • Three groups, one per unit (dollars, agent hours, core hours), each sorted by saving. No unit is converted into another.
  • The findings query, with --rule to show one rule's full detail.

A first rough pass on 2026-11-15 suggested where the large ones are: 78 hours of orchestrator sessions waiting, each wake-up reading a large context again; 46 hours in 41,000 small shell reads; just ui-test run 835 times at a minute each. Treat these as things to confirm, not as results.

Shared context

  • The design is docs/efficiency-dashboard.md. Read the sections named above before anything else; the rest can wait. The decisions taken with the user are in the epic, bd show by-ig5e.
  • The dashboard's code is the separate Python project in efficiency/ (package beryl_efficiency, standard library only, pyre strict, black). It imports nothing from tools/ and nothing imports it. Read efficiency/AGENTS.md first once it exists.
  • Tests use small synthetic sources built in the test itself or kept under efficiency/tests/. The repository is public: never commit a real transcript, session record or command line from this machine.
  • Real data exists only on the main Mac (host jarvis). Where the acceptance criteria name a check against real data, run it there; if this session is on another machine, record that the check was not run in a comment on this bead and close on the tests.
  • Collection must stay free for agents: no hook, wrapper or prompt text may be added to any session, and ingest must never run inside another command.

Acceptance criteria

Tests: each rule fires on a fixture built to trigger it and stays silent on one built not to; a finding's saving equals the hand-computed difference from its reference; findings are grouped by unit and sorted within each group. On the main Mac, just efficiency findings prints three ranked groups, and running the top finding of each group's evidence command prints the numbers their summaries cite.

Derek Thurn2026-11-15

Decisions: evidence for every finding is 'efficiency findings --rule <rule>' (prints the items whose sums the summary cites), with 'see' naming the wider query. Figures are per week (divided by range weeks). Cohort = role+tier labels, min 5 beads; tier-gap compares tiers within a role by mean cost (direct+rework), 20+ beads each. small-reads counts Read/Grep/Glob as reads too. never-caught counts 'mixed' as a catch, all-time runs >= 100, CPU over the range, scripts ci/check/sweep/nightly. misses = bisection CPU + failed slow-CI runs on commits in the Steward range. compile-share: heavy kinds only (light commands printing cargo's Finished lines from logs inflated it 7x). repeated-command: only kinds whose cohort median >= 1 (else rare kinds counted whole time; 73 h -> 30 h on real data). A finding whose saving rounds to 0 is dropped. Real-data check on a scratch copy of the jarvis store: three groups printed; top of each group (tier-gap $3,173/wk, waiting-on-person 67.7 h, never-caught 585.5 core h) matched its --rule evidence; never-caught agrees with 'efficiency ci' rust lane 565.7 core h. A full findings run takes ~2.5 min wall under load ~60.
