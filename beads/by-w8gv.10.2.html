Close reason

ControllerOf(Those) reads the last controller of what moved; the check refuses unkept last known information (Malformed::LastKnown); 93b44b62

Description

Found by the M5 Mason audit (by-w8gv.10.1). A definition that compiles and passes its generated scenarios reads the wrong player in one corner.

Current design. The interpreter keeps last known information (CR 608.2h) in three shapes (rust/crates/beryl_rules/src/interpret/scene.rs, Registers): known[TARGETS] for targets an instruction moved, controlled (per player, the permanents the last moving instruction took, by who controlled each; Run::remember in interpret/run.rs writes it) and outcome. Scene::players reads Players::ControllerOf(objects) as the controller of each object where it is now, plus Known::controller for moved targets only (Scene::moved returns nothing for Objects::Those, All and the rest). So 'Destroy all creatures. Their controllers each ...' written as ControllerOf(Objects::Those) reads State::controller of a card in a graveyard, which is its owner (beryl_kernel/src/query.rs, controller): wrong for a permanent controlled by another player. beryl_card/src/effect/reference.rs documents ControllerOf as 'of one that has left, its last controller (CR 608.2h)', which holds for targets only. Nothing refuses it (beryl_card/src/check.rs walks it only), no assertion fires, and a generated scenario never steals a permanent. No card of the pool says ControllerOf today; Amount::ThoseOf already reads the controlled register correctly. The sibling hole, Condition::Is on a target the effect moved, is a debug assertion only (scene.rs, 'the last known characteristics of a target the effect moved'), so a release build answers false.

Proposed design. One rule for what a moved object was: Scene::players(ControllerOf(Those)) takes, for objects of the outcome that the last moving instruction took from the battlefield, the player whose controlled register holds them, and reads the rest where they are. Then either keep what Condition::Is needs in Known, or refuse in the definition check (a new Malformed class, as the Warden's a65a9389 did for MayCast, ChangeRule and unlisted tokens) every expression that would need last known information the interpreter does not keep: Condition::Is of a target after an instruction that moves it, and ControllerOf of a set no register covers. Prefer the refusal where keeping the value would widen Known; say which in the bead. The doc on Players::ControllerOf then says exactly what is kept.

Eliminates: a silent CR 608.2h error behind a doc that promises otherwise, and a release-only wrong answer behind a debug assertion, before milestone 8's pilot has a cheap model writing definitions.

Must not change: every card's scenarios, the frozen save corpus, rollouts_never_change, the count gate with no bump (the read is on the resolution path, not the hot path).

Files: rust/crates/beryl_rules/src/interpret/scene.rs (Scene::players, Scene::moved, Scene::holds), interpret/run.rs (remember), rust/crates/beryl_card/src/check.rs and check/tests.rs, effect/reference.rs. Tests: beryl_rules/src/tests/effects.rs has test definitions over the interpreter; beryl_card check tests show a refused definition. Add the docs/bugs.md entry AGENTS.md asks for.

Acceptance criteria

A beryl_rules test resolves a test definition 'destroy all creatures, then each of their controllers loses 1 life' (ControllerOf(Objects::Those)) with one creature owned by one player and controlled by the other: the controller loses the life, not the owner. A definition asking Condition::Is of a target after an instruction that moves it either answers from last known information in a test, or fails to compile its card() with a Malformed class a check test covers; no debug assertion is the only guard. just check passes; count gate holds with no bump.

Derek Thurn2026-11-12

Decisions. (1) ControllerOf(Those) reads the controlled register (Scene::controller in interpret/scene.rs) for a card that has no controller where it is now; one on the battlefield or the stack is read where it is, so a permanent that left and came back under another controller is not answered from a stale register. (2) Refusal, not a wider Known: Condition::Is needs a moved target's characteristics, which Known does not hold, so the definition check refuses it (Malformed::LastKnown). The check now follows what each instruction may have moved, in order, through If branches (either way) and ForEachPlayer (read twice, for the next player's turn). Refused after a move: Condition::Is, EnteredThisTurn and Token of a target, This, AttachedTo or TriggeredOn; ControllerOf, OwnerOf and Power, Toughness, ManaValue, Counters of This, AttachedTo or TriggeredOn (a target's are kept in Known). No card of the pool trips it. (3) Beyond the bead's text: for_each_player now gathers the controlled register across players as it does the outcome, since each player's moving instruction overwrote the one before; no card moves inside a ForEachPlayer today (Winds of Abandon only reads there). Not done: ControllerOf(TriggeredOn) of a trigger on an object that had already left before the ability resolved (a dies trigger on a stolen creature) is the trigger's last known information, not the effect's, and is untouched here.
