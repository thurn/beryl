Close reason

test-rust prints cargo's Finished line with build seconds

Description

On jarvis only 120 of 1,963 'rust tests' tool calls in the efficiency store have a compile/run split. The dashboard (efficiency/src/beryl_efficiency/claude.py, compile_seconds and FINISHED) reads cargo's 'Finished test profile ... in Ns' line from a command's output, but tools/src/beryl_tools/rust_tests.py runs nextest with --cargo-quiet (lines ~294 and ~551), so cargo never prints it. Print one line in cargo's format with the build's seconds from rust_tests.py (for example by building with cargo nextest run --no-run --cargo-quiet first and timing it, or by timing until nextest starts running tests), without bringing back cargo's per-crate Compiling lines, which cost agents tokens.

Acceptance criteria

After a source edit, just test-rust -p <crate> prints one 'Finished ... in Ns' line; a test in tools/tests checks the line's format matches efficiency's FINISHED pattern; on jarvis, a new rust-tests call in the efficiency store has compile_seconds set and the bead query shows a compile part.
