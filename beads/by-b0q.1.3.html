Close reason

UI design system (tokens, fonts, cards, controls, orbs, piles, stack, arrows, overlay), pseudo-3D table, fixture transport and just ui-shots; reviewer subagent: no major discrepancy

Description

Part of Milestone 1 (epic by-b0q): a rules-exact engine, game UI and AI opponents for a mirror match of the 40-card WU Control main deck in docs/sample-decks/2026-10-17-PrinceJools-wu-control.txt (29 distinct cards). Read the epic's description (plan, card table) and design field (decisions) first; docs/engine-architecture.md is the design. Rules code cites the Comprehensive Rules with yawgatog links and quotations (AGENTS.md).

Design decisions 10 and 11. The component library in docs/ui_mockups/ui_system.png, and the tooling every later UI bead uses to check itself without opening a window.

  • Add Motion (the motion package) and Playwright (dev dependency; the WebKit browser installed by the recipe into the cache, not the repo).
  • Tokens from the mockup: Table #625C56, Surface #242321, Text #F2ECE1, Gold #E9AD4A, Cyan #38DCFF; a serif for titles and actions, a sans serif for instructions, both bundled locally (open-licensed, for example via @fontsource) since the app runs offline; matte tabletop; thin metallic borders.
  • Components: primary, secondary and disabled buttons; the priority pill; the phase tracker; active and inactive life orbs; player badges; library and graveyard piles; stacked lands with a ×N count; the card frame (name bar colored by color, art, P/T badge, type line, rules box, mana symbols from an open-licensed set) with its states: tapped, source (gold glow), target (cyan glow), attacker (angular) and blocker (rounded); the stack-item frame; arrows (gold source to ability, cyan ability to target); the overlay shell with a dimmed battlefield backdrop.
  • A pseudo-3D table: CSS perspective and depth shadows, laid out as battlefield.png. No WebGL.
  • A gallery route that reproduces ui_system.png with placeholder art.
  • ui/src/ipc.ts: a transport abstraction, Tauri or fixture, so screens run in a plain browser. The fixture transport replays a recorded stream of messages; the sessions bead defines their types.
  • just ui-shots (in by): serves the UI with Vite, captures a configured list of routes and states with headless Playwright WebKit into a gitignored folder, and prints the paths. Later beads add fixture states to the list.

Acceptance criteria

  • npm run typecheck and prettier pass; just smoke passes.
  • just ui-shots captures the gallery. A reviewer subagent compares it with docs/ui_mockups/ui_system.png and finds no major discrepancy; its verdict is a comment on this bead.
  • No screenshots committed; nothing opens a window.

Derek Thurn2026-11-05

Executor decisions:

  • Screenshots go to $BERYL_CACHE/ui-shots/<checkout>/ (outside the tree, wiped per run) rather than an in-repo gitignored folder: .gitignore says run output lives in the cache, and the shots outlive the worktree for the Warden. WebKit installs to $BERYL_CACHE/playwright.
  • by ui-shots (tools/src/beryl_tools/shots.py) serves Vite on a free port and drives ui/scripts/shots.mjs (Node: Playwright's API is JS; the Python package would be a new dependency). Shot list: ui/shots.json (name, hash route, optional ?fixture=, viewport). Captures use reducedMotion and wait for fonts and finite animations; a page error fails the run.
  • ipc.ts: Transport (invoke/listen), Tauri inside the app, else a fixture transport replaying {kind: response|event} messages; ?fixture=<name> loads /fixtures/<name>.json from ui/public/fixtures (gitignored). The sessions bead defines the payload types.
  • Fonts: EB Garamond (serif) and Inter (sans) via @fontsource-variable; mana symbols from mana-font (OFL font). Only mana.woff2 is registered, because mana.css also bundles MPlantin, a proprietary font.
  • Table depth: headless WebKit ignores perspective()+translateZ on screen-parallel layers, and a rotateX plane keystones every card, which the mockup does not. Permanents are upright and scaled by the projection d/(d+z) with depth rising up the table (Table.tsx depthScale), plus a slab edge and cast shadow; the hand leans back with real CSS perspective (rotateX).
  • Routes: #/gallery, #/table, #/table/scry.

Reviewer subagent verdict (cold-context acceptance review of just ui-shots output: gallery.png vs ui_system.png, table.png vs battlefield.png, table-scry.png vs scry.png): NO MAJOR DISCREPANCY. It confirmed every listed component and state, the depth treatment (far creatures ~184px vs ~185 scaled mockup, near ~197 vs ~201), the hand fan and tilt, the arrows, and the dimmed overlay backdrop. Earlier critique round (user-requested) found major gaps, all fixed before this verdict: black card body, metallic-blade life orbs with the active ray flare, the table's compact phase tracker (filled glyphs, diamond caps, gold-underlined current step), card-wide attacker chevron and blocker arc, shield stack item with large centred text, the scry overlay's column layout, and a weak depth treatment. Minors applied after the verdict: scry content 18px lower, a fuller gallery scry crop, graveyard pile edges, deeper amber primary buttons, a silver frame for dual lands, readable swatch hex. Minors left as polish: the full-art Island frame in scry (the mockups disagree on type lines for lands in hand), a darker frame for mono-black spells, the opponent's hand foreshortening, and the outline icons in the gallery's full tracker (they match ui_system.png). The user asked for a closer match to the mockup's subtle perspective: battlefield cards now stay upright and scale with depth (Table.tsx depthScale) instead of tilting on a rotateX plane, which keystoned every card.
