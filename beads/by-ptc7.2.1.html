Close reason

Added and verified the rulings ledger, names check, and card commands on staging b773569188.

Description

Why

just card brief prints Scryfall's rulings for a card (79,706 rulings for 20,080 cards in $BERYL_CACHE/scryfall/rulings.jsonl.gz, read by card.rulings() through scryfall.bulk_file("rulings")). Each ruling says what a card must do. by-bajq's beads told writers to turn rulings into scenarios, and nothing recorded which were. Plan: Designs A, "The rulings ledger".

What to build

  • data/rulings-ledger.json: per card name, a list of entries, each identifying one ruling by its published_at date and a short hash of its comment, with exactly one of scenario (names of scenarios in the card's file or in beryl_cards/src/library/), covered (the vocabulary entry or rules-library scenario that shows it for every card) or untestable (the reason: it restates reminder text, it is about a tournament procedure, it needs a card nobody has implemented, which is named). Keep the ruling's text out of the file: the hash is the key, and the text is Scryfall's.
  • tools/src/beryl_tools/rulings.py: a step rulings in the names lane (lanes.py, checks.steps()). It fails when a listed card has a ruling with no entry, an entry names a scenario that does not exist (read scenario names with beryl_scenario dump output or by scanning the card file, whichever is cheap), or an entry's hash matches no ruling. It is skipped, with a logged skip, where the bulk file is not cached (as citations is where the rules text is not). A card that is not listed is not checked.
  • just card rulings <name>: each ruling's text beside its entry, and --add to append entries for rulings that have none, with untestable left empty for the writer to fill.
  • just card brief marks each ruling with its entry's state.
  • Describe the file in data/AGENTS.md, the check in docs/checks.md, and add tests in tools/tests/test_rulings.py with a synthetic rulings file.

Seed the file with one card audited end to end, Blood Moon, so the format is proven: every ruling a scenario, covered or untestable.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.
