Close reason

e8a2f9a6 and 5c6b5c68: Enact's remove hook saves rust/target only from slow CI's worktrees (named ci-<12 hex>, detached) and marks the cache with .beryl-slow-ci; other worktrees save only where slow CI has not saved within a day (the second Mac). I chose the worktree name Enact already gives over a new marker or environment variable. mark_unread and the UNUSED_DAYS eviction stay, because slow CI's prune still uses access times. Measured after: removing an agent worktree left the cache untouched. A fresh worktree after a beryl_kernel public-API change built its tests in 59 s wall and 520 CPU-seconds at load 12-18, compiling only workspace crates (cold before: 148 s and 1,158 CPU-seconds). iroh, reqwest and rustls are now only in beryl_link_iroh, which routine builds exclude.

Description

Symptom

The fast check (by check) goes over its 60 s budget on most pushes that touch Rust: the Rust lane takes 100–300 s, and the check files an "Audit slow steps" bead (check-budget) about every 75 minutes (15 between 2026-11-13 18:00 and 2026-11-14 14:47). Each bead's session fixed one symptom (by-vyom, by-tbbr, by-3dgk, by-z3np, the mark_unread fix in warm.py), and a new bead was filed within minutes.

Cause: the shared Rust cache is last-writer-wins

tools/src/beryl_tools/warm.py gives each new worktree an APFS clone of $BERYL_CACHE/target (ensure_target). When Enact removes a worktree, its remove hook (remove_hook -> save) prunes that worktree's rust/target and then replaces the whole cache with it (replace(target, cached)). Nothing merges the two. So whichever worktree is removed last decides what every later worktree starts with. If it built only part of the workspace (a -p build, a change with no Rust lane, a run on a target that started empty), the cache loses everything else.

What was measured on 2026-11-14, at load about 30 on this Mac:

  • The cache held 584 fingerprints for 101 crates, all built that day. It had no tokio, tauri, tauri-utils, reqwest, iroh or rustls. Its CACHEDIR.TAG was dated 01:55 local, so a target that started from nothing had replaced the cache then. A full workspace build has 1,526 fingerprints.
  • In a fresh worktree cloned from that cache, after a public-API change to beryl_kernel: cargo clippy --workspace --exclude beryl_bench --all-targets took 15 s. cargo test --workspace --exclude beryl_bench --no-run took 148 s wall and 1,158 CPU-seconds, mostly rebuilding third-party crates (cargo --timings: tauri-utils 46 s, noq-proto 40 s, tauri 31 s, reqwest 30 s, iroh 29 s, rustls 23 s, tokio 22 s).
  • The same test build after a second kernel change took 13 s. A warm worktree fits the 60 s budget even at load 30. The overruns are cold caches, and the many sessions rebuilding the same crates at once account for much of the machine's load.

Change

Make slow CI the only writer of $BERYL_CACHE/target:

  • Slow CI's worktrees (the ci-<sha> worktrees that enact ci creates) build the whole workspace, its tests and the app at the tip of staging. After a run whose Rust build succeeded, the cache is saved from that worktree as it is now.
  • Every other worktree clones the cache as now (ensure), but its remove hook no longer saves rust/target back. It still deletes it. Keep saving ui/node_modules as now, since that cache is already keyed by the package-lock.json.
  • Decide how a save tells a slow-CI worktree from others. Prefer something Enact already sets, such as the worktree name or an environment variable from enact ci, over a new marker file. Record the choice on this bead.
  • Keep prune, record_sources, restore_sources and rehome working as they do. Check whether mark_unread and the UNUSED_DAYS eviction are still needed once only full builds are saved, and delete what isn't.
  • Windows (Cygnus) uses the same code with robocopy. Make sure it still saves from its own slow-CI worktrees.
  • Update the module docstring in warm.py, and the "Outside the repository" note in AGENTS.md if its description of the cache changes.

Tests

tools/tests/ has warm.py's tests (find them with grep -rl warm tools/tests). Add a test that saving from a non-CI worktree leaves the cache untouched, and one that a slow-CI save replaces it.

Acceptance

  • After an agent worktree that built only part of the workspace is removed, $BERYL_CACHE/target/debug/.fingerprint still holds the third-party crates (tokio, tauri, reqwest).
  • In a fresh worktree after a slow-CI save, a public-API change to beryl_kernel builds its tests (cargo test --workspace --exclude beryl_bench --no-run) without rebuilding any third-party crate. Record the wall and CPU seconds on this bead.
