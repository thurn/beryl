Ash and vortex particles for vanish in Enhanced landed (145af96b5)

Description

Read first: the epic by-q44s ('Rules for every bead', rules 2, 3, 6 and 7b); rust/beryl3d/AGENTS.md; docs/beryl-3d.md 'The Enhanced tier' (particles), 'Effects' (dissolve and blanch, and the rule that an effect never changes where anything is), 'Determinism' and 'The frame' (the particle row of the material table).

The looks of vanish in the Enhanced tier: a destroyed permanent falls to ash as it dissolves (dissolve), and an exiled one is drawn into a vortex as it whitens (blanch). The client core writes the particles as records; the renderer skeleton bead already shades them (shade_particle). The web interface has no particles, so there is no web file to follow: the shapes below are the design. Edit only beryl_scene src/effects/particles.rs (new), the one call in src/play/mod.rs, src/effects/mod.rs's module list, the tests named below and data/beryl3d.

What exists: EffectRun { effect, on, start, duration, curve, step } (src/effects/mod.rs), the show's runs; effects::light::write(runs, now, scene, builder) (src/effects/light.rs), called from src/play/mod.rs, which finds what a run is on with scene.reach(run.on) and draws one record per run, allocating nothing (follow it); effects::card::look, which darkens a dissolving card and then raises look.dissolve from 0 to 1 after dissolve::DARKENED of the run, and whitens a blanching card to blanch::WHITE before fading it; the Baseline shader breaks a dissolving card from the top down (DISSOLVE_GRID in beryl_render src/shader.wgsl). Draw::particle(transform, tint, sprite, age, seed), Band::Particles, PARTICLES (2000) and FrameBuilder::tier() come from the contract bead.

Build, in src/effects/particles.rs, write(runs, now, scene, builder), called right after effects::light::write and returning at once unless builder.tier() is Tier::Enhanced:

  • Add enhanced.particles to data/beryl3d/space.json: ash: { count: 96, life: 0.35, size: [1.2, 2.4], fall: 18, drift: 6 } and vortex: { count: 128, life: 0.5, size: [1.0, 2.0], turns: 1.5 }, lengths in millimetres and lives as a share of the run.
  • Each particle is a pure function of the run, its index and now: no state between frames, so a frame drawn after skipped frames is the frame drawn after every tick. Its randomness is hash(object id, run.step, index, k), a 32-bit integer hash written in the file (no random number generator, no clock), giving numbers in 0 to 1. Its seed field is the first of them.
  • Ash, for each dissolve run on a card, while look.dissolve would be over 0: particle i is born when the breaking edge passes its row (its row a hash, its birth the share of the run at which card::look's dissolve reaches that row from the top), at a point of that row across the card's width (a hash), and for life of the run falls fall mm toward the table and drifts up to drift mm sideways, eased out. Its tint is the dissolve's dark color from card::look's darken at its darkest, its sprite Sprite::DISC, its size between size's ends (a hash), and its age the share of its life gone.
  • Vortex, for each blanch run on a card: particle i starts at a point of the card's face (two hashes), born in the first half of the run, and for life of the run turns turns times round the card's centre on a spiral that ends at the centre, shrinking to nothing. Its tint is the blanch's white from tokens::color. Its sprite is Sprite::DISC.
  • Particles lie in the card's plane, placed with the card's pose of this frame, so they follow a card that moves.
  • Count: when the frame's runs want more than PARTICLES particles, each run gets PARTICLES / runs (rounded down) of its particles, lowest indices first; never more than PARTICLES in a frame. Allocates nothing (the allocation gate holds it).
  • Write no other colors than these two (rule 6): add none to the tokens file.

Tests, in beryl_scene/tests/all/particles.rs, on hand-built scripts of a vanish with each case (follow how tests/all builds scripts with beryl_scene::testing):

  • in Baseline a frame writes no particle records;
  • in Enhanced a dissolving card writes ash records only after its darkening, a blanching card vortex records, and each count is at most its count;
  • the same moment drawn directly and after stepping every tick from the script's start writes equal records;
  • two clients given the same script write equal records; a different object id gives different seeds;
  • forty cards dissolving at once write at most PARTICLES records in total (Load::particles);
  • resolved is equal in both tiers at every frame of the script (the contract's tier check covers the gated boards; this covers a board with particles).

Must not build: any shading in beryl_render, bloom on particles, the gate's limit on particles (the limits bead).

Run: just b3d cargo-test -p beryl_scene; just b3d cargo-test -p beryl_inspect; just b3d gate; just b3d lane.

Beads named above: the contract bead (the tier input and the check) is by-q44s.11.2; the renderer skeleton bead is by-q44s.11.3; the shadow map bead by-q44s.11.4; the lighting bead by-q44s.11.5; bloom by-q44s.11.6; particles by-q44s.11.7; the tier choice bead by-q44s.11.8; the settings row by-q44s.11.9; the limits bead by-q44s.11.10; the settings screen bead by-q44s.5.27. Every bead of this milestone depends on by-q44s.4, the review gate before it.

Handoff: new rust/beryl3d/crates/beryl_scene/src/effects/particles.rs (write, called after effects::light::write in src/play/mod.rs); data in space.json enhanced.particles (ash/vortex counts listed in top-level counts); tests in beryl_scene/tests/all/particles.rs (6 tests, 0.04 s total). Decisions: (1) birth, life and age are shares of the run's EASED progress, the same progress card::look uses, so ash leaves a row as the dissolve edge passes it under any curve (vanish is linear anyway). (2) 'Falls toward the table' is taken as falling down the card's face (local -y) so particles stay in the card's plane as the bead requires. (3) There is no blanch-white token. The web blanch paints rgb(var(--light)) = 255 246 222, which tokens already hold as color::TRAIL, so the vortex uses that and no token was added. (4) Ash tint = white x dissolve::DARK, which is the card's darkest tint in card::look for a white card. (5) Only Subject::Object runs write particles. Ash particles born near the bottom rows are cut off when the run ends (the card is fully dissolved by then). The renderer's shade_particle is not on staging yet (renderer skeleton bead), so nothing shades these records yet. Lane: tests 729 passed, gate passed, interface 8264 tests 0 failed, timeline passed. Reviewer: check the hash in Seeds::random and the PARTICLES/runs share in write.
