Close reason

Client lists faces from card records and draws cards from their layers; check_recording and b3d check run blank-card

Description

Symptom: every recorded fixture fails the blank-card interface check on every card ("is drawn face up with no face of its own"), because the client never sets Resolved::face: Table::write in rust/beryl3d/crates/beryl_scene/src/table/scene.rs always writes face: None and draws every card from layer 0. beryl_inspect::pages::check_recording therefore leaves that rule out (pages::LEFT_OUT).

docs/beryl-3d.md ('Inputs', AssetReady::Face { face: FaceId, size, layer }, and 'Card faces') says a FaceId is an index into the list of faces the client made when the match loaded, and the worker reports which texture-array layer each face landed in.

Build in beryl_scene:

  • The client's face list: one FaceId per distinct card face it can show, made from the recording's card records (the first message of every recording in the pack, card_records::fixture_message) or the session's equivalent, and a way for the host to read it so the worker knows what to prepare.
  • Client::handle(Input::Assets(AssetReady::Face { .. })) records the layer for each face and size; Table::write sets Resolved::face and the card draw's layer for a face-up card whose name the viewer knows once its board-size face has a layer.
  • The test driver (Page, rust/beryl3d/crates/beryl_scene/src/driver/mod.rs) acts as a host whose faces are all ready: it answers the face list with one AssetReady::Face per face at the start. Then remove Rule::BlankCard from pages::LEFT_OUT (and LEFT_OUT itself and Page::check_without if nothing else uses them).

Tests: beryl_scene: a face arriving gives its cards that layer and blank-card passes; a face that has not arrived leaves the card on layer 0 and faults. Client::frame still allocates nothing (beryl_inspect/tests/frame_allocation.rs).

Acceptance criteria

check_recording("verbs-zones") passes with blank-card run (nothing left out); the face tests pass; just b3d lane passes.

Handoff: commit b7f2e04. New beryl_scene::faces: FaceList (built from CardRecords; FaceId 0 is the card back; a token's face is also found by its token_printing key 'token:<name>:<id>', which the view sets) and Faces (the list plus the board/full layer of each face). New Input::Cards(Box<CardRecords>) makes the list, Client::faces() exposes it to the host, and AssetReady::Face records layers. Show owns Faces and Table::write takes &Faces: a card draws its face's board layer (0 until it arrives), and the back draws the card back's layer. Resolved::face is set whenever the name (or printing) has a board layer. The driver (Page::begin) and the gate's Playback give Cards plus FaceList::all_ready() (layer = FaceId) before the first view, so the allocation gate now covers the face lookups. Stress boards get a card_records::fixture_message first, as recordings do. Removed pages::LEFT_OUT, Page::check_without and the '(left out)' text in 'b3d check'. Deviation from the plan: beryl_assets::MatchFaces is now built from the same FaceList (MatchFaces::new(&list); decklist_faces(decklists) builds a list without a client) and Preparer::prepare_match takes &FaceList instead of decklists, so FaceIds agree between the client and the workers (noted on by-q44s.1.41). Gotcha: the hand-built test view's token is now named 'Soldier Token', because the store names tokens with a ' Token' suffix. Verified with just b3d lane, just b3d check verbs-zones (1244 frames, 0 faults) and pay-default.
