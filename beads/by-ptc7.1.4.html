Close reason

Five kernel lints enforced on staging. Targeted Rust suites, pinned rollouts and frozen saves passed. Count gate passed at 379,552,664 before and 379,802,256 after (+0.07%). Fixed the merged-zone query panic and the validation gap for granted abilities that define both power and toughness.

Description

Why

Nine logged bugs were a reader that handled some kinds of a thing and silently skipped the rest, and five were a value narrowed wrongly between the Small and Large layouts. A wildcard arm and an as cast are how the compiler lets both through. Plan: Designs B1 and B2.

What to do

In rust/crates/beryl_kernel only:

  1. Add #![deny(clippy::wildcard_enum_match_arm, clippy::cast_possible_truncation, clippy::cast_possible_wrap, clippy::cast_sign_loss, clippy::cast_precision_loss)] at the top of src/lib.rs, with a comment saying why (a crate that inherits the workspace's lint table cannot add to it in Cargo.toml).
  2. Rewrite each wildcard arm over an enum (73 arms outside tests) to name the variants it stands for. Behavior must not change: the named variants do exactly what _ did. Where a reader really means "any other kind", give the enum a predicate that is itself an exhaustive match (in beryl_card for a vocabulary enum, beside its definition) and call it, so a new variant is classified once.
  3. Replace each as cast (79 outside tests). A discriminant read becomes a const fn on the enum (Zone::index). A narrowing becomes try_from with the failure handled, or layout::index::<L> (which panics out of range) where the bound is argued in a comment. A count that must fit a byte saturates and says so. Helpers that exist: layout::index, SlotId::try_from_index, Slot::try_new, relayout::{slot, card, bits}, widen_mask, the index! newtypes of beryl_card/src/index.rs.
  4. Tests may keep wildcards and casts: put #![allow(..)] on the tests module, not on items one at a time.

Most arms are in static_ability.rs (12 arms), memos.rs (7), effects.rs, stack.rs; casts in trackers.rs (13), ids.rs (8), object.rs, rule_changes.rs, zone.rs.

A wildcard that hid a real gap (a variant the reader should handle and does not) is a bug: fix it in its own commit with a scenario and a docs/bugs.md entry, or file it as a child of this milestone if it is large.

Other sessions are editing these crates. Land this as several small pushes, one directory at a time, so that each rebases easily. The deny line goes in with the last one.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.
