Warden review of M5 (all 18 beads), read at staging f553102d; fixes pushed as a65a9389.

Found and fixed (one commit, a65a9389): three definitions the engine could not carry out as written and nothing refused.

  1. Effect::MayCast anywhere but last in its effect, or inside ForEachPlayer: the card is offered as the resolution finishes (casting::offer sets one slot), so later instructions ran before the cast and a second offer replaced the first, silently. Now Malformed::Cast (beryl_card/src/check.rs, casts_last).
  2. Two Effect::ChangeRule in one ability: Ability::effect names only the first to the game (Effect::starts), so the second panicked in continuous::change_rule when it resolved. Now Malformed::Rules.
  3. An effect creating a token or emblem its card does not list in CardDef::tokens: tokens.rs and emblems.rs panic on index_of when it is created. card() checks before .creating() adds the list, so the table refuses it: TableError::Unlisted (beryl_kernel/src/table.rs, listed; CardDef::creates in beryl_card/src/walk.rs; beryl_session/src/replay.rs reports it). Tests: check/tests.rs what_an_effect_as_a_whole_cannot_mean_is_refused; table/tests.rs a_table_refuses_a_card_that_creates_what_it_does_not_list. No card of the pool said any of the three. Also two stale doc lines (Objects::Paid named a TableError::Paid that does not exist; the contract said the tiering test was still to come).

Checked and held:

  • Nothing silent: each class of the M2 Mason's item 4 has its Malformed and a test (Target both ways, ThatPlayer, Paid, Grant, Copy, AddMana), plus the port's own (Countered, Delayed, Carried, TriggeredOn, Chosen, ZoneOf, Permitted, Cost, Fateseal); triggers, statics, replacements, rule changes, players in filters and costs are refused by the table.
  • Decisions did not change: the scenario half of every card file is byte-identical across each commit of 9.13, 9.15, 9.16, 9.17, 9.18, 9.19, 9.9, 9.12 (9.7 changed one comment; 9.8 touched only definitions). Corpus (5 passed) and rollouts_never_change pass on the tip. Three independent readers compared every ported card's old body with its data and the arms it reaches (9.15, 9.16, 9.17): no behavioural difference. Three places where the data is now closer to the card than the body was, none reachable in the pool: Beza compares life clamped at 0 (CR 107.1b); Elite Spellbinder grants no permission for a card a replacement kept out of exile; Aang's Iceberg does not scry if its sacrifice was replaced ("if you do").
  • Entries are rules: read all of Effect, Objects, Players, Amount, Condition and the terms. Each cites its rule, takes the vocabulary's expressions and reads as a second card could use it. None is a card's sentence renamed.
  • Bodies that stayed: none. All 47 cards are data; CustomBody is kept compiled by test bodies in beryl_rules/src/tests (cast.rs, events.rs).
  • Tests: the tiering test (tests/vocabulary.rs) and the generator's coverage test hold by coverage, no timing anywhere. Library scenarios are mostly the edge case (nothing to choose, empty library, declined choice) beside each card's own positive scenarios, which is what the oracles then check; left as they are. The Oculus dump failure noted above is gone (9.19's snapshot change): beryl_scenario dump records no failure in 424 scenarios.
  • Count series (rollouts corpus, bar 389,343,295, never bumped): 389,908,157 at the start (9.2 before) -> 389,507,068 (9.2) -> 389,530,096 (9.3) -> 388,755,869 (9.4) -> 388,633,629 (9.5) -> 388,132,971 (9.6) -> 388,280,382 (9.7) -> 386,956,937 (9.9) -> 386,018,406 (9.12 rebased) -> 388,617,465 (9.13) -> 387,518,179 (9.15) -> 388,988,143 (9.16 over 9.17) -> 388,980,405 (9.18) -> 389,333,349 (9.19) -> 389,325,611 at a65a9389, measured twice. Left alone, for the Mason gate (by-w8gv.10):

  • CardDef::tokens is derivable from the effect data (CardDef::creates now walks it). Deriving it would delete the list and TableError::Unlisted, but it fixes the order of game indices, which saves hash.
  • Choose (one pick), PutBack, Dig's Taken and Search's Found are four shapes of "a player picks N of a set and puts them somewhere"; one general pick would subsume them when a card needs a fifth.
  • Dig is also Forge's name for the effect. Its parameters follow the card text, and the word is common Magic usage, so not renamed; K16 may want another word.
  • search::instruction reads count once for all its players; right for every card today (Winds uses ForEachPlayer), wrong for a per-player count with several players.
  • The count has no slack left under the bar: 9.19's +0.09% came with no rules change beyond coverage::hit, which is empty without the feature, so it is layout drift worth a look before M6 adds work.
