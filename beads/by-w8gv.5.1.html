  • Queries replace raw reads: the card behind an object (none for a token), mana value, copiable values. Bug-log classes to make inexpressible are in docs/bugs.md and the plan's audit.
  • Bitboards outside the kernel are order-free; a sequence names a rules-visible order.
  • Newtypes for ability, grant, casting-option, target, target-spec and mode indices (today bare u8: FaceAbility, AbilityIx, PendingTrigger::ability, ctx.paid, ctx.target). Target stops storing a player in its incarnation field (state.rs:482 to 520).

  • No N-player logic. #[inline] on mutators; the count gate decides.
  • Do not write typed mutators for the fields milestone 4 removes (listed in by-w8gv.7.1: Player::sorceries_as_flash, CastPermission's extra, exile and flashback fields, State::entered_x, the seven ObjectFlags, Counters' long-tail kind).   • Label tier:fable the one or two beads that settle the design the rest build on (the kernel's public API: its mutators, queries and set types); everything else follows the run epic's Models policy.

Derek Thurn2026-11-11

From the M2 Mason audit (by-w8gv.4.1), for this decomposition: what M2 left in the code milestone 3 moves. None needs a bead before M3; each belongs in one of yours.

  1. Crate direction. The plan's Crates table is being corrected by by-w8gv.4.2: beryl_card stays the dependency-free bottom crate and beryl_kernel depends on it. Seat, Zone, TurnStep, CounterKind, the characteristic and mana types, FaceIx, AbilityIx, FaceAbility and Castings stay where M2 put them (beryl_card); do not move them into the kernel. The kernel may then read CardDef and Face for its queries.
  2. The Layout trait cannot move as it is. beryl_engine/src/layout.rs:158-162 gives it body(&Bodies) and condition(&Conditions), whose types are function pointers taking EffectCtx (rules). Move those two onto a rules-side trait implemented for Small and Large before layout.rs goes to the kernel. interpret/mod.rs (resolve) and interpret/scene.rs (Condition::Custom) are their only callers.
  3. Index newtypes: the vocabulary now holds bare u8 indices in two different spaces, and 3.2's handoff warns they are easy to confuse.
    • The target spec (which instance of the word "target"): Objects::Target(u8), Players::Target(u8), Effect::removes(u8), Ability::removes_target(u8), state's Target::spec.
    • The chosen target's place in the stack entry's list: resolve::legal_targets' u8 mask, Registers::legal, noted and known in interpret/scene.rs, EffectCtx::target(i). Also Modification::Grant(u8) (a grant index) and CastingOption::Overload { ability: u8 } (an ability index). The spec, grant and ability newtypes are named by definitions, so they are defined in beryl_card; the place index, and a set type over places to replace the u8 masks, are the kernel's.
  4. A player set already exists: interpret/scene.rs Who (insert, contains, in_turn_order). It is the order-free set with a named order that the plan's Kernel rules ask for; make it the kernel's type rather than adding a second. The interpreter's only two-player shortcuts are in it (EVERYONE = 0b11, in_turn_order through active.opponent()) and at scene.rs:231 (Players::EachOpponent).
  5. Queries the interpreter wrote for itself, which are the kernel queries of your scope: Scene::controller (a permanent's or spell's controller, else its owner, CR 108.4a; scans the stack), Scene::mana_value (a spell's with its X, CR 202.3e; scans the stack, else filter::mana_value), Scene::power and Scene::toughness (derived on the battlefield, printed elsewhere).
  6. One new raw write: interpret/run.rs:351, state.stack.retain in Run::unstack. "A spell leaves the stack without resolving, and is exiled instead if it was cast with flashback (CR 702.34a)" is now written four times: cast::leave_stack, EffectCtx::return_to_hand, EffectCtx::put_spell_into_library and Run::unstack. The stack is two structures (the zones.stack bitboard and the stack queue) that each caller keeps in step by hand. One kernel mutator that takes objects off the stack and returns their entries, with the flashback rule applied once by its one caller in rules, replaces all four.
  7. Modification is both what a card says and what the state stores. Modification::Control(Seat) (beryl_card/src/continuous.rs) names a seat, which no definition can (K7); it exists only for effect.rs:1266. M2 already split Duration this way (beryl_card::Duration against state::Duration, which carries the Seat; interpret/run.rs maps one to the other). The payload of milestone 4's Effects store should be the resolved form in the same way, so do not write typed mutators around Continuous::Layer(Modification) that M4 will redo.
