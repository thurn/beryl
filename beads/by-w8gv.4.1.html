M2 architecture audit: summary (staging 71126927; read through a detached worktree, no code changed).

AGAINST THE BEAD'S FIVE CHECKS

  1. Decisions as decided. K1 holds: Behavior::Data(&Effect) run by one interpreter (beryl_engine/src/interpret), Behavior::Custom the escape hatch, count gate 404,574,527 against a bar of 405,276,238 with no bump. K2's naming holds (static_ability). K7 holds in Players (You, EachOpponent, EachPlayer, Target, ControllerOf, OwnerOf, ThatPlayer); Whose and Modification::Control(Seat) do not yet, and M3's scope has Whose. Deviations, all recorded: Needs is still declared, not read from data (by-w8gv.3.2); Trigger, Whose, Cost, Affected, StaticCondition, Replacement, Rule and Modification were moved, not redesigned (by-w8gv.3.1, decision 6); the paper test's draw cannot be reproduced (script and Scryfall file not kept; by-w8gv.3.4).
  2. Conventions hold in new code. card-names: beryl_card is in scope and adds no entry. file-length: nothing added; card.rs left the list and five entries fell. No procedural macro; the two macro_rules (bodies!, conditions!) predate M2. beryl_card has no dependency; beryl_engine's only one is beryl_card. One name to change before cards use it: the builder when (see 7 below).
  3. K16: nothing shaped by Forge. No string-typed parameter and no named variable: references back are Objects::Those, Amount::ThatMany and Condition::Did, values of their own types; the only strings are card names and mana("{1}{U}"), which yields a typed ManaCost at compile time.
  4. Hot path: no general hook. Mana abilities take a direct path (interpret::mana_ability); interpret::data is out of line; an inline answer source is asked before Ability::asks walks an effect; target legality is found once (resolve::legal_targets).
  5. M3's plan section does not fit in one place: the Crates table's direction. Filed as by-w8gv.4.2.

FILED (children of the gate, both tier:sonnet, both small)

  • by-w8gv.4.2 Plan: the kernel depends on the vocabulary crate. The state holds 14 of beryl_card's types by value and M3's kernel queries read CardDef, so beryl_card must sit under the kernel, not over it. Docs and doc comments only. by-y8jt (human, non-blocking) tells the user the plan's table changed.
  • by-w8gv.4.3 Fast check runs the scale tests when card files change. The bug class behind M2's one slow-CI failure (by-1ebx): a Python test that reads Rust, selected only for changes under tools/. M3 to M5 rewrite every card file.

NOT FILED, PUT WHERE THEIR READER IS

  • Seven notes for M3's decomposition, on by-w8gv.5.1: the Layout trait names EffectCtx; two u8 target index spaces; Who is the kernel's player set; the interpreter's own controller, mana value and power queries; the fourth copy of "a spell leaves the stack" and its raw stack write; Modification as both vocabulary and stored payload.
  • Seven notes for M5's decomposition, on by-w8gv.9.1, ranked: (1) Trigger as event x subject x players, since 17 of 60 sampled cards needed a new entry of today's flat list; (2) Affected, StaticCondition, Cost and Whose; (3) Ability's 14 fields with a kind tag as an enum or private fields behind builders; (4) a const well-formedness check over a definition, since six kinds of ill-formed data do nothing silently or fail only when played, Effect::AddMana outside a mana ability among them; (5) Needs, may_pause and .removal(); (6) delete effect_data.rs with the last body; (7) rename when.
  • One note for the CI track, on by-w8gv.20.17: the retired long-think arena's tests are about 400 test-seconds of every rust lane run.

WHAT IS FINE AS IT IS

  • The Effect tree: every instruction cites its rule, asks() and removes() are exhaustive const matches, so a new entry cannot forget either.
  • Registers and Known (last known information kept for targets only, noted as a mask): the Warden's fix reads "moved" from the state instead of a second flag, which is the right shape.
  • Custom as &'static dyn Any: a run-time downcast, but the coverage requirement resolves every ability in tests, and the alternative is a type parameter through CardDef, Face and Ability.
  • The cost per data resolution (about 470 instructions) with 4.75M instructions of room under the gate's limit.

NOT DONE The fast and slow checks were not timed: the machine's load was 20 to 35 throughout, and the CI track's by-w8gv.20.17 measures them.
