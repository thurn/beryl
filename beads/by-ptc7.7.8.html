Description

What to do

Every agent must play every keystone of this family legally and never stall, and the session must show it with what the UI already has (decision P13 of the plan).

  • beryl_search: the rollout policy answers a cast offered inside a resolution, a search that offers a cast, a band declaration and a division by a player who is not the active player. The combat search (beryl_search/src/combat.rs, 783 lines) declares attackers one at a time; with banding it must not multiply its candidates when no bander is in play, and must stay bounded when one is. Card values need an estimate for cascade and banding.
  • beryl_session: a spell cast during a resolution goes on the stack with the existing cast verb while its cause is still resolving; the script invariants hold. A band is shown with marks that exist (the attackers of one band share a mark from the closed list, data/ui-conventions.json), or with none if nothing fits: list it under "Not seen in Arena" by editing the JSON, never the page. Do not add a numbered exception.
  • The prompts: a division by the defending player, a band choice, a cast-or-find choice in a search. Each uses one of the existing shapes (K10 of the architecture).
  • beryl_cli script-check passes for each keystone's spec moments from both seats; the session fuzz plays the pool; saves replay under each perturbation with each keystone, cut off and resumed in the middle of a cast inside a resolution and of a division.
  • The oracle exporters: band declarations and a cast inside a resolution are exported where the oracle can be told, or reported as unsupported with the reason.

Fix what you find; file what is large as a child of this milestone.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.

Acceptance criteria

Every agent plays 500 pool games containing each keystone of the family with no illegal choice and no stall other than a budget. script-check and the save perturbation tests pass for each keystone.
