Staging 5f9955cd73dd adds rule declarations, ownership checks, coverage, and the complete module map. The rollout count gate passed at 379,552,664 instructions.

Description

Why

About 30 engine files sit between 745 and 800 lines, cut at the limit instead of at a boundary (cast/ beside casting.rs, three files named elsewhere.rs, kernel files additions.rs and defined.rs). Nothing says which file owns which rule, and nothing lists the rules no code implements. Plan: Designs C, "Declaring ownership" and "The layout it leads to".

What to build

  • The declaration: one line in a module's //! header, //! Implements: CR 601, CR 602.2, or //! Implements: none with a sentence. A directory's mod.rs may declare for its files.
  • tools/src/beryl_tools/rule_ownership.py, a step rule-ownership registered in checks.steps() and added to names_lane() (lanes.py); models are discarded_push.py and two_player.py. It reuses citations.citations_in() and parse_rules(). It fails when a file under rust/crates/beryl_rules/src or beryl_kernel/src (tests excluded) cites a rule outside the ranges it or its parent declares, unless the citation follows the word see; when two modules declare one rule; and when a module declares a rule it never cites. Like citations, it is skipped where the rules text is not cached.
  • A shrinking allowlist data/rule-ownership-allowlist.json of files not yet moved, so the check lands now and the module passes empty it. Describe it in data/AGENTS.md.
  • just citations coverage: every rule of the pinned release that no module declares, by section, printed and written to $BERYL_CACHE/rule-coverage.json.
  • The module map: decide the final directory for every file of beryl_rules/src and beryl_kernel/src, starting from the table in the plan, and write it into the plan as the table the module passes follow, one row per pass with its file list. Where a pass's bead (children of the "M4: module passes" epic) names different files, edit that bead's description.
  • tools/tests/test_rule_ownership.py, and the check's description in docs/checks.md.
  • Root AGENTS.md, "Code structure": one line for the rule. Leave the 800-line rule.

Do not move any engine file in this bead.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.
