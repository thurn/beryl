Close reason

Landed macOS table menu switching, Quit confirmation, and tested web-view shortcut handling

Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Keyboard shortcuts' (the collision table), decision T17.

At a manual table Cmd+W, Cmd+M, Cmd+comma, Cmd+R, Cmd+P, Cmd+=, Cmd+− and Cmd+Q must reach the table instead of closing or minimising the window, opening settings, reloading, printing, zooming or quitting. Elsewhere in the app they keep their usual meaning.

  • Find how the app's menu is built: search rust/crates/beryl_app/src for Menu and accelerator, and rust/crates/beryl_app/tauri.conf.json. On macOS these keys are menu accelerators handled before the web view sees them.
  • Add a command table_keys { on: bool } (epic Rules, 6). With on, the app replaces its menu with one whose items for those keys have no accelerator (or removes them), so the key event reaches the web view; with off, it restores the normal menu. Cmd+Q with on emits an event table-quit-asked instead of quitting; the interface asks to leave the table and then calls the existing quit path.
  • In the web view, the reload, print and zoom defaults are stopped by preventDefault in the shortcut listener (a later bead attaches it); expose ui/src/table/keys.ts::claims(event): boolean listing exactly these keys, with a test.
  • Cmd+B is Beryl's bug report (ui/src/components/BugReport.tsx, about line 145). Give that listener a way to be told "a table is open": then it answers Cmd+Shift+B and leaves Cmd+B alone. In the lobby and everywhere else it stays Cmd+B.
  • On the phone apps table_keys does nothing.

Agents cannot open a window, so test what can be tested: a unit test for the menu-building function with on and off (make it a pure function returning a description of the menu that the Tauri calls are built from), claims, and the bug-report listener's two modes. Record on this bead that the native behavior itself was not exercised. Run just test-rust -p beryl_app, cd ui && npm run typecheck && npm test, just smoke.

Acceptance criteria

table_keys swaps the menu so the listed keys reach the web view and restores it; Cmd+Q asks first at a table; the bug report moves to Cmd+Shift+B only at a table; the pure menu function, claims() and the listener modes are tested; just smoke passes.
