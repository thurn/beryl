Description

Milestone 5 of Project 50k (plan K5 and K3; epic by-w8gv.9): the rules library and the card port. Line numbers and counts below were read at staging f5034c58; the code as it stands wins over this text, and a deviation is a comment on this bead.

rust/crates/beryl_rules/src/mana.rs (1,585 lines) and engine.rs (826 lines), moved from beryl_engine by this milestone's first bead, are on data/file-length-allowlist.json. Split both. Plan K17 and K5: mana.rs goes into pool, sources and solver.

Rules

  • Move code only. No logic change, no renamed item, no reworded comment. Keep every citation with its code.
  • mana/mod.rs (there is already a mana/units.rs) and engine.rs or engine/mod.rs re-export what the files exported under the same names, so no caller outside changes. An item used across the new files becomes pub(super).
  • A file is named for what it holds; none is named utils, helpers or misc. Each is under 800 lines and opens with a //! line saying what it holds.
  • Remove both files from the allowlist. One commit for each file.

mana.rs seams (functions by their line at staging f5034c58)

  • mana/sources.rs: Class, Sources, allowed, controlled, source, mana_contribution, read_source, impl Sources, available (lines 46 to 325): what can make mana (CR 605).
  • mana/pool.rs: Funds, payable (326 to 409), pay_unit, helps (1441 to 1456): what a pool and its sources can pay (CR 106).
  • mana/solver.rs: Plan, each_plan, walk, spent_by_class, complete, wasteful, floats_for_nothing, lowest_kind (410 to 642) and plans (1071): the payment plans offered.
  • mana/lookahead.rs: Later, later_costs, still_payable, Ahead, sorcery_window, instant_speed, enters_untapped, ahead, Outlook, Lookahead, symbols, outlook, looking_ahead (643 to 1220, less plans): what a plan leaves payable later.
  • mana/pay.rs: pay, by_card, human_taps, augment, assign, activate, manual_options, manual_pay, standalone_options, waterbend_mana_options, add_activations (1221 to the end, less pay_unit and helps): tapping and paying (CR 601.2g and 601.2h).

Where a helper is used on both sides of a seam, it goes with its first user.

engine.rs

It is 26 lines over. Outline it (grep -n '^pub fn\|^pub(crate) fn\|^fn' engine.rs) and move one cohesive group to its own file: the decision builders (decision, options, priority_decision, only_idle, land_face, lines 301 to 482) or the collapsing of interchangeable options (collapse, interchangeable, collapse_in_order, collapse_ordered, 766 to the end).

Checks

cargo test -p beryl_rules, cargo test -p beryl_cards, then the parity list below. The mana solver is the hottest code in a rollout. The benchmark profile is fat LTO with one codegen unit, so a move within a crate should not change the instruction count: run just bench-count before and after, and if it moves by more than 0.1%, find the function that stopped inlining and give it the #[inline] it needs rather than accept the change.

Need not read: anything outside the two files and their callers' use lines.

Parity and checks

Parity (plan K11) at the push: just check passes; the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds (cargo test -p beryl_bench rollouts_never_change); slow CI's counts lane (just count-gate, bar 389,343,295 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. Run just bench-count before and after and record both on the bead: the benchmark is the WU Control mirror, so what this milestone moves is on the counted path. No behavior changes: no rules fix, no new card, no new mechanic (K14). A rules bug you do find and fix gets a docs/bugs.md entry (AGENTS.md). A save or a rollout replays the decisions a game asked, in order: never change which questions a resolution asks, their order or their options.

Held by checks (AGENTS.md, Code structure): no card name in generic code; no source file over 800 lines (data/file-length-allowlist.json only shrinks, and a new file starts under the limit); rules code and card bodies ask the state for a player's opponents and never name the other of two; they change the state through a mutator, never the board door; a push whose bound is argued takes Queue::push_bounded and any other propagates Full; a count or position that grows with the layout is never narrowed with as. No procedural macro, and a macro_rules! only where a const fn cannot remove the repetition. beryl_card, beryl_kernel and beryl_rules take no runtime dependency. Rules code cites the Comprehensive Rules with a yawgatog link and a quotation; keep the citations of code you move, and check new ones against the pinned release with just citations. Forge is a test oracle only (K16): no entry, name or design comes from its scripts. beryl_search/src/expert and beryl_search/src/frozen are exempt from the project: edit them only where a call stops compiling, giving the answer the old read gave.
