Close reason

efficiency/ skeleton with store, beads ingest, sql/ingest/coverage and its own isolated check lane; pushed a47c9b10

Description

Create the standalone project that every other bead of this epic builds on, and prove that it is isolated from the rest of the repository's checks.

Design sections: "Design overview", "The store", "Isolation", "The command".

What to build

  • A new top-level directory efficiency/: pyproject.toml (its own uv project, no dependencies outside the standard library apart from the dev tools black, pyre and pytest that tools/pyproject.toml already pins), src/beryl_efficiency/, tests/, AGENTS.md and a one-line CLAUDE.md that imports it.
  • just efficiency *args in the justfile, running the project's command at background priority (see how the low variable and the cpu recipe are written, justfile lines 13 to 30 and 188).
  • The store: one SQLite file at <cache>/efficiency/store.sqlite, where <cache> is $BERYL_CACHE or the default that tools/src/beryl_tools/paths.py::cache_root uses (copy the rule; do not import the module). Create every table the design lists, the sources table of byte offsets and fingerprints, and the lock file that lets one ingest run at a time.
  • The ingest framework: a source is "these files, read from their recorded offsets, into these rows", idempotent, skipping and counting malformed lines. Implement one real source with it: beads, from bd list --all -n 0 --json (fields used later: id, parent, labels, status, created_at, started_at, closed_at, metadata.enact_*).
  • Queries sql '<read-only query>', ingest (with --rebuild) and a first coverage that reports rows per table, skipped lines per source and each ingest's own wall and CPU seconds.
  • Its own check lane, efficiency, in the fast check and in slow CI. Follow the Beryl 3D precedent exactly: tools/src/beryl_tools/beryl3d/paths.py (OWN, split) and how tools/src/beryl_tools/checks.py::fast_lanes uses it, then slow_ci.py::lane_reason and lanes_for. The lane's own paths are efficiency/ and data/efficiency-*.json. Its steps are black, pyre and pytest on efficiency/. It has no browser step.
  • One line for the lane in docs/checks.md, one line for efficiency/ under "Layout" in the root AGENTS.md, and the three data files' entries in data/AGENTS.md when later beads add them (add the heading now).

Need not read

The Rust workspace, ui/, and every check lane's internals other than python and beryl3d.

Shared context

  • The design is docs/efficiency-dashboard.md. Read the sections named above before anything else; the rest can wait. The decisions taken with the user are in the epic, bd show by-ig5e.
  • The dashboard's code is the separate Python project in efficiency/ (package beryl_efficiency, standard library only, pyre strict, black). It imports nothing from tools/ and nothing imports it. Read efficiency/AGENTS.md first once it exists.
  • Tests use small synthetic sources built in the test itself or kept under efficiency/tests/. The repository is public: never commit a real transcript, session record or command line from this machine.
  • Real data exists only on the main Mac (host jarvis). Where the acceptance criteria name a check against real data, run it there; if this session is on another machine, record that the check was not run in a comment on this bead and close on the tests.
  • Collection must stay free for agents: no hook, wrapper or prompt text may be added to any session, and ingest must never run inside another command.

Acceptance criteria

just efficiency ingest then just efficiency sql 'select count(*) from beads' prints the bead count on any machine; a second ingest reads zero new bytes; a change only under efficiency/ makes just check run the efficiency lane and repo, and no python, rust, ui or names lane; a change only under rust/ or tools/ does not run the efficiency lane (both shown by tests of fast_lanes beside the existing Beryl 3D ones in tools/tests/); slow CI lists the lane; just efficiency coverage prints the ingest's own cost.

Handoff: efficiency/ project (package beryl_efficiency). store.py: schema as MIGRATIONS; append a new entry to change it, never edit the first (the real store on jarvis has user_version 1). Columns of requests/tool_calls/windows/commits/checks/cpu/leases are a first draft; the beads that fill them may change them by a new migration. ingest.py: LineSource (files from offsets, fingerprint of first 256 bytes, partial last line left, malformed lines counted) and SnapshotSource (command output, digest-gated; owns tables it replaces whole). beads.py runs bd in the main checkout (git common dir). cli.py: ingest [--rebuild], sql, coverage; --json, --no-ingest; a query ingests first if the last ingest is >60 s old; QUERIES dict is where new queries go; render.Result carries data/lines/more. Lane: tools/src/beryl_tools/efficiency.py (OWN, split, lane) wired in checks.fast_lanes and slow_ci (LANES, lanes_for, PLACED, choose); dashboard paths are also left out of the fast check's citation check, since data/efficiency-*.json would otherwise select names. The lane runs black/pyre/pytest from the tools' interpreter (same pins), so no second venv per worktree; just efficiency uses uv run --no-dev --project efficiency. Tests: efficiency/tests (synthetic only), tools/tests/test_efficiency.py. Real data on jarvis: 1732 beads ingested, second ingest 0 bytes, ~0.7 s CPU per ingest (bd list dominates).
