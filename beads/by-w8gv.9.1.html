Derek Thurn2026-11-11

From the M2 Mason audit (by-w8gv.4.1), for this decomposition. M2 designed Effect, Objects, Players, Amount and Condition. It moved the rest of the vocabulary without redesigning it (by-w8gv.3.1, decision 6), and no later milestone's scope names that work. It belongs at the front of this milestone, before any card is ported, so each card file is written once.

  1. Trigger (beryl_card/src/trigger.rs) is a flat list with one entry for each pair of event and subject: YouCast, YouDraw, YouDiscard, YouAttack, YouCreateTokens(Types), Step(TurnStep, Whose). 17 of the paper test's 60 cards needed a new entry (by-w8gv.3, comment of 2026-11-11 04:46), nearly all an event that exists with another subject or player. As it stands the enum grows with the card pool. Make it event x subject Filter x Players. Matching is on the hot path: index by event kind behind a capability bit (docs/rules-coverage.md, Principles) and prove it on the count gate.
  2. Static abilities and costs, same record. Affected {Itself, Enchanted} cannot say a filtered set (6 cards). StaticCondition {Always, HasCounter, Impending} is a second, smaller Condition (4 cards); its Impending is the Condition::All(Paid, Compare) that Ability::impending_countdown already writes. Cost has one bool for each self-cost and no "sacrifice, exile or reveal a [filter]" (8 cards). Whose, in Filter and in Trigger::Step, is Players' job (3 cards); M3 touches Whose for K7.
  3. Ability (beryl_card/src/ability.rs) is one struct of 14 fields with a kind tag. trigger, condition, replacement, layer, rule, produces, only_if_you_control and needs each apply to one kind and hold a None variant for the others, so a Static ability with a trigger, or a Mana ability whose produces disagrees with its AddMana effect, is representable (M2's Warden noted the second). Card files write struct literals with ..Ability::NONE: 45 abilities with bodies and 20 as data today. Either make it an enum by kind, or make the fields private behind const builders that can only build valid combinations (the plan's "A card file" sketch is builders). Keep size_of a power of two: ability.rs records 0.11% on the gate.
  4. An ill-formed definition makes the interpreter do nothing, silently, or fail only when played:
    • Objects::Target(n) or Players::Target(n) with no spec n, or a spec of the other kind (an object where a player is meant);
    • Players::ThatPlayer outside ForEachPlayer (a debug assertion at run time, interpret/scene.rs);
    • Condition::Paid(kind) on a face with no such casting option; Modification::Grant(i) past Face::grants;
    • CopyException::PowerToughness other than 1/1 (a panic at run time, interpret/run.rs no_primitive);
    • Effect::AddMana outside a mana ability. The kind comes from EffectCtx::mana, which is Colorless unless a mana ability set it, so a spell's "Add {B}{B}{B}" trips a debug assertion and adds colorless mana in release; a set of several kinds would have to ask, and Effect::asks says AddMana never does. All of it is const data. One const fn check over a CardDef, asserted in a const _ beside each card (a compile error in the card's own file, which is what a cheap model writing cards needs and what M8's just card check wants) or, failing that, one test over CARDS, turns each of these into a build failure. Effect::asks and Effect::removes show the const walk works.
  5. Needs is still declared (the vocabulary has no reference to the cards exiled with the source), and may_pause and .removal() remain on the 45 bodies. Derive or delete each as the bodies go; the plan's "A card file" wants all three read from the data.
  6. beryl_cards/src/tests/effect_data.rs keeps five Rust bodies written against EffectCtx as its reference. It proved K1. When EffectCtx dissolves, delete it with the last body rather than port its bodies.
  7. when(condition, then) in beryl_card/src/effect/build.rs builds Effect::If. On a card "when" begins a triggered ability (CR 603.1), so the name will mislead whoever writes "When this enters". It has four uses, all in beryl_engine/src/tests/effects.rs: rename it (if_then, beside if_else) before cards use it.

From the M4 Mason audit (by-w8gv.8.1), for this decomposition. Read at staging 86ee9715. The plan's milestone 5 section still fits the code. This bead's scope text is stale in four places, and one design step belongs in M5's first bead.

  1. Stale in the scope above:
  2. The count gate's bar is 389,343,295 (rust/crates/beryl_bench/count-gate.toml), lowered twice in M4, not 405,276,238.
  3. "Five methods mutate without events (add_mana, allow_sorceries_as_flash, allow_cast, grant_flashback, add_effect)": allow_sorceries_as_flash is gone (Teferi's body calls add_effect with Affects::Player and Payload::Rule). add_effect, add_effect_on_set and gain_control are in beryl_engine/src/effect/continuous.rs, allow_cast and grant_flashback in effect/permit.rs, and all go through kernel mutators already (State::start_effect, start_effect_on_set). What is left for M5 is that they are EffectCtx methods. effect.rs is 1,115 lines with 63 pub fns.
  4. The one-card vocabulary to replace has one more entry: Rule::SorceriesAsFlash (data/card-names-allowlist.json, mechanics: nine entries). The kernel mirrors one of them: effects::LayerChange::PowerIsCreaturesYouControl (beryl_kernel/src/effects.rs), the resolved form of Modification's. When the vocabulary says it with an Amount, decide who evaluates it: the kernel stores payloads and cannot evaluate a vocabulary expression, the layers (rules code) can, so the payload would name the expression and not a number. A value locked in as the effect begins (CR 608.2h) is a number in the payload; one read as the layer applies (CR 613.4a, a characteristic-defining amount) is not.
  5. State a card creates is in four stores, not three: Effects, Memos, Trackers and the counters table (beryl_kernel/src/lib.rs "Stores"). Legacy and floating.rs are gone.
  6. Make the legal pairs of "what it affects" and "what it does" the only ones that can be written, in the bead that designs the library's continuous-effect functions. Today State::start_effect(source, Affects, Payload, Duration) takes any pair. The store's invariants say a player is affected by a rule change alone and a set by a layer change alone; the mutator holds the first with a debug assertion (in release the entry is stored and does nothing) and the second with unreachable!, a panic in release. Readers carry the dead arms: rule_applies and rule_change::maker (Affects::Set => false / None), layers::resolved_effects (Affects::Player => {}), cast_permissions (a filter_map over (payload, as_object)). A card body can write the wrong pair today (teferi_time_raveler.rs:82 writes the right one by hand). One type removes all of it:

pub enum Effect<L: Layout> { Layer(Permanents<L>, LayerChange), // Permanents: One(ObjectRef) | Set(LockedIn), the second made only by the store Move(ObjectRef<L>, MoveReplacement), Rule(Subject<L>, Rule), // Subject: Player(Seat) | Object(ObjectRef) Cast(ObjectRef<L>, Permission), Cost(ObjectRef<L>, CostChange), }

It deletes two invariants of effects/store.rs, the debug assertion and the unreachable! in start_effect, and the dead arms above; rule_applies takes a Subject. Constraints: an entry is 24 bytes in Small (the const assertion in effects.rs) and the count gate holds, so measure both; if the nested enum does not fit 24 bytes, keep Affects and Payload as stored and make the typed enum the mutator's and the readers' argument only. Not filed as its own bead: the callers (add_effect, permit, gain_control, Run::modify, permission::begin_on_spell) are exactly what M5 rewrites as library functions, so doing it there writes each once.

  1. Two gate beads land before M5 and change code it builds on: by-w8gv.8.2 (one kernel query for what names an object, replacing cast::referenced and combat::related) and by-w8gv.8.3 (the layers' apply list holds one entry for each effect; no discarded push or narrowing cast in rules code, held by a check in the names lane). Library code written in M5 follows both: a list whose bound is argued uses the asserting push, and a count or position that grows with the layout is never narrowed with as.
  2. Left as they are, for M5 to know:
  3. A checkpoint (beryl_session/src/checkpoint.rs) saves memos kind by kind (impending, exiled with, exiled until) and Memos::lingering is None. A memo kind that a later turn reads needs a save field of its own or a lingering answer. M5 adds no kind; whoever adds the first one after it does.
  4. Memo::X is "never 0" and Memo::Paid "never empty" by the store's invariant, not by type (NonZeroU8 would say the first). Small.
  5. The Trackers store implements Store with keys, expire and fits that answer nothing, since the turn resets it and it keys no slot. Fine while its kinds are per-permanent bits; a per-player or per-game count (storm, "this turn" counts) is the moment to revisit whether it is a Store at all.
