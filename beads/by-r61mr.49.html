Description

A label can be added and then removed in real Beads 1.3.4 without changing any field in bd export. Both commands add audit events. cli/src/migration/source.rs keys its audit history cache to the export row, so tk import and tk compare can agree while omitting the new events. The Warden proved this in a disposable Beads repository. For the Warden rehearsal, an independent read of the frozen Dolt events table matched all 2,859 audit events across 4,837 tickets. Make the cutover import and comparison obtain independent, current audit evidence on both projects even when cached export rows match. The legacy bd sql command does not run in embedded mode. Reading the events table through dolt sql on a frozen embedded copy is a locally tested bulk path. Keep live Beads authoritative and verify through isolated Beads stores and the local simulator.

Acceptance criteria

A real Beads test adds and removes a label after caching a rehearsal, verifies the export row stays identical, and proves the next import contains both audit events. A compare against the stale server must fail and a rerun against the repaired server must pass. The final cutover invokes this authoritative audit check without opening the live store for writes.
