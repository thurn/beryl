Close reason

View + UI for phasing, merged piles, copies, chosen values, controlled turns (8a1bf1ce); seven states pass spec shots desktop+phone; no engine change (count gate, State<Small> unchanged)

Description

Why

Decision R14: every keystone is playable in the app from both seats, with the prompt shapes and animation verbs that exist. Each card bead already holds its card to just specs. This bead makes the states no existing drawing covers visible, and nothing more.

What to build

Plan: Designs 8, "The view".

  1. PlayerView (beryl_session, generated into ui/src/generated/protocol.ts) says, and the script's verbs carry, for each of these:
    • who the viewer is acting for in a controlled turn (by-bajq.9.1);
    • which permanents are phased out (by-bajq.8.4): drawn in place, dimmed, not clickable;
    • the cards under a merged permanent (by-bajq.8.5): drawn as a pile under the top card, each readable on inspection;
    • the definition a copy shows (g5): the copied card's face, with a mark that it is a copy and of what the card really is on inspection;
    • changed text (by-bajq.5.3): the rendered rules text and type line with their words changed;
    • a chosen value on a permanent (by-bajq.3.3);
    • an ability on the stack that is a target (by-bajq.8.1).
  2. Each is built from components and verbs the stage already has (root AGENTS.md, "UI": anything the recordings don't show is built from what Beryl has, never a new look). Look each up with the arena-video skill first: Arena has mutate, phasing and copies, and if the recordings show one, follow it. Add the ones they do not show to data/ui-conventions.json under "Not seen in Arena" and run just conventions. Do not add a numbered exception: that needs the user's yes.
  3. A spec moment or fixture for each state, so the generic UI checks (overlap, off-screen, reachability, duplicate objects, page errors, motion) run over it from both seats and in both layouts.

Files

rust/crates/beryl_session/src/ (view, script builder), ui/src/ (the stage's object drawing, card inspection), data/ui-conventions.json, ui/AGENTS.md for the checks.

Bars (every bead of this epic)

  • The absent-cost gate holds with no bump (just count-gate; R2 in the plan). The count is exact, so report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust). A change to what the WU mirror's rollouts do is a bug in this epic.
  • Rules code cites the Comprehensive Rules with a quotation (root AGENTS.md); just citations.
  • A new card follows the card-writing skill: just card new, just card check <name> (Beryl, XMage and Forge), every instruction carried out by its own scenarios, and just specs <card> passing the generic UI checks from both seats. A disagreement with an oracle is settled by the rules and recorded in data/oracle-divergences.json.
  • Read the card's rulings before writing its scenarios (just card brief <name> prints Scryfall's). Each statement in a ruling that a scenario can show is a scenario of the card. Where one cannot be shown yet, the close reason names the ruling and why.
  • A rules bug found on the way gets its docs/bugs.md entry.
  • If the design in the plan is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.

Acceptance criteria

Each of the seven states has a spec moment or fixture that passes the generic UI checks from both seats in both layouts. cd ui && npm run typecheck and npm test pass.
