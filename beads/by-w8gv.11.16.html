Close reason

Session warns before a counter takes the viewer's own spell; engine fact Takes by data or declaration; old board's Oracle regex deleted; staging 26c33202

Description

The session's target prompt does not ask before the viewer aims a counterspell at their own spell (UI Conventions, exception 7). The old UI still does it itself, by a regular expression over Oracle text (ui/src/game/Board.tsx: counteringSpell, selfCounter), which is prompt logic in the UI (plan K26) and is deleted with the old board at the stage's cut-over (by-w8gv.21.32). Found by by-w8gv.11.8 and confirmed by the milestone's Warden (by-w8gv.11.12).

What to build

  • A fact the engine can answer for the target being announced: its effect counters the spell chosen. Today rust/crates/beryl_card/src/ability.rs Ability::removes_target says it for permanents only, from effect data (Effect::removes) or a card's declaration (TargetSpec::removal, rust/crates/beryl_card/src/target.rs, field removes_permanent). Widen that one fact to a target that is a spell (TargetKind::Spell, SpellOrPermanent): Counterspell's effect data says so (Effect::Counter); Mana Drain, Mana Tithe and No More Lies have Rust bodies and declare it on their spec, as six cards declare removal() today. Rename the field and beryl_engine's public query target_removes_permanent (rust/crates/beryl_engine/src/cast.rs, re-exported in lib.rs) to say what they now mean. cast.rs is at its file-length allowance: put no new function there.
  • rust/crates/beryl_session/src/prompt/pick.rs, Objects::targets: the warned list takes the viewer's own spells on the stack too (it filters to ZoneName::Battlefield today), worded by wording.rs OWN_TARGET (Arena's 'Do you want to target {name}?', Yes and No). Among two or more spells the pick already waits for its button (aimed, 'Target {name}'): there the title of the viewer's own spell picked is the warning's question, and Confirm answers.
  • Then delete counteringSpell and selfCounter from ui/src/game/Board.tsx and have the old board read the session's warned list (ShapeView::Pick.warned), as it does for permanents.

Tests

  • rust/crates/beryl_session/tests/clicks.rs: the scenario TITHED already reaches the viewer's own spell under an opponent's Mana Tithe (its own-spell pick is titled 'Target Mana Crypt' today). Hand-write the state after each click (plan K24): the pick asks, No takes it back, Yes answers, and the clicks end where picking the candidate ends. One more with two spells on the stack.
  • A test over every card: an ability whose effect data counters its target, or whose card declares it, says so, and no other does.

Rules

Parity (plan K11): just check; cargo test -p beryl_session --test corpus; cargo test -p beryl_bench rollouts_never_change; the count gate with no bump (the fact is read by the session only, never in a rollout). Engine code cites the Comprehensive Rules with a yawgatog.com link and a quotation (CR 701.6a, counter). just ui-test and just ui-shots pass (fixtures counterspell-targets, target-own).

Acceptance criteria

The session's target prompt lists the viewer's own spells a counter would take in warned and asks before answering with one, held by hand-written click tests for a lone own spell and for two spells on the stack; no regular expression over Oracle text decides a prompt in ui/src/game/Board.tsx; the engine's fact covers every counter in the pool by effect data or declaration, held by a test; the parity checks, just ui-test and just ui-shots pass.

(3) Counter only for spells, as exception 7 and the bead say: Reprieve (returns a spell to hand, effect data) does not warn, as in the old UI.
