Close reason

Typed CombatRole, private ObjectFlags with Flag, EventKind and Listens; pins hold, count gate +0.18% with no bump

Description

Current design

  • ObjectFlags(pub u32) (rust/crates/beryl_kernel/src/object.rs:19-60) is a public untyped integer; has(flag: u32) and set(flag: u32, ..) accept any number, and callers mask the field directly (zone.rs:78: o.flags.0 & (TOKEN|ONE_ONE)).
  • Combat is five of those bits, ATTACKING, BLOCKING, BLOCKED, ATTACKS_PLANESWALKER, STRUCK_FIRST, plus Object.combat: Option<Slot> (object.rs:~99), which means "the planeswalker it attacks" or "the attacker it blocks" depending on the bits. ATTACKING|BLOCKING together is representable; combat == None on an attacker means either "attacks a player" or "its planeswalker left". blockers_of (beryl_rules/src/combat.rs:57) scans the battlefield, and the clear-on-move resets (zone.rs:78, :101) exist to keep the bits consistent. A blocker can name only one attacker, but CR 509.1a lets an effect allow blocking several.
  • Event kinds are bare u16 constants (beryl_kernel/src/event.rs:285-305), two of which are explicitly "not an event kind" (RULE_CHANGE, DRAW_REPLACEMENT). struct Kinds(u16) (effects.rs:~340) wraps them but its methods take u16; listener.rs, beryl_rules/src/trigger.rs:64-72 and drawing.rs:34-35 pass raw masks; Event::kind() returns 0 for "no trigger".

Proposed design

Keep the per-object layout (flat Copy state, no heap, hashed for search), but type it:

pub enum CombatRole {               // replaces the five bits and `combat`
    None,
    Attacking { target: AttackTarget, blocked: bool, struck_first: bool },
    Blocking { attackers: SlotSet /* small fixed set */ },
}
pub enum AttackTarget { Player(Seat), Planeswalker(Slot), Removed }
struct ObjectFlags(u8);             // private: TAPPED, SUMMONING_SICK, TOKEN, ONE_ONE
pub enum Flag { Tapped, SummoningSick, Token, OneOne }  // has(Flag), set(Flag, bool)
pub enum EventKind { ... }  pub struct EventKinds(u16);  // contains(EventKind), |
                                    // RULE_CHANGE / DRAW_REPLACEMENT move to their own set type
fn kind(&self) -> Option<EventKind>

end_combat sets every role to None; a zone move resets it as part of the object's reset. Each CR 506-511 citation moves with the code it describes.

Eliminates: the contradictory bit combinations, the dual meaning of combat, raw-integer flag and kind arguments, and the "0 means none" convention.

Must not change

Game behavior: rollouts_never_change, frozen saves (beryl_session/tests/saves), every card's scenarios. The count gate (just count-gate) must hold with no bump; measure with just bench-count before and after. If SlotSet makes Object larger, size it to keep Object within its current size or record the measured cost on this bead.

Test

Compile-time: no pub access to ObjectFlags.0; no function in beryl_kernel or beryl_rules takes a flag or event kind as u16/u32. Runtime: existing combat tests in beryl_rules/src/tests/combat.rs pass; add one test where a planeswalker being attacked leaves the battlefield and the attacker reports AttackTarget::Removed and deals no damage.

Acceptance criteria

Combat is one CombatRole per object with no contradictory states; ObjectFlags and event kind masks are typed with private bits; all tests, frozen saves and rollouts_never_change pass; count gate holds with no bump.

Derek Thurn2026-11-13

Decisions and deviations: (1) Struck-first is on both Attacking and Blocking: a blocker with first strike also strikes first (CR 510.4), which the bead's sketch left out. (2) Event kinds are EventKind, and the per-card mask is one type, Listens(u16), with RULE_CHANGE and DRAW_REPLACEMENT as named constants rather than a second set type, so the table still reads each card's mask with one AND. (3) The private Kinds(u16) types in effects.rs and memos.rs are store-internal effect and memo kinds, not event kinds, and were left alone. (4) Object's Hash reproduces the old u32 bits and slot (CombatRole::legacy), so the rollouts_never_change and corpus_never_changes pins and state hashes are unchanged. (5) SlotSet holds 3 attackers. Object holds 22 bytes of data and is #[repr(align(4))] to stay 24 bytes, which measured 118K fewer instructions than 22. (6) A creature blocking several attackers assigns all its damage to the first; no card lets one block more than one yet. Count gate: 390,616,505 before, 391,331,327 after (+0.18%), within tolerance, no bump. Profiling against the base commit found most of the rise is code moving between files plus inlining drift.
