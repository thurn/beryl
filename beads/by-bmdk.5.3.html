Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'Connecting over the internet', 'Two apps on one machine'. Epic 'Contracts' (App commands), Rules, 6, and the decision that phones may join but not host.

Wire the sessions to the app.

  • table_host { link: "iroh" | "local", settings } -> { invite }: opens an IrohHost (identity file <profile data dir>/identity, relay from the setting below) or a TcpHost, starts TableSessions::host, and returns the invite code text.
  • table_join { invite, name }: parses the invite (beryl_link::invite), connects with IrohLink::connect or TcpLink::connect, starts TableSessions::join. A malformed or wrong invite is a clear error value and no table.
  • table_resume { id } and table_saved (list) for a host; table_leave sends leave.
  • The handshake's wire is beryl_session::wire_hash(..) including the table types.
  • Events: table-link with the LinkState; table-lobby (payload defined by the lobby bead; pass it through as JSON).
  • A setting for the relay address: default n0's public relay; a URL means a self-hosted relay. Store it in <profile data dir>/settings.json with a command pair table_settings_get / table_settings_set.
  • On iOS and Android (AppInfo.platform), table_host returns the error "Hosting is not available on this device." The phone apps can still join and play solo.
  • If the iroh crate is behind a cargo feature (bead "iroh link" decides), table_host and table_join with an iroh invite return "This build has no internet play." when it is off.
  • beryl_cli/src/serve.rs: routes for all of these with the local and in-process links only, and a way for one server process to hold a host and a guest table at once (two session keys, chosen by a query parameter the liveTransport passes), so a headless check can drive both seats in two pages.
  • ui/src/ipc.ts: tableHost, tableJoin, tableResume, tableSaved, onTableLink, onTableLobby, settings wrappers.

Tests: handlers as pure functions where possible; a beryl_cli test that hosts and joins through the server's two session keys over the local link and exchanges one action. Extend ui/scripts/table.mjs with pair() returning two pages, host and guest. Keep its offline art stub and paused-clock playback. Give each page its own session key on both the invoke URL and the event stream in liveTransport (ui/src/ipc.ts). Pass that key through the table driver's command and current-view helpers so an assertion can compare the two seats. clickTableResult currently matches the full URL ending in /invoke/table_act; match the URL pathname when requests carry query parameters. Keep the solo defaults for existing checks. Use the M2 projected guest check in ui/scripts/kept-table-drag.mjs as a reference for real two-seat assertions. Run just test-rust -p beryl_app -p beryl_cli, cd ui && npm run typecheck, just smoke.

Acceptance criteria

table_host, table_join, table_resume, table_saved, table_leave and the relay setting work through Tauri and the HTTP server; phones cannot host; table.mjs can open a host page and a guest page on one server; just smoke passes.
