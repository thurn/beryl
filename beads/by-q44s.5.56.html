Close reason

Key bindings with reset, full custom token form, Create another token, and undo blockers in the log for Beryl 3D's manual table; log folding already matched the web

Description

by-q44s.5.31 built the command list, ask prompt, token search, library order tray and log in rust/beryl3d/crates/beryl_scene/src/manual/{palette,ask,tokens,order,log}.rs, with the client side in src/client/manual_overlays.rs. Left out, each a smaller piece of the web's behaviour:

  1. Option+Return on a command list row binds a key to it (CommandList.tsx captureBinding, bindings.ts); bindings are stored with the settings. Also the 'Reset shortcuts' row.
  2. The custom token asks only for a name (ask.rs Ask::custom_token). The web's CustomToken (ui/src/table/TokenSearch.tsx) also takes a type line, colors, power/toughness and a note.
  3. 'Create another token' (token.repeat, condition last_token in commands.rs condition()) is never offered: the client does not remember the last token made (web: TableCommands #lastToken).
  4. When an undo is refused with blocked_by (Reply::TableAct Refused), the log should open with the blocking lines highlighted (tableLog.ts sendHistory, data-blocks-undo).
  5. The log is folded to a button until opened; the web unfolds it when no permanent reaches into its column (GameLog in ui/src/game/Narration.tsx, layout.ts). Tests go in beryl_scene/tests/all/manual.rs.

Acceptance criteria

Each of the five items works as the web's does, with a test in tests/all/manual.rs for each; just b3d test b3d:table and b3d:screen/table pass.
