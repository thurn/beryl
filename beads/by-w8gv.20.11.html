Close reason

fast check runs browser checks chosen by coverage, body, fixture, harness and record, time-boxed (2a938cb3)

Description

Run the browser checks a change affects in the fast check, time-boxed, worst failure record first (plan K19; docs/project-50k.md, Target architecture, Checks, "Selection"). Step two of the CI track (by-w8gv.20). Builds on the coverage bead's $BERYL_CACHE/ci/coverage/ files.

Measured (by-w8gv.20.5)

Fixed costs, warm: recording ui-test's 54 fixtures 2.4 s, Vite 0.5 s, interactions.mjs with one check about 2 s; just ui-shots <one> 4.7 s end to end. A Rust change makes record_fixtures build beryl_cli (48.7 s cold), beside the rust lane's own build. Whole lanes: ui-test 92-158 s, shots 59-115 s.

What

  • In checks.py fast(): when ui/, rust/ or the fixtures changed, add ui-test and shots lanes running only the chosen checks (ui_test takes title filters, ui_shots takes names; pass long lists through a file or stdin rather than argv if they grow).
  • Choose a check when:
    • coverage:<file>:<line> — a changed line in ui/src (from git diff -U0 against branch_base()) is in its recorded lines. A changed CSS rule works the same way.
    • body — its own body changed (the check's region in ui/scripts/interactions.mjs, the shot's entry in ui/shots.json). verdicts.py's per-lane path rules (CHECK_SIDE) already locate check regions.
    • fixture:<name> — for Rust or fixture changes, re-record the fixtures (record_fixtures into a scratch dir) and compare with the recording made at the coverage file's commit. The checks that load a fixture whose recording changed are chosen. A changed boards.rs board works the same way.
    • record — a changed line no check covers: new code, or a file absent from coverage. Fill the remaining time with the worst failure records.
    • harness — changes to the harness itself (capture.mjs, audit.mjs, a check() option default) choose all, time-boxed.
  • Order chosen checks by failure record (verdict counts from the ci-check beads and runs.jsonl via ci-report's Tally: catches first, then failures per run), cheapest first within a tie. Run what fits a time box measured to keep the fast check inside 60 s with the rust lane running beside it. Checks cut by the box are logged skip with chosen: cut; slow CI covers them.
  • No coverage file, or one over 3 days old: fall back to record ordering for ui/ changes and print one line saying so. The Windows host always falls back.
  • The run log's chosen field (runlog.Run.chosen, now per run) becomes per check and says why: coverage:ui/src/game/Board.tsx:1234, body, fixture:combat-declare, record, harness, cut. Slow CI keeps all.
  • Quarantined and pending checks (verdicts.excused) behave as in slow CI. If the prune bead's SLOW_ONLY table exists, skip its checks.

Files

tools/src/beryl_tools/checks.py (fast, ui_test_lane, shots_lane, Lane, run_lanes), a new tools/src/beryl_tools/selection.py (keep checks.py under 800 lines), runlog.py (chosen per record, Tally), verdicts.py (CHECK_SIDE regions, excused), shots.py (ui_test, ui_shots, record_fixtures, INTERACTION_FIXTURES).

Tests

pytest for each reason with synthetic coverage and diffs, the time box, the stale-coverage fallback and the ordering. By hand, in a worktree: change one line of ui/src/game/combat.ts and show the chosen checks and the fast check's seconds; do the same for a Rust session change.

Acceptance criteria

just check on a ui/src change runs only the browser checks whose coverage meets the diff (plus body, fixture and record reasons), worst record first, time-boxed within 60 s; runs.jsonl records chosen per check; stale coverage falls back; pytest covers each reason.

The push's own check (interactions.mjs changed outside any check, so harness): 57 run, 280 cut, 25.4 s. Deviations: (1) the bead history comes from a cache ($BERYL_CACHE/ci/history.json, written by by ci-report and a new nightly step, by ci-history), because one bd list of the ci-check beads took 25 s, too slow for the fast check. (2) The fixture comparison uses the fixtures the step records anyway, against hashes the coverage file now keeps (recordings); files from before this commit have none, so a Rust change chooses by record until the next nightly. (3) The always-on ability-log check in interactions.mjs is now gated by wanted(), so it runs only when chosen or filtered. SLOW_ONLY is honoured, though prune.SLOW_ONLY_LANES holds only rust for now.

Derek Thurn2026-11-11

Handoff: tools/src/beryl_tools/selection.py holds it all: hunks()/shift() (git diff -U0 parsing; a ui/src line is mapped from the branch base back to the coverage commit), Coverage.load/stale (3 days, missing commit, Windows), regions()/statements()/body_reasons() (check() calls in interactions.mjs located by prettier's indentation; a constant title is resolved from its last definition above the call; a line outside any check is harness unless its top-level block holds checks), choose() (harness, body, shots.json entries, fixture flag, coverage, record fill), fixture_reasons(), records()/order()/fit() (catches, then failure rate, then cheapest; the box is BOX=45 s from the step start, less STARTUP, over 4 workers), and Chooser (one per --select step: built before recording, run() after, label() rewrites the step's results with chosen per check and appends skip/cut). shots.py: ui_test/ui_shots take --select; interactions.mjs reads BERYL_CHECKS (exact titles; gates match a chosen title that contains them), so a rerun's filters narrow the chosen set. runlog: read_results keeps chosen, Run.records uses it, label(). coverage.py writes recordings. checks.fast adds both lanes for rust/ or ui/ changes when there is a base. For a reviewer: the box estimate uses mean seconds from runs.jsonl (slow CI under full parallel load), so it runs short of 45 s in practice; and checks whose titles come from a variable this parser cannot follow are matched by the patterns in body_reasons (a broad template such as '.+ (.+)' selects many checks).
