Close reason

Hosted tables serialize both seats, persist accepted actions, and resume the reserved guest on staging 6aca0c6a.

Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'Networking' (opening, 'Messages', 'Dropped connections and saving') and decisions T3, T20, T22.

In rust/crates/beryl_table_session, add src/host.rs: a hosted table for two seats.

  • TableSessions::host(link_source, settings, emit): seat 0 is the local player, seat 1 the guest. Implement beryl_link::host::Hosted for the table: act applies the action as that authenticated seat through the checked per-seat publication path from by-bmdk.4.3 (TableActionRefs and Log). update_for builds a whole view with a fresh reference mapping and a reset script; seat_for gives seat 1 to the first guest and the same seat back to a guest who rejoins.
  • One order. Every action, the local player's and the guest's, goes through one queue and is applied one at a time. After each, build each seat's view and script (view.rs, script/) and send them (emit locally for seat 0; Sender::update for seat
    1. before applying the next.
  • A refused action answers refused with permission, stale or invalid and sends no update. Preserve blocking entry numbers on invalid actions through the refusal payload from by-bmdk.4.4.
  • Saving. src/saves.rs: on every applied entry, append it with beryl_table::save::append to <data dir>/tables/<table id>.jsonl and flush. The header also stores the table secret, the seats' names and the settings. TableSessions::resume(table id, link_source, emit) reopens it with save::open. list_saved() for the start screen. A crash loses at most the action in progress.
  • When the link drops (Hosted::dropped), the table freezes: every action is refused until the guest is back, and seat 0's TableView says the other player is reconnecting (add link: LinkState to TableView: alone, connected { direct, round_trip_ms }, reconnecting, left). When the guest sends leave, say so and do not wait.
  • The data directory and the link are passed in; this crate does not know about Tauri or iroh.

Tests in tests/host.rs over beryl_link::memory::pair with a raw guest end: actions from both seats interleaved keep one order and each seat gets its own redacted update; a refused action; the file after N actions reopens to the same table; frozen while dropped. Run just test-rust -p beryl_table_session.

Acceptance criteria

A hosted table applies both seats' actions in one order, sends each seat its own view and script, appends every entry to a save file that reopens to the same table, and freezes while the guest is gone; tests cover each.
