Mason audit of milestone 3 (flat layer, prompts, screens, sound, bug reports, app). Answers to the bead's questions, then findings ranked.

Q1. Does a frame with no input rebuild or lay out anything? No. Layout and text shaping run in Client::handle (client/mod.rs handle -> show_screen, prepare_counts, NoticeFloats::prepare, Banner::prepare, piles/row_counts prepare). Client::frame only swaps prepared floats (Layer::show_prepared, set_float_look). beryl_inspect tests/all/recorded.rs asserts (layout_nodes, text_runs) == (0, 0) for the same view sent again and for a frame with no input, for every view of the recordings; flat_layer.rs, notices.rs and verbs_count.rs hold the same per moment. Two layouts happen inside frame by design, both driven by time or by the table rather than by a rebuild: Client::inspect (client/inspect.rs) lays out the inspector float when the card under a still pointer changes because a card moved under it, and manual's hold_table_menu opens a menu when a touch hold reaches its time. Both are counted by the gate's layout_nodes. Q2. Is every screen a function of its inputs with no hidden state? Yes. screens::screen, screens::sheet, prompts::screen and inspect::inspector take &ScreenIn and nothing else; there is no static, Cell or thread_local under screens, prompts, widgets, hud, inspect or manual. Retained state that is not an input (scroll offsets, focus, transitions) lives in Layer and is matched by name, as the doc says. ScreenIn was built twice with drifted copies and carried an unread hovered field: fixed (5062f758e, Client::screen_in). Q3. Are prompts drawn only from what the session says? Yes. Each shape reads PromptView (ShapeBody, buttons, Click values) plus the session's PlayerView, the window, faces and the order prompt's carried item (UI state). Divide's More/Less enablement is computed from the session's left and each Share's amount. No legality is computed client side. Q4. Can the phone layout reuse the widgets unchanged? Yes for widgets: nothing under src/widgets reads the window or the layout. Screens branch on Window::phone in four places (hud/steps.rs, inspect/inspector.rs, screens/table.rs twice, client/manual.rs). The risk is the screens' own number literals, filed as by-q44s.6.4. Q5. Can anything on the frame thread block? Not in release paths. Settings, the frame log, bug reports, export and audio all hand off to threads (beryl_3d settings.rs Saver, frame_log.rs writer thread, bugs.rs spawn, audio/mod.rs messages); the Warden by-q44s.5.43 already moved live png and music off it. Remaining, tools build only: AppFeed::replay -> Fixture::new reads a recording file on the frame thread when the testing screen replays one (beryl_3d fixture.rs). Lower-value, not filed.

Rules for every bead: rule 2 (scene-purity) and rule 3 (allocation gate) are enforced by checks; rule 11/12 hold (only beryl_render names wgpu). Rule 6 is broken in the flat layer: about 250 float literals across screens/start.rs (48), bug_report.rs (30), inspect/inspector.rs (26), lobby.rs (17) and others (by-q44s.6.4). Rule 7 is enforced by the named check.

Code map: corrected in the epic (beryl_3d src/audio is a folder; the tokens command is just design-tokens, tools/src/beryl_tools/design_tokens.py; screens/lobby.rs and widgets/check.rs were missing). docs/beryl-3d.md 'The flat layer', 'Floats', 'Sizes' and 'Text' match the code; nothing to correct.

Filed (children of the gate, which by-q44s.7.20, .7.21 and .7.22 already wait on):

  1. by-q44s.6.3 (opus): one Gesture enum for the primary pointer in place of Client's pressed, slider, scroll_drag, carried_item and viewing.down, reset in one place. The current fields are cleared by hand in six places, and by-q44s.7.22's taps, holds and drags would add more.
  2. by-q44s.6.4 (sonnet): move the flat layer's number literals to data/design-tokens.json and add a beryl3d lane check, before the phone screens copy them.

Lower-value, not filed:

  • Client is about 65 fields and client/mod.rs is at 799 of 800 lines; several other files sit near the limit (play/step.rs 787, driver/mod.rs 788). Splitting the screen state into its own struct is mostly moving code; the next edit will have to split mod.rs anyway.
  • beryl_assets tests/all/literal_glyphs.rs and glyph_coverage.rs landed 12 minutes apart and overlap (both check characters in scene source against the bundled fonts); one would do. Text the session sends at runtime (card names, typed bug text) is still not covered, by design ('A character no bundled font has').
  • live.rs Live::trees calls client.frame a second time each tick a tree is asked for (debug builds only), probably so that a tick the host skipped still answers; harmless as far as I could tell.
  • CI budget: no stored timing for the beryl3d lane was found in $BERYL_CACHE/ci, so the lane was not timed here; the Sage's process audit covers check time.
