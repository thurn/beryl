Close reason

b3d cargo-test never cuts a test that failed in the last 3 h on the branch or in the sweep (87bb0570d)

Description

Symptom: on 2026-11-16 Beryl 3D's lane on staging failed from 14:59Z to 16:11Z (about 72 min). Two milestone 3 beads (by-q44s.5.18, by-q44s.5.20) could not push and one was released, and by-q44s.59 was filed to repair staging. The failing tests were beryl_inspect prompts::a_payment_says_what_is_left_to_pay_unless_a_mana_payment_has_paid_nothing (a hard-coded element id that the settings gear in 2104192d7 shifted) and differential::the_check_times_find_every_planted_fault (exposed by b55feb411, a main-workspace engine fix that changes the recordings).

Why: 2104192d7's own fast check failed beryl3d-tests:cargo-test and beryl3d-interface:test ($BERYL_CACHE/ci/runs, commit 2104192d), yet it landed after a retry. When the fast check runs out of its 180 s budget, the Beryl 3D test step cuts tests and leaves them to the sweep ('cut' in the run log; the planted-fault test was cut 5 times and four others 4 times between 2026-11-15 21:00 and 2026-11-16 20:30). A test that failed on an earlier run of the same branch can therefore be cut on the retry, and the push lands. The second test is the C17 cost the epic accepted (a main-workspace change runs no Beryl 3D check), so only the sweep could catch it.

Proposed change: in the Beryl 3D test step's selection (tools/src/beryl_tools/beryl3d/lane.py and the cut logic it shares with checks.py), never cut a test that failed in any run of the same branch or of its base on staging within the last few hours (the run log has both); run those first. Also stop hard-coding element ids in beryl_inspect tests (locate by role and name).

Expected gain: no staging-red window from a test the branch itself already saw fail; saves the release, repair bead and rebases it caused (about 3 session-hours on 2026-11-16).

Acceptance criteria

A test in the run log that failed for a branch is run, not cut, in that branch's next fast check even when the budget is short (a tools test shows it). No beryl_inspect test asserts a numeric element id (grep '#655' finds none in rust/beryl3d/crates/beryl_inspect/tests).
