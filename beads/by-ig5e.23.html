Close reason

meta/close push in the background and syncs skip known pulls: meta lock hold 28 s -> 1.4 s median (enact 414a510, CI green)

Description

Simple Enact bookkeeping calls take tens of seconds. Over 7 days on jarvis: enact meta 795 calls averaging 48 s (639 agent minutes), bd comments 940 calls averaging 33 s (519 min), enact start 53 s, enact close 51 s, enact worktree 76 s. enact meta only records a metadata field. Two Enact commits already landed that should help, cafb1c0 perf: queue for the ownership lock, skip idle syncs and 440767f fix: skip a sync when this clone has the remote tip, so first measure what remains.

Where the time goes (start here)

  • cmd_meta in ~/enact/scripts/enact.py (around line 1068) runs sync(repo) before and after the write, each a Dolt pull and push to the remote (sync, sync_beads, ~line 793-925), all while holding the ownership lock, so every other session's Enact call queues behind it.
  • bd comments add is raw bd; Beryl's .beads/config.yaml sets sync.remote. Find out whether bd itself pushes or auto-commits on each write and how long that takes (time bd comments add ... against a throwaway bead, then delete the comment or bead).
  • Use the lock log from by-ig5e.21 (lock-waits.jsonl in the clone state directory, with waited_s, held_s, sync_s) to see which subcommands hold the lock longest.

Change

Cut the time each call spends in syncs and under the lock, without weakening Enact's guarantees (two viziers never claim the same bead; metadata written by one machine reaches the others). Options to evaluate, pick by measurement: skip the pre-write sync when the bead's owner is this actor and the clone pulled recently; push asynchronously or batch pushes (a short debounce) for metadata that no other machine needs to see immediately; do the network pull outside the lock and take the lock only for the local write plus a fast-forward check. Record the choice and its reason in ~/enact/docs/design.md.

If bd is the slow part, change how Enact and the role files call it (for example, comments through a helper that writes locally and lets the next sync push) rather than patching bd.

Work in the Enact repository following ~/enact/AGENTS.md (its own worktree, push and slow CI). Keep changes backward compatible: every machine and live session runs this code directly. The integration tests (tests.test_integration, real git, bd and Dolt in temp dirs) must still pass.

Acceptance is measured: report before and after medians for enact meta, enact start, enact close and bd comments add on jarvis, from the lock log or by timing 10 calls each.

Acceptance criteria

Median wall time of enact meta, enact start, enact close and bd comments add on jarvis drops substantially (before and after medians reported on the bead), time held under the ownership lock per call drops, the integration tests pass, the choice is recorded in ~/enact/docs/design.md, and it lands through Enact's own push with slow CI green.
