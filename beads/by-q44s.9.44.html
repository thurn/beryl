Description

Symptom: the desktop app drew text with letters missing ("You won the ip"), no inline mana symbols, no loyalty and no gear icon. Every interface test passed, because no check asks whether a text element's glyphs or an icon actually drew. A tree line with the right string only says that the text was laid out (by-q44s.9.39).

Change: add an interface check (beryl_scene/src/agent/checks.rs, a new Rule) that runs after the host has delivered glyphs and icons. It reports a fault for any laid-out line with a glyph that has no atlas cell at its own key (text::glyphs::Glyphs, missing() or a per-line lookup), and for any icon draw that has no cell (widgets::icons::Icons::get returning None). Also have the windowless and desktop app's frame log (beryl_3d/src/frame_log.rs, missing_glyphs) fail just b3d app --for and just smoke-style runs when glyphs are still missing at the end. The check must run at scale 2 as well, which needs the scale bead this one depends on.

Files: beryl_scene/src/agent/checks.rs, agent/fault.rs, text/glyphs.rs, widgets/icons.rs, client/screen.rs (missing_glyphs), beryl_3d/src/frame_log.rs, beryl_host/src/headless.rs.

Acceptance criteria

A new interface check faults when a laid-out line's glyph or an icon has no atlas cell after delivery; a test shows it fails on a frame with a missing glyph; it runs in just b3d test at scale 1 and 2.
