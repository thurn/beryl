Description

The Android WU Control mirror against Expert, seed 13111305, produced an ANR at 21:40:48 on 2026-11-13 around turn 13, before the later game-over ANR. The terminal result frame-loop fix in commit 7055bd242ca0846ff4a7c8bd7acccb399340ad7b stops drawing only after the result script settles, so it does not cover this earlier hang.

The original emulator trace is /data/anr/anr_2026-11-13-21-40-48-213. The app main thread was waiting in HardwareRenderer.syncAndDrawFrame, and RenderThread was in eglClientWaitSyncKHR through qemu_pipe_read. The game session and Expert AI ran on their own thread; journal timings did not show a 5-second game command. The later 21:48:23 trace had the same graphics wait. The full replay remains on the emulator as /data/user/0/ca.thurn.beryl/replays/1794633686.502856880-13111305.json if its AVD data is preserved. A shortened replay of the final decision did not reproduce an ANR.

Investigate the ongoing-game render work in ui/src/stage/stage.ts, overlay.ts, dom.ts and light.ts, especially the per-frame light painting during combat. Profile or replay the full turn sequence on the Android emulator, distinguish an app rendering issue from emulator GPU behavior, and make touch input responsive without losing required combat visuals. Inspect the existing stage tests in ui/scripts/stage*.test.mjs for the cheapest deterministic regression, then run npm test, npm run typecheck, the relevant UI browser check, and just android-smoke. Do not change emulator GPU mode as a speculative workaround: both auto and swiftshader showed slow frames, and host rendering was also slow.
