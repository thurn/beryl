Close reason

Go: engine and search generic over Layout (Small only); rollouts 429.0M -> 423.4M instructions, State size unchanged; Slot/Bitboard as layout types left to by-cbf.2

Description

First step of the epic, and its go/no-go gate: prove the layout-generic engine costs search nothing before building Large.

Make State and the engine (and beryl_search where it names engine types) generic over a Layout trait with only Small implemented. Small's types must not change at all: Fixed keeps its u8 length, Slot stays NonZeroU8, Bitboard stays [u64; 4], size_of::<State<Small>>() is unchanged. A type alias can keep most call sites readable.

The count gate (rust/crates/beryl_bench/count-gate.toml) allows 1.0% over its bar, about the size of the inlining drift a refactor like this can cause, and a refactor is not one of its reasons to raise the bar. If counts rise, fix inlining (#[inline] / #[inline(always)] on the trait shims, Callgrind to find which did not inline); never raise the bar or the tolerance.

Report in the bead before closing: just count-gate and just bench-count before and after, and just check wall time on a Rust-only change before and after.

Acceptance criteria

  • Engine and search generic over Layout, Small only; all tests pass.
  • just count-gate passes with the bar unchanged.
  • size_of::<State<Small>>() unchanged.
  • Before/after counts and just check times recorded in the bead.

Spike results (commit ee055d7). Go: the generic engine costs search nothing measurable.

Design: State<L: Layout = Small> (also Zones, Scratch, Observation, EffectCtx, Answers<L>, search's Agent<L>, Mcts<L>, LongSearch<L>, ExpertAgent<L>, rollout policy views). Layout has GATs Queue<T, N> (Small: Fixed<T, N>) and Table<T, N> (Small: [T; N]), plus hooks clone_state, body and condition. Defaults to Small keep session/cli/app/cards/bench unchanged. Construction (State::new, setup) stays on State<Small>: by-cbf.2 widens a Small state rather than building Large. Frozen agents (beryl_search::frozen) left concrete on Small.

Deviation: Slot and Bitboard are NOT associated types yet; they stay the concrete u8/[u64;4] types, as do nested Fixed fields inside non-State types (StackEntry.targets, Player.emblems, Resolving.record). For Small this is the same code either way, so it doesn't change the cost answer; by-cbf.2 must make them layout types (Object, ObjectRef, Target, Pending, Decision, Opt, events all carry Slot). Card bodies/conditions are static fn pointers typed for Small; Layout::body/condition is the dispatch point, so Large needs a second instance per card (e.g. a macro instantiating each body for both layouts); effect.rs's library bodies are already generic.

size_of::<State<Small>>() = 20,440, align 8, before and after (checked with a const assert).

Instruction counts (just bench-count, Callgrind Ir), before -> after:

  • copy 261,918 -> 261,565 (-0.13%)
  • next_apply 401,626,305 -> 395,786,229 (-1.45%)
  • policy 1,544,768 -> 1,601,372 (+3.66%, +57k absolute)
  • rollouts 429,022,809 -> 423,395,715 (-1.31%) just count-gate: before 429,022,809 (-1.77% vs bar 436,754,038), after 423,395,715 (-3.06%), exit 0, bar unchanged. rollouts_never_change passes, so the rollouts do the same work. The drop is likely codegen placement: generic engine code is now instantiated in the calling crate, where LLVM can inline it.

Benchmark change: rollout_counts toggled Callgrind on beryl_search::rollout::rollout by name. Generic rollout::<Small> is now compiled into both beryl_search (the corpus's games) and beryl_bench, and the counts went bogus (0, 230M, 194M). Entry is now beryl_bench::rollout::counted_rollout (#[inline(never)] wrapper), with rollout itself #[inline(never)] (without it, 194M again: Callgrind loses the frame).

just check on a Rust-only change (one comment in beryl_engine/src/rng.rs), machine load ~50: before 82 s cold / 60 s warm wall (148 s / 87 s user); after 53 s / 59 s wall (101 s / 102 s user). Wall time within the 60 s budget and noise; warm user CPU +17%, plausibly each test binary now compiling its own engine instance.

Measurement hazard found and filed as by-cbf.4: the VM's shared CARGO_TARGET_DIR let another worktree's beryl_engine rlib stand in for this one's (cargo said Fresh; compile failed with no Layout). All counts above are from runs after touching every source file.
