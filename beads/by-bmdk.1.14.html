Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'Library flows' and 'Ability menus' under 'Assists'.

Create rust/crates/beryl_table/src/assist/text.rs. These read the fixed forms of rules text and never what it means.

  • pub enum AbilityRow { Loyalty { cost: LoyaltyCost, text: String }, Activated { cost: String, text: String } } with LoyaltyCost::{Plus(u16), Minus(u16), MinusX, Zero}.
  • pub fn abilities(face: &Face) -> Vec<AbilityRow>: a paragraph that begins with a loyalty cost and a colon is a loyalty ability (accept both − U+2212 and -). A paragraph with a cost before a colon, where the colon is outside quotation marks and outside reminder text in parentheses, is an activated ability. The doc's five example lines are the specification: make each a test with the doc's expected reading.
  • pub fn ability_action(source: ObjectId, row: &AbilityRow, x: Option<u16>) -> Action: for a loyalty ability, a batch of counter (loyalty, by the cost) and marker; for an activated ability, a marker alone. The table never pays a cost.
  • pub enum Flow { Scry(u16), Surveil(u16), LookTop(u16) } and pub fn flows(face: &Face) -> Vec<Flow>: matches only the wordings "scry N", "surveil N" and "look at the top N cards of your library", N a digit or a number word one to ten.
  • pub fn flow_result(flow, top: &[ObjectId], choice: &FlowChoice) -> Action: the batch that puts the looked-at cards where the player sorted them (top in the given order, bottom, or graveyard), and pub fn flow_line(..) -> String giving the log wording ("Scried 2: 1 on top, 1 on the bottom").

Tests in tests/assist_text.rs use real store records for a planeswalker with a −X ability, a mana creature, an artifact with a sacrifice cost, a card with a quoted ability granted to a token (must not be read as the card's own), and cards with scry and surveil. Run just test-rust -p beryl_table.

Acceptance criteria

The doc's five example lines are tests with the readings the doc gives; quoted and parenthesised colons are not read as abilities; flows match only the three fixed wordings; ability and flow results are ordinary actions.

Derek Thurn2026-11-14

The adapter should prompt for X before building a MinusX action. The action helper treats absent X as zero, following its infallible signature. FlowChoice carries the library seat because object IDs do not identify their zone, and flow_result returns Refusal::INVALID if the choice does not partition the host’s looked-at cards. The host should pass the current top snapshot and use flow_line for the public summary. The count in the summary is the number of cards the player actually saw.

D
Derek Thurn2026-11-14

Handoff: assist::text::abilities and flows read the visible Oracle text of a store Face. ability_action builds a battlefield marker and includes the loyalty adjustment for loyalty rows. flow_result validates a FlowChoice against the host’s top slice and returns ordinary moves in one batch. Use flow_line for the public summary. The seven assist_text tests apply the results, including all three library flows and private card identities. Fast checks passed on staging in de09bf53.
