Close reason

Published card command facts on staging at 9bb50d20. Both-seat projection and capped editor, counter slot, and drag attachment checks passed.

Description

The table UI recomputes facts the host should supply. ui/src/table/dropActions.ts parses cardRecords type lines to decide auto-attach. ui/src/table/cardState.ts and menuRows.ts parse Oracle text for quick counter names. cardState.ts also derives editable base P/T by subtracting counters from displayed P/T, but rust/crates/beryl_card_store/src/facts.rs clamps the displayed result. A permanent with base power i32::MAX and a +1/+1 counter opens the editor at i32::MAX-1 and a decrement writes i32::MAX-2. Card facts must come from the same face and card identity as the projection, including custom tokens and hidden faces.

Compute manual-only editing facts in rust/crates/beryl_table_session/src/view/cards.rs using the already selected redacted face and shared beryl_card_store facts, and expose them from the manual portion of the protocol by stage slot. Include exact base stats, quick counter names and the auto-attach flag; use the same server-side face selection for each. Remove equivalent TS card-text parsing and P/T inversion. Port the current quick counter selection order and attachment behavior for known cards, preserve manual escape hatches, and expose no hidden printed facts.

Acceptance criteria

A projection test for both seats covers a known attachment, a facedown counterpart, and exact editable base stats when displayed stats saturate. A headless table fixture starts a stats editor on a capped permanent and decrements its base by exactly one. Existing counter slot and drag attach checks pass.
