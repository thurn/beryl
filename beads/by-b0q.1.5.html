Scenario runner, RandomAgent, determinization, invariants, fuzz and perf counts in b8fddaf

Description

Part of Milestone 1 (epic by-b0q): a rules-exact engine, game UI and AI opponents for a mirror match of the 40-card WU Control main deck in docs/sample-decks/2026-10-17-PrinceJools-wu-control.txt (29 distinct cards). Read the epic's description (plan, card table) and design field (decisions) first; docs/engine-architecture.md is the design. Rules code cites the Comprehensive Rules with yawgatog links and quotations (AGENTS.md).

Architecture sections 13, 17.1 and 17.4: the harnesses every card and agent bead tests through.

  • beryl_scenario: the typed builder (setup, steps, assertions), serde serialization, and the strict runner through the public decision API only: an unscripted decision fails. A dump command writes every scenario as JSON for the oracle exporters.
  • beryl_cards: each card file's SCENARIOS, a registry, and one test that runs them all; scenarios for Plains, Island and Tundra.
  • beryl_search: the Agent trait (section 19.1) and a seeded RandomAgent.
  • Determinization (section 13): deal the unknown remainder of each decklist into the viewer's unknown slots, keeping everything the viewer knows.
  • The fuzz harness: random-versus-random games over the cards implemented so far (a helper builds a legal deck from them), in debug with the invariants of 17.4 after every decision. A small count runs in just ci; a larger one on demand.
  • Determinism (same seed and choices give the same hash at every decision), information independence (an Observation-reading test agent decides the same on the full state and on a re-determinized one), and a counting allocator asserting zero heap allocations across a random game.
  • A scaffold for perf counters with tolerance bands (17.4).

Acceptance criteria

  • A test shows the strict runner failing on an unscripted decision.
  • beryl_scenario dump writes valid JSON for every scenario.
  • The fuzz, determinism, information-independence and zero-allocation tests pass and run inside just ci's budget.

Derek Thurn2026-11-05

Delivered in b8fddaf. Notes for later beads:

  • Scenario actions today: PlayLand, Answer (Pick::Pass or Pick::Card), AdvanceTo{turn, step}, Assert. Assertions: Life, Count, Tapped, Decision, Outcome. Casting/activation/combat beads add their Action variants (and runner arms in beryl_scenario/src/run.rs); layers/stack/planeswalker beads add P/T, stack, counters and controller assertions plus setup fields (counters, attachments). Engine enums serialize by variant name, so new DecisionKind/Zone variants need no serde mirror.
  • Position semantics: assertions read the state at a decision point (after next). AdvanceTo installs a Profile::breakpoint so the game stops at the target's first active-player priority even when it would pass silently; the runner clears it once reached. Setups start at turn 1 precombat main, P0 active, both at 20, exactly the cards listed (an empty library loses on the next draw).
  • beryl_scenario dump is a bin in beryl_cards (cargo run -p beryl_cards --bin beryl_scenario -- dump [PATH]): the cards depend on beryl_scenario, so the scenario crate can't hold it. JSON: an array of {card, name, setup, actions}.
  • Determinization is Observation::determinize in the engine (it rewrites crate-private state); docs/engine-architecture.md section 16 updated. It reseeds both RNG streams.
  • State::check_invariants: zone bitboards/lists vs object zones, stack spell refs current, knowledge of public zones and own hand, no permanent status off the battlefield (stack exempt), no lost player at an open priority. 'derived is clean when read' waits for the layers bead.
  • Perf counts: Scratch.counts (decisions, silent, state_based_checks), pinned in beryl_search/tests/games.rs perf_counts_stay_in_their_bands (5% bands, smart-stop three-land mirror). Bump the pins on purpose when an engine change moves them.
  • Fuzz: 40 games in just ci (plus 10 for information independence); just fuzz N runs N in an optimized build with debug assertions and overflow checks (2000 games in ~11 s). The allocation test is a harness=false binary with a counting global allocator (a local allow(unsafe_code)).
  • Verified: leaking Observation::object, a Box in next, and allowing land plays in the opponent's turn each fail the relevant test.
