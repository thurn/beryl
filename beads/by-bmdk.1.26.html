Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'The context menu' and decision T10. Reference images: docs/ui_mockups/manual_card_menu.png and manual_library_menu.png (intent only, never sizes or positions).

Create ui/src/table/Menu.tsx and menu.css. This bead is the component only; which rows appear for what is a later bead.

  • Input: { header: { title, whose }, groups: Group[] } where a group has an optional heading ("Move to", "Assists") and rows { id, label, key?, checked?, click?: boolean, submenu?: Row[] }, plus at: Point and onChoose(id), onClose().
  • Every row is a plain label with its key hint at the right edge. No row holds a button, a stepper, an icon or any control. A row with click: true shows "click" where the key would be. A row with checked: true shows a check mark. A label ending in "…" is shown as given.
  • A row with submenu opens one more level beside it. A submenu row never has a submenu: enforce it in the type.
  • Arrow keys move, Return chooses, Escape closes, a click outside closes. The menu stays fully on screen at any at (flip or shift it), at the desktop sizes the stage supports.
  • Styling uses the design tokens in ui/src/design/; read ui/AGENTS.md first.
  • A presentation: "menu" | "sheet" prop is declared now; "sheet" may render the same as "menu" until the touch bead builds it.
  • Add three gallery states (ui/src/screens/Gallery.tsx): a permanent's menu, a library's menu with a checked row and an "Assists" group, and a menu opened at the bottom right corner.
  • Add the entry to data/ui-conventions.json under kind no-equivalent, name "Context menu", rule from decision T10; run just conventions.

Tests: npm test for keyboard movement and the no-nested-submenu type; the gallery states under the generic audits. Run cd ui && npm run typecheck && npm test.

Acceptance criteria

Menu renders headers, groups, key hints, check marks and one submenu level; it holds no controls; it stays on screen in a corner; keyboard works; gallery states and the UI conventions entry exist.
