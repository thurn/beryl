Description

Read first: docs/beryl-3d.md 'The parity list', 'Timeline parity' and 'The agent interface' (the tool's rules); rust/beryl3d/AGENTS.md (data files); data/beryl3d/screens.json and rust/beryl3d/crates/beryl_inspect/tests/all/screens.rs (how a built screen is tested); tools/src/beryl_tools/beryl3d/timeline.py (load_allowlist, key_of) and sweep.py (OWN, read_log, last_passed).

The parity list is the report that says what of the web interface Beryl 3D still lacks. This bead builds the command, its data and the check that keeps it current. It fixes nothing the list finds: the beads after it do.

Data, decided here (the doc is corrected to match by the planning bead's own change):

  • Screens stay in data/beryl3d/screens.json, which beryl_inspect's screens test already reads. Do not move them.
  • New data/beryl3d/parity.json:
    • tools: one entry per job, {"job", "web", "skills": [...], "b3d": "<command or skill section that does it>" | null}. The jobs: specs (a card's moments as text, film and checks; skill specs), ui-review (playing as a player; skill ui-review), motion-film (just motion --film), motion-review (skill motion-review), arena-pixel-match (skill arena-pixel-match), bugfix (skill bugfix), ui-perf (just ui-perf). All start with "b3d": null; the tool beads fill them in.
    • skills: every directory of .claude/skills mapped to a job name above, or to "none: <why it does not look at a client>" (card-writing, cifix, efficiency, status-dashboard; b3d maps to "none: Beryl 3D's own"; arena-video maps to arena-pixel-match).
    • web_screens: every file of ui/src/screens/.tsx and every component file of ui/src/table/.tsx whose name ends in View.tsx, Opening.tsx or is ui/src/table/lobby/*.tsx, mapped to the name of a screens.json entry, or to "missing" when Beryl 3D has no such screen. Open each file to decide: a file that is part of another screen (ui/src/screens/Board.tsx is the game's board) maps to that screen. ui/src/screens/Scry.tsx says it is a static mock-up; map it to "none: static mock-up".
    • verbs, effects, marks: each name of data/ui-conventions.json's verbs, effects and marks lists mapped to one recording of just b3d list that plays it (read just b3d timeline <recording> for verbs and effects, just b3d info for marks), as screens.json's prompt_shapes maps each prompt shape.
  • New directory data/beryl3d/conventions/, one file per section kind of data/ui-conventions.json (exception.json, settled.json, no-equivalent.json, not-seen.json), each {"entries": {}}. An entry, added by the UI Conventions beads, is keyed by the convention's name and is {"recording", "at", "shows"} with the same meaning as a screens.json entry, or {"open": "<why Beryl 3D cannot follow it without a numbered exception>"}. Never write to data/ui-conventions.json (rule 17).

Rust, in rust/beryl3d/crates/beryl_inspect/tests/all: conventions.rs, beside screens.rs and in the same style: every key of each conventions file is the name of an entry of that section in data/ui-conventions.json; every {"recording","at","shows"} entry's recording shows the shows line at at (reuse the helper screens.rs uses); and one more test in screens.rs's style: every recording parity.json's verbs, effects and marks name is a recording of the pack.

Python, new module tools/src/beryl_tools/beryl3d/parity.py, registered through MODULES in cli.py with its own COMMANDS (see the bead it depends on):

  • just b3d parity prints the doc's format, one line per kind: fixtures, card specs, timelines, verbs, effects, marks, prompt shapes, screens, conventions, tools, launch tests. Each line is <kind> <done> / <total> and, when not complete, missing: with at most five names and (+N more, --full). --full prints every missing name, --json the whole report.
  • A fixture (a definition of ui/fixtures.json) or a card spec moment is done when every interface test of its recording passes, from both seats and every window, desktop and phone, and no <recording>/<seat> key of data/beryl3d/timeline-parity.json names it. Get the tests' results by running b3d test --json and b3d test --phone-only --json (the run_b3d helper in cli.py), or read them from --results <dir> holding those two outputs as desktop.json and phone.json, so the sweep step can reuse them.
  • timelines: recordings of the pack minus the keys of timeline-parity.json, counted per <recording>/<seat>.
  • A verb, effect or mark is done when the recording parity.json names for it is done. A prompt shape likewise, through screens.json's prompt_shapes.
  • A screen is done when its screens.json entry is built; web_screens entries mapped to missing count as screens not done.
  • A convention is done when its conventions file has a recording entry for it; an open entry is printed under missing with its reason.
  • A tool is done when its parity.json b3d is not null.
  • launch tests: macOS with the last result of the sweep's smoke step and the commit it ran at (sweep.py read_log), else not run. iOS, Android and Windows are not required in this epic and are printed as not required.
  • The output's first line is the command that reproduces it, and the command writes no file (rule 19).

Sweep: a step parity-list in sweep.py OWN, running just b3d parity --check, which fails (exit 1) when a skill directory or a web screen file is missing from parity.json's skills or web_screens, or a key names something that no longer exists, printing which. It does not fail on an incomplete list.

Docs: the command's line in rust/beryl3d/AGENTS.md's command list and in the b3d skill (.claude/skills/b3d/SKILL.md), and parity.json's format in rust/beryl3d/AGENTS.md's data list.

Tests in tools/tests/test_beryl3d_parity.py, on small values built by hand: a recording with one failing test is not done; a recording listed in timeline-parity.json is not done; a verb whose recording is done is done; --check fails for a skill directory missing from parity.json and for a web screen file missing from web_screens; the printed lines follow the doc's format. Run: just test-py tests/test_beryl3d_parity.py and just b3d cargo-test -p beryl_inspect.

Do not build any tool or fix anything the list shows missing.

Before enact push: run just b3d cargo-test and just b3d test yourself, because the fast check can cut them at its time limit. Tests in beryl_inspect locate elements by role and name, never by numeric id. Do not re-pin limits in data/beryl3d/gates.json by hand.
