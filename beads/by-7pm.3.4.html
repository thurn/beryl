Close reason

Phone boards fit 375-430 widths and crowded layouts, with all phone shots and fast checks passing

Description

Hold the phone's game screen to its audits at every size it must run at. Today the phone's shots on the stage (phone-stage-* in ui/shots.json before the cut-over) exist only at 393×759. Nothing checks 375×647 (iPhone SE, the smallest supported) or 430×850 (the largest), nothing handles a viewport narrower than 375 or wider than 430, and the crowded boards have no phone shot.

Where the code is

  • ui/shots.json: every shot. A shot whose route has phone is a phone shot (ui/scripts/shots.mjs then runs phoneFaults). The verb and shape suites (ui/scripts/verbs.mjs, shapes.mjs) run the phone layout at each phone size the shots list has.
  • ui/src/mobile/layout.ts: phoneLayout(view, viewport), its bands and its row fitting (fitAcross, the creature rows near line 241, the lands and others rows).
  • ui/src/mobile/chrome.tsx: useViewport() measures .phone-board.
  • ui/src/mobile/phone.css: .phone-board is position: fixed from the top safe area to the bottom, full width.
  • ui/src/stage/phone.ts: the stage's poses from those bands.
  • Boards: rust/crates/beryl_cli/src/boards/table.rs (Scenario::new("crowded") near line 199: nine and ten nonland permanents a side), boards/combat.rs. Fixtures: ui/fixtures.json (crowded, piles-crowded, combat-blockers, stack-overload); read its $comment.

What to do, in this order

  1. Every phone shot at the small size. For each shot in ui/shots.json whose route has phone and whose size is 393×759, and that has no twin at 375×647, add the twin with the suffix -se (same route, same click, hover and waitFor). Do it with a short script, not by hand, and do not add a twin that exists. Then run just ui-shots on the new names and fix every fault in the layout, not in the audit: text under 12px, a control under 40×40, a control crowding another, clipped text, a card off the screen.
  2. Three shots at the large size, 430×850, suffix -max: the main board (fixture phone-main), the attack (phone-attack) and the stack (phone-respond).
  3. Crowded boards, at 393×759 and 375×647: phone-crowded (/?phone&fixture=combat-blockers&at=1#/game), phone-crowded-stack (/?phone&fixture=crowded&at=2#/game), phone-piles-crowded (/?phone&fixture=piles-crowded#/game), phone-stack-overload (/?phone&fixture=stack-overload#/game). Fix what the audits report. Then open each PNG and check by eye what no audit measures: every card on the table shows at least its name bar, and every stack item shows.
  4. A board past what the cube made. Add a scripted board crowded-max beside crowded in rust/crates/beryl_cli/src/boards/table.rs: fourteen creatures and twelve other nonland permanents a side, some tapped, built the way crowded is built (same helpers, cards from decks::WU_CONTROL's pool; no new card implementations). Register it wherever crowded is registered (grep -rn '"crowded"' rust/crates/beryl_cli/src). Add the fixture crowded-max ("board": "crowded-max", "until": "first priority decision for seat 0") and the shots phone-crowded-max and phone-crowded-max-se. The rule to hold, from the phone's design: a creature card is never drawn under 56px high; past that the row's cards overlap evenly instead of shrinking, down to a 14px visible step for creatures and 18px for lands and other permanents. If phoneLayout does not do that, make it. Add a unit test for the floor in ui/scripts/ beside the other layout tests (npm test runs ui/scripts/*.test.mjs).
  5. Widths outside 375 to 430.
    • Wider than 430 (large Android phones): the board is laid out 430 wide and centered, with the table's background filling the sides. In phone.css, .phone-board { max-width: 430px; margin: 0 auto; } with left: 0; right: 0 kept does that for a fixed box; check that useViewport then reports 430.
    • Narrower than 375 (360-wide Androids): lay the board out 375 wide and scale it down by width / 375 with a CSS transform on .phone-board (transform-origin: top left), its layout height being innerHeight × 375 / width. Text then falls just under 12px: that is accepted, so add no shot at that size to ui/shots.json (it would fail phoneFaults); instead add one unit test of the scale computation.
    • Sheets (.phone-sheet, .phone-menu-sheet) and the screens by-7pm.3.1 and 3.2 built must stay inside the same 430-wide column: check them at a 480-wide viewport.

Verify

  1. cd ui && npm run typecheck && npm test.
  2. just ui-shots for every shot whose route has phone: all pass. The command takes names; list them with python3 -c "import json; print(' '.join(s['name'] for s in json.load(open('ui/shots.json'))['shots'] if 'phone' in s['route']))".
  3. just ui-test verb: and just ui-test shape: pass: they now run at both phone sizes.
  4. just test-rust -p beryl_cli passes with the new board.
  5. Add the sentence D7 asks for about large boards and widths to "The phone" in data/ui-conventions.json and run just conventions.
  6. just check. If the fast check's browser budget cuts phone shots, that is its selection working (the run log's cut), not a failure.
