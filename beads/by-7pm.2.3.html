Close reason

Superseded by Project 50k, 2026-11-12: plan K26 put each prompt's state in the session, and ui/src/stage/prompt.ts and PromptBar.tsx draw it for both layouts, which is what this controller was for. Board.tsx, which it was to be lifted out of, is deleted at the cut-over (by-w8gv.21.32). Not built.

Description

Lift the desktop board's interaction logic out of ui/src/game/Board.tsx into a pure, layout-independent module that both Board and ui/src/mobile/PhoneBoard.tsx drive, before the M2 phone beads (by-7pm.3.1–3.4) each extract or re-derive pieces of it in parallel lanes.

Current design

Board.tsx (2.8k lines) holds the table's interaction state machine as closures inside the component:

  • state: draft (combat declaration), picks (choice of cards on the table), casting, chooser, paid, menu (Board.tsx ~273–300), all reset on a new view (~486);
  • transitions: onClick (~821: cast-step payment switching, declaration toggles, table picks with pile rules, exile host, ability chooser vs play chooser vs cast vs menu), drafted (~976), declare, attackWithAll, confirmPicks, castOrSetUp/stepsIn/cast/setUp/pickAct (~494–630), the attacker/blocker parts of onDrop (~909);
  • derivations: per-card glows states (~632–800: playable, target/source highlights during declarations and table picks, aims at walkers/blockable attackers), the dock (passesOn ~1101, stop label from HALT_BUTTON/passButton, finish/declaring ~1140), and withResolving(view) as the view shown.

Pure helpers already exist (combat.ts Draft/declared/blockable/attackPlan/blockPlan, tablePick.ts, decisions.ts interactions/follow/tapsOnly, casting.ts), but the logic that combines them per tap is component-local, so M1's PhoneBoard re-derived a subset and it already diverges:

  • its glows skip declarations and table picks;
  • its passesOn drops desktop's decision.kind === "priority", !casting, !chooser conditions and the floating-mana pulse (setLost);
  • it renders view without withResolving;
  • "No Attacks"/"No Blocks" are hard-wired, with no draft.

M2 needs all of it on the phone: 3.1 taps attackers ("same attacker decision path as desktop"), 3.2 blocks/targets/pays and opens the ability chooser, 3.3 picks cards on the table, 3.4 undo. 3.1 is lane mobile-ui and 3.2–3.4 lane mobile-moments, so two sessions would extract from Board.tsx concurrently and fork it.

Proposed design

A pure module, e.g. ui/src/game/table.ts, with no React and no layout geometry:

interface TableState { draft: Draft; picks?: ReadonlySet<number>; casting?: Casting; chooser?: ChooserRequest; menu?: MenuRequest }
type TableInput =
  | { kind: "tap"; slot: number; pile: number[] }        // pile: the layout's identical-permanent group, top first
  | { kind: "dropOn"; slot: number; onto?: number | "opponent"; forward: boolean }
  | { kind: "declare" } | { kind: "attackWithAll" } | { kind: "confirmPicks" } | { kind: "closeChooser" } ...
type TableEffect = { kind: "choose"; index: CandidateIndex; then?: Intent[] } | { kind: "sound"; name: SoundName } | { kind: "viewExiled"; slot: number } | { kind: "refused"; slot: number };
function step(ctx: TableContext, s: TableState, input: TableInput): { state: TableState; effects: TableEffect[] }
function glows(ctx: TableContext, s: TableState): Map<number, CardState>   // playable / target / source
function dock(ctx: TableContext, s: TableState, waiting: boolean): DockModel  // turn button label+caption, onPress input, passesOn, finish

TableContext = the withResolving view, interactions(view), objects map, stops. Origin points for the chooser stay in the component (it maps a ChooserRequest to Mode[] with geometry). Board keeps its rendering, drag physics, hover/inspector and layout; it holds TableState in one useState/useReducer and runs effects. PhoneBoard does the same, feeding pile from its own layout (mobile/layout.ts Spot needs a pile or group lookup) and rendering dock() in PhoneDock.

What it eliminates

  • The forked glow and dock derivations in PhoneBoard.tsx (and the four more forks M2 would add for declarations, picks, casting and choosers).
  • Two lanes editing the same 300 lines of Board.tsx at once.
  • ~600 lines of closures out of Board.tsx into a testable module.

Behavior that must not change

Desktop: every click, drag, cast step, chooser, menu, declaration, table pick, glow, sound and dock label exactly as today. Phone: M1's board renders as now (shots unchanged), except that its dock now follows desktop's rules (pass-on only at a priority with nothing being cast).

Acceptance

  • Board.tsx and PhoneBoard.tsx both get glows and the dock from the shared module; PhoneBoard.tsx no longer imports tapsOnly, passButton, HALT_BUTTON, attackPlan or blockPlan directly, and the phone shows withResolving(view).
  • just ui-test (all desktop flows) and just ui-shots (desktop and the M1 phone shots) pass unchanged; cd ui && npm run typecheck passes.
  • Add one phone flow to just ui-test (runner and flows: ui/scripts/interactions.mjs, tools/src/beryl_tools/): at 393×759 with ?phone, on the attack fixture, tap a creature during declare attackers and confirm through the dock; the session receives the same attack the desktop click-and-confirm sends. (by-7pm.3.1 then builds the touch gestures on this path.)

Files: ui/src/game/Board.tsx, ui/src/mobile/PhoneBoard.tsx, ui/src/mobile/layout.ts, ui/src/game/combat.ts, tablePick.ts, decisions.ts, casting.ts, ui/src/game/layout.ts (passButton, HALT_BUTTON).

Acceptance criteria

Board and PhoneBoard both take glows, the dock and tap/drop transitions from one pure module; PhoneBoard imports no tapsOnly/passButton/HALT_BUTTON/attackPlan/blockPlan; desktop ui-test and all ui-shots pass unchanged; a phone ui-test flow taps an attacker and confirms through the dock, sending the desktop's attack.
