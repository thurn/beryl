Description

What is wrong today

The Trackers store (beryl_kernel/src/trackers.rs) has one shape, a set of permanents per kind. Its rustdoc says a count kept for a player "joins with a shape and a span of its own". Storm needs the spells cast this turn, and Chains of Mephistopheles and Notion Thief need the cards a player has drawn this turn and whether one was the first of their draw step.

What to build

Plan: Designs 1, "This turn's counts".

  • A second shape in the Trackers store: a u8 count for each player and kind, cleared in State::begin_turn with the rest. Kinds: SpellsCast, CardsDrawn, and DrewInDrawStep (whether the player has drawn the first card of their draw step this turn).
  • Each has its Capability, found in GameTable::new from what the game's cards read (a new Amount or Condition entry for each, in beryl_card/src/effect/). The rules write a count only behind GameTable::can: cast/steps.rs where a spell becomes cast, drawing::draw for each card.
  • The store's plumbing (hash, relayout, invariants, Observation::tracked) as for the existing kinds.

Files

beryl_kernel/src/{trackers.rs, trackers/tests.rs, table.rs, turn.rs}, beryl_card/src/effect/{amount.rs, condition.rs}, beryl_rules/src/{drawing.rs, cast/steps.rs}.

Bars (every bead of this epic)

  • The absent-cost gate holds with no bump (just count-gate; R2 in the plan). The count is exact, so report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust). A change to what the WU mirror's rollouts do is a bug in this epic.
  • Rules code cites the Comprehensive Rules with a quotation (root AGENTS.md); just citations.
  • A new card follows the card-writing skill: just card new, just card check <name> (Beryl, XMage and Forge), every instruction carried out by its own scenarios, and just specs <card> passing the generic UI checks from both seats. A disagreement with an oracle is settled by the rules and recorded in data/oracle-divergences.json.
  • Read the card's rulings before writing its scenarios (just card brief <name> prints Scryfall's). Each statement in a ruling that a scenario can show is a scenario of the card. Where one cannot be shown yet, the close reason names the ruling and why.
  • A rules bug found on the way gets its docs/bugs.md entry.
  • If the design in the plan is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.

Acceptance criteria

The three kinds are counted only in a game with a card that reads them, shown by a test game with and without. State size reported: allotment +8 bytes. Count gate holds.

Decisions: (1) DrewInDrawStep is kept as a count (cards drawn in the player's own draw step this turn), not a bool, so all three kinds share the u8-per-player shape; Condition::DrewInDrawStep(Players) holds when each named player's count is above zero. (2) Vocabulary: Amount::SpellsCast(Players), Amount::CardsDrawn(Players) (totals over the players), Condition::DrewInDrawStep(Players). (3) Capabilities are found by a generalized walk (beryl_card walk.rs now visits Node::{Filter,Amount,Condition}); EnteredThisTurn detection moved onto the same walk, replacing asks_what_entered_this_turn. (4) Trackers' Hash feeds counts only when one is nonzero, so games without a reader hash as before (corpus_never_changes pin kept). (5) beryl_search long/turn.rs observation_key now hashes each player's counts. Plan section in docs/rules-coverage.md matches; not amended.
