Close reason

Measured native phone play, tuned mobile AI budgets, verified full games and lifecycle behavior, and landed passing fast checks on staging.

Description

Measure how the engine and the AI behave on a phone and set what a phone offers so that the game never stalls. Nothing has measured it. What is known: the search's budget is Budget::DEFAULT for every platform (rust/crates/beryl_session/src/ai.rs, new_agent: 4000 iterations over 18 trees, each tree on a thread of its own, tuned for about 2 s a decision on an 18-core Mac: rust/crates/beryl_search/src/mcts.rs); the two deep agents spend 30 million engine steps a decision on every core (deep_family in rust/crates/beryl_search/src/lib.rs); the app embeds the card store, a 22 MB TSV (data/card-store.tsv, beryl_card_store); and the start screen's default opponent is expert, which does not search.

Depends on by-7pm.3.6 only so that one session at a time drives the simulator and the emulator.

Where the code is

  • rust/crates/beryl_search/src/lib.rs: AGENTS (the eight offered: random, greedy, expert, expert-frozen, mcts-omniscient, mcts-hidden, and the two deep ones), AgentInfo, deep_family. mcts.rs: Budget.
  • rust/crates/beryl_session/src/ai.rs: new_agent(name, table, seed). lib.rs: agents(). sessions.rs and session.rs: Sessions::new, with_ledger, the session's thread, resume_latest. game.rs lines near 297 and 424 call new_agent.
  • rust/crates/beryl_app/src/games.rs: sessions(app) (replays go in app_data_dir()/replays), list_agents, resume_game. lib.rs: setup (ArtCache in app_cache_dir()/art). art.rs: ArtCache.
  • ui/src/screens/StartScreen.tsx: DEFAULT_AGENT, the agent list from listAgents(), "Return to Game".
  • The journal (beryl.jsonl in the app's log folder): tools/src/beryl_tools/mobile.py journal(udid, pid) and android.py journal(pid) read it. rust/crates/beryl_session/src/journal.rs writes it.
  • tools/src/beryl_tools/mobile.py: SIMULATOR_APP, DEVICE_IPA; android.py: APK.

What to do, in this order

  1. Make decisions measurable. If the journal does not already record how long each of the agent's decisions took, add one debug record per agent decision in beryl_session (source ai, the decision's wall-clock milliseconds and the agent's name), written on every platform. Check with a desktop game first (just smoke still passes; the record appears in the desktop's journal).
  2. Measure, per platform (iOS Simulator, Android emulator), for each of expert, mcts-hidden, mcts-omniscient and pimc72-hidden-30m-anchor: start a game against it from the start screen and play at least ten turns (pass priority and make simple plays by touch; an early concession is not enough). From the journal: the median, 95th percentile and worst decision time. Also record: the app's resident memory at its peak (iOS Simulator: ps -o rss= -p <pid>, the app is a Mac process; Android: adb shell dumpsys meminfo ca.thurn.beryl), whether the UI still answers a touch while the agent thinks (open the menu during a long decision), cold start to "ui ready" (just ios-smoke, just android-smoke print it or the journal times it), and the size of Beryl.app for the simulator, of the device archive from just ios-device --no-install, and of the APK. Put the numbers in a table in a comment on this bead. The simulator and the emulator run this Mac's cores: say so beside the numbers, since a phone is slower by a factor nobody has measured.
  3. Set the phone's budget and agents from those numbers. The target: no offered agent's 95th-percentile decision over 3 s in the simulator. The default design, to change only if the numbers say otherwise:
    • Budget::PHONE beside Budget::DEFAULT in mcts.rs, with trees at most 6 and iterations set so that mcts-hidden meets the target, its doc comment giving the measurement as DEFAULT's does.
    • new_agent takes the budget as an argument; Sessions holds one (Sessions::with_budget(budget), default Budget::DEFAULT), and beryl_app's games::sessions sets Budget::PHONE under #[cfg(mobile)]. beryl_session learns nothing about platforms.
    • The two deep agents ignore the budget and cannot meet the target: games::list_agents leaves them out under #[cfg(mobile)] (by name, as beryl_search::AGENTS names them). They stay buildable, so a game saved against one still resumes.
    • The desktop's agents, budget and results do not change: just count-gate and the test rollouts_never_change (rust/crates/beryl_bench/src/rollout.rs) must pass untouched.
  4. Resume after a kill. On each platform: start a game, play three turns, kill the app (xcrun simctl terminate <udid> ca.thurn.beryl; adb shell am force-stop ca.thurn.beryl), launch it again. The game is offered ("Return to Game" on the start screen, or it resumes at launch, whichever the desktop does) and continues from the same decision. If it does not, find why (resume_latest, the replays folder on that platform) and fix it.
  5. While in the background. Send the app to the background during an agent's decision (iOS: the Simulator tool's button HOME; Android: adb shell input keyevent KEYCODE_HOME), wait 30 s, return. The game must continue. Do not add a pause mechanism unless the app was killed or the game was lost: say what you saw.
  6. Art cache. Images are downloaded on demand into app_cache_dir()/art, which both systems may purge. Check on each platform that card images appear in a game, and after a relaunch with the network off (iOS Simulator: there is no switch, so point art::SCRYFALL's host at an unroutable address in a build you do not commit, or check the cached files exist and the journal shows no download; Android: adb shell svc wifi disable and svc data disable, then enable both again) the cached ones still appear. No size bound is added: the system's purge is the bound. Record what you checked.

Verify

  2. just ios-smoke, just android-smoke, uv run --quiet --project tools by mobile-check.
  3. One whole game against mcts-hidden to game over on each platform with the phone budget, no decision over the target: the journal's numbers in the close reason.
  4. just check.

Phone measurements, 2026-11-13. Debug builds ran in the iOS Simulator and Android emulator on this 18-core Mac; these are the Mac's cores, not measured physical-phone performance. I drove seed 11 through the app's WebView by Tauri IPC, choosing a land, then a cast, then Pass when available. The headless iOS tool did not expose touch injection, so these are on-device engine and WebView measurements rather than touch-play measurements. Percentiles use nearest rank. RSS peaks are the largest samples I observed, not continuous maxima.

| Platform | Agent | Decisions | Median ms | P95 ms | Worst ms | Observed RSS peak | | iOS Simulator | expert | 19, through turn 10 | 0 | 5 | 5 | 306 MiB | | iOS Simulator | mcts-omniscient | 18, through turn 10 | 210 | 334 | 334 | 306 MiB | | iOS Simulator | mcts-hidden | 129, game over turn 40 | 224 | 368 | 419 | 308 MiB | | iOS Simulator | pimc72-hidden-30m-anchor | 1 | 126341 | 126341 | 126341 | 322 MiB | | Android emulator | expert | 19, through turn 10 | 0 | 0 | 0 | 298 MiB | | Android emulator | mcts-omniscient | 18, through turn 10 | 782 | 1820 | 1820 | 295 MiB | | Android emulator | mcts-hidden | 129, game over turn 40 | 639 | 1175 | 1634 | 324 MiB | | Android emulator | pimc72-hidden-30m-anchor | first search unfinished after 286 s | unavailable | >286000 | >286000 | not sampled |

The deep Android search was stopped after 286 s while the iOS archive built, so ten turns and a completed-decision percentile would have taken far longer than the other measurements; the iOS deep sample already establishes that it cannot meet 3 s. Both deep agents remain buildable by name but are absent from each phone's six offered agents. At 160 iterations, Android's ten-turn P95 was 5140 ms omniscient and 4600 ms hidden; 64 iterations and four trees brought every offered agent below 3 s. The desktop still uses 4000 iterations and 18 trees.

Cold launch to the journal's ui ready: iOS Simulator 1510 ms; Android emulator 6595 ms from a fresh emulator boot, 737 ms for a cold app process on an already booted emulator. Sizes: iOS Simulator Beryl.app 165208 KiB on disk (161.3 MiB); unsigned device Beryl.ipa 21683549 bytes (20.7 MiB); Android debug APK 330849592 bytes (315.5 MiB). An incremental Gradle build first produced a 654196420-byte APK with a 323 MB unused ZIP gap. Deleting the previous APK before packaging restored the 330849592-byte output.

On iOS, the menu opened during a search, the app stayed alive after Safari held the foreground for 30 s, and a terminated turn-8 game returned at turn 8 after relaunch. Seventeen cached card images were present on disk and loaded in the WebView after relaunch. On Android, the menu opened during a search, a 30 s launcher interval advanced the same game from turn 2 to turn 21, and a force-stopped turn-10 game returned at turn 10. With Wi-Fi and mobile data disabled during relaunch, all 18 visible card images loaded from the cache; both radios were re-enabled afterward. No physical device was used.
