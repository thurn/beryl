Close reason

Renderer uploads compressed card faces with block placeholders and paced late uploads; b3d png shows cached scans (staging d21487750)

Description

Read first: docs/beryl-3d.md 'Card faces' ('Preparation': the two kinds of upload that remain during play) and 'Rendering' (card faces in a texture array). Read beryl_assets' prepare_match and Prepared, and the renderer's placeholder faces.

In rust/beryl3d/crates/beryl_render:

  • formats() reports which compressed formats the device supports. The board-size and the full-size face arrays are created in the first that prepare_match can make.
  • upload_layer(prepared). During play, a board-size face that arrives late is uploaded only in a frame in which the client's wake() is not Now, one layer a frame, and at most one full-size face is uploaded per frame.
  • The generated placeholder stays for a face that has not arrived.

In beryl_host's Headless and in b3d-render: start prepare_match for the recording's decklists and upload what arrives before drawing, so just b3d png shows real scans where they are cached.

Tests in beryl_render/tests, on the default device and on one created with the downlevel limits: an offscreen render samples a known pixel of a compressed face within tolerance; with 5 layers waiting and the client animating, no layer is uploaded, and with the client still, one is uploaded per frame.

Run: just b3d cargo-test -p beryl_render; just b3d png verbs-zones --at 1500ms.

Acceptance criteria

just b3d png verbs-zones --at 1500ms shows real card scans where they are cached and placeholders elsewhere; the pixel and upload tests pass on both devices; no decode, encode or file read happens on the thread that calls Client::frame.

Pass the client's list (Client::faces(), made from the card records given as Input::Cards) so the FaceIds the workers report match the client's. Derek Thurn2026-11-15

Handoff: beryl_render/src/faces.rs is new. It holds FaceArray (one compressed array per face size, a full mip chain, write() checks the format, size and byte count), face_arrays/empty_arrays, solid_block (ASTC void-extent, ETC2 individual mode plus EAC alpha, BC7 mode 6), solid_level (the placeholder at each mip level), and Waiting (the paced queue). Renderer gains formats(), set_faces(names, format), upload_layer, hold, waiting and upload_waiting(wake). set_placeholder_faces is gone. Headless and surface devices now request whichever ASTC, ETC2 and BC features the adapter has. Arrays use the non-sRGB Unorm formats, because every color is sampled as stored. Placeholder pictures (textures.rs face/back) take a size and keep their shapes on the 4-pixel block grid. beryl_host: Headless::new takes &Scans (Scans::app() = ~/Library/Caches/ca.thurn.beryl/{art,faces}). load_faces runs prepare_match on Page::faces() (new in the driver) through a NOWHERE origin, so it never downloads, then drops the Preparer, which waits for its workers to finish every queued face, and uploads them all. Tests: beryl_render/tests/faces.rs (pixel test for each format plus Rgba8, placeholder agreement, board pacing, full-size pacing; all on default and downlevel limits) and beryl_3d/tests/pictures.rs cards_show_the_scans... (seeded scan cache, faces_built_on_this_thread()==0). Not done here: the desktop app and phone host do not call prepare_match, set_faces or upload_waiting yet. Warm 'just b3d png verbs-zones --at 1500ms' takes about 5 s at load 40-55. Missing scans are re-encoded as placeholders on every run, because beryl_assets never caches placeholders. Fast check: beryl3d cargo-test was cut off under load and handed to the b3d sweep; I ran the beryl_render, beryl_scene, beryl_host and beryl_3d pictures tests locally, all green.
