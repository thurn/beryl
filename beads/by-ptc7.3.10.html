Description

What to do

Rewrite .agents/skills/card-writing/SKILL.md (the .claude/skills entry points at it) for the workflow of Designs E of the plan. Its dependencies have landed: the generated bar, the brief that drafts, the prelude helpers and the rulings ledger. Read their close reasons.

The new procedure:

  1. Worktree, then just card brief. The brief's draft is the starting definition.
  2. Check the draft against the Oracle text and the rulings, sentence by sentence. Compose what it could not draft using the vocabulary and its prelude functions. Add a shared function only when it clarifies a composition. Pass card-specific details as arguments. A clause that needs a new variant is escalated, as before.
  3. just card check --no-oracles, then just card check. Read the generated line: a card whose generated scenarios kill every mutant and agree with the oracles has no scenarios module. Otherwise write one scenario for each surviving mutant it names, and nothing more.
  4. Rulings: a ruling that a scenario can show and that no vocabulary entry covers gets a scenario and an entry in data/rulings-ledger.json (just card rulings --add). A card with no such ruling is not listed.
  5. Citations only for a card-specific ruling (already in the skill).
  6. Commit and enact push.

Keep the rules that hold the workflow together: only card files, prelude helpers, escalations and a wording allowlist entry; every clause, always; no Rust body; never from Forge; never weaken a check. Keep "Cards for scenarios", "Reading failures" (add the generated line and the rulings check) and "Escalating".

Say which model tier each kind of card is for (the tiers of just set plan), so a bead that names a tier can point here.

Also: rust/AGENTS.md, "Testing rules and cards", for the same changes; tools/src/beryl_tools/card.py's docstring, which points at a skill path that does not exist; and change the model card the skill names if it is no longer a good model.

The skill is read by cheap models. Follow "Writing for readers" in the root AGENTS.md, and keep it under 250 lines.

The drafted-card trial on GPT-6.1 Luna

The user selected GPT-6.1 Luna for the drafted-card trial. Keep the tier:haiku routing label used by the set planner and map it in .enact.toml with [tiers.haiku.codex] and model = "gpt-6.1-luna". The tier inherits the configured Codex effort.

  • Start the skill with the drafted-card loop. Run just card new, read the render diff, and edit the definition until just card render <name> matches. Then run just card check.
  • Hand the card back to the comparison tier with a note if a surviving mutant needs a scenario, the vocabulary cannot express a clause, a compile error comes from outside the draft, or three render attempts fail to match.
  • Give a fresh GPT-6.1 Luna subagent only the skill and three drafted cards from just set plan. Record whether each card finished or hit a stop rule.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason.
  • If the count gate still fails after three attempts, follow the run decision on by-ptc7. Leave this bead unresolved and continue independent ready work.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.

A fresh GPT-6.1 Luna subagent given only the skill and three drafted cards finishes each or hits a named stop rule. The close reason lists the actual models, cards, and first failure for each card.
