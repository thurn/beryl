Close reason

Measured 115 s vs 224 s per bead (build + test build) for a reused path; built slots in Enact (02b732f), default off pending target pruning

Description

What we see

Every bead starts in a new worktree directory and enact push deletes it. A comment in Beryl's tools/src/beryl_tools/warm.py says each new worktree builds the workspace crates under new hashes, because cargo's fingerprints include the worktree's path. If so, every bead pays for a rebuild of Beryl's own crates even though the cached rust/target was copied in.

Change

Measure first. In Beryl, time cargo build and cargo test --no-run for the workspace in a new worktree (after warm.py has copied the cache) and again in a worktree created at a path that was built before. Record both in this bead.

If the reused path saves less than about 30 seconds per bead, close this bead with the figures.

Otherwise, give Enact a fixed pool of slot directories (for example .worktrees/slot-01 to slot-20, the size set in .enact.toml). enact worktree create hands out a free slot reset to origin/staging on a new branch, and enact push returns it to the pool instead of deleting it. Keep the worktree's name for the bead in metadata, since the directory name no longer carries it. sweep_worktrees, worktree_bead and the [worktree] remove hook must keep working, and Beryl's warm.py then has less to do.

Done when

The measurement is recorded here, and either the bead is closed on it or an integration test shows a slot being handed out, pushed and handed out again with its build directory intact. This change is in the Enact repository at ~/enact (scripts/enact.py, tests in tests/test_unit.py and tests/test_integration.py), not in Beryl. Read ~/enact/AGENTS.md first and follow that repository's workflow. The measurements behind this bead are in its parent, by-gdn3.
