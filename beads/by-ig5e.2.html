Claude transcripts and session records ingested into requests, tool calls and bead windows; bead query and coverage added; pushed e2bc99d7

Description

Read Claude Code's session transcripts into the store and decide which bead every request and tool call belongs to. This is the first point at which the tool shows a real number, so it also adds a minimal bead query.

Design sections: "Sources", "Attributing sessions to beads", "The store".

Sources, as found on 2026-11-15

  • Transcripts: ~/.claude/projects/<project>/<id>.jsonl, where <project> is the checkout path with / replaced by - (for the main checkout, -Users-<user>-beryl); subagents in <id>/subagents/agent-*.jsonl. 1,111 files and 4.3 GB after six days, so read incrementally and never load a file whole.
  • A line with "type":"assistant" has timestamp, message.id, message.model, message.usage (input_tokens, cache_creation_input_tokens, cache_read_input_tokens, output_tokens) and message.content[] blocks, of which {"type":"tool_use","id","name","input"} is a tool call. The same message.id appears on several lines, one per content block: count its usage once.
  • A line with "type":"user" whose message.content[] holds {"type":"tool_result","tool_use_id"} ends that tool call at its timestamp. toolUseResult holds the output (stdout, stderr for the shell): store its size, never its text.
  • Desktop session records: ~/Library/Application Support/Claude/claude-code-sessions/<x>/<y>/local_<uuid>.json with sessionId, cliSessionId, priorCliSessionIds, priorCliSessionLeftAt, title, model, spawnedFrom. A bead's enact_session metadata is the sessionId; the transcript ids are the cliSessionId values. A session Enact clears between beads gets a new cliSessionId each time.

What to build

  • Rows in requests, tool_calls and windows per the design, each with host and provider claude.
  • Bead windows from the session's own shell commands (enact start, enact claim, enact close, enact close --continue), with the rules of the design for requests before the first window, subagents, orchestrator sessions (enact_vizier metadata on the beads they started), enact worktree create <name> sessions and the rest.
  • A minimal just efficiency bead <id>: requests, tokens by class, wall minutes inside its windows and its sessions. Later beads replace its rendering.
  • coverage gains: sessions with no window, beads whose host has no data (shown as "no data", never as zero), transcripts not yet read.

Need not read

Time categories and dollars: the next beads add them on these rows.

Shared context

  • The design is docs/efficiency-dashboard.md. Read the sections named above before anything else; the rest can wait. The decisions taken with the user are in the epic, bd show by-ig5e.
  • The dashboard's code is the separate Python project in efficiency/ (package beryl_efficiency, standard library only, pyre strict, black). It imports nothing from tools/ and nothing imports it. Read efficiency/AGENTS.md first once it exists.
  • Tests use small synthetic sources built in the test itself or kept under efficiency/tests/. The repository is public: never commit a real transcript, session record or command line from this machine.
  • Real data exists only on the main Mac (host jarvis). Where the acceptance criteria name a check against real data, run it there; if this session is on another machine, record that the check was not run in a comment on this bead and close on the tests.
  • Collection must stay free for agents: no hook, wrapper or prompt text may be added to any session, and ingest must never run inside another command.

Acceptance criteria

Tests on synthetic transcripts cover: one message id on several lines counted once; a transcript that works two beads with enact close --continue giving two windows with no overlap and no gap; requests before the first window joining it; a subagent transcript joining its parent's window; an orchestrator's cost going to its epic; a second ingest reading zero bytes; a truncated last line skipped and read on the next ingest. On the main Mac, just efficiency bead by-bajq.6.9 shows non-zero requests and tokens, and the token totals of one transcript match a hand sum of its usage objects.
