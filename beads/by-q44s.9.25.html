Proposal panel, nudge labels, ability menus, library flows and sorting tray in Beryl 3D; four conventions entries pass

Description

No-equivalent UI Conventions entries Beryl 3D does not follow yet (found 2026-11-16). The lobby (screen/lobby) has the assist switches, but the table shows none of what they turn on:

  • "Proposal panel" (ui/src/table/ProposalPanel.tsx): turn upkeep and combat proposals with a checkbox per line, a mark on each affected card and Apply as one undoable batch.
  • "Assist label": state nudges' clickable tags on cards and life totals.
  • "Ability menus on a manual table" (ui/src/table/abilities.ts): ability rows under Assists in a permanent's menu, the stack marker they place.
  • "Manual table library flows" (ui/src/table/flows.ts): Scry and Surveil under Assists in the library menu, the count prompt and the shared sorting tray, and what the other player sees.

Read first: docs/ui-conventions.md (generated from data/ui-conventions.json) for each entry named below; docs/beryl-3d.md "The parity list"; .claude/skills/b3d/SKILL.md; data/beryl3d/conventions/no-equivalent.json and rust/beryl3d/crates/beryl_inspect/tests/all/conventions.rs (an entry is {"recording", "at", "do"?, "shows"}; "do" lists actions such as menu <locator>, a right click, run at "at" before "shows" is looked for). The manual table client is rust/beryl3d/crates/beryl_scene/src/manual/ and src/client/manual*.rs; screen/table and the table-* recordings show it (just b3d tree screen/table --at end --do ...). The web interface is the reference: ui/src/table/ and ui/src/screens/Table.tsx.

For each entry: build what Beryl 3D lacks in beryl_scene, following the web code, add a recording (a screen recording in beryl_inspect/src/screens.rs, or a stress board) if none shows it, and replace the entry's {"open": ...} in data/beryl3d/conventions/no-equivalent.json with {"recording", "at", "do"?, "shows"}. Never edit data/ui-conventions.json or add a numbered exception. If one entry would pass about 600 lines, leave it open naming a new bead under by-q44s.9.

Run: just b3d cargo-test -p beryl_inspect conventions, just b3d test, just b3d parity (conventions line). Before enact push: run just b3d cargo-test and just b3d test yourself. Tests in beryl_inspect locate elements by role and name, never by numeric id. Do not re-pin limits in data/beryl3d/gates.json by hand.

Acceptance criteria

Each of the four entries in data/beryl3d/conventions/no-equivalent.json is a recording entry that the conventions test passes; just b3d test passes; enact push passes.

What changed:

  • SessionCommand::TableAnswer(Answer) (beryl_scene/src/command.rs), wired to ipc::TABLE_ANSWER in driver/recording.rs and to TableConnections::answer in beryl_3d/src/session.rs. Client::send_answer (client/manual.rs) queues it; its reply comes back as Reply::TableAct like a table action's.
  • New beryl_scene/src/manual/assists.rs: proposals() (checkbox per line, Apply; on the desktop at the left edge, vertically centred between the players' rows, because under the log it covered the opponent's lands at 1440x900), labels() (small buttons anchored with Anchor::Object on each battlefield card or life total), sort_tray() and sort_answer() for TablePrompt::Sort (clickCard semantics from TablePromptView.tsx). New TablePress variants in manual/mod.rs, handled in client/manual_overlays.rs.
  • menus.rs: card_rows() expands Activate ability into one row per TableCardCommands ability (Act::Answer, or Act::AskX for -X, which opens Ask::ability_x 'Choose X'), and card.scry/surveil/look_at_top into one row per distinct printed count. commands::card_entries() offers those commands, which commands_for leaves out because their condition is about the card. ask.rs: look_flow turns Look at top cards on your library into a look_at_top flow while Library flows is on.
  • Recording screen/table-assists (beryl_inspect/src/screens.rs); the four no-equivalent conventions entries now point at it. Tests: beryl_scene tests/all/manual_assists.rs (8 tests).
