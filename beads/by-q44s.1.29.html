Close reason

Beryl 3D sweep on staging at 1a7e65073; slow CI started it and it passed at 85f814a31

Description

Read first: docs/beryl-3d.md 'Checks and isolation'. Then tools/src/beryl_tools/sweep.py in full (it is the model: when a sweep is due, how slow CI starts one in the background, how a failure is bisected and filed as a bead, and where its record is kept), nightly.py (OVERLOAD_PER_CORE), budget.py (what slow CI's CPU budget counts) and deadline.py (what happens to a step the fast check cuts off).

Beryl 3D's checks after a push are a sweep of its own. It never blocks master and never spends slow CI's budget.

In the tools package, sweep.py:

  • just b3d sweep runs, in a detached worktree of the staging tip with that commit's own tools, every step of the beryl3d lane in full and then the sweep's own steps. The steps are a list in the package, each with a name, a command and the machines it runs on; later beads append to it. --step <name> runs one. --dry-run prints what it would run and the bead it would file.
  • It is due when staging holds a commit, since the last sweep, that changes a Beryl 3D path or one of Beryl 3D's inputs from the main workspace: beryl_session, beryl_cli and beryl_art with every crate they depend on by path (computed as script_checks.inputs does), data/ui-conventions.json, data/card-store.tsv and ui/fixtures.json. It skips when the machine is overloaded or another sweep is running.
  • Slow CI starts it in the background after a run when it is due, by one call added beside the one that starts the browser sweep.
  • A failure files one P1 bead for each failing step, as a child of the epic (EPIC in the package's paths.py), labelled b3d-sweep, naming the step, the failing checks, the commit or range that broke it (bisected as sweep.py does, for at most 15 minutes) and the command that replays it. A check that an open sweep bead already names gets a comment instead.
  • After a build that passes, it saves the workspace's build directory to $BERYL_CACHE/b3d/target, which new worktrees clone.
  • It builds the recordings pack for the commit it checks, once the pack exists.
  • A step of the beryl3d lane that the fast check cuts off at its hard limit is the sweep's, not slow CI's. Read how a cut-off step is recorded and make the lane's message say so; slow CI has no beryl3d lane, so nothing there picks it up.
  • Its record is $BERYL_CACHE/b3d/sweep: log.jsonl, one line per firing, and last-output.txt. It runs at utility priority and takes CPU tokens as the browser sweep does. Its checks are logged under the script name b3d-sweep; confirm in budget.py that slow CI's budget does not count them, and add a test that says so.
  • docs/checks.md: add the sweep to the 'Beryl 3D' section.

Tests, in the tools' tests: the due rule on five lists of paths; a failing stand-in step makes exactly one bead's text in --dry-run, and a second failure of the same check makes a comment; slow CI's budget report leaves out records whose script is b3d-sweep.

Run: just b3d sweep --dry-run; just b3d sweep.

Acceptance criteria

just b3d sweep passes on the staging tip; after a push that changes a file under rust/beryl3d, the next slow CI run starts a sweep (paste its log line); a planted failing test, swept with --dry-run, prints the bead it would file under the epic; slow CI's CPU report for a run holds no b3d check; a sweep's failure cannot fail slow CI (a test).

Decisions: (1) Each sweep step runs as a lane of its own (b3d-<step>), so one failing step does not hide the others and each failure files its own bead. A lane stops at its first failed step, which is why the steps are split. Steps rerun once, whole (reruns.whole), which also gives bisect.py a Failure to replay. (2) The due rule also counts tools/src/beryl_tools/beryl3d/ and rust/Cargo.toml (lints-match reads its [workspace.lints]). (3) The sweep runs on both slow-CI machines; SweepStep.machines filters steps per sys.platform. (4) Its beads are role:executor (not steward), --parent by-q44s, P1, label b3d-sweep, and are not hidden from 'just beads' the way CI beads are. (5) coverage.in_tree gained place= and warm_rust=, so the sweep's tree has its own lock (the old shared coverage lock would have made it wait hours behind a browser sweep) and does not clone the main rust/target. (6) Added --commit and --force to 'just b3d sweep', so a planted test on a local commit can be swept with --dry-run; --step and --dry-run runs are not logged as sweeps. (7) Not done: building the recordings pack, because the pack does not exist yet. The pack's bead should append a SweepStep to sweep.OWN. Evidence: a planted failing beryl_scene test, swept with 'just b3d sweep --dry-run --commit HEAD --step cargo-test', printed one 'would file under by-q44s, labelled role:executor,b3d-sweep, P1: Fix the Beryl 3D sweep's cargo-test step: b3d-cargo-test:cargo-test'. Its cold build took 21 min at utility priority with a load average near 64. Budget: check_value.slow_ci keeps only script=ci records; the test test_slow_cis_budget_leaves_out_the_sweeps_records holds it.
