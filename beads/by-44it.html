Close reason

The flaky test cannot be identified: on Dereks-MacBook-Pro the rust:tests step logs no test by name (cargo-nextest missing, so it falls back to plain cargo test), and that machine's run log is not on this Mac. Cause is the environment; the step stays. b1342b05 makes the step print that cargo-nextest is missing and how to install it, so a later flake there names its test and gets a bead of its own.

Description

The step rust:tests, which names no checks of its own, failed and then passed on its rerun on the same tree in by check on Dereks-MacBook-Pro at 3f08d7afb9. The flake failed no lane, but checks must fail deterministically, so the flaky one is deleted instead of being rerun until it passes. just ci-report lists its runs, failures and verdicts; its bead of verdicts is by-ci-13a40d87c9.

First find which test or check inside the step failed: the slow-CI and fast-check logs of the failing run show its output. Then treat that one as the flaky check.

Before deleting it, ask: could a fast, deterministic test (a Rust unit test, a Node test with no browser, a check against a recorded fixture) keep most of what this check protects? If so, write that test, then delete this check. If not, delete it when it has never caught a real bug (no catch verdict), or move it to the nightly when it has. If the flake comes from a race in the product rather than in the test, fix the race instead and say so.

Record on this bead which you chose and why. The cifix skill (.agents/skills/cifix/SKILL.md) says how to work this bead.

Acceptance criteria

The flaky test inside rust:tests no longer runs in CI, or it is replaced by a deterministic test, and this bead records which and why. The step stays.
