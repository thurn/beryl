Description

Review group 4 as built, against Designs 4 of docs/rules-coverage.md, CR 604.3 and CR 612, and fix what you find.

Look hardest at:

  • The word types. Find a word a text change should reach that is still a plain value: walk every type of beryl_card that holds a Colors or a Subtype and ask whether a card's text names it as a word. Try Mind Bend, in a test, on every implemented card that names a color or a land type.
  • CR 612.2: a card's name is never changed. CR 612.3: a granted ability is never changed.
  • An ability on the stack whose source's text changes, or changes back, before it resolves.
  • Hidden information: does a color given to a card in a hand or library reach an Observation that should not see the card? Run the information-independence test with Painter's Servant in play.
  • Characteristics read off the battlefield: grep beryl_rules for a read of a face's colors or types that does not go through the query.

Two things every Warden of this epic reports

  • The group's count. The count gate's tolerance is one total shared by the whole epic, so a group that uses most of it leaves the next bead to fail for work it did not do. From the close reasons of this group's beads, add up the change each made to the absent-cost count (just count-gate) and put the total in your close reason. A bead that raised the count by more than 0.05% without saying why is a finding: find the cost and remove it, or file it.
  • Test definitions. List each behavior a bead of this group proved with a test definition in beryl_rules/src/tests/ where it had no real card. For each, name the card scenario that now covers the same path and agrees with XMage and Forge. Where the card has landed and no scenario does, write the scenario. Where the card is in a later group, comment on that card's bead with the path its scenarios must cover. Where no card of the epic has the behavior, file a tier:sonnet partner card bead under this group.

Bars (every bead of this epic)

  • The absent-cost gate holds with no bump (just count-gate; R2 in the plan). The count is exact, so report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust). A change to what the WU mirror's rollouts do is a bug in this epic.
  • Rules code cites the Comprehensive Rules with a quotation (root AGENTS.md); just citations.
  • A new card follows the card-writing skill: just card new, just card check <name> (Beryl, XMage and Forge), every instruction carried out by its own scenarios, and just specs <card> passing the generic UI checks from both seats. A disagreement with an oracle is settled by the rules and recorded in data/oracle-divergences.json.
  • Read the card's rulings before writing its scenarios (just card brief <name> prints Scryfall's). Each statement in a ruling that a scenario can show is a scenario of the card. Where one cannot be shown yet, the close reason names the ruling and why.
  • A rules bug found on the way gets its docs/bugs.md entry.
  • If the design in the plan is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.

Acceptance criteria

Findings fixed or filed as children of this group. The close reason gives the group's total change to the count and the list of test definitions with the card scenario that covers each.
