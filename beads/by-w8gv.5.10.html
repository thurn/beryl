Close reason

Index types SpecIx, AbilityIx, GrantIx, CastingIx and ModeIx in beryl_card; vocabulary, kernel records and EffectCtx retyped; the enum AbilityIx renamed ObjectAbility; parity and count hold

Description

Milestone 3 (plan "Kernel rules"): "Ability, target, mode and option indices are distinct types. Those a definition names are defined in beryl_card." Today they are bare u8 in two crates, and M2's handoff warns they are easy to confuse.

Read first

docs/project-50k.md, "Kernel rules" and "Crates". Mason note 3 on by-w8gv.5.1 (bd show by-w8gv.5.1). rust/crates/beryl_card/src/definition.rs: FaceIx, AbilityIx and FaceAbility are the pattern to follow. rust/crates/beryl_kernel/src/lib.rs for the API contract.

Scope

The indices a definition names, defined in beryl_card:

  • Target spec (which instance of the word "target" in an ability, an index into its target specs; CR 115.1): Objects::Target(u8) and Players::Target(u8) (beryl_card/src/effect), Effect::removes(u8), Ability::removes_target(u8), the state's Target::spec and Casting::spec (beryl_kernel, from state.rs), and the builders in beryl_card/src/effect/build.rs.
  • Ability (an index among a face's abilities): AbilityIx exists. Use it where a bare u8 means the same thing: PendingTrigger::ability, CastingOption::Overload { ability: u8 }, trigger::ability(t, card, face, ability), FaceFacts' activated bit positions.
  • Grant (an index among a card's granted abilities): Modification::Grant(u8) (beryl_card/src/continuous.rs), GrantRef::grant (state), Derived::granted.
  • Casting option (an index among a face's CastingOptions, the bit positions of Castings, beryl_card/src/cost.rs:155): Castings::only(u8), EffectCtx::paid(index: u8), cast.rs's option loops.
  • Mode (CR 700.2): where a modal choice is carried as a bare integer today (the Ask and Opt variants for modes in decision.rs, and what a resolving body reads back).

Find the rest by changing a type and reading the compiler's list. Card files (rust/crates/beryl_cards/src, 47 files) write these as literals through const fn builders: keep the builders taking the literal and wrapping it, so a card file does not change, or changes by a search and replace.

Constraints

  • The place of a chosen target in a stack entry's list is a different index space (resolve::legal_targets' u8 mask, EffectCtx::target(i)). It is the next bead's (by-w8gv.5.11 (target places)). Do not merge the two: the point is that they stop being interchangeable.
  • These types are stored in State. Target<Small> stays 4 bytes and State<Small> within 20 KiB (asserted in the kernel). A newtype over u8 with #[repr(transparent)] costs nothing; run cargo test -p beryl_bench rollouts_never_change to see nothing moved.
  • decision.rs is being edited by the prompts milestone (by-w8gv.11): keep the diff there to the type of a field.
  • ts-rs generates ui/src/generated/protocol.ts from beryl_session; a test fails when it is stale and its header says how to regenerate it. A newtype that reaches the protocol must serialize as the number it wraps, so saves (the frozen corpus) and the UI do not change.

Parity and checks

Parity (plan K11) at the push: just check passes; the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds (cargo test -p beryl_bench rollouts_never_change); slow CI's counts lane (just count-gate, bar 405,276,238 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. No behavior changes: no rules fix, no new card, no new mechanic. Work the card-names and file-length allowlists down as files are touched (data/card-names-allowlist.json, data/file-length-allowlist.json; an entry moves with its file and its count only falls; a new file is under 800 lines). Rules code cites the Comprehensive Rules (AGENTS.md); keep the citations of code you move.

Acceptance criteria

beryl_card defines distinct index types for a target spec, an ability of a face, a grant, a casting option and a mode, and no vocabulary type, state record or EffectCtx method carries one of those as a bare u8 (Objects::Target, Players::Target, Effect::removes, Ability::removes_target, Modification::Grant, CastingOption::Overload, Target::spec, Casting::spec, GrantRef::grant, PendingTrigger::ability, EffectCtx::paid); passing one kind of index where another is expected does not compile; card files still read as before (a builder takes the literal); sizes asserted in the kernel are unchanged; parity holds.

Decisions and deviations (executor):

  1. AbilityIx was not an index: it was the enum {Own(u8), Granted(u8)} a decision to activate carries. It is renamed ObjectAbility (first commit, a pure rename), and AbilityIx is now the newtype over Face::abilities the bead assumed. FaceAbility is {Own(AbilityIx), Grant(GrantIx)}; ObjectAbility is {Own(AbilityIx), Granted(u8)}. Granted's number counts the abilities granted to a permanent (Derived::granted), a state count and no list of a definition, so it stays a number.
  2. Casting::spec was read two ways: the target spec, and for CastStep::Exile the graveyard position picks continue from. A SpecIx cannot honestly be the second, so Casting has a new field graveyard_from: u8. One byte in Pending; State<Small> stays within 20 KiB, and corpus_never_changes and rollouts_never_change hold.
  3. Mode: nothing carries a modal choice today (no card of the pool is modal, decision.rs has no mode variant since Ask was deleted in c1143436). ModeIx is defined in beryl_card with CR 700.2 for the acceptance criterion and has no user yet.
  4. New types live in beryl_card/src/index.rs (one macro_rules!, since a const fn cannot define a type): SpecIx, AbilityIx, GrantIx, CastingIx, ModeIx. Each is repr(transparent) over u8, derives the same Hash as the byte, has new/get/index and Display. A compile_fail doctest there shows two kinds do not mix.
  5. Builders keep literals in card files: effect::build::target/target_player (unchanged), Modification::grant(n), CastingOption::overload(cost, n), Castings::only(n) (unchanged), FaceAbility::own(n), ObjectAbility::own(n). Card files changed: damn and winds_of_abandon (overload builder), swift_reconfiguration (grant), mana_drain and teferi_hero_of_dominaria (EffectCtx::delay takes an AbilityIx, as paid takes a CastingIx).
  6. FaceFacts::activated is private; activates() and activated() (an iterator of AbilityIx) replace the raw u64, both #[inline].
  7. Not converted: beryl_search's own tables (values.rs bit masks, index_of, main_activate) stay u8 and convert at the boundary with .get(), in the live and the frozen agent alike; beryl_session's protocol writes the number (.get()), so protocol.ts and saves are unchanged.
  8. Counts (just count-gate): 405,151,563 with this change, against 405,148,597 recorded by by-w8gv.5.8 on its rebased tree (+2,966, +0.0007%); bar 405,276,238.
