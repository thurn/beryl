Close reason

Manual hand, exile and sideboard orders replay by stable slot. Staged as 1c5a6e75 after fast checks.

Description

by-bmdk.3.1–.2 require positions from every manual zone and a fly after a hand reorder. beryl_session/src/script/table.rs stores objects in a map and only recognizes battlefield, library and graveyard as ordered. ui/src/stage/table.ts::forHand derives hand order from the encounter order of objects, and place updates an existing object in place. Merely reordering view.objects while retaining stage slots can look right after a full reset and still pass Rust replay on a reorder script that did nothing. Exile and sideboard also have table order and no corresponding replay order.

Change beryl_session/src/{protocol/table.rs,script/table.rs,script/act.rs} and ui/src/stage/{table,desktop,phone}.ts and generated definitions. Carry explicit ordered slots where the shared engine model has no order, and let the existing move/appear/vanish or set payloads amend those lists. Share the placement operation with the existing ordered piles. Preserve legacy engine view ordering and stable manual stage slots.

Acceptance criteria

Build a neutral manual view with a three-card hand. Move its third card to the first spot without changing the card's slot, then add and remove ordered cards from exile and sideboard. The Rust and TypeScript script models produce the transmitted order, a missing reorder fails replay, and engine fixtures keep their current order.
