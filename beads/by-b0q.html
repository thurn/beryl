Description

Milestone 1: rules engine, game UI and AI opponents

Implementation plan, agreed with the user in a design interview on 2026-11-04. The decisions are in this epic's design field. Run it as a full Enact run (Wardens, Mason and Sage gates, Archivist): /enact-plan <this epic> <N> full. Without full, AGENTS.md makes the run light and would close those beads.

Goal

A playable, rules-exact game of Magic in the Tauri app. A human plays a mirror match of the 40-card main deck in docs/sample-decks/2026-10-17-PrinceJools-wu-control.txt (29 distinct cards) against one of five AI agents, in the UI of docs/ui_mockups/. Both seats play that decklist.

  • Engine: docs/engine-architecture.md, its structures built as designed, with only the mechanics these 29 cards use.
  • Measurement: docs/benchmarking.md.
  • Prior art: docs/rules-engine-research.md.
  • Every piece of rules code cites the Comprehensive Rules with https://yawgatog.com/resources/magic-rules/ links and quotations (AGENTS.md).

Design

Decisions from the design interview on 2026-11-04. Each records the choice and the alternative it beat.

  1. Engine scope: the architecture's structures as designed, only the mechanics these 29 cards use. No code for absent mechanics (storm, phasing, poison...).
  2. Card rendering: custom frames as in the mockups (name bar, Scryfall art_crop, P/T badge, type line, rules box) built from pinned card text. Hovering or inspecting shows the full Scryfall scan, which carries the artist credit. Rejected: real scans everywhere; frames only.
  3. Card art: a tools script writes a committed data file per card: the Scryfall default printing (overridable), image URLs, artist, and display text. beryl_app serves images over a custom URI scheme from a disk cache, downloading from cards.scryfall.io on a miss, one request at a time with a proper User-Agent. Placeholders until loaded. Tests and CI never touch the network; no images in git. Rejected: the webview loading Scryfall URLs; a prefetch-only command.
  4. Greedy agent = the D21 rollout policy wrapped as an Agent. Rejected: a separate one-ply lookahead greedy.
  5. MCTS: UCT, full-game rollouts under greedy, stall scores 0.5, nodes store choices and replay from the root, iteration budgets (a seed reproduces a move), independent trees root-parallel on threads with visit counts summed in a fixed order. Hidden information: ensemble determinization (K determinizations from the Observation, one tree each). Omniscient: the same search on the true state. Tournaments run one thread per game, games in parallel; the UI opponent uses root parallelism. Rejected: SO-ISMCTS; single-threaded; short horizon plus evaluation.
  6. Expert system: rules plus card knowledge plus engine copies for combat and lethal checks only. Bar (revised by the user on 2026-11-05, replacing "5 games, all reasonable, zero blunders", which proved unreachable: 9/35 clean on unseen seeds): the goal is plausible play, not flawless play. The rubric asks whether a competent human could plausibly have made each decision; a blunder is only an unambiguous, transcript-confirmed losing mistake, and defensible judgment calls (e.g. holding or firing a wheel when behind) are never blunders. Final round: 10 never-reviewed seeds chosen after the last code change, one Sonnet reviewer each; pass when at least 7 of 10 are judged plausible. If 3 rounds under this rubric miss 7/10, accept the best round provided at least 5 of 10 are plausible, and file the open blunder patterns as follow-up beads (non-blocking). Strength floor: expert wins at least 90% against random and 70% against greedy over 200 seeded games. Rejected: pure rules; generic heuristics.
  7. Strength gates: seeded tournaments, at least 100 games per pairing, seats alternated. Every agent wins at least 90% against random; mcts-omniscient at least 60% and mcts-hidden at least 55% against greedy. Every other pairing is reported in the epic notes, not gated.
  8. Oracles: XMage and Forge both in M1. just oracle-setup installs Maven with Homebrew if missing, shallow-clones both at pinned commits into ~/Library/Caches/beryl/oracles and builds them with openjdk@21; agents run it unattended. Unsupported cards or scenarios are reported, not failed. The Comprehensive Rules decide disagreements; oracle bugs go on an allowlist with the CR citation.
  9. Performance: the cube rollout benchmark on WU-mirror positions, _counts, _timing and _abba targets for copy, next+apply and the rollout policy, and the search Cargo profile. Gates: State at most 20 KiB at compile time, zero hot-path allocations, stall rate under 0.5%, perf-counter bands. The time targets are reported from instruction counts; timing is for a human on a quiet machine and is never an acceptance criterion.
  10. UI: a pseudo-3D table with CSS 3D transforms (no WebGL) and Motion (the successor to Framer Motion) for every zone change: cards never jump. Arena-style drag to play: drag a hand card onto the battlefield, attackers forward, a blocker onto an attacker, with a click fallback for every drag. Targets are picked by clicking cyan-highlighted candidates; ordering (scry, Jace's put-back) by dragging.
  11. UI verification: ui/src/ipc.ts gets a fixture transport that replays sessions recorded from real seeded games. just ui-shots generates the fixtures with beryl_cli, serves the UI with Vite and captures fixed states with headless Playwright WebKit into a gitignored folder. A reviewer subagent compares them with docs/ui_mockups. Plus typecheck and just smoke. Agents never open a window.
  12. Modes: a human against one chosen agent. No spectating, no hotseat.
  13. Human stops: the smart stops of architecture section 15 by default; the primary button names the stop it advances to; a setting switches to the exact profile.
  14. Protocol: beryl_session emits a reduced PlayerView (not the masked State), with TypeScript types generated by ts-rs.
  15. Run shape: full Enact, about 21 implementation beads, gates after M1a and M1b.
  16. Pixel fidelity (added 2026-11-05): the UI is matched to docs/ui_mockups part by part. A harness renders replica states of each mockup at its native size, with each card's art cut from the mockup itself (dev-only, gitignored), and writes side-by-side, onion-skin, difference and flip images per part. A part is done when a fresh reviewer subagent calls it indistinguishable at a glance; no numeric thresholds. The card back is our own Project Beryl back (after scry.png) everywhere; the MAGIC back in three mockups is masked. Fonts are chosen per role by overlay from open-licensed fonts (bundled) and macOS system fonts (by name). Component parts in M1a; whole screens in M1b. Rejected: Scryfall art in replicas (art noise drowns chrome offsets); numeric pixel thresholds; a separate M1c.
