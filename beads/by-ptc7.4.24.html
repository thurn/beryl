Description

Review these passes as built, in continuous/, replacement/, combat/, zones/, objects/, actions/ and keywords/ of rust/crates/beryl_rules/src/, against Designs C of the plan and the two contracts, and fix what you find.

  • Did a pass change behavior? Read each pass's third commit for a deleted branch, a merged function or a removed check. The tests held, but a test may not exist: for each thing removed that no test covers, either show it was dead or restore it with a test.
  • Typed references: is any function still taking an ObjectRef or a bare L::Slot where it means a permanent, a spell or a card in one zone? Is any is_current test left that the type makes redundant, or removed where the type does not carry it?
  • Rule ownership: open just citations coverage. For the sections these modules own, is each rule that the code implements declared, and is anything declared that the code only mentions?
  • File boundaries: is any file split at a place that is not a rule boundary? Is any file named for where it came from (elsewhere, additions, more) and not for what it holds?
  • One question, one answer: grep for two functions that answer the same rules question (the logged class). List each pair and merge it.
  • The count: add up each pass's change from the close reasons and put the total and the lines removed in yours.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.

Acceptance criteria

Findings fixed or filed as children of this milestone. The close reason gives the total change to the count and to non-test lines for these passes.
