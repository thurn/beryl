Description

Milestone 7b of Project 50k (docs/project-50k.md K2: "keyword-only creatures need no authoring"; "Authoring tools" 1: "No model. Vanilla and keyword-only creatures are complete from generated characteristics"; the run epic: "an unimplemented card is a record in the card store, never a file"). Last bead of lane set-crates: characteristics are generated from the store for cards with files, and Subtype covers the catalogs (the previous two beads; read their handoffs).

What to build

  1. Cards with no file. A pool card is complete from the store when it is a single-faced creature whose Oracle text, with reminder text removed, is empty or only keyword abilities the engine has (Keywords in rust/crates/beryl_card/src/characteristics.rs: first strike, flying, reach, vigilance and flash today). The rule follows that list as it grows; never keep a second list. The build helper generates a whole CardDef for each such card into the set crate of its first-printing set: generated code in OUT_DIR, no file in the tree, no stub. By Scryfall's keyword field 1,199 of the pool's 32,496 cards are vanilla or keyword-only creatures; with today's five keywords it is fewer. Print the count from the helper's test and put it on the bead. A set group with such cards but no card files now needs its crate: the crate directories (a few-line build.rs and a Cargo.toml each) are written from data/set-groups.json by a command, and a check holds them current; nobody writes one by hand.
  2. A card that gets a file later replaces its generated definition: the helper skips cards with a file. Whether a file may exist for a card the store says is complete (to add something the store lacks) or is an error naming the card: choose, enforce and record.
  3. They are cards like any other: in beryl_cards::CARDS, found by CardTable::get, served a spec on request (/specs/<card> generates for the requested card only; check one), usable in a decklist, and passing card()'s compile-time checks. Scenarios for them come only from the existing generators (beryl_cards/src/derive/; the keywords' library scenarios in beryl_cards/src/library/keywords/), per card on request. Do not add a thousand cards to any sweep (just oracle with no names, script-check, ui-shots, the fuzz decks): say on the bead how each sweep keeps to the cards with files and the decks.
  4. just card path <name> and just card brief <name> say "complete from the store" for them.
  5. Parity: the 47 cards' rollouts and the corpus do not see the new definitions (game indices come from decklists). The count gate must not move. Measure just smoke's start-up and the app binary's size before and after and put them on the bead (plan: "App startup and the UI bundle do not grow with the card store": static definitions are data, not start-up work, so the binary may grow and start-up may not).
  6. One real test of the claim: a scenario that casts a store-only flying creature and a store-only vanilla creature by name, attacks and blocks with them, run by cargo test -p beryl_cards and by just oracle against XMage and Forge for those two cards.

Results and decisions.

  • Count: 581 pool cards are complete from the store with today's five keywords (beryl_card_build test count_the_cards_complete_from_the_store; Python store_cards.names() agrees), 0 of them with files. They span 22 of 24 set groups. Six new crates were written by 'just card crates': cards_1994_1996, 1999_2000, 2001_2002, 2007_2009, 2013_2014 and 2025_2026.
  • The rule also requires a mana cost the engine can hold. Hybrid costs ({R/G}) broke the build at first, so the reader moved into beryl_card/src/mana_notation.rs, which mana() calls and beryl_card_build includes by #[path]. There is still no second list of symbols in Rust. Python mirrors the rule (store_cards.py), and both read Keywords from characteristics.rs. The bead's 1,199 figure counted Scryfall's keyword field with every keyword.
  • A file for a complete card is allowed and wins: the helper skips cards with files, because AGENTS.md says never delete a card implementation, and a card written before its keywords existed would otherwise become an error. card brief notes when this happens.
  • CardTable::with_store(cards, from_store): cards() still lists only cards with files, get() finds both, and from_store() lists the store cards. So every sweep that walks CARDS.cards() or SCENARIOS (derive::all, specs list, script-check, prompts and props tests) keeps to cards with files. Fuzz plays the decklists. ui-shots plays fixtures. 'just oracle' with no names dumps no store card; '--card NAME' (passed from oracle's card arguments) adds derive::for_card for named store cards. specs: spec(card) builds a store card's spec on request, from its library scenarios plus derive.
  • Sweep counts before -> after: scenario dump 524 entries/48 cards -> 525/49 (only the new hand-written library scenario, under Serra Angel); script-check 806 -> 806; ui-shots 152 -> 152 (fixtures unchanged); fuzz decks unchanged.
  • Test: library/keywords/evasion.rs plays Serra Angel (flying, vigilance) and Savannah Lions (vanilla) from the store: both cast, the Angel attacks over the Lions, and the untapped Angel blocks and kills them. Forest has no card file, hence a white vanilla instead of Grizzly Bears. 'just oracle "Serra Angel" "Savannah Lions"': XMage 3 pass, Forge 3 pass (the library scenario plus one generated cast per card).
  • Specs: 'beryl_cli specs-check "Serra Angel" savannah-lions' gives 4 moments, all ok.
  • just card path 'Serra Angel' says it is complete from the store (exit 0); card brief adds a 'Complete from the store' section.
  • App (debug, tauri/debug/beryl): size 106,569,032 -> 106,924,744 bytes (+355,712, +0.33%). Start-up to 'ui ready' over 7 launches, back to back: median 304 ms before, 312 ms after (noise). just smoke passes.
  • just scale --cards 5000 --crates 5: before, cold check 8.8 s, release 8.0 s, one-card rebuild 1.3 s, script checks 3.1 s; after, 4.6 / 5.7 / 0.9 / 1.7 s (the baseline ran on a busier machine). 500 checks both times.
  • Parity: just test-rust, the corpus (5 pass) and rollouts_never_change pass. Count gate: 389,850,071 instructions, +0.13% against the bar of 389,343,295 (the bar has moved since this packet's 405M figure), and pass.
  • The registry's names now include any card named in beryl_cards/src that the store has, so library scenarios can name store cards.
