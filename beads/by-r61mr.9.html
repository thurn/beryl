Close reason

Enact 4bf45f6 passed fast and slow CI and reached master with tk register and the per-project GitHub token cache.

Description

Read the epic by-r61mr first: it holds the decisions, the code map and the directory layout this bead assumes. The work is in the Enact repository (~/enact) unless this bead says otherwise, delivered with that repository's own enact worktree create and enact push.

The three machines have no channel between them except GitHub, and the Enact repository is public, so no token can be handed out. Instead each machine makes its own (the epic's decision 17).

  • tk register in cli/: generate a random token, store it in the file outside any repository that tk reads, and push its SHA-256 with the machine's name to a ref in the project's GitHub repository (for example refs/enact/tokens/<machine>), using the push access the machine already has. Running it again replaces the machine's token.
  • In server/src/: implement the accepted-set interface from the feed bead. When a write arrives with a token whose hash is not in the cached set, fetch the token refs from GitHub's public API once, cache them in the Durable Object, and decide. Do not fetch more often than the contract allows, because unauthenticated GitHub requests are rate limited.

Keep it this simple: the stakes are low and the user asked for no more security than bearer tokens.

Acceptance criteria

A simulator test with a fake GitHub endpoint shows a write succeeding after its token's hash appears on the ref, failing for an unknown token, and the server making at most one GitHub fetch for repeated unknown tokens within the contract's interval. tk register run twice leaves one ref for the machine.

Notes

Section 8 of the contract fixes the token file, the ref name and the server's refresh rule.

Decision: tk register uses the project’s configured Git remote and ENACT_HOST when set. It atomically creates the new ref and deletes the machine’s older refs, then installs the private token file. A rejected push leaves the old file in place. The Worker persists the attempt timestamp before fetching and includes cache writes in its daily accounting. Local tests cover rotation and rejected pushes, and the Worker simulator covers successful writes, unknown tokens and rate-limit failures. The GitHub remote accepted an atomic push dry run. A live unauthenticated API probe returned HTTP 403 with its rate-limit balance at zero. I flagged live discovery and the shared token file’s behavior across projects on the deployment bead.
