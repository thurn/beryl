Keep VS Code from watching and indexing agent worktrees

Close reason

Cause found (VS Code parcel watcher overflowing on .worktrees); exclusions added in .vscode/settings.json; after figure needs a window reload

Description

What we see

VS Code used 0.8 to 1.0 of the Mac's cores continuously through a 3-hour sample, which is close to what all the agent sessions' own commands used together. The process was Code Helper.

Why

Not confirmed. The likely cause is VS Code's file watcher, search index or rust-analyzer following .worktrees/ (up to 20 copies of the repository) and each copy's rust/target.

Change

First find the cause: check which Code Helper process is busy (ps, and VS Code's "Developer: Open Process Explorer") while agents are working. Then add workspace settings in .vscode/settings.json that exclude .worktrees, rust/target and ui/node_modules from files.watcherExclude, search.exclude and rust-analyzer's files.excludeDirs, or whatever the cause calls for. If the cause is something a checked-in setting cannot fix, record what it is in this bead and close it.

Done when

This bead records the cause and a before and after CPU figure for VS Code measured with agents active. The measurements behind this bead are in its parent, by-gdn3.
