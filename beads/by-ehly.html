For each check, first ask: could a fast, deterministic test (a Rust unit test, a Node test with no browser, a check against a recorded fixture) keep most of what this end-to-end check protects? If so, write that test, then delete the check. If not, delete it when it caught nothing (delete above), or move it to the nightly (a step in nightly.STEPS, tools/src/beryl_tools/nightly.py) when it caught something (move to the nightly above). Either way the check leaves slow CI: when the fast check (by check) runs it too, keep it there and take it out of slow CI alone. Checks listed together failed in the same runs and go together. Make the cuts without asking anyone, and record on this bead what you did with each check and why.

No cut bead names these checks, which guard something no other check does:

  • app:smoke: the desktop app builds and starts at all
  • ui-test:Enter on the start screen starts a game: the browser UI starts a game
  • ui-test:a land pressed while a script plays on to it is played: the browser UI plays a step of a game
  • rust:clippy: the whole workspace builds and passes clippy
  • ui:tsc: the UI type-checks in strict mode
  • names:*: the repository rules AGENTS.md names, a few CPU seconds in all

Acceptance criteria

Every check listed no longer runs in slow CI: deleted, replaced by a fast deterministic test, or moved to the nightly; this bead records which for each and why.
