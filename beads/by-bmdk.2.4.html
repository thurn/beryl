Close reason

Staged at 2dd60bd5. Manual counts replay at full precision, timed notices play on both layouts, and all 133 engine fixtures are byte-identical.

Description

Manual actions accept a life of 40,000, a power of 200, damage of 300, and a +1/+1 counter count of 999. beryl_table/src/{state,apply/cards,apply/players}.rs uses i32 for them, but beryl_session/src/protocol/view.rs uses i16 for life, i8 for stats, and u8 for recognized counters, damage and each mana count. NamedCounter is u16 and host player counters allow i32::MAX. beryl_session/src/script/{act,table}.rs has no count cases for named/player counters or marked damage, and replay's Piles omits named counters. Notice is closed over engine turn/scry/top-or-bottom/coin, so by-bmdk.3.3–.4 cannot announce a shuffle, a manual roll or a rewind as planned. Narrowing conversions, a fake engine coin source, or applying the final view after replay would conceal the discrepancy.

Give the shared view and script one lossless representation for values accepted by the host, using shared fields where widening preserves engine serialization, or explicit manual fields when it avoids changing engine semantics. Extend the existing count and announce verbs with the missing typed payloads, and include animated manual values in the Rust and TypeScript replay state. Touch beryl_session/src/{protocol/view.rs,protocol/table.rs,script/act.rs,script/table.rs,typescript.rs}, the matching UI stage reducers and notices, and regenerate protocol.ts. Keep engine JSON and the current fixed motion verbs.

Acceptance criteria

A neutral manual view with life 40,000, stats (200, -200), damage 300, recognized and named object counters at 999, and a large mana/named player count round-trips and replays through actual count steps in Rust and TypeScript. Leaving out a count sees a replay mismatch. A roll without a card source, shuffle and rewind can each render the specified announcement. Existing engine fixture payloads stay unchanged.
