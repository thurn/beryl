Description

Read the epic by-r61mr first: it holds the decisions, the code map and the directory layout this bead assumes. The work is in the Enact repository (~/enact) unless this bead says otherwise, delivered with that repository's own enact worktree create and enact push.

Add tk import and tk compare in cli/, with the server's bulk-import endpoint.

  • tk import reads bd export (JSON lines, 18 MB for Beryl's 4,644 beads) and each bead's changelog from bd history --events, and writes tickets with their dependencies, labels, comments, parents, assignees, timestamps and changelog. IDs keep their root and numbers with the project prefix dropped; the prefixed form becomes an alias.
  • It is idempotent and resumable: running it again writes only what changed since the last run, which is what makes the cutover's final import small.
  • It respects the daily rows-written limit: it reads the server's counter, stops before the share the contract reserves for normal work, and reports how many days the remaining import needs. Closed beads go first.
  • tk compare reads both stores and reports every ticket whose fields, dependencies, labels, comments or readiness differ. Readiness must match bd ready for every open bead, including beads under today's gate epics, which become ordinary tickets.

bd history --events takes about half a second per bead and can wait on Dolt's lock, so fetch changelogs at low priority and cache them on disk.

Acceptance criteria

Against wrangler's local simulator with the daily limit lifted, importing a full bd export of Beryl and then running tk compare reports no differences, and a second import writes zero rows. A test with a low limit shows the import stopping early and resuming. The row count of a full import is recorded in the bead with the number of days it needs under the real limit.

Server import/export wire format for interoperability: POST /import takes {tickets: [...]}. Each element is a flat Ticket object (contract fields including id, next_child, timestamps) with edges (outgoing), comments, history and aliases (strings) arrays. GET /export produces the same flat objects as JSON Lines sorted by id, with a page size of 200 and an empty page at EOF. The server allocates version for changed snapshots; input version is optional and ignored. Child allocation high-water marks never decrease. POST replies {seq, imported, rows_written}, with rows_written counting import data and sequence only.
