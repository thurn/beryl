Description

Why

641 of about 1,300 functions in beryl_rules are written fn name<L: Layout>(game: &mut Game<'_, L>, ..). That is repeated text in every signature, and every crate that uses the engine compiles the engine again for each layout it uses. Plan: Designs C, "The L: Layout parameter".

What to do

Measure, then decide, then write the decision down. Do not convert the crate: the module passes do that in their third commit.

  1. Measure: lines of signature the parameter costs; cargo llvm-lines for beryl_session and beryl_search (the compile-time bead by-ptc7.1.2 may already have it in its close reason); check and test-build seconds of those crates.
  2. Try each option on one module (beryl_rules/src/actions/ is small and typical) in a scratch branch:
    • inherent impl<L: Layout> Game<'_, L> blocks spread over the rules modules, so the parameter is written once a block and a call reads game.destroy(p);
    • the same, with non-generic entry points in beryl_rules (next and apply for Small and for Large) so that the engine is compiled once in its own crate;
    • leaving it as it is. For each: lines saved in the module, what happens to names that today are told apart by their module path (actions::scry::scry), the count gate (inlining across the crate boundary can change; just count-gate), and check seconds downstream.
  3. Decide. Write the decision and the numbers in this bead's close reason, in the rules contract (beryl_rules/src/lib.rs, a section the module passes follow), and in the plan's section.
  4. If the decision includes non-generic entry points, build them here, since they are one file and the passes do not touch it.

K5 of docs/engine-architecture.md says the rules library is free functions over Game, so that an agent finds "Scry 2" by file name. Whatever is chosen must keep that.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.

Acceptance criteria
