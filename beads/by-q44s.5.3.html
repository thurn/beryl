Description

Read first: the epic by-q44s ('Rules for every bead'); rust/beryl3d/AGENTS.md; docs/beryl-3d.md 'Elements' (styles come from design tokens), 'What the two clients share', 'Checks and isolation' (this is one of its listed exceptions); data/AGENTS.md; ui/AGENTS.md. Code: ui/src/design/tokens.css (hand-written today, about 45 variables: colors, stat colors, --playable, the button sizes, metal lines, fonts, --radius-card, shadows and glows, --grain, --tabletop); rust/beryl3d/crates/beryl_scene/src/tokens.rs (hand copies of some of them); beryl_scene/build.rs (how space.json becomes constants in src/data.rs); ui/src/screens/Gallery.tsx (a hand-copied table of token values, near its line 52); tools/src/beryl_tools (how a generator and its check are registered, e.g. just conventions for data/ui-conventions.json).

This bead changes a file the web interface reads, so its push runs the web interface's checks once. It is its own bead for that reason.

Build:

  1. data/design-tokens.json, described in data/AGENTS.md: {"tokens": [{"name": "surface", "kind": "color" | "length" | "number" | "font" | "css", "value": "<the CSS text>", "note": "<optional comment>"}], "flat": {...}}. tokens holds every variable of tokens.css, in its order, with the value it has today. css is for values only CSS can use (gradients, shadows, --grain), which the Rust side skips. flat holds what only Beryl 3D's flat layer uses and CSS has no variable for: the spacing steps S 4, M 10, L 16; the type styles TITLE, BODY and BUTTON as tokens.rs gives them (font, weight, size, line height); the sizes and the panel color of tokens.rs (PANEL is surface with alpha 0xe0, written as {"color": "surface", "alpha": 224}).
  2. just tokens in tools/src/beryl_tools (a new module tokens.py, registered like conventions): writes ui/src/design/tokens.css from the file, with a generated-file header naming the command, each note as a comment, and the variables in the file's order. just tokens --check exits 1 when tokens.css differs from what it would write; add it as a step of the main ui lane in checks.py, and list data/design-tokens.json among the ui lane's inputs.
  3. beryl_scene's build script reads data/design-tokens.json as it reads space.json, and writes the constants of src/tokens.rs (space, type_style, size, color, with a color constant for every color token, named in upper case: SURFACE, GOLD, ...). src/tokens.rs keeps its doc comments and include!s the generated file. Add data/design-tokens.json to the inputs of Beryl 3D's sweep in tools/src/beryl_tools/beryl3d/sweep.py, so that a change to it runs Beryl 3D's checks there.
  4. Gallery.tsx's hand-copied table: leave it (C1: no change to the web interface beyond the generated file).

Do not build: new tokens for screens later beads build. A later bead that needs a color or a size adds it to data/design-tokens.json and runs just tokens.

Tests: a test in tools (tests/test_tokens.py) that the generator round-trips every variable of the committed tokens.css; a beryl_scene test that tokens::color::SURFACE equals the CSS value #211f1c and type_style::BUTTON.size is 24.

Run: just tokens --check; just ui-typecheck; just ui-shots game-start game-first-target game-choice-scry (before and after the change); just b3d cargo-test -p beryl_scene; just b3d lane.

Acceptance criteria
