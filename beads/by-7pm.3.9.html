Description

Fresh review of the native beads of by-7pm: by-7pm.3.5 (the beryl_mobile plugin: snapshot, device info, the platform value), 3.11 (share, just mobile-bugs) and 3.7 (the phone's budget and agents, resume, art cache). Sonnet sessions wrote them from step-by-step beads: check the result, not the steps. Read each bead's close reason and comments first.

Depends on by-7pm.3.12 only so that one session at a time drives the simulator and the emulator.

Check, and fix what fails:

  • The plugin. Swift and Kotlin are thin and hold no logic Rust could. The snapshot runs on the main (UI) thread and its completion cannot be lost: snapshot::capture times out rather than hangs if the native side never answers. The PNG file is deleted after it is read. No force-unwrap or unchecked cast on a path a user can reach.
  • Share. share_bug accepts only a report id that is a folder directly under the bugs folder (try .., an absolute path, an empty string in a unit test). Android's FileProvider exposes only the share folder of the cache, is not exported, and grants read for the one URI. Old zips are removed.
  • just mobile-bugs. It never deletes or writes on a device; it takes only folders named like a report; a report already on the Mac or done is skipped; the paired-iPhone path runs only with --device and was never run by an agent; a failure in one source does not stop the others.
  • The platform value. One source: AppInfo.platform and simulator. No user-agent sniffing remains in ui/src (grep -rn "userAgent" ui/src). The report's front matter matches it.
  • Smoke. just ios-smoke and just android-smoke fail if the snapshot fails: break the native snapshot in a scratch worktree and see each fail, then discard the worktree.
  • The phone's budget. Desktop agents and results are untouched (just count-gate; rollouts_never_change). beryl_session and beryl_search name no platform (grep -rn "cfg(mobile)\|target_os" rust/crates/beryl_session rust/crates/beryl_search). The measurements on by-7pm.3.7 support the chosen numbers: rerun one agent's measurement on one platform and compare.
  • Dependencies. Each new one in a Cargo.toml or a Gradle or Swift package file has a comment saying what it is for; none is in the kernel, rules or card crates.
  • Clippy is clean for the app on the host and on both phone targets (uv run --quiet --project tools by mobile-check).

Verify: just test-rust, just smoke, just ios-smoke, just android-smoke, just check.

Warden review, 2026-11-13. The Swift snapshot dispatches onto the main queue and invokes its completion on success or failure. Kotlin draws on the activity UI thread and resolves or rejects its invocation. Rust's mobile snapshot task has a timeout, reads and removes the temporary PNG, and stays alive to remove it even if the caller times out. Android smoke took 3,515 ms to snapshot under concurrent build load, too close to the old 5-second timeout, so I made the mobile-only timeout a 45-second hang guard. A caller's region beyond the PNG used to make Pixels::crop index past the buffer; I clamped the fallback pixel and added a regression test. I found no force unwrap or unchecked cast on the native request paths. In a discarded scratch worktree, I made each native snapshot command reject. just ios-smoke and just android-smoke both failed at runtime with no window snapshot: snapshot deliberately disabled, then the scratch worktree was removed.

share_bug validates a direct child folder and archive file types; its test now covers empty, .., relative traversal, and absolute paths. Rust deletes stale share ZIPs. The merged Android manifest has a nonexported FileProvider; its only path is cache/share/, and the send intent grants read for the URI. just mobile-bugs uses only simulator container reads, Android run-as find and tar, and devicectl copy from; its paired-device route is under --device and was not run. I fixed a source failure aborting later sources, skipped symlinked report folders, and accepted both directory shapes a paired-device copy may produce. Mocked tests cover duplicate and done reports, invalid folders, both copy shapes, and a failed simulator followed by Android and the optional device route.

rg userAgent ui/src found nothing. AppInfo.platform and the plugin's device reply supply phone status and report front matter; the front-matter test covers those fields. rg 'cfg(mobile)|target_os' rust/crates/beryl_session rust/crates/beryl_search found no search hits. Session hits are Platform::current in the IPC protocol and the preexisting mobile exclusion of desktop bug filing; the AI, game, and session budget paths contain no platform branch. games::sessions alone chooses Budget::PHONE, and games::list_agents alone filters the two deep agents. The dependency comments are present in Cargo and now also in the Swift and Gradle packages; kernel, rules, and card crates gained none. I found no unassigned run bead that these fixes obsolete.

Verification: just test-rust passed, including rollouts_never_change; just test-rust -p beryl_app -p beryl_session passed after the fixes. just count-gate passed at 391,693,905 instructions, +0.60% against its bar. just smoke, just ios-smoke, just android-smoke, by mobile-check, full tools pytest, Black, Pyre, and just check passed. The final phone smokes logged PNGs after 446 ms on iOS and 1,921 ms on Android. Explicit Clippy with -D warnings --all-targets passed on both phone targets after gating a desktop-only test and documenting a cross-target false positive on an already-const thread-local initializer; host Clippy passed in just check. just check took 180.5 adjusted seconds against 60; the existing budget bead by-0obt covers that preexisting issue.
