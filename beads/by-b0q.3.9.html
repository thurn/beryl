Rollout benchmark, perf gates and search profile on staging (e8ffee2); counts and round robin on the epic

Description

Part of Milestone 1 (epic by-b0q): a rules-exact engine, game UI and AI opponents for a mirror match of the 40-card WU Control main deck in docs/sample-decks/2026-10-17-PrinceJools-wu-control.txt (29 distinct cards). Read the epic's description (plan, card table) and design field (decisions) first; docs/engine-architecture.md is the design. Rules code cites the Comprehensive Rules with yawgatog links and quotations (AGENTS.md).

Design decisions 7 and 9, architecture section 18 and docs/benchmarking.md.

  • beryl_bench: the cube rollout benchmark, a corpus of mid-game WU-mirror positions cut from seeded expert and greedy games and pinned by a test. _counts (Gungraun), _timing (Criterion) and _abba targets for a State copy, next plus apply averaged over rollouts, and the rollout policy per decision. Report decisions per turn under the search profile and rollouts per core-second.
  • The search Cargo profile (fat LTO, panic = "abort", codegen-units = 1) and recipes passing -C target-cpu=apple-m4.
  • Perf counters per seeded game (state copies, layer recomputes, solver runs, events) with tolerance bands, as tests.
  • Tests for the gates: zero allocations across the rollout loop with the policy, and a stall rate under 0.5% over seeded random and greedy games.
  • Run just bench-count and post the counts as a comment on the epic. Timing is not required: the machine is busy during a run.
  • Run the 5-agent round robin (at least 100 games per pairing, seats alternated) with beryl_cli tournament and post the table to the epic's notes.

Acceptance criteria

  • The corpus is pinned by a test; the benchmarks build and just bench-count runs them.
  • The gate tests pass in just ci.
  • The counts and the round-robin table are on the epic.

Executor notes:

  • Perf counters (Counts: state_copies, layer_recomputes, solver_runs, events) are counted in the Sink, which reaches every place the engine does that work, and moved into Scratch.counts when next/apply return; engine::decision and mana::plans now take the sink. A thread_local tally was tried first and refused by the engine's banned-types test (no hidden global state, §14). Search counts its own State copies via Counts::copied (MCTS iterations, expert combat runs).
  • Gates: per-game perf bands for 3 random + 3 greedy seeded WU-mirror games (games.rs, replacing the three-land placeholder workload); stall rate over 25 random + 25 greedy seeded mirror games in debug (BERYL_FUZZ_GAMES scales it; the tournament reports stall rates at scale); zero allocations across the benchmark corpus's 96 rollouts (beryl_bench tests/allocations.rs, alongside beryl_search's existing one).
  • beryl_bench::rollout: corpus pinned by corpus_never_changes (turns + FNV hash). Note: an expert change that alters its games will move this pin on purpose. The engine-only subject replays each rollout's recorded answers (replays_end_where_rollouts_end checks they reach the same state).
  • rollout_abba compares the current code with itself until an optimization puts its old version in A (null comparison = noise floor).
  • just bench now builds the search profile with -C target-cpu=apple-m4 unless --profile is given; just play/tournament build the search profile too.
  • Gungraun gotcha: rollouts counted 13k instructions under the default entry point (setup's rollouts confuse Callgrind's shadow stack); it now toggles on beryl_search::rollout::rollout. Not in docs/bugs.md: staging just limited it to rules-engine bugs.
  • Counts and hot spots are on epic by-b0q.
