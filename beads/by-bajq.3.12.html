Description

Review group 3 as built, against Designs 3 of docs/rules-coverage.md and CR 614 to 616, and fix what you find.

Look hardest at:

  • The transaction around a step. Does anything an advance does escape the scratch copy (the event sink, chance's record, a counter of the budget)? Does a save of a game with a replacement choice in the draw step replay under each perturbation (beryl_session::perturb)?
  • CR 614.5 and 616.1f: an effect applied once to an event and to what replaces it; the set collected again after each application.
  • CR 614.6: grep for triggers matched on a proposal and not on what happened.
  • Is every mutation a card can replace built as a proposal, or do some library functions still change the state directly (mill, discard, sacrifice, the return of CR 610.3)?
  • Protection: the four parts, each at every place it applies (targets chosen and targets checked on resolution; Auras and Equipment; blockers).
  • The gate: the code a WU mirror move, draw and damage runs.

Two things every Warden of this epic reports

  • The group's count. The count gate's tolerance is one total shared by the whole epic, so a group that uses most of it leaves the next bead to fail for work it did not do. From the close reasons of this group's beads, add up the change each made to the absent-cost count (just count-gate) and put the total in your close reason. A bead that raised the count by more than 0.05% without saying why is a finding: find the cost and remove it, or file it.
  • Test definitions. List each behavior a bead of this group proved with a test definition in beryl_rules/src/tests/ where it had no real card. For each, name the card scenario that now covers the same path and agrees with XMage and Forge. Where the card has landed and no scenario does, write the scenario. Where the card is in a later group, comment on that card's bead with the path its scenarios must cover. Where no card of the epic has the behavior, file a tier:sonnet partner card bead under this group.

Bars (every bead of this epic)

  • The absent-cost gate holds with no bump (just count-gate; R2 in the plan). The count is exact, so report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust). A change to what the WU mirror's rollouts do is a bug in this epic.
  • Rules code cites the Comprehensive Rules with a quotation (root AGENTS.md); just citations.
  • A new card follows the card-writing skill: just card new, just card check <name> (Beryl, XMage and Forge), every instruction carried out by its own scenarios, and just specs <card> passing the generic UI checks from both seats. A disagreement with an oracle is settled by the rules and recorded in data/oracle-divergences.json.
  • Read the card's rulings before writing its scenarios (just card brief <name> prints Scryfall's). Each statement in a ruling that a scenario can show is a scenario of the card. Where one cannot be shown yet, the close reason names the ruling and why.
  • A rules bug found on the way gets its docs/bugs.md entry.
  • If the design in the plan is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.

Acceptance criteria

Findings fixed or filed as children of this group. The close reason gives the group's total change to the count and the list of test definitions with the card scenario that covers each.

Derek Thurn2026-11-15

Warden findings and changes:

  • Bug (fixed): damage::instruction counted proposed damage as dealt, so 'damage dealt this way' (Amount::ThatMany, Condition::Did) ignored prevention. damage::deal now returns the damage dealt; test any_target::damage_dealt_this_way_counts_none_that_was_prevented (fails without the fix: 3 life gained instead of 1); docs/bugs.md entry.
  • Transaction: a save of a game with dredge chosen in the draw step (Pending::StepActions) replays the same under all four perturbations; new beryl_session test replacement_saves (6 draw-step dredges over 15 turns). resolve_on_copy discards the paused run's events (sink.truncate) and its state; decisions are counted once on the committed state (answer_inline); chance is kept through keep_what_was_seen. No escape found.
  • CR 614.5/616.1f: replaced_destination recollects after each application with an applied list; draws use Sink::applied around a body. CR 614.6: triggers match Event::ZoneChange built from the replaced moves, look-back uses replaced destinations, Draw events only for cards actually drawn, Discard by Reason (still a discard under Rest in Peace, as its scenario shows).
  • Mutations: every zone change in beryl_rules goes through event::move_batch_to -> replace::moving (only start.rs and layers::entering's scratch copy call move_object directly), so mill, discard, sacrifice and the CR 610.3 return are proposals.
  • Protection: targets (cast/targets.rs, cast and CR 608.2b), Auras (sba doomed), Equipment (may_equip_in, both equip and the 704.5n SBA), blockers (combat::can_block), damage (replace::damage). Equipment falling off has no scenario (no colored Equipment implemented).
  • Oracles: the exporter could not write a life payment, so Griselbrand's activations were unsupported in both oracles; card_facts.cost_text now writes 'Pay N life'. Forge 5/5 pass, XMage 3 pass (the 0-life scenario ends the game, which XMage's exporter cannot assert).
  • Count: three beads rose >0.05% without naming the cost (3.2 +0.12%, 3.9 +0.10%, 3.8 +0.16% by its own figures): filed by-bajq.3.17 under the run epic. This bead's change: 393,587,948 -> 393,590,215 (+0.00%).
  • Left alone: two Chains of different controllers ask a pointless order choice (cosmetic); drawing::FirstAnswer leak is a zero-size Box (no allocation).
