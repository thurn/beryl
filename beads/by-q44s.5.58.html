Close reason

Revealed Cards faces print as place 'revealed' (Place::Revealed); stand-in fails on a card resting in nowhere; 3 stand-in passes

Description

Seen in one run of just b3d stand-in (which plays a game against expert in the windowless app, answering every prompt through just b3d live): after 20 prompts, with a prompt open and the table at rest for over half a second, the live tree listed card "Portable Hole" #.. nowhere.yours, a face-up card in the place nowhere (ZoneName::Nowhere, where a card goes that has left every zone). The player had not cast it. After a quit and restart, the resumed client showed no such card, so the live client kept an object the views no longer place. The game's seed (1794855470236857000) is above 2^53, so the start screen's seed field cannot replay it; reproduce by running just b3d stand-in --no-build until a tree shows a card in nowhere (the stand-in leaves such cards out of its resume comparison, stand_in.nowhere in tools/src/beryl_tools/beryl3d/stand_in.py; each run's prompts and answers are in $BERYL_CACHE/b3d/out/stand-in-<pid>.txt).

Read first: rust/beryl3d/AGENTS.md; docs/beryl-3d.md 'Objects and placement'. Code: beryl_scene src/play (Show, how a script step moves an object to nowhere and when the object is dropped), src/table (placement), src/agent/tree.rs (place words). A bug report (Cmd+B through live do 'key Cmd+B') saves the views the client was given (fixture.json) and the tree.

Make the stand-in fail when a card rests in nowhere with a prompt open (so the run catches it), find the cause and fix it in the client, with a beryl_scene test of the views that leave the card behind.

Acceptance criteria

A beryl_scene test with the views that left a card in nowhere passes; just b3d stand-in fails on a card at rest in nowhere and passes 3 runs in a row (output in a comment).
