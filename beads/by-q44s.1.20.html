Description

Read first: docs/beryl-3d.md 'The agent interface' in full. It is the specification of this bead: the rules the tool is held to, the commands, the four notations and what is printed. Then the tools package's cli.py (the table of subcommands), and the driver's moments, seek, run and tree.

An agent meets this tool with no memory of it. Build it so that every output can be pasted into the next command.

In rust/beryl3d/crates/beryl_inspect, the library module cli and the binary b3d (src/main.rs calls the library and nothing else):

  • One option parser for every command that takes a recording, in the library, because the picture program reuses it. A recording is named as just b3d list prints it, or by a test's name (b3d:<recording>/<seat>/<width>x<height>, which also sets the seat and size). Options: --seat, --layout, --size, --scale, --tier, --at, --do (repeatable, run in order after seeking to --at) and --json, with the doc's defaults.
  • list [prefix]: every recording with its length and its number of views.
  • info <recording>: every moment, each on a line that begins with the text --at accepts: the views with their times, each script's steps with their start and end, and each prompt with its buttons.
  • tree <recording>: the two header lines and the tree, with --within, --role and --full.
  • diff <recording> --from <moment> --to <moment>: the elements that appeared, left, moved or changed state, one line each, in the tree's line format with what changed after it.
  • check <recording>: every check on every tick for the seat and size given; faults in the doc's format with their show: command; the same fault at several ticks printed once with a count; at most 20, then a count of the rest; one closing line.
  • Exit status 0, 1 when a check found a fault, 2 when the command was wrong. A wrong recording, moment, locator or option says what was expected and lists the five nearest names.

In the tools package: the five subcommands, each building b3d in the workspace's build directory and running it; one line each in just b3d's listing; --help with two examples.

For the agents that follow: a skill b3d beside the specs skill (the same directory and front matter), saying when to use it, the commands with one example each, how moments and locators are written, and that just b3d lists everything; a section 'Seeing and checking' in rust/beryl3d/AGENTS.md; and one line under 'Testing your work' in the root AGENTS.md that points to it.

Tests in beryl_inspect/tests: every line tree prints after its header matches the line grammar; every moment info prints is accepted by --at; an unknown recording exits 2 and lists nearest names; diff of a moment with itself prints nothing; --json output parses; --do 'hover <a tree line>' changes that element's states in the next tree.

Edit-to-output time. Agents work in a loop of edit, then one of these commands. After a one-line edit to a function body in beryl_scene, time just b3d tree verbs-zones --at 1500ms from start to its last line, five times, with the load beside each. The target is 3 seconds. If the median is over it, try these in order, measuring each, and keep what helps: debug = "line-tables-only" and split-debuginfo = "unpacked" in the workspace's dev profile; opt-level = 1 for dependencies only ([profile.dev.package."*"]); and moving beryl_session's protocol types into a crate of their own, which is a bead to file under milestone 1, not work for this one. Put the numbers, and what you kept, in a comment and in a short table in the doc under 'The agent interface'.

Run: just b3d list verbs; just b3d info verbs-zones; just b3d tree verbs-zones --at 1500ms; just b3d diff verbs-zones --from 800ms --to 1500ms; just b3d check verbs-zones.

Acceptance criteria

The five commands work in a fresh worktree and match the doc's 'The agent interface'; a comment holds a transcript in which nothing was typed but what the tool had printed: a name from list, a moment from info, a line from tree used in --do, and a diff across it; five wrong inputs (a misspelt recording, a moment past the end, a locator matching two elements, an unknown command, a bad duration) each exit 2 with a message that names what would work; the edit-to-output time is in a comment and in the doc, at or under 3 seconds or with what was tried.

Decisions and deviations:

  • The client never set the 'hovered' state, so the bead's hover test could not pass. Client now tracks the mouse pointer (Move/Down/Up; Leave/Cancel clear it; touch never hovers) and marks the element agent::hit returns HOVERED after building each frame. No allocation (hit iterates the frame).
  • step:V.B.S moments were refused ('need the script clock'). Implemented: Page::steps() plays the recording once with the script record on and maps history index i to view i+1; a step moment is the middle of its step in real time. Unknown step lists the five nearest.
  • --layout phone without --size uses 393x759 (the phone layout's usual window, as pages::usual_window), not 1600x900. Doc updated.
  • check leaves out blank-card (pages::LEFT_OUT) and says so in its closing line; it refuses --do. Faults about the same rule and elements are printed once with '(and N more times)'.
  • --json prints only the JSON object (the command line is its 'command' field), so it parses.
  • recordings::list now takes a prefix and plays only matching recordings; recordings::names() lists names without playing.
  • The python wrapper hands passthrough commands' arguments, --help included, to b3d unread and does not echo the command (b3d prints the canonical one).
