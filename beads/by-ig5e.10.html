Close reason

Commits source, lead time, cards query, rework rules and metrics; pushed 3a43a585

Description

Connect beads to the commits they landed, and use that for three things: lead time, cost per card, and rework, the cost of later fixes that a bead's commits caused.

Design sections: "Units", "Rework".

What to build

  • Ingest of the git history of staging and master into commits: time, subject, changed paths, the time each commit reached master (first-parent history of master), and the bead that landed it (from the beads' enact_commits; a commit no bead names belongs to "(no bead)").
  • Lead time per bead: creation to start, start to close, and last commit on staging to that commit on master.
  • The card cohort: beads whose commits add a file under rust/cards/, with the number of card files each added, and the cards query giving cost per card by tier, role or any label.
  • Rework, by the two rules of the design. Slow-CI breakages: the Steward bead's cost goes to the beads with commits in its enact_ci_range, narrowed to those whose files the Steward's fixing commits touch when that distinguishes them, shared equally. Fixes to cards: a later commit whose subject begins with fix and changes a card file is rework for the bead that added the file; the fixing bead's cost is divided equally among the card files it changed. A bead is never charged with rework from its own commits.
  • Rework as dollars and as a share of direct cost on every bead, epic and cohort result, always a separate figure.
  • Metrics card.dollars, card.agent-minutes, bead.rework-share, bead.lead-minutes.

Shared context

  • The design is docs/efficiency-dashboard.md. Read the sections named above before anything else; the rest can wait. The decisions taken with the user are in the epic, bd show by-ig5e.
  • The dashboard's code is the separate Python project in efficiency/ (package beryl_efficiency, standard library only, pyre strict, black). It imports nothing from tools/ and nothing imports it. Read efficiency/AGENTS.md first once it exists.
  • Tests use small synthetic sources built in the test itself or kept under efficiency/tests/. The repository is public: never commit a real transcript, session record or command line from this machine.
  • Real data exists only on the main Mac (host jarvis). Where the acceptance criteria name a check against real data, run it there; if this session is on another machine, record that the check was not run in a comment on this bead and close on the tests.
  • Collection must stay free for agents: no hook, wrapper or prompt text may be added to any session, and ingest must never run inside another command.

Acceptance criteria

Tests: a Steward bead over a range with three beads, where its fix touches files of one, charges that one; with no distinguishing file it is shared by all three; a fix commit to two card files added by two beads splits the fixing bead's cost equally; a bead's own later fix is not its rework; direct cost never changes when rework is added. On the main Mac, just efficiency cards --by tier --since all prints cost per card with direct cost and rework in separate columns.

Decisions: (1) When a commit reached master comes from master's reflog in the main checkout. With Enact fast-forwarding master, first-parent history carries no promotion time. The reflog is stored in a new table, ref_moves, which keeps rows after git expires them. on_master is derived at query time. (2) A commit's bead is resolved at query time from enact_commits, not stored. (3) Only the Steward itself is excluded from its own candidates. Other Steward beads can be at fault: on real data, by-gfp (a Steward) carries the 50.53 dollars of by-q3d, whose range held only by-gfp's commit. (4) Card fix: a card file the fixer itself added counts in neither the numerator nor any charge. 'fixed later' counts a later fix commit by any lander other than the adder, including commits with no bead. (5) bead.lead-minutes runs from creation to the last commit reaching master. Real-data check: run against a copy of the store in a scratch cache, because this code migrates the store from schema 6 to 10, and migrating the shared store early could clash with a parallel bead's migration. cards --by tier --since all: opus 52 cards at 12.50 direct / 0.33 rework per card, sonnet 21 cards at 1.21 / 0.03.
