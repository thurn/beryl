Close reason

Board enum owns stress names; Drive and unjudged on Stress; gates unchanged

Description

Symptom: how each stress board is driven and judged is decided by comparing its name to a string literal in three files, and two of them implement the same driving twice. A new stress board, or a renamed one, silently loses its pointer moves, its wait or its check exemptions.

Current design (rust/beryl3d/crates/beryl_inspect/src):

  • stress.rs audited(recording, rule): recording != "stress-verbs" || !matches!(rule, Crowded | StepShown), called from runner.rs (twice) and cli/check.rs.
  • pages.rs page: if name == "stress-hand" sets pointer_moves; if name == "stress-stack" sets a reply delay of STACK_REST_FRAMES ticks.
  • gate.rs Playback::new: if name == "stress-hand" builds a second Page only to read pointer_moves; stack_rest: name == "stress-stack" and Playback::due re-implement the stack's wait with its own frame counting.
  • stress.rs stress(name) and NAMES list the boards by string again, and gate.rs BOARDS lists them a third time.

Proposed design: one enum names the boards, and each board's value carries how it is driven and which checks skip it.

pub enum Board { S255, S1024, Verbs, Hand, Stack } pub struct Stress { pub views: Vec<PlayerView>, pub timings: Vec<Vec<StepTiming>>, pub drive: Drive, // what a page or a playback does besides handing over views pub unjudged: &'static [Rule], // empty except stress-verbs: Crowded, StepShown } pub struct Drive { pub pointer_over_hand: bool, pub rest_before_last: Option<usize /* frames */> }

Board::name() and Board::ALL replace NAMES; stress(name) parses a name once. page and Playback both read Drive and share one implementation of the last view's wait (the reply delay Page already has). audited becomes a lookup in unjudged.

What it removes: the string comparisons in gate.rs, pages.rs and stress.rs, and the duplicate stack-rest logic in Playback::due.

Behavior that must not change: every stress board's frames, work counters and faults. just b3d gate passes with gates.json unchanged, and just b3d test stress- gives the same faults (none listed today).

Acceptance criteria

  1. No string literal naming a stress board appears in beryl_inspect/src outside the one place that maps names to Board. 2. A beryl_inspect test asserts that Board::ALL round-trips through its names, and that stress-verbs alone has unjudged rules. 3. just b3d gate and just b3d test pass with data/beryl3d/gates.json and test-faults.json unchanged.
