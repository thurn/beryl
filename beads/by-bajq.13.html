Handoff: The cause was layers::together::parts, which resolved static parts with LayerChange::resolve. That returns None for Modification::AddChosenColor (Painter's Servant) as well as for amounts, so the part was taken for an amount and static_ability::amounts_of panicked. I fixed it with elsewhere::resolve and added an engine test in tests/entering_together.rs that reproduced the panic. On push, staging already had the same fix in 2fef7d987 (with a Worldgorger Dragon scenario and a bugs.md entry), so I dropped my commit and pushed nothing. The shrunk fuzz choices no longer reach the state on current staging. With the fix, BERYL_FUZZ_GAMES=1000 session fuzz passed all 1000 games. The engine fuzz in the same recipe fails on seed 613 ('a capacity ran out') without this change too; filed as by-bajq.14.
