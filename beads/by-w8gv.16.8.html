Close reason

Tunings name each ability's expected shape; consistency test and negative tests added; before tables removed; rollouts_never_change holds

Description

Current design

The per-deck AI overlay (decision K9: hand-tuned numbers survive only as an optional overlay for supported decks), rust/crates/beryl_search/src/overlay/mod.rs:

  • Tuning.name: &'static str, matched by a linear find in apply (lines ~125-137). Names come from generated names:: constants, so a deleted card breaks the build, but a tuning for a card that is not in the game is a silent no-op.
  • never and tuned_as_not_drawing are bitmasks over the position of an ability on the front face (lines ~27-31; values.rs:137-148 reads only the first 8). Inserting, removing or reordering an ability in a card file silently moves the tuning onto a different ability or drops it. For example Tuning::value(names::SPARAS_HEADQUARTERS, 12).tuned_as_not_drawing(4) means "ability 4 is cycling" only as long as the file keeps that order.
  • The overlay tests (overlay/tests.rs:84-128) compare against a second copy of the old tables with the same positions, so position drift passes them.

The next project edits card files constantly (new abilities, reworded definitions), which is exactly what breaks this silently.

Proposed design

Each tuned ability names what it expects to find, and a test checks it:

Tuning::value(names::SPARAS_HEADQUARTERS, 12).tuned_as_not_drawing(Expect::ability(4, Shape::Cycling))

where Shape is a small enum matched against the ability's effect data (for example Cycling, Draws, Activated). Add one test that every tuning's name resolves in CARDS and every expected ability index has the expected shape; delete the duplicate before::* tables from the tests. A position mismatch is then a test failure that names the card and the ability.

Must not change

Agent behavior: the tuned agents' decisions on decks::WU_CONTROL and VINTAGE_WU_CONTROL (rollouts_never_change).

Test

The new consistency test; plus a negative test that swaps two abilities in a test-local tuning and checks the consistency test reports it.

Acceptance criteria

Every overlay entry's name resolves in CARDS and each tuned ability index is checked against an expected shape by a test; duplicate before::* tables gone; rollouts_never_change holds.
