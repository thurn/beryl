Close reason

Large layout, lossless widening and session promotion on Stalled(Capacity); fuzz covers Large; count gate -1.43% with bar unchanged; slots and nested capacities left to by-cbf.5

Description

Second step of the epic, after the spike shows the generic engine is free for Small.

  • Implement the Large layout: wider slots, growable bitset, Vec queues that never return Full, more object slots than Small's 255.
  • Widening Small into Large keeps every slot number, incarnation, queue order and knowledge bit; a test checks that a widened state's next decision equals the Small one.
  • In beryl_session, keep the pre-action copy for each player-game action and promote on Stalled(Capacity), applying the same choice to the widened state. The session holds enum Game { Small, Large }; the protocol and UI do not change.
  • The AI opponent in a Large game searches Large copies with the same MCTS.
  • Fuzzing: just fuzz runs a share of games forced into Large from the start, so the second code path stays tested.
  • A scenario that overflows a Small queue in a player game (for example more than 64 stack entries) finishes the game.

Acceptance criteria

  • A player game that overflows any Small capacity continues on Large instead of stalling.
  • Widening is lossless (test compares next decisions).
  • Fuzz covers Large games.
  • just count-gate still passes with the bar unchanged.

Delivered: Large layout (layout.rs: Vec queues whose push never fails, PerSlot tables with an entry per slot), State<Small>::widen (lossless: slots, incarnations, queue order, knowledge, rng), card bodies/conditions instantiated per layout via bodies!/conditions! (Ability.body: Bodies {small, large}). Session: Game holds enum Boards {Small, Large}; Boards::apply/next_in_step keep the pre-call Small copy and event count, and on Stalled(Capacity) widen that copy, drop the failed call's events and make the same call in Large, where the game stays. Cancel restores a Small snapshot into a widened game by widening it. Agents: registry builds Box<dyn GameAgent> (Agent<Small> + Agent<Large>); Widening<A: Widen> makes the Large agent on first use: Mcts keeps seed/decision index (kept trees dropped), Expert keeps rng/plan; the frozen expert has no Large copy, so past Small the current expert plays on from its stream. Scripted (cli boards) and beryl_scenario::answer/describe are layout-generic.

Tests: games.rs a_widened_game_plays_on_as_the_small_one (4 seeds, next decision equal and small.widen() == large at every decision); random_games_keep_the_invariants plays every 4th seed in Large (so just fuzz covers Large); session tests/promotion.rs: nine Snapcaster Mages overflow Small's 8 cast permissions and the game ends in a win (fails with promotion disabled).

Count gate: 405,195,913 instructions, -1.43% against the bar 411,090,084, bar unchanged.

Deviation: per the spike's note, Slot and Bitboard are not layout types yet, so Large has Small's 255 slots, nested Fixed queues (targets, emblems, record), Fixed<Opt,64> decision options and engine-local temporaries. Those still stall in Large; filed by-cbf.5 to lift them. The 'more than 64 stack entries' example was replaced by cast permissions (8), which a scenario reaches with real cards.
