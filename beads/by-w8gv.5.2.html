Description

Milestone 3 of Project 50k: a kernel crate owns the game state (plan K6). This bead creates the crate, moves the state into it and writes down the API design that every other M3 bead builds on. It moves code and widens or narrows visibility. It changes no behavior and converts no call site to a new API.

Read first

docs/project-50k.md: Decisions K6, K7, K11, K12; Target architecture: "Crates" (beryl_card is the bottom crate and beryl_kernel depends on it; M3 moves no vocabulary type), "State", "Kernel rules". docs/engine-architecture.md §4 to §6 and §16 for the state as built. The Mason's notes for this milestone are comments on by-w8gv.5.1 (bd show by-w8gv.5.1); notes 1, 2, 6 and 7 bear on this bead. docs/bugs.md: ten of its entries are one class, "any module can read or write any field".

What moves into rust/crates/beryl_kernel

Move files with git mv so history follows and other tracks' edits rebase onto the new path. From rust/crates/beryl_engine/src:

  • ids.rs (Slot, LargeSlot, SlotId, CardIx; Seat is beryl_card's), bitboard.rs, fixed.rs, rng.rs.
  • layout.rs: Item, Queue, Table, Layout, Small, Large, PerSlot.
  • state.rs (1,018 lines, on the file-length allowlist): split it by struct as it moves so no kernel file is over 800 lines, and delete its allowlist entry.
  • relayout.rs: the trait and the impls for types that move. Impls for types that stay in rules stay with them.
  • zone.rs and chance.rs (the zone-move, draw, shuffle and identity chokepoints), invariants.rs, and the board mutators of setup.rs (place to order_library).
  • The data types State embeds or the chokepoints need: decision.rs's (State::pending holds a Decision), profile.rs's Profile, Stops, StepStops, Limits, Breakpoint and Payment, and event.rs's Event, Reason, Recipient, LossCause, kind, Sink and Work (zone.rs and chance.rs take the Sink for sink.chance and sink.revealed).
  • table.rs (CardTable, GameTable, FaceFacts), which the invariants, State::name and milestone 3's queries read.
  • observation.rs: the hidden-information view over a State, whose determinize rewrites objects.

beryl_engine depends on beryl_kernel and re-exports every moved item at its old path (beryl_engine::state, ::ids, ::bitboard, ::fixed, ::layout, ::rng, ::decision, ::event, ::chance, ::relayout, ::table, ::observation, and lib.rs's root re-exports), so beryl_cards, beryl_scenario, beryl_search, beryl_session, beryl_cli, beryl_bench and beryl_app compile unchanged. The plan: "beryl_engine stays as the facade other crates import until the last caller has moved."

Tangles, with a default for each

The code and the plan's intent win where a default does not fit; say so in a comment on the bead.

  • Layout names rules types. layout.rs:158-162 gives the trait body(&Bodies) and condition(&Conditions), function pointers over EffectCtx. Move those two, with Bodies, Conditions, Body and Condition, onto a rules-side trait in beryl_engine implemented for Small and Large. Their only callers are interpret/mod.rs (resolve) and interpret/scene.rs (Condition::Custom). Layout::clone_state stays.
  • decision.rs and relayout.rs are being edited by the prompts milestone (by-w8gv.11) at the same time. Move decision.rs as one whole-file git mv and change only its use lines and what the compiler forces. The Answers trait takes an Observation, which is why observation.rs moves too; Observation::matches needs filter::Evaluate, so it becomes a rules-side function. Keep the diff to relayout.rs to the split.
  • profile.rs mixes data with logic that reads combat.rs and turn.rs (stops_for, asks_lone, next_stop, can_declare_blockers). The data moves; the logic stays in beryl_engine as functions over it.
  • event.rs (1,062 lines, allowlisted): the types and Sink move. The pipeline stays in beryl_engine: settle, move_one, move_batch, in_order, the replacements, lose_life, gain_life, draw, deal_damage, add_counters, remove_counters, set_tapped, create_tokens. Its raw writes are converted by later beads. If what stays is under 800 lines, delete its allowlist entry.
  • table.rs: FaceFacts holds mana.rs's ManaFace (mana.rs:267), built by ManaFace::of(&Face), which reads only a definition. Move the enum and of with the table.
  • setup.rs: begin_at, begin_before_turn and off_board read trigger.rs. They stay in beryl_engine (an extension trait or free functions) unless they split cleanly.
  • reference.rs stays in beryl_engine. The plan lists it for the kernel, but it recomputes layers and payments with layers.rs, mana.rs, filter.rs and trigger.rs. Say so on the bead for the Mason.
  • Tests. Unit tests inside a moved file move with it. beryl_engine/src/tests stays.
  • Inlining. State's methods are generic over the layout and instantiate in the calling crate, but Slot, CardIx, Rng, SplitMix64, GameTable and FaceFacts are not generic: give their hot accessors #[inline]. The search profile builds with fat LTO, so the gate should not move; run just bench-count before and after (docs/benchmarking.md) and record both counts on the bead.

Transitional visibility

Today State's fields are pub(crate) and every rules module reads and writes them. For this one push they become pub where beryl_engine needs them, with a comment on each struct naming the bead that makes it private: objects (by the by-w8gv.5.3 (objects) bead), zones, battlefield, derived, knowledge and listening (the by-w8gv.5.4 (zones) bead), players, turn and the game-level fields (the by-w8gv.5.7 (players and turn) bead), the stack and the queues (the by-w8gv.5.8 (stack and pending) bead). object_mut and player_mut become pub the same way. Add no accessor the move does not force.

The API contract

Write it as the rustdoc of beryl_kernel/src/lib.rs, about a screen of prose and a table, in the present tense ("only the kernel writes a field"). Later beads implement it and amend it. Settle:

a. Mutators. One per thing the rules do to the state. What each must leave consistent: zone bitboards and ordered lists, the battlefield queue and each object's index into it, flags.derived_dirty, attachment and link back-references, both players' knowledge, incarnations. #[inline], generic over the layout. b. Events. Today a primitive in event.rs writes a field and then calls settle (layer refresh, trigger matching, the sink). Decide whether a mutator returns or pushes the Event it causes, so no visible change can happen without one, or stays silent with event.rs as its one caller. The presentation track will later want each event to carry its cause (plan K23). Record the reason. c. Entities and records. Object, Player, Turn, Zones and State get private fields and #[inline] getters. Decide which of the records rules code builds and the kernel stores (StackEntry, PendingTrigger, Target, TriggerInfo, Lki, Derived, Casting and Pending's other payloads) stay plain data handed to a mutator. d. The board door. setup.rs's public mutators (and renumber_deck_slots and reverse_deck_slots, which beryl_scenario's permuted-slot runs use) build positions for beryl_scenario/src/setup.rs, beryl_session/src/checkpoint.rs, beryl_cli/src/blunders.rs, beryl_search/tests/greedy.rs, beryl_cards/src/tests.rs and beryl_engine's tests, and bypass events by design. Put them behind one named door (for example a Board handle borrowed from the state) that rules code and card bodies cannot reach by accident. Callers change in the by-w8gv.5.3 (objects) bead, not here. e. The legacy accessor. Milestone 4 (by-w8gv.7.1) deletes Player::sorceries_as_flash; CastPermission's extra, exile and flashback fields; State::entered_x; the ObjectFlags KICKED, OFFSPRING, IMPENDING, EVOKED, EXILED_UNTIL, EXILED_WITH and LOYALTY_ACTIVATED; and Counters' long-tail kind (other_kind, other). It also replaces the effects and permissions queues with stores, whose payload will be a resolved form of Modification (Mason note 7). All of these get no typed mutator: name the one accessor that reaches them raw, marked as deleted by milestone 4. f. Sets and orders. Outside the kernel a set of objects offers only order-free operations. Name the orders a caller can ask for: battlefield order, a library top first, a graveyard's order, players in turn order (CR 101.4), event.rs's in_order, and the option order of a Decision's candidates (ascending slot: not a rules order, but saves and rollouts_never_change depend on it). g. Queries. Names and signatures for the card behind an object (none for a token), mana value, copiable values, controller, power and toughness. h. Players. How rules code will reach players without the two-player shortcut: opponents of a player, players in turn order, defending players.

Not this bead

Converting call sites, privacy for any field, new index types, capacities. Do not move a vocabulary type out of beryl_card.

Acceptance criteria

rust/crates/beryl_kernel exists, depends only on beryl_card and has no file over 800 lines and no file-length allowlist entry; State, its layouts, ids, bitboards, Fixed, the zone-move and chance chokepoints, the board-setup mutators, invariants and the event and decision types State needs are defined there; the Layout trait names no rules type; beryl_engine re-exports the moved items at their old paths and no other crate's source changed except for that; beryl_kernel/src/lib.rs documents the API contract (sections a to h of the description); state.rs is off the file-length allowlist and event.rs is too if its rules half is under 800 lines; just bench-count before and after is recorded on the bead; parity holds.

Decisions and deviations (code read at staging 980e457c):

  1. Counts, just bench-count (rollout_counts::cube_rollout, bar 405,276,238): rollouts 404,574,527 before, 404,479,535 after (-0.02%); next_apply 376,493,444 before, 376,587,442 after (+0.02%); policy 1,764,069 -> 1,758,539; copy 15,373 -> 15,119. The count build is the bench profile, which is thin LTO, not the fat-LTO search profile the bead assumed, so the crate boundary does move inlining: with no new #[inline] the move cost +3.2% (417.6M), nearly all of it GameTable::facts. With #[inline] on the non-generic accessors it was +0.31%; the rest was FaceFacts::of, facts' rare path, now inlined into every scan, so it is #[inline(never)] with a comment. Inlining has_other_ability and ManaFace::of costs +1.6%: leave them out of line. Later M3 beads should count after every push: one accessor can move the gate 3%.
  2. Layout names no rules type through a type family, not a rules-side trait. A trait in beryl_engine implemented for Small and Large would need L: RulesLayout on every generic function down from next/apply, and 49 files outside the engine write L: Layout (393 times).
