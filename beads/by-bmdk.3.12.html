Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Select', and the appendix table 'Selection and viewing'.

How interface beads in this milestone fit together: ui/src/table/client.ts (bead "Table screen") is the manual table's pointer client. It owns the selection, sends actions with tableAct from ui/src/ipc.ts, and lets each interaction register handlers from its own file. Put your code in the file this bead names and register it; change client.ts only to add a registration point it lacks. Check your work on a live manual table in a headless browser: ui/scripts/table.mjs (same bead) starts one through the HTTP server and gives a Playwright page. Add one scripted check per behavior to ui/scripts/kept-table-<topic>.mjs and run it with just ui-test <title>.

File: ui/src/table/select.ts and Selection.tsx.

  • Cmd-click (Ctrl elsewhere; keys.meta from the pointer) toggles a card in the selection.
  • sweep from the pointer draws a rectangle on the stage and selects every card it touches; draw the rectangle with the stage's overlay layer (ui/src/stage/overlay.ts).
  • Cmd+A selects every card in the zone under the pointer; Cmd+Shift+X the row under it; Cmd+Shift+C the column, in a viewer.
  • Clicking a selected card acts on the whole selection: if any selected permanent is untapped, all are tapped; otherwise all are untapped. One action, one log line.
  • A selected card wears the existing selected mark (gold outline).
  • A small summary sits by a selection of permanents: count, total power, total toughness.
  • Escape closes whatever is open on top (command list, menu, prompt, viewer) and, when nothing is open, clears the selection. Keep one ordered list of "open things" in client.ts so later beads push onto it.
  • A selection survives an update if its cards still exist; cards that changed zone drop out.

Checks (kept-table-select.mjs): Cmd-click two lands then click one taps both; a rectangle over four lands selects four; Escape order; the summary's numbers. Add a fixture state with a selection for the generic audits (extend the manual fixtures: ui/fixtures.json, bead "Manual-table fixtures", or a kept moment if fixtures cannot carry interface state; say which on the bead). data/ui-conventions.json: no-equivalent, "Selection rectangle".

Acceptance criteria

Cmd-click, rectangle, Cmd+A, row and column selection, act-on-selection, the summary and the Escape order work with a headless check each; a selection state is covered by the generic audits.

Handoff: TableClient.selection contains viewer-local stage names. Drag and arrow handlers can test membership and resolve each name against the current view with TableClient.card. Selected cards survive updates while their action zone and stage name survive. TableClient.pushOpen registers Escape callbacks in opening order and returns an unregister function. The viewer uses it now. The command dispatcher can reuse selectAt for the three selection commands. Desktop select all and select row use the hovered card to choose the player's battlefield side. The selected board runs the generic audits in the live kept check because its selection is local UI state. No local Arena recordings were available, so the design and existing gold selected mark supplied the visuals. Nine selection checks, nine click checks, and the fast checks passed.
