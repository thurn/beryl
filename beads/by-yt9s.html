Build the Beryl 3D dependency probe on Windows and ask wgpu for an adapter

Description

Beryl 3D (docs/beryl-3d.md) plans to link wgpu 30.0.2, winit 0.30.13, taffy 0.15.1, parley 0.13.0, glam, bytemuck, pollster, image (jpeg, png), ctt 0.6.1 (default features off; encoder-astcenc, encoder-etcpak, encoder-bc7f), postcard 1.1.3, swash 0.2.10, tiny-skia 0.12.0, rodio 0.23.0 (default features off; playback, mp4) and beryl_session. Bead by-q44s.1.15 built all of them for macOS, iOS, the iOS Simulator and Android, but could not build them for x86_64-pc-windows-msvc from the Mac: ctt's three C++ encoders and zstd-sys need MSVC's cl.exe and lib.exe. This bead needs a Windows machine with the MSVC build tools, which is why it is pinned to Cygnus.

Steps, on Cygnus in an Enact worktree:

  1. Recreate the probe crate from the comment on by-q44s.1.15 that starts 'Probe source': rust/beryl3d/crates/beryl_probe/Cargo.toml and src/main.rs. The workspace picks it up through members = ["crates/*"].
  2. In rust/beryl3d, run: cargo build --release -p beryl_probe --target x86_64-pc-windows-msvc, with CARGO_PROFILE_RELEASE_STRIP=symbols. Record whether it builds, every change it needed and the size of target/x86_64-pc-windows-msvc/release/beryl_probe.exe. Then, as by-q44s.1.15 did for the other targets, record the size each dependency adds: build once with --no-default-features --features wgpu,winit,taffy,parley,glam,bytemuck,image,ctt,postcard,swash,tiny-skia,rodio (everything but the session), then once more with each one of those left out.
  3. Run the probe as Cygnus's CI user (the account that runs enact ci), the way slow CI runs tests. Its first output line is 'adapter: <name> (<backend>)' or 'adapter: none'. This says whether that user gets a wgpu adapter with no surface. Also run it with WGPU_BACKEND=dx12 and then gl, and record each line.
  4. If the CI user gets no adapter: Beryl 3D's renderer tests must be left out of that machine's sweep by name in tools/src/beryl_tools/beryl3d, as WINDOWS_SKIPS in tools/src/beryl_tools/checks.py does for the main lanes. They must never be skipped silently at run time. Add that skip list, with a test, in this bead (it may be empty of names until beryl_render has tests, but the mechanism and its comment must exist).
  5. Delete the probe crate, and revert any change to rust/beryl3d/Cargo.lock that only the probe caused. Commit nothing of the probe.

Record the results in a comment on this bead and in a comment on epic by-q44s.1, and correct docs/beryl-3d.md ('Platforms and versions', 'Card faces') if Windows needs something it does not say.

Acceptance criteria

A comment on this bead and on by-q44s.1 gives: whether the probe builds for x86_64-pc-windows-msvc and what it needed; the stripped binary's size and the size each dependency adds; the adapter line for Cygnus's CI user with default, dx12 and gl backends. If there is no adapter, a named skip list for Beryl 3D's renderer tests on Windows exists in tools/src/beryl_tools/beryl3d with a test. The probe crate is not in the repository.
