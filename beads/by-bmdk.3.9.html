Landed deck import, profile storage, card and token search, and the named-frame regression check on staging.

Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Cards and decks'. Epic 'Contracts' (App commands) and Rules, 6.

Expose milestone 1's deck import and store search to the interface.

  • deck_import { text?: string, cod?: string, name: string } parses with beryl_table::deck::parse_text or parse_cod, saves it under <profile data dir>/decks/ (beryl_app/src/profile.rs::data_dir), and returns { name, main, side, unknown: string[], skipped: string[] }.
  • deck_list returns saved decks with counts. deck_delete { name }.
  • Opening a file: the desktop app has tauri-plugin-dialog; add deck_open_file that shows the open dialog for .txt, .dec and .cod, reads the file and returns its text and kind. On the phone apps it returns "unavailable" and the interface offers paste only.
  • card_search { text, tokens: bool, limit } returns the records' name, type line, mana cost, power and toughness and image address, from Store::search or search_tokens. card_tokens { name } returns facts::tokens_made for a card.
  • A card name the store lacks must still draw: check how the interface gets a card's image and frame from a name (ui/src/cards.ts, ui/src/cardRecords.ts, beryl_session/src/card_records.rs) and make an unknown name produce a plain frame with its name instead of an error. Add a test.
  • Put the handlers in a new rust/crates/beryl_app/src/decks.rs, the request and reply types in rust/crates/beryl_table_session/src/ipc.rs if the crate exists when you start, otherwise in beryl_session/src/ipc.rs; routes in beryl_cli/src/serve.rs; wrappers in ui/src/ipc.ts.

Tests: handlers as pure functions over a temporary directory; the unknown-name frame. Run just test-rust -p beryl_app -p beryl_cli and cd ui && npm run typecheck && npm test.

Acceptance criteria

deck_import, deck_list, deck_delete, deck_open_file, card_search and card_tokens work through Tauri, the HTTP server and ipc.ts; decks are stored per profile; an unknown card name draws as a plain named frame.

Card records accept differently cased names and the stage has a regression check for the plain frame shown for an unknown name.
