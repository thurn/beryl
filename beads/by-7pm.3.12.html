Close reason

Verified phone safe areas and keyboard behavior, fixed Android Back and native smoke startup, and passed fast checks and both smokes.

Description

Check and fix what only shows in a real WebView. Every UI check so far ran in headless desktop browsers at phone sizes, which have no notch, no home bar, no on-screen keyboard, no rubber-band scrolling and no rotation.

Depends on the UI beads (by-7pm.3.2, 3.4, 3.6) so that every phone screen exists, and on by-7pm.3.7 so that one session at a time drives the simulator and the emulator.

Tools

  • iOS: just ios builds and launches in the "Beryl iPhone" simulator. Drive it with the iOS Simulator tool (screenshot, tap, swipe, touch_path, text, set_keyboard, rotate, set_appearance). Coordinates are device points.
  • Android: just android. adb -s emulator-5584 shell input tap|swipe|text|keyevent, adb -s emulator-5584 exec-out screencap -p > <file>, and the WebView's DevTools through adb forward.
  • Never the user's phone (D2).

Where the code is

  • ui/index.html: the viewport meta tag (viewport-fit=cover).
  • ui/src/mobile/phone.css: body.phone (no scroll, no zoom, no selection, no callout), .phone-board (fixed, from env(safe-area-inset-top), padded by env(safe-area-inset-bottom)). ui/src/mobile/chrome.tsx: useViewport reads that padding as insetBottom.
  • The screens by-7pm.3.1, 3.2 and 3.6 built, and the sheets in ui/src/stage/PhoneChrome.tsx.
  • rust/crates/beryl_app/gen/apple/beryl_app_iOS/Info.plist (UISupportedInterfaceOrientations; the iPad list also allows upside down), gen/apple/beryl_app.xcodeproj/project.pbxproj (TARGETED_DEVICE_FAMILY = "1,2"), gen/android/app/src/main/AndroidManifest.xml (android:screenOrientation="portrait"), rust/crates/beryl_app/tauri.conf.json.

Checklist: on each platform, look, screenshot, fix, look again

For each line write "ok" or what you fixed, per platform, in a comment on this bead.

  1. Safe areas. On the start screen, the opening, the game screen, each sheet (menu, log, a graveyard), game over and each stage of the bug reporter: nothing lies under the notch or status bar, and no button lies under the home bar. The hand may run under the home bar; its cards must still be readable above it. Use a simulator with a notch or island (the "Beryl iPhone" device) and an emulator with gesture navigation.
  2. No page scroll, bounce, pinch or double-tap zoom on any screen: swipe up and down hard on the board, pinch with touch2_path, double-tap a card. The page must not move or zoom. A sheet's own list scrolls (the log, a long graveyard) and nothing behind it does.
  3. No text selection, callout or magnifier on a long press of a card, a button or a label. The seed box and the bug report's text box do select and take a paste.
  4. Keyboard. Focusing the seed box and the bug report's text box does not zoom the page (both are 16px) and does not push the layout off screen; the focused box stays visible above the keyboard; dismissing the keyboard restores the layout exactly (screenshot before and after). The seed box brings up a numeric keyboard. A number prompt (fixture shape-number, or any X spell in a live game) and a catalog prompt with a text entry, if one has a text box on a phone, behave likewise.
  5. Touch. A touch on a card answers the first time, with no 300 ms delay and no ghost second click (a touch that opens a sheet must not also press what appears under the finger). Carrying a card out of the hand follows the finger, and releasing it over the table plays it; releasing it over the hand puts it back. A touch dragged off a button and released does not press it.
  6. Rotation. Rotating the device (rotate; adb shell settings put system user_rotation 1 with auto-rotate off) leaves the app in portrait on both. The app is for phones: set TARGETED_DEVICE_FAMILY = 1 so that an iPad runs it as an iPhone app, and remove the iPad orientation list. If Tauri regenerates gen/apple from tauri.conf.json or a project file, make the change at its source, so that just ios-smoke does not undo it: check by running it and looking at git status.
  7. Dark and light system appearance (set_appearance; adb shell cmd uimode night yes|no): the app looks the same in both, with no white flash at launch and no light system bars over the dark table. Set the launch screen and the WebView's background to the table's color if either flashes.
  8. Back on Android. The system back gesture (adb shell input keyevent KEYCODE_BACK) closes an open sheet or the bug reporter; with nothing open on the game screen it does nothing; it never kills a game in progress. On the start screen it may leave the app.
  9. Sound. Game sounds play after the first touch (WebViews block audio before one), the menu's volume sliders work by touch, and the app goes silent in the background.
  10. Relaunch. Killing and relaunching lands on a working screen in portrait, with the safe areas right on the first frame.

Verify

  1. A fix that a headless shot can hold gets one (a phone shot in ui/shots.json at both sizes). A fix that only a device shows is described in the comment with what you looked at.
  2. cd ui && npm run typecheck && npm test; just ui-shots for the phone shots your changes touch; just ios-smoke; just android-smoke; uv run --quiet --project tools by mobile-check; just check.
  3. Commit no screenshots (AGENTS.md).

Delivery

Read the epic by-7pm first: its "What changed since M1", decisions D1 to D9, engineering defaults and code map apply to this bead. Work in a worktree (enact worktree create <short-name> from the main checkout), commit with a Conventional Commits subject of at most 60 characters, and enact push. Record every choice the text above leaves open, and every step you could not do as written, as a comment on this bead. Nothing waits on the user (D9).

Acceptance criteria

A comment on the bead answers each of the ten checklist lines for the iOS Simulator and the Android emulator with 'ok' or the fix made; the app is iPhone-only and portrait-only on both and stays so after a rebuild; nothing lies under the notch or the home bar on any phone screen; no page scroll, zoom, selection or callout; text boxes stay visible above the keyboard without zooming; Android's back closes a sheet and never ends a game; typecheck, npm test, the smokes, by mobile-check and just check pass.
