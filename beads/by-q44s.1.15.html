Close reason

Probe built for macOS, iOS, iOS Simulator and Android (API 26 with rodio, 24 without); ctt without ISPC encoders; sizes recorded; Windows and adapter in by-yt9s

Description

Read first: docs/beryl-3d.md 'Migration and compatibility' ('Platforms and versions') and 'Card faces' ('Preparation': the three crates). Read tools/src/beryl_tools/mobile.py and android.py for the phone toolchains this machine already has (just mobile-setup).

Find out now whether anything in the dependency tree stops a platform, before the beads that use each dependency are written.

Make a throwaway crate in the workspace, beryl_probe, that depends on everything the design plans to link and touches each from main: beryl_session, wgpu 30.0.2, winit 0.30.13, taffy 0.15.1, parley 0.13.0, glam, bytemuck, pollster, image (jpeg and png), ctt 0.6.1, postcard 1.1.3, and the current releases of swash, tiny-skia and rodio (with the symphonia features that decode AAC in an M4A file). Build it for:

  • aarch64-apple-darwin, aarch64-apple-ios and aarch64-apple-ios-sim;
  • aarch64-linux-android, with cargo-ndk;
  • x86_64-pc-windows-msvc, on Cygnus through its CI, or with cargo check --target if the toolchain is here;
  • aarch64-unknown-linux-gnu in beryl3d-bench, if the spike bead has made it by then. If it has not, say so, and leave a note on that bead to build the probe there.

Also find out, with a ten-line program that asks wgpu for an adapter with no surface, whether Cygnus's CI user gets one. Where there is none, the renderer's tests are left out of that machine's sweep by name in the tools package, as WINDOWS_SKIPS does for the main lanes. They are never skipped silently at run time.

For each target, record on this bead: whether it builds, what had to change, and the size each dependency adds to a stripped release binary. Record the exact releases of swash, tiny-skia and rodio you built: later beads pin those.

If ctt does not build for a phone target, choose its replacement by this rule and record it in a comment on the epic, where the card faces bead reads it: first ctt with only the features that need no C++ or ISPC compiler; failing that, a pure-Rust ETC2 encoder for Android and a pure-Rust ASTC encoder for iOS, named with their releases.

Delete beryl_probe before closing.

Run: the cargo commands you used, listed in this bead's closing comment.

Acceptance criteria

A comment lists each target with its result, the changes needed and the binary sizes; the texture encoder to use on each platform is named in a comment on the epic; the releases of swash, tiny-skia and rodio are recorded; whether Cygnus gives a GPU adapter is recorded; beryl_probe is gone.

Results of the dependency probe (beryl_probe, deleted; its source is in the comment on this bead that starts 'Probe source').

Releases built, which later beads pin: swash 0.2.10, tiny-skia 0.12.0, rodio 0.23.0 (default features off; playback, mp4, which pulls symphonia 0.5.5 with its isomp4 and aac features, and cpal 0.18.2). Also ctt 0.6.1 (default features off; encoder-astcenc, encoder-etcpak, encoder-bc7f), postcard 1.1.3 (default features off; alloc), wgpu 30.0.2, winit 0.30.13, taffy 0.15.1, parley 0.13.0, glam 0.34.3, bytemuck 1.25.2, pollster 1.0.1, image 0.25.10. winit pulls a second tiny-skia, 0.11.4, through sctk-adwaita, on Linux only.

Each target:

  • aarch64-apple-darwin: builds. Stripped release binary 37.5 MB. At run time wgpu gets 'Apple M5 Max (Metal)', the session starts a game, an M4A from ui/public/audio decodes, and ctt encodes a 256x360 face to ASTC 4x4 in 1.6 ms, ETC2 RGBA in 0.5 ms and BC7 in 25 ms.
  • aarch64-apple-ios: builds with IPHONEOS_DEPLOYMENT_TARGET=15.0. 37.0 MB.
  • aarch64-apple-ios-sim: builds. 37.2 MB.
  • aarch64-linux-android (NDK 28.2.13676358, with CC/CXX/AR/linker set to the NDK's clang, as cargo-ndk would set them; cargo-ndk is not installed here): builds, but links only against the API 26 sysroot. cpal's Android backend is AAudio and ndk-sys links libaaudio.so, which the API 24 sysroot lacks, so a binary with rodio's playback cannot load on API 24 or 25. Without rodio it links at API 24 and needs only libc++_shared.so, libandroid, libdl, libm and libc. The APK must bundle libc++_shared.so (ctt's C++ encoders need it). 38.3 MB.
  • x86_64-pc-windows-msvc: NOT built. cargo check --target from the Mac fails in the build scripts of ctt's C++ encoders and zstd-sys, which need MSVC's cl.exe and lib.exe. Cygnus's CI shares no logs with this machine, so the Windows build and the adapter question are filed as by-yt9s, pinned to Cygnus, outside the epic (no Cygnus vizier serves by-q44s).
  • aarch64-unknown-linux-gnu in beryl3d-bench: NOT built. The VM does not exist yet (the spike bead by-q44s.1.31 is open); a comment on by-q44s.1.31 asks it to build the probe there.
  • Whether Cygnus's CI user gets a wgpu adapter: NOT answered here; by-yt9s does it.

ctt: the default features fail on every phone target, because encoder-intel and encoder-bc7enc link prebuilt ISPC kernels and ispc-build-utils has none for ios-aarch64 or android-aarch64. Following the bead's rule, ctt with only the encoders that need no ISPC compiler builds on every target: astcenc, etcpak and bc7f. These are C++ that the cc crate compiles with each platform's own clang. I read 'no C++ or ISPC compiler' as 'no compiler beyond the platform's own toolchain', since every ctt encoder is C++ and ctt with none would compress nothing.

Size each dependency adds to a stripped release binary, in bytes. beryl_session's figure is the full probe minus the probe without it.
