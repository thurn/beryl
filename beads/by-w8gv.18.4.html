Description

Move the Python tools that read data/cards.json to the card store's Python reader, so the UI bead can delete the file. Mechanical: each site parses the JSON file and looks cards up by name; replace that with the reader the pipeline bead wrote (its handoff names the module and functions). No behavior changes.

Sites:

  • tools/src/beryl_tools/specs.py: oracle (line 122) and nearest (line 139) read cards.OUTPUT. nearest ranks implemented cards only (implemented(), line 99), so ask the store for those names; never iterate the whole pool.
  • tools/src/beryl_tools/forge.py line 134 (every face name with what a GameState line needs) and its caller oracles.py line 503, which passes the path.
  • tools/src/beryl_tools/xmage.py line 240 (Faces.load) and its caller oracles.py line 553.
  • tools/src/beryl_tools/video_cards.py (its header at line 5 and wherever it loads the file).
  • tools/tests/test_forge.py line 8, and any other test that opens the file (grep tools/ for cards.json and cards.OUTPUT).
  • tools/src/beryl_tools/checks.py near line 539: the comment on CARD_READERS says test_forge reads data/cards.json; make it name the store. If a test that reads the store would be skipped by a lane that a store change runs, add it to the list that lane reads.

Where a tool listed every card in cards.json (forge.py's faces, xmage.py's Faces), it meant the implemented cards and their tokens: take the names from where the tool already gets its cards, or from the store's records for the implemented names. Do not delete data/cards.json or stop cards.py writing it: the UI still imports it until its own bead.

Read first: the pipeline bead's handoff and the reader module. Need not read: the Rust workspace, the UI.
