Android host delivers touches, safe-area insets, Back, rotation and on-demand frame pacing. Vulkan and OpenGL ES smokes passed. Staging ff6d6c3f.

Description

Read first: docs/beryl-3d.md 'Hosts' (the Android host, 'Choosing a frame rate', the C functions, KeyCode::Back) and 'The flat layer' ('Sizes': safe area); include/beryl3d.h and src/ffi/android.rs as the C functions bead (by-q44s.7.3) left them (the JNI names, nextRequest, requestText, the waker); rust/beryl3d/crates/beryl_3d/android (MainActivity.kt, app/build.gradle.kts, AndroidManifest.xml); tools/src/beryl_tools/beryl3d/phone.py (android_apk, start_emulator, run_android_smoke, adb). The web interface's side: ui/src/ipc.ts onAndroidBack and ui/src/App.tsx (the Tauri app turns Android's Back into the beryl:android-back event that ui/src/components/BugReport.tsx closes the form on); ui/src/mobile/report-taps.ts (touches).

Why. The spike's Kotlin host passes a surface and the display's time. This bead makes it pass touches, the system bars' insets, orientation changes and the Back button, carry out the frame rate the library asks for, and stop ticking while the library is idle. The host holds no game or layout logic.

Build, in android/app/src/main/java/ca/thurn/beryl3d (split MainActivity.kt into files under 300 lines if it grows: Native.kt for the JNI declarations, MainActivity.kt, Touches.kt):

  • Touches. The SurfaceView subclass overrides onTouchEvent. Each pointer gets the lowest free id from 1 to 255 on ACTION_DOWN or ACTION_POINTER_DOWN, kept by MotionEvent.getPointerId until ACTION_UP, ACTION_POINTER_UP or ACTION_CANCEL. ACTION_MOVE sends a Move for every pointer in the event. Positions are divided by resources.displayMetrics.density into points. Historical samples are not sent.
  • Insets and orientation. The activity draws edge to edge (window.setDecorFitsSystemWindows(false) on API 30 and above; SYSTEM_UI_FLAG_LAYOUT_STABLE | SYSTEM_UI_FLAG_LAYOUT_HIDE_NAVIGATION | SYSTEM_UI_FLAG_LAYOUT_FULLSCREEN below). setOnApplyWindowInsetsListener on the view reads the system bars and the display cutout (WindowInsets.Type.systemBars() or WindowInsets.Type.displayCutout() on API 30 and above; systemWindowInset* and, on API 28 and above, displayCutout safe insets below) and passes them in points with Native.surface, which gains top, right, bottom, left float arguments (change android.rs's surface to take them; the spike passes zeros). The manifest's activity declares android:configChanges="orientation|screenSize|screenLayout|smallestScreenSize|keyboard|keyboardHidden|navigation|uiMode|density" so rotating changes the surface's size and never recreates the activity or the app.
  • Back. onBackPressed (API 24 to 32) and an OnBackInvokedCallback at PRIORITY_DEFAULT (API 33 and above) send BERYL_KEY_BACK down then up. The host never finishes the activity on Back itself: the client decides what Back does, and Home leaves the app.
  • Frame rate. displayHz for create is the largest refreshRate in display.supportedModes (API 23+). After each frame, when the returned rate (add it to what Native.frame returns: make it return a LongArray(2) of [wake, hzBits] where hzBits is java.lang.Float.floatToIntBits(hz), changing android.rs accordingly) differs from the last applied, call holder.surface.setFrameRate(hz, Surface.FRAME_RATE_COMPATIBILITY_FIXED_SOURCE) on API 30 and above; below 30 do nothing (the library skips ticks itself).
  • Idle. On the wake -1 (never) stop posting the Choreographer callback. On a wake time, post it with postFrameCallbackDelayed for the difference from System.nanoTime(). The waker object passed to create posts to a main-thread Handler that restarts the callback if it is stopped. Any touch, key, inset or surface change restarts it too.
  • Live game or replay. The intent extra fixture replays a recording, as now; without it the app plays a live game. The extra standIn, read only when BuildConfig.DEBUG, is passed as the stand-in.
  • Requests. After every frame, call Native.nextRequest until it returns -1 and pass each to perform(kind, rect, text), a when whose cases this bead leaves empty except a debug log line. The lifecycle bead fills share, haptic and URL; the text entry bead fills the two text cases.

Smoke test: just b3d android-smoke --touch (and with --gles), with --help text and two examples. After the first frame it runs adb shell input tap 100 100, adb shell input swipe 100 300 200 300 500, adb shell input keyevent KEYCODE_BACK, then rotates with adb shell settings put system accelerometer_rotation 0 and adb shell settings put system user_rotation 1 and back to 0, and restores accelerometer_rotation afterwards. adb shell input cannot make two fingers, so ids are checked for one finger here and the id table is read by the Warden. It fails unless the frame log holds Pointer down and up lines for id 1, a Key line Back down and up, two Surface lines whose width and height swap, and a nonzero top inset (the emulator's status bar), and unless the app's process is still running after Back. As on iOS, the frame log's frames in the final 2 seconds of idle must be 0. Add the log-reading checks to tools/tests/test_beryl3d_phone.py.

Not in this bead: suspend and resume, low memory, share, haptics, URLs (the Android lifecycle bead, by-q44s.7.9); text entry; the phone layout.

Run: just b3d android-smoke; just b3d android-smoke --touch; just b3d android-smoke --touch --gles; just test-py tools/tests/test_beryl3d_phone.py.

Acceptance criteria

just b3d android-smoke --touch and just b3d android-smoke --touch --gles pass: touch down/up for id 1, Back down and up with the app still running, two Surface lines with swapped sizes, a nonzero top inset, and no frames in the final 2 s of idle; just test-py tools/tests/test_beryl3d_phone.py passes; the Kotlin files hold no game or layout logic.
