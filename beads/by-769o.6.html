Close reason

by ci-value scores checks by catches per CPU-second with fail-together groups; check_value.cuts for the budget detector (1e0fde5e)

Description

Why

Slow CI should keep the checks that catch the most real bugs per CPU-second. The run log ($BERYL_CACHE/ci/runs.jsonl) has every check's outcome per run, and verdicts.py gives each failure a verdict (catch, stale, flaky, miss). For example verb:appear/theirs/desktop had 9 failures in 241 runs over 30 days and 0 catches: each failure was a stale expected value.

What to change

Add a module (for example tools/src/beryl_tools/check_value.py) and a command (for example by ci-value, with a just recipe) that reports, for every check slow CI ran in the last 30 days: runs, real catches, median CPU seconds (the cpu_seconds field from the bead this depends on), and value = catches per CPU-second. Group checks that always fail together (for example the yours/theirs and phone/desktop variants of one verb), because a group costs the sum of its members but catches only once. Sort lowest value first. Expose a function the budget detector can call to get the cheapest set of checks whose removal brings the median run under a given CPU budget.

Files and tests

tools/src/beryl_tools/verdicts.py (how verdicts are stored and read), tools/src/beryl_tools/runlog.py, the new module, tools/tests/ for the scoring and grouping, justfile, docs/checks.md.

API for by-769o.7: score(records, history, since) -> Scores(groups lowest value first, runs: {(host, commit): {check: cpu_s}}); cuts(scores, budget_cpu_s) -> list[Group] (Group.checks, .catches, .cpu, .estimated, .value(), .json()); median_run(runs, cut). Decisions: only script=ci, non-backfilled pass/fail records. A run is identified by (host, commit), since records carry no run id, so a commit tested twice on one host counts as one run. Cost is the median measured cpu_seconds; checks with none yet are estimated from wall seconds times the lane's CPU-to-wall ratio (flagged estimated; most of the log is estimated today, as cpu_seconds landed 2026-11-13). Groups: identical failure sets with at least GROUP_FAILURES=2 failures, ignoring (run, lane) pairs with more than MASS=20 failures; group catches are distinct commits of catch verdicts. stand_ins() drops a step's own record (lane:step) when its check never passed in the window, or when it is marked whole beside other records (the whole mark landed in by-769o.8). Today: 280 runs, median run 1303 CPU s (mostly estimated); the longthink CLI tests are the costliest zero-catch checks, and repo:file-length has the most catches. A group that has caught a bug may appear in cuts(): by-769o.7 should move those to the nightly instead of deleting them.
