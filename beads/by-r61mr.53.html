Description

The full pytest tools suite on 9ab4cd6c1 had 937 passes and failed test_low_on_disk_it_leaves_a_live_bisection_alone while opening .cargo-lock in the real coverage worktree. Captured output shows the test pruned build artifacts from real worktrees. tools/tests/test_caches.py low_disk_cache patches paths.worktree_names but caches.prune_worktree_targets separately calls paths.worktree_paths, which still enumerates the repository. All 17 cache tests pass when the checkout enumeration points to a disposable Git repository. Scope real worktree discovery to the fixture. The same failure exposed a production race where a target disappears between discovery and acquisition. Treat its disappearance as an already-removed target while preserving the lock against live builds.

Acceptance criteria

An isolated regression simulates a target disappearing after enumeration and verifies pruning continues. Run the cache tests and full Beryl Python tools suite without touching real worktree targets.
