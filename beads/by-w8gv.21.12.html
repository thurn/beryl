Decisions: (1) The session fuzz is a #[cfg(test)] module, rust/crates/beryl_session/src/fuzz.rs, not an integration test: the planted builder fault needs a test-only hook in script/build.rs (thread-local PLANTED, cfg(test)), which an integration test cannot reach. (2) beryl_search's shrink machinery lives in its test files and beryl_search cannot depend on beryl_session, so fuzz.rs follows tests/shrink.rs's pattern (seed + choices by index modulo candidates, proptest shrinking) rather than sharing code. Both seats' choices come from one list: the human answers through Game::answer/choose as a client does, the other seat is a Picks agent reading the same list (Game::prepared). Each update also draws the other seat's view (new pub(crate) Game::opponent_view, which publish_review now uses), so both seats' scripts are checked. (3) Fast check: both fuzz tests are in verdicts.SLOW_ONLY (2.5 s and 2.2 s debug); slow CI plays 3 games plus the planted test. (4) Scale: script cost is the script-check run (by-w8gv.21.11) over the pool's cards, read from its run-log lines; it measures each spec moment played from both seats with every script built and replayed under the checks, i.e. session play included, not the builder alone (isolating the builder would need timing instrumentation in production code). Measured: 582 checks over the 41 clonable cards, mean 0.049 s per card, 50,000 clones = 2,455 s of checks, about 1,219 s at the run's 2.0x parallelism. Release fuzz: 100 session games in 2.7 s.
