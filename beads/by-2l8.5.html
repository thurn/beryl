Close reason

Live panel for just longthink: in-place 4 Hz panel, two-stage Ctrl-C, plain piped output, --status ladder; pty/screen/renderer tests (919b829)

Description

Part of the long-think epic. The terminal interface of just longthink (by-2l8.3): a live panel, redrawn in place, that shows the run as a whole and the game being played now. The run lasts days, so it should read at a glance from across the room, and leave a scrollback history when it exits. Few words: numbers, bars and glyphs over sentences.

Layout

A scrolling log above, a fixed panel below, redrawn in place:

✓ 100k v expert   s16·B  won  T14  6:51
✗ 100k v expert   s17·A  lost T21  9:02
────────────────────────────────────────────────────────────
longthink 3f9a2c   up 6h12m   154 games   ⏸ after this game
       vs         win   95%       games  min/game
3k     expert  ██▌    28%  18–41   60/60    0:21
10k    expert  ████   41%  29–54   60/60    1:05
30k    expert  █████▋ 57%  44–69   60/60    3:12
100k   expert  ███████ 71% 55–83   34/60    7:04  ◀
300k   expert                       0/60
Elo/×3  +62 ±18      last 10  ●●○●●●○●●●
────────────────────────────────────────────────────────────
▶ 100k v expert  s17·B  T9  you 14 · them 9  hand 4 · 3
  decision 64  ████████▍       58,120/100k  3.1s  stop −31%
  prev  Counterspell → Snapcaster Mage
  • Log (permanent, printed above the panel, kept after exit): one line per finished game, ✓/✗/½ in green/red/dim, plus a line when a rung reaches its 60 games or a new rung or opponent opens.
  • Header: run key (short), uptime, games, and the stop state when Ctrl-C was pressed.
  • Ladder: one row per rung and opponent (expert, the rung below, omniscient), with a win-rate bar, the Wilson 95% interval, games of the target, mean minutes a game, and ◀ on the row being played. Unopened rungs dim. Then Elo per tripling and the last 10 results.
  • Now: the game in progress (rung, opponent, seed, the search agent's seat, turn, life, hand sizes) and the search in progress: decision number, a bar of rollouts spent against the budget (from a shared atomic counter the trees bump; relaxed, so it never orders the search), seconds in this decision, and what the exact stop saved this game. prev is the last searched decision's choice, as the transcript names it.

Behavior

  • Redraw at 4 Hz from a render thread reading a snapshot the runner publishes; the search never waits on the terminal. Move up with ESC[nA, clear each line with ESC[2K, hide the cursor while drawing and always restore it on exit.
  • Truncate every line to the terminal width, rechecked each redraw (resizes just work). A terminal too short for the panel drops the ladder rows below the current rung first.
  • Ctrl-C once: finish this game, header shows ⏸. Twice: stop now, losing the game in progress. Either way the cursor is restored and the panel's last frame stays on screen.
  • Not a terminal (piped, > file, CI) or TERM=dumb: no escapes, just the log lines and a ladder table every 10 games. NO_COLOR turns colors off but keeps the in-place panel.
  • just longthink --status prints the header and ladder once, with no Now block.
  • The recipe's supervisor (by-2l8.3) restarts a crashed runner. It ignores SIGINT itself and leaves the terminal to the runner, stopping only when the runner exits because the user asked. A restart or a mid-game resume prints a log line ("↻ resumed s17·B at decision 64") and the panel picks up where it was.

Implementation notes

  • The workspace denies unsafe code, so no libc calls: std's IsTerminal for detection, the ctrlc and terminal_size crates (small, safe APIs) for the two-stage Ctrl-C and the width, and plain ANSI strings for drawing. crossterm would do it all but is far more than this needs.
  • Keep rendering a pure function from (snapshot, width, height, color) to lines, so it is tested without a terminal, and keep the escape-sequence writer tiny.

Acceptance criteria

  • Snapshot tests of the pure renderer: a mid-run frame, a fresh run, a too-narrow (60 col) and a too-short terminal, and no color.
  • Piped output (just longthink | cat) contains no escape sequences and prints the log lines and periodic ladder tables.
  • A screen test: a small ANSI interpreter in the test (cursor up, clear line, carriage return, newline, cursor show/hide) replays a captured run's bytes, and the final screen equals the expected frame with no leftover lines, at two widths.
  • A pty test (Python's stdlib pty, from tools/ tests): just longthink on a 1k smoke ladder; one ^C shows ⏸ and exits after the game, two exit at once; both end by showing the cursor again (ESC[?25h) and leave a resumable run.
  • The search's progress counter costs nothing measurable: the bench-count pins don't move.

Design as built (executor, 84c3a45 before review): • longthink/panel.rs: pure render(Frame, width, height, color) -> lines, ladder() from games+clock, game_line() for the log. Elo/×3 is the weighted least-squares slope of each rung's Elo v the opponent over log3(budget), ±1.96 se (delta-method se per rung). • longthink/term.rs: Screen<W> (ESC[nA, ESC[2K, CR/NL, ?25l/?25h only; also clears the cursor's line so an echoed ^C vanishes); Display: the runner publishes to a Mutex<Board> (brief locks only), a painter thread redraws at 4 Hz and is the only writer in live mode (log lines queue on the board), so a blocked terminal never stalls the search. Ctrl-C via ctrlc: once sets stopping (header ⏸, runner stops after the game, exit 0); twice paints the last frame, shows the cursor, exit 130. Supervisor installs a no-op SIGINT handler and exits 130 when the runner does. Panic hook shows the cursor. Not a tty or TERM=dumb: plain lines + a ladder table every 10 games; NO_COLOR keeps the panel. • beryl_search: a process-wide relaxed AtomicU64 bumped per rollout in Tree::grow (rollouts_run()); the panel shows its difference across the decision. game::play's callbacks now get the position and decision (asking) and the transcript's label (answered); Transcript::decision returns the chosen label. • --status now prints the header and ladder (supersedes by-2l8.3's 'prints summary.txt'; summary.txt is still written/rebuilt). The crash test now checks the ladder and '1 crashed' in the header. Deviation: the pty test is a Rust integration test (tests/longthink_tty.rs) driving tests/pty.py (stdlib pty) on the debug binary's supervisor (the command the recipe execs), not a tools/ pytest through just longthink: the recipe builds the fat-LTO search profile, minutes cold, which no check budget affords, and the python lane would not rebuild beryl_cli. The just path was checked by hand (below). By hand, just longthink (search profile, BERYL_CACHE scratch, 1k rung, 18 trees, expert-frozen), in a 110x40 pty via tests/pty.py: one ^C mid-game -> ⏸ in the header, game finished and logged, exit after it, output ends ESC[?25h; two ^C -> exit 130 at once, game 2 left at decision 11 in its log; rerun -> '↻ resumed 1k v expert-frozen s0·B at decision 11', finished. --status prints header+ladder; just longthink --games 3 | cat -> plain lines, no escapes. Note: just itself prints 'error: Interrupted by SIGINT' (exit 130) after any ^C, even when the runner exits 0: it sits in the terminal's foreground group; only taking the terminal's process group (tcsetpgrp) would avoid it, not worth it. bench-count (rollout_counts) with and without the counter (base 7715c6d's beryl_search swapped in): all four 'No change'; rollouts 489,390,210 instructions. The bench calls rollout() directly, so the counter is outside it by construction; it adds one relaxed add per ~0.6 ms rollout in real searches.
