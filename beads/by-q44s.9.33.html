Beryl 3D bug reports record the build commit

Description

Symptom: a bug report saved from Beryl 3D (Cmd+B in the beryl3d app) carries commit: unknown in its fields, so just b3d bug <report> prints 'built from unknown' and a worker cannot tell which commit the report came from.

Why: the web app's shell calls beryl_session::bugs::set_build_commit(env!("BERYL_COMMIT")) (rust/crates/beryl_app/src/lib.rs:273), with BERYL_COMMIT set by rust/crates/beryl_app/build.rs. The beryl3d binary (rust/beryl3d/crates/beryl_3d, which has its own build.rs) never calls it.

Do: set BERYL_COMMIT in rust/beryl3d/crates/beryl_3d/build.rs as beryl_app's build.rs does, and call set_build_commit at the app's start (src/app.rs or main). Weigh the cost: beryl_app's rerun-if-changed on HEAD relinks the crate on every commit; keep the env var confined to the binary crate so the scene and inspect crates do not rebuild. Extend rust/beryl3d/crates/beryl_3d/tests/all/bugs.rs to check the report's commit is not 'unknown'. Run just b3d cargo-test and just test-py tests/test_beryl3d_bug.py.
