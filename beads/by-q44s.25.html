Close reason

Spec stand-in kept a second identical trigger off the stack; Follow::play now holds the replay check; every recording replays

Description

Symptom: in the Beryl 3D recording currency-converter/exiles-thirst-for-discoverys-discards-no-3, seen from the viewer's seat (you), one script played over the protocol table of the view before it (beryl_protocol::script::Table::of, then Table::apply for each step) does not give the table of the view it came with. The replayed stack holds two identical Currency Converter triggers (ability 0, source #11, nth 0); the view's table holds one. Found while working by-q44s.22: Beryl 3D now keeps the table a script ends on for the next script only when Table::is_of(view) holds, so this recording just falls back to building the table again, and no test fails. Nothing else checks it today: replay::failure is meant to run wherever the session builds a script in a debug build, so either that check does not run on this path (the recording builder, rust/beryl3d/crates/beryl_record, or the seat that is not acting) or the view's stack and the resolving item (DecisionView::resolving, see Table::named) disagree about a second trigger of one ability. Reproduce: in beryl_scene's play/compile.rs, temporarily assert played.is_of(after) in carry() and run just b3d test b3d:currency-converter/exiles-thirst-for-discoverys-discards-no-3/you; replay::difference names the stack.

Acceptance criteria

The script replays to its view's table (replay::failure is None) for every recording from both seats, checked by a test that walks every recording's scripts through beryl_protocol::script::replay::check; the Currency Converter case is fixed in the session's script builder or the table's stack rule, not by loosening the check.

Handoff: The bead's guess (session builder or Table stack rule) was off. The views were made wrong by the spec harness, rust/crates/beryl_cli/src/specs/start.rs: when a stand-in answers the viewer's decision, it turns the view into Status::Playing and pushes decision.resolving back onto view.stack, but only if !stack.contains(resolving). A second trigger of the same ability compares equal, so it was dropped. Now it always pushes, matching Table::of. The session's own debug verify never saw this because the rewrite happens after the session builds the script. Guard: Follow::play (rust/crates/beryl_session/src/script/follow.rs) now also runs replay::check against Table::of(view), so beryl_cli script-check and spec traces fail on this class (confirmed: 4 currency-converter moments fail without the fix; 1914/1914 pass with it). New test rust/beryl3d/crates/beryl_inspect/tests/all/replay.rs walks every recording (fixtures, spec moments, stress, screens) from both seats through replay::check (~5 s). Also examined and left as is: session Moment::Playing drops a paused resolving entry in game/views.rs, but no recording reaches that state. Commit 1aaa147d5.
