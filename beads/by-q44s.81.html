Close reason

python lane runs only Beryl 3D tool tests for confined changes

Description

Symptom: a push that changed only Beryl 3D's code and its tools (tools/src/beryl_tools/beryl3d/) ran the main python lane: black, pyre and all of pytest, including tests such as test_bisect.py (33 s) and test_checks.py (28 s) that have nothing to do with Beryl 3D. In milestone 2 that cost 1,628 s of lane time over 6 pushes. docs/checks.md 'Beryl 3D' says this is by design, but it goes against C17's aim that Beryl 3D's changes run only Beryl 3D's checks.

Proposed change: in fast_lanes (tools/src/beryl_tools/checks.py), when every non-Beryl-3D path in a change is under tools/src/beryl_tools/beryl3d/ or tools/tests/test_beryl3d_*.py, run the python lane with only tools/tests/test_beryl3d_*.py, plus black and pyre on the changed files. Update docs/checks.md to match.

Files: tools/src/beryl_tools/checks.py (fast_lanes, python_lane), tools/src/beryl_tools/python_tests.py (pytest_step), tools/src/beryl_tools/beryl3d/paths.py, docs/checks.md.

Acceptance criteria

A change confined to Beryl 3D's paths and its tools runs only the Beryl 3D tool tests in the python lane, with a test in tools/tests/test_checks.py.
