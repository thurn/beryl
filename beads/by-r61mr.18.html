Description

Read the epic by-r61mr first: it holds the decisions, the code map and the directory layout this bead assumes. The work is in the Enact repository (~/enact) unless this bead says otherwise, delivered with that repository's own enact worktree create and enact push.

Give scripts/enact.py a second backend. A key in .enact.toml (default: beads) selects it, and the server's cutover state can force it, so the whole fleet switches at once.

With the server backend, class Beads (line 403) and its callers run tk instead of bd: claim (1242), cmd_start (1275), cmd_close (1307), cmd_meta, cmd_brief, cmd_pool, cmd_run, cmd_next and next_step (2410, 2426) and cmd_wait (2460). next, start and close each make one compound request. next --wait and ci --wait wait on the WebSocket through tk, not by polling. With the server backend the helper takes no ownership lock (ownership_lock, 751) and runs no sync (924); cmd_sync becomes a no-op that says so.

The beads backend must keep working unchanged until the cleanup bead deletes it. Run tests/test_unit.py and tests/test_integration.py for both backends, the server one against wrangler's local simulator.

Acceptance criteria

Both test files pass for both backends. A test asserts that next, start and close each make exactly one server request and that no ownership lock file is created with the server backend. Timings of enact next on both backends are recorded in the bead.

Notes

Build this against the contract with a stand-in for tk generated from server/contract/api.json, so it can start as soon as the contract lands, in parallel with the real CLI and server. The Warden bead for this area runs it against the real ones. The contract replaced compound endpoints with GET /graph plus one POST /batch carrying preconditions (section 3). Keep schedule and next_step in Python over the graph, cache the graph on disk and revalidate it with its ETag, and make each reservation, start and close one batch. Test against scripts/tk_stub.py from the contract-files bead. The acceptance's 'exactly one server request' reads: at most two requests for next, start and close, three for a lane continuation.
