Description

Why

A witness (rust/crates/beryl_cards/src/derive/witness.rs) is a position fragment under which a field's value changes the outcome: REGENERATION_SHIELD lets a scenario tell "destroy" from "destroy, it can't be regenerated". There are seven, picked by hand, and nothing proves one exists for each neighbour the mutation check can make. A generated position also has no board partner for a card whose filter names a quality: Lord of Atlantis needs another Merfolk, an Aura needs something to enchant. Plan: Designs E3, "Witnesses from neighbours" and "Partners by filter".

What to build

  • For every kind of neighbour tests/mutation/neighbours.rs makes (after the bead that widens it, a dependency), a witness or a stimulus under which the card and the mutant differ in the snapshot. A test walks the neighbour kinds in an exhaustive match and names the witness for each, so a new kind without one does not compile.
  • Partners by filter (position.rs, start): where a card's Filter names a quality (a creature type, a card type, a color, flying, tapped, a mana value bound, "you control" or "an opponent controls"), the position holds one object with it and one without, on the side the filter names. Use a Prop:: where its contract promises the quality (beryl_card_shared/src/props.rs); otherwise the simplest implemented card with it, found from the CardTable; otherwise report the card as needing a prop and add the prop (a keyword-only creature complete from the store is preferred).
  • EQUIVALENT (8 entries in tests/mutation.rs) may only shrink: remove each entry a witness now kills.

Report, for the 121 cards, how many have every mutant killed by generated scenarios alone (change scenarios_of to derive::all() for the measurement, as the test damn_that_allows_regeneration_is_killed_by_its_generated_scenarios does for one card).

  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
