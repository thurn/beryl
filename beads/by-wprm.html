Slow CI over CPU budget: moved the 4 named rust tests to FAST_ONLY (fast check still runs them) in b8e33966

Description

Slow CI on JARVIS is over its CPU budget: a full run (each check's median CPU seconds, summed over the checks of each lane's last 10 runs) uses 829 CPU seconds, and the budget is 800 (SLOW_CPU_BUDGET, tools/src/beryl_tools/budget.py). just ci-value scores every check by the real bugs it caught in the last 30 days per CPU-second, and these are the lowest-value checks of the rust lane among those whose removal brings a full run under the budget, about 37 CPU seconds a run:

  • delete: rust:beryl_session::undo::passing_on_goes_past_the_stops_in_its_step: 301 runs, 0 catches, 9.85 CPU s a run
  • delete: rust:beryl_bench::rollout::tests::rollouts_never_change: 300 runs, 0 catches, 9.44 CPU s a run
  • delete: rust:beryl_cli::bin/beryl_cli::why::tests::tree_report_counts_the_ordinary_search_visits: 83 runs, 0 catches, 9.21 CPU s a run
  • delete: rust:beryl_cards::tests::derive::every_ability_of_a_generated_card_is_exercised_by_its_generated_scenarios: 100 runs, 0 catches, 8.99 CPU s a run

For each check, first ask: could a fast, deterministic test (a Rust unit test, a Node test with no browser, a check against a recorded fixture) keep most of what this end-to-end check protects? If so, write that test, then delete the check. If not, delete it when it caught nothing (delete above), or move it to the nightly (a step in nightly.STEPS, tools/src/beryl_tools/nightly.py) when it caught something (move to the nightly above). Either way the check leaves slow CI: when the fast check (by check) runs it too, keep it there and take it out of slow CI alone. Checks listed together failed in the same runs and go together. Make the cuts without asking anyone, and record on this bead what you did with each check and why. The cifix skill (.agents/skills/cifix/SKILL.md) says how to work this bead.

No cut bead names these checks, which guard something no other check does:

  • app:smoke: the desktop app builds and starts at all
  • ui-test:Enter on the start screen starts a game: the browser UI starts a game
  • ui-test:a land pressed while a script plays on to it is played: the browser UI plays a step of a game
  • rust:clippy: the whole workspace builds and passes clippy
  • ui:tsc: the UI type-checks in strict mode
  • names:*: the repository rules AGENTS.md names, a few CPU seconds in all

Acceptance criteria

Every check listed no longer runs in slow CI: deleted, replaced by a fast deterministic test, or moved to the nightly; this bead records which for each and why.

All four checks moved to verdicts.FAST_ONLY (tools/src/beryl_tools/slow_only.py) in b8e33966, not deleted. Why: each is an ordinary workspace test that the fast check already runs whenever its package changes, and the bead says a check the fast check also runs stays there and leaves slow CI alone. Each one guards something no other test checks: the undo/pass-on walk; the rollout pin, which lets a running search switch to a faster binary; the why tree report's visit counts; and coverage of every generated card ability by its scenarios. Slow CI saves about 37 CPU seconds a run. Slow CI passed on b8e33966.
