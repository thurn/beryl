Description

The one Warden of milestone 4 (plan K15: one Warden per milestone). Review the stores as a whole after every implementation bead of by-w8gv.7 has landed, following ~/enact/skills/enact/roles/warden.md. Parity is machine-checked at every push; what the checks cannot see is whether each store really is the one place its concerns are written, and whether the hot path gained a hook.

Read first

docs/project-50k.md: K4, K6, K11, K12, "State", "Kernel rules". docs/rules-coverage.md "Principles". rust/crates/beryl_kernel/src/lib.rs: the contract, with its "Stores" section. The Mason's notes (first comment on by-w8gv.7.1). enact brief for every bead's handoff; each records just bench-count before and after and the state size.

Check, and record each result on the bead

  1. Nothing is left behind. Legacy, State::legacy_mut, ObjectFlags::LEGACY, floating.rs's FloatingEffect, Continuous and CastPermission, Player::sorceries_as_flash, State::entered_x, the ObjectFlags KICKED, OFFSPRING, IMPENDING, EVOKED, EXILED_UNTIL, EXILED_WITH, LOYALTY_ACTIVATED and ENTERED_THIS_TURN, Object::linked, Counters::other_kind and other are gone. For StackEntry::exile, StackEntry::flashback, Casting::extra and ObjectFlags::ONE_ONE, the contract says where each went or why it stays, and the code agrees.
  2. K4. Read the fields of State, Object, Player, Turn and StackEntry. Each is something the Comprehensive Rules give that thing. List any that a card creates and that no bead moved; move it or file it.
  3. Once per store. Each store's empty value, copy, relayout, fit, invariant, save description (off_board, checkpoint.rs) and observation are written once, in the store's file, and adding a kind would touch none of them. Try it: add a scratch kind to each store, confirm what the compiler asks for is the kind's own entry and its reader, and delete it.
  4. Expiry. The rules end durations through one mutator; no caller sweeps a store by hand; an effect, a permission and a memo of an object that left its zone are gone or unreadable (CR 400.7), each with a test. "Exiled with" outlives its source exactly as the contract says (CR 607.2a).
  5. Absent kinds cost one AND. For each GameTable capability bit, find its reads on the hot paths (the layers' recompute, the zone move, the turn's reset, event::destination, finding what a player may cast, the timing checks) and confirm an absent kind is one test of the bit, not a scan of an empty store. No general hook runs in case some card cares (rules-coverage, Principles).
  6. The kernel's contract holds for the stores. Their writes are #[inline] State mutators generic over the layout; none returns &mut into a store; one whose change a player sees returns its Event; the one that changes a layer input sets derived_dirty; a full store returns Full. Payloads are kernel types: Modification::Control holds no Seat.
  7. Rules. Rule changes: "can't" beats "can" (CR 101.2); a static's rule change follows its permanent's controller after continuous effects and is nothing for a face-down permanent. Locked-in sets do not change after the effect begins (CR 611.2c). Timestamps are taken as effects start (CR 613.7). Counters: an object holds two keyed kinds at once and loses them on a zone change (CR 122.2).
  8. Interchangeability. State::signature tells apart two permanents that differ only in a memo, a keyed counter or an effect's membership; search's state equality (beryl_search/src/mcts/tree.rs) still compares what it compared.
  9. Capacities. size_of::<State<Small>>() is within 20,480 and matches the contract's target; each store's Small capacity overflows into a stall to Large, with a test; State::try_relayout refuses a store that does not fit.
  10. Structure. No kernel or engine file over 800 lines was added to data/file-length-allowlist.json and no count there rose; no card name in generic code (python -m beryl_tools.checks card-names) and the mechanics list lost Player::sorceries_as_flash, CounterKind::Story and CounterKind::Chorus; no runtime dependency was added (K12); no procedural macro; expert/ and frozen/ changed only at call sites.
  11. Parity. just ci on the tip, including counts with rust/crates/beryl_bench/count-gate.toml's bar unchanged at 405,276,238. Add up the beads' recorded counts from the 404,858,188 the milestone started at: if the drift adds up, find which bead paid it. just fuzz and just exhaust (invariants run on every debug apply).
  12. Citations. Moved and new rules code cites the Comprehensive Rules (just citations).

Fix what you confirm. Do not rerun tournaments: nothing in this milestone is gated on one.
