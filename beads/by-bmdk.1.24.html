Close reason

Landed manual-table pointer hooks at 6c0d7313. TypeScript, 249 unit tests, two engine drag checks and a WebKit event probe passed.

Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'Working alongside the engine and stage work' (the pointer hooks), 'Select', 'Drag', 'Arrows', 'Touch'.

ui/src/stage/pointer.ts (211 lines) tells one listener about hover, click, lift and drop. Its only client is the engine prompt code (ui/src/stage/prompt.ts:216), and ui/src/stage/dom.ts:199 ignores every button but the left one. The manual table is a second client and needs more. Add hooks; change nothing an engine game does.

Extend PointerEvents (all optional, so prompt.ts compiles unchanged):

  • click(name, at, keys) gains a third argument keys: { meta: boolean; shift: boolean; alt: boolean } (meta is Cmd on macOS, Ctrl elsewhere). drop's Drop gains keys too.
  • secondary?(target: Name | Under | undefined, at: Point): a right click, or on touch a press held 500 ms without moving past DRAG_THRESHOLD. undefined is empty table.
  • aim?(from: Name, at: Point, over: Under | undefined, done: boolean): a drag with the right button from a node, told on every move and once more with done: true on release.
  • sweep?(from: Point, to: Point, done: boolean): a left-button drag that began on empty table (no node under the press), told on every move and on release.
  • over?(drop target under a held card): while a card is held, tell which node or player is under it on each move, so a client can light a drop target and split a pile into halves. Today hover is silent while holding; keep hover silent and add this.
  • Touch: a card is picked up only after a 150 ms hold, so a hand can still be scrolled.

In dom.ts: deliver button 2 and contextmenu (call preventDefault only when a listener has secondary or aim), presses on the stage background, modifier keys from the event, and the touch timers. Keep the existing pointer-capture behavior.

Pointer stays free of the page: dom.ts makes calls on it and tests make the same calls. Add unit tests beside the existing pointer tests (find them with grep -rl "new Pointer" ui/src ui/scripts): each new event, that a listener without the new members sees exactly what it saw before (replay the existing tests unchanged), that a right press never produces click or lift, and the two touch timers using a fake clock.

Run cd ui && npm run typecheck && npm test, then just ui-test for two existing checks that drag a card in an engine prompt, to show nothing changed.

Acceptance criteria

PointerEvents has keys on click and drop, secondary, aim, sweep and held-over events; dom.ts delivers right button, background presses, modifiers and touch timers; existing pointer tests pass unmodified and new tests cover each event; engine prompts behave as before.
