Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'The log, undo and rewind' in full.

Create log.rs, undo.rs and save.rs in rust/crates/beryl_table/src/, and implement the undo, rewind and batch actions (they are stubs in apply/mod.rs).

  • Log: the entries in order. Each entry already carries its changes; add to Entry the set of objects and zone positions it touched (derive it from the changes).
  • undo (the acting seat's most recent entry that is not already undone): allowed when no later entry touched any of the same objects or positions. It is applied as a new entry whose changes are the inverses in reverse order, with undoes: Some(n). When a later entry is in the way return Refusal::Invalid carrying the numbers of the blocking entries (add a field), so the interface can highlight them.
  • A batch applies its members in order as one entry and is undone as one unit, by either seat.
  • Knowledge: an undo restores positions, order, state and ids exactly, and never removes a seat from known_to. Undoing a shuffle restores the earlier order, ids and known_to. Undoing a draw returns the card with the drawer still in known_to; mark the entry seen: true so the log line can say "(seen)".
  • Random results: undoing a roll removes the result; rolling again asks Chance afresh.
  • rewind { to: n } restores the whole table to the moment after entry n. Later entries stay in the log, flagged struck. The rewind is itself an entry, and undoing it restores the table as it was before the rewind. Either seat may rewind.
  • Snapshots: keep a full Table copy at the start of each turn. pub fn rebuild(log, upto) replays from the nearest snapshot with Chance::replaying. A rewind entry means "the table is now as after entry k", and replay honors it.
  • save.rs: pub fn append(writer, &Entry) writes one JSON line per entry; pub fn open(reader) -> Result<(Table, Log), SaveError> rebuilds by replay. The first line is a header with format: 1 and the seed. A file with a higher format is a clear error.
  • pub fn line(entry, table, for_seat) -> String in log.rs: the log's wording, as in the doc's five-line example ("Cast Brainstorm.", "Drew 3 cards.", "Undid: ..."), covering every kind of line in the appendix's 'Chat and the log' list. It takes a redacted entry.

Tests: the doc's undo list as named tests; apply then undo restores the table for every action kind (reuse tests/common/random.rs: after each random action, undo it and compare, and assert no known_to shrank); save then open equals the table, for a log containing undos and rewinds; undo of a rewind. Run just test-rust -p beryl_table.

Acceptance criteria

undo, rewind and batch are implemented; the apply-then-undo and save-then-open random tests pass for every action kind; knowledge never shrinks on undo; a log line exists for every kind in the appendix's log list.
