Close reason

low-disk mode in prune-caches, triggered from warm's clone path; pushed cb5ba0e5

Description

Incident by-64fx: the Data volume filled up (377 MiB free) and stopped every build and slow CI. Arq's hourly backup holds an APFS snapshot of the Data volume for about 6 hours per cycle. While that snapshot exists, deleting a file frees nothing if the file predates the snapshot. Meanwhile each Enact worktree writes about 15 GB of new rust/target, and screenshots and films add tens of GB more. 'by prune-caches' (tools/src/beryl_tools/caches.py) only runs nightly and keeps folders for MIN_AGE = 1 day. So nothing frees recent output when space runs short. The incident was cleared by hand: delete $BERYL_CACHE/target/debug/incremental, target/tauri and the mobile target dirs, plus per-checkout screenshot folders of beads already gone (~48 GB). Add a low-disk mode. When free space on the cache's volume (shutil.disk_usage) is under a threshold (default 60 GB), prune-caches lowers the age to about 1 hour for per-checkout folders whose checkout is gone, and removes the shared target's debug/incremental and other-target dirs (tauri, aarch64-*) when no clone is in progress (warm.lock). Call it from warm.py's clone path (worktree creation) so it runs without the nightly. Tests go next to caches.py's existing tests.

Acceptance criteria

With free space under the threshold, 'by prune-caches' frees per-checkout folders of gone checkouts older than an hour and the shared target's incremental dir. Above the threshold it behaves as today. warm triggers it. Tests cover both branches with a faked disk_usage.

Handoff: tools/src/beryl_tools/caches.py: LOW_DISK (60e9 bytes, --low-disk GB flag) and LOW_DISK_AGE (1 h); run() checks free_space() (shutil.disk_usage on the cache root) and in low-disk mode prunes gone checkouts' folders older than an hour plus spare(target) = target/debug/incremental, target/tauri, target/aarch64-* via prune_target(), which takes warm.try_locked() (new, non-blocking flock on warm.lock) and skips the shared target if a clone/save holds it. run(only_when_low=True) is a no-op above the threshold. warm.py: ensure() calls make_room() (lazy 'from . import caches', so the stdlib-only remove hook is unaffected) before taking the lock, only when the checkout has no rust/target (the clone path); errors are logged, never fatal. Tests: tests/test_caches.py (both branches with faked shutil.disk_usage, lock-held case), tests/test_warm.py (ensure triggers the prune). Dry run on jarvis at 68.7 GB free with --low-disk 100: 36 folders 1.8 GB + shared target 26.6 GB (tauri 22.5 GB). Gotcha for reviewers: dropping target/tauri makes the next Tauri build (just smoke, slow CI app lane) cold; accepted per the bead since it only happens under 60 GB free.
