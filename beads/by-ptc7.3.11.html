Description

Why

every_card_has_scenarios_and_they_pass costs about 12 CPU-seconds a run at 121 cards, 0.1 s a card, and the mutation check and the generated scenarios scale the same way. At 50,000 cards an engine change would test for over an hour. Decision P12 of the plan; Designs D.

What to build

  • The per-card tests of rust/crates/beryl_cards (tests.rs, tests/mutation.rs, tests/derive.rs, tests/exhaust.rs) take a card filter from one environment variable, read in one place.
  • tools/src/beryl_tools/: the fast check and slow CI set the filter to the cards of docs/sample-decks/, the keystones and partners (decks::KEYSTONE_FAMILIES and the rulings ledger's cards), the cards whose files changed against master, and a sample of the rest fixed by the commit hash. oracle_selection.py already chooses cards this way for the oracle lane: share its code. A change to beryl_card_build or to the tests themselves plays every card.
  • The nightly (nightly.py) plays every card and files one bead for a failure, naming the card and the commit range since the last pass.
  • just scale (scale.py, scale_workspace.py): the rehearsal clones today's card files, scenarios and all. Give it the mix the pool will have once simple cards carry no scenarios (three quarters of the clones without a scenarios module, taken from cards the generated bar has converted), run it, and set its budgets (BUDGETS) again from that run. Report cold check, release build, one-edit rebuild and memory before and after, and the per-card test cost extrapolated to 50,000.
  • docs/checks.md: the selection, and what the nightly plays.
  • data/efficiency-changes.json: the entry for the sampled tests.

Nothing may make a card's failure invisible: the sample is fixed by the commit, so the same commit always tests the same cards, and the nightly covers the rest within a day.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.

Acceptance criteria

The fast check and slow CI play the selected cards and the nightly plays all. just scale uses the new mix with budgets set from a measured run. The close reason gives the numbers before and after.
