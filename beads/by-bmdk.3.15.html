Close reason

Landed registry-driven table menus, typed prompts and target picks with six audited menu states.

Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'The context menu' (all of it, including the 'First rows' table and the three rules), and the appendix tables for cards, moving, power and toughness, counters, the hand and the library.

How interface beads in this milestone fit together: ui/src/table/client.ts (bead "Table screen") is the manual table's pointer client. It owns the selection, sends actions with tableAct from ui/src/ipc.ts, and lets each interaction register handlers from its own file. Put your code in the file this bead names and register it; change client.ts only to add a registration point it lacks. Check your work on a live manual table in a headless browser: ui/scripts/table.mjs (same bead) starts one through the HTTP server and gives a Playwright page. Add one scripted check per behavior to ui/scripts/kept-table-<topic>.mjs and run it with just ui-test <title>.

File: ui/src/table/menuRows.ts and TableMenu.tsx. The component is ui/src/table/Menu.tsx; the commands are commandsFor in ui/src/table/commands.ts.

  • The pointer's secondary event on a card or pile opens the menu for it, or for the selection if the card is selected.
  • menuRows(kind, context) -> { header, groups }: pure. Rows come from the registry's menu placement; the header names the card and whose it is; for the viewer's own cards and piles the first row is what a plain click does, marked "click"; a "Move to" group lists the zones; a switch row shows a check mark when on; the last row is "Every action…".
  • Permissions: a row the viewer may not use is absent, never greyed. The other player's hand offers nothing but its count. Work this out from the view (TableView.acting, who controls and owns the card) with one function allowed(command, target, view) that the command list reuses.
  • Choosing a row: asks: none sends the action at once; number, text or stats closes the menu and opens AskPrompt (ui/src/table/AskPrompt.tsx) with the start value and confirm label for that command, then sends; target calls pickTarget; token opens the token search (later bead; export a hook). Fill the registry's action template placeholders in one function fill(template, {objects, seat, number, text, target}).
  • "View related cards" and "Token: (name)" rows come from cardTokens for the card.
  • A two-faced card adds "Transform".

Tests (npm test): menuRows for each row of the doc's "First rows" table, compared with the exact labels in the doc; allowed for own, other's and hidden things; fill. Checks (kept-table-menu.mjs): right-click a permanent and add a +1/+1 counter; "Draw cards…" opens the prompt at the lower right, 3 and Return draws three; "Attach to…" picks a host. Fixtures or kept moments for the generic audits: the menu for a permanent, the other player's permanent, a hand card, a stack entry, a library and a life total.

Milestone 1's registry is ui/src/table/commands.ts and data/table-commands.json. Supply the current conditions to commandsFor and use its per-target placements. The registry currently exposes the templates, so implement the shared dispatch for menu and keyboard here. Keep the play-then-arrow sequence for a hand card and preserve selected order when moving multiple cards to a library. Use the existing focus regression in ui/scripts/kept-command-list.mjs when wiring the overlays.

Acceptance criteria

A right click opens the menu with the doc's first rows for each kind of thing; unavailable rows are absent; rows that ask open the prompt or a target pick and then send the filled action; menuRows, allowed and fill are unit tested; six menu states are under the generic audits.
