Close reason

Work::placed counts placement work, so rank sees script compile frames; count limits reset after VM drift; pushed ad42cc04d

Description

Symptom: since the instruction-count gate counts every frame (b3d-frame-counts under Callgrind, commit 'perf: count Beryl 3D frames in one Callgrind run'), its ranking check fails on verbs-zones. Frame 894 takes 2,085,813 instructions, the board's most, but beryl_inspect::gate::rank (the 8 frames with the most work by the native work counters) does not include it. The old gate counted only the ranked frames, so it reported 878,544 (frame 30) and never saw frame 894.

Why: frame 894's handle takes a view whose script compiles in beryl_scene::play::compile and re-places battlefield rows in beryl_scene::table::place (Callgrind self cost, frame 894: compile and place dominate, then malloc). None of the counters in beryl_scene::frame::Work (elements, segments, records, layout_nodes, text_runs) counts that work, so the native gate, which runs in the lane in seconds, cannot see a regression there.

Fix: add a work counter that grows with script compile and placement work (for example, rows placed or steps compiled), count it in Work, include it in gate::total, print it from the gate bin (src/bin/gate.rs), give it limits in data/beryl3d/gates.json frames.<board> via just b3d gate --update, and check that rank puts frame 894 among the verbs-zones top 8. Then run just b3d gate --counts (about 40 s now) and confirm the ranking check passes on all four boards. Coordinate with by-q44s.22, which is cutting script compile cost in the same code; its changes will move these counts.

Files: rust/beryl3d/crates/beryl_scene/src/frame.rs (Work), play/compile.rs, table/place.rs, beryl_inspect/src/gate.rs (rank, total), src/bin/gate.rs, tools/src/beryl_tools/beryl3d/gate.py, data/beryl3d/gates.json; tests in beryl_inspect tests/all/gate.rs.

Acceptance criteria

just b3d sweep --step frame-counts --commit origin/staging passes at the staging tip.
