Description

The flat layer and everything a desktop game needs from start to finish. Doc: 'The flat layer', 'Card faces' (Beryl's drawn frame), 'Sound', 'Bug reports', 'The agent interface' (driving the running app), 'Migration and compatibility' (what the two clients share).

Exit checks:

  • Elements, flexbox and grid layout, text with inline mana symbols, the glyph atlas and the widget set exist, and every one of the session's prompt shapes is playable.
  • Every screen the web interface has is present: start, opening hand and mulligan, game, game over, settings, bug report, card gallery, testing screen, and the manual table's screens as far as that epic has shipped them.
  • A game against the expert agent plays to its end in the desktop app, resumes after a restart, and plays its sounds.
  • Design tokens come from one data file that also generates the web interface's CSS.
  • The text fits, named and phone-size checks run. just b3d live drives a debug build.

From the milestone 1 architecture audit (by-q44s.2.1). What milestone 3's beads should know.

  1. The element tree has nowhere to put a value. Resolved (beryl_scene/src/frame.rs) has a role, a name and state bits, but no value: a text field's contents, a slider's position or a list's chosen item cannot be printed by just b3d tree or matched by a locator except through the name. by-q44s.5.2's contract adds no such field. Decide it in that contract: either Resolved::value: NameRef (text in Frame::names, written as value="..." in the tree printout), or a rule that a widget's name carries it. Without one, by-q44s.5.8 (slider, toggle) and by-q44s.5.10 (text field) will each invent their own.
  2. Input::Text(TextChange) carries the whole new text but no selection or composition range. by-q44s.5.10 promises selection and paste; if the phone hosts' native field must report a selection, put the range in TextChange in by-q44s.5.2, since Input is the contract the phone hosts of milestone 4 build against.
  3. Literals that the design tokens bead (by-q44s.5.3) should take over: every constant in beryl_scene/src/tokens.rs, and DOCK_RIGHT and DOCK_BOTTOM in src/layout/mod.rs (copied from ui/src/screens/styles/controls.css).
  4. scene-purity is stricter (bbc704dd2): a new dependency of beryl_scene must be listed in SCENE_DEPENDENCIES in tools/src/beryl_tools/beryl3d/purity.py. tiny-skia and swash for icons and card frames belong in beryl_assets, not the client core.
  5. Test views are built in one place after by-q44s.2.5 (beryl_scene::testing, ObjectView::neutral); screen and prompt tests should use it rather than writing ObjectView or Script literals.
  6. The beryl3d lane is over its budget (by-wzq9, under the gate). Add integration tests as modules of a crate's existing test binary, not as new files under tests/.
