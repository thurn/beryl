Close reason

Beryl 3D builds ObjectView/Script through neutral constructors in one place

Description

Symptom. In two days, Beryl 3D stopped compiling five times because the main workspace added a field to a wire type, and it took six commits to repair: ObjectView::hidden_pick (c757730d1, e86463a45, and 88178b598, which removed a duplicate after two sessions fixed it at once), Script::timing with ObjectView::custom_colors and token_printing (9c771e82c), and ZoneName::Merged (602294c2a). Each break also failed every Beryl 3D push until someone fixed it.

Why. Beryl 3D builds ObjectView, Script and GameUpdate with struct literals in three places: testing::object and ScriptBuilder in rust/beryl3d/crates/beryl_scene/src/testing.rs, permanent and the scripts in rust/beryl3d/crates/beryl_inspect/src/stress.rs, and record and the updates in rust/beryl3d/crates/beryl_scene/tests/common/mod.rs. A struct literal names every field, so any new field breaks all three. PlayerView::neutral and PlayerState::neutral in rust/crates/beryl_protocol/src/protocol/neutral.rs already solve this for the player view.

Proposed design. Add ObjectView::neutral(slot, zone, side) and Script::empty() (or Default on Script) to beryl_protocol's neutral.rs, beside PlayerView::neutral, with the same neutral values Beryl 3D's builders use now. Beryl 3D's three builders become one: stress.rs and tests/common use beryl_scene::testing (stress.rs's crate already enables the driver feature, or enable it), and every literal becomes ObjectView { name, ..ObjectView::neutral(slot, zone, side) }. The exhaustive matches on ZoneName in the tree printout stay exhaustive, so a new zone still has to be given its word.

This touches beryl_protocol, a main-workspace crate: list it under the exceptions in docs/beryl-3d.md 'Checks and isolation' in the same change. It changes no wire type, only adds constructors.

What it eliminates: a Beryl 3D build break for every new field of ObjectView or Script.

Behavior that must not change: every stress board and test view is identical (the recordings pack's hash for stress boards, and every beryl_scene and beryl_inspect test, pass unchanged).

Acceptance criteria

grep for 'ObjectView {' and 'Script {' in rust/beryl3d/crates finds only struct-update forms ending in ..ObjectView::neutral(...) or ..Script::empty(), all in beryl_scene/src/testing.rs; adding a field with a default to ObjectView in a scratch build compiles Beryl 3D unchanged (say so in a comment); just b3d lane and the rust lane pass.
