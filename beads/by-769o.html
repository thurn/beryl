Description

What we see

master sat on d6acb6a8 for about three hours on 2026-11-13 while slow CI failed on every run from 30fc3534 onwards. The failures were deadline kills, not test failures: the rust lane's clippy step spent about 290 s waiting for CPU tokens, finished its own work in 2.7 s, and left the tests step 8 s before the lane's 600 s deadline. The mobile, ui-test, shots and oracle lanes timed out the same way. Bisect skips timeouts, and the Steward bead (by-kaz8) fixed the failures that differed between runs, never the timeouts all of them shared.

Policy: timeouts stay as a safety net for real problems such as a hang, but never as a gate meaning "CI took too long"; a slow run files a bead instead of failing. Nondeterministic tests should be very rare, and a flaky one is deleted. Slow integration tests are strongly discouraged.

Separately, slow CI grows with every card (oracle scenarios, spec moments) and every verb (about eight browser checks each) and nothing ever removes a check. The existing budget beads (budget.py, by-vdpy and by-vz64) measure load-adjusted wall time, ask someone to "audit slow steps" without naming a cut, and sit open at P2.

Goal

  1. Slow CI never fails because something was slow, only because something failed or hung, and master moves again. Children: the token pool fix, turning the run deadline into per-step hang limits, and raising or replacing gate-like timers in browser checks, Rust tests and smoke tests.
  2. Slow CI keeps to the most valuable checks it can run quickly. It records each check's CPU time, scores each check by real catches per CPU-second, and when it runs over a CPU budget it files beads naming the checks to delete (or, for checks that do catch bugs, to move to the nightly). Flaky checks get a bead to delete them instead of being quarantined.

Constraints

  • The Mac is never quiet (load average around 20-40 is normal), so wall time and the load-adjusted clock (clock.py) are not usable measures of a check's cost. Use CPU time.
  • No scheduled review and no admission gate on new checks: the system detects over-budget CI itself and files the beads.
  • Default to deleting checks that have never caught a real bug. The nightly is for checks that have caught something but cost too much to run on every commit. A nightly failure files a bead and never blocks master.
  • No step waits for the user's approval: the agent working a cut bead makes the cut and records it in the bead.
