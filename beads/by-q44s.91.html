M7: tools to match the web interface's look

Description

The owner's first look at Beryl 3D found its styles very different from the web interface's: flat panels where the web draws gradients and shadows, text drawn over other text, and content drawn in the wrong place. He is happy with the web interface and wants Beryl 3D to match it nearly pixel for pixel. On 2026-11-16 he asked for this milestone, at high priority so that it runs next, beside milestones 4 and 5. It builds the tools an agent needs to find and close every difference from the web interface, plus the style vocabulary those tools will show is missing.

Today the only comparison is just b3d compare (tools/src/beryl_tools/beryl3d/compare.py, rust/beryl3d/crates/beryl_pictures/src/compare.rs). It puts the two pictures side by side for a person to read, and nothing measures how far apart they are. Style (rust/beryl3d/crates/beryl_scene/src/element/style.rs) can say only a flat background, a border, a radius and an opacity. The web interface's CSS uses about 113 box-shadows, 69 gradients, 22 drop-shadow filters, 4 brightness filters, 1 grayscale, 1 blur and 10 mask-images.

Decisions (owner, 2026-11-16)

  • M1. C5 is amended for comparisons with the web interface. A check may compare Beryl 3D's frame with the web interface's screenshot of the same moment, and a ratchet file holds the result (contract below). There is still one renderer: the reference is the web interface as WebKit draws it, not a second renderer of ours. Single-pixel renderer tests stay as they are.
  • M2. Text is compared as data, not as glyph pixels. Glyph antialiasing and subpixel placement differ between WebKit/CoreText and parley/swash, and the owner accepts that. Each line's string, font family, size, weight, color, baseline and box are compared exactly, and glyph pixels are masked out of the pixel score.
  • M3. Styles are not generated from the web's CSS. The owner declined that. Beryl 3D's elements keep their own Styles, which the tools hold equal to the web's computed styles.
  • M4. Priority. Every bead here is P0, so that it runs before the rest of milestones 4 and 5.

Defaults recorded without asking

  • The reference browser is WebKit, which is what tools/src/beryl_tools/shots.py already uses on the Mac (BROWSER), and what the Tauri app's WKWebView draws.
  • Matching the 3D table's placement to the web's is not in this milestone. The doc ("Migration and compatibility") currently has each client fitted to Arena separately. The box diff will measure how far apart the card placements are, and the probe bead (the last one) records that number and files a bead with a recommendation.
  • No change under ui/ (decision C1). The web side is read by a script that Playwright evaluates in the page, kept under tools/src/beryl_tools/beryl3d/match/. If an element can't be matched without a web attribute, the matcher lists it as unmatched instead.

Contract (every bead builds against this)

  • Command group. just b3d match <subcommand>. The Python lives in the package tools/src/beryl_tools/beryl3d/match/, one module per subcommand, each registering itself as by-q44s.9.2 made possible. Element dumps come from the b3d program (beryl_inspect). Pixel work runs in b3d-render (beryl_pictures).
  • Target. The same arguments as compare: <recording> --at <moment> [--seat] [--layout desktop|phone] [--size WxH] [--scale], or a test name b3d:<recording>/<seat>/<W>x<H>[@2]. The default scale is 2.
  • Snapshot directory. $BERYL_CACHE/b3d/match/<target slug>/ holds web.png, web.json, b3d.png, b3d.json, joined.json and report.txt. A subcommand reuses an existing snapshot unless --fresh is given or its inputs changed.
  • Element record. web.json and b3d.json each hold {"target", "scale", "elements": [...]}. Each element is {"key", "role", "name", "object", "box", "z", "parent", "style", "text"}:
    • key: the b3d locator, <role> "<name>" #<id>, or null when there is none;
    • box: [x, y, width, height] in points;
    • z: the paint order;
    • parent: the index of the parent element;
    • style: an object of CSS property names to normalized values (the list below);
    • text: a list of lines, each {"string", "family", "size", "weight", "color", "baseline", "box"}.
  • Style properties compared. background-color, background-image, border-width, border-color, border-radius, box-shadow, filter, opacity, color, font-family, font-size, font-weight, mask-image and transform. Values are normalized so that equal looks compare equal: colors as RGBA, lengths in points, and shadow and gradient lists parsed into structures. Beryl 3D emits the same names from its resolved Style. A web value Beryl 3D can't express is reported as unsupported, not as a difference.
  • Ratchet file. data/beryl3d/web-match.json is {"targets": {"<test name>": {"unmatched": n, "boxes": n, "styles": n, "unsupported": n, "pixels": n}}, "samples": {"<sample>": max_error}}. Counts may only go down. just b3d match score --update lowers entries, and --raise (with a reason in the commit body) is the only way to raise one, as with timeline-parity.json.
  • Docs. Each bead documents its subcommand in rust/beryl3d/AGENTS.md ("Seeing and checking") and in .claude/skills/b3d/SKILL.md, and the doc's section "Matching the web interface's look" (docs/beryl-3d.md, under "Migration and compatibility") is kept current.

Graph

The snapshot bead and the conformance suite start at once. The matcher, the style diff, the pixel diff and the motion tracks build on the snapshot. The two style-vocabulary beads build on the conformance suite, in one lane. The score needs the matcher, the style diff and the pixel diff. The probe is last, and it runs the whole loop on real screens.

Exit checks

  • just b3d match (snapshot, boxes, styles, gaps, pixels, motion, score) works on every desktop and phone test target.
  • Every conformance sample is within its tolerance.
  • data/beryl3d/web-match.json lists every test target, the lane holds it, and the sweep files a bead when a target drifts.
  • The probe's comment records how far the loop got on its screens and what is left.
