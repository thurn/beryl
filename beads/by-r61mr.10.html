Description

Read the epic by-r61mr first: it holds the decisions, the code map and the directory layout this bead assumes. The work is in the Enact repository (~/enact) unless this bead says otherwise, delivered with that repository's own enact worktree create and enact push.

Every machine pulls Enact's master, so the helper is how tk reaches them. In scripts/enact.py, extend cmd_install (line 4799) and cmd_setup (4880) so that the helper builds cli/ with cargo into a per-machine directory outside the repository, rebuilds when a hash of cli/'s sources changes, and returns the binary's path to the rest of the helper. Building happens at most once per source change, under a lock, at below-normal priority, and never during a command that does not need tk.

It must work on macOS and Windows (pathlib, no shell syntax), and must fail with a clear message when cargo is missing. Run tk register as part of set-up when the machine has no token.

Acceptance criteria

Unit tests cover the source hash, the rebuild decision and the Windows path. On this machine, enact setup builds tk once, a second run builds nothing, and touching a file under cli/src/ causes one rebuild.
