Acceptance criteria

by check on every lane fits 60 s on an idle machine.

Notes

Cause: in a new worktree, cargo rebuilt every workspace crate. warm.py clones the cached rust/target, but cargo judges path crates by mtime, and a fresh checkout writes every file (and folder: build scripts watch rust/cards/<set>/ and docs/sample-decks) with a new mtime. So every push from a new worktree paid a full rebuild in clippy, the test build, the script checker's build and card-text's beryl_scenario build. It is a steady pattern, not a one-off: on the Mac the same one-line beryl_cli change measured rust lane 104/114/185 s and script 48/57/75 s in three fresh worktrees (load 15-28, 18 cores), against rust 23 s / script 6 s once built. Cygnus run log is not on this Mac, so its split is inferred from the bead only. Choice per step: make cheaper (no move, no delete; clippy is in budget.KEEP anyway).

  • clippy, tests, script-check, card-text builds: warm.save now records each tracked file's git blob + mtime and each folder's name digest + mtime in target/.beryl-sources.json; warm.ensure, after cloning, restores the recorded mtime on files with the same blob and folders with the same names. Content that differs keeps its new mtime, so cargo still rebuilds it. Measured in a fresh worktree with restored times (probe, load 27): rust 25 s (clippy 3, tests 18, card-text 1), script 18 s, whole check 31.7 s, vs 79-170 s before. Fresh-worktree clippy -p beryl_cli: 47-76 s -> 0.26 s standalone.
  • card-text: now skipped unless the change reaches beryl_cards (card_text.affected), or its allowlists/code changed (card_text.INPUTS). Saves the 13 s seen on Cygnus for a beryl_cli-only change. Landed as 6c8a21bf on staging. Effect needs one save with the new warm.py per machine (the first worktree removed after this lands writes the record); until then clones have no record and behave as before. Not measured on Cygnus (Windows: robocopy keeps mtimes, so the same mechanism should apply). Side finding, not fixed: warm.prune keys units by '<name>-<hash>', but deps/ uses the crate name (unicode_ident) and .fingerprint/ the package name (unicode-ident), so hyphenated packages' fingerprints are evicted apart from their artifacts; measured cost ~0-2 s per fresh clippy, so left alone.
