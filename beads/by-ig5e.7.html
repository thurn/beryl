Lease log, CPU ingest, core minutes per bead, queued for cores, machine query and metrics; pushed 9817ac54

Description

Add the machine's CPU: core minutes per bead, shared CPU, how busy the machine was, and exactly how long commands queued for cores.

Design sections: "CPU accounting", and "queued for cores" under "Time accounting".

Existing pieces

  • The sampler is tools/src/beryl_tools/cpu.py, kept running by a launchd agent (just cpu install). It appends one Row per minute to <cache>/cpu/samples.jsonl: time, seconds, cores, cpu (CPU seconds keyed by context, kind and worktree), unnamed, peak_cores, top_cores, load. Read its module comment for how a process gets its context, kind and worktree. Do not change the sampler.
  • The CPU token pool is tools/src/beryl_tools/tokens.py (Lease, its release, and the function that grants a lease). Classes are queue, push, agent and ci.

What to build

  • In tools/ (a separate small commit; it runs the python lane): when a lease that owns tokens is released, append one line to <cache>/cpu-tokens/leases.jsonl under the pool's existing lock, in the format the design gives (time, class, worktree, command, cores, wanted, waited_s, held_s; cores is the number of CPU tokens the lease got, named so that nobody reads it as LLM tokens). An inherited lease writes nothing. A failed append is reported and never fails the command. Keep 30 days, as the sampler does. Add its test beside the pool's in tools/tests/test_tokens.py.
  • Ingest of sampler rows into cpu and of lease lines into leases.
  • Core minutes per bead: the sampler's CPU for the worktree in the bead's enact_worktree, between its start and close. Shared CPU by context and kind.
  • Queued for cores in the time split: join each lease's waited_s to the tool call running in that worktree at that time, and move those seconds out of the tool's kind.
  • The machine query: cores in use, saturation (share of minutes at or above 90% of the machine's cores), queued core hours by command kind, leases that got fewer tokens than they wanted, shared CPU, and the sampler's and ingest's own CPU.
  • The parallel capacity estimate for a cohort, and metrics machine.queued-core-hours-per-day, machine.saturation, bead.core-minutes.

Shared context

  • The design is docs/efficiency-dashboard.md. Read the sections named above before anything else; the rest can wait. The decisions taken with the user are in the epic, bd show by-ig5e.
  • The dashboard's code is the separate Python project in efficiency/ (package beryl_efficiency, standard library only, pyre strict, black). It imports nothing from tools/ and nothing imports it. Read efficiency/AGENTS.md first once it exists.
  • Tests use small synthetic sources built in the test itself or kept under efficiency/tests/. The repository is public: never commit a real transcript, session record or command line from this machine.
  • Real data exists only on the main Mac (host jarvis). Where the acceptance criteria name a check against real data, run it there; if this session is on another machine, record that the check was not run in a comment on this bead and close on the tests.
  • Collection must stay free for agents: no hook, wrapper or prompt text may be added to any session, and ingest must never run inside another command.

Acceptance criteria

Tests: a lease line is written once per owning lease with the waited and held seconds, and none for an inherited lease; a fixture bead's core minutes equal its worktree's sampled CPU inside its window; queued seconds move from the tool's kind to queued for cores and the window's categories still sum to its length; saturation counts only minutes at or above 90%. On the main Mac after an hour of normal work, just efficiency machine --since 24h shows non-zero queued time and the sampler's and ingest's CPU together under 1% of the machine's total.

Decisions: (1) Lease lines are logged only for leases from Pool.acquire; top-ups (extra tokens for an already logged lease, taken without waiting) and inherited leases write nothing. Check steps log command 'lane:step', test-rust logs 'test-rust', tokens-run logs the executable name; worktree is the checkout's directory name. (2) Queued seconds are not stored on tool_calls: the leases table keeps the joined (transcript, call), and timing.spans_of works out each call's queued seconds from the union of its leases' waits, so a transcript re-read keeps them; tool_calls.queued_seconds is dropped in migration 8. A lease is joined to the latest-started top-level tool call in its worktree (bead's enact_worktree basename, or a no-bead window's label) covering its wait with 2 s slack; unmatched leases are retried until the store has tool calls a day later. (3) Queued core hours = waited seconds x tokens wanted. (4) The sampler's own CPU comes from ps over the launchd agent's process tree (uv and the sampler under it), as cores averaged since it started. (5) Peak cores is the busiest minute's mean, clipped at the machine's cores; the sampler's peak_cores and some minute totals exceed 18 cores on jarvis (19 of 175 minutes), so such minutes count as all busy and are reported as over_cores; filed by-ig5e.18 for the sampler. (6) Core minutes are null for a bead that started before the sampler's first row on its host.
