Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'Dropped connections and saving' and 'Builds must match'.

Interface code goes in ui/src/table/, registered with TableClient (ui/src/table/client.ts). Headless checks start a table with ui/scripts/table.mjs and go in ui/scripts/kept-table-<topic>.mjs; run one with just ui-test <title>.

File: ui/src/table/LinkBanner.tsx, link.ts.

  • While LinkState is reconnecting, both tables freeze under a banner: "<name> is reconnecting". Neither player can act: the TableClient ignores gestures and keys.
  • When the guest's link drops, the guest redials on its own (Rust does this); the banner shows until Resumed, then the whole view arrives with no animation.
  • A left state shows "<name> left the table" and offers "Lobby".
  • A wire mismatch shows, to both players, exactly: "Both players need the same version of Beryl." A wrong or malformed invite shows a clear failure on the join form and opens no table.
  • If the host's app was quit, the start screen offers "Resume table" for each saved table (tableSaved); resuming keeps the identity and secret, so the guest's redial succeeds without a new invite.
  • Use the stage's existing notice or banner component (ui/src/stage/notices.ts); no new look.

Checks (kept-table-link.mjs, with pair()): cut the link from the server side (add a test-only route in beryl_cli/src/serve.rs that severs the pair's link) and see both banners, then restore and see the guest's table match the host's; a bad invite; a mismatch (the test route starts a guest with a different wire). A fixture or kept moment with the banner up.

Acceptance criteria

Both players see the reconnecting banner and cannot act while the link is down; the guest resumes without a new invite; mismatch and bad-invite messages are exact; headless checks cover drop, resume, mismatch and bad invite.
