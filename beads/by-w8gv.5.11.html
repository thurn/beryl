Close reason

TargetPlace, TargetPlaces and placed() in the kernel; resolve, the interpreter and EffectCtx use them; Target's fields are private; parity and count hold

Description

Milestone 3 (plan "Kernel rules"): the second of the two u8 index spaces for targets becomes a type, and the state's Target record stops reusing a field.

Read first

Mason note 3 on by-w8gv.5.1 (bd show by-w8gv.5.1). The handoff of the by-w8gv.5.10 (index newtypes) bead (enact brief): the target-spec index it defined in beryl_card is the other space. rust/crates/beryl_kernel/src/lib.rs for the API contract (sets and orders, section f).

Scope

  • Place: the position of a chosen target in a stack entry's targets queue (StackEntry::targets, capacity TARGETS = 8). Today a bare index and u8 masks over it: resolve::legal_targets' mask (rust/crates/beryl_engine/src/resolve.rs), Registers::legal and the noted and known masks (interpret/scene.rs, interpret/run.rs), EffectCtx::target(i: usize) (effect.rs:158). Define the place index and a set over places in the kernel, with only order-free operations plus "in the order the targets were chosen" (CR 601.2c), and use them at every site.
  • Target (beryl_kernel, from state.rs:395-440): { spec, slot: Option<Slot>, incarnation: u16 }, four bytes, where a player target is stored as no slot and the seat in incarnation. Give it a representation whose fields mean one thing each (for example a private payload with a tag the type system checks, or a private union behind as_object and as_player), keep Target<Small> at 4 bytes (const assertion) and keep Target::object, Target::player, as_object and as_player as the only way in and out. Relayout (relayout.rs:91) and beryl_session's checkpoint encoding go through those.
  • A target that is a player holds a Seat. The by-w8gv.5.13 (player API) bead decides how a player is named in a format-neutral state; do not widen it here.

Constraints

  • interpret/ is the hot path of every resolution (about 470 instructions each). A set over 8 places is one byte; keep it one. Run just bench-count before and after and record both.
  • relayout.rs is being edited by the prompts milestone (by-w8gv.11): keep the diff there to Target's impl.

Parity and checks

Parity (plan K11) at the push: just check passes; the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds (cargo test -p beryl_bench rollouts_never_change); slow CI's counts lane (just count-gate, bar 405,276,238 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. No behavior changes: no rules fix, no new card, no new mechanic. Work the card-names and file-length allowlists down as files are touched (data/card-names-allowlist.json, data/file-length-allowlist.json; an entry moves with its file and its count only falls; a new file is under 800 lines). Rules code cites the Comprehensive Rules (AGENTS.md); keep the citations of code you move.

Acceptance criteria

beryl_kernel defines the index of a chosen target's place in a stack entry's list and an order-free set over places; resolve::legal_targets, Registers::legal, the noted and known masks in interpret/scene.rs and EffectCtx::target use them and no u8 mask or bare index of that space is left; a place and a target-spec index cannot be passed for one another; Target has no field that holds a player under the name incarnation, is built and read only through typed constructors and accessors, and Target<Small> is still 4 bytes; relayout and the frozen save corpus are unchanged; parity holds.

Decisions and deviations (executor):

  1. Names: beryl_kernel's stack.rs defines TargetPlace (the index; FIRST, new, index), TargetPlaces (the set, one byte: NONE, insert, contains, is_empty) and placed(&[Target]) (the targets with their places in the order chosen, CR 601.2c). The set does not iterate: nothing needs it, and the one order is placed(). Re-exported from state.
  2. Target keeps its bytes: { spec, slot: Option<Slot>, rest: u16 }, all private. slot is the tag (an Option the compiler checks), rest is the object's incarnation or the player's seat and is read only by as_object and as_player. Tried on paper and rejected: an enum of ObjectRef and Seat beside the spec is 6 bytes; a two-variant enum holding the spec in each arm can be 4 but puts spec at a different offset per arm, a branch on the interpreter's hot filter, and changes the derived Hash; a union needs unsafe, which the workspace denies. So the field is renamed and sealed rather than split. Target::spec() replaces the public field.
  3. EffectCtx::target, target_object and target_player take a TargetPlace. Every caller passed 0, so 16 card files and the tests now write TargetPlace::FIRST (a search and replace plus an import).
  4. Semantics kept, and a trap for the Mason: a card body's target_object(place) reads the entry's list by place, not by spec. For an ability whose first instance of the word target is optional, the second instance's target sits at place 0 when the first chose none. No card of the pool has that shape; effect data is not affected (Objects::Target goes by SpecIx). A spec-keyed accessor for bodies would remove the trap; it changes behavior, so it is not done here.
  5. Counts (just count-gate): 405,151,563 before (staging 44a0cdd2), 405,154,072 after (+2,509, +0.0006%); bar 405,276,238. Measured before the rebase over by-w8gv.5.5 (05e675a5).
  6. The first push failed on the fast check's Rust tests timing out at its 120 s deadline (load average 35 on 18 cores, a rebuild after the rebase); the same tree passed on the retry with tests at 100 s adjusted. The rust lane has little margin under load.
