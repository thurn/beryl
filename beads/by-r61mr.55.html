Close reason

Native tk uses Beads spellings in Enact 7defbf9. Beryl 68ec143 updates verdict callers. Both repositories passed fast and slow CI.

Description

Work in the Enact repository (~/enact), delivered with that repository's own enact worktree create and enact push. Read the epic by-r61mr first, especially section 9 of its design field (bd show by-r61mr --json, key design). On 2026-11-17 the user decided the spelling rule recorded there: where a tk command means the same as a bd command, it uses bd's name, flags, short flags and positional arguments. Section 9's command block is the target.

Why. tk currently renames several bd commands and flags without any need from the server, for example comment for comments add, --set k=v for --set-metadata k=v, dep add --kind for --type, and a repeated --dep for --deps a,b. create takes only --title, and show only one ID. Every rename means rewriting agent prompts and skills (by-r61mr.30), and agents keep typing the bd form from habit. On JARVIS, agents typed bd forms such as bd create "<title>" -l a,b even where bd's own flags were stricter. With bd's spelling, callers move from the shim to tk mostly by changing the program name.

What to change.

  • cli/src/args.rs: rename and add arguments to match section 9. show takes one or more IDs. create takes the title either as a positional argument or with --title, plus -t, -l, --description, --deps a,b and --silent. update uses --set-metadata/--unset-metadata and accepts --claim. comments <id> lists comments and comments add <id> [TEXT | -f F] adds one. dep add|remove uses -t|--type. list accepts -n. Keep tk claim, the lease, event, wait, state, batch, export, import, compare, register and bench commands as they are. search, children, list --label-any and dep cycles are added by by-r61mr.54, which follows this bead in the same lane.
  • cli/src/commands.rs and its callers: follow the new names. tk keeps its own JSON output (the server's JSON) and exit codes.
  • Every caller of the old spellings: Enact's scripts/enact.py (the server backend, for example Beads.ticket(...) and ticket_graph), scripts/cutover.py, cli/tests/ (shim.rs, simulator.rs, shim-replay.py, cutover-rehearsal.py), the skills and role prompts in skills/ and templates/, and docs/design.md (its tk command block near "tk show <id>"). In Beryl, check the native ticket paths that by-r61mr.27 and .28 added, such as tools/src/beryl_tools/tickets.py, verdicts.py and efficiency/src/beryl_efficiency/tickets.py, and change them in the Beryl repository with its own worktree and push.
  • cli/src/shim.rs and cli/src/shim/: where a shim argument struct now duplicates the tk one, share it rather than keeping two copies. Keep the shim's bd-shaped output and its cutover gating unchanged.

Nothing is deployed and no live caller uses tk yet, so rename outright and keep no aliases for the old tk spellings.

Acceptance criteria

Every command line in section 9 of the epic's design parses with tk and behaves as described against the local Wrangler simulator. No caller in Enact or Beryl still uses the old tk spellings (comment, --set, --unset, --kind, --dep). Enact's fast and slow CI pass, including the shim replay and the cutover rehearsal.
