Description

Read the epic by-r61mr first: it holds the decisions, the code map and the directory layout this bead assumes. The work is in the Enact repository (~/enact) unless this bead says otherwise, delivered with that repository's own enact worktree create and enact push.

With the server backend selected, replace Enact's git-ref locks with server leases and post what the dashboard shows.

  • The staging lock: class StagingLease (line 3381) and staging_lock (3424) take, renew and release a server lease instead of compare-and-swapping refs/enact/staging-lock. The merge queue's behaviour is unchanged: the lease is still held while a batch runs its check, and a holder that dies is replaced after expiry.
  • The Justiciar: justiciar_state, justiciar_transition and cmd_justiciar (2479 to 2550) use a lease per machine instead of refs/enact/justiciars/.
  • Slow CI: ci_pass, ci_run_once and the Steward filing post a CI event per operating system, and ci_status and ci_wait (4005, 4062) read them. Steward tickets are filed through tk.
  • Sessions: start, close and the vizier's spawn and archive steps post session events.
