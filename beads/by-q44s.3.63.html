Deviation from the plan: two of the cuts are on the drawing side, which frame 30 also counts: screen areas are measured only on request (Frame::areas; about a fifth of an idle stress frame), and face lookups by name search a hash-sorted Vec instead of a BTreeMap<String> (scene-purity forbids HashMap). Compile side: tracks sized for tokens created past the starting view's slots (a realloc copied ~200KB of Tracks, ~60K instructions), and Motion::place loops dirty groups by index. Because the stack frames got cheaper, stress-stack's costliest frame became frame 0 (HUD layout and text), which the unweighted counter sum did not rank; gate::total now weights each counter by a least-squares fit of instructions per unit (elements 200, segments 3000, records 750, layout/text 30000, placed 700, steps 10000). Rejected: a Table-level hand fan cache (no win on single-script boards, +1 handle allocation on stress-hand).

Derek Thurn2026-11-16

Why 2.0M was not reachable by tuning: with per-instruction attribution through inlining (callgrind --dump-instr + addr2line -i), compiling the 106-step beat costs ~1.9M of frame 30 and drawing ~0.6M. The compile cost is spread over per-slot passes for each step: 1,990 objects laid (1,325 row, 665 hand), 2,048 rest comparisons in mark_affected, 1,209 follow calls (only 309 push a segment; the rest retarget a segment pushed earlier in the same beat), and 1,990 commits of Option<Rest> (~48 bytes). Each pass costs 20-100 instructions per slot (commit 55K, Placement::set 47K, Placement::get 33K, Pose == 78K, in_row 60K, fan_poses asin 46K, retarget 30K). No single pass is over ~5%. Reaching 2.0M needs fewer passes, not cheaper ones; see the follow-up bead.
