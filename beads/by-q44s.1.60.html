Close reason

Search threads now in the default class (web app's); assets user-initiated; doc re-measured: class effect within noise (median 0.99 over 20 pairs)

Description

docs/beryl-3d.md 'Threads' (decision C9) holds the AI's search threads to within 2% of the web app's search throughput with the table still. by-q44s.1.57 measured it ('Measurements', 'The search threads against the frame thread'): with the session and search threads in the utility class, as beryl_3d's session thread puts them (session::spawn, rust/beryl3d/crates/beryl_3d/src/session.rs), the opponent's rollouts a second were a median 0.88 of the same game's with them in the default class, the web app's (8 of 10 paired rounds lower, at machine load averages of 41 to 77). Late frames while the AI searched were no fewer with utility than with default, so utility bought drawing nothing measurable on this machine.

Do: choose the class the session thread starts in (default, or user-initiated with the asset workers moved, keeping every one of Beryl's threads below the frame thread's user-interactive class), change the doc's 'Threads' and C9's text to match, and measure again with the same driver: beryl3d --window none --agent expert --for 600s from a release build with --features tools, five rounds alternating --search-class utility and the chosen class, with and without --load 16:default. Add the numbers under 'Measurements'.

Acceptance criteria

The session thread's class is the chosen one; 'Measurements' gives five paired rounds of the chosen class against default and the late frames while the AI searched; 'Threads' says whether the 2% budget is met with it.
