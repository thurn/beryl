Description

Read the epic's contract first; this bead builds against it. Doc: docs/beryl-3d.md, 'Migration and compatibility' and 'The agent interface'.

The owner wants to know how close the tools can get Beryl 3D to the web, and agents need a procedure to follow.

Change:

  • Write the loop into the b3d skill (.claude/skills/b3d/SKILL.md, a section 'Matching the web'). Pick the worst target by match score. Then fix boxes, then style values, then unsupported properties (against match samples), then pixel regions worst first, then motion. Check with --only, lower web-match.json with --update, and push.
  • Run the loop for one working session on the desktop opening hand, one prompt with buttons, the battlefield mid-game and the same three on the phone. Record before-and-after counts and the remaining worst regions in a comment on the epic, with the crop pictures' paths. Record how far the 3D table's card placement is from the web's (box diff over cards), and file a bead under by-q44s with a recommendation: refit the camera to the web's card quads, or port the web's placement (ui/src/stage/layout.ts, desktop.ts, phone.ts).
  • File a bead under by-q44s for each remaining class of difference the tools found but that the loop couldn't close.

Files: .claude/skills/b3d/SKILL.md, tools/src/beryl_tools/beryl3d/match/, data/beryl3d/web-match.json.

Acceptance criteria

The skill section exists, the six targets' counts went down and are recorded on the epic, and the placement recommendation and the remaining-difference beads are filed.
