Description

Milestone 3 (plan "Kernel rules"): "A bitboard outside the kernel offers only order-free operations. Getting a sequence means naming an order the rules can see, such as battlefield order." The newest entry in docs/bugs.md is the class: declared attackers tapped in slot order, because combat::finish_attack walked a Bitboard.

Read first

docs/project-50k.md: Decisions K6, K7, K11 and K12, and "Crates", "State" and "Kernel rules" under Target architecture. rust/crates/beryl_kernel/src/lib.rs: its rustdoc is the kernel's API contract (who writes, mutator and getter naming, events, the board door, the legacy accessor, sets and orders); follow it, and change it in the same push when the code proves it wrong. enact brief shows the handoffs of the beads this one depends on.

Scope

  • beryl_kernel's Bitboard<S> (bitboard.rs): iter, first, nth and the public Words field give ascending slot order to any caller. Slots are no order at all: the deal and the shuffles put cards in them at random (architecture §14).
  • The set type other crates see keeps contains, insert, remove, is_empty, count, the set algebra and order-free folds (any, all, count matching, a sum). A caller that needs a sequence asks the state for one by name (contract, section f): battlefield order, a library top first, a graveyard's order, event.rs's in_order (which belongs in the kernel beside them), and the candidate order of a Decision.
  • Parity limits what may change. A Decision's candidates are listed in ascending slot order, a Choice is an index into that list, and saves and rollouts_never_change record choices. So every existing iteration keeps the order it has today. Each site becomes one of: an order-free operation (prove it by reading the loop body: no early exit that picks a member, no event pushed per member, no queue pushed per member); a named rules order that yields the same sequence the site gets today (where the order is rules-visible and today's is slot order, that is a bug: file it as a bead under by-w8gv with the scenario that shows it, do not fix it here); or the candidate order, named for what it is, with a comment on why slot numbers cannot leak into the rules through it.
  • Milestone 1's permuted-slot runs are the test that an iteration does not depend on slot numbers: every scenario must trace the same under three slot numberings (Slots::ALL, beryl_scenario/src/setup.rs). Run them (cargo test -p beryl_cards, cargo test -p beryl_scenario) after each file.
  • The player set: Mason note 4 on by-w8gv.5.1. interpret/scene.rs's Who (insert, contains, in_turn_order) is the order-free set with a named order that the plan asks for. Move it into the kernel as the one player set; do not add a second. Its two-player shortcuts (EVERYONE = 0b11, in_turn_order through active.opponent()) stay until the by-w8gv.5.13 (player API) bead.
  • The place set of the by-w8gv.5.11 (target places) bead, if it has landed, follows the same rule.

Size

When this was decomposed a rough grep found about 50 iteration sites in beryl_engine/src and about 60 across beryl_search, beryl_session, beryl_cli, beryl_cards and beryl_scenario. Make the methods private and count what the compiler lists. Convert beryl_kernel, beryl_engine and beryl_cards here. If the other crates add more than you can convert with the same care in this session, leave them compiling through one clearly named bridge (the candidate order), write the site-by-site mapping in a tier:sonnet follow-up bead under by-w8gv.5, and make the Warden (by-w8gv.5.16) depend on it. beryl_search/src/expert and frozen/ are frozen: change only what no longer compiles.

Constraints

  • Bitboard iteration is in the rollout's hottest loops. The named orders must compile to what the loops do today. Run just bench-count before and after and record both.

Parity and checks

Parity (plan K11) at the push: just check passes; the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds (cargo test -p beryl_bench rollouts_never_change); slow CI's counts lane (just count-gate, bar 405,276,238 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. No behavior changes: no rules fix, no new card, no new mechanic. Work the card-names and file-length allowlists down as files are touched (data/card-names-allowlist.json, data/file-length-allowlist.json; an entry moves with its file and its count only falls; a new file is under 800 lines). Rules code cites the Comprehensive Rules (AGENTS.md); keep the citations of code you move.

Acceptance criteria

Outside beryl_kernel a set of objects has no iter, first, nth or public word access: only order-free operations and the named orders of the contract; every former iteration in beryl_engine names a rules order, uses an order-free operation, or uses the candidate order with a comment saying why its result cannot depend on slot numbers; the kernel's player set replaces interpret/scene.rs's Who; the permuted-slot scenario runs pass; a comment on the bead tabulates the sites converted by kind; if crates outside beryl_engine were left for a follow-up, that bead is filed tier:sonnet with the mapping table and the Warden depends on it; parity holds.

Decisions and deviations:

  • The kernel's player set is PlayerSet, not Players as the contract said: beryl_card::Players is the vocabulary's word for which players an effect names, and the interpreter maps one to the other. The contract (beryl_kernel/src/lib.rs, 'Sets and orders' and 'Players') is amended; by-w8gv.5.13 reads PlayerSet where its description says Players.
  • State::players_in_turn_order takes the set to order (the contract listed it with no argument); the active player is the state's.
  • The order-free closures are Fn, so a caller cannot carry state from one member to the next. collapse's two lazy values became OnceCell for that.
  • Bitboard::at_least was added to the contract's list: 'at least n match' stops early, as the two sites it replaces did.
  • Candidates::objects and Observation::in_candidate_order are the candidate order for callers with a decision or an observation and no state.
  • mana.rs would have grown past its allowance by the comments the candidate order asks for, so Units and Groups moved to mana/units.rs (1730 -> 1586 lines); no code in them changed.
  • Not filed, not rules: the protocol sends attackers, tokens and a hand to the UI in candidate order, and RolloutPolicy::keep breaks a tie by it.

Counts (just count-gate, rollouts subject): 405,148,597 before; 405,072,554 after, on the same base. After the rebase over by-w8gv.5.5: 404,619,742 (bar 405,276,238). A first version cost +0.72%: sba::any_group written as any within any compared every pair twice in a check made after every action; the per-symbol callgrind diff found it.
