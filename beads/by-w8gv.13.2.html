Close reason

Card records carry first_set/first_released; data/set-groups.json (24 stable crates) and data/catalogs.json written by just cards, with path helpers

Description

Milestone 7b of Project 50k (docs/project-50k.md: K2, K8, "Card pool pipeline"). The set crates, the generated characteristics and the generated subtype list all need three facts the card store does not carry yet. This bead adds them as data just cards writes; it touches no Rust but the store's reader.

What to build

  1. First-printing set on every card record. data/card-store.tsv records carry set, which is the printing shown (pinned or original-art), not the first printing. Add the first printing's set code and release date to each card: record (for example first_set, first_released), from cards.py's first_of(found) (tools/src/beryl_tools/cards.py:165), which already picks a card's first real printing. Update the format's specification in the docstring of tools/src/beryl_tools/card_store.py and the Rust reader rust/crates/beryl_card_store/src/lib.rs (Record) with its tests; the Node reader only if it validates fields.
  2. Set groups. Plan K8: card files are "grouped by first-printing set, in many crates", 500 to 1,500 cards each. Write data/set-groups.json (generated by just cards, committed): an ordered list of groups, each a crate name and its set codes, covering every first-printing set in the pool (32,496 cards today). Requirements: deterministic; stable (a Scryfall refresh or a new set never moves an existing set to another group: new sets join the newest group or open a new one, so the file is extended, never reshuffled; the generator reads the existing file and keeps its assignments); sets ordered by release date so a group is an era; a set larger than 1,500 is a group by itself. Crate names are spelled-out, valid Cargo package names (for example cards_1993_1996; choose and record). Add Python helpers (card_store.py or paths.py): the group of a card, and the path its file belongs at, rust/cards/<group>/<set code>/<slug>.rs. A set code that is not a valid Rust module name (one starting with a digit, a keyword) needs a spelled rule: record it. The set-crates bead consumes exactly these helpers, so name them in your handoff.
  3. Catalogs. Write data/catalogs.json from Scryfall's catalog endpoints (https://api.scryfall.com/catalog/<name>: creature-types, planeswalker-types, land-types, artifact-types, enchantment-types, spell-types, battle-types, card-types, supertypes, keyword-abilities, keyword-actions; check Scryfall's API documentation for the current list rather than trusting this one). tools/src/beryl_tools/scryfall.py has http_get and the cache; follow its user agent and rate rules. Scryfall may have no catalog of counter kinds: if there is none, derive the list from the pool's Oracle text ("<kind> counter") in the same command and record the rule in the file. Sorted and stable, so a refresh diffs small. A test holds every subtype on a pool card's type_line to the catalogs.

just cards must stay a no-op on unchanged bulk data.

(3) First run partitions by DP (least distance outside 500..1500, then fewest groups): 24 groups of 762..1497 cards today. Later runs append: a new set joins the newest group while it stays <=1500, else opens one; a set with no cards left keeps its place. (4) Crate names cards_<y1><y2> / cards<y> from the years at creation, part<n> on collision, never renamed. (5) Set dir is the set's module name, not the raw code: code if a valid identifier and no Rust keyword, else set_<code> (10e -> set_10e); card file stem is the NFKD-folded ASCII words joined by _ (card_ prefix likewise: '+2 Mace' -> card_2_mace). All 32,496 paths are distinct (test). (6) Scryfall has no counter catalog: counter_kinds derived from Oracle text (word before 'counter(s)' after a quantity word; keyword-ability pairs like 'first strike'; +N/+N kinds), rule recorded in the file. Catalogs fetched also include ability-words; cached a week in the scryfall cache like bulk files.
