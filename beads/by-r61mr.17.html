Browser review used the same 4,707-ticket Beryl snapshot with imported comments and history in Wrangler and the legacy Python site. I checked 1,280 px and 375 px in both themes, with no horizontal overflow or browser errors.

First content in Chrome, in milliseconds (cold / service worker / prefetched click to DOM swap):

  • 1280 light: Worker 120 / 96 / 2.9, legacy 84 / 36 / 2.8.
  • 1280 dark: Worker 104 / 48 / 2.6, legacy 88 / 32 / 2.5.
  • 375 light: Worker 80 / 36 / 2.6, legacy 80 / 32 / 2.6.
  • 375 dark: Worker 92 / 48 / 2.9, legacy 80 / 32 / 2.6.

A tk title write updated the open home and ticket pages in 241 ms on the review checkout and 245 ms on the delivered commit. A separate real Chrome regression check preserved scroll, replayed after reconnect, rendered live project status, and showed that an offscreen card first scrolled into view after a live swap now prefetches without hover. The home and ticket page made zero additional HTTP requests in five minutes after settling, including any requests from the service worker. Both original WebSockets stayed open and delivered a new change after the idle interval.

Local macOS workerd process CPU across the full import was 1.40 ms on a cold home request, 0.13 ms median with a warm ETag, and at most 0.17 ms for the home and status fragments. All 4,707 ticket URLs returned 200 on the first-render sweep. Their median was 0.11 ms, p99 0.31 ms, and maximum 0.54 ms. The baseline at d868b32 measured 0.94 ms for cold home, 0.12 ms median for warm ETag, and 0.10 ms median, 0.30 ms p99, and 0.56 ms maximum for the same detail sweep. These are local simulator CPU measurements. Chrome first paint is elapsed browser time.

Side-by-side display differences:

  • Home has the same ordered 9 Active and 46 All cards in the same groups. The new page says Tickets, uses the prefix-free IDs and project URLs, and adds the requested Project status section for sessions, CI, staging, cutover and usage. The shorter IDs avoid the legacy breadcrumb truncation seen at 375 px.
  • r61mr, q44s.7.24 and q44s.3.55 have the same title, section headings and counts, relationships, comments and visible properties after normalizing ID prefixes. The first two also have matching changelogs. The third had no recorded events in the snapshot. The Worker shows its creation and start from the imported timestamps and labels them as inferred from the ticket, where the static legacy page says no changes were recorded.
  • The Worker was exposing the migration-only metadata object in Details in place of Owner and Started. Restored those fields, kept the ordinary metadata, and restored the start event when the timeline falls back to imported timestamps. Legacy ticket links still redirect to the canonical URL.
