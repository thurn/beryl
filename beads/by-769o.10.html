Close reason

Vizier leases in Enact b6fbdd3 + dc3c1c9; slow CI green

Description

This change is made in the Enact repository at ~/enact (scripts/enact.py, tests in tests/test_unit.py and tests/test_integration.py), not in Beryl. Read ~/enact/AGENTS.md first and follow that repository's workflow; record design decisions in ~/enact/docs/design.md. Keep changes backward compatible: projects and live sessions on every machine run this repository directly.

What we see

On 2026-11-13 Beryl's master sat for about three hours while slow CI failed and nobody repaired it. enact push prints the watch_ci notice, which makes the pushing session watch slow CI and repair a failure, only when vizier_active (enact.py, around line 2858) is false. It was true the whole time.

Why

vizier_active returns true when any epic has an enact_vizier_route_* key (written once by register_run), its run is not paused or blocked, and the epic is open or run_delivery says its delivery is incomplete. Nothing checks that the vizier is still running. In Beryl at the time:

  • by-gdn3, by-97g and by-sxgz were open epics with complete deliveries. by-gdn3 stays open because two children are deferred.
  • by-w8gv was closed, but its delivery stayed incomplete: run_delivery folds in Steward beads whose failure range overlaps the run, its commit list had grown to 455, and one of them was always the staging tip not yet on master.

What to change

  • Each machine only fixes its own slow-CI failures, so liveness is local: no lease is shared across machines. A vizier renews a lease each time it calls enact next (which it does in a loop with --wait) by writing .git/enact/vizier-<session>.json with the epic and time.
  • vizier_active becomes: on this machine, some run that is not paused, blocked or finished has a route for this host whose lease file is younger than its time to live (for example three times the vizier's --wait plus slack, around 20-30 minutes). Routes registered on other hosts are ignored. Whether the epic is open or its delivery complete no longer matters.
  • Steward beads filed for this machine (enact_ci_host) are the only ones a local vizier is expected to pick up. Drop or simplify any logic that routes a Steward bead to another machine's vizier, including the two-hour handover in roles/steward.md, if it exists only for that.
  • Use the same check wherever Enact routes Steward beads to viziers (schedule, vizier_routes) and in stranded().
  • A route with no lease at all (a vizier from before this change) counts as not alive, so old registrations stop holding runs active.

Done when

Unit tests cover a fresh lease, an expired lease, a missing lease and a route registered on another host (ignored), and an integration test shows a push printing watch_ci when the only registered vizier's lease has expired.
