Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Arrows', and the appendix table 'Arrows'.

How interface beads in this milestone fit together: ui/src/table/client.ts (bead "Table screen") is the manual table's pointer client. It owns the selection, sends actions with tableAct from ui/src/ipc.ts, and lets each interaction register handlers from its own file. Put your code in the file this bead names and register it; change client.ts only to add a registration point it lacks. Check your work on a live manual table in a headless browser: ui/scripts/table.mjs (same bead) starts one through the HTTP server and gives a Playwright page. Add one scripted check per behavior to ui/scripts/kept-table-<topic>.mjs and run it with just ui-test <title>.

File: ui/src/table/arrows.ts.

  • The pointer's aim event (a right-button drag from a card) draws a live arrow from the card to the pointer with the stage's existing arrow drawing (ui/src/stage/lines.ts, Aim.tsx); on release over a card or a player's life total it sends arrow. With a selection, each selected card gets an arrow in one batch.
  • An arrow drawn from a card in hand plays the card first: a batch of move to "play" then arrow. The host gives a card entering a public zone from a hand the same object, so the arrow's from is the played card; check beryl_table for how a batch names an object created or re-identified earlier in the same batch, and if it cannot, file a bead under M2 for beryl_table and send the two actions in sequence meanwhile.
  • The arrow's kind (attack, block, friendly or hostile target) is computed by the host and arrives in the view; draw the four kinds as engine games do.
  • Right-clicking an arrow removes it (the secondary event over an arrow: arrows are not stage nodes, so hit-test the pointer against the drawn lines in this file). Cmd+R sends clear_arrows.
  • A command with asks: "target" ("Attach to…", "Draw arrow…") starts the same aim from the card with a left click choosing the end: export pickTarget(from): Promise<Under | undefined> for the menu bead to call. Escape cancels it.

Checks (kept-table-arrows.mjs): an attack arrow during combat; a block arrow; a target arrow outside combat; arrow from hand plays first; right-click removes; Cmd+R clears only the viewer's arrows.

Acceptance criteria

Right-drag draws arrows of the host-computed kind, from one card or a selection; an arrow from hand plays the card first; right-click and Cmd+R remove; pickTarget exists for menu rows; each has a headless check.
