Agent randomness per decision, not a running stream

Close reason

Agents draw randomness per decision (AgentDecision::rng); rewind/next_decision gone; resume property test; by-bfav closed

Description

What was seen

In the authoring pilot (by-w8gv.15), three of four new cards failed at push in beryl_session's resume and save tests. The Warden (by-w8gv.15.21, commit 0a9d70e9) found the cause: a game resumed from its save replays the agent's recorded decisions without asking the agent, so a seeded agent restarted its random stream after a resume, and the resumed opponent played differently from the uninterrupted game. by-bfav (open) is the same bug seen earlier.

Why it could happen, and still can

The fix is opt-in per agent. Game::agent_skips_decision (beryl_session/src/game.rs:~487) calls Agent::rewind, but Agent::next_decision and Agent::rewind default to "none" and a no-op (beryl_search/src/lib.rs:67-81). Any agent that does not override both silently keeps its stream from the start. There are about nine implementations (six in beryl_search/src/lib.rs, mcts.rs:~405, long.rs:~1021, beryl_cli/src/specs/playground/opponent.rs:~135). RandomAgent is right only because it takes exactly one draw per decision, which a doc comment holds. The regression test (beryl_session/src/game/replaying.rs:~625-666) compares agent_next(), not the games.

Proposed design

Make an agent's randomness a pure function of the game seed and the agent's own decision index, handed in per call, so there is no stream to drift:

pub struct DecisionRng(SplitMix64); // seeded from (seed, AgentDecision(n))
trait Agent<L> {
    fn choose(&mut self, obs: Observation<'_, L>, d: &Decision<L>, rng: DecisionRng) -> Choice;
}

The session (and every other caller) counts the agent's decisions and builds the DecisionRng; replay counts the skipped ones the same way. Then next_decision, rewind and agent_skips_decision go away for every agent without other state. MCTS keeps search trees beyond its randomness, so it keeps resume_point and Mcts::resumed; that becomes the one documented exception instead of a default every agent must remember to override.

This changes what a seed means, so rollouts_never_change and frozen saves may move: if they do, record the reason in the commit and update the pinned values only for this change. The count gate must hold with no bump.

Test

A property test in beryl_session that, for a few seeds and both the random and the seeded search agents, resumes from the save after every decision index k and checks that the next 20 views equal the uninterrupted game's. This replaces the agent_next() comparison. Close by-bfav with this bead.

Acceptance criteria

Agent has no rewind/next_decision for stateless agents; a resume-at-every-decision test passes for random and seeded agents over several seeds; count gate holds with no bump; by-bfav closed.

Design as built: Agent::choose(obs, d, at: AgentDecision). Instead of a DecisionRng handed in, AgentDecision::rng(seed) gives the decision's stream (a pure function of the agent's seed and its own decision index), because agents already hold their seeds and Mcts/LongSearch already seed trees from (seed, decision). Callers count: the session keeps the agent's next index (skipped on replay, restored on undo); straight-through harnesses use AgentDecision::take. Stateful agents (Mcts, LongSearch, the specs playground Opponent) see a jump in 'at' and drop what they kept, which replaces rewind. next_decision, rewind and agent_skips_decision are removed.
