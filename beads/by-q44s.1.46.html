Close reason

step:V.B.S moments resolve from the client's script records; MOVING state set; staging cc0ada104

Description

The Page test driver (rust/beryl3d/crates/beryl_scene/src/driver/mod.rs) parses step:V.B.S moments (driver/moment.rs, Name::Step) but Page::time_of returns an error for them, and Page::moments lists no steps, because the client had no script clock when the driver was written. Once the script clock (by-q44s.1.4) plays scripts with the timings the session sends (by-q44s.1.25), resolve step:V.B.S as the middle of step S of beat B of view V's script: the view's arrival time on the recording's clock plus the middle of that step's span as the script clock lays it out. Expose the step's start and end from the client (or play module) without the driver re-deriving timing. List each step in Page::moments after its view. Tests in beryl_scene/tests/driver.rs: on a hand-built recording whose second view has a two-beat script with timings, step:2.0.0 and step:2.1.0 resolve to the expected times and seek lands mid-step with the subject moving.

Acceptance criteria

step:V.B.S moments resolve and are listed by Page::moments; seek to one shows the step's subject moving; the driver reads no duration except from the client's script clock; tests pass (just b3d cargo-test -p beryl_scene).

Handoff: driver/mod.rs: named_moments plays through with fresh(true) so the client keeps ScriptRecords; play_through calls step_moments(view) after each view's View/Prompt moments; script number == view index (one Show::push per Update, record() called in begin before any update). Step time = middle of ScriptRecord::span(step) (new, play/record.rs; real start/end via the record's start and rate), so catch-up rate is honoured and no timing is re-derived. Deviation from the bead text: times are measured from the script's actual start on the client clock, not the view's arrival, since a script waits behind earlier ones. Also: StateBits::MOVING was never set anywhere; table/scene.rs now sets it while Track::moving(t) (new, motion.rs: a segment under way whose from != to or arc != 0). Moments list is no longer time-sorted: steps follow their view though they play before it rests (as the bead asked). Test: tests/driver.rs step_moments_come_from_the_script_clock (step:2.0.0 = 600 ms, step:2.1.0 = 950 ms; seek shows the subject moving).
