Run log grows 180 MB a day and every reader scans it whole

  • Close reason
  • Description
  • Changelog

Close reason

Fixed in 1a2cea7bb (with docs in c2ad2c7c1): the run log is kept in hour files under $BERYL_CACHE/ci/runs/ with per-lane sums for each finished hour and day (runstore.py). The fast check's per-lane reads (selection.Chooser, deadline.Records) went from 2.3-3.6 s and 130-370 MB to 0.03-0.31 s with identical totals. Files are pruned after 31 days. The remaining full-window raw readers (budget, check_value, bisect) are filed as by-50275.

Description

Symptom

$BERYL_CACHE/ci/runs.jsonl (runlog.py) held 2,006,369 lines and 722 MB on 2026-11-15, all written since 2026-11-11: about 500,000 lines and 180 MB a day. Nothing rotates or compacts it. Every reader (selection.Chooser and deadline.Records in each fast-check lane, budget.py at the end of slow CI, bisect.py, check_value.py, nightly_failures.py, by ci-report) scans the whole file for a 30-day window, so at steady state the file would be about 5.4 GB.

Commit 100efece made read_log stream the file and skip other lanes' and hosts' lines before parsing. One lane's read went from 7 s and 5.7 GB to 1.5-4.9 s and 108-419 MB (load 44). Both numbers still grow linearly with the file, so at 30 days a rust-lane read would be roughly 30 s and 3 GB. bisect.py and by ci-report still parse every record into memory (they read all lanes).

Where the volume comes from (four days)

  • per-test passes: check/script 395k lines, ci/rust 326k, check/rust 269k, ci/oracle 228k, ci/script 218k
  • skips: check/ui-test 135k, check/shots 62k (a skipped check is logged per run although it has no seconds and no CPU)
  • each line repeats host, commit, tree, script, lane, load and chosen (~360 bytes a line)

Work

Pick a design that keeps reads bounded:

  1. Roll the log up: keep raw lines for a few days (bisect and nightly_failures need commit-level records), and fold older lines into a per-day, per-check summary (runs, failures, skips, seconds, cpu_seconds) that Tally can read directly.
  2. Stop logging per-run skips that nobody reads, or log them as one count per step.
  3. Have Chooser/Records read the summary plus the recent raw tail.

Done when: a lane's read in the fast check takes under 1 s and under 100 MB regardless of how many days the log covers, by ci-report --days 30 gives the same totals as before for the same window, and tests in tools/tests/test_runlog.py cover the rollup.
