Close reason

Scripts carry one StepTiming per step and stage_timings is wired; staging 7daf5c1ce

Description

Read first: docs/beryl-3d.md 'Timing a script' (this bead is change 2). Then rust/crates/beryl_session/src/script/build.rs (where the session builds a view's script; find the last point at which a script is complete), check.rs, timing.rs (the bead before this one wrote it), wire_fingerprint.rs and its tests, migrate.rs and save/, and the entry for save-breaks.json in data/AGENTS.md. Read ui/src/generated/protocol.ts's header for how it is regenerated.

Why. The bead before this one proved that Rust times every step as the web interface does. This bead makes the session send that timing. The web interface receives it and ignores it; the next bead makes it play it.

  • Script gains pub timing: Vec<StepTiming> with #[serde(default)], documented as in the doc. Step does not change, so no Step { act, cause } literal anywhere needs editing.
  • The session fills timing with time_script as the last thing it does to a script, after every pass that adds, removes, reorders or merges steps. Find those passes by reading build.rs and the modules it calls (follow.rs, settle.rs, staging.rs, spans.rs, stack.rs, moves.rs, mana.rs, attack.rs). The table time_script starts from is the one the seat's script was built against: the builder keeps one per seat.
  • A script with no timing is timed where it enters. A game loaded from a save, a replay or a recorded fixture made before this change has scripts whose timing is empty: time them when they are loaded, with the table they were built against, so that no client ever receives a script whose timing has a different length from its number of steps. If a loaded script cannot be timed because its table is not kept, say exactly where in a comment on this bead, give those scripts the timing a reset has (none, the script replaced by its view's reset), and add the case to the tests.
  • check.rs: a debug-build invariant that timing.len() equals the number of steps.
  • own_timings() -> OwnTimings in timing.rs. The web stage makes some steps itself while a prompt is open, at seven places in ui/src/stage/prompt.ts (search it for verb: "mark", verb: "point" and verb: "lift"). List the distinct shapes of act those places make (a mark beginning, by mark kind; a mark ending; a prompt's arrow beginning, to something on the stack or not; an arrow ending; the tray's lift beginning, sorted or not; the tray's lift ending). OwnStep is a closed enum with one variant per shape, and OwnTimings maps each to the StepTiming that timing_of gives an act of that shape. Where timing_of would fill after with the arrow's own two ends, OwnTimings cannot name them: add after_ends: bool to the entry instead, and say in its comment that the client fills after with its arrow's ends that are not players.
  • A session command stage_timings that returns OwnTimings, wired as the other commands are (rust/crates/beryl_app/src/lib.rs generate_handler!, ui/src/ipc.ts, and the fixture transport's answer for it). Nothing calls it yet.
  • Regenerate ui/src/generated/protocol.ts. Follow wire_fingerprint.rs's tests when they fail: they say what to update when the wire format changes on purpose.
  • just timing-parity still passes: change ui/scripts/timings.mjs to also read each script's sent timing and require it to equal what the web computes, so the check now covers what is actually sent.

Tests in beryl_session: a script built for a cast and its resolution carries one timing per step with the cases own spell cast and permanent resolves; a saved game from the corpus loads and every script it replays has full timing; own_timings has an entry for every OwnStep.

Run: just test-rust -p beryl_session -p beryl_app; just ui-typecheck; just ui-unit; just timing-parity; just smoke.

Acceptance criteria

Every script a client receives, live, from a save, from a replay or from a fixture, has one StepTiming per step, and a debug build asserts it; just timing-parity passes against the timing actually sent; stage_timings returns a StepTiming for every shape of step prompt.ts makes; the web interface's behavior is unchanged (just ui-unit, just ui-test verb: and just smoke pass).
