Close reason

Held-up draw leans, turns at HELD_TURNING and grows on screen only once edge-on; thrown rise capped at the room under the window top

Description

Found by the warden by-q44s.3.36 comparing rust/beryl3d/crates/beryl_scene/src/verbs/fly.rs with the web stage, with no comment explaining the differences:

  1. A drawn card held up (fly.rs held_up) never leans. The web leans it HELD_LEAN = 6 degrees times sin(pi * min(1, flying / HELD_TURNING.at)) as it leaves the library (ui/src/stage/drawn.ts, HELD_LEAN and leaning). The held bow's lean is 0 and nothing else adds one.
  2. Its size grows with the step's curve over the whole flight in. The web keeps it at library size until it is edge-on and then grows it by a smoothstep (drawn.ts grown(); its comment says growing over the whole flight made a card 1.8 times as wide edge-on).
  3. Its turn over uses DRAW_TURN / held.in (at 0.291, each 0.145 of the flight in), where the web uses HELD_TURNING {at 0.3, each 0.12} of the flight in (drawn.ts).
  4. Shape::Thrown (a permanent resolving onto the battlefield) always rises verbs.fly.thrown.height card widths; the web caps the rise at min(start.y, rest.y) (ui/src/stage/lift.ts lifted) so a card never rises past the far edge of the table, e.g. resolving into the opponent's back row.

Files: verbs/fly.rs (held_up, held_place, path_of), pose.rs (Shape, Turning), motion.rs (Segment::pose_at, through), data/beryl3d/space.json verbs.fly. Tests: tests/all/verbs_fly_draw.rs, tests/all/verbs_fly.rs.

Acceptance criteria

Each of the four matches the web or carries a comment saying why it differs; tests in verbs_fly_draw.rs / verbs_fly.rs measure the lean, the size while edge-on, the turn's moments and the capped rise; just b3d cargo-test, just b3d test and just b3d gate pass.

Handoff: verbs/fly.rs held_up now makes Shape::Held (pose.rs) when the drawn card turns over: bow as Bowed, plus lean held.lean=6 deg CCW about bow.axis by sin(pi*min(1, elapsed/turning.at)), and on-screen size (scale / depth, depth = eye - p.axis, eye stored in the shape) held at the library's until edge-on then smoothstep (motion.rs travelled/through, held_grown). Deviation from the bead's wording: the web holds on-screen WIDTH, not world scale; in 3D the card nears the camera, so holding world scale made it 1.5x wider edge-on, so I hold scale/depth instead (edge-on width now ~1.0x the library's). Turn uses held.turn {0.3, 0.12} of the flight in (new in space.json). Thrown rise is capped by fly.rs room(): min over start and rest of (card top - safe_area.top) in points / points-per-mm. On the desktop layout the opponent's hand sits above the rows, so the cap never engages in a plain window; the test uses a 260-point top inset to engage it. Tests: verbs_fly_draw.rs (held turn moments, lean + width, resize-through for Held) and verbs_fly.rs (thrown cap, new 'opponent permanent resolves' case). Rebased over by-q44s.3.50's Shape::Lifted with no interaction.
