Description

Read first: the epic by-q44s ('Rules for every bead'); rust/beryl3d/AGENTS.md; docs/beryl-3d.md 'Driving the running app' (live tree, live png, live do, --app; release builds contain no socket), 'The agent interface' (rules for every command: --help with two examples, output that begins with the command that reproduces it, bounded output, files named for the run), 'Times, moments, locators and actions'. Code: beryl_3d src/app.rs (the frame loop's before and after), src/options.rs, Cargo.toml (the tools feature that only debug and tool builds enable); beryl_scene src/driver/action.rs (parsing an action line) and src/agent/tree.rs (the tree printout); beryl_host src/drive.rs (how a drive script's actions become inputs on the display's clock); beryl_render's offscreen target (src/target.rs) and how b3d-render reads a frame back (beryl_3d src/pictures); tools/src/beryl_tools/beryl3d/cli.py and app.py.

Build:

  • beryl_3d src/live.rs, compiled only with the tools feature: a Unix socket at $TMPDIR/beryl3d-<process id>.sock, accepted on a thread of its own; each line is tree, png or do <action>. The frame loop takes requests from a channel in before and answers in after: tree prints the frame's tree as just b3d tree does; png reads the frame back from the GPU (Renderer::read_back in beryl_render, a new function: copy the presented texture to a buffer, map it on the next frame, never wait on the frame thread) and writes it to $BERYL_CACHE/b3d/out/live-<pid>-<n>.png; do gives the action's inputs through the frame loop on the next display tick, as a drive script's line is given. The socket file is removed when the app exits.
  • tools/src/beryl_tools/beryl3d/live.py: just b3d live tree, live png and live do '<action>', finding the one socket in $TMPDIR, or taking --app <process id> when several exist (and listing them when it is missing), each with a 10-second time limit.
  • A test that the release binary (cargo build --release -p beryl_3d) contains no beryl3d- socket path string: run as a step of the sweep, not the lane, because it builds release.

Tests: in beryl_3d, a test starts the live server on a temp path, sends tree while a windowless host replays pay-default and gets a tree with the prompt's buttons back; in tools, tests of the socket choice with zero, one and two sockets.

Run: just b3d cargo-test -p beryl_3d; just b3d app --fixture pay-default --for 20s in the background, then just b3d live tree, just b3d live do 'press button "Auto Pay"' and just b3d live png; just b3d lane.

Acceptance criteria

The tests pass; with just b3d app --fixture pay-default --for 20s running, just b3d live tree, live do and live png succeed (outputs and the PNG's path in a comment); the sweep step finds no socket path in the release binary.
