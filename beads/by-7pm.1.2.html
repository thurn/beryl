Description

Make beryl_app build and run as an Android app in a headless Android emulator, through Tauri 2's Android target, alongside the iOS target the previous bead in this lane added. Read the run epic's Decisions and Code map first, and the iOS bead's close reason (bd show the bead this one depends on) for what it set up.

What to do

  • Toolchain, added to just mobile-setup (the iOS bead created it in tools/src/beryl_tools/): nothing Android is installed. Install idempotently via Homebrew: a JDK the Android Gradle Plugin supports (the system Java is 27, likely too new; use e.g. openjdk@21 or temurin@21 and point JAVA_HOME at it only for Android builds), android-commandlinetools; then sdkmanager for platform-tools, a current platforms;android-XX, build-tools, ndk;<version Tauri recommends>, emulator, and an arm64-v8a system-images;...;google_apis;arm64-v8a image. License acceptance is authorized (epic Decision 4). Use ~/Library/Android/sdk as ANDROID_HOME; recipes must set ANDROID_HOME/NDK_HOME/JAVA_HOME themselves rather than relying on the user's shell profile. Rust target aarch64-linux-android (add x86_64-linux-android only if needed).
  • Tauri Android init; commit gen/android (no build output). Crate-type gains cdylib.
  • ureq's native-tls needs OpenSSL on Android: switch the mobile (or just Android) build to rustls via target-specific features, keeping desktop as is, or vendor OpenSSL; prefer rustls. Card art must download in the emulator.
  • Portrait only (screenOrientation in the manifest via Tauri config or the generated project). Safe areas/edge-to-edge: the hand runs under the gesture bar per DESIGN.md.
  • Paths: the iOS bead routed bugs::dir() and others through Tauri's path API; check they resolve on Android.
  • Recipes: just android (build debug APK, start an AVD with a window, install, launch) and just android-smoke (create the AVD if missing with avdmanager, start it headless -no-window -no-audio -no-boot-anim, wait for boot, install, launch with smoke mode on, pass when the UI reports ready, read via adb logcat or the journal pulled with adb exec-out run-as ca.thurn.beryl ..., then shut the emulator down). Smoke env: Android apps don't inherit env vars; pass smoke mode through an intent extra or a system property read in Rust, and keep lib.rs's smoke logic shared.
  • Slow CI: measure whether a cached cargo check --target aarch64-apple-ios-sim -p beryl_app and --target aarch64-linux-android fit just ci's 300 s budget (tools/src/beryl_tools/checks.py) on a warm cache. Add them as a lane only if they do; otherwise record the measurement in your close reason. Never add native builds to just check.
  • Desktop and iOS unchanged: just smoke, just ios-smoke, just test-rust pass.
  • Record exact commands, cold/warm build times, APK size and emulator boot time in your close reason. Add one line per new recipe to AGENTS.md "Testing your work".

Handoff: Android shell on staging (e7e6466f, e771afab).

  • gen/android committed. Patched by hand (keep if regenerating): app/build.gradle.kts rootDirRel -> ../../../../../../ui (the Rust task runs the Tauri CLI from ui/), BuildTask.kt defaults TAURI_APP_PATH, compileSdk/targetSdk 37->36 to match mobile-setup's platform, manifest screenOrientation=portrait.
  • beryl_app: crate-type += cdylib; ureq is target-specific (native-tls everywhere but Android, rustls there; art.rs picks the provider by cfg). Smoke on Android: lib.rs reads system property debug.beryl.smoke via /system/bin/getprop (unsafe_code is denied, so no FFI); ui_ready's cfg!(mobile) branch from the iOS bead journals and exits. ipc.ts artSchemeUrl uses http://beryl-art.localhost on Android (UA test).
  • tools: mobile.py gains android_setup (JDK openjdk@21, brew cask android-commandlinetools to bootstrap, sdkmanager into ~/Library/Android/sdk: cmdline-tools, platform-tools, emulator, platforms;android-36, build-tools;36.0.0, ndk;28.2.13676358, system-images;android-36;google_apis;arm64-v8a; licenses accepted), android_env(), ndk_env(), run_records() (journal parsing shared by both platforms), and 'by mobile-check'. android.py: android / android-smoke on AVD beryl_phone (pixel_8) at port 5584 (serial emulator-5584); smoke sets the property, waits for the pid to exit, reads logs/beryl.jsonl via run-as, resets the property and kills the emulator if it started it.
  • New slow-CI lane 'mobile' (checks.py): cargo check -p beryl_app for aarch64-apple-ios-sim and aarch64-linux-android. Measured: warm <1 s each; cold (empty target) 41 s + 17 s at load ~40; slow CI was ~190 s of 300. Uses check, not clippy: clippy on the Android target flags beryl_session/src/perturb.rs's thread_local (missing_const_for_thread_local false positive, it is already const).
  • Driving the emulator: adb -s emulator-5584 shell input / exec-out screencap -p; WebView DevTools via adb forward tcp:9333 localabstract:webview_devtools_remote_<pid> then plain CDP Runtime.evaluate (no Target wrapping, unlike iOS). Safe-area insets measured 51/0/0/0 (412x915 CSS px viewport).
  • Debug APK is 485 MB: Tauri's gradle keeps debug symbols in the .so (jniLibs.keepDebugSymbols); install is part of smoke time. Not changed.
