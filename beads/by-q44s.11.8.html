Close reason

Tier chosen at startup by an Enhanced probe, drops for late frames, Graphics setting; just b3d tiers in the sweep (4c3b2a37)

Description

Read first: the epic by-q44s ('Rules for every bead', rules 2, 9, 10 and 18); rust/beryl3d/AGENTS.md; docs/beryl-3d.md 'Choosing a tier', 'Hosts' (the rate rule) and 'Driving the running app' (the frame log).

The tier starts as Baseline, becomes Enhanced when a measurement before the first turn passes, steps down for the session when frames run late, and has a setting that can fix it.

What exists:

  • beryl_host src/rate.rs: RateRule::new(display_hz, tier_can_drop, thresholds), whose step_down returns Step::Baseline first when tier_can_drop; the thresholds frame_rate in data/beryl3d/space.json (settle_frames 120, late_intervals 1.5, window 60, misses 3). src/frames.rs: FrameLoop::paced(display_hz, tier_can_drop) and fixed_at, and pace, which hands the client Input::Tier(Tier::Baseline) on Step::Baseline. Every host passes false today: src/desktop.rs (paced(display_hz, false), with a comment that Enhanced is not built), src/windowless.rs and src/phone.rs.
  • beryl_3d src/frame_log.rs logs each rate step, with None for the tier's drop; src/options.rs has --slow-gpu (the windowless and desktop hosts hold each frame back that long); src/app.rs makes the renderer and starts the host; src/settings.rs saves beryl_scene::settings::Settings as settings.json.
  • beryl_scene src/settings.rs: Settings, Setting and Settings::apply.
  • Renderer::enhanced_available() and drawing a frame in Tier::Enhanced come from the renderer skeleton bead.

Build:

  • The setting. Graphics { Automatic, Baseline, Enhanced } in beryl_scene src/settings.rs, Settings::graphics (default Automatic) and Setting::Graphics(Graphics); beryl_3d src/settings.rs saves and loads it, a file without it reading as Automatic. The settings sheet's row for it is a bead of its own, after the settings screen.
  • The measurement, in beryl_3d src/tier.rs, probe(renderer, size, scale, display_hz) -> Probe { slowest, interval, chosen }: move board and permanent (with what only they use) from beryl_inspect src/stress.rs into a new beryl_scene module src/probe.rs behind the driver feature, as testing is, so the release app has the board, and make stress.rs call it, unchanged in output (the stress-255 gate numbers must not move). probe makes a Client for the window's size, hands it probe::board(255)'s first view and Input::Tier(Tier::Enhanced), builds one frame, then draws that frame into an offscreen Target of the window's physical size 30 times (enhanced.probe.frames in data/beryl3d/space.json, with share: 0.3333), each followed by Renderer::finish, timing each with std::time::Instant. chosen is Enhanced when the slowest is under share of 1 / display_hz and enhanced_available(); Baseline otherwise, and without drawing when Enhanced is not available.
  • When: in src/app.rs, after the renderer is made and before the frame loop's first frame, when graphics is Automatic. Baseline sends nothing; Enhanced sends Input::Tier(Tier::Enhanced) when enhanced_available() and logs why not otherwise. The doc says 'during the loading screen'; the frames are drawn offscreen before the first frame, so correct the doc's sentence to say that, with the measured time it adds on this Mac in a comment.
  • Stepping down: every host passes tier_can_drop = graphics == Automatic && tier == Enhanced to paced (desktop.rs, windowless.rs, phone.rs; delete the comments that say Enhanced is not built). A host paced by fixed_at (winit's redraw requests, which cannot ask for a lower rate) still runs the rule for the tier's drop: make fixed_at keep a RateRule whose rate steps are ignored, so that Step::Baseline reaches the client there too.
  • A change of the setting during play: Baseline sends Tier::Baseline; Enhanced sends Tier::Enhanced if available and turns off the drop; Automatic keeps the tier and allows the drop if it is Enhanced. No new measurement during play.
  • The log: one frame log line at startup, tier, with the setting, the probe's slowest and interval in milliseconds, and the chosen tier; the existing step line for the drop. just b3d frames prints both (tools/src/beryl_tools/beryl3d/app.py's summary).
  • --tier automatic|baseline|enhanced (tools builds only) sets graphics for the run, and --probe pass|fail (tools builds only) replaces the measurement's verdict, so that the tests do not depend on how loaded the machine is (rule 10). Both are passed through by just b3d app.

Tests:

  • beryl_host, in src/frames.rs's tests: a FrameLoop paced with tier_can_drop true, given frames whose gaps miss the rate 3 times in 60 after settling, hands the client Tier::Baseline within 120 animating frames of the first miss, before any rate step; with tier_can_drop false it never does; with fixed_at it does.
  • beryl_scene: Setting::Graphics applies; beryl_3d: the saved file round-trips graphics and a file without it loads as Automatic.
  • The app, with no window: just b3d app --window none --fixture verbs-zones --tier automatic --probe pass --slow-gpu 25ms --for 8s logs tier Enhanced at startup and the drop to Baseline within 120 animating frames after settling, and its frame log shows the drop before any rate step; with --tier enhanced instead it logs no drop; with --probe fail it logs Baseline at startup. Wrap these three runs in a test under tools/src/beryl_tools/beryl3d (the app's existing tests are the model) that reads the frame log, and add it to the sweep's own steps in sweep.py, not to the lane (it builds the app).
  • Nothing moves: the contract bead's tier check holds this; add no other.

Must not build: the settings sheet's row, the Enhanced tier's limits.

Run: just b3d cargo-test -p beryl_host; just b3d cargo-test -p beryl_scene; just b3d cargo-test -p beryl_3d; just b3d gate; just b3d app --window none --fixture verbs-zones --tier automatic --probe pass --slow-gpu 25ms --for 8s; just b3d frames; just b3d lane.

Handoff: the tier is now chosen at startup, drops during play, and follows a Graphics setting.

Files and functions:

  • beryl_scene: settings::Graphics { Automatic, Baseline, Enhanced }, Settings::graphics, Setting::Graphics (client/stops.rs does nothing extra for it). New probe module (driver feature): board, permanent, card, moved unchanged from beryl_inspect stress.rs, which now wraps probe::board (gate numbers unchanged; just b3d gate passed with no limit edited).
  • beryl_host frames.rs: Opening (handed to setup), Chosen { graphics, tier, enhanced_available } with tier_can_drop() and BASELINE; FrameLoop::with_tier, fixed_at(hz, tier_can_drop) (a RateRule whose lowest_hz is hz, so it never steps the rate but still drops the tier); next_request watches Request::SaveSettings and calls set_graphics when graphics changed. rate.rs: RateRule::set_tier_can_drop. Host run setup closures are now FnOnce(&mut Renderer, Opening) -> Chosen. Phone uses Chosen::BASELINE (no measurement on phones).
  • beryl_3d: tier.rs (probe, choose, setup, Tiered log line, Verdict); places.rs (path helpers moved out of app.rs to stay under 800 lines and clippy's 100-line function limit); options --tier, --probe; settings.json saves graphics (missing = automatic); frame log Line::Tier and Stepped::frame.
  • tools: tiers.py (just b3d tiers, three windowless runs checked from the frame log), sweep step tiers; app.py passes --tier/--probe and prints the tier line.
  • docs/beryl-3d.md "Choosing a tier" corrected: measured before the first frame, ~50 ms on this Mac.

Deviations from the bead:

  • The probe draws one unmeasured warm-up frame before the 30 measured ones. Without it the slowest frame was always the first (14.5-34 ms vs 2-4 ms for the rest, it creates the multisampled buffers and first uses each pipeline), so the measurement would never pick Enhanced even on an M5 Max.
  • The frame-loop tests are in beryl_host tests/all/tier.rs (the crate's frame tests live in tests/all, not in src/frames.rs).
  • Tiered also records took_ms, the time the choice added before the first frame.
  • --tier is written into the settings handed to the client, so a later SaveSettings never carries the saved value back and flips the tier.

Measured: windowless verbs-zones with --slow-gpu 25ms: tier Enhanced at startup, Baseline step at frame 125 (settle 120 + 3 misses), then 30 Hz. --tier enhanced: no drop. --probe fail: Baseline at startup. Unforced probe under load 20-30: slowest 1.8-3.7 ms, chose Enhanced.

Reviewer: check FrameLoop::set_graphics (Automatic reads client.tier(), so low memory keeps the drop off), and fixed_at's lowest_hz trick.

Note: on staging, just b3d cargo-test -p beryl_host alone fails to build because beryl_scene's manual/*.rs use serde_json unconditionally while serde_json is optional (driver feature). Building with -p beryl_3d alongside unifies the feature. Not caused by this bead.
