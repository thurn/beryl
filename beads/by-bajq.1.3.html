Close reason

Ability zones (graveyard/exile/stack) + state triggers; on-demand away set, no State bytes (20,056 unchanged); count 391,158,048 -> 391,158,539 (+491, no bump)

Description

What is wrong today

Only permanents and emblems listen (trigger::match_event walks the battlefield and the emblems). An ability that works in a graveyard (dredge), on the stack (storm, a spell's own "when you cast this") or in every zone has nowhere to be found. A state trigger ("when you control no Islands", "when this has no ice counters") is not an event at all.

What to build

Plan: Designs 1, "Abilities outside the battlefield" and "State triggers".

  1. Where an ability works (CR 113.6). Ability gains the zones it works in, defaulting from its kind: the battlefield for a permanent's, the stack for a spell's own. A builder sets another (.in_graveyard(), .on_the_stack(), .everywhere() for a characteristic-defining ability).
  2. GameTable records for each card the zones other than the battlefield in which some ability of it works, and a Capability says whether any card of the game has one.
  3. State keeps one bitboard: the slots in such a zone now. State::move_object writes it with one table read, behind the capability, in the arm that already handles the keyed slots. Trigger matching and (from group 3) the replacement lookup walk the battlefield's listeners, then that set.
  4. State triggers (CR 603.8). A TriggerEvent::State(Condition) is checked in sba::check behind its own kind. It does not trigger again while it is waiting or on the stack; find that by looking at the waiting triggers and the stack for the same source and ability, and store no flag.
  5. The card table refuses an ability whose zone the rules have no match for, as listener::listens_to refuses a trigger today.

No card lands here. Prove each part with a test definition in beryl_rules/src/tests/.

Derek Thurn2026-11-14

Deviation from the plan (Designs 1, recorded in docs/rules-coverage.md in the same push): the state keeps NO bitboard of objects outside the battlefield, so State<Small> is unchanged at 20,056 bytes (the bead expected +32). Reasons: State::move_object has no GameTable to ask which cards work where; the board door (Board::place, swap_cards, set_card) moves cards and changes identities too, so a cached set would go stale; and the zones' membership bitboards already say where each object is. trigger::away(s, t) computes the set on demand behind GameTable::zones_away(), which is empty in a game with no such card. Also no Capability bit: GameTable::listens_away() / zones_away() are the gate. Library and hand are refused (Unmatched::Zone) because hidden cards there can be dealt again (rebind, determinization). A non-triggered ability outside its kind's zone is refused (TableError::Zone) until a later group finds it there. Count gate: base 391,158,048 -> 391,158,539 (+491). Without #[cold] on the away and state paths the count rose by 0.15-0.25%, so keep them cold.
