Description

Read the epic's contract first; this bead builds against it. Doc: docs/beryl-3d.md, 'Migration and compatibility' and 'The agent interface'.

The tools only help if improvements stick. One agent's fix must not undo another's, and the web interface changes about 500 times a week.

Change:

  • Add just b3d match score [prefix] [--update] [--raise]. It runs boxes, styles, gaps and pixels for each test target and compares the counts with data/beryl3d/web-match.json (contract), failing for a target that went up or isn't listed. --update lowers entries. A count below its entry also fails, with the command that lowers it, as test-faults.json does.
  • Lane and sweep. Add the score for a fixed small set of targets (one desktop and one phone per screen kind, under 20 seconds) to just b3d lane (tools/src/beryl_tools/beryl3d/lane.py). Add the full score to the Beryl 3D sweep (sweep.py). Because a web change never runs Beryl 3D's checks (decision C17), the sweep is what catches drift: it files one bead per drifted target under the newest open milestone of by-q44s, naming the target and its worst elements.
  • Write the first web-match.json with every target's current counts.

Files: tools/src/beryl_tools/beryl3d/match/, lane.py, sweep.py, data/beryl3d/web-match.json, data/beryl3d/timeline-parity.json and test-faults.json (for the ratchet pattern), docs/checks.md (the beryl3d lane).

Acceptance criteria

match score holds every target, the lane runs its subset within budget, the sweep files drift beads, and web-match.json lists every target.
