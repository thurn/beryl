Description

The scale rehearsal (just scale --assert, tools/src/beryl_tools/scale.py and scale_workspace.py; by-w8gv.13.11) misses one budget of docs/project-50k.md's Acceptance after three attempts: the rebuild after one card edit (cargo check of the registry with scenarios after changing one card file) takes 3.7 s load-adjusted (3 CPU-s, 5.7 s wall at load 28 on 18 cores) at 50,000 clones in 37 set crates, against 2 s. The other three budgets are met: cold check 41.5 s / 60, release 16.1 s / 180, largest process 1.43 GiB / 4.

Where the time goes (cargo --timings, load about 23): about 0.6 s of cargo before any unit runs (a no-op check takes 0.62 s: fingerprinting the 37 crates' rerun-if-changed=. directories, 50,000 files); 0.33 s for the edited crate's build script (beryl_card_build, now at opt-level 3, reading the 36 MiB scratch store); 1.2 s for the incremental recheck of that whole crate of about 1,350 clones; 1.0 s for rechecking the registry (rust/crates/beryl_cards in the tree, the scratch registry crate in the rehearsal), which cargo always rebuilds when a dependency's metadata changes; these run one after another.

Ideas to measure, cheapest first: (1) what the registry's 1.0 s is (its 50,000-entry CARDS gathering by const evaluation in beryl_cards/src/lib.rs, gathered; its names module, measured as negligible) and whether CARDS can be gathered at first use like scenarios(); (2) whether the set crate's build script can skip rewriting cards.rs when its text is unchanged, and whether rerun-if-changed on each set directory instead of the crate root cuts cargo's stat work; (3) why an incremental recheck of a 1,350-card crate after one new item costs 1.2 s (rustc -Z self-profile on nightly); (4) smaller set crates only if data/set-groups.json's rule changes, which is the plan's decision K8. Land speedups in the real tree, re-run just scale --assert, and when the measure meets 2 s, drop the held limit in scale.py's BUDGETS (it holds the measure at 4.1 s meanwhile) and update docs/project-50k.md's Measurements.

Acceptance criteria

just scale --assert at 50,000 cards meets the plan's 2 s one-edit rebuild budget with the held limit removed from BUDGETS in scale.py, or the bead records each attempt's numbers and cause; the other three budgets still pass; just check passes.
