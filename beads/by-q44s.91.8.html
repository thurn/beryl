just b3d match motion prints per-element track differences and writes overlay plots, desktop and phone (7b9c454f7)

Description

Read the epic's contract first; this bead builds against it. Doc: docs/beryl-3d.md, 'Migration and compatibility' and 'The agent interface'.

timeline-parity holds each step's start, end and verb equal, but not the path an element takes, its size, its opacity or its easing frame by frame. Those are what make an animation feel different.

Change: add just b3d match motion <recording> --from <moment> --to <moment> [--only <locator>]. On the web, step page.clock one frame (1/60 s) at a time and dump boxes, opacity and transforms of the matched elements at each frame. In Beryl 3D, use the stepped clock to the same times. For each element, print the largest position, size and opacity differences and the frame where each occurs. Write a plot picture per element: x, y, scale and opacity over time, both clients overlaid. A 3D card's box is its projected screen rectangle.

Files: tools/src/beryl_tools/beryl3d/match/, tools/src/beryl_tools/beryl3d/motion_film.py, rust/beryl3d/crates/beryl_inspect/src/cli/timeline.rs, ui/scripts/motion.mjs (read only).

Handoff: just b3d match motion <recording> --from <moment> --to <moment> [--layout] [--only <locator>] is on staging (7b9c454f7).

Where things are:

  • Rust: b3d tree --records --to <moment> (beryl_inspect/src/cli/view.rs records/record_value) prints one JSON line per 60 Hz frame from --at to --to, adding frame, t_ms to the microsecond and views_given_ms (from the new Page::views_given_at in beryl_scene/src/driver/cues.rs, which went there because driver/mod.rs is at 800 lines). Test: records_to_a_later_moment_print_one_line_a_frame_60_to_the_second.
  • Web: dump.mjs's page setup and records moved to match/page.mjs (withPage, records({roles, only, light})). light skips the text lines and adds a stable track per DOM node. match/motion.mjs steps the paused clock to each time. CSS and Web Animations are paused when first seen and moved on by hand, because Playwright's clock doesn't drive the document timeline; an animation that reaches its end gets finish().
  • Deviation from the bead's plan: opening the page at the span's view (as snapshot does) showed the view's animation already finished, because events the page opens with are delivered as past events and drawn at rest. So motion.py schedule opens the page with the views given before the span's first batch and calls window.berylFixture.advance() at the times Beryl 3D got each later batch. It mirrors playsOn from ui/src/ipc.ts to count advances, and notes when the web gets more views than Beryl 3D had.
  • Python: match/tracks.py (pure: name_tracks follows a Beryl 3D element by the #id in its locator, so card #259 → card "Snapcaster Mage" #259 stays one track; partners uses majority vote over per-frame joined.join; moves, difference, present). match/plot.py writes an SVG (x, y, scale = width / web's last width, opacity; Beryl 3D dashed), and plot.mjs renders PNGs. snapshot.py's page runner is split into page_job(t, messages, at, art, out) + run_page(script, job, out, serving). Output goes in <snapshot dir>/motion-to-<to>/: motion.txt, motion.json, web.json, plots/.
  • Tests: tools/tests/test_beryl3d_match_motion.py (six tests). Pyre and clippy are clean.

Verified by hand: verbs-zones 460→1300ms desktop (19 moving pairs; the Thirst for Discovery fly, the Island taps) and phone --only 'card "Thirst', plus 4360→5300ms (a vanish: Counterspell's opacity differs by 0.25, and Snapcaster leaves a frame apart). Each run takes about 8 s. I read the plots. Tracks agree in shape for the fly, and the tap's scale overshoots in Beryl 3D but not on the web.

Known limits for reviewers: the web's animation starts about one frame later than Beryl 3D's (the page takes a frame to react to an advance). The "moving on the web with no partner" list is noisy (card-internal regions), so only 20 are shown. The span is cut at the next view arrival only if view changes; views given in one batch play in sequence on both sides.

Also pushed 28644bf26, which raises tests.median_frames in gates.json from 137 to 139. The fast check failed on staging's tip because 12270c783's new card scenarios added interface tests; its cards-only push never ran the beryl3d-interface lane.
