Description

Read the epic by-r61mr first: it holds the decisions, the code map and the directory layout this bead assumes. The work is in the Enact repository (~/enact) unless this bead says otherwise, delivered with that repository's own enact worktree create and enact push.

Create the empty projects the other beads fill in, so they can start in parallel without colliding on set-up files.

  • server/: a TypeScript Cloudflare Worker with one SQLite-backed Durable Object class declared in server/wrangler.toml, a static assets directory server/static/, and tests that run in wrangler's local simulator (vitest with Cloudflare's Workers pool). One route returns a version string and one test calls it.
  • cli/: a Rust crate that builds a binary named tk with one subcommand, tk version. Choose the HTTP and TLS crates here and say in cli/Cargo.toml comments what each replaces. The binary must build on Apple silicon macOS and on Windows.
  • Checks: extend the fast and slow commands in .enact.toml so the Worker's tests and cargo test run, staying inside the budgets in Enact's AGENTS.md. Update AGENTS.md, which says today that Enact is skill text plus one stdlib script.
  • wrangler: run it through npx (it is not on PATH). Run npx wrangler whoami. If no login is saved on this machine, record that in a comment on the epic and carry on: nothing before the production deploy needs it.

Acceptance criteria

npm test in server/ passes against the local simulator, cargo test in cli/ passes and cli/target/release/tk version prints a version. enact push runs both in its fast check. A comment on the epic states whether wrangler whoami shows a login on this machine.
