Close reason

Enact logs every ownership-lock wait, hold and sync to lock-waits.jsonl (enact ca1b065, CI green)

Description

Sessions often wait on Enact's ownership lock, but nothing records how long. Over 7 days on jarvis (efficiency store, tool_calls), enact meta averaged 48 s over 795 calls, enact start 53 s, enact close 51 s and enact worktree 76 s. The only evidence of lock waiting is the still waiting for the ownership lock, held by ... line on stderr, and the efficiency store keeps no tool output. The vizier for this epic saw its enact next give up after 180 s twice in one afternoon while another epic's next held the lock.

Change (in the Enact repository, ~/enact, not Beryl)

Follow ~/enact/AGENTS.md: python3 scripts/enact.py worktree create lock-log in ~/enact, commit there, python3 scripts/enact.py push there, watch slow CI if it prints watch_ci. Keep it stdlib-only, cross-platform and backward compatible.

  • In ownership_lock (scripts/enact.py, around line 646), append one JSON line per acquisition to a log in the clone's state directory (repo.state / "lock-waits.jsonl", next to ownership.lock): time (ISO UTC, when the wait began), pid, command (subcommand and bead, as holder already records from sys.argv[:4]), waited_s, held_s (written when the lock is released), outcome (acquired or gave_up), and for a wait over 1 s, the holder command seen while waiting. One line at release with both numbers is simplest. Writing must never fail the command (suppress OSError), and the cost must be one small append.
  • Also time the remote syncs, since cmd_meta calls sync(repo) twice (line ~1068) and each one is a Dolt pull/push: add sync_s (seconds spent in sync/sync_beads while holding the lock) to the same line.
  • Rotate or cap the file (for example keep the last 50,000 lines, or start a new file each month), so it never grows without bound.
  • Document the file and its fields in docs/design.md.
  • Unit test in tests/test_unit.py: two processes or two lock contexts, the second waits, both lines are written with plausible waited_s and held_s; and a gave-up wait writes outcome: gave_up.

Bead by-ig5e.22 (the efficiency ingest) reads this file; tell it the exact path and fields in your handoff comment. Bead by-ig5e.23 (making slow calls faster) uses the numbers.

Acceptance criteria

Every ownership-lock acquisition in the Enact helper appends one JSON line with waited_s, held_s, sync_s, command, holder and outcome to lock-waits.jsonl in the clone state directory; writing it never fails a command; the file is capped; unit tests cover a contended wait and a give-up; landed through Enact's own push with slow CI green.
