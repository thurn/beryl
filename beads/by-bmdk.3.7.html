Close reason

Manual stage state and face-down previews shipped to staging with 25 replayed steps, focused UI coverage and three byte-identical engine shots.

Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'The table' (the field rules) and 'Placement'.

Milestone 1 added fields to the view that the stage ignores. Draw them. Files: ui/src/stage/table.ts and layout.ts (rows), ui/src/stage/Faces.tsx (a card's face), ui/src/stage/drawn.ts; read ui/AGENTS.md first.

  • ObjectView.pinned: the card sits in that row instead of the one its types give.
  • ObjectView.face: back draws the second face of a two-faced card; down draws a card back. A face-down card the viewer knows shows its face in the hover preview only; one the viewer does not know shows no preview.
  • note: a short line on the card, cut with an ellipsis; the whole note is in the preview.
  • named_counters: drawn like the existing counters with the name as the label; a name longer than 6 characters is cut. On a player, beside the life total, after the mana symbols; shown once nonzero.
  • doesnt_untap: reuse an existing indicator if the engine game has one for "doesn't untap" effects (search ui/src/stage for untap); otherwise a small lock glyph in the design system's icon style at the card's corner.
  • An attached card sits tucked under its host and moves with it, as engine games draw an Aura or Equipment (exception 6 in UI Conventions draws linked exile the same way; reuse that layout code).
  • ZoneName.sideboard: not on the table; it appears only in a viewer (later bead).
  • An ability marker on the stack: drawn as engine games draw an ability on the stack.

To test before the adapter records live tables, construct one manual GameUpdate with every field above using the neutral constructors in rust/crates/beryl_session/src/protocol/neutral.rs. Register a generated board fixture in ui/fixtures.json, following rust/crates/beryl_cli/src/fixture.rs, so the stage audits and just ui-shots can replay it. If the recorder from by-bmdk.3.6 is available, use it. Record a board definition or actions so the fixture is regenerated by the normal tooling. Engine fixtures must look identical: run just ui-shots for three engine fixtures before and after and compare.

Run cd ui && npm run typecheck && npm test and just ui-test for the new fixture. Add not-seen entries to data/ui-conventions.json for the note and the face-down preview rule; just conventions.

Acceptance criteria

Each new view field is drawn as described and covered by the table-drawn fixture under the generic audits; engine fixtures render unchanged; UI conventions entries exist.
