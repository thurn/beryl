Close reason

A spec's first view starts over with a reset from its scripts; stack check added; 3 Subtlety moments left to by-w8gv.21.60

Description

The stage's motion audit (just specs --motion --stage, ui/scripts/stage-audit.mjs) reports still ... ability 1 leaves the stack (resolve): nothing of it was there to go in moments that open with a spell or ability already on the stack: the page never had a node for it, and the script that follows takes it off the stack all the same. Two causes, both in what a page is first shown.

  1. A spec moment's first view is sent with the script it was built with, not a reset. beryl_cli's spec server (rust/crates/beryl_cli/src/specs/serve.rs record_view) shows as a seat's first view the first one after the moment's setup, its events cleared, with whatever script the session wrote for it: just specs --script the-wandering-emperor --moment 1-grows-a-creature-and-gives-it-first-strike-pass prints view 1 "(no steps)" where a seat's first view should say "reset" (beryl_session's script/mod.rs: "A seat's first script, and the script beside an undone view, has Script::reset"), and view 2 then has "set a1 ..." with no emerge before it. The stage starts over from a first view with no reset as if it had none (ui/src/stage/stage.ts play: tableOf(view, script?.reset)), so the abilities on that view's stack get no numbers and no nodes, and their lines and marks have nothing to be drawn on.
  2. A view built while a spell or ability resolves says what is resolving only to the one deciding (DecisionView::resolving; ui/src/stage/table.ts tabled puts it back on top for them). A viewer whose opponent decides, or one whose view only plays on, gets a stack list without it. When such a view is the first a page sees (a spec moment that opens at the ask, a page reloaded or a game resumed mid-resolution, an undone view), its reset has no word of the item: just specs --motion --stage thundertrap-trainer --moment takes-a-spell-ask-2 from their seat.

Read first: the epic by-w8gv.21; rust/crates/beryl_session/src/script/mod.rs (Reset, Names) and script/table.rs (Table::of); rust/crates/beryl_cli/src/specs/serve.rs (record_view, current) and specs/start.rs (the status rewrite, which by-w8gv.21.24 taught to keep the resolving item on the watched stack); ui/src/stage/table.ts (tableOf, tabled); by-w8gv.21.24's handoff.

What to do

  • The spec server sends a seat's first view with a reset written from the session's own table at that view (the abilities' numbers as the scripts after it name them), so the stage starts with a node for everything the next script moves. If the session has no way to write a reset for a view it has already sent, add one beside where a seat's first script and an undone view's are written.
  • A reset names what is resolving for every seat: either the view's stack lists it for one who is not deciding, or the reset carries it. Hold it with a script check (script/check.rs): a script never takes off the stack what the table it plays over does not hold.
  • No change to a view a game in progress sends between two scripts: the replay check, the frozen corpus and the count gate hold with no bump.

Part 2 (a reset names what is resolving for every seat): game views already list it for a non-deciding viewer (Moment::Thinking); the spec stand-in's Deciding->Playing rewrite was the gap, which by-w8gv.21.24's start.rs fix closed and which landed while this was in work (I had the same change; the rebase dropped it).
