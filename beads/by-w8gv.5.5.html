Close reason

Kernel queries (card_behind, copiable, mana_value, controller, power, toughness) replace raw card reads; State::card and Object::card are kernel-private; counts 404,271,601 -> 403,971,755

Description

Milestone 3 (plan K6, "Kernel rules"): other crates read derived answers, not raw fields. "card_behind(object) is nothing for a token; mana_value(object) accounts for copies and faces."

Read first

docs/project-50k.md: Decisions K6, K7, K11 and K12, and "Crates", "State" and "Kernel rules" under Target architecture. rust/crates/beryl_kernel/src/lib.rs: its rustdoc is the kernel's API contract (who writes, mutator and getter naming, events, the board door, the legacy accessor, sets and orders); follow it, and change it in the same push when the code proves it wrong. enact brief shows the handoffs of the beads this one depends on.

Scope

  • The raw reads to replace: State::card(slot) (the CardIx an object was built from, which for a token or a copy is not "its card"), Object::card, Object::face used to pick a face's printed values, Object::base_controller, and the t.def(card) and t.facts(card, face) chains built on them. Find them by making State::card and the card getter private to the kernel and reading the compiler's list across the workspace.
  • Mason note 5 on by-w8gv.5.1: the interpreter wrote these queries for itself in rust/crates/beryl_engine/src/interpret/scene.rs: Scene::controller (a permanent's or spell's controller, else its owner, CR 108.4a; scans the stack), Scene::mana_value (a spell's with its X, CR 202.3e, else filter::mana_value), Scene::power and Scene::toughness (derived on the battlefield, printed elsewhere). They become the kernel's, and the interpreter calls them.
  • Copiable values (CR 707.2): one query that answers "what would a copy of this see" (the face up, or face down's blank characteristics, CR 708.2), used by the token-copy and clone paths in event.rs (create_tokens, TokenEntry) and effect.rs instead of reading card and face.
  • docs/bugs.md: read every entry, and for each one a query would have prevented, make the wrong read impossible to write (a private getter, a query with the rule in its name). List them in a comment on the bead. Read the plan's audit ("What the audit found", Bugs).
  • Callers outside the engine: beryl_search (values.rs, rollout.rs, mcts.rs, expert/, frozen/), beryl_session (protocol.rs, preview.rs, game.rs), beryl_cards' bodies and beryl_cli read cards through Observation::card and State::card. Observation::card (None when the viewer does not know the card) stays; it and the queries are the two doors. beryl_search/src/expert and frozen/ are frozen: change only what no longer compiles there.

Constraints

  • A query must cost what the read it replaces cost. Scene::controller scans the stack today only off the battlefield; keep the fast path first. Run just bench-count before and after and record both.
  • The queries read the GameTable. Do not cache anything new in State.
  • Milestone 4 moves cast-time facts (kicked, X, what it exiled) into Memos. Do not add queries for them; they stay behind the legacy accessor.

Parity and checks

Parity (plan K11) at the push: just check passes; the frozen save corpus replays (cargo test -p beryl_session --test corpus); rollouts_never_change holds (cargo test -p beryl_bench rollouts_never_change); slow CI's counts lane (just count-gate, bar 405,276,238 instructions, 1% tolerance, rust/crates/beryl_bench/count-gate.toml) passes with no bump to the bar. No behavior changes: no rules fix, no new card, no new mechanic. Work the card-names and file-length allowlists down as files are touched (data/card-names-allowlist.json, data/file-length-allowlist.json; an entry moves with its file and its count only falls; a new file is under 800 lines). Rules code cites the Comprehensive Rules (AGENTS.md); keep the citations of code you move.

Acceptance criteria

beryl_kernel has queries for the card behind an object (None for a token), its mana value (with X on the stack, CR 202.3), its copiable values, its controller in any zone, and its power and toughness in any zone, each citing its rule; State::card, Object::card and the raw t.def(state.card(slot)) chain are not callable outside the kernel; Scene::controller, Scene::mana_value, Scene::power, Scene::toughness and filter::mana_value are gone or one-line calls of the kernel's; a kernel test covers each query for a token, a face-down permanent, a copy and a double-faced card where the 47 cards allow; a comment on the bead lists which docs/bugs.md entries the queries now make inexpressible; parity holds.

Decisions and deviations (executor).

Queries built (beryl_kernel/src/query.rs): State::card_behind, card_def, copiable -> Copiable, mana_value, controller, power, toughness, definition_name. Counts: 404,271,601 before, 403,971,755 after (count-gate bar 405,276,238).

Deviations from the contract's sketch, amended in lib.rs:

  1. copiable(slot) takes no table. Copiable keeps the definition index and face privately and answers face(t), facts(t), has_rule, may_listen, name, power, toughness. It never returns the index: record(t) gives the (index, face) a record or a token copy keeps, which for a face-down permanent is FACE_DOWN_COPY's; key() gives an opaque DefinitionKey that compares, orders and indexes a per-definition table (mana.rs classes, engine::collapse, CardValues::of). So a face-down read on the hot path costs no branch, and the hidden card cannot reach a record.
  2. controller does not scan the stack. The zone move resets base_controller to the owner and only become_spell and arrive name another, so off the battlefield it is one read; invariants.rs already checks that. Scene::controller's stack scan is gone.
  3. make_token takes a Copiable and returns the face the token enters with (CR 707.8a). TokenEntry lost one_one and face; EffectCtx::copiable_values is gone; create_tokens_of and create_tokens_of_for take a Copiable.
  4. card_def(t, slot) is card_behind as a definition, for the sites that read a card's other faces (cast options, land face, turn face up, the look-ahead).
  5. definition_name(t, slot): the definition's name whichever face is up. event::move order (the future in_game_order of by-w8gv.5.6) sorts by it, and tests, checkpoints and the transcript name objects by it. Parity needed the exact old key there.
  6. Object::base_controller is private too; State::base_controller stays for layers.rs (the layer-2 start) and checkpoint.rs.

Three unreachable differences in behavior, in docs/bugs.md: a filter's mana value now counts a spell's X; a 1/1-by-exception token reads 1/1 off the battlefield; last-known information of a face-down permanent names the blank card. No card of the pool reaches them; corpus replay, rollouts_never_change and every scenario hold.

Cost note for later beads: in mana.rs Funds, comparing each class with a tuple built inline instead of a bound variable cost 0.7M instructions (404.58M against 403.83M). Found by bisecting the count gate.

Not done here: Observation::card and the t.def(obs.card(slot)?) chains in beryl_search and beryl_session stay, as the bead says. Board::place_token still takes a CardIx from a name lookup.

docs/bugs.md entries the queries now make inexpressible outside the kernel:

  1. 'Exile costs counted a Treasure sacrificed for mana as a graveyard card' (CR 111.6): card_behind is None for a token; cast.rs's two cost filters now ask it instead of testing the TOKEN flag by hand.
  2. 'The battlefield's cached trigger listeners counted face-down permanents by their hidden card' (CR 708.2a): Copiable::may_listen is 0 face down, and no caller can reach GameTable::listens with an object's index.
  3. 'A token copying a face-down permanent still held the original's hidden card' (CR 707.2, 708.2): State::make_token takes a Copiable, whose record is FACE_DOWN_COPY for a face-down original.
  4. 'Fractured Identity's copy of a face-down permanent kept the original's card and face down': the same, and face_down::face_up_cost asks card_def, which a token answers with none.
  5. 'A token copy of a transformed double-faced permanent took its front face's mana value' (CR 712.8e): State::mana_value is the only mana value; filter::mana_value and Scene::mana_value are gone.
  6. Partly, 'an answer named a permanent too loosely to tell a token copy from its card': card_behind tells them apart; the save's description is beryl_session's.

Not covered by a query: the slot-order entries (by-w8gv.5.6), knowledge (by-w8gv.5.4), Winds of Abandon's owner/controller split (a card body's logic).

In beryl_engine: scene.rs lost controller, power, toughness, mana_value; event.rs TokenEntry is {tapped, attacking} and create_tokens takes a Copiable; effect.rs lost copiable_values; cast.rs activated() returns (Copiable, FaceAbility); mana.rs classes key on DefinitionKey; layers.rs, trigger.rs, sba.rs, face_down.rs, reference.rs, engine.rs, run.rs. beryl_search: values.rs CardValues::of(DefinitionKey), eval.rs, expert combat (frozen too, only what no longer compiled). beryl_session, beryl_cli, beryl_scenario, beryl_cards: call sites only.

What replaced what:

  • t.def(s.card(slot)).face(o.face) -> s.copiable(slot).face(t); t.facts(card, face) -> s.copiable(slot).facts(t); may_have_rule && has_rule -> copiable.has_rule(t, rule); t.listens(card) -> copiable.may_listen(t).
  • a card's other faces (cast, land, turn face up) -> s.card_def(t, slot)? or s.copiable(slot).turned(face).face(t) for one chosen face.
  • a record's card and face -> s.copiable(slot).record(t).
  • 'same card' and 'order by card' -> s.copiable(slot).key().
  • t.def(s.card(slot)).name in tests and tools -> s.definition_name(t, slot).

Gotchas: (1) Copiable::record costs a branch on face down; keep it off loops over every permanent (use face, facts, key there). (2) In hot solver code a tuple or struct built inside a comparison closure is not free: bisect with just count-gate. (3) cast.rs and mana.rs sit at their length allowance; mana.rs names crate::query::DefinitionKey and crate::state::CastPermission by path to save import lines. (4) The lock test longthink::files::a_second_lock_names_the_first_holder failed once under cargo test --workspace and passed alone and on two reruns; it is not touched here.

Counts: 404,271,601 before; 403,971,755 after, on the bead's base. After rebasing over by-w8gv.5.8 (which measured 404,879,191): 404,525,125. Not measured after the last rebase over the index-types change.

A reviewer should check: Copiable's rule citations and that record() is the only way an index leaves it; State::controller against the deleted Scene::controller for a spell (it reads base_controller, no stack scan); the three unreachable behavior differences in docs/bugs.md; the kernel tests' coverage against the acceptance list.

Verified: workspace tests, clippy, corpus replay, rollouts_never_change, kernel query tests, the fast check at push (oracle lane included). Not verified by me: slow CI on 05e675a5, running now.
