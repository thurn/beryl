Description

Read first: docs/beryl-3d.md 'Timeline parity' and 'Timing a script'; rust/beryl3d/AGENTS.md; the comments on by-q44s.3.35.

After by-q44s.3.35, about 120 recordings in data/beryl3d/timeline-parity.json still differ in steps the session sent, not only in the steps a prompt makes (own steps). Each differs because the web stage's beat ends depend on its own layout, which Beryl 3D does not share on purpose:

  1. Closing up after a vanish (closedBy and roomIn in ui/src/stage/tracks.ts, #lay and #left in ui/src/stage/stage.ts). The web stage's beat waits for each card whose resting place the step moved. Which cards move depends on the layout. Examples: aangs-iceberg/exiles-a-permanent-until-it-leaves-waterbend-taps-a-creature-to-pay/opponent (the web keeps creatures and other permanents in one shared row, so Aang's Iceberg slides when Geist of the Moors is exiled; Beryl 3D's separate rows move nothing), combat-attackers/opponent view 95 (the web's exile pile shifts up when the stack empties). In the other direction, blood-artist/dying-with-two-others-triggers-three-times/opponent: the web logs a closing track for slot 0 after three creatures are destroyed in one beat, but its beat does not wait for it. Find what replaces that track before closedBy runs.
  2. A strike that would cross an earlier strike waits (awaited in ui/src/stage/enter.ts), in steps of LOOK.wait, from the web layout's paths. Beryl 3D has no port of it: combat-declare/opponent view 32, stress-verbs/you.

Choose one of two fixes and record the choice here: port the web stage's rules into Beryl 3D using its own geometry, accepting that some recordings can never agree; or make the wait independent of layout in the session (beryl_protocol script::timing sends closes for every vanish that leaves room), which changes the web stage too and needs decision C1 revisited.

How to see the web side: copy ui/src and ui/scripts/timeline.mjs to a scratch directory, link ui/node_modules and data/ next to it, log from #lay when carried returns a track with closes, and from #tick where closedBy extends a beat. In Beryl 3D, the slides that extend a beat are where note_closing is called in rust/beryl3d/crates/beryl_scene/src/play/step.rs.

Done when every recording left in the list differs only in own steps, or each one left is named here with the layout difference that keeps it.
