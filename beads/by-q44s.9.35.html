Close reason

Atlas overflow at scale 2: prepared glyphs now leave room for icons and requested glyphs; test at scales 1-3

Description

Symptom: in the desktop app, text is missing letters and symbols. The start screen's play/draw message reads "You won the __ip" (letters drawn as gaps or underscores). Mana symbols in text never appear, and neither does a planeswalker's loyalty. Icons are missing too: the menu button's circle has no gear in it.

All of these come from the same atlas: glyphs and icons are rasterized on the glyph worker and sent as AssetReady::Glyphs / AssetReady::Icons, then uploaded into atlas pages. So one cause is likely: pages not uploaded or replaced on rescale, cells looked up at the wrong scale, or the shader's Glyph / Icon branch sampling the wrong page.

Files: rust/beryl3d/crates/beryl_assets/src/glyphs.rs (GlyphWorker, pages, rescale, Icons), beryl_assets/src/icons.rs, beryl_assets/src/svg.rs, beryl_scene/src/client/screen.rs (handling AssetReady::Glyphs and ::Icons), beryl_scene/src/driver/glyphs.rs, beryl_scene/src/widgets/icons.rs, beryl_scene/src/widgets/icon_button.rs, beryl_render/src/atlas.rs, beryl_render/src/shader.wgsl, beryl_host/src/desktop.rs. Built in by-q44s.5.6 (3211ac401) and by-q44s.5.7 (46b1c978a).

Reported by the owner on 2026-11-16 from the desktop app (just b3d app, a real window on a Retina Mac). Every interface test and Warden passed on this code, so the headless tools do not see it. Reproduce in the real window path first: just b3d live against a running debug build (live tree, live png), not only just b3d png / tree, which use the headless host. A likely difference is the display scale: the desktop host (rust/beryl3d/crates/beryl_host/src/desktop.rs, Glyphs::start(window.scale_factor()), glyphs.rescale, Translator::new(size, window.scale_factor())) runs at scale 2 on a Retina display, while the headless host and the test matrix may run at scale 1. Confirm or rule this out.

Rules: the epic by-q44s ('Rules for every bead'), rust/beryl3d/AGENTS.md, docs/beryl-3d.md. A UI bug fix adds the broken state to a check that runs on every push (root AGENTS.md, 'Checks'), so the fix includes a test that fails before it at the scale and host the owner used.

Note from by-q44s.9.39: no headless tool runs at scale 2. The driver sends Input::Surface scale 1.0 (beryl_scene/src/driver/mod.rs begin), Headless asks for glyphs and icons at 1.0, and png --scale only enlarges the target. It also loses clipped content: png screen/start --at end --scale 2 shows an empty opponent list. The windowless app is hardcoded to scale 1 (beryl_3d/src/app.rs). The owner's screenshot shows the live app drawing 'You won the ip' (the fl ligature is missing), while png opening-play --at prompt:1 at scale 1 draws it correctly. A scale-2 test therefore needs the Surface scale fed through the driver (by-q44s.9.43 makes that general).

Derek Thurn2026-11-17

Handoff: Cause confirmed by measurement, not by opening a window (agents never open one): at scale 2, prepare_latin + icons filled atlas pages 1-10, but ATLAS_PAGES is 8, so Renderer::upload_page refused pages 8-10 and the client never received the icons or the glyphs text asked for later (mana symbols, letters of 'flip'). At scale 1 (headless host, interface tests) everything fits in 3 pages, which is why no check saw it. Phones (scale 2-3) had the same bug. Fix (8132a4d90): new GlyphWorker::prepare for ahead-of-time glyphs, which fills only pages that leave the last DEMAND_PAGES=3 free and runs after icons and requested glyphs in each batch; Atlas::add takes a last page and never opens one past ATLAS_PAGES-1; skipped prepared glyphs stay un-done so a later request rasterizes them. ATLAS_PAGES moved to beryl_assets::packer (beryl_render re-exports it). Hosts (assets.rs desktop/phone Glyphs, headless.rs) call prepare. Test: beryl_assets tests/all/glyphs.rs every_icon_and_demanded_glyph_fits_the_atlas_at_every_display_scale (scales 1,2,3), which failed before the fix with pages [1..10]. Reviewer: check DEMAND_PAGES=3 is enough at scale 3, and that repeated display-scale changes still leave old-scale cells in the atlas (pre-existing; they now stop at the last page with a log line instead of being dropped silently by the renderer). Note: building beryl_assets alone (cargo test -p beryl_assets) fails because beryl_scene's 'driver' feature isn't enabled; workspace runs are fine.
