Enhanced limits in gates.json; fragments counted over every pass, draw calls, particles and resolved parity gated (433d05e27, f4cea37ed)

Description

Read first: the epic by-q44s ('Rules for every bead', rules 8, 10 and 17); rust/beryl3d/AGENTS.md; docs/beryl-3d.md 'The Enhanced tier' (its limits), 'Performance gates' ('What is counted', 'What it is held to', 'During the build-out') and 'Checks and isolation'.

The Enhanced tier's limits in data/beryl3d/gates.json and the gates that hold them, with the Baseline tier's limits unchanged and every interface check still passing. The doc's target is "enhanced": { "draw_calls": 32, "fragments": 4.0, "particles": 2000 }.

What exists:

  • The native frame gate: beryl_inspect src/bin/gate.rs plays gate::BOARDS through Playback and prints each frame's Load and work; tools/src/beryl_tools/beryl3d/gate.py holds them to frames.<board> (measured limits that only go down). Playback::with_tier and Load::particles come from the contract bead.
  • The GPU gate: beryl_render examples/fragments.rs counts the fragments of each board's 8 ranked frames with FragmentCounter (src/count.rs, one pipeline statistics query around the one render pass) in the beryl3d-bench virtual machine; tools/src/beryl_tools/beryl3d/gpu.py holds them to tiers.baseline.fragments.<board> and the shader costs to materials. It is the sweep's gpu step (just b3d gate --gpu).
  • The Enhanced renderer draws a frame in several passes: the shadow map's, the multisampled main pass, bloom's four and the flat layer's.

Build:

  • FragmentCounter counts every pass of a frame: a query set of 8 queries, one around each render pass the frame records, summed when read. Baseline's count must not change: just b3d gate --gpu gives the same tiers.baseline.fragments as before, number for number.
  • fragments.rs takes --tier baseline|enhanced (baseline by default) and draws the frames in that tier on a Limits::Default device, printing the fragments and Drawn::draw_calls of each frame. gpu.py runs it for both tiers and holds the Enhanced counts to tiers.enhanced.fragments.<board> (measured limits set by --update, which only go down, as the Baseline ones are) and to tiers.enhanced.draw_calls (32) on every board, with the doc's 4.0 screens as the target the per-board limits must stay under. The four-sample main pass shades each pixel once unless a triangle's edge crosses it, so count what the driver reports; do not divide by the sample count.
  • gate.rs plays each board in Enhanced too and prints particles per frame under the board's name with an enhanced suffix (stress-verbs enhanced); gate.py holds the worst frame's particles to tiers.enhanced.particles (2000) and fails on any Enhanced frame whose resolved count differs from Baseline's at the same frame. The Enhanced boards get no frames.* work limits of their own: the client's work is the same in both tiers except for particles, and the tier check holds the rest.
  • data/beryl3d/gates.json: add tiers.enhanced with draw_calls, particles and fragments per board, from just b3d gate --gpu --update and just b3d gate --update. git diff of the file shows no change under frames or tiers.baseline, and every material's entry stays at or under its old value.
  • The doc's 'The Enhanced tier' gets the measured table of Enhanced fragments per board beside the Baseline's, with the adapter and date, as 'The Baseline tier' gives its own.
  • If a board is over 4.0 screens or 32 calls in Enhanced, do not raise the target: find which pass costs it with the per-pass counts, cut it (the shadow map's size, bloom's scale) in data/beryl3d/space.json, and give the numbers before and after in the commit body.

Tests: gpu.py's and gate.py's existing tests under tools (follow them) for the Enhanced keys: a board over its fragment limit fails, a frame over 2000 particles fails, a board with a different resolved count in Enhanced fails, --update lowers and never raises.

Run: just b3d gate; just b3d gate --gpu; just b3d test; just b3d lane.

Beads named above: the contract bead (the tier input and the check) is by-q44s.11.2; the renderer skeleton bead is by-q44s.11.3; the shadow map bead by-q44s.11.4; the lighting bead by-q44s.11.5; bloom by-q44s.11.6; particles by-q44s.11.7; the tier choice bead by-q44s.11.8; the settings row by-q44s.11.9; the limits bead by-q44s.11.10; the settings screen bead by-q44s.5.27. Handoff: Enhanced tier limits and gates landed in 433d05e27 (feat) and f4cea37ed (re-pin of frame limits after rebase).

Files and functions:

  • beryl_render src/count.rs: FragmentCounter holds 8 pipeline statistics queries; count::begin/count::end wrap each render pass (begin takes the next query index), resolve() resolves the queries the frame used and restarts at 0, read() sums them. renderer.rs resolves once per frame after every pass; enhanced/mod.rs (render takes counter), shadow.rs (draw) and bloom.rs (apply, all four passes) count their passes.
  • beryl_render examples/fragments.rs: --tier baseline|enhanced (Playback::with_tier), prints tier and per-frame draw_calls; refuses Enhanced on an adapter without it. --recorded stays Baseline.
  • beryl_inspect src/bin/gate.rs: plays every board again in Enhanced and prints enhanced: [{name: "<board> enhanced", frames: [{particles, resolved}]}]; Baseline frames also print resolved.
  • tools gpu.py: TARGETS {baseline 1.75, enhanced 4.0}; runs the example twice per tier (compare_runs); fragment_failures(tier=...), Enhanced over 4.0 always fails (HARD_TARGETS; Baseline keeps its build-out-only target), draw_call_failures for tiers.enhanced.draw_calls. gate.py: parse_enhanced, enhanced_failures (particles over tiers.enhanced.particles, resolved count differing from Baseline's at the same frame). Tests added in tools/tests/test_beryl3d_gpu.py and test_beryl3d_gate.py.
  • data/beryl3d/gates.json: tiers.enhanced {draw_calls 32, particles 2000, fragments per board}. docs/beryl-3d.md: 'The Enhanced tier' has how the gates hold the limits and the measured table; 'What is counted' updated.
