Handoff: Audited milestone 2 on origin/staging at 94af7b87. Read the closed by-bmdk.3 commit list, the milestone 3 host/guest, prompts and ability plans, and the protocol, adapter, command and UI paths.

  1. Shared views. beryl_table_session/src/view.rs and view/cards.rs construct PlayerView, PlayerState, ObjectView and StackItem through beryl_session/src/protocol/neutral.rs. Those field-by-field constructors fail to compile on additions or incompatible field changes. TableView is an exhaustive literal at its call site, and protocol/shown.rs and the generated-TypeScript check add separate guards. Semantic changes to defaults still rely on tests. tests/view.rs and tests/script_history.rs exercise both seats, anonymous cards, replay and rewind. The separate seat, old/new Slots, refs and view arguments can still be mismatched. by-bmdk.4.3 binds those values together and checks all active projections before a commit.
  2. Interface structure. TableClient in ui/src/table/client.ts is a 380-line pointer registry and shared interaction state. It leaves drag, aiming, click, selection, keys and turn behavior to their modules registered in screens/Table.tsx. It also keeps the action lookup and cancels gestures on view changes, which belongs at that boundary. The larger file is TableMenu.tsx (675 lines): TableCommands.run dispatches target pickers, token search and several numeric/text prompts. Its existing clients registry already handles pile viewer commands. Extend that seam for milestone 3 and render host-held prompts in the planned TablePromptView. Moving the current branches wholesale would leave the same coupling.
  3. Linked play. The typed UI seam works: tableAct and tableCurrent in ui/src/ipc.ts and the game-update feed in screens/Table.tsx carry the same requests and updates. The Rust table_act handler in beryl_app/src/tables.rs is synchronous today, so guest integration needs async or worker dispatch for the remote wait. TableSessions currently holds only Solo. by-bmdk.4.3 makes its checked log/reference/publication path reusable by the host. Updated by-bmdk.5.1 to call that path. by-bmdk.4.4 preserves blocking entry numbers through the link so ui/src/table/tableLog.ts can highlight the same rows for a guest.
  4. Host authority. Play/resolve routing already uses host destinations. Type-line parsing for drag attach, Oracle text parsing for quick counters, and reconstructing editable base stats from saturated displayed values are in dropActions.ts, menuRows.ts and cardState.ts. by-bmdk.4.5 projects these facts on the host. Object refs already cover explicit reveals. Menu access for a lent hand and drag access to hidden piles diverge from permissions.rs. by-bmdk.4.6 makes these controls consume one host zone grant. The host should continue to validate submitted actions. Choosing an explicit click destination, drag position or batch order remains UI interaction work.
