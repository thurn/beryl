Close reason

Enact ends processes in a worktree before removing it (enact 4ad31fe)

Description

What happened

On 2026-11-12 a fuzz run (cargo test --release -p beryl_search --test games) used a full core for four and a half hours. It had been started in the worktree of bead by-w8gv.13.6. The bead was closed and enact push deleted the worktree, but the process kept running with launchd as its parent, and nothing would ever read its result.

Why

remove_worktree in scripts/enact.py deletes the directory and the branch. It does not look for processes that still use the directory.

Change

Before remove_worktree deletes a worktree, end every process whose working directory or executable path is inside it: send SIGTERM, wait a few seconds, then SIGKILL. Do the same in sweep_worktrees. Report what was ended in the command's JSON output. Never end the calling process or its ancestors. On Windows, do the equivalent or skip it with a logged reason.

Done when

An integration test starts a long sleep inside a worktree, removes the worktree and finds the process gone. This change is in the Enact repository at ~/enact (scripts/enact.py, tests in tests/test_unit.py and tests/test_integration.py), not in Beryl. Read ~/enact/AGENTS.md first and follow that repository's workflow. The measurements behind this bead are in its parent, by-gdn3.
