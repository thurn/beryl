Close reason

Waiting scripts compile as they start; verbs-zones worst frame 34 -> 12 steps

Description

Symptom: verbs-zones' worst frame (frame 980) still compiles 34 script steps in one tick after by-q44s.4.10. That frame's handle takes eleven updates at once (scripts #24 to #34 of the recording: 10+1+1+1+1+1+1+15+2+1 steps), and the first of them has a step with StepTiming::hold.

Why: by-q44s.4.10 compiles a script over frames (rust/beryl3d/crates/beryl_scene/src/play/part.rs, Show::in_parts and Show::prepare) only when it arrives with nothing playing or waiting and needs no relay. A script that arrives behind another is compiled whole in push_timed, because it is played from the table the one before ends with (Show::played), and a push while a script is still compiling in parts first compiles that one whole (Show::complete). A script with a hold or alone timing is compiled whole too, because Show::relay lays every beat out again as it starts from compiled.laid.

What to build: (1) A waiting script can be played from the table the script before it ends with, worked out by beryl_protocol::script::replay without playing any step over the table (part::finals_of already replays), so it can be compiled in parts once it starts, and the push need not complete the one before. (2) relay only needs the laid-out beats (cheap), not the steps' segments, so it could run on a script compiled in parts and shift later steps as they are compiled. Keep the property that every pose at every frame equals the whole compile's (tests/all/compile_in_parts.rs, a_client_compiles_a_long_script_over_frames_and_draws_each_as_compiled_whole).

Files: rust/beryl3d/crates/beryl_scene/src/play/{part.rs,mod.rs,relay.rs,compile.rs,playing.rs}; gate limits in data/beryl3d/gates.json (verbs-zones worst_frame_steps 34, worst_frame_instructions).

Acceptance criteria

  1. just b3d gate shows verbs-zones' worst_frame_steps below 34, with the limit lowered by just b3d gate --update in the same change.
  2. A beryl_scene test plays two updates handed over in one tick through Client (handle, prepare, frame) and checks that every frame's draw records equal those with Client::compile_whole.
  3. just b3d lane passes with frame_allocations 0.
