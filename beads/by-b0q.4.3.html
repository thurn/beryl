Description

Part of Milestone 1 (epic by-b0q), filed by the M1b Mason audit (by-b0q.4.1) at staging 2532e87. Read docs/engine-architecture.md §7 and §15 and AGENTS.md first.

Current design

The engine's resolution questions are generic: EffectCtx::choose_up_to, choose_object, choose_yes_no, may_choose_object and scry all emit DecisionKind::ChooseUpTo / ChooseObject / YesNo with no record of what the question is for (rust/crates/beryl_engine/src/effect.rs:286-380, 742). The meaning is then recovered from the resolving card's name by every consumer:

  • UI, ui/src/game/choices.ts:70-125: seven card-name constants (ICEBERG, JACE, TRAINER, SPELLBINDER, TIME_SPIRAL, SKYDIVER, SPRINGS) pick the overlay; LOOKS = {Iceberg: 2, Trainer: 4}, TIME_SPIRAL_LANDS = 6 and HAND_SIZE = 7 copy rules text into TS; at.inLibrary(at.offered) guesses that a ChooseUpTo over library cards is a scry.
  • Expert, rust/crates/beryl_search/src/expert/mod.rs: yes_no (≈2492) tells Jace, the Mind Sculptor's +2 (name == JACE_THE_MIND_SCULPTOR && e.ability == Some(FaceAbility::Own(0))) from a Map's explore (name == "Map Token"); x (≈2515) and take_from_hand (≈504) likewise test names or candidate zones.
  • The UI also re-implements the engine's smart stops: nextStop (ui/src/game/layout.ts:645-700) copies §15 / beryl_engine/src/profile.rs::is_smart_stop to caption the pass button (its canAttack guess ignores what the engine actually checks), and sourceOf (ui/src/game/decisions.ts:119) guesses a decision's source from candidates and the stack.

Every new cube card with a look, scry, explore or "up to N" then needs a TS edit and an agent edit keyed by its name, and the UI's copy of the stop rules can drift from the engine's.

Proposed design

The engine says what each resolution question is for, once, where the card's code asks it; the protocol forwards it; consumers dispatch on it.

// beryl_engine
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Default)]
pub enum Ask {
    #[default]
    Plain,
    /// CR 701.22a: choosing cards for the bottom, then ordering the rest on top.
    Scry { phase: ScryPhase },
    /// Look at cards of a library and may take one (Thundertrap Trainer: 4, Elite
    /// Spellbinder: an opponent's hand).
    Look { from: Zone, count: u8 },
    /// Put cards from hand back on top (Jace, the Mind Sculptor's 0).
    PutBack { count: u8 },
    /// Whether the top card of `player`'s library goes to the bottom (Jace's +2).
    Fateseal { player: Seat },
    /// CR 701.44a (a Map's explore): the revealed card to the graveyard or not.
    Explore,
    /// Choose up to `max` permanents to untap (Time Spiral).
    Untap { max: u8 },
    /// CR 118.12a: pay or the spell is countered.
    UnlessPays,
}
pub struct Decision { pub player: Seat, pub kind: DecisionKind, pub candidates: Candidates, pub ask: Ask }

EffectCtx's asking methods take the Ask (or a card helper sets it), so each card file states its own purpose. DecisionView gains ask (ts-rs) and, for the turn button, passTo computed in Rust from the engine's stop rules (export one pub fn next_stop(s, player) beside is_smart_stop, so the caption and the engine share code), and source: Option<Slot>. choiceOf switches on decision.ask with an exhaustive assertNever; nextStop and sourceOf are deleted. The expert's yes_no / take_from_hand dispatch on d.ask where they now compare names for the question's meaning (card-specific strategy may still use names).

Decision is rebuilt on replay, so Ask is not stored in State unless the pending representation needs it; keep the 20 KiB State assert.

What it eliminates

The seven name constants, LOOKS, TIME_SPIRAL_LANDS, HAND_SIZE and the inLibrary scry guess in choices.ts; the UI's copy of §15 and the source heuristic; name tests for a question's meaning in the expert. New cards with these mechanics need no UI or agent change.

Behavior that must not change

Every overlay, caption and answer the game screen shows today (just ui-test's 15+ interactions, just ui-shots), the engine's decision sequences and state hashes (replay tests, scenarios, both oracles), expert/greedy/MCTS choices for the same seeds (games, expert and mcts tests).

Smallest black-box test

A beryl_session test that plays seeded scenarios for Aang's Iceberg (scry 2), Thundertrap Trainer, Elite Spellbinder, Jace TMS (+2 and 0), a Map's explore and Time Spiral, and asserts each resolution DecisionView.ask (e.g. Time Spiral's is untap { max: 6 }); plus a UI check that ui/src/game contains no card names (grep in the ts check or a ui-test assertion).

Acceptance criteria

  • Engine Decision carries an Ask (or equivalently named) purpose set where each card's code asks; PlayerView's DecisionView exposes it, plus what passing advances to and the decision's source, generated by ts-rs.
  • ui/src/game/choices.ts and the rest of ui/src/game name no card and hard-code no rules count (no LOOKS, TIME_SPIRAL_LANDS, HAND_SIZE); nextStop and sourceOf are gone; choiceOf switches exhaustively on the ask.
  • The expert no longer tells a question's meaning from card names (Jace +2 vs Map explore, Trainer/Spellbinder looks).
  • New beryl_session test asserts the ask of each resolution prompt for Iceberg, Trainer, Spellbinder, Jace TMS, Map and Time Spiral.
  • just ui-test, just ui-shots, the replay/scenario/oracle tests and the agent tests pass with unchanged behavior; State stays under its compile-time size assert.
