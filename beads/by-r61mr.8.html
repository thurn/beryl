Close reason

Rust tk client reached Enact master at 7834427 after fast and slow CI. Wrangler benchmark medians were 16.66 ms read and 27.33 ms write.

Description

Read the epic by-r61mr first: it holds the decisions, the code map and the directory layout this bead assumes. The work is in the Enact repository (~/enact) unless this bead says otherwise, delivered with that repository's own enact worktree create and enact push.

Implement the contract's command surface in cli/ as the binary tk: every ticket operation, claims, leases, the compound next, start and close calls, events, export, and waiting on the WebSocket feed. Output is JSON where the contract says so.

  • The project and server address come from the repository's .enact.toml; the token from a file outside any repository, at the path the contract names.
  • One command makes one request. Start-up must do no work a command does not need.
  • When the server is unreachable or answers with the daily-limit error, retry with backoff for the time the contract gives, then exit with the contract's distinct code.
  • Add a benchmark, tk bench, that times a read and a write end to end, and record its numbers against wrangler's local simulator in the bead.

Acceptance criteria

cargo test passes with tests that run tk against the local simulator for every command. tk bench against the simulator reports a median under 30 ms for a read, which leaves room for the network inside the epic's 100 ms target. The binary builds for Apple silicon macOS and for Windows.

Notes

The command surface, exit codes, retry rule and token path are sections 8 and 9 of the contract. There are no compound endpoints: every write is POST /batch.
