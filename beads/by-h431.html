Cast steps read the stack entry without cloning it

Close reason

Landed in 77efb48a: top() borrows; count 391,693,905 -> 390,293,470, bar lowered.

Description

Since e8d5e451 (tagged unions for casting and stack items), the rollout benchmark spends about 2.4M instructions (0.6% of the count gate's 391.7M) in beryl_rules::cast::steps::top, which clones the top StackEntry about 12,500 times per run. Each step of casting, targeting and paying (cast/steps.rs, cast/parts.rs, cast/targets.rs, cast/costs.rs: 15 call sites) calls it, though most read only the item, the targets or X before mutating the state. The derived Clone for the generic StackEntry<L> copies field by field (about 190 instructions per call), and top is no longer inlined. Forcing #[inline(always)] made the count 0.15% worse.

Have the call sites borrow the entry, or copy out only the fields they use, so that no StackEntry is cloned on the path every cast takes. Measure with just bench-count -p beryl_bench --bench rollout_counts before and after, and name both counts in the commit. rollouts_never_change must not change.
