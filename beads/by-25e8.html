budget.py's slow-CI estimate counts shared and stale CPU

Description

Symptom: budget.py estimated slow CI's full run on this Mac at 1090 CPU seconds (budget 800) and filed cut beads by-99s7, by-cz7b and by-znfk. Several of the checks those beads named would not lower slow CI's CPU if cut.

Why:

  1. Renamed checks count twice. The estimate sums each check's median CPU over the checks seen in a lane's last 10 runs. When beryl_session's tests moved into one test binary, each test appeared under its old name (rust:beryl_session::undo::...) and its new one (rust:beryl_session::session::undo::...), so 9 tests (about 50 CPU s) were counted twice. Old names that no longer run should drop out of the estimate.
  2. A step's CPU is shared among its checks. runlog.py gives each check a share of its step's process-tree CPU, weighted by wall seconds (oracle checks of one XMage batch get equal shares; script checks share the step's cargo build). Cutting one such check moves its share to the others, so the cut ranking (check_value.py, budget.py file_cut) should not name single checks of a shared-CPU step, or should count only the CPU a check adds.
  3. Runs that play everything (the oracle lane when a harness file changed, the script lane's 'all') put every check into the union, though a normal run plays only a sample.

Files: tools/src/beryl_tools/budget.py, check_value.py, runlog.py (records(), share()). Tests: tools/tests/test_budget.py. Change the estimate and ranking so a cut bead only names cuts that lower real CPU.
