Description

The manual table plays a hand card first when drawing an arrow. TableActionRefs::apply_checked in beryl_session resolves all members against the published view, so an Arrow expecting the card in its new zone is rejected as stale before beryl_table can apply the move. Allow a batch to reference a visible card after its own earlier move with fresh staged-zone validation, while still rejecting stale references, arbitrary destination zones, and hidden re-identification. Update ui/src/table/arrows.ts to send the move and arrow atomically.

Acceptance criteria

One TableAction batch plays a land or spell from hand and draws the arrow from the destination; invalid targets roll back the move. Tests cover mixed destinations and rejected stale or hidden references.
