Description

Read first: the epic by-q44s ('Rules for every bead'); rust/beryl3d/AGENTS.md; docs/beryl-3d.md 'The flat layer', 'Hosts'; docs/manual-multiplayer.md (the manual table's design: what a command is, the context menus, the command list, keys). What has shipped in the web interface is the solo table and everything on it; hosting and joining have IPC wrappers in ui/src/ipc.ts (tableHost, tableJoin, tableResume, tableSaved) but no screen calls them, so they are not built here. Code: beryl_scene src/screens/table.rs (the contract's stub), a new module src/manual (mod.rs, commands.rs, menus.rs), src/command.rs (SessionCommand), src/widgets/menu.rs, src/element/keys.rs; beryl_3d src/session.rs (Session::run). The table's Rust side: rust/crates/beryl_table_session/src/connections.rs (TableConnections: what each table_* command of rust/crates/beryl_app/src/tables.rs calls), beryl_protocol src/protocol/table.rs (TableView, TableAction, TableObjectRef, TableCardCommands) and src/ipc.rs (TableSoloRequest, TableActReply, TableRefused). The commands: data/table-commands.json (209 commands, 100 with keys, each with its applies_to and its key for the Mac and others). Web: ui/src/screens/Table.tsx (TableScreen: wires the client, the menu, the commands, the arrows and the bindings on the shared stage), ui/src/table/commands.ts (commands, commandsFor: which commands apply to a target, the 15 values of AppliesTo), ui/src/table/TableMenu.tsx (TableCommands, TableMenu, TableOverlay), ui/src/table/keyboard.ts (listenTableKeys, pointedTarget: keys act on the card or player under the pointer; repeats ignored; Shift with a token.* key falls back to the unshifted binding), ui/src/table/keys.ts (claims), ui/src/screens/StartScreen.tsx (the 'Solo table' handler, which builds the deck and calls tableSolo).

Build:

  • SessionCommand::TableSolo(TableSoloRequest), TableAct(TableAction) and TableLeave, answered on beryl_3d's session thread by a TableConnections beside Sessions, as rust/crates/beryl_app/src/tables.rs answers them (add beryl_table_session to beryl_3d's dependencies by path; its Cargo.toml comment says it replaces nothing and is the table's session). The table's views reach the client as Input::Update like a game's.
  • The start screen's 'Solo table' press sends TableSolo with the deck StartScreen.tsx builds and shows Screen::Table.
  • src/manual/commands.rs: data/table-commands.json read at build time into constants, and commands_for(target, view) ported from commandsFor.
  • src/screens/table.rs table: the 3D table as in a game, with the hud, and a right-click (or a long press) on a card, a pile, a hand, a life total or the table opening a context menu of that target's commands with their key hints; a row sends TableAct with the action its template makes (commandActions.ts); the keys of data/table-commands.json, by the rules of keyboard.ts, as the root's shortcuts, acting on the pointed target.
  • Leaving (Cmd+Q, the 'table.leave' command) sends TableLeave and shows the start screen.

Do not build: the command list, the ask prompt, token search, library order, the log (the next bead); viewers, selection, drag and drop (the bead after).

Tests, in beryl_scene/tests/manual.rs (new), with views built by hand from TableView: commands_for a permanent gives the commands whose applies_to holds permanent, in the file's order; right-clicking a permanent opens a menu with those rows; F12 over your life total sends TableAct for gain 1; Cmd+D draws. In beryl_3d, a test of the session thread starts a solo table with the WU Control deck and gets a view back.

Run: just b3d cargo-test -p beryl_scene; just b3d cargo-test -p beryl_3d; just b3d lane.

Acceptance criteria

The tests pass; just b3d app --for 5s still starts and ends; the table's entry in data/beryl3d/screens.json names a recording (screen/table, a hand-built table view in beryl_inspect) and just b3d test b3d:screen/table passes.

Decisions and deviations:

  • The web's StartScreen no longer has a solo-table handler: since fb79cc146 every manual table is prepared in a lobby (Lobby.tsx, TableEntries.tsx). Beryl 3D's 'Solo table' still sends TableSolo, built from the sample WU Control deck the old StartScreen used (beryl_scene build.rs writes it as SOLO_REQUEST; manual::solo_request). The lobby screen is filed as by-q44s.5.49, blocked on this bead.
  • Tests live in beryl_scene/tests/all/manual.rs, not tests/manual.rs: rust/beryl3d/AGENTS.md keeps each crate's integration tests in one binary.
  • Action templates stay JSON text in COMMANDS and are filled with serde_json at runtime, then read as TableAction, as fill.ts does. serde_json was already allowed by scene-purity.
  • Ported from commandActions.ts: plain templates, pile targets (library ends, whole graveyard/exile/hand), counter-name templates, grouping by zone/owner/face, untap all. Not yet: flows, phase.next (turn.ts advancePhase), stat changes, tokens, and every command that asks for a value; their rows show disabled. Of commandsFor's conditions only last_draw is computed; commands with other conditions are hidden, as the web hides one whose condition fails. Of the client commands only table.leave (Cmd+Q) is built.
  • KeyCode gained F1 to F12 and the punctuation keys the table binds (Minus, Equal, Comma, Period, Slash, brackets, Backslash), mapped in the desktop host and in driver actions; shifted punctuation (+ < > ?) parses as Shift on its key. The phone FFI's key list is unchanged.
  • The hud floats (life totals, pools, pile counts, notices) now show on the table screen as well as the game screen (Client::hud_shown).
  • Long press to open the menu is not built: only a right click. The touch layout of the table is by-q44s.5.32's drag and selection work; noted in the handoff.
  • docs/beryl-3d.md's SessionCommand and Reply listing gained the three table variants.
