Close reason

Corpus replays identically under seed, candidate-order and slot perturbations (format 6+); ties fixed: save v6, batch and mana order

Description

Part of the durable-saves epic (read it first). Depends on the corpus bead.

Prove the format's independence from engine internals, by replaying the frozen corpus under perturbations that must not matter.

Build

Three test-only hooks (compiled into tests only, zero cost in the app and in search), each run over the whole corpus, each requiring all three corpus levels to hold:

  • RNG: a different seed derivation (rng.rs SplitMix64 or how State seeds its streams). Any save that diverges still depends on the seed.
  • Candidate order: each decision's candidates reversed, and shuffled with a fixed seed, before matching. Any save that diverges still records indexes.
  • Object ids: another id assignment order (zone::rebind, deck slot assignment in start.rs).

Run them in just test-rust if the corpus stays cheap; otherwise in just ci, within its budget.

Tests

Each hook proves it changes something: with the hook on, at least one index-based (v1) replay fails, so a hook that does nothing can't pass.
