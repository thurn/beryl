Close reason

Slot/Seat/CardIx ids, NONE and GRANTED gone, typed Derived, AbilityIx vs FaceAbility/GrantRef, engine-only base controller; behavior and perf counts unchanged

Description

Mason finding (by-b0q.2.1). Before M1b's agents (greedy, expert, MCTS) write thousands of lines of slot and seat code against Observation, give the engine's identifiers types.

Current design

  • Slots, players and game-table card indices are all bare u8 (341 : u8 fields and parameters in beryl_engine/src outside tests), so a seat passes where a slot is expected and nothing notices.
  • "No object" is the in-band sentinel NONE = 255 (155 uses in engine and cards): Object.attached_to, linked, copy_of, combat, chosen, AbilityRef.card, Target's player encoding, Opt::Defender(NONE) for "the player".
  • Derived stores raw bits (types: u8, colors: u8, keywords: u64, subtypes: [u64; 2]) although Types, Colors, Keywords, Subtypes newtypes exist; 34 sites rewrap them (Types(d.types).contains(..)).
  • GRANTED | k (card.rs:128) means two things: in Opt::Activate and scenarios k indexes the permanent's Derived::granted; in a StackEntry it indexes the granting face's Face::grants (cast.rs:53-66, :599). The Wardens left this as a known gap.
  • Base Object.controller is pub and Observation::object hands it to agents, but the real controller is the layer-2 result (State::controller). M1a fixed this mistake twice (filter.rs and the scenario runner's Tapped assertion, 8b3a215 and 71f99eb); a greedy agent reading obs.object(slot).controller after Thieving Skydiver steals something would repeat it.

M1a bugs these types admitted: the token allocator handed out slot 255 = NONE (8b3a215); an Aura's bare attached_to slot kept enchanting whatever reused the slot (e510c4e); begin_at accepted active >= 2 (71f99eb).

Proposed design

pub struct Slot(NonZeroU8);          // stores slot + 1: Option<Slot> is one byte
pub enum Seat { P0, P1 }             // opponent() is a method; arrays index by Seat
pub struct CardIx(u8);               // index into the GameTable
pub enum AbilityIx { Own(u8), Granted(u8) }        // what Opt::Activate names
pub struct GrantRef { card: CardIx, grant: u8 }    // what a stack entry names
struct Derived { types: Types, colors: Colors, keywords: Keywords, subtypes: Subtypes, .. }
// Object: attached_to / linked / combat: Option<Slot>; copy_of: Option<CardIx>;
// the base controller renamed and pub(crate); readers use State/Observation::controller.

Target becomes a two-variant enum (object or player) if it still fits four bytes; Choice(u8) and the Candidates encoding stay as they are (architecture §7.1).

What it eliminates

The NONE constant and its comparisons, the GRANTED bit trick, the 34 rewraps, a public base controller that can be mistaken for the real one, and the seat/slot mixups the type checker cannot see today. Slot 255 stops being special (capacity becomes 255 slots, which the 120 deck + ~130 token slots fit; say so where TOKEN_SLOTS is defined).

Must not change

Game behavior: every scenario, the determinism and replay tests, the information independence test and perf_counts_stay_in_their_bands pass unchanged (the counts bands must not move). State stays Copy, heap-free and under the 20 KiB compile-time assert; Option<Slot> and friends must stay one byte (add const size asserts).

Scope notes

Mechanical across beryl_engine, beryl_cards (bodies and scenarios), beryl_scenario, beryl_search and beryl_session (which maps to its own wire types; branded TS ids are the protocol bead's job). Rules-code CR citations move with the code. Merge conflicts with the protocol bead filed alongside are expected and cheap: rebase onto whichever lands first.

Acceptance criteria

  • beryl_engine has Slot, Seat and CardIx newtypes (or equivalent names) used for every slot, player and game-index field and parameter of State, Object, Derived, StackEntry, PendingTrigger, Opt, Decision and the EffectCtx API; grep -rn 'NONE' rust/crates/beryl_engine/src rust/crates/beryl_cards/src finds no slot sentinel, and GRANTED no longer exists.
  • Object relations (attached_to, linked, combat, copy_of) are Option<..> of a one-byte type, with const asserts that each is one byte; the State 20 KiB assert holds.
  • Derived fields use the Types/Colors/Keywords/Subtypes newtypes.
  • Granted abilities have two distinct types for "the permanent's k-th granted ability" and "the granting face's k-th grant"; Swift Reconfiguration's crew scenario passes.
  • Code outside beryl_engine cannot read an object's base controller under the name controller; Observation offers the layer-2 controller of a permanent.
  • just check and just ci pass with every existing scenario and test unchanged in outcome, including the perf counts bands.

  • No-object references are Option: Object.attached_to/linked/combat, copy_of, Opt::Defender(Option<Slot>), Pending::DeclareAttackers/Blockers, and the emblem case: PendingTrigger.source, StackEntry.object and TriggerInfo.object are Option<ObjectRef> (NO_OBJECT gone). EffectCtx::source() panics for an emblem's ability (documented); StackEntry::spell() gives the spell's card.

Scenario API: Action::activate_granted(player, card, k) replaces activate(.., GRANTED).
