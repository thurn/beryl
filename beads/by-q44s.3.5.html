Description

Read first: docs/beryl-3d.md 'Timeline parity', 'The agent interface' ('Commands', 'What is printed'); the epic by-q44s ('Rules for every bead'); rust/beryl3d/AGENTS.md. Code: rust/beryl3d/crates/beryl_inspect/src/cli/mod.rs (how list, info, tree, diff and check are declared and given --help with two examples), src/cli/listing.rs, src/pages.rs (page, recording), src/recordings.rs (names, find), and beryl_scene's src/driver/check.rs (Page::steps) and src/play/record.rs (ScriptRecord, StepRecord). tools/src/beryl_tools/beryl3d/cli.py (b3d_command) lists the commands of just b3d.

Add two text commands to the b3d program:

  • just b3d timeline <recording> prints one line of JSON for each step of each script of the recording, as the given seat sees it. The keys, in this order: "recording", "seat", "view" (the view's number in the recording, from 1), "beat" and "step" (from 0), "verb" (Verb::name), "case" (the step's StepTiming::case, or null), "start" and "end" (StepRecord::from and to, which are on the script's own clock, in milliseconds rounded to 3 decimal places), and "effects": one string for each StepEffect of the step's timing, in order, <name>@start or <name>@end, with +<into> to 3 decimal places appended when into is set, as in "impact@start+0.376". A step the client made itself would add "own": true; Beryl 3D makes none until milestone 3. The step records come from a Page that called Client::record and played to its end, and the case and effects from the timing of the same view's script, entry by entry.
  • just b3d timeline --all writes the same lines for every recording and seat of recordings::names(), in name order, to a file named for the run under $BERYL_CACHE/b3d/out, and prints the file's path and the number of recordings and lines.
  • just b3d export <directory> writes each recording's messages to <directory>/<name>.<seat>.json, a / in the name written __, as the JSON array of fixture messages the pack holds. This is what ui/scripts/timeline.mjs (by-q44s.3.4) reads. It prints the directory and the number of files.

Both follow the tool's rules (epic rule 19): --help with two examples, the first line of output is the command that prints it again, a wrong name exits with 2 and the five nearest names. Add both to rust/beryl3d/AGENTS.md's 'Seeing and checking' list in one line each.

Do not build: the comparison or the allowlist (by-q44s.3.6).

Tests, in beryl_inspect/tests/cli.rs: timeline verbs-zones prints one line per step, the number of steps info verbs-zones lists; every line parses as JSON with the keys in order; two runs print identical bytes; export into a temporary directory writes a file that serde_json reads back as the messages recordings::find gives.

Run: just b3d cargo-test -p beryl_inspect; just b3d timeline verbs-zones; just b3d lane.

Acceptance criteria

The four tests pass; just b3d lists timeline and export; just b3d timeline verbs-zones --seat opponent prints lines whose "seat" is "opponent".
