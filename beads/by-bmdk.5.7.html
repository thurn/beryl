Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Setup and match flow' and 'Cards and decks'. Reference image docs/ui_mockups/manual_lobby.png (intent only).

Interface code goes in ui/src/table/, registered with TableClient (ui/src/table/client.ts). Headless checks start a table with ui/scripts/table.mjs and go in ui/scripts/kept-table-<topic>.mjs; run one with just ui-test <title>.

File: ui/src/screens/Lobby.tsx, ui/src/table/lobby/ (DeckPicker.tsx, SideboardSwap.tsx, AssistSwitches.tsx, GameSettings.tsx).

  • ui/src/screens/StartScreen.tsx gains three entries: "Host a table", "Join a table" (a field for the invite code), "Solo table". Remove the temporary "Solo table" button the table-screen bead added. On a phone, "Host a table" is absent.
  • The lobby is a panel where a player prepares. This bead builds it for the solo table and for the local side of a hosted one:
    • Deck: the saved decks (deckList), "Change" to pick one, paste a list (Cmd+Shift+V) or open a file (Cmd+O, deckOpenFile; absent on phones). After import the lobby lists names the store lacks so a typo is noticed. Unload is Cmd+Option+U.
    • Sideboard: opens a swap view (Cmd+Shift+B in the lobby) where cards move between main and sideboard; it sends sideboard actions. There is no lock.
    • Assists: the player's five switches, all off by default, sending set_assist.
    • Game (host or solo only): starting life (20), starting hand size (7), who plays first (a roll, or a named player).
    • Start: on a solo table, enabled once a deck is loaded.
  • Lobby state comes from the host as one value. Define LobbyView in beryl_table_session/src/lobby.rs (each seat's name, deck loaded and its counts only, never the list, ready, score, settings, the viewer's own deck and sideboard and unknown names) and send it on table-lobby after every lobby action and when a game ends. A seat's decklist is never in another seat's LobbyView: add a test.
  • Lobby changes use table_lobby { change } mapping to the table's load_deck, sideboard, ready, set_assist and settings; start starts.
  • Lobby shortcuts use scope lobby in ui/src/table/shortcuts.ts. Resolve them with the existing per-profile Bindings (ui/src/table/bindings.ts). The temporary solo launch in ui/src/screens/StartScreen.tsx calls tableSolo directly with the sample deck. Replace that direct launch with the lobby entry described above.
  • data/ui-conventions.json: no-equivalent, "Lobby".

Checks (kept-table-lobby.mjs): solo from the start screen: paste a decklist with one misspelled name, see it listed, start, play. Sideboard swap changes the counts. A fixture or kept moment of the lobby for the generic audits.

Acceptance criteria

The start screen has host, join and solo entries (no host on phones); a player can import, pick and unload decks, swap sideboard cards, set assists and game settings and start a solo game; LobbyView never carries another seat's decklist; headless checks and a lobby state under the audits exist.
