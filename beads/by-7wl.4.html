Close reason

987f287: --add asks the pinned binary (longthink-check-family), refuses under pre-live runners; runner exits 75 on upgrade, supervise relaunches; --upgrade before --add

Description

Part of epic by-7wl, but useful on its own: make just longthink --add work for a family that needs code the running arena's binary lacks, on a live arena. Today it does not, safely.

What exists (checked 2026-11-06)

In rust/crates/beryl_cli/src/longthink/ (mod.rs, run.rs, upgrade.rs):

  • --add FAMILY parses the name with the invoking binary and writes config.json. A live runner rereads config.json before each game (Runner::claim), so a family the run's binary already knows opens from the next game. That part works.
  • The runner is the run's pinned binary, <run>/beryl_cli, launched by supervise and relaunched only after a crash. --upgrade replaces that file only if the current code replays every logged game to the same transcript and re-searches a sample of every entrant's searches to the same answers.

Gaps

  1. --add never checks that the run's own binary can parse the family. If it cannot, the first time the schedule picks that family, Spec::new -> entrant fails, claim returns an error, the runner exits, and supervise stops the arena ("the runner stopped").
  2. A live runner keeps its old binary in memory after --upgrade. Nothing makes it pick up the adopted one until it exits.
  3. Given --add and --upgrade together, the family is added before the adopt, so a refused adopt leaves config.json naming a family the run cannot play.

Build

  • --add refuses a family the run's pinned binary cannot parse (ask that binary, e.g. through a hidden subcommand), saying to run --upgrade first.
  • After --upgrade adopts a new binary while a runner plays, the runner stops at its next safe point (a stop costs at most the decision being searched) and supervise relaunches it on the adopted binary.
  • With both flags, upgrade first; add nothing if the adopt is refused.

Done

On a live scratch run (not run-003): just longthink --upgrade, then just longthink --add <family the old binary lacked>, and the family plays from the next game without a manual restart. Tests cover the refusal and the flag order.
