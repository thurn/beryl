Close reason

Slow CI runs only a ui-smoke lane; full shots/ui-test/mobile run in by sweep every 3 h, bisected and filed as sweep-failure beads (c021caf8, f05dcc59, 69716e56)

Description

Why

The browser lanes are most of slow CI's cost: over the week to 2026-11-13 the median slow-CI run spent 547 s in ui-test, 325 s in shots and 110 s in mobile, and ui-test alone was 135 of 337 logged check-hours over three days. They are also where slow CI's timeouts and flaky failures come from.

Most of their value for a given change is already captured before the push: the fast check's change-aware selection (tools/src/beryl_tools/selection.py) runs the browser checks a change to ui/ or rust/ can break. What a full sweep adds is catching cross-cutting breakage, where a change to shared stage or engine code breaks a verb or screen the selection did not pick. That does not need to run on every staging tip, and it should not block master.

Telling agents in AGENTS.md to run these checks by hand was considered and rejected: agents skip validation they are only told to run. The pre-push selection is the enforced form of "run the checks your change needs".

What to change

  • Slow CI stops running the full ui-test, shots and mobile lanes. It keeps one small browser smoke check: the app renders and a game can be played a few steps, chosen so that it is fast and deterministic. Record which check and why in this bead.
  • A periodic browser sweep runs the full ui-test, shots and mobile lanes on origin/staging every few hours (for example every 3 hours; record the choice) at utility priority, as the nightly does (tools/src/beryl_tools/nightly.py, system.utility). It can be a new step schedule beside the nightly's launchd agent or a second agent. With about 8 commits an hour, a nightly failure leaves about 190 commits to search; every 3 hours leaves about 24.
  • A sweep failure never blocks master. It bisects over the commits since the last passing sweep when that is affordable, and files a bead naming the failing check and the culprit commit or range (reuse nightly_failures.py and bisect.py). The bead's description includes the "rewrite before deleting" question from the cut beads: could a fast, deterministic test keep most of this check's value?
  • The pre-push selection in selection.py stays, and should still fit the fast check's budget. If the time freed in slow CI makes it worthwhile, let it pick more checks.
  • Update docs/checks.md and the "Checks" and "Testing your work" sections of AGENTS.md so they say which browser checks run where.

Files and tests

tools/src/beryl_tools/slow_ci.py (lanes_for, full_due), tools/src/beryl_tools/checks.py (the lane list for by ci), tools/src/beryl_tools/nightly.py, tools/src/beryl_tools/nightly_failures.py, tools/src/beryl_tools/bisect.py, tools/src/beryl_tools/selection.py, the nightly-install recipe in the justfile, tools/tests/, docs/checks.md.
