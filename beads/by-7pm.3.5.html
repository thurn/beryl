Close reason

Delivered native phone snapshots and platform details in f18aca3a. iOS and Android smoke passed twice each, saved regions matched the native frames pixel for pixel, and fast checks passed. Native submission was verified from the start screen.

Description

A bug report freezes the page and snapshots the window (capture_window), and the report's screenshot.png and window.png are made from that snapshot. On a phone there is no snapshot: platform::snapshot in rust/crates/beryl_app/src/snapshot.rs has only a stub for anything but macOS and Windows, and smoke mode skips the check there (ui_ready in lib.rs: if cfg!(mobile) { … std::process::exit(0) }). Add the snapshot on iOS and Android, and tell the UI and the report which platform they are on.

Step 0: the shells still run

M1's shells have not been launched since 2026-11-09 and the app has changed under them. Before anything else run just mobile-setup, just ios-smoke and just android-smoke. If one fails, fix that first, in its own commit (tools/src/beryl_tools/mobile.py, android.py, rust/crates/beryl_app), and say what broke in a comment on this bead.

Where the code is

  • rust/crates/beryl_app/src/snapshot.rs: capture(app) calls window.with_webview and hands the platform's webview to platform::snapshot(…, send), which sends the image's bytes once; platform::pixels(bytes) decodes them to Pixels (RGBA); platform::CONTENT_TYPE is what the frozen frame is served as (Snapshots::respond); Snapshots::pngs(id, region, page_width) crops and encodes the report's images. The Windows module already decodes a PNG (reads_back_a_png_snapshot tests it).
  • rust/crates/beryl_app/src/lib.rs: app_info, ui_ready (smoke mode), capture_window, report_bug, run (plugins, setup).
  • rust/crates/beryl_session/src/ipc.rs: AppInfo { version, smoke, mobile }. rust/crates/beryl_session/src/bugs.rs and bugs/markdown.rs: the report's front matter. bugs::dir() and bugs::set_dir.
  • ui/src/ipc.ts: canCaptureWindow(), captureWindow(), snapshotUrl(id), artSchemeUrl (sniffs the user agent for Windows and Android), the fixture transport's own app_info reply. ui/src/App.tsx reads info.mobile.
  • tools/src/beryl_tools/mobile.py (READY, launch_until_ready, journal), android.py (the same for the emulator).
  • Tauri's guide to mobile plugins: https://v2.tauri.app/develop/plugins/develop-mobile/ . Read it before writing any Swift or Kotlin.

What to build

  1. A Tauri plugin crate rust/crates/beryl_mobile with an iOS half (Swift) and an Android half (Kotlin), laid out as the guide lays one out (Cargo.toml, build.rs, src/lib.rs, src/mobile.rs, ios/, android/). Add it to the workspace, and make it a dependency of beryl_app under [target.'cfg(any(target_os = "ios", target_os = "android"))'.dependencies], with a comment saying what it is for. Register it in run() under #[cfg(mobile)]. Keep the native code thin: no logic that Rust could hold. It has two commands in this bead:
    • snapshot: draws the webview into a PNG file and answers its path. iOS: webview.takeSnapshot(with: nil) { image, error in … image.pngData() … }, written to the app's caches directory. Android: on the UI thread, Bitmap.createBitmap(webView.width, webView.height, ARGB_8888), webView.draw(Canvas(bitmap)), bitmap.compress(PNG, 100, stream) to a file in cacheDir. A plugin gets its webview in load(webview:) (iOS) and load(webView) (Android). If Android's PNG comes out blank (a hardware layer the software canvas misses), use PixelCopy.request(activity.window, bitmap, …) instead and say so in a comment on this bead.
    • device: answers { os: String, model: String, simulator: bool }. iOS: UIDevice.current.systemVersion, the model identifier, and #if targetEnvironment(simulator). Android: Build.VERSION.RELEASE, Build.MODEL, and whether Build.FINGERPRINT contains generic or Build.HARDWARE is ranchu or goldfish.
  2. snapshot.rs on a phone. Replace the stub module's use on mobile with one (#[cfg(mobile)] mod platform) whose snapshot asks the plugin for the PNG's path, reads the file, deletes it and sends the bytes; whose pixels is the PNG decode (move the Windows module's PNG decoding into a shared private function and call it from both; do not copy it); and whose CONTENT_TYPE is image/png. capture gets one more cfg arm. Keep the stub for other targets (Linux). If the file passes 500 lines, move each platform module to snapshot/<platform>.rs behind the same snapshot, pixels and CONTENT_TYPE.
  3. Scale. Snapshots::pngs crops by the ratio of the image's width to the page's CSS width (page_width). The phone's PNG must be the whole webview, safe areas included, at the device's scale: check that a region chosen on the page crops the same pixels in the image (the test crops_a_region_at_the_display_scale shows the arithmetic), and that the frozen frame the reporter shows (snapshotUrl) lines up with the page under it.
  4. Smoke mode checks it. In ui_ready, a phone now takes the same path as the desktop: capture, make the PNGs, and only then journal the ready record that mobile.py's READY waits for, plus a record with the timings the desktop prints. On failure journal an error and exit with status 1. An iOS app must still end with std::process::exit (the existing comment says why).
  5. Platform as one value. In beryl_session::ipc::AppInfo, replace mobile: bool with platform: Platform (a ts-rs enum, camelCase: macos, windows, linux, ios, android) and simulator: bool. beryl_app sets them from cfg! and, on a phone, from the plugin's device. Regenerate ui/src/generated/protocol.ts (its header says how). In ui/src/ipc.ts derive from it: whether the app is on a phone (what App.tsx passes to setMobile and canExportBugs), and artSchemeUrl's choice (windows and android use http://beryl-art.localhost), deleting the user-agent sniffing. Update the fixture transport's app_info reply.
  6. The report says where it was filed. Add to the report's front matter: platform (as above), and on a phone os, model and simulator. Pass them into bugs::write from report_bug; do not read them from a global. On desktop the front matter gains only platform.
  7. bugs::dir() on a phone. report_bug calls bugs::dir(), which on a phone depends on set_dir having run in setup. Keep it, but make report_bug and the "started" journal line use one value computed in setup and held in Tauri state, so that the app never falls back to a path under $HOME inside the sandbox.

Verify

  1. just test-rust -p beryl_app -p beryl_session, and cd rust && cargo clippy -p beryl_app -p beryl_mobile -- -D warnings.
  2. just ios-smoke and just android-smoke pass, and each prints or journals the snapshot's size in bytes. Run each twice.
  3. just smoke passes (the desktop's snapshot is untouched).
  4. In the iOS Simulator (just ios, then the iOS Simulator tool's screenshot) and the Android emulator (just android, then adb -s emulator-5584 exec-out screencap -p), open a game, open the menu, press Report Bug: the frozen frame fills the screen and lines up with the page. Save one report on each with a region selected, pull the report folder out by hand (xcrun simctl get_app_container <udid> ca.thurn.beryl data; adb exec-out run-as ca.thurn.beryl tar c <folder>), and check that window.png is the whole screen, screenshot.png is the region, and report.md has the platform lines. The reporter's UI is still the desktop's and awkward by touch: by-7pm.3.6 fixes that.
  5. cd ui && npm run typecheck && npm test; just ui-shots game-start and one shot whose route has phone still pass.
  6. uv run --quiet --project tools by mobile-check (slow CI's mobile lane), then just check.

Acceptance criteria

A plugin crate beryl_mobile gives the app a webview snapshot and device info on iOS and Android; capture_window works on both and smoke mode requires its PNG there, so just ios-smoke and just android-smoke cover it; AppInfo carries platform and simulator in place of mobile and the UI derives phone mode and the art scheme from it with no user-agent sniffing; a report's front matter names its platform, and on a phone its OS, model and simulator; a report saved in the simulator and in the emulator has a whole-screen window.png and a cropped screenshot.png; just smoke, just test-rust, clippy, by mobile-check, typecheck and just check pass.

Mason (by-7pm.2.1) notes for this bead, not filed separately:

  1. Platform as one typed value: today the UI tells platforms apart three ways: AppInfo.mobile: bool (beryl_session ipc.rs, set from cfg!(mobile)), UA sniffing in ui/src/ipc.ts artSchemeUrl (/Windows|Android/), and canCaptureWindow() = 'TAURI_INTERNALS' in window (true on phones although capture fails there until this bead). Since this bead adds front matter 'platform' (ios/android, simulator/device, OS, model), replace AppInfo.mobile with a ts-rs enum, e.g. platform: 'macos'|'windows'|'ios'|'android' plus simulator: bool, set in beryl_app from cfg; derive mobile, the art scheme URL and capture support from it in ipc.ts, and write the same value into the report. Net: one source instead of three.
  2. snapshot.rs is 423 lines with macos/windows/other modules; adding iOS and Android puts it well past 500. Split the platform modules into snapshot/{macos,windows,ios,android}.rs behind the existing platform::snapshot/pixels signatures, and replace capture()'s three cfg'd call sites with one per-platform fn taking the PlatformWebview.
  3. bugs::dir() resolves BERYL_BUGS, then a OnceLock set by beryl_app's setup on mobile, then the macOS/Windows path: anything calling it before setup on a phone silently gets $HOME/Library/... in the sandbox. Keep the fallback for beryl_cli, but have beryl_app compute the folder once in setup and pass it to bugs::write (it already takes dir) and to the journal line, so the app never reads the global.
