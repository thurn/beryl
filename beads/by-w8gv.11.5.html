Close reason

Split protocol.rs into 10 modules under 800 lines, code moved only; pushed to staging

Description

Split rust/crates/beryl_session/src/protocol.rs (2,489 lines) into a protocol/ directory of modules, each under 800 lines, moving code only. Milestone 6 of Project 50k owns this split (plan K17); later beads of the milestone add the prompt shapes as new modules beside these.

The split

Make rust/crates/beryl_session/src/protocol/mod.rs and move the file's items into these modules, in file order (line numbers are today's; find items by name if they have drifted):

  • view.rs: the view types from PlayerView to TargetRef (about 32 to 325).
  • decision.rs: DecisionView, Refused, RefusalView, AskView, PassTo, CandidateView, Payment, Candidate (about 326 to 610).
  • outcome.rs: OutcomeView, LossReason, Culprit, AbilityRef, AbilityClass (about 612 to 680), with outcome_view and ability_ref (about 2100 to 2186).
  • stops.rs: StopsSetting and StepSet with their impls (about 683 to 790).
  • event.rs: GameEvent (about 793 to 918) with recipient, ability_event, cast_item, counters_event, mana_event, library_event, game_events, game_event (about 2187 to 2455).
  • names.rs: the mirror! macro and every enum it makes, CardType, Keyword (about 920 to 1043).
  • build.rs: Moment, player_view, pending_attackers, player_state, card_handling, side, slots, name, face_name, object_view, ability_order, paid_costs, stack_item (about 1045 to 1488).
  • decide.rs: decision_view, refused, halt_view, ask_view, pass_to, skip_idle_blocks, the From<NextStop> for PassTo impl, decision_source (about 1489 to 1736).
  • candidates.rs: candidate, mana_candidate, ability_nth, land_face_name, cast_candidate, casting_options, color_words, activated_cost, cost_text, counter_name, activate, trigger (about 1737 to 2099).
  • The mod tests at the end goes with the code it tests, or to protocol/tests.rs if it tests several modules.

Rules

  • Move code only: no renames, no changes of behavior, no edits to doc comments beyond fixing an intra-doc link the move broke. Keep each item's comments with it.
  • mod.rs re-exports every public item (pub use view::*; and so on) and keeps the module's top doc comment, so every crate::protocol::X and beryl_session::protocol::X path in the workspace still resolves with no edit outside this directory. Helpers one module needs from another become pub(super).
  • ui/src/generated/protocol.ts must come out byte-identical: cargo test -p beryl_session --test typescript passes with no regeneration.
  • Remove rust/crates/beryl_session/src/protocol.rs from data/file-length-allowlist.json; add no new entry.
  • Other sessions edit this file: enact push rebases, and a conflict is resolved by applying the other change to the item's new home.

Tests

cargo test -p beryl_session; just check.

Need not read

Anything outside rust/crates/beryl_session/src/protocol.rs and the use lines that import from it.
