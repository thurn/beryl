Derek Thurn2026-11-08

Review of by-7pm.1.1/1.2. Fixed (72ef2db9): (1) mobile.run_records gathered every journal run with the smoke's pid; a freshly booted emulator reuses pids, so an earlier passing run could pass a failing smoke. Now takes only the last run with that pid; tests/test_mobile.py covers it (fails on the old code). (2) android start_emulator used adb wait-for-device, which hangs forever if the emulator dies (e.g. its AVD is running elsewhere); now polls boot with a 600 s hang guard, and smoke waits for the emulator it killed to exit. (3) ios-smoke/android-smoke now hold a per-platform file lock in the cache, so parallel sessions don't reinstall under or shut down each other's simulator/emulator. Checked, left alone: cfg gating (ui_ready mobile exit, setup's set_dir, activation policy macOS-only, snapshot stub), bugs::set_dir keeps desktop path, rustls only on Android, gen/apple and gen/android commit no build output (build dirs ignored; worktree clean after builds), CSP/art scheme URLs, portrait orientation. staticlib+cdylib crate types cost desktop ~0.5 s per beryl_app rebuild (2.0 vs 1.5 s at load 42) and a 468 MB .a; Tauri's mobile CLI needs them, so kept. Android smoke spawns getprop per smoke_seconds call (3 per launch): negligible. Verified: just smoke, ios-smoke (build 42 s), android-smoke (build 67 s) pass.
