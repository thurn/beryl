Close reason

Published host zone grants for manual controls and verified both seats and owner returns

Description

A lent opponent hand still has no hand commands because ui/src/table/menuRows.ts::allowed rejects every opponent hand before it consults the host grant. ui/src/table/dropActions.ts::available mirrors the host's owner-or-grant destination rule only for hand, so the UI can offer an opposing library destination that permissions::Reference::MoveInto refuses. TableView also encodes the same hand grant twice, in acting and lent_hand. Object references already distinguish an explicitly revealed card from access to the whole zone.

Use a single authoritative host-projected zone-grant representation (existing TableView.acting can serve), exposed from the permission logic in rust/crates/beryl_table/src/permissions.rs and projected by beryl_table_session/src/view.rs. Make menuRows.ts, dropActions.ts and controls which use hidden zones consume that grant consistently, removing lent_hand and its duplicate special cases. Preserve the recipient's right to act on individually revealed cards without a whole-zone grant, and the destination exception for moving a card into its owner's hidden zone. Enable the existing hand commands for the lent zone only to the extent the host allows each command; for draw/mulligan keep the library-and-hand requirement.

Acceptance criteria

A deterministic adapter test covers owner, lent zone, individually revealed card and ungranted zone for both seat perspectives. A two-seat fixture or headless test verifies hand action availability changes with a grant and the drag target for an ungranted opposing library rejects an unowned card while still accepting the library owner's card. Existing solo behavior is unchanged.
