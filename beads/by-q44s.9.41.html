Close reason

Beryl 3D hosts, joins and resumes manual tables; Manual table connection convention is a recording entry (d892bc581)

Description

Beryl 3D can only open a solo manual table. The web interface also hosts, joins and resumes linked tables, and the UI Conventions entry "Manual table connection" (no-equivalent) needs those screens: Resume table on the start screen for saved hosted tables and for the last table the guest joined, join failures on the join form, a version mismatch shown to both players, and quitting keeping the guest's join while leaving clears it.

Already built (by-q44s.9.24): the banner and input freeze while LinkState is Reconnecting or Left, and Lobby on a table the other player left (rust/beryl3d/crates/beryl_scene/src/manual/link.rs, recording screen/table-left). The session in rust/beryl3d/crates/beryl_3d/src/session.rs drops every TableEvent but Lobby; TableEvent::Error (join failures, version mismatch) must reach the client as an Input.

Build, following the web: ui/src/table/lobby/TableEntries.tsx (Host, Join and Resume table forms, saved tables list, errors), ui/src/table/link.ts (error events), ui/src/screens/Table.tsx. Session API: rust/crates/beryl_table_session/src/connections.rs (host, join, resume, saved, join_mismatched_for_test, cut_host_for_test). Add SessionCommands for host, join, resume and saved in rust/beryl3d/crates/beryl_scene/src/command.rs and map them in driver/recording.rs (ipc::TABLE_HOST, TABLE_JOIN, TABLE_RESUME, TABLE_SAVED). Start screen: rust/beryl3d/crates/beryl_scene/src/screens/start.rs. Add screen recordings in rust/beryl3d/crates/beryl_inspect/src/screens.rs (a start screen with saved tables, a join form with an error), then replace the "Manual table connection" entry's {"open"} in data/beryl3d/conventions/no-equivalent.json with a recording entry. Never edit data/ui-conventions.json.

Run: just b3d cargo-test -p beryl_inspect conventions, just b3d test, just b3d parity.

Acceptance criteria

The 'Manual table connection' entry in data/beryl3d/conventions/no-equivalent.json is a recording entry that the conventions test passes; Beryl 3D's start screen offers Resume table for a saved table and its join form shows a join failure; just b3d test passes; enact push passes.

Handoff: Beryl 3D now hosts, joins and resumes manual tables (staging d892bc581).

What changed:

  • beryl_scene/src/command.rs: SessionCommand::TableHost { name }, TableJoin { invite, name }, TableResume(id), TableSaved; Reply::TableOpen(Result<(), String>) and Reply::TableSaved(Result<Vec<SavedTable>, String>). input.rs: Input::TableError(String).
  • beryl_3d/src/session.rs: maps the new commands to TableConnections::host/join/resume/saved with Platform::current(), routes TableEvent::Error to Input::TableError, and sends the saved tables before the agents in begin().
  • beryl_scene/src/screens/table_entries.rs (new): the start screen's Host a table (desktop only, also Cmd+N from lobby.host), Join a table, Solo table, the host/join form (fields "table name", "invite code"), the saved tables with Resume table, "Could not load saved tables." and the last error. Replaces StartForm::solo_failed.
  • beryl_scene/src/client/entries.rs (new): press handling and replies. Opening a table shows the empty lobby at once, as Solo table does; a failure brings the start screen back with the reason. TableError goes to the start screen while a table opens, and otherwise to Lobby::link_error, which the lobby and the table's connection banner (manual/link.rs) show. It is cleared when a table view's link is Connected or both lobby seats are named.
  • driver/recording.rs: wire names for the new commands; an unrecorded table_saved answers with no tables; a recorded table_host/join/resume value of {"reason": ...} is a failure. driver/mod.rs gives the saved tables before the agents, as the live session does.
  • beryl_inspect/src/screens.rs: new recording screen/start-tables (a joined table "Sam · Alex" and a hosted table "Alex", and a join refused with the version-mismatch text). "Manual table connection" in data/beryl3d/conventions/no-equivalent.json is now a recording entry that joins and shows the mismatch. New test the_start_screen_offers_resume_table_for_saved_tables (desktop and phone).
  • beryl_protocol SavedTable gained Clone.

Decisions:

  • Hosting is always TableLink::Local, with no Connection choice, because beryl_3d builds beryl_table_session without the iroh feature. This matches the web's browser build. Enabling internet play would mean turning on that feature and adding the web's Internet/Local select.
  • Saved tables arrive before the agents so that the start screen's first frame lists them. Without that, the panel re-centred after the reply and the overlap check caught gliding buttons crossing the new list at t=90ms. The client keeps the last list between visits and asks again each time the start screen opens.
  • take_agents moved from client/mod.rs to client/screen.rs to keep mod.rs under 800 lines.

Checks: just b3d lane passed except two tests that fail on staging without this change (beryl_assets glyphs::every_icon_and_demanded_glyph_fits_the_atlas_at_every_display_scale and beryl_inspect furniture::the_life_orbs_are_drawn_in_the_webs_core_bezel_and_ring; I reverted my commit locally and both still failed). Staging's d83b8c70f updates both. Interface tests: 8368, 0 faults. Gate passed after rebasing.

Picture: just b3d compare screen/start-tables --at end --scale 2 wrote ~/Library/Caches/beryl/b3d/out/screen_start-tables-you-1600x900-end-compare-44900.png. The Beryl 3D side shows the entries as intended. The web side shows a game board, because the web does not read the beryl3d-open event that engine-less screen recordings use, so these recordings have no web counterpart to compare.

For a reviewer: the reply ordering in client/entries.rs (Lobby events can arrive before Reply::TableOpen; the client then asks for the lobby with LobbyChange::View), and the link_error clearing rules in client/lobby.rs and client/manual.rs.
