Derek Thurn2026-11-15

Every place the frame thread can wait, as of this review (desktop, windowless and phone hosts, beryl_3d's AppFeed, the renderer). Checked by reading every call reachable from FrameLoop::handle/tick/schedule and each host's event handlers, and grepping beryl_host, beryl_render, beryl_assets and beryl_3d for lock(), recv(), join(), sleep, fs:: and println.

Waits by design:

  1. Renderer::present -> Surface::get_current_texture: the wait for a drawable from the display (FIFO, 2 frames in flight). Logged as Shown.waited. This is the one wait the doc allows.
  2. --slow-gpu: std::thread::sleep in Screen::draw (desktop) and Offscreen::draw (windowless). Opt-in, imitates a slow GPU.
  3. Windowless host: recv_timeout/recv on its inbox between ticks. That is its event-loop sleep, not a wait inside a frame.

Waits at startup or exit only (not during play):

  1. Renderer::for_window / headless: pollster::block_on(request_adapter/request_device), before the first frame.
  2. Commands::close joins the session thread, but only a test calls it; the app drops Commands when the event loop ends, which detaches the thread without waiting.
  3. FrameLog::finish joins the log's writer: on the desktop after the event loop ends. On a phone it ran on the frame thread at the fixture's end; it now runs on a thread of its own (fixed here).

Waits that remain during play, accepted:

  1. println!/eprintln! on the frame thread: FIRST_SHOWN and FIXTURE_ENDED once each, fixture answer errors (tools builds only), and the atlas's wrong-size page message. Each takes the stdout/stderr lock and can block if the reader of a pipe stops reading. Once per run, so left alone.
  2. winit calls in carry_out (IME on/off, cursor area) and set_fullscreen: AppKit calls on the main thread that do not wait on Beryl's threads. Share/OpenUrl spawn a thread each.

Waits that were found and removed here:

  • FrameLog::create created the folder, created the file and wrote and flushed the first line on the frame thread when the host opened (file I/O). The log's thread now does it, and finish reports a failure.
  • The phone's finish_log joined the writer on the frame thread (see 6).

Not on the frame thread (checked): Sessions calls (session thread only; Commands::send is an unbounded mpsc send), GlyphWorker::flush and Preparer's drop-join (Headless only, a tool), ArtCache downloads (worker threads). The frame thread holds no Mutex: the only Mutexes are Preparer's job queue and send lock, taken by its workers only.

Derek Thurn2026-11-15

Review findings (staging 6047c8b9f). Fixed: (1) beryl_render's instance buffer held 4096 records but frame::DRAWS is 8192, so a full stress-1024 frame created a GPU buffer on the frame thread mid-play; now made once at DRAWS, never replaced, records past it dropped with a debug_assert (test render.rs the_largest_frame_draws_its_last_record, both limit sets). (2) set_class was a no-op on Windows and iOS: session/search threads ran at drawing's priority there. threads.rs now uses SetThreadPriority (BELOW_NORMAL/NORMAL/HIGHEST) on Windows (windows-sys 0.61.2, already in the lock) and QoS on all Apple targets; QoS calls moved out of macos.rs. Test threads.rs. Windows code clippy-checked in a scratch crate, since beryl_host cannot cross-build for MSVC from the Mac (ctt's C++). (3) Preparer and GlyphWorker threads never set a class and would inherit the frame thread's; Config.start / spawn(.., start) now take a fn, hosts pass beryl_host::asset_thread (Default class). (4) Phone::frame returned only Client::wake, ignoring the feed (fixture views) and the pause; FrameLoop::next_wake is now public and used (test frames.rs the_loops_wake_counts_the_feed_and_the_pause). The Swift/Kotlin hosts ignore the value today. (5) Renderer::for_window requested wgpu default limits; now downlevel_webgl2 with adapter resolution, like phones. (6) FrameLog::create did file I/O on the frame thread; now on the log's thread, errors via finish (test). Phone finish_log moved off the frame thread. Doc 'Threads' updated. Checked, no issue: no wgpu type outside beryl_render; every unsafe block in my scope has a SAFETY comment; beryl_art move keeps get()'s behavior (now re-reads the file after download) and beryl_app links only beryl_art+ureq, no encoders; fonts are include_bytes and glyphs rasterize on the worker; frames draw only on display link/redraw/timer/platform ticks and only when wanted; film width capped at 2000 px and picture names carry the pid. Left alone: depth texture is made on the first frame and on resize (inherent to resize); full-size face uploads may land mid-animation by design (doc); println of FIRST_SHOWN/FIXTURE_ENDED on the frame thread (once per run). Note: the beryl3d lane passed but ran 143 s against a 60 s budget under load ~40; by-wzq9 already tracks that.
