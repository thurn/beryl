Close reason

Beryl 3D screens take sizes from design tokens; scene-literals check added

Description

Symptom class: the phone layout's screens will copy the desktop screens' sizes by hand, and the two will drift, because the flat layer's screens write their spacing and type sizes as number literals instead of design tokens.

Rule 6 of epic by-q44s says spatial and color values are data, never literals: for the flat layer they come from data/design-tokens.json through beryl_scene's generated tokens module (rust/beryl3d/crates/beryl_scene/src/tokens.rs, written by beryl_scene's build.rs write_tokens). Most of milestone 3's screens follow it, but these files still hold their own numbers (count of non-trivial float literals, from grep -cE "[^a-zA-Z_.0-9][1-9][0-9]*\.[0-9]+", under rust/beryl3d/crates/beryl_scene/src):

  • screens/start.rs 48 (PANEL_WIDTH 620, PANEL_PADDING, PANEL_GAP, PANEL_RADIUS, AROUND_AGENTS, AGENTS_LEAST, SEED_WIDTH, CORNER, RADIO, CHECKBOX, eight local TypeStyles, inline .gap(12.0), .radius(8.0), padding arrays),
  • screens/bug_report.rs 30, inspect/inspector.rs 26, screens/lobby.rs 17, prompts/order.rs 12, screens/game_over.rs 11, widgets/slider.rs 9, hud/steps.rs 9, screens/opening.rs 7 (two local TypeStyles), hud/counts.rs 7, and 1 to 6 each in manual/drop.rs, hud/notices.rs, screens/settings.rs, screens/gallery.rs, manual/tokens.rs, inspect/revealed.rs, hud/players.rs, hud/banner.rs, screens/testing.rs. Also Window::phone in table/mod.rs compares with the literal 500.0, which docs/beryl-3d.md 'Sizes' names as the phone threshold; it belongs in data/beryl3d/space.json (by-q44s.7.17 "Share the Beryl 3D phone layout selector" may already move it; if so, leave it).

Why now: by-q44s.7.20 and by-q44s.7.21 add *_phone variants of exactly these screens and are told to reuse the desktop's builders. With the values as tokens, both layouts read one name; with literals, each phone function copies or re-guesses them.

Proposed change:

  1. Move each value to data/design-tokens.json: shared ones into the existing space, size and type-style tokens where an equal token exists (the web interface's CSS often already has it: check ui/src/design/tokens.css and the screen's CSS in ui/src/screens), and the flat layer's own into the file's flat object, which only beryl_scene reads. Run just design-tokens so ui/src/design/tokens.css stays generated (its output must not change for any token the web already used). Keep every value equal to what it is now: this is a move, not a retune.
  2. Ratios that are not sizes (line heights inside a TypeStyle, 0.5 for a centre, 0.75 scale factors) may stay where the token file has no kind for them, with a named constant.
  3. Add a source check to the beryl3d lane in tools/src/beryl_tools/beryl3d (model it on purity.py, the scene-purity check, and register it the same way in lane.py) that fails on a float literal other than 0.0, 1.0, 0.5 and 2.0 in beryl_scene src/screens, src/prompts, src/widgets, src/hud, src/inspect and src/manual outside #[cfg(test)], with a message that names the token file. No allowlist: the move above takes the count to zero first.

Behavior that must not change: just b3d test (every interface test, its faults file data/beryl3d/test-faults.json unchanged), the tree printouts of just b3d tree for the start, opening, game over, lobby and bug report screens (positions identical), and just design-tokens --check.

Acceptance: the new check passes on the result and fails when a .gap(12.0) is added to screens/start.rs (a tools test in tools/tests or the lane's own test file shows this); just b3d lane passes.

Note: data/design-tokens.json and ui/src/design/tokens.css are outside Beryl 3D's paths, so this change also runs the main design-tokens lane. Moving the start screen's numbers is the bulk of the work.

Acceptance criteria

No float literal beyond 0, 0.5, 1, 2 in the listed beryl_scene folders; a beryl3d lane check enforces it; tree printouts and just b3d test unchanged.
