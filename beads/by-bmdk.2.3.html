Close reason

Added ordered per-seat table animation events with hidden hand motion and scoped look and reveal facts.

Description

The adapter plan in by-bmdk.3.2 asks for a fly when either seat watches a draw, and by-bmdk.3.3–.4 need repeated looks/reveals and animated batch members. In beryl_table/src/redact.rs, entry_seen_by intentionally removes Move and ReplaceId for a card moved into a hand hidden from the viewer. It returns the same Entry type as host history, retains no public movement event, and evaluates redaction using only the entry-wide before and after tables. In apply/mod.rs batches flatten member changes with no member boundaries. In apply/library.rs a look or reveal only writes Learn for a newly informed seat, so no changes can describe an already-known selection. A parallel second implementation of actions and visibility in each adapter script would make these mistakes recur.

Change beryl_table/src/{apply/mod.rs,apply/library.rs,redact.rs,log.rs} and tests/{redaction,history}.rs. Keep the host's reversible Change stream and the existing action/outcome save format. Provide a distinct per-seat animation projection with an ordered event or member stream. It may use transient projected locations and face-down motion for a hidden hand entry, but must never disclose its old-to-new identity mapping or the shuffle permutation. Give a look/reveal separately scoped presentation facts even when Learn is empty. Use the state at each member or event for its visibility and avoid duplicating host action decoding in each consumer. Preserve current visible log wording and rollback behavior.

Acceptance criteria

From public Table actions and the projection API, cover a mixed batch (move a public card into the other player's hand, shuffle, draw, look twice, and reveal an already-known card), plus a draw followed by undo. Verify the event and member order for both viewers. The other seat sees the appropriate anonymous movement and look count, the allowed seats can see the reveal, and no projected payload gives an old-to-new private id link, permutation, private random offset, or unauthorized card name. Existing history and save round-trips pass.

Handoff: Use beryl_table::redact::animation_seen_by on the original host Entry and the host table immediately before it. The result groups events in flattened batch member order. Mulligan has return, shuffle, and draw groups, and undo walks the inverse groups. HandMove is a face-down zone-to-zone flight for the other seats and carries only the hand-side identity for the owner. Shuffle installs the fresh library order. Look supplies the selected cards to its actor and a count to other seats, and Reveal supplies cards only to its recipients. Use entry_seen_by with log::line. The action/outcome save format reconstructs the animation facts on replay.
