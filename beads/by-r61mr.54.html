Description

Work in the Enact repository (~/enact), delivered with that repository's own enact worktree create and enact push. Read the epic by-r61mr for the shim's role in the cutover.

After cutover, bd is the shim in cli/src/shim.rs. Any command line its clap parser (Options and Action) does not accept fails with "bd: unsupported arguments for ...; use tk ...". On 2026-11-16, JARVIS recorded 9,126 real bd calls (see the comment on by-r61mr.25). Agent sessions typed these commands by hand, and the shim rejects all of them today:

  • bd search <words> [--status S] [--json]: 30 calls, the most common rejected command after history. Sessions use it to check whether a bug is already filed, for example bd search mana symbol --status open or bd search atlas --json. Native tk has no search either, so this gap stays after the shim is deleted (by-r61mr.31).
  • bd create "<title>" --type bug -p 0 --parent X -l tier:opus,lane:y --body-file F --acceptance A --silent: 5 calls. Real bd accepts the title as a positional argument and -l as short for --labels. The shim's Create (cli/src/shim/create.rs) requires --title and has no -l.
  • bd children <id> --json: 1 call. It is the same as bd list --parent <id>.
  • bd list --label-any <a,b> --status open: 1 call. It matches tickets that have any of the given labels. The shim's list supports only --label, which requires every label.
  • bd comments add <id> -f <file>: 1 call. It reads the comment text from a file. The shim's Comments takes only positional arguments.
  • bd dep cycles: 2 calls. It lists dependency cycles. cli/src/shim/diagnostics.rs already computes blocking_cycles for ready --explain.

Add these to the shim, and add tk search to the native CLI (cli/src/args.rs, cli/src/commands.rs) so that it outlives the shim:

  • Search matches words against the title, case-insensitively, plus an exact or prefix match on ID, including legacy by- IDs. It covers all statuses unless --status is given and supports --json and --limit. Build it on the server's existing list title filter (server/src/ticket-store.ts, filter.get("title")), or add a server query parameter if a word-based match needs one. Match real bd's JSON row shape (bd search --help and bd search x --json on ~/.local/bin/bd show it).
  • Mirror bd 1.3.x's output for the other commands, the same way the existing shapes do.

bd version, bd sync and bd history were left out on purpose. version and sync mean nothing on the ticket server, and history is only called by Beryl's status site, which by-r61mr.29 removes. Add each new shape as a replay case in cli/tests/shim-replay.py, using the recorded command lines above as the examples.

Acceptance criteria

Each command line listed in the description runs through the shim against the local Wrangler simulator, and its output and exit code match real bd 1.3.x within the replay's existing normalization rules. tk search <words> [--status S] [--json] works natively. cli/tests/shim-replay.py has cases for search, positional-title create with -l, children, list --label-any, comments add -f and dep cycles, and they pass in Enact's fast check.
