Close reason

Landed the solo table session and all four app commands on staging, with game-update delivery and typed refusal replies.

Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), sections 'Networking' (the first three paragraphs) and decision T21. Epic 'Contracts' (App commands) and Rules, 6.

Make a manual table reachable from the interface, for one seat, with no link.

  • rust/crates/beryl_table_session/src/sessions.rs: TableSessions, holding at most one open table. solo(deck: Deck, emit) creates a one-seat table, loads the deck, applies start, and emits the first update. act(action) -> Result<(), Refusal> applies it as seat 0, then builds the view (view.rs) and script (script.rs; until the script beads land, send the view with a reset script) and emits a GameUpdate on the existing game-update event, exactly the value an engine game emits. current(), leave(). Look at beryl_session/src/sessions.rs for how Sessions holds its emitter and is shared with the app; mirror it.
  • Commands (Rules, 6, all four places each): table_solo { deck }, table_act { action } returning { ok } | { refused: reason, blocked_by? }, table_current, table_leave. The request takes the existing beryl_session::protocol::TableAction with viewer references. Keep the matching TableActionRefs from the current projection and invoke TableActionRefs::apply as the authenticated seat. TableAction is already generated into the protocol and covered by WIRE_HASH. Use wire_hash for additional message types if needed.
  • ui/src/ipc.ts: tableSolo, tableAct, tableCurrent, tableLeave.
  • rust/crates/beryl_cli/src/serve.rs: the same four routes, so liveTransport and headless checks can run a manual table.
  • A refused action must reach the interface as a value, not an error, so it can shake the card.

Tests: tests/solo.rs drives TableSessions directly (start, draw, play a land, tap it, undo) and checks the emitted updates; a serve.rs test posts table_solo then table_act over HTTP if that file already has such tests for engine commands (follow its pattern). Run just test-rust -p beryl_table_session -p beryl_cli -p beryl_app and cd ui && npm run typecheck.

Acceptance criteria

table_solo, table_act, table_current and table_leave work through Tauri handlers, the HTTP server and ipc.ts wrappers; updates arrive on game-update; Action is a generated TypeScript type; a refused action returns a value.
