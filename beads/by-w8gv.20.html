Description

The CI track of Project 50k: decisions K18 to K21 in docs/project-50k.md (Decisions; Target architecture, Checks; Milestones; Acceptance; Measurements, Slow CI). Read those sections before any bead here. It runs beside the other four tracks and blocks nothing.

Why

Slow CI failed 60 of 414 runs; 57 were the browser lanes (ui-test, shots), which the fast check never runs. 34 Steward beads in five days (2026-11-06 to 11-10), about 12 per 100 landed commits: about 12 a test made stale by an intended change, 9 a test racing the wall clock, 8 a real bug, 2 host load or a cold cache. Nothing records what a check has caught or cost.

Decisions from the user (design interview, 2026-11-10)

  • Affected browser checks run in the fast check, so the author repairs what they broke. Chosen by measured coverage (a nightly Chromium run records the functions and CSS rules each check executes), capped by time, worst failure record first.
  • Every run of every check is logged to $BERYL_CACHE, never committed. A check is one Rust test, browser check, screenshot or oracle scenario.
  • Verdicts are inferred, and the agent is asked only when the tool cannot tell: flaky (passes on rerun, tree unchanged), stale test (the fix touched only the check or its fixture), caught a bug (the fix touched product code), selection miss.
  • A failed check reruns once. Two flakes in seven days quarantine a check: it runs and is logged but cannot fail a run, and files no bead.
  • A weekly Sonnet bead applies the pruning rule with no approval step, in one commit listing what it removed with its numbers: delete at three stale updates and no catch, or quarantined and never caught anything; fix when quarantined with a catch; slow CI only when never failed and in the costliest tenth; a keep comment with a reason overrides.
  • New browser coverage goes to the generic audits first (K20, already in AGENTS.md, Checks).
  • The 212 existing checks get their records backfilled from history and the rule is applied once.
  • A slow-CI failure that survives the rerun is bisected by by ci, which ends its log with the checks, the culprit commit and each check's record. Enact already copies the log's tail into the Steward bead: no Enact change. Load and cold-cache failures rerun and file nothing.
  • Slow CI stays the full sweep on every staging tip until the miss rate is measured.
  • Budgets stay 60 s and 300 s.

Steps

  1. Measure and stop the bleeding: the beads filed here.
  2. Select and bisect: decomposed by this epic's decompose bead against the log as built.

Acceptance

  • Bar: over the two weeks after step two lands, at most 2 Steward beads per 100 landed commits, with the fast check within 60 s for a UI change. Missed after three attempts: record the measured value and cause here and file a follow-up.
  • Then, if selection misses are under 1 per 100 commits, a follow-up moves the browser lanes' full run to nightly.
  • Reported, no bar: failures by verdict, flakes and quarantined checks, checks deleted, seconds per lane. Never tune to these.

Code map

  • tools/src/beryl_tools/checks.py: Lane, Steps, run_lanes, fast, slow, rust_tests_step (nextest). shots.py: ui_shots, ui_test (title filters), record_fixtures. paths.py: cache_root. oracles.py: the oracle report.
  • ui/scripts/interactions.mjs: check() (line 149), the 212 checks, wanted() title filter. capture.mjs: workers, screenFaults and the control audits. audit.mjs: duplicate and motion audits. shots.mjs with ui/shots.json.
  • Slow CI's history on the development machine: .git/enact/ci.log in the main checkout (ci: lane lines and FAILED: titles). Steward beads: bd list --all --label role:steward.

Models

tier:opus by default; tier:sonnet for mechanical, fully specified beads. Warden and decompose beads are tier:opus. No tier label on this epic.
