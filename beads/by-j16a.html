Description

Symptom: a game against the "random" opponent, saved and resumed, plays on differently from the same game played without stopping. beryl_session's test a_game_resumed_from_its_save_plays_on_as_if_it_never_stopped (crates/beryl_session/tests/sessions.rs) failed this way once Leonin Scimitar joined the card pool and changed the decks fuzz_deck deals for seed 3.

Cause: Game::from_replay (crates/beryl_session/src/game/replaying.rs, the (At::Agent(d), Entry::Choice) arm of the replay loop) applies each logged agent choice with agent_decides without calling the agent. RandomAgent (crates/beryl_search/src/lib.rs) draws from a SplitMix64 stream once per choose, so after a resume its stream is back at the seed, and its first multi-candidate decision after the resume differs. Any other agent that keeps state between decisions has the same problem.

The test now plays against the greedy agent, which keeps no state, so it still checks save and resume. Fix options: derive a stateful agent's randomness from (seed, decision number) instead of a running stream, or have the replay advance the agent (an Agent::replayed hook) for each logged agent choice. Then switch the test back to "random" (or add a case for it).
