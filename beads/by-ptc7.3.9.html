Description

What to build

Plan: Designs E6. No command lists a set's cards today; data/card-store.tsv records each card's first_set, and tools/src/beryl_tools/card_store.py (Store) and set_groups.py read it.

  • just set list <code>: the cards first printed in the set, one a line, with whether each has a file (card_files.implemented()), is complete from the store (beryl_card_build's rule, mirrored in card.complete_note), or is escalated (data/card-escalations.json).
  • just set plan <code>: each unwritten card in one tier, using the drafter (tools/src/beryl_tools/draft.py, a dependency):
    • store: complete from the card store;
    • drafted: every sentence drafted;
    • composed: some sentence has no complete draft, but each keyword is a Keywords bit or a vocabulary entry and the card's layout is one the engine has;
    • vocabulary: a sentence whose nearest wording is far (a threshold you set from the implemented cards), grouped by the normalised sentence, most cards first;
    • mechanism: a keyword, layout or rule the engine lacks (from just census's uncovered kinds and the card store's keywords and layout). It prints the table with counts and writes $BERYL_CACHE/set-plan-<code>.json with the cards of each tier and, for vocabulary, each group's sentence and cards.
  • --beads prints, and does not file, a bd create line for each vocabulary group (tier:opus) and each batch of twenty drafted or composed cards (tier:light and tier:sonnet), so a later planning session can file them under its own epic.
  • tools/tests/test_set_plan.py, and a paragraph in rust/AGENTS.md.

Run it on original Theros (ths, 211 cards first printed there) and put the table in the close reason. Do not write any Theros card.

Tiers from Phase's parse (added 2026-11-15)

by-ptc7.3.8 now drafts from phase.rs's published typed parse ($BERYL_CACHE/phase/card-data.json). Use it here:

  • drafted means the draft is complete and, once written, renders exactly; before a card has a file, "complete" is what the planner can know, so report both counts where the drafter's check has them. In the prototype 63% of completely drafted commons rendered exactly; the rest named the missing words in the render diff.
  • Group vocabulary cards by the Phase node kind that has no row in the drafter's table, or whose row says Beryl has no entry, instead of (or before) the normalised sentence. One node kind is one clause shape across many wordings, so the groups are larger and each is one vocabulary bead. Phase's commons and uncommons use 637 node kinds; the 200 most common cover 81% of the cards it parses fully.
  • A card Phase cannot parse (its coverage-data.json marks gaps, 11% of commons and uncommons) falls back to the sentence rules above.
  • --beads lines for drafted batches use tier:haiku (by-ptc7.3.10 adds the tier); composed stays tier:sonnet.
  • Counting Phase's node kinds is allowed (the decision is recorded in by-ptc7.3.8); never copy a vocabulary design from it.
