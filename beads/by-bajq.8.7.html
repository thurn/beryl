Description

Review group 7 as built, against Designs 7 of docs/rules-coverage.md, and fix what you find.

Look hardest at:

  • Ability targets: every way an entry leaves the stack from below the top; a copy of a spell that targets an ability (Fork on Stifle); the invariant.
  • Phasing: grep the kernel and the rules for every walk of the battlefield queue and every battlefield bitboard, and for every test of zone() == Zone::Battlefield, and ask of each whether a phased-out permanent is rightly in or out. Phased-out permanents and the legend rule, the layer results, a static ability's set, an effect locked in on one.
  • Merged permanents: the same walk for the new zone state. A card under a permanent must never be counted as a permanent, targeted, or left behind when the permanent moves. Ownership when the cards have different owners.
  • The loop check: a loop with a choice in it that cannot break it; a loop whose state differs only in something the canonical hash should ignore, and one that differs in something it must not.
  • Saves and checkpoints (beryl_session::checkpoint): a board with a phased-out or merged permanent, recorded at a turn's start and rebuilt.

Two things every Warden of this epic reports

  • The group's count. The count gate's tolerance is one total shared by the whole epic, so a group that uses most of it leaves the next bead to fail for work it did not do. From the close reasons of this group's beads, add up the change each made to the absent-cost count (just count-gate) and put the total in your close reason. A bead that raised the count by more than 0.05% without saying why is a finding: find the cost and remove it, or file it.
  • Test definitions. List each behavior a bead of this group proved with a test definition in beryl_rules/src/tests/ where it had no real card. For each, name the card scenario that now covers the same path and agrees with XMage and Forge. Where the card has landed and no scenario does, write the scenario. Where the card is in a later group, comment on that card's bead with the path its scenarios must cover. Where no card of the epic has the behavior, file a tier:sonnet partner card bead under this group.

Bars (every bead of this epic)

  • The absent-cost gate holds with no bump (just count-gate; R2 in the plan). The count is exact, so report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust). A change to what the WU mirror's rollouts do is a bug in this epic.
  • Rules code cites the Comprehensive Rules with a quotation (root AGENTS.md); just citations.
  • A new card follows the card-writing skill: just card new, just card check <name> (Beryl, XMage and Forge), every instruction carried out by its own scenarios, and just specs <card> passing the generic UI checks from both seats. A disagreement with an oracle is settled by the rules and recorded in data/oracle-divergences.json.
  • Read the card's rulings before writing its scenarios (just card brief <name> prints Scryfall's). Each statement in a ruling that a scenario can show is a scenario of the card. Where one cannot be shown yet, the close reason names the ruling and why.
  • A rules bug found on the way gets its docs/bugs.md entry.
  • If the design in the plan is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.

Acceptance criteria

Findings fixed or filed as children of this group. The close reason gives the group's total change to the count and the list of test definitions with the card scenario that covers each.

Derek Thurn2026-11-15

Warden findings (staging c5fcf4cd). Fixed:

  1. State::off_board did not report a merged permanent. Its other cards are in Zone::Merged, which no checkpoint lists, so a turn-start save claimed it could be rebuilt when it could not. Now reported like a phased-out permanent. Test: tests/phasing.rs a_board_with_a_phased_out_or_merged_permanent_is_not_rebuilt. docs/bugs.md entry.
  2. Game::on_battlefield (asked by destroy, sacrifice, damage, gain_control, transform, explore) tested zone == Battlefield, so it counted a phased-out permanent as present. No card could reach it, because every instruction filters through Run::permanents, which reads Object::on_battlefield. It now reads the battlefield index too. exile_until_leaves keeps zone semantics for its 'until' source, because phasing out is not leaving (CR 702.26d). Phasing walks checked and correct: legal.rs activation enumeration uses zone sets; locked-in sets (apply_to_members) walk the battlefield list; layers/mod.rs Permanents::One skips objects with no battlefield position; the legend rule and SBAs walk the battlefield; memos ExiledUntil/PartOf rightly keep zone semantics. Left alone, with reasons: (a) Stifle: the resolving entry is held outside the stack, so its ability targets are not repaired if an earlier instruction of the same resolution removes an entry below them. Only a card that targets an ability and also removes a stack entry earlier in its text would hit this, and the pool has none (Stifle has one instruction). (b) Loop check: a loop whose every iteration has a choice with more than one candidate, even when no candidate can break it, resets the count and runs to the budget instead of a draw. This is a limitation, not a false draw. False draws can only come from a hash that ignores state that matters; the canonical hash ignores only incarnations (references are read relative to the current one), stale timestamps and timestamp ranks. (c) attach::may_enchant treats an Aura with no enchant ability left as unrestricted; no card in the pool removes one. (d) Merged ownership: mutate needs the same owner (Filter::Owned), so a pile of mixed owners cannot arise yet. by-bajq.8.8 covers the other abilities of cards under a merged permanent.
