Handoff: Cause was not a Beryl 3D regression but the parity tooling. ui/scripts/timeline.mjs needs a stage_timings response to time steps a prompt makes itself; 'b3d export' (beryl_inspect src/cli/timeline.rs) never wrote one because the pack has none, so the web side printed nothing for those recordings and every renamed/new spec moment with a prompt failed as unlisted. Fix: export prepends FixtureMessage::response(STAGE_TIMINGS, own_timings()) (with_own_timings); web cache hash in tools/.../timeline.py now covers exported files (else stale web lines are reused); --update drops entries for recordings no longer exported. Allowlist regenerated with --update --raise: 1688 entries/43970 steps -> 1899/8116; 215 added + 73 raised are almost all own steps (own:true marks, tray lift) that native doesn't produce yet, covered by the prompt beads by-q44s.5.. Verified: just b3d timeline-parity (full) and --fixtures pass at the rebased tip. Gotcha: each run leaves a ~400MB b3d-parity- export dir in the temp folder (kept so the printed node command can replay it).
