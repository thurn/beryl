Close reason

Smoke, Vite and playground test timers raised to hang-guard levels with 'appears hung' messages (91b07c39)

Description

What we see

Some Rust tests and smoke checks use timers. A timer is fine as a safety net against a hang, but not when a slow, healthy run on a loaded machine can reach it.

  • rust/crates/beryl_cli/src/specs/playground/history_tests.rs lines 45 and 319 call recv_timeout(3 s), which a loaded machine can exceed. This one is a gate, not a hang guard.
  • rust/crates/beryl_session/tests/sessions.rs lines 198 and 231 and games_ledger.rs line 11 call recv_timeout(120 s).unwrap(). Check against the run log whether 120 s is far above their slowest pass; if so, keep them as hang guards with a clear panic message.
  • Smoke checks: tools/src/beryl_tools/app.py (smoke, timeout=seconds + 10), mobile.py (around line 383) and android.py (around line 188), which wait seconds + 30 and fail if the app never logged that it was ready, and shots.py (SERVER_TIMEOUT, 60 s). Find how long a healthy start takes on a loaded machine and make sure each limit is a hang guard well above it.

What to change

Replace gate-like timeouts with blocking waits on a deterministic signal, or raise them to hang-guard level, and make each remaining timeout's failure say that the thing appears hung. Prefer the app exiting as soon as its UI reports that it has loaded over a fixed BERYL_SMOKE run time.

Files and tests

The files named above, rust/crates/beryl_app (the BERYL_SMOKE handling), just test-rust, just smoke, just ios-smoke, just android-smoke.
