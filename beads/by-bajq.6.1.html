Description

What is wrong today

A copy is a token whose card is the copied definition, with one exception as a flag (Flag::OneOne of ObjectFlags, CR 707.9b). A card cannot be a copy, an exception cannot be copied in turn, and a copy cannot end. The kernel contract says the flag "is the copy effects' to widen".

What to build

Plan: Designs 5, "Copiable values" and "Where they live"; decision R7. This bead changes the representation and adds no card: Fractured Identity and the token copies that exist must behave as before.

  1. Additions. A definition's face lists its copy exceptions (Face::excepts): each a short list of changes (add card types or subtypes, set or add colors, set P/T, not legendary, has an ability of Face::grants). An addition is a card and an index into that list, or a card and a face meaning "every ability of this face" (group 7's merged permanents use that). Copiable holds the face it had and up to two additions in Small, more in Large; a third in Small is Full.
  2. The fields. Object::card and Object::face hold the definition the object has the values of, so State::copiable reads exactly what it reads today. The card the object really is, where that differs, is Memo::Really(card, face), read behind the keyed bit by State::card_behind, State::definition_name and the zone move, which restores the fields as the object leaves.
  3. Layer 1. A copy effect is an entry of the Effects store on the object: the copied record, its additions and a duration. The mutators that start and end one set the object's fields to what layer 1 now gives (the latest entry by timestamp, or the real card), and an invariant checks the fields against the entries. The recompute applies the additions as it builds each row's base values. CR 305.7 removes "copiable effects affecting that land" when a land's type is set: leave that as a noted gap in the bead unless it falls out.
  4. Copying an object takes its Copiable whole, additions included, and appends the copier's own (CR 707.9). Nothing ever walks a chain.
  5. Flag::OneOne becomes an addition, and State::make_token takes the additions.
  6. What is not copied (CR 707.2): counters, memos, what is attached, the effects on it.

Mason audit (by-bajq.4.1): now blocked by by-bajq.4.2, 4.3 and 3.17. (1) An addition that gives abilities must be read through 4.2's State::abilities query; the card table's per-definition data (GameTable::listeners, Copiable::may_listen/may_replace, FaceFacts) does not see additions, so a copy with 'has this ability' or a merged permanent needs the masks and listeners from its additions too. (2) Derived::lost is a 16-bit mask over the face's abilities in Small; abilities from additions need places in it (or stall past the width). (3) Copiable is 3 bytes and each of the 16 LastKnown rows (58 bytes) holds one, so two additions inline grow the state by about 64 bytes; 4.3 gives the allotment (only 136 bytes are left today). Plan section 5 amended ('What the additions reach').
