Description

Specs generate for the card requested, not for every card at first use, and the tests that walk every spec are bounded (plan: docs/project-50k.md, Card pool pipeline, "Specs are generated for the card requested, not for every card at start"). Split specs/mod.rs under 800 lines while there.

Read first: rust/crates/beryl_cli/src/specs/mod.rs (939 lines; on data/file-length-allowlist.json at 939); the call sites of specs() listed below; .agents/skills/specs/SKILL.md. Need not read: specs/auto.rs's generator beyond the signatures of generate and checkpoints; the engine.

Today

specs/mod.rs line 45, generation(): the first call to specs() or dropped() spawns one thread per card in CARDS, generates every card's moments by playing each from both seats, and keeps the lot in a OnceLock. Everything goes through it: find (222), listing (419), describe (673), check_all (751, 758), serve.rs (154, 164, 381, 514), playground.rs (532), and the tests (mod.rs 928; playground.rs 682 and 713; playground/history_tests.rs 14). So describing one card, or serving one card's page, generates all 47; at 50,000 it would never finish.

Do

  • One card's spec is generated on its first request and cached (its dropped candidates with it); asking for one card generates no other. Nothing generates every card except a sweep someone asked for (specs-check or specs-describe with no card), and a sweep runs on a pool bounded by std::thread::available_parallelism, not a thread per card. Look cards up by name or slug without building every spec.
  • GET /specs (serve.rs annotated_listing, line 357; mod.rs listing, line 418) must not generate: it lists the cards (name, slug, reviewed, reports, momentReports) and a new route returns one card's moments. Update its readers: ui/src/screens/Testing.tsx (useSpecs, line 46, and the SpecListing type), ui/scripts/moments.mjs (listing and chosen: fetch moments for the slugs asked for, all only when none is named), ui/scripts/specs.mjs, the mock in ui/scripts/interactions.mjs line 352, and tools/src/beryl_tools/specs.py warm_specs (line 253), which warms by generating everything: warm the cards asked for. serve.rs review (line 380) finds the next unreviewed spec by position in specs(): use the card list. A card whose generation leaves no moments is absent from today's listing; decide what its page says and note it.
  • Bound the tests that iterate every spec (moments_are_named_uniquely, first_example_offers_the_card_in_hand, every_prepared_example_reaches_its_interaction, and any other loop over specs()): one helper picks the cards, every card while there are at most 64 and otherwise a fixed 64 chosen by a stable hash of the name, so a failure reproduces; a failure message names the card. The full sweep must still run unattended somewhere: beryl_cli specs-check with no card is that sweep, and tools/src/beryl_tools/nightly.py is where nightly sweeps live.
  • Split mod.rs under 800 lines along its seams, moving code only: the text description (reach, trace, events_line, view_lines, describe: lines 442 to 735) and starting a moment (start, start_review, at_checkpoint, review_position: 240 to 395) are each a file. Name each file for what it holds; remove mod.rs from the allowlist.
  • by-w8gv.19.4 splits specs/auto.rs and specs/serve.rs (both stay on the allowlist until then: do not grow either; put new server code in a new file) and by-w8gv.21.25 adds a script dump to specs. Neither is a dependency: enact push rebases, and the later push fixes the conflict.
  • The spec index page (Testing.tsx) is a developer's screen, not the game: keep its look, changing only where its data comes from.
