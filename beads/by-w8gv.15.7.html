Description

Milestone 8 of Project 50k (run epic by-w8gv; plan docs/project-50k.md, "Authoring tools", decisions K13). Read the plan's sections named here and enact brief on this bead before starting. This milestone starts once M7b (by-w8gv.13) closes: read its beads' handoffs for the set crates, the generated registry and characteristics, and the card store as they landed.

M8 scope: the vocabulary's English templates also "give the UI rules text for abilities". Depends on the renderer bead (read its handoff: render_ability).

Today

The UI shows an object's printed rules text from the card store (ui/src/components/Card.tsx LitRules, via ui/src/cardRecords.ts) and lights the paragraph an option uses. The session finds that paragraph by counting abilities of the same kind before it (beryl_session/src/protocol/outcome.rs ability_ref → AbilityRef { kind, nth }, build.rs paragraphs_before; also decision.rs ~line 112 and view.rs ~line 285). That guess fails where the printed text has no paragraph for the ability: abilities granted by another object or by a continuous effect, emblems, a copy or token whose text differs, a keyword line holding several abilities, and any of the 50,000 cards whose paragraphs do not line up with its definition.

What to build

  1. The protocol carries, for each ability the UI can point at (stack objects, ability choosers, outcome culprits, granted abilities), its rendered text (render_ability), alongside the existing paragraph reference. Regenerate ui/src/generated/protocol.ts (its header says how).
  2. The UI uses the rendered text where no printed paragraph says the ability (the session knows when: a grant, an emblem, a token with no store text, or when the paragraph count runs past the printed paragraphs), and keeps lighting the printed paragraph where one exists. Arena's wording rules (AGENTS.md "UI") hold for labels; ability text is the card's text. Check docs/ui-conventions.md for a numbered exception before changing what Arena shows; if this adds a case Arena does not show, add it under "Not seen in Arena" in data/ui-conventions.json and run just conventions.
  3. Add a fixture or spec moment with a granted ability (or an emblem) on screen, so the generic UI checks cover it (AGENTS.md, Checks: "A UI bug fix adds the broken state as a fixture or spec moment").

Files

beryl_session/src/protocol/ (outcome.rs, build.rs, decision.rs, view.rs, candidates.rs), ui/src/generated/protocol.ts, ui/src/components/Card.tsx and the components that show a stack object's or chooser option's text, ui/src/ipc.ts fixture transport if fixtures change. Tests: cargo test -p beryl_session, cd ui && npm run typecheck && npm test, just ui-test and just specs <card> for the card with the grant (specs skill), beryl_cli script-check (the script lane) if the session's scripts change.

Decisions: (1) The session decides when to send text (new beryl_session/src/protocol/rules_text.rs, unprinted()): always for a granted ability (render_ability, bare context, since the grantor's face would give the wrong self-reference); for an own ability, when the card store has no printed text for the face (card or token/emblem record) or the ability's nth runs past the paragraphs of its kind, counted with a Rust copy of the UI's faces.ts rules. Delayed triggers (Mana Drain, Teferi's -3) keep the UI's existing printed-words fallback since their words are printed inside another paragraph. (2) Fields: StackItem::Ability.text, CandidateView.text (activate own/granted and trigger candidates), Culprit.text; all optional and skipped when None, so the save corpus and recorded views are unchanged where nothing is unprinted. (3) Way::Unusable (an unpayable loyalty ability on the chooser) carries no text: it is always an own printed planeswalker ability. (4) No new fixture: the existing spec moment swift-reconfiguration/crewing-the-vehicle-makes-it-a-creature-until-end-of-turn already puts the granted crew 5 on the stack and is covered by the generic checks; a session test (tests/ability_events.rs a_granted_ability_carries_its_rules_text) asserts its text is 'Crew 5'. (5) No UI-conventions change: Arena shows a granted ability's words on its stack item, and the look is the existing StackItem plate. Probe over all cards: only granted crew, Subtlety's evoke sacrifice trigger and Spara's Headquarters' cycling activation get text among candidates/stack items.
