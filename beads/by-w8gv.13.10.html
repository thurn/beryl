K16: Forge is a test oracle only. No card data, vocabulary or design comes from its scripts or code. This bead only changes how Beryl's scenarios are translated into Forge's test harness.

Part 1: the Forge exporter

tools/src/beryl_tools/forge.py (474 lines) holds 32 card names (data/card-names-allowlist.json) in two tables: COSTS (line 79: the casting option a scenario pays, as the text naming it in Forge: "Impending", "Overload", "Evoke", "Kicker", "Offspring") and ABILITIES (line 90: an ability by card, Own/Granted and index, as text that picks it out of Forge's description: "+1", "-3", "Draw a card", "Cycling", "Crew", "Destroy target land"). Replace both with rules over the dump's card description: a casting option by its keyword; a loyalty ability by its loyalty change; a keyword ability by its keyword; any other activated ability by a distinctive piece of its own Oracle text paragraph from the store (Forge's description of an ability is built from the card's text, so the paragraph's effect clause after the colon is the default). A scenario no rule can translate is reported unsupported through data/oracle-exporter-gaps.json, by mechanism. Count Forge passes before and after; list any scenario lost on the bead with its mechanism. Remove forge.py's count from the card-names allowlist.

Part 2: when the oracles run

Today slow CI's oracle lane plays every card scenario (checks.py:590, oracle_lane: by oracle), and the fast check plays the changed card files' (checks.py:601, card_oracle_lane, cards from changed_cards at :671 through card_names.cards_in). The full sweep took 400 to 600 seconds on Windows and grows with every card.

  • Slow CI's oracle lane plays the cards whose files changed since origin/master (what slow CI is testing), plus every card when a file the exporters or the oracle harness are built from changed (tools/src/beryl_tools/xmage*.py, forge.py, oracles.py, the Java harnesses, the oracle pins) and a fixed sample otherwise (a few cards chosen by a hash of the commit, so each run checks something and a failure is reproducible from the SHA). A rules change does not select every card: the nightly does that.
  • The nightly (tools/src/beryl_tools/nightly.py: steps such as coverage_step, fuzz_step, motion_step) gains an oracle_step running the full sweep on origin/staging, logged in the run log like the others. A failure there must reach someone: follow what the other nightly steps do on failure (read run_nightly and how K21's bisection files a Steward bead for a failure on staging), so a card broken by a rules change is bisected and filed the next morning rather than at push time. just oracle with no names stays the manual full sweep.
  • Update the Checks section of AGENTS.md and the justfile comment for ci in the same push, in a sentence each.
