Description

What is wrong today

What something listens to is Listens, a typed set over a u16 (beryl_kernel/src/event.rs). Nine of its bits are the events of EventKind and two are not events at all (Listens::RULE_CHANGE, Listens::DRAW_REPLACEMENT). The keystone cards need about twenty more trigger events and four kinds of replacement, so the mask runs out, and a replacement's gate shares an AND with triggers.

What to build

Plan: Designs 1, "Kinds". by-w8gv.16.6 has landed and made the kinds a typed set (EventKind, Listens); this bead widens it.

  • The set of trigger kinds is 64 bits (State::listening, GameTable::listens_any, Copiable::may_listen, GameTable::listeners).
  • Replacement kinds are a second typed set with the same three levels (the game's cards, the battlefield now, one card's face): GameTable::replaces_any, State::replacing, Copiable::may_replace. DRAW_REPLACEMENT moves there. RULE_CHANGE stays what it is, a fact the layers' pass folds, under a name that says so.
  • layers::listening folds both sets in its one pass over the battlefield and Rederive::finish stores both.
  • No new trigger event and no new replacement is added here: this is the room for them.

Files

beryl_kernel/src/{event.rs, listener.rs, table.rs, derive.rs, state.rs, query.rs}, beryl_rules/src/{trigger.rs, layers.rs, drawing.rs}. The reference recompute in beryl_rules/src/reference.rs checks the stored masks.

Need not read

ui/, beryl_session/, card files.

Bars (every bead of this epic)

  • The absent-cost gate holds with no bump (just count-gate; R2 in the plan). The count is exact, so report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust). A change to what the WU mirror's rollouts do is a bug in this epic.
  • Rules code cites the Comprehensive Rules with a quotation (root AGENTS.md); just citations.
  • A new card follows the card-writing skill: just card new, just card check <name> (Beryl, XMage and Forge), every instruction carried out by its own scenarios, and just specs <card> passing the generic UI checks from both seats. A disagreement with an oracle is settled by the rules and recorded in data/oracle-divergences.json.
  • Read the card's rulings before writing its scenarios (just card brief <name> prints Scryfall's). Each statement in a ruling that a scenario can show is a scenario of the card. Where one cannot be shown yet, the close reason names the ruling and why.
  • A rules bug found on the way gets its docs/bugs.md entry.
  • If the design in the plan is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.

Acceptance criteria

Both sets are typed and 64 bits wide; no caller passes a bare integer as a kind. The count gate holds with no bump (two words where there was one: report the count). State size reported.
