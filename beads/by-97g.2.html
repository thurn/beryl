Close reason

Landed 7cf03324: beryl_cli positions build/sample (just positions) and just ladder --positions DIR (4 pairs in 5 from a position, cycled; games name their position; positions copied to the match dir; anchor_replay::walk replays them; report gives pair-score spread positions v shuffle). A position is a turn-start Checkpoint (beryl_session::checkpoint) started via Checkpoint::arrange. Deviations: (1) cuts with known library cards are kept, since arrange keeps known cards at their depth and shuffles only unknown ones, and a London mulligan's bottom card stays known, so the stricter rule rejected ~all cuts; only lingering cuts are rejected, and a test checks known cards survive start. (2) The determinism test builds twice and compares hashes rather than pinning a literal hash, which every search change would break. Trial at 3M: 18 games -> 108 cuts, 103 clean, 14 kept (14%), 5.4 min under load; default --games is 250 for ~200 positions (~75 min). The real set has not been built yet.

Description

Part of the ladder epic (read it and docs/ai-strategy.md §4.1 first). Curated balanced start positions, so the openings' luck leaves the match's variance.

Where

  • rust/crates/beryl_session/src/save.rs, migrate.rs, corpus.rs: the save format and the migrations the frozen corpus already carries; a position is a save.
  • rust/crates/beryl_cli/src/game.rs: seeded games between named agents.
  • rust/crates/beryl_search/src/long.rs: LongSearch, Search::means, for the champion's estimate of a position.
  • rust/crates/beryl_engine: Observation, determinize, what each player knows of the libraries.
  • A new rust/crates/beryl_cli/src/positions.rs; main.rs; the justfile.

Build

beryl_cli positions build [--games N] [--seed N] [--work 3M] [--out DIR] and beryl_cli positions sample [--count N] DIR:

  • Play N seeded champion-against-champion games at the proxy budget. Cut each at the start of turns 3 to 8, before the draw, where neither player knows any card of either library (no scry or put-back pending), so a reshuffle of both libraries by the game's seed keeps every player's knowledge true.
  • Score each cut by the champion's own estimate from each seat: a search of the position at the proxy budget as each player. Keep it where both estimates lie within 0.45 to 0.55 for the seat to move.
  • Write each kept position as a save under --out, default $BERYL_CACHE/ladder/positions, with its source seed, turn and both estimates. A fixed seed rebuilds the same set; pin its hash in a test. Aim for about 200 positions.
  • sample prints N positions as transcripts (transcript.rs) for a human to read, as §4.1 asks, with their estimates.
  • The ladder runner (just ladder --positions DIR) starts a game from a position by loading the save and reshuffling the libraries with the game's seed.

Tests

A fixed seed rebuilds the same set (hash pinned). Each position loads and plays on. A cut with a known library card is rejected. just test-rust, clippy pedantic.

Measure

The first ladder match reports the spread of pair scores from positions against the shuffle (§9, first question). If positions buy nothing, this set is dropped and the runner's default becomes the shuffle; record that in the epic.
