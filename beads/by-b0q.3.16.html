Warden review of by-b0q.3.2 (XMage) and by-b0q.3.3 (Forge), delivered in f2d8473.

Verified: just oracle on staging 3d0f951: XMage 73 pass, 0 fail, 3 allowlisted, 2 unsupported; Forge 78 pass, 3 sim games finished. Both acceptance criteria hold.

Found and fixed:

  • The 3 XMage allowlist entries (Mana Tithe / No More Lies vs a controller who can't pay, Seachrome Coast's white mana) weren't XMage being wrong: CounterUnlessPaysEffect asks 'Pay {N}?' because XMage's ManaCost.canPay ignores available mana, and a yes then fails to pay with the same outcome. That is a question-surface difference, so the allowlist hid 3 scenarios from the oracle. xmage.py now has an UNLESS_PAYS table: when such a counterspell leaves the stack without Beryl asking its payer, the target spell's controller gets an optional 'No' (BerylScenarioTest wraps chooseUse in withOptional). Allowlist is empty; XMage now 76 pass, 0 fail, 0 allowlisted, 2 unsupported. New pytest covers both the unasked and asked cases.
  • just oracle ran only by hand ('nightly' in the architecture doc, but nothing scheduled it), so card changes could break oracle agreement unnoticed and the dump fixtures could drift from the real dump format. Added an 'oracle' lane to just ci: full slow CI 101 s with it (oracle 60 s under load), budget 300 s. It fails on a machine without just oracle-setup, which is loud by design. AGENTS.md, justfile and section 17.2 updated.
  • forge.export now reports a scenario Beryl itself fails as unsupported, as xmage.py does, instead of playing it.
  • docs/bugs.md entries for both.

Left alone: the string-matching exporter pytests (cheap, give fast-check feedback where the oracle lane doesn't run); Stops::Forced folding a forced-answer policy into the priority-stops enum (fine with one caller); pay() replaying taps only when they land in the position right after the cast (targeted spells fall back to XMage paying itself, which the oracle would surface if it mattered). The Forge harness passes only after every step plays, and its hang guard counts loop steps, not time.
