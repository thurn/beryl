Description

Read first: .claude/skills/bugfix/SKILL.md ('Worker: fixing one report', how a report is reproduced from its replay); docs/beryl-3d.md 'Bug reports'; rust/beryl3d/crates/beryl_3d src/bugs.rs (save, write: tree.txt, frames.jsonl, ui.json naming Beryl 3D) and src/options.rs (the tool options, --fixture, --pause-at); tools/src/beryl_tools/bugs.py (bugs_dir, find, load, parse).

A Beryl 3D bug report holds the picture, the element tree, the frame log and, from a live game, the session's replay. A worker fixing a report needs to see it and bring the app back to the same state.

Rust, beryl_3d:

  • bugs.rs: when the app is replaying a recording, ui.json also records recording and at (the table's clock at the freeze, in ms), so the report can be reopened offline.
  • options.rs and the session start: a tool option --replay <path> that starts the app on the game in that replay file, positioned at its latest decision, as resuming the newest game does (beryl_shell::resume_latest, which calls Sessions::resume_latest in rust/crates/beryl_session/src/sessions.rs). If Sessions cannot resume a given replay file, add a function beside resume_latest that shares its code (not a protocol change); do not write a second loader.

Python, new module tools/src/beryl_tools/beryl3d/bug.py with just b3d bug <report> (a folder, or a key bugs.py's find accepts): prints the description, the client and commit from ui.json, tree.txt cut to 60 lines, the frame log's summary (reuse just b3d frames <path>), and the commands that reproduce it: just b3d tree <recording> --at <at>ms and png for a replayed recording, or just b3d app --replay <folder>/replay.json --window none --for 120s followed by just b3d live tree for a live game. A web report (ui.json not naming Beryl 3D) says so and points at the bugfix skill's web steps.

Skill: a "Beryl 3D reports" part of 'Worker: fixing one report' in .claude/skills/bugfix/SKILL.md: just b3d bug <report> first, then the printed commands.

Tests: in beryl_3d, a unit test that ui.json of a report saved while replaying holds recording and at; that --replay with a missing file is a usage error. In tools/tests/test_beryl3d_bug.py, on a report folder built by hand: the printed commands for a replayed and a live report, and the web-report notice. Run: just b3d cargo-test -p beryl_3d, just test-py tests/test_beryl3d_bug.py.

Each skill keeps working for the web interface until the switch: add a Beryl 3D section, never replace the web instructions. Register any new command through MODULES in tools/src/beryl_tools/beryl3d/cli.py with a COMMANDS tuple in your own module, --help and two examples (rule 19). When the job works, set this job's b3d in data/beryl3d/parity.json's tools to the command or skill section that does it. Rule 17: no new recipe in the justfile and no change to tools outside tools/src/beryl_tools/beryl3d except the skill's own files.

Before enact push: run just b3d cargo-test and just b3d test yourself, because the fast check can cut them at its time limit. Tests in beryl_inspect locate elements by role and name, never by numeric id. Do not re-pin limits in data/beryl3d/gates.json by hand.

Handoff: just b3d bug <report> and beryl3d --replay <file> landed in staging at ec7bda7c (commits 0b104ac3, 9109c5da, ec7bda7c).

What changed:

  • rust/beryl3d/crates/beryl_3d/src/fixture.rs: Fixture now remembers the recording's name, its seat, the host clock when its first views were given (started) and the clock when its last script ended (ended_at, set by finished_at). replayed_at(clock) returns a Replayed { recording, seat, at_ms, ended }.
  • src/app.rs: AppFeed keeps the clock of the latest frame. On Request::FreezeFrame it hands fixture.replayed_at(clock) to Bugs::freeze. Source::Fixture is now boxed, because clippy's large_enum_variant lint fired after Fixture grew.
  • src/bugs.rs: a report's ui.json log holds recording, seat, at (ms) and ended when a recording was replaying.
  • src/options.rs: the new tools-only option --replay <path>. A missing file is a usage error, and combining it with --fixture or --agent is an error. The --drive script loader moved here from app.rs as drive_script, to keep app.rs under 800 lines.
  • src/session.rs: Live::resuming(path). begin calls Sessions::resume_replay instead of resume_latest when a path is set. A --replay run uses no data dirs and no settings saver, so the run saves nothing.
  • rust/crates/beryl_session/src/sessions.rs: the new pub fn resume_replay(path), which shares resume_file (now taking save: Option<&Path>) with resume_latest. It saves nothing, so a report's replay.json is never rewritten and the resumed game never becomes the newest game a later launch resumes. Unlike resume_latest, it resumes a game that has already ended.
  • tools/src/beryl_tools/beryl3d/bug.py: just b3d bug, registered in MODULES. tools/tests/test_beryl3d_bug.py tests it. just b3d app passes --replay through (app.py).
  • Docs: the "Beryl 3D reports" part of the bugfix skill's 'Worker: fixing one report', a bug entry in the b3d skill, docs/beryl-3d.md 'Bug reports', and rust/beryl3d/AGENTS.md. parity.json's bugfix job now names the command.

Deviation from the bead: at alone did not reproduce the frame. The app replays the recording live, so by the time someone presses Cmd+B the recording has usually ended (pay-default ends at 1783 ms on the driver clock, but the freeze came 19.7 s into the run), and --at 19689ms is rejected as past the end. The report therefore also records ended, and just b3d bug prints --at end for such a report.

Verification:

  • Saved a report from just b3d app --fixture pay-default --window none with live do 'key Cmd+B', key space, type field "description", press button "Submit". just b3d bug <folder> printed it, and its command just b3d tree pay-default --seat you --at end printed exactly the tree in tree.txt (same "Resolve" / "To Main 2" prompt).
  • just b3d app --replay <web report>/replay.json --window none --for 60s resumed that game at its declare-attackers prompt ("All Attack" / "No Attacks"), matching the report's step: declareAttackers. The file was byte-for-byte unchanged afterwards.
  • just b3d clippy, just b3d cargo-test (740 passed), just b3d test (8264 tests, 0 failed), just test-py tests/test_beryl3d_bug.py and cargo clippy -p beryl_session all pass. The integration test in tests/all/bugs.rs now checks that ui.json holds recording, seat, at between 1000 and 1100 ms and ended: false.

For a reviewer: Beryl 3D reports carry commit: unknown, because the beryl3d binary never calls beryl_session::bugs::set_build_commit, so just b3d bug prints "built from unknown". This is outside this bead and I filed nothing for it.
