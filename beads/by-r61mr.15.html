Description

Read the epic by-r61mr first: it holds the decisions, the code map and the directory layout this bead assumes. The work is in the Enact repository (~/enact) unless this bead says otherwise, delivered with that repository's own enact worktree create and enact push.

Port the pages of Beryl's status site (status/src/beryl_status/render.py, 608 lines, and site.py) to the Worker under server/src/dashboard/, reading the ticket store directly: the home page with its Active and All parts, the five sections of All and the contents rail, and a page per ticket at <project>/tickets/<id> with status, priority, assignee, epic, labels, description, blockers, the tickets it blocks, subtasks, comments and changelog. The changelog is now in the store, so it no longer loads late behind a skeleton.

Keep the site's performance design from Beryl's status/AGENTS.md: rendered HTML cached by a fingerprint of everything the page shows, ETags and 304s, the service worker answering from its cache and revalidating, and prefetch on hover. A page render must fit in 10 ms of CPU; the home page lists about 200 open tickets, so cache its sections separately if needed. Prefixed IDs and the old beads/<id> paths redirect to the ticket's page.

Performance and browser check: used the same 5,000-ticket fixture for Python and the Wrangler simulator. Python's full rebuild used 4.75 s of CPU cold and 37 ms warm. Python page renders measured 4.46 ms for home with the index built in the measurement and 0.10 ms for the detail page using the retained index. The Worker renders on request. Simulator median elapsed time was 7 ms for a cold home, 7 ms for a cold ticket, 1 ms for a ticket after home, and below the 1 ms timer resolution for a warm 304. Chrome at 1280/375 px, light/dark, gave prefetched click-to-DOM-swap medians of 1.7–1.8 ms for Python and 1.7–1.9 ms for the Worker. Both layouts match apart from the requested Tickets wording and canonical ID display. Chrome also checked hovercards, comments, history and no horizontal page overflow. The simulator budget check is opt-in with VITE_DASHBOARD_BUDGET_CHECK=1 to keep host scheduling out of CI.
