Close reason

Exhaustive search from scenario ends in the fast check; just exhaust goes deeper (78ea3ec0)

Description

The plan's Verification section: play every decision sequence from scenario positions to a fixed depth, checking invariants at each state. Fuzzing samples games; this enumerates them near positions known to matter.

  • For each card scenario's end position (beryl_scenario/src/run.rs builds it), enumerate every legal decision sequence to depth D. State is Copy: copy per branch, no undo. At each state run State::check_invariants and check_references (beryl_engine/src/invariants.rs, reference.rs) and require that apply never panics. Once by-w8gv.1.4 lands, debug builds check inside apply and this only has to walk.
  • Chance: fix the seed per branch; do not enumerate shuffles.
  • Skip states already seen (state hash). Cap nodes per position so one wide position cannot eat the budget, and print which positions hit the cap.
  • Budget: the default depth runs over the whole scenario corpus inside the fast check's rust lane, in a few seconds. A command beside just fuzz (just exhaust [card] --depth N) runs deeper.
  • A failure prints its decision sequence as a scenario-shaped transcript (beryl_cli/src/transcript.rs), with the same printer as by-w8gv.1.5 if that has landed.
  • A real violation found is a rules bug: fix it and add its docs/bugs.md entry, or, if the fix is large, file it as a child of this milestone and list the position in a skip list the test prints.

Acceptance criteria

A deliberately broken invariant behind a test-only hook is found from a scenario position and printed as a transcript; the default run passes in just check within budget; just count-gate reports no change.

Handoff: beryl_scenario/src/exhaust.rs adds exhaust(cards, scenario, Bounds{depth,nodes}, Check) -> Result<Searched, Box<Found>> and the default check invariants (check_invariants + check_references). It plays the scenario's non-assert actions through Live, takes the runner's own root decision (so a breakpoint stop after a trailing Resolve/AdvanceTo is kept), then DFS-branches on copies of State under the runner's TRACED profile, answering one-answer questions as the runner does; panics are caught; positions are skipped by DefaultHasher state hash when already seen with >= depth left; Bounds::nodes caps decisions per scenario and Searched::capped flags it. Found carries why, the replayable Scenario (own actions + sequence; None if a choice has no scenario action) and the source text. New beryl_scenario::setup_source prints any Setup (battlefield permanents included); shrink.rs now uses it (same printer), and source() spells AdvanceTo. Test beryl_cards/tests/exhaust.rs: every_scenario_keeps_the_invariants_to_a_depth (depth 3, cap 400: 160 scenarios, ~1.7k decisions, ~3 s debug; prints capped scenarios; SKIPPED list empty, fails when a skipped one passes) and a_broken_invariant_is_found_and_replays (a panicking 'stack stays empty' check is found from Mana Tithe's scenario and the transcript replays through Live to the failure). just exhaust [card] --depth N --nodes N runs release+debug-assertions like just fuzz. No real violation found even at depth 30 (257k decisions, 6 s release): scenario libraries are tiny, so most branches end at the next draw. Count gate: 407,771,404 both on this commit and its base (+0.62% vs bar, pre-existing). Fast check passed but reported 93 s adjusted vs its 60 s budget at load 24 on 18 cores (tests 69 s, clippy 23 s); the new test is ~3 s of that in parallel.
