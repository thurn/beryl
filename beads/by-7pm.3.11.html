Description

Two ways for a bug report to leave a phone (epic, D1): a Share button's native half, which zips a saved report and opens the system share sheet, and just mobile-bugs, which copies reports from the iOS Simulator, the Android emulator and a paired iPhone into the Mac's bugs folder.

Where the code is

  • rust/crates/beryl_mobile: the plugin by-7pm.3.5 made (snapshot, device). Read that bead's close reason and comments first.
  • rust/crates/beryl_session/src/bugs/archive.rs: save(folders, destination) writes report folders as a zip; active(root) lists them. bugs.rs: BugSaved { id, … }, the folder of a report is dir/<id>.
  • rust/crates/beryl_app/src/bug_reports.rs: export_bugs, a command with a desktop body and a mobile body that answers an error. lib.rs: the handlers! list, which requires each command's function to be named as its constant in beryl_session::ipc.
  • rust/crates/beryl_session/src/ipc.rs: the command names and the table of commands with their request and reply types (search for EXPORT_BUGS), from which ui/src/generated/protocol.ts is generated.
  • ui/src/ipc.ts: exportBugs, canExportBugs.
  • tools/src/beryl_tools/bugs.py: bugs_dir(), import_cmd (unpacks a zip of reports into the bugs folder: by bugs import <zip>), stage_bundle, load, update, DONE. mobile.py: simulator(), BUNDLE_ID, run, paired_device(). android.py: adb, PACKAGE, SERIAL, running(). cli.py registers each module's commands. justfile: the mobile-setup, ios and android recipes show the form.
  • .agents/skills/bugfix/SKILL.md (or .claude/skills/bugfix/SKILL.md): where /bugfix is told reports are.

What to build

  1. Command share_bug. Add SHARE_BUG: &str = "share_bug" to beryl_session::ipc with a request ShareBugRequest { id: String } and reply (), in the command table beside EXPORT_BUGS; regenerate protocol.ts. In beryl_app/src/bug_reports.rs: on mobile, check id is a report folder's name directly under the bugs folder (reject anything with a path separator or ..), zip that one folder with bugs::archive::save to <app cache dir>/share/<id>.zip (create the folder; delete older zips in it first), and ask the plugin to share that path; on desktop, answer SessionError::Io { reason: "Share is available on a phone." }, as export_bugs does the other way round. Add it to handlers!.
  2. Plugin command share, taking the file's path. iOS: present a UIActivityViewController with the file's URL from the root view controller (on an iPad it needs a popoverPresentationController.sourceView; set it to the root view). Android: Intent.ACTION_SEND with type application/zip, the file's FileProvider URI as EXTRA_STREAM and FLAG_GRANT_READ_URI_PERMISSION, through Intent.createChooser. The provider is declared in the plugin's own AndroidManifest.xml (authority ${applicationId}.fileprovider, androidx.core.content.FileProvider, exported="false", grantUriPermissions="true") with a res/xml paths file exposing only <cache-path name="share" path="share/"/>.
  3. ui/src/ipc.ts: shareBug(id) and canShareBugs() (true on ios and android, from the platform value by-7pm.3.5 added). No UI yet: by-7pm.3.6 adds the button.
  4. just mobile-bugs: a new module tools/src/beryl_tools/mobile_bugs.py, registered in cli.py as mobile-bugs, with a justfile recipe in the group the other mobile recipes are in.
    • No argument: pull from every source that is there, and say for each how many reports it brought and how many it already had. A source that is not there (no booted simulator, no running emulator) is reported in one line and is not an error.
    • iOS Simulator: xcrun simctl get_app_container <udid> ca.thurn.beryl data, then the folder Library/Application Support/ca.thurn.beryl/bugs under it (the journal's path in mobile.py's journal shows the layout). Only if the simulator is booted.
    • Android emulator: find the folder with adb shell run-as ca.thurn.beryl find . -type d -name bugs (as android.py's journal finds the journal), then adb exec-out run-as ca.thurn.beryl tar c -C <folder> . piped into Python's tarfile. Only if the emulator is running.
    • --device: a paired iPhone, with xcrun devicectl device copy from --device <id> --domain-type appDataContainer --domain-identifier ca.thurn.beryl --source "Library/Application Support/ca.thurn.beryl/bugs" --destination <temporary folder>. Agents never touch the user's phone (D2): write this path, cover its command line with a unit test that fakes subprocess, and do not run it. Without --device the phone is never contacted.
    • A path argument ending .zip: the same as by bugs import <zip> (call bugs.import_cmd's logic; do not copy it).
    • Each pulled report folder is adopted the way import_cmd adopts one: staged in a temporary folder inside the bugs folder, checked to be a report (load), skipped if <root>/<id> or <root>/done/<id> exists, else renamed into place under the .triage.lock. Factor that out of import_cmd into one function both use. Only folders whose names match REPORT_ID are taken, and nothing is ever deleted from the device.
  5. Tests in tools/tests beside the other tools tests: adopting a folder, skipping one already there or done, the tar path, the devicectl command line.
  6. In the bugfix skill's "Where reports are", two sentences: phone reports stay on the phone until just mobile-bugs pulls them, and a shared zip is taken with just mobile-bugs <zip>.
