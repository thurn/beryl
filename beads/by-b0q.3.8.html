Implementation notes (executor 6424752a):

  • Protocol: DecisionView gains 'resolving' (StackItem | null): the spell/ability whose paused resolution asks the decision. The engine pops the stack entry before running the body and the view replays the body, so the view's stack never showed what was resolving; the session now reads it from the committed state's stack top (beryl_session game.rs draw) and keeps a resolving spell's card among the objects. sessions.rs asserts every paused resolution names its entry.
  • Fixtures: new 'resolving <card>' condition in beryl_cli fixture.rs; fixtures choice-scry (random seed 3), choice-jace (random 3), choice-look (greedy 1), choice-pay (greedy 1). Greedy never scries or uses Jace's 0 in 800 seeds, hence random agents for those two.
  • UI: game/choices.ts turns a decision into an overlay model (arrange / pick / ask) and a plan of Intents (one per engine decision: e.g. a scry is bottom picks, done, then top order). Game.tsx now owns the plan queue (Board's drag follow-ups use it too) and holds the overlay until the plan is sent. game/ChoiceOverlay.tsx draws them in the existing Overlay shell (which gains 'actions'); click fallback for every drag (a click moves a card to the far end of the other pile).
  • Covered: scry (Aang's Iceberg), Jace TMS 0 and +2, Thundertrap Trainer, Elite Spellbinder, Time Spiral lands, discard (cleanup down to 7), legend rule, Soporific Springs pay life, Mana Tithe/No More Lies pay-or-counter, Malcolm cast offer, X (Skydiver kicker), coin-flip result banner, View Battlefield peek. Mulligan bottom stays on the opening screen (the battlefield bead did it, one click per card).
  • ui-test: 4 new checks (scry click-to-bottom then Done, Jace drag put-back order, pay prompt answer, View Battlefield peek). Spellbinder/Time Spiral/Jace +2/discard/X/pay life/legend rule overlays were captured from temporary fixtures and looked at, not committed.
