Description

What to do

Both oracle exporters refuse to cast any face but the front: tools/src/beryl_tools/xmage.py raises Unsupported("casting {card}'s back face") (lines 377-378) and forge.py raises Unsupported for a nonzero cast face (line 260). card_facts.py reads casting options from the front face only (line 358). So no scenario that casts a split half, an Adventure, a modal back face or a prototype can be checked against XMage or Forge.

  • XMage (xmage.py, xmage_java.py, the BerylScenarioTest helpers): cast a split half, a fused split card, an adventure's Adventure, a modal double-faced card's back face and a prototyped spell by the names and options XMage's test framework takes (castSpell with the half's or face's name; fuse is "fused <Left // Right>"). Read the XMage test classes for one card of each kind in the checkout under $BERYL_CACHE/oracles for the exact strings.
  • Forge (forge.py, tools/oracles/BerylForgeHarness.java): the same, through the harness's choice of a spell ability by its description.
  • card_facts.py: describe every face's casting options, and a card's shape, to the exporters (the dump's description of a card comes from rust/crates/beryl_scenario/src/facts.rs).
  • Morph and turning face up are partly there (TurnFaceUp, assertFaceDownControlled): add casting a card face down.
  • tools/tests/ for each, with the generated Java or Forge text for a small scenario.

The Rust side that scripts a face (the scenario builder's cast of a named face) is built by the bead that adds a shape to card definitions, a dependency of this one. Until a real card of each kind exists, test with the test card paths the dump already has, and say in the close reason which kinds you could only test on generated text.

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.

Acceptance criteria

A scenario that casts a split half, a fused card, an Adventure, a modal back face, a prototyped spell or a face-down card exports to XMage and to Forge, or is reported unsupported with a reason that is the oracle's own limit.
