Close reason

board-door and citations steps hold the names lane in both checks; forget_derived moved to State

Description

From the M3 Mason audit (by-w8gv.6.1). Two rules the kernel's contract and AGENTS.md state are held by nobody: a search a reviewer must remember to run, and a command an author must remember to run. Plan K6's reason is that ten of 17 logged bugs needed a chokepoint nothing enforced, so each becomes a check, like two-player (K7) already is.

1. The board door stays shut in rules code

Current design. State::board() (rust/crates/beryl_kernel/src/board.rs) lends Board, which writes any field raw with no event: set_life, set_counters, place, set_tapped and so on. It is pub because scenarios, checkpoints, tools and tests need it. The contract (beryl_kernel/src/lib.rs, "The board door") says "rules code never names it, and a search for .board() finds whoever does". Nothing runs that search. beryl_engine holds &mut State in every rules module, so s.board().set_counters(..) compiles there: the crate boundary of K6 has one unlocked door, and milestones 4 and 5 rewrite exactly the code (effect.rs, event.rs, cast.rs) that will meet a missing mutator.

Today's only use in rules code is rust/crates/beryl_engine/src/reference.rs:72, fresh.board().forget_derived(), which marks a clone's layer results stale so the reference check can recompute them.

Proposed design.

  • Give that one caller a kernel method that is not the door: State::forget_derived(&mut self) in beryl_kernel/src/derive.rs (it only sets flags.derived_dirty, which can cause a recompute and nothing else, so it is safe as a public mutator; cite nothing new, move Board::forget_derived's rustdoc). Board::forget_derived stays for tests or calls it. reference.rs calls the State method. Update the contract paragraph in lib.rs: rules code has no use of the door, and the names lane holds it.
  • A check board-door beside two-player: copy tools/src/beryl_tools/two_player.py (same RULES roots rust/crates/beryl_engine/src and rust/crates/beryl_cards/src, same skipping of tests directories and tests.rs, but no exemption for lib.rs). It fails each line matching \.board\(\) or \bboard::Board\b, with advice: "rules code changes the state through a mutator (beryl_kernel's contract, 'Mutators'); add the mutator the rule needs". Register it in tools/src/beryl_tools/checks.py: the dispatch table beside "two-player": two_player.step (near line 743) and names_lane() (near line 550). Test it like tools/tests/test_two_player.py. Add it to AGENTS.md's Checks paragraph where two-player is described, and to "Code structure" in one line.

Eliminates: the one way rules code can write state with no mutator, no event and no invariant kept, without a reviewer's grep.

2. just citations runs without being asked

Current design. tools/src/beryl_tools/citations.py (by-w8gv.5.18) holds every Comprehensive Rules link and quotation in the tree to the rules page: 3,340 rules, about 5 s with the page cached (1.3 s of CPU). It fetches https://yawgatog.com/resources/magic-rules/ into $BERYL_CACHE/rules/magic-rules.html and reuses it for a day (rules_page, MAX_AGE_SECONDS). Because it needs the network it is in no check: AGENTS.md says to run it "after a rules release and after writing a citation". The 2026-11-06 release left 11 dead citations in the kernel and about 85 elsewhere, found only because the M3 Warden thought to check. Milestones 4 and 5 write the stores and the whole rules library, each function with a citation and a quotation.

Proposed design. The check never fails for want of a network, so it can be a lane step:

  • rules_page gains a mode that never fails on the fetch: use the cached page if it is under a day old; otherwise try to fetch (short timeout, 10 s) and on any error fall back to the cached page however old; with no cached page and no network, return nothing and the step logs a skip (see how the oracle lane logs a skip when the oracles are held) and passes.
  • Slow CI (just ci): a step citations over the whole tree, in the names lane. A release that renumbers a rule then fails slow CI once and files one Steward bead, which is the fix's owner.
  • Fast check (just check): the same step in the names lane, restricted to the files changed since the branch left origin/staging (the lanes already get that list: fast_lanes(changed)), and never fetching: cached page or skip. An author's wrong quotation is refused at the push, and a release cannot fail someone's unrelated push because only their changed files are read.
  • AGENTS.md: replace "(it needs the network, so no check runs it: run it after a rules release and after writing a citation)" with what now runs it; update the Checks paragraph's lane lists and citations.py's module docstring.

Eliminates: the only correctness check in the tree that runs when someone remembers to.

Must not change

No engine behavior: parity (plan K11) holds trivially, and the count gate is untouched because forget_derived is called only by the reference check. The fast check's budget (60 s): the two steps add about 1 s of CPU; measure the names lane before and after from the run log and say so on the bead. just citations and --refresh keep working as they do.

Files

rust/crates/beryl_kernel/src/derive.rs, board.rs, lib.rs (contract text); rust/crates/beryl_engine/src/reference.rs; tools/src/beryl_tools/two_player.py (the model), checks.py, citations.py; tools/tests/test_two_player.py and test_citations.py (the models); AGENTS.md. Do not read the rest of the kernel.

Acceptance criteria

  • A scratch line s.board().set_life(Seat::P0, 1); added to rust/crates/beryl_engine/src/turn.rs makes just check fail in the names lane with a board-door: line naming the file and line; removed, it passes. grep -rn '\.board()' rust/crates/beryl_engine/src rust/crates/beryl_cards/src finds only tests.
  • A scratch comment citing [CR 100.1](https://yawgatog.com/resources/magic-rules/#R1001): "not the rule's text" in a changed Rust file makes just check fail with a citations: line; removed, it passes. With $BERYL_CACHE/rules moved aside and the network unreachable (point RULES_URL at an unroutable address in a test), the step logs a skip and passes; with a stale cached page and no network it checks against the stale page.
  • pytest covers the board-door check (a rules file refused, a tests directory skipped) and the three page cases (fresh cache, stale cache with a failed fetch, no page).
  • just check and slow CI pass; AGENTS.md says which checks run both.
