Close reason

Cause: cargo's records of files outside each crate's folder (rust/Cargo.toml read by clippy for every crate; data/card-store.tsv embedded by beryl_card_store, beneath every rules and card crate) are absolute paths naming the worktree that last saved the shared rust/target, so every new worktree rebuilt the whole workspace. 5746c686 makes warm.ensure rewrite those paths to the new checkout (tools/src/beryl_tools/rehome.py). Same beryl_session change in a fresh worktree on JARVIS: fast check 140 s -> 72 s adjusted (65 s on the clock, load 8 on 18 cores), clippy 54 -> 23 s, tests 59 -> 33 s; a no-change clippy in a fresh clone 54 -> 6 s. What remains is recompiling beryl_session's dependents; budget.py refiles if a run still overruns.
