Description

Read the epic by-r61mr first: its description holds the decisions and the code map, and its design field holds the contract this bead builds against. The work is in the Enact repository (~/enact) unless this bead says otherwise, delivered with that repository's own enact worktree create and enact push.

Implement the rest of the contract's server state in server/src/:

  • Leases (section 5): acquire, renew and release, the waiters' queue in arrival order, expiry, and dropping a waiter that has not asked for 60 seconds.
  • Events: POST /events and GET /events, and the daily alarm that deletes events older than 30 days.
  • GET /state and POST /state with the cutover state's allowed moves (section 7).
  • The per-day counters of requests and rows written, reset at 00:00 UTC, and the 429 answer at 90 percent of a limit.
  • POST /import and GET /export (section 3).

Acceptance criteria

Simulator tests show: of many concurrent acquires of one lease exactly one succeeds and the rest are queued in order; a non-holder cannot renew or release; an expired lease goes to the first waiter; the cutover state refuses to move backwards except from paused to before; the counters match the operations a test performs and a write past 90 percent returns 429; and an import sent twice writes rows once.
