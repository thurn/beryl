Warden review of by-b0q.3.4 (260a64a). Fixed in b1974fb:

  • Bug: dragging a hovered (raised) hand card. Un-hovering it at drag start changed its placement, which started a spring on x/y while pointer moves set them; for ~0.5 s the card sank back to the fan, up to ~430 px from the pointer (measured in WebKit). CardLayer now holds x/y while the pointer has the card (dragging, or dropped to be played until the next view); this replaces the 'returns' counter.
  • Bug: cards jumped in size when their look changed widths (back 105 / full 182 / field 232 / land 190). An opponent's card leaving their hand ballooned to 233 px wide on the first frame, then shrank to 99. The scale now absorbs the width change in a layout effect before painting, then glides.
  • ui-test: the drag check now asserts the card follows the pointer (clock paused before pickup, so deterministic), and a new check asserts an opponent's card grows out of its back. Both fail on the original code and pass with the fix; ui-test passed 3/3 with all cores saturated (~3.5 s per run). Verified: just ui-shots (all shots, no page errors; game-main/castable/cast-menu/target/mulligan compared with battlefield.png myself: no major discrepancy beyond the minor layout notes already on by-b0q.3.17), ui-test, typecheck, prettier, just smoke. Every drag has a click fallback (click lists every candidate; the prompt panel lists every pick). Rust candidate labels and the 'from turn' fixture qualifier reviewed, fine as is. Left alone: running several ui-test/ui-shots at once in ONE checkout races on ui/public/fixtures (each run deletes and re-records it); CI never does this. A drop whose choose call fails leaves the card at the drop point until the next view (rare; the error toast shows).
