Close reason

Target clone 5.3 s -> 2.0 s: tauri cloned on demand, stale objects and sessions pruned on save (dab5614)

Description

Part of Milestone 1 (epic by-b0q). Filed by the M1a Sage audit (by-b0q.2.2).

Measured problem

Every worktree that touches rust/ or ui/, and every slow-CI run, starts by APFS-cloning ~/Library/Caches/beryl/target (tools/src/beryl_tools/warm.py). Over M1a's 55 slow-CI runs that clone grew from 2.1 s to 11.8 s (.git/enact/ci.log, warm: cloned .../target in N s). A fresh worktree's fast check with an engine change took 29 s, of which 6.6 s was the clone.

The cache is now 6.1 GB and about 28,000 files:

  • debug/deps: 2.7 GB, 13,141 files. About 1,780 of them per beryl crate, nearly all *.rcgu.o objects that macOS's unpacked debug info keeps.
  • debug/incremental: 853 MB, 58 session dirs.
  • tauri/: 2.4 GB, 9,325 files. This is the Tauri CLI's separate target dir. Only smoke, ui-shots and dev use it; the rust lane never does.

save renames each worktree's target back as the new cache, so the cache only grows. The clone counts against the 60 s fast-check budget, and M1b adds agent, search and bench crates.

Proposed change (pick what measures best)

  • Clone target/tauri only for lanes and commands that run the Tauri CLI (app.py), not for the rust lane.
  • Shrink debug artifacts, for example [profile.dev.package."*"] debug = false or line-tables-only for dependencies in rust/Cargo.toml. Keep full debug info for the workspace crates only if it is needed.
  • On warm.py save, prune stale artifacts: incremental session dirs other than the newest per crate, and objects older than that crate's newest build.

Expected gain

A target clone back to a few seconds, which keeps the fast check well under budget through M1b and saves about 5-10 s on every bead worktree and every slow-CI run.

Acceptance criteria

  • A fresh worktree's first rust check clones the target cache in 4 s or less on this machine, measured and recorded on the bead with the before/after cache size and file count.
  • The cache no longer grows without bound across save cycles (pruning or smaller artifacts), covered by a pytest for any new warm.py logic.
  • just smoke and just ui-shots still work from a fresh worktree; just check and just ci pass.

Delivered in dab5614 (staging). Measured on jarvis, Nov 5.

Cause of growth: on macOS a debug build keeps each incremental unit's codegen-unit objects in deps/ (unpacked debug info), named <unit>.<cgu>.<build>.rcgu.o, and every rebuild writes a full new set under a new <build> token without deleting the old one. Only 2,807 of the cache's 12,921 deps objects belonged to each unit's newest build. Every incremental crate dir also kept 2 finished sessions.

Change (tools/src/beryl_tools/warm.py):

  • ensure() clones rust/target without target/tauri; app.py (smoke, dev, bundle) passes tauri=True and gets target/tauri cloned on demand. save() carries the cache's tauri over when a worktree never built it.
  • save() prunes each unit's older object sets (by build token, newest by mtime) and all but the newest finished incremental session per crate, in every profile and under tauri/. Best effort, so the remove hook never fails on it.
  • New pytests cover the on-demand tauri clone, the tauri carry-over on save and the pruning.

Rejected: split-debuginfo=off / debug=false in rust/Cargo.toml. It would remove the deps objects, but backtraces lose file:line (checked on a toy crate), and pruning alone meets the target.

Measurements (same load, about 30-40 load average):

  • Before: cache 6.5 GB, 32,172 files; full clone 5.3 s (3.9 s idle earlier: debug 3.9 s + tauri 1.3 s).
  • After pruning: 4.3 GB, 15,614 files; the non-tauri clone is 10,953 files, 2.7 GB: 1.8-2.0 s (fresh worktree: 'warm: cloned ... target in 2.0 s').
  • Per save, the hook pruned 2,533 objects from one worktree's rebuild: the growth it now stops.

Verified from a fresh worktree: cargo test --workspace passes (only workspace crates recompiled, as always for a fresh checkout), just smoke passes (clones tauri on demand, incremental Tauri build 9 s), just ui-shots passes, fast check passes. Slow CI (just ci) runs on dab5614.
