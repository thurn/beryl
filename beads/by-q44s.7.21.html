Description

Read docs/beryl-3d.md “The flat layer” and “Sizes”. In beryl_scene src/screens keep the existing screen/widget/state APIs. Add portrait functions in start.rs (start_phone), opening.rs (opening_phone), game_over.rs (game_over_phone and its action dock), settings.rs, bug_report.rs, gallery.rs, testing.rs and table.rs for the entries these use. Select each alternate through the shared Layout::for_size selector in its existing public function so the game-furniture bead can edit game.rs and client routing independently. Reuse Element, Press, FieldState, the native client field requests and the desktop screen functions' form/action builders. Give long content a bounded scroll area, keep primary actions inside the usable bottom edge, and ensure every exposed action remains reachable when a field is in focus. Reflow current desktop gallery, testing and table entry widgets as a single safe-area column. On start, preserve agent selection, seed, fair setting and pending/error states; use a one-column agent list with scroll when needed. On opening keep and mulligan, keep the card selection above the dock; present the game's result and buttons in portrait. The bug report uses the existing desktop draft and submit actions in a bottom sheet over the frozen view. No host or keyboard implementation is in this bead.

Web references: ui/src/screens/StartScreen.tsx StartScreen and mobile/phone-start.css .phone-start-agent-list, .start-seed and .start-buttons; ui/src/screens/Opening.tsx OpeningPresentation and ui/src/screens/GameOver.tsx GameOver with mobile/phone.css .phone-opening and .phone-game-over; ui/src/components/BugReport.tsx BugReporter and mobile/bug-report.css .bug-panel, .bug-text and .bug-tools. Use the completed milestone 3 screens, widgets and report flow as the behavior reference for native-only actions.

Tests in beryl_scene tests/all/screens_phone.rs assert the seed step, agent selection, opening confirmation, result return, bug draft preservation and send/cancel presses, with a shorter effective viewport modelling the keyboard and nonzero safe-area insets. Run: just b3d cargo-test -p beryl_scene --test all screens_phone; just b3d test b3d:screen/ --phone-only; just b3d test b3d:opening-keep --phone-only; just b3d test b3d:game-over --phone-only. Existing screen recordings are registered via beryl_inspect src/screens.rs and data/beryl3d/screens.json.

Acceptance criteria

Portrait start, opening, game-over, settings, bug report, gallery, testing and table entry controls pass their replay checks at all three phone sizes. Start and report fields remain reachable with reduced viewport height, and their desktop tests still pass.
