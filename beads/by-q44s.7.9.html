Close reason

Android suspend, surface recovery, low memory and platform requests verified on Vulkan and OpenGL ES. Staging 0636dc06.

Description

Read first: docs/beryl-3d.md 'Hosts' ('Losing the surface', 'Low memory', Request); the Kotlin host as the Android touch bead (by-q44s.7.8) left it (perform, the stopped and restarted Choreographer callback); the low-memory bead's (by-q44s.7.5) handoff (what Lifecycle::LowMemory does, and that a lost surface keeps the GPU device); rust/crates/beryl_mobile/android/src/main/java/ca/thurn/beryl/mobile/BerylMobilePlugin.kt (share: copying the file into cacheDir/share, FileProvider.getUriForFile, ACTION_SEND) and its AndroidManifest.xml (the provider declaration); tools/src/beryl_tools/beryl3d/phone.py (run_android_smoke).

Why. The milestone's exit checks need suspend and resume with the surface lost and recreated, and the low-memory path, to work on Android, on Vulkan and on OpenGL ES 3.0, and the client's platform requests to be carried out. Android destroys the window's surface in the background, which on the GL path is the riskiest case: the EGL surface goes while the context and its textures must stay.

Build, in the Kotlin host:

  • Suspend and resume. onPause sends SUSPENDED and stops the frame callback. surfaceDestroyed calls Native.surfaceLost before returning (Android requires that nothing draws on the surface after this callback returns). surfaceChanged after a return passes the new surface; onResume sends RESUMED and restarts the callback.
  • Low memory. onTrimMemory(level) with level >= TRIM_MEMORY_RUNNING_CRITICAL while in front, or >= TRIM_MEMORY_COMPLETE in the background, and onLowMemory, send LOW_MEMORY once per call and restart the callback.
  • Requests, the cases of perform:
    • share: copy the file into cacheDir/share, get a content:// URI from androidx.core.content.FileProvider with the authority ca.thurn.beryl3d.fileprovider, and start Intent.createChooser on an ACTION_SEND with EXTRA_STREAM and FLAG_GRANT_READ_URI_PERMISSION, as BerylMobilePlugin.kt does. Add implementation("androidx.core:core:1.13.1") to app/build.gradle.kts with a comment saying it replaces writing a content provider by hand, the provider to the manifest, and res/xml/share_paths.xml naming cache-path share/.
    • haptic: view.performHapticFeedback(HapticFeedbackConstants.CLOCK_TICK) for light and VIRTUAL_KEY for medium. No permission is needed.
    • open URL: startActivity(Intent(Intent.ACTION_VIEW, Uri.parse(text))), catching ActivityNotFoundException. Debug builds append one line per request to filesDir/host.log, and register a receiver for the broadcast ca.thurn.beryl3d.TEST (not exported, RECEIVER_NOT_EXPORTED on API 33 and above) whose string extra what is share, haptic or open-url, calling perform with a request built in Kotlin (the share of the newest frame log, a medium haptic, https://example.com), so the smoke tests each case's code before any screen sends one.

Smoke test: just b3d android-smoke --lifecycle, with and without --gles. After the first frame it presses Home (adb shell input keyevent KEYCODE_HOME), waits 3 seconds, starts the activity again (adb shell am start -n ca.thurn.beryl3d/.MainActivity, which brings the running task to the front without the fixture extra changing anything), runs adb shell am send-trim-memory ca.thurn.beryl3d RUNNING_CRITICAL, sends the test broadcasts for haptic and share with adb shell am broadcast -a ca.thurn.beryl3d.TEST -p ca.thurn.beryl3d --es what <what>, waits for the recording's end, takes the screenshot, and only then sends open-url, because opening a URL sends the app to the background. It fails unless: the frame log has Lifecycle lines Suspended, Resumed and LowMemory in that order; a Surface line follows Resumed; no frame line falls between Suspended and Resumed; frames follow Resumed; the fixture ended; beryl3d.log and wgpu.log hold no error; and host.log names the haptic, the URL and the share. Add the checks to tools/tests/test_beryl3d_phone.py.

If the GL path fails to draw after the return (an EGL error in wgpu.log), do not change the renderer's design: record the exact error and wgpu call on this bead, file a bead under milestone 4 for the renderer, and finish the Vulkan path.

Not in this bead: text entry; the phone layout.

Run: just b3d android-smoke --lifecycle; just b3d android-smoke --lifecycle --gles; just test-py tools/tests/test_beryl3d_phone.py.

Acceptance criteria

just b3d android-smoke --lifecycle and just b3d android-smoke --lifecycle --gles pass: Lifecycle lines Suspended, Resumed, LowMemory in order, a Surface line after Resumed, no frame between Suspended and Resumed, frames after Resumed, the fixture ends, no error in beryl3d.log or wgpu.log, and host.log records the haptic, the share and the URL (or a filed milestone 4 bead names the GL failure and the Vulkan run passes).
