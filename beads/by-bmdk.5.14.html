Description

Read first: epic by-bmdk, sections 'Rules for every bead', 'Contracts' and 'Code map'. Design: docs/manual-multiplayer.md ("the doc"), section 'Ability menus'.

Interface code goes in ui/src/table/, registered with TableClient (ui/src/table/client.ts). Headless checks start a table with ui/scripts/table.mjs and go in ui/scripts/kept-table-<topic>.mjs; run one with just ui-test <title>.

Host: rust/crates/beryl_table_session/src/abilities.rs. Interface: ui/src/table/abilities.ts. The text reading is beryl_table::assist::text::abilities and ability_action.

  • With the Ability menus assist on, a permanent's context menu lists its abilities under "Assists", one row each, labelled with the cost and the start of the text, cut to fit ("+1: Draw a card, then…"). The host puts each known permanent's ability rows in the view (beside the flows) so the interface reads no rules text.
  • A loyalty ability changes the loyalty counter by its cost and puts an ability marker on the stack. A cost of −X asks for X with the number prompt.
  • An activated ability puts an ability marker on the stack with its text. The table does not pay the cost: the player taps and pays by hand.
  • A marker resolves by a click, like any stack entry, and then ceases to exist. Its hover preview shows its source card and the ability's text.
  • The marker emerges from its source for both players.

Checks (kept-table-abilities.mjs): right-click a planeswalker, choose a loyalty ability: the counter changes and a marker is on the stack; click the marker: it is gone; a −X ability asks for X; a mana ability row puts a marker and does not tap the land. With the assist off the rows are absent.

Acceptance criteria

Ability rows appear only with the assist on, built by the host; loyalty abilities change the counter and add a marker, −X asks for X, activated abilities add a marker without paying; markers resolve by a click; headless checks cover each.
