Close reason

fuzz decks pick cards by rendezvous hash; game-shape asserts on fixed decks; rare seed search now a scenario; replay reveal bug fixed

Description

What was seen

During the authoring pilot (by-w8gv.15), adding any one new card file broke tests in beryl_session and beryl_search that have nothing to do with that card. The next project adds cards continuously, so every card writer would hit this.

Why

beryl_cards::decks::fuzz_deck (rust/crates/beryl_cards/src/decks.rs:91-106) sorts all implemented nonbasic cards by name and then shuffles the whole list with SplitMix64::shuffle. Adding one card shifts every later position, so every seed deals a different deck. Tests then assert things that held only for the decks those seeds happened to deal:

  • Users of fuzz_deck: beryl_search/tests/common/mod.rs:19, games.rs:115,200, shrink.rs:51; beryl_session/src/fuzz.rs:102, tests/sessions.rs:33, tests/streaming.rs:103, tests/saves.rs:28; beryl_cli/src/freeze.rs:190,194, fixture.rs:400.
  • Hard thresholds on fuzz-deck games: decisions > 40 "a short game" (beryl_search/tests/games.rs:106,156,276,308,392), stalls * 200 < n (games.rs:46), hashes.len() > 40 and assert_ne!(record(seed + 4).1, ...) (games.rs:392,402).
  • The save test assumed a fixed seed's scripted human plays a card within 30 answers (the Warden patched this one).
  • Seed searches for a seed that shows a rare case: beryl_session/tests/modes.rs:309 (0..32), checkpoints.rs:179 (0..20), smart_stops.rs:209 ("rare (seed 34...)").

Change

  1. Pick a fuzz deck's nonbasics by rendezvous hashing: rank each card by hash(seed, card name) and take the lowest FUZZ_NONBASICS. Adding a card then changes a given seed's deck only when the new card ranks into it (probability about 23/N), and never reorders the rest.
  2. Keep fuzz decks for invariants that hold for any deck (replay equals live play, reference checks, no capacity stall panics). Move assertions about how a game goes (length, stall rate, distinct hashes, two seeds differing) onto the fixed decks decks::WU_CONTROL / VINTAGE_WU_CONTROL.
  3. Replace each seed search with a Scenario (beryl_scenario) that builds the situation directly.

Behavior that must not change: what each test is meant to cover. Do not loosen an invariant.

Test

Add a test that removes or adds one card to the input of the deck builder (make fuzz_deck a thin wrapper over a function taking the card list) and checks that at least 90% of seeds 0..100 keep the same deck. Then, as a manual proof recorded on the bead, add a throwaway card file locally and run cargo nextest run -p beryl_session -p beryl_search: nothing fails.

Acceptance criteria

fuzz_deck uses rank-by-hash selection with a stability test; game-shape assertions run on fixed decks; seed searches replaced by scenarios; adding a throwaway card breaks no beryl_session or beryl_search test (recorded on the bead).

Deviations and proof.

  1. Stability test: the bead asked for >=90% of seeds 0..100 to keep their deck when one card is added or removed. That is impossible at today's pool size (~57 nonbasic cards, 23 per deck): a given card is in about 40% of decks, and any deck it joins must change. The test instead checks the rendezvous property exactly, for every nonbasic card and seeds 0..100: a deck the card is not in is unchanged, and a deck it joins differs by that card alone (one card dropped). The share of unchanged decks rises to ~1-23/N as the pool grows.
  2. Seed searches: smart_stops.rs (0..64, the rare opponent response) is now a Scenario (Thundertrap Trainer, Get Lost held by an opponent that always casts) asserting exactly one response and one spell resolved unasked, plus four seeded games that check the same rules and replay (prepared games cannot replay, so the replay check stays on seeded games). modes.rs (first seed whose flip the human wins) and checkpoints.rs (a game with a lingering effect) were left: both play fixed decklists, so they do not depend on which cards exist, and both need a seeded session game (the opening's coin flip, a replay with turn checkpoints) that a prepared scenario game cannot provide.
  3. Found and fixed a replay bug (beryl_session/src/game/replaying.rs): when a save lacks a priority the game now asks and a card reveal was logged after the answer before it, replay failed its chance check before passing the missing priority, and silently rebuilt from the turn's beginning. Regression test: saves.rs a_priority_the_record_lacks_before_a_reveal_is_passed. Not added to docs/bugs.md, which excludes non-rules bugs.

Manual proof: with throwaway card files Divination (draw two) and then also Night's Whisper (draw two, lose 2 life) added locally, cargo test -p beryl_session -p beryl_search passed all 49 test binaries each time. The only failures were beryl_cards' own every-card-has-scenarios checks for the throwaway files, which is expected.
