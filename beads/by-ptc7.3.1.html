Description

Why

The mutation check (every_mutant_of_a_card_is_killed_by_its_scenarios, rust/crates/beryl_cards/src/tests/mutation.rs and tests/mutation/neighbours.rs) changes one node of a definition and requires a scenario to tell the mutant from the card. It mutates only the effect data of spell, activated and triggered abilities, and each target's optional flag. A card may drop hand-written scenarios only if "every mutant is killed" means every part of it is pinned. Plan: Designs E1.

What to build

In neighbours.rs (1,246 lines: split it by what is mutated, one file each for effects, abilities' interfaces and faces), add neighbours for:

  • a static ability's Modification (a neighbouring variant, an amount plus or minus one), its affected set (filter widened or narrowed, controller swapped) and its Condition (negated);
  • a replacement ability's event and its rewrite, and a RuleChange's Governed, When and players;
  • a mana ability's product (another color, one more or fewer);
  • a trigger's event (a neighbouring TriggerEvent), its Subject (This against a filter), its condition, and "next" against every time;
  • each CostPart dropped or changed (tap, sacrifice, life, a count plus or minus one) and the mana cost of an activated ability changed by one generic;
  • each CastingOption dropped, and an additional cost dropped;
  • each keyword bit of a face dropped (printed characteristics are generated and are not mutated).

Each new kind of mutant will have survivors on today's 121 cards. For each survivor: a hand-written scenario that kills it already exists and the mutant builder is wrong; or the card needs a scenario, which you write; or the two are equivalent and it goes in EQUIVALENT with the reason. Report the count of each.

The check must stay fast: it is about 3 s over every card today and runs cards on available_parallelism threads (reports()).

Bars (every bead of this epic)

  • The plan is docs/project-50k-part-2.md. If its design is wrong for the code, build what is right and amend the plan's section in the same push. Never wait for an answer: record the choice in this bead.
  • The absent-cost gate holds with no bump (just count-gate). When you touched the kernel, the rules or the card vocabulary, report the count before and after in the close reason. If it cannot hold after three attempts, stop and say so on the epic: this is the one thing that stops the run.
  • size_of::<State<Small>>() stays within 20,480 bytes. Report the size if you changed it.
  • The frozen saves replay and rollouts_never_change holds (just test-rust).
  • Rules code cites the Comprehensive Rules with a quotation (just citations). A card file cites a rule only for a card-specific ruling.
  • A new card follows the card-writing skill and passes just card check <name> (Beryl, XMage and Forge). A keystone or partner is listed in data/rulings-ledger.json once that file exists, with every ruling a scenario or a reason.
  • No UI work. beryl_cli script-check must pass for a new card from both seats with the verbs and prompt shapes that exist.
  • A rules bug found on the way gets its docs/bugs.md entry, naming the guard that now stops its class.
  • A bead you file is tier:opus for design, keystones and reviews, tier:sonnet for partner cards, sweeps and measurements, and never tier:fable.

Acceptance criteria

Every kind listed has neighbours and the check passes on all cards. The close reason gives, per new kind, the mutants made, the survivors found and how each was settled, and the check's seconds before and after.
