Close reason

pose_at, Track and the beat port of laid on staging at ffa9d40db

Description

Read first: docs/beryl-3d.md 'Determinism' (positions are functions of time; Segment) and 'Timing a script' (what a client still does). Then ui/src/stage/beat.ts in full (laid), the Timing record at the top of ui/src/stage/tracks.ts, and CURVES in ui/src/stage/timing.ts. StepTiming is in rust/crates/beryl_session/src/script/timing.rs (the timing types bead).

Pure functions only. Nothing here knows a script, a view or a card.

In rust/beryl3d/crates/beryl_scene:

  • src/motion.rs: pose_at(segments: &[Segment], t: u64) -> Pose. The four named curves are the CSS cubic Beziers the web's CURVES maps them to. A segment's path rises arc millimetres above the straight line at its middle. Track is a fixed array of 8 segments for one object, sorted by start. Track::push may drop a segment only once it ended before now, and keeps the latest such one, because a compiled script holds segments that lie in the future.
  • src/beat.rs: one function, a port of laid. Given a beat's StepTimings, the time the beat starts, and the two things only a client knows (since when each span has stood whole, and until when something passes over the table), it returns each step's start and end. Port it line for line, keeping its variable names and its comment. Its doc comment names laid.

Tests in beryl_scene/tests: pose_at at a segment's start, middle and end, and past its end; an arc's height peaks at the middle; Track::push keeps 8 segments and the right one of those that ended; and beat on five beats built by hand. Get their expected values by running laid on the same five beats once in Node (ui/scripts/stage.test.mjs shows how to import the stage with no browser), write the numbers into the test as constants, and give the Node command in a comment. Do not commit the Node script.

Run: just b3d cargo-test -p beryl_scene.

What the prototype found (rust/prototypes/beryl3d, 2026-11-14; read its code for a working example, then build it properly):

  • A fixed array of 8 segments per object, sorted by start, was enough (core/motion.rs, Track::push).
  • data/ui-conventions.json's curves are names: "ease-out", "ease-in", "none" and null (keep the verb's). The session resolves cases, so beryl_scene sees only the curve each StepTiming carries.

Acceptance criteria

The tests pass; beat has the branches of laid in the same order; nothing in motion.rs or beat.rs keeps state between calls or reads data.
