Description

Milestone 4 of Project 50k (plan K4, epic by-w8gv.7). Trackers are this-turn and this-game counts, kept only when a card in the game reads them. This bead builds the Trackers store and moves onto the stores the two facts about a permanent that end with the turn: that it entered this turn and that one of its loyalty abilities was activated this turn.

Read first

  • docs/project-50k.md: decisions K4, K6, K11, and "State" and "Kernel rules" under Target architecture.
  • rust/crates/beryl_kernel/src/lib.rs: the kernel's contract. Its "Stores" section (written by by-w8gv.7.2) is the design this bead follows: kinds, shapes, capacities and byte allotments, expiry, indexing, capability bits, and what a store implements once. The same numbers are in a comment on by-w8gv.7.2, and enact brief shows that bead's handoff. Where the code proves the contract wrong, change its text in the same push and say so on the bead.
  • rust/crates/beryl_kernel/src/legacy.rs: the table of what M4 deletes. Delete each Legacy method this bead replaces; the struct itself goes in by-w8gv.7.10.
  • The contract says whether a per-turn fact about a permanent is a tracker keyed by object or a memo with an expiry (by-w8gv.7.2 decided it). Build what it says. If it put both facts in the Memos store, this bead still builds the Trackers store's kind list, capability bits and once-written parts as the contract shapes them, and says on the bead that no kind uses it yet.
  • docs/engine-architecture.md §6.4 and docs/rules-coverage.md Principles 1 and 2.

Need not read: the Effects store's internals, mana.rs, layers.rs, combat.rs, beryl_session beyond checkpoint.rs, ui/.

Where it is (staging 08d1a377)

  • ObjectFlags::ENTERED_THIS_TURN (object.rs, with the getter entered_this_turn): set by the zone move for every permanent that enters (zone.rs move_object), cleared by State::reset_permanents_for_turn (mutate.rs), arranged by Board::set_entered_this_turn (board.rs). The rules never read it. One static ability does: Rule::InstantLoyaltyTheTurnItEntered in the loyalty timing check of beryl_engine/src/cast.rs (The Wandering Emperor). It is not in ObjectFlags::LEGACY because the audit missed it.
  • ObjectFlags::LOYALTY_ACTIVATED (object.rs): set through Legacy::set_object_flags where cast.rs activates a loyalty ability, read a few lines above the timing check (CR 606.3: "only if no player has previously activated a loyalty ability of that permanent that turn"), cleared by reset_permanents_for_turn, arranged by Board::set_loyalty_activated; read by beryl_search/src/expert/mod.rs and frozen/expert/mod.rs.
  • Player::lands_played (CR 305.2) and the fields of Turn are the rules' own and stay.

Scope

  1. The Trackers store as the contract shapes it: a closed list of kinds, each kept only while a GameTable capability bit says a card of the game reads it, each reset by the kernel when its span ends (the turn; never, for a this-game count), with what a store implements once in its own file.
  2. "Entered this turn" is tracked only in a game with a card that reads it. The WU mirror has The Wandering Emperor, so it is tracked on the counted path: the write is on every battlefield entry and must cost what the flag did, or close to it.
  3. "A loyalty ability was activated this turn" is tracked only in a game with a loyalty ability.
  4. Both flags, Board's two setters' use of them and Legacy::set_object_flags' last use go. Readers ask a query.
  5. Build no kind that no card of the 47 reads: no card reads a this-game count or a per-player this-turn count today. The kind list is where the next one goes.

Gotchas

  • A checkpoint is taken as the upkeep begins, when both facts are empty, so there is nothing to save; off_board (board.rs) must not report a tracker that is empty.
  • A permanent that leaves and returns in one turn is a new object: it entered this turn, and no loyalty ability of it was activated.
  • by-w8gv.7.3 changes how Rule::InstantLoyaltyTheTurnItEntered is asked, in the same expression of cast.rs. Whichever lands second rebases a three-line conflict.
  • Scenarios: cargo test -p beryl_cards wandering, teferi, jace; just oracle "The Wandering Emperor".

Acceptance criteria

The Trackers store exists as the contract shapes it: a closed kind list, a GameTable capability bit for each kind so that an unread kind costs one AND and is never written, a reset by the kernel when the kind's span ends, and its empty value, copy, relayout, fit, invariant, save description and observation written once in its own file. ObjectFlags::ENTERED_THIS_TURN and LOYALTY_ACTIVATED are gone, each held in the store the contract names and read through a query; a test shows a game with no card that reads "entered this turn" does not track it, and one with The Wandering Emperor does; a permanent that leaves and returns in one turn has entered this turn with no loyalty ability activated. just bench-count before and after and the state size are recorded on the bead; the planeswalker scenarios and just oracle "The Wandering Emperor" pass; parity holds with no bump to the count gate.

Numbers (just count-gate, the rollouts subject, as by-w8gv.7.2 measured): before 387,956,541 at staging 79fc8568; after 389,728,983, +0.46%, which is +0.10% against the bar of 389,343,295: no bump. size_of::<State<Small>>() is 20,080 (20,016 before, +64, the allotment). rollouts_never_change is untouched and the frozen save corpus replays; corpus_never_changes moved (6_445_720_418_991_420_564 to 15_570_083_640_149_560_188) because an object no longer hashes the two flags and the state hashes the store: with the trackers hashed back into each object's flags as bits 16 and 17, the corpus gives the old pin. just oracle "The Wandering Emperor": XMage 3 pass, Forge 3 pass.

Where the 0.46% is (callgrind, by symbol): the write as a permanent enters and the clear as one leaves, about 0.03%; State::signature's two bits and collapse, about 0.04%; the rest in engine::decision, the check of whether a loyalty ability may be activated, made tens of thousands of times in the benchmark. A tracker read is a load and a bit test of the state where the flag was a test of the object in hand (about 0.1% direct), and the loop around it compiled to more besides. Variants measured: the first cut, the old order of checks with the store at the end of State, 390,057,413; the loyalty check out of line (inline(never)), 391,310,485; timing first with the rule asked before the activation tracker, 390,508,346 (it also recorded more coverage hits); timing first, one tracker read at most decisions, store at the end, 389,992,845; the same with the store laid out beside keyed, 389,630,133; that with the counters test folded in so cast.rs does not grow, 389,728,983, which is what landed.

Decisions and deviations:

  1. The contract held: both facts are trackers keyed by permanent, a set of slots each (trackers.rs). Capability stays the table's enum and each Tracker names its bit.
  2. State::track takes the table and gates on GameTable::can itself, so no rules call site can forget the AND. The zone move has no table, so the entry is noted by the engine's arrive (event.rs), the one place a permanent enters.
  3. The Trackers store keys no slot (Store::keys is empty) and is no part of forget_keyed: the move's leaving arm clears a permanent's two bits. Its Store::expire is a no-op: begin_turn empties it. Contract amended to say so.
  4. Contract amended: the turn's reset clears the eight words in every game (State::begin_turn has no table), not 'nothing in a game no card of which reads them'.
  5. The field sits after keyed, not with the stores at the end of State: 0.09% on the count. State's rustdoc says why. A new kind keyed by permanent moves the offsets of everything after it by 32 bytes.
  6. Board::place no longer marks a permanent as entered this turn (the old flag was set by every zone move, the board door's too). Scenario setup (beryl_scenario/src/setup.rs) notes it for each permanent it places, as before, because the UI fixtures and spec scripts recorded from scenarios stop where a placed planeswalker may act at instant speed: beryl_session's ability_events test failed without it. beryl_cli's blunders/board.rs and the engine tests' Game::give now place permanents that have not entered this turn, which is what a mid-game board means. Worth a look some day: whether scenarios should keep that accident.
  7. In a game with no card that reads 'entered this turn', State::signature no longer tells a permanent that entered this turn from one that did not. They nearly always still differ by SUMMONING_SICK; the corpus and every test hold.
  8. Fixed in passing: the last assertion of a_permanent_lets_loyalty_abilities... in tests/casting.rs asked the opponent's decision, so it could not fail; it now passes priority first.
  9. Board's two setters became one, Board::set_tracked(slot, tracker, on).
