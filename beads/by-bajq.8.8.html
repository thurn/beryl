Description

What is wrong

A merged permanent (CR 731, built in by-bajq.8.5) has every ability of each card that represents it (CR 731.2a, 702.140e). Today only some of those reach the rules: the keywords of the cards under it (layer 1, State::copy_layer_one) and their triggered abilities (trigger::elsewhere::match_given and look_back_merged, read from Copiable::merged_faces). The other kinds do not:

  • activated and mana abilities: State::abilities (beryl_kernel/src/abilities.rs) yields the top face's own abilities and the granted ones only, so cast/legal.rs offers no activation of an ability of a card under the permanent, and the mana solver (mana/sources.rs, mana/pay.rs, mana/lookahead.rs) finds none;
  • static abilities with a continuous effect: layers/mod.rs apply_layers lists only the top face's (and granted) static abilities;
  • static replacement and rule-change abilities: replace::statics, rule_change.rs read State::abilities and the top face's replacement mask (Copiable::may_replace).

So Gemrazer cast over a creature with an activated ability (e.g. a mana creature) leaves a merged permanent that cannot use it: a silent rules bug.

What to build

Extend State::abilities with the abilities of Copiable::merged_faces (a new ObjectAbility kind naming the merged card's face and index, which activation turns into an AbilityRef with that card), list the merged faces' static abilities in apply_layers (an Apply::order that names the merged face), and include the merged faces in the replacement and listener masks a merged permanent reports. Session saves and candidates (beryl_session/src/save/ability.rs, protocol/candidates.rs) name the new kind.

Acceptance

  • Scenarios in Gemrazer's file (or a partner's): Gemrazer over a creature with an activated ability activates it; over a creature with a static ability (an anthem or a replacement), the effect applies. They pass on Beryl, XMage and Forge.
  • just count-gate holds with no bump; just test-rust.

Acceptance criteria

Merged permanents have activated, mana, static and replacement abilities of every card under them; scenarios pass on all three engines; count gate holds.

Decisions: (1) New ObjectAbility::Merged(place, index): place = position among Copiable::merged_faces (top of pile down), index on that card's face. State::abilities yields own, merged, granted. Lost abilities: merged ones are lost only when the permanent lost all abilities (lost == ALL); a single-ability removal names the top face. (2) Layers: merged static abilities are listed with Apply::order = MERGED (0x40) | index and source = the merged card (layers/merged.rs); player rules moved to layers/player_rules.rs to keep layers/mod.rs under 800 lines. Static abilities that reach every zone from under a merged permanent are not listed for the kernel's elsewhere reach (it names an ability by index on the permanent's own face). (3) Mana: a merged permanent is on the slow makes_card_mana path (layers set mana_changed when one exists), so the solver reads it ability by ability. (4) Not done, filed as by-bajq.8.9: replace::statics and object rule changes (rule_change::maker_of) keep an AbilityIx on the own face as identity. Acceptance's 'replacement' is covered here by a player rule change (Platinum Emperion); no non-Human creature with a static replacement is implemented. (5) Oracle exporters: Cards.track_merges follows a scenario's mutate Cast/Target/YesNo answers to know the pile; a mutate cast whose target Beryl chose silently is not followed, so merged activations need an explicit target answer. Count gate: base ac574fe 375,875,934; first version 392.7M (+4.5%), now 378,825,524 (+0.78% vs base, -1.40% vs bar 384,206,865, no bump). Main costs were a Copiable copied into every Abilities iterator and player_rules losing its inlining; merged paths are now #[cold]/out of line. State<Small> size unchanged.
