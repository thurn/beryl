Close reason

Live hosts prepare, hold and upload card faces (board and full size); frame-log guard in stand-in

Description

Symptom: in the live desktop app (and the windowless and phone hosts) every card draws as the placeholder back pattern; no card face, drawn frame or scan ever shows. Seen by the Warden by-q44s.5.43 with just b3d app --fixture pay-default then just b3d live png.

Why: only the headless picture host (beryl_host src/headless.rs, load_faces) prepares faces. (1) Nobody gives the client Input::Cards in a live game (beryl_3d src/session.rs Live::begin and game starts) or in an app replay (beryl_3d src/fixture.rs; the recordings carry their records, see beryl_scene src/driver/mod.rs:550), so Client::faces() is empty. (2) beryl_host src/desktop.rs, src/windowless.rs and src/phone.rs never call Renderer::set_faces, never run a beryl_assets::Preparer (prepare_match, full for Client::wanted_faces), and never route faces arriving during play through Renderer::hold / upload_waiting(client wake) (at most one full-size face a frame, board-size only while still; late scans from the beryl-assets-late thread the same way). The phone host also lacks glyph delivery.

Build: extend beryl_host src/assets.rs (added by by-q44s.5.43: Glyphs, called through Draw::assets before and after each frame) with a Faces part the desktop, windowless and phone draws share: detect a new face list (match start, gallery switch), set_faces + prepare_match with the real art cache (beryl_art ArtCache, beryl_art::SCRYFALL, the app's scan cache dir as Scans::app() names it), hand every result to hold, upload via upload_waiting, give the client each AssetReady as Input::Assets, and keep waking while Renderer::waiting() > 0. The gallery's list (Client::showing_gallery, AssetReady::GalleryFace) must not overwrite match readiness. Give the client Input::Cards for both decklists before the opening hand (docs/beryl-3d.md 'Card faces' steps 1-4: board-size faces uploaded during the loading screen), using beryl_session::card_records. Wire Glyphs into beryl_host src/phone.rs too.

Guard: add a frame-log count of drawn cards whose face had no layer and of text runs lacking glyphs, and have just b3d stand-in (tools/src/beryl_tools/beryl3d/stand_in.py) fail when either stays above zero after the opening hand, so a live host that forgets an asset path fails a check (the stand-in reads only the tree, which is why this went unseen).

Acceptance criteria

In a windowless live run (just b3d app, then just b3d live png) battlefield and hand cards show drawn frames or scans; the inspector shows a full-size face; tests cover face-list change, hold/upload_waiting delivery and gallery isolation; the frame-log guard exists and the stand-in passes with it; no face is decoded or composed on the frame thread (faces_built_on_this_thread stays 0 there).

Handoff: beryl_host src/assets.rs gains pub Faces (and Scans moves there from headless.rs). The desktop, windowless and phone hosts own it beside Glyphs, and the phone host now runs Glyphs too. Faces::deliver makes the renderer's face arrays when (showing_gallery, Faces::number) changes. Faces::number is new in beryl_scene: Faces::replace numbers each Input::Cards, so an equal list given again (a resume with the same decks) is still prepared again. It queues prepare_match, sends wanted_faces to Preparer::full, holds every result and runs upload_waiting only before the frame (Draw::assets now takes When). Gotcha: upload_waiting must use the client's wake read right after the last frame (Faces::after_frame), because any input, the host's own Nudge included, sets client.wake() to Now and would hold board-size faces for ever. Gallery readies are mapped to GalleryFace; on going back to the match, Client::face_arrays_made forgets its full-size layers. beryl_3d: Live::give_cards sends decklist_records (deck names plus the tokens their cards make) after begin, Start and Resume; Fixture::cards gives the recording's records. Guard: the frame log summary has faceless_cards (Frame::faceless_cards) and missing_glyphs (a counter in text/glyphs.rs), and stand_in.check_assets fails a run that ends with either above zero. Deviations: the guard counts missing glyph keys, not text runs. A new match uploads one board-size face per still frame (about 2.5 s for 150 faces at 60 Hz), not all of them behind a loading screen. On Android, Scans::app() falls back to HOME/.cache, which may not be writable; faces then draw as frames. Verified: tests/all/faces.rs (3 tests), just b3d app --fixture pay-default plus live png (scans on battlefield, hand and stack; full-size inspector face; both counts 0), just b3d stand-in passed.
