Graph:

  • lane:event-tags (fable): .71 every recorded event names its cause and its stack entry (type, register in the sink, scope sites, every stack arrival and departure in the stream) -> .72 simultaneity groups at the cited sites, a block as an event.

  • .75 Warden, tier:fable, depends on .71 to .74.

Decisions and deviations:

  1. The Warden is tier:fable, not tier:opus as this bead's first paragraph says: its Models section and the run epic's override it for engine and UI logic (as step one's did).
  2. The count gate's bar is 389,343,295 (rust/crates/beryl_bench/count-gate.toml; M5 lowered it), not the 405,276,238 this bead and the epic name. Every bead says the file is right and does not change; the two engine beads report just bench-count before and after.
  3. Two lanes, not one: the engine beads touch beryl_kernel/src/event.rs and the rules' scope sites, the session beads beryl_session/src/script. .73 can start once .71 lands, beside .72.
  4. Tags are stamped in the sink from a register the rules set, not at the event sites: only eleven sites push or note, and Sink::push and note are the only ways in. Recommended, for .71 to settle: a tag beside each event (Event's variants unchanged, so trigger matching is untouched), and a stack entry named by its index from the bottom, read only when the sink is on, with the session following the stack event by event; StackEntry and State gain no field.
  5. Where the tags travel in the session is .73's to decide; recommended beside the events and not serialized, so protocol.ts, fixtures and saves are untouched and the UI cannot read one.
  6. infer.rs holds more than guesses about the engine: show, looked, making and quiet read the seat's own prompt, and some of together and order is staging (a payment's sources turning ahead of their mana). .72 sorts each rule into the rules' or presentation in a comment; .74 keeps the presentation ones in a module that reads tags and never the order of events.
  7. The scripts-changed report needs a dump of every script as text before and after: .73 adds a flag to beryl_cli script-check for it, and .74 sums both beads' diffs on the epic.
  8. by-w8gv.21.10's handoff asked for a Block event and the engine's word for a new object (Screen.broken): both are in .72 and .74.
  9. No inline reviews and one Warden for the step, per the run's role policy.

What the planner's code map missed: beryl_engine/src/event.rs is now beryl_kernel/src/event.rs (type and Sink) and beryl_rules/src/event.rs (the pipeline); the interpreter is beryl_rules/src/interpret/{mod,run,scene}.rs with resolve.rs and resolution.rs; an untargeted trigger going on the stack has no event today.
