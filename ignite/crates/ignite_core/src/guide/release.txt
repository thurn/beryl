RELEASE: giving a ticket back, or setting it aside

Ordinary difficulty is not a reason to release: failing tests, confusing code
and conflicts are the job.

You cannot reproduce the fault a ticket reports:
- Never release it: the next worker would only repeat your attempt. If your
  attempt was inconclusive, run the step you would hand on yourself.
- If it does not fail at the tip, run ignite close, saying what you ran and
  where. A fault that returns gets a new ticket naming this one.

Your ticket needs another ticket's work that has not landed:
- Do not wait or watch the integration branch. Commit what you have, add the
  dependency, say in the note what you need and where you stopped, and
  release. If that work has no ticket, file one first. If the ticket you need
  is closed, its work has landed: run ignite sync.

Only another machine can do or check the work (its operating system, a device,
its local logs), or the failure is that machine's own environment:
- Do not try to reach that machine and do not wait for it. Say why in the note
  and run ignite release --needs <machine>.

The work needs access, credentials, a decision only the person can make, or an
irreversible outward action:
- Run ignite release --needs person, stating the exact need and what you
  tried. Never close it as done, and never release it plainly: the next worker
  would meet the same wall.

The ticket cannot be completed as written: its acceptance contradicts its
body, gates on something you cannot control (a timing on a loaded machine), or
needs a constraint relaxed. This is not ordinary difficulty:
- Do not wait and do not close it. Run ignite justiciar "<ticket>: <what is
  impossible, and the evidence>", then ignite release -m <exact state>.

Several tickets fail for one cause: file one ticket for the cause, make each
affected ticket depend on it, and release yours with a pointer to it.

Other cases:
- A reported-only ticket (a benchmark, a measurement) blocks other work:
  remove its dependents' edges so it leaves the critical path.
- The ticket is too big: land the first coherent part and file the rest.
- The ticket is obsolete or already done: run ignite close, naming the commit
  or code that shows it.
- A figure measured on a loaded machine is reported, never gated on or chased,
  unless the acceptance names a deterministic measure.

After a release, by you or by Ignite (ignite guide turn-end), never use the
tree's path again. After an interruption (a usage limit, a crash, a nudge), run
ignite brief first, and continue only if you still hold the ticket.
